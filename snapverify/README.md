# snapverify — 增量快照校验

接收端只持有**可信旧根**，凭证明（Proof）与差量（Delta）验证新根确实由声明的差量推出。

## 模型

- **键空间**：`2^depth` 个有限有序 ID（`uint64` 键，深度可配），快照是深度为 `depth` 的二叉 Merkle 树，空叶子、值叶子、内部节点使用不同的域分隔标签。
- **Delta**：声明全部变更，携带 `OldVersion`/`NewVersion`（必须 +1）与键范围 `[RangeLo, RangeHi)`：
  - `Adds`：旧快照中必须为空，写入新块；
  - `Deletes`：声明被删块的旧值，验证时重放删除；
  - `Inherits`：声明原样继承的块，旧新值必须一致。
  同一键在三组中至多出现一次，且必须落在声明范围内。
- **Proof**：头部绑定旧/新版本与范围（必须与 Delta 完全一致，防止跨版本/跨范围重放）；正文是受影响键路径上的兄弟哈希多重证明，按 `(Level, Index)` 索引，**与顺序无关**，且必须恰好等于所需集合——缺失、重复、多余一律拒绝。

## 验证流程（`Verify`）

1. 校验 Delta 结构（版本步进、范围合法、键不重复）；
2. 校验 Proof 头部与 Delta 绑定一致；
3. 用声明的旧值 + 证明节点重建旧根，与可信旧根比对——删除/继承块谎报旧值、或证明造假都会在此失败；
4. 用声明的新值正向算出并返回新根。未声明的键被证明哈希钉死，无法偷换；声明的删除若不重放，就算不出匹配的新根。

空差量是合法特例：证明必须为空，新根等于旧根。

## 参考实现与测试

`Reference` 保存完整映射并**全量重建**整棵树作为基准；`BuildProof` 同时充当证明方。测试覆盖：空差量、重复键操作、证明节点顺序（乱序通过/缺失/重复/多余拒绝）、跨版本拼接（含过期差量重放与跳版本）、遗漏删除、偷换未声明块、头部绑定、错误旧根、增删继承混合对照全量重建。
