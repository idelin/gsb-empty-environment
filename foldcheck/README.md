# foldcheck

归档导入前的大小写折叠冲突预检工具。折叠规则完全来自输入显式提供的折叠表，
工具本身不做任何隐式大小写转换。

## 用法

```
foldcheck -table fold.json [-paths manifest.txt | -root DIR] [-json]
```

- `-table`：折叠表 JSON，`{"from": "to", ...}`。键可以是多字符，值可以是一对多
  （如 `"ß": "ss"`）；匹配采用最长键优先的贪心策略。
- `-paths`：清单文件，每行一条：`F <路径>`、`D <路径>`，或裸路径（以 `/` 结尾视为目录）。
- `-root`：直接遍历某个目录树代替清单。
- `-json`：以 JSON 输出冲突组。

退出码：发现冲突为 1，无冲突为 0，用法/输入错误为 2。

## 规范化规则

对每个路径段独立处理（多段折叠），再拼接比较：

1. 按折叠表折叠该段；
2. 末尾空格规则：去掉段尾的空格和 `.`（Windows 风格）；
3. 保留名检查：折叠后的基名（第一个 `.` 之前）若为
   `CON/PRN/AUX/NUL/COM1-9/LPT1-9`（不区分大小写）则标记；
4. 折叠结果为空段则标记为 invalid。

## 冲突类型

- `name`：不同原名折叠到同一规范化路径；
- `type`：某个文件的规范化路径是另一条目的**父前缀**（文件被当作父目录）——
  只比较完整路径字符串会漏掉这类冲突；
- `reserved`：路径段折叠后命中保留名；
- `invalid`：路径段折叠后为空。

## 最小冲突组

若某组的所有原始路径都已被更浅层（祖先路径）同类冲突组覆盖，则该组被抑制——
子路径冲突是父冲突的推论，不重复报告。`name`/`type` 共享覆盖类；
`reserved`/`invalid` 独立跟踪，不会被同路径的名称冲突掩盖。
组内 `origins` 始终保留原始路径名（含文件/目录类型），不做折叠。

## 测试

```
go test ./...
```

合成目录树覆盖：多段折叠、一对多映射、原名保留、父前缀类型冲突、
末尾空格/点、保留名、最小组抑制，以及真实临时目录树的端到端遍历。
