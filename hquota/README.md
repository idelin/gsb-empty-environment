# hquota — 层级配额库

按树结构分配整数额度：内部节点持有总上限（Cap），叶节点持有需求（Demand）
与权重（Weight）。分配满足**加权最大最小公平**（weighted max-min fairness），
零头按叶编号轮转分发，游标跨批次保留。

## 分配流程

1. **实数域注水**：所有未冻结叶按权重同步抬升水位，任一节点上限或叶需求
   触紧即冻结相应叶，直至全部冻结，得到每叶的精确公平份额。
   全程不取整——**不会先逐层取整丢掉可用额度**。
2. **一次性向下取整**：对叶的精确份额取 floor。各节点子树的 floor 之和
   必然不超过其上限，因此取整结果天然可行。
3. **零头轮转**：剩余额度从游标开始按叶编号循环扫描，每叶每轮至多 +1，
   须满足叶需求与沿途全部祖先上限；一整轮无分发即结束。
   游标保存在 `Allocator` 中，**跨批次（多次 Allocate / 缩容重分）延续**，
   长期看各叶分到的零头均匀。

## 公平性核验

- `Allocator.Verify()`：核验最近一次分配——可行性（叶需求、节点上限）、
  瓶颈公平准则，以及严格的不浪费（未满足叶必有恰好饱和的祖先）。
- `Tree.VerifyAllocation(alloc)`：独立核验任意一份整数分配。
  瓶颈准则：任一未满足叶 i 必存在近似饱和的祖先 n（空隙小于子树叶数，
  即取整固有损耗），使 n 内不存在未达需求却明显更占便宜的叶 j：
  `alloc[j]*w[i] > (alloc[i]+1)*w[j] + w[i]` 即为违例（+1 为取整容差）。

## 额度缩小重分

`Allocator.SetCap(nodeID, cap)` 调整节点上限并立即重新分配：
受影响子树按公平原则重新注水，其余部分自动让出/补入额度。

## 用法

```go
tr, _ := hquota.NewTree("root", 100)
tr.AddNode("root", "teamA", 60)
tr.AddNode("root", "teamB", 60)
tr.AddLeaf("teamA", 1, 100, 1) // 叶编号 1，需求 100，权重 1
tr.AddLeaf("teamB", 2, 100, 1)

a := hquota.NewAllocator(tr)
alloc := a.Allocate()          // map[1:50 2:50]
if v := a.Verify(); len(v) > 0 {
    // 处理违例
}

alloc, _ = a.SetCap("teamA", 30) // 缩容重分：map[1:30 2:60]
```
