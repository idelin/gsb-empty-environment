# framearc — 带独立校验的前缀编码帧归档

一个自同步的帧式归档格式与读取器。设计目标：**归档中一帧坏掉后，后续合法帧仍应可读**；
同时读取器**只报告能证明的事实**——它给出坏字节的范围，绝不凭压缩字节猜测
不存在的"精确原始损坏位置"。

## 帧格式

所有整数大端。每帧：

| 偏移 | 大小 | 字段 |
|---|---|---|
| 0 | 4 | 魔数 `PCF1` |
| 4 | 4 | 序号 seq |
| 8 | 4 | 原始长度 origLen（解码后符号数） |
| 12 | 4 | 载荷长度 payLen（压缩字节数） |
| 16 | 2 | 码表项数 tabLen |
| 18 | 2×tabLen | 码表：`(符号字节, 码长字节)`，规范前缀码 |
| … | 4 | 头部 CRC32（覆盖此前全部字节，含魔数与码表） |
| … | payLen | 载荷：规范前缀码比特流，MSB 优先，末尾零填充 |
| … | 4 | 载荷 CRC32（覆盖**解码后的原始字节**） |

两个 CRC 相互独立：头 CRC 保证结构（长度、码表）可信；载荷 CRC 保证内容可信。
码表存码长，规范（canonical）分配码字：按 `(码长, 符号)` 排序后顺序编号，
解码端用同一规则重建，无需存码字本身。

## 读取器状态机

**正常模式**：位于帧边界，只按已确认的头部长度消费。载荷字节里出现的魔数
**不是**帧头——长度可信时绝不扫描。头部 CRC 有效但载荷 CRC 失败 →
报告 **坏帧**（范围精确等于该帧），越过它继续。

**重同步模式**：头部非法（无魔数、字段越界、头 CRC 失败）时进入。
从下一字节起逐字节扫描候选偏移；候选只有在**结构合法且两个 CRC 全部有效**
时才被接受。头 CRC 有效但载荷未齐时"锚定"等待更多数据；找到合法帧后，
其间字节报告为**间隙**。

**暂停与恢复**：`Budget` 限制单次调用检查的候选位置数。预算耗尽即暂停，
缓冲区、扫描位置、间隙起点全部保留；`Pump`/`Feed` 从断点继续，不漏一字节。
`Close` 表示流结束：剩余无法解码的字节报告为间隙。

## 结果语义（能承诺什么、不能承诺什么）

| 事件 | 含义 |
|---|---|
| `EventFrame` | 双 CRC 通过，解码字节完整可信 |
| `EventBadFrame` | 头 CRC 有效 → 范围可信；载荷 CRC 失败 → **整帧载荷不可信** |
| `EventGap` | 结构不可确定的字节范围，对其原始内容一无所知 |

**为什么坏帧不定位到具体字符**：前缀码是变长的，符号边界依赖此前所有比特。
压缩流中一个 bit 翻转会改变其后每一个符号的边界，"哪个原始字符错了"
这个问题本身没有定义良好的答案。CRC 只能证明"帧内有错"，证明不了错在哪里。
因此读取器只报告字节范围，不把 CRC 失败解释成某一个原始字符必错。

## 限制

- 单帧原始长度 ≤ `MaxOrigLen`（1 MiB），载荷 ≤ `MaxPayLen`（1 MiB）
- 码表 ≤ 256 项，码长 ≤ 24 bit
- `Reader.Budget`：单次调用的重同步候选扫描预算（≤0 表示不限）

## CLI

```sh
framearc encode [-size N]   < plain > archive      # 分帧编码，默认每帧 4096 字节
framearc decode             < archive > plain      # 解码，事件报告打到 stderr
framearc corrupt -mode M [flags] < archive > dmg   # 构造破坏样本
```

`decode` 退出码：0 全部完好；3 发现坏帧/间隙（完好的帧照常输出）。
`corrupt` 模式：`insert-magic`（插入伪魔数）、`drop`（截断头/删字节）、
`flip`（单 bit 翻转）、`wrong-table`（换成另一张合法码表并重算头 CRC）。

## 测试

```sh
GO111MODULE=on go test ./...
```

覆盖：往返一致；载荷含魔数不当帧头；伪魔数插入、截断头、错误码表、
单 bit 翻转（载荷/头部）各自的分块（1/13/整块）投喂核对——后续完整帧
**只读一次**、错误范围覆盖实际破坏、预算暂停恢复不漏字节；
单 bit 翻转必被检出（逐字节逐位遍历）。
