# failreduce

失败配置缩减工具：调用一个给定的**确定性判定程序**（oracle），在保持配置项
依赖合法的前提下，把触发目标测试失败的配置缩减到 **1-最小** —— 在结果集合中，
再删除任何单项（连同依赖它的项）都不再复现失败。

## 判定程序契约

oracle 是任意可执行程序，通过退出码报告判定结果：

| 退出码 | 含义 | 缩减器如何处理 |
|---|---|---|
| 0 | 通过（未复现失败） | 候选被拒绝 |
| 1 | **目标测试失败**（感兴趣的失败） | 候选被接受 |
| 2 | **编译失败** | 与目标失败区分，候选被拒绝，单独计数 |
| 其他 | 判定程序异常 | 缩减立即中止（确定性前提被破坏） |

配置以**规范化形式**（去重、字典序排序）传递给 oracle：默认作为尾部参数，
或用 `--oracle-stdin` 改为标准输入逐行传入。

## 依赖合法性

`--deps FILE` 声明依赖，每行 `item: dep1 dep2 ...`（`#` 为注释）：

```
ui: api
api: auth
cache: db
```

`item` 依赖的项必须同在配置中。缩减器删除某项时，会级联删除所有（传递）
依赖它的项，因此**提交给 oracle 的每个配置都是合法的**；初始配置不合法则
直接报错退出。

## 算法

1. **粗粒度阶段**（ddmin 风格）：把配置切成 n 块，尝试整块删除（带依赖
   级联），成功则重来，否则加倍块数。
2. **单项阶段**（保证阶段）：反复尝试删除每一个单项及其依赖者，直到
   没有任何单项删除能复现失败 —— 此时输出即为 1-最小集合。

候选仅当 oracle 返回退出码 1（目标测试失败）时才被接受；编译失败（退出码
2）不算失败复现。

## 判定缓存

所有判定按**规范化配置键**（排序去重后的项集合）缓存：同一集合无论项的
顺序、重复如何，只实际调用一次 oracle。`--verify` 利用这一点零成本复查
1-最小性（全部命中缓存）。

## 用法

```
failreduce --oracle ./oracle.sh --deps deps.txt --items-file items.txt [--verify] [--json]
```

选项：

- `--oracle PATH`：判定程序路径（必需）
- `--oracle-arg ARG`：传给 oracle 的固定参数（可重复）
- `--oracle-stdin`：配置通过 stdin 而非 argv 传递
- `--timeout D`：单次判定超时（默认 60s）
- `--deps FILE` / `--items a,b,c` / `--items-file FILE`
- `--verify`：缩减后复查 1-最小性（纯缓存命中，不增加判定次数）
- `--json`：机器可读输出

输出包含缩减后的集合与统计信息：**实际判定次数**（oracle 真实调用数，即
缓存未命中数）、缓存命中数，以及三种判定各自的出现次数。

工具自身退出码：`0` 成功；`1` 用法错误；`2` 前置条件不满足（初始配置
不合法或不复现目标失败）；`3` 判定程序执行异常。

## 示例

```
cd examples
failreduce --oracle ./oracle.sh --deps deps.txt --items-file items.txt --verify
```

将 `{ui api auth db cache logging}` 缩减为 `{cache db}`，实际判定 9 次，
其中区分出 2 次编译失败。
