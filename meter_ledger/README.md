# meter_ledger — 有理数采样曲线的版本化计量账本

纯标准库 Python 实现,不连接真实计量设备。把采样、校准和积分查询的
版本关系真正做出来:迟到数据与追溯校准以"撤销 + 替换"的差量发布,
崩溃后可从日志与检查点恢复,重放不会重复扣减。

## 运行

```bash
cd meter_ledger
python3 demo_recovery.py              # 场景 + 崩溃恢复演示
python3 -m unittest test_meterledger -v # 测试(含独立全量重算)
```

## 验证场景(阶梯模式)

采样 `(0,2) (10,5)`,查询 `A=[0,12)` 积分 **30**;补 `(4,3)` 后 **36**。
再注册 `B=[3,9)`,声明断测 `[6,8)`,校准 v1 自 `t=5` 起 `scale=2`:

| 查询 | 结果 | 积分 | 缺测 | 采样v | 校准v | 说明 |
|------|------|------|------|-------|-------|------|
| A | r1 | 30 | 0 | 2 | 0 | 初始 |
| A | r2 | 36 | 0 | 3 | 0 | 补采样 (4,3) |
| A | r3 | 30 | 2 | 3 | 0 | 断测 [6,8) |
| A | r4 | 49 | 2 | 3 | 1 | 校准 @5 |
| B | r1 | 17 | 0 | 3 | 0 | 初始 |
| B | r2 | 11 | 2 | 3 | 0 | 断测 [6,8) |
| B | r3 | 17 | 2 | 3 | 1 | 校准 @5 |

每次替换都先撤销旧结果再发布新结果(见 `demo_recovery.py` 输出)。

## 设计

- **有理数**:`Fraction` 表示时间与值,积分精确无浮点误差。
- **插值**:`step`(阶梯,末段开放外推)与 `linear`(梯形积分,
  尾部按最后值外推);首个采样点之前计为未知。
- **断测**:用户声明 `[a,b)`;查询返回 `(已知部分积分, 缺测长度)`,
  断测区间不参与积分、不当零值,`Result.complete` 标记是否完整。
- **版本模型**:采样/断测按序号,校准按版本号,结果按 `查询:rN`;
  曲线只增不改(同时刻改值也追加),任意历史版本组合可重放。
- **增量修正**:迟到采样只影响相邻段,断测只影响声明区间,校准只
  影响 `[生效时刻, ∞)`;相交查询按"旧区间值 − 新区间值"打补丁,
  不重算整段历史,不相交查询完全不动。
- **差量发布**:稳定 ID `结果ID:revoke|publish`,日志位置单调递增,
  消费者确认位置(`confirmed_position`)随检查点持久化。
- **恢复**:生产者重放日志,对"已撤销未替换"的查询补发同 ID 差量;
  消费者按 ID 去重,重启重放不会重复扣减。
- **检查点**:未闭合采样段(尾部开放段)+ 查询索引 + 去重状态,
  原子写(`tmp` + `replace`)。

## 文件

```
meterledger/
  curve.py      采样曲线:插值、断测、校准时间线、按版本积分
  ledger.py     账本:查询版本化、增量修正、差量发布、恢复重放
  journal.py    追加式事件日志(JSONL,带位置)
  consumer.py   差量消费者:幂等应用、确认位置
  checkpoint.py 检查点读写
demo_recovery.py    场景验证 + 崩溃恢复演示
test_meterledger.py 单元测试 + 独立全量重算对照
```

## 限制

单进程、单日志文件;检查点是生产者快照与消费者进度的合订视图,
日志仍是事实之源(恢复以重放为准,检查点用于去重与快速定位)。
