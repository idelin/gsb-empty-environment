# 规则遮蔽分析器 (shadowanalyzer)

按**顺序首次匹配**语义分析权限规则表：请求自上而下匹配，第一条命中的规则生效。
本工具找出**永远无法生效**的规则，给出覆盖它的**最小前序规则集合**；
对**部分遮蔽**的规则给出一条仍可生效的**见证请求**。

## 模型

- **主体域 / 动作域**：有限集合，规则中可用具体值或 `*`（匹配域中任意值）。
- **路径模式**：有限深度片段序列，每段为字面量、`*`（恰好一个片段）或 `**`（零个或多个片段）。
- **请求**：`(主体, 动作, 路径)` 三元组。

## 判定方法（非文本比较）

文本比较或单条包含关系都不足以判定遮蔽——多条前序规则的**并集**才可能覆盖目标
（例如按主体切分的两条规则联合覆盖一条 `*` 规则）。本工具的做法：

1. 主体×动作域有限，逐对枚举目标规则适用的 `(主体, 动作)`。
2. 路径模式编译为 NFA。片段名字无限，但模式只测试与字面量的相等性，
   故字母表取「全部规则出现过的字面片段 + 一个代表任意其它片段的符号」即可精确建模。
3. 在「目标 NFA × 前序规则 NFA 子集构造」的乘积图上 BFS：
   - 存在被目标接受、却不被任何前序规则接受的路径 → 该路径即**可生效见证**（部分遮蔽）。
   - 所有 `(主体, 动作)` 对下都不存在 → 规则**完全遮蔽**（语言包含于前序并集）。
4. 完全遮蔽时求最小覆盖集：候选 ≤14 时按子集大小递增枚举求**精确最小**，
   否则贪心删除求极小集合。

## 使用

```sh
go run . -i example.json          # 文本报告；存在完全遮蔽规则时退出码为 1
go run . -i example.json -json    # JSON 报告
cat example.json | go run .       # 标准输入
go test ./...                     # 运行测试
```

输入格式见 `example.json`。输出中每条规则分类为：

- `unshadowed`：与前序规则无任何重叠，附一条可生效见证；
- `partially_shadowed`：部分请求被前序规则截获，附一条仍可生效的见证请求；
- `fully_shadowed`：永远无法生效，附覆盖它的最小前序规则集合 `coveredBy`。

见证路径中的 `other` 片段名代表「任意未在规则中出现过的片段」。

## 校验

`MatchPath(pattern, path)` 提供具体请求与模式的匹配判定，测试中用它逐条验证
分析器给出的见证：必须匹配本规则、且不匹配任何同 `(主体, 动作)` 下适用的前序规则。
