# grayalloc — 策略灰度分配器

升级灰度时，把不可分割的用户组整体分配到旧版/新版，使新版总人数落在
精确区间 `[min_new, max_new]` 内，并尽量少迁移用户。若整组分配无法达到
精确比例，输出可验证的不可行证明，绝不拆组凑数。

## 模型

- 每组用户必须同版本（整组切换，禁止拆组），组数 ≤ 20。
- 目标：新版总人数 ∈ `[lo, hi]`（由显式区间或 `ratio ± tolerance` 推出，
  整数区间向外取整，绝不夸大比例带）。
- 优化目标：先最小化迁移用户数，再最小化迁移组数，最后按位掩码取确定解。

## 算法

折半枚举（meet-in-the-middle），精确求解，复杂度 O(2^(n/2) · n)：

1. 把 n ≤ 20 组分成两半，各枚举 2^(n/2) 种子集，记录
   （新版人数, 迁移用户数, 迁移组数, 掩码）。
2. 右半按人数排序去重（同人数只留最优），建稀疏表做区间最小值查询。
3. 对每个左半和 s，在右半二分出入 `[lo-s, hi-s]` 的范围并 O(1) 查询最优，
   合并取全局最优。

不可行时输出 gap 证书：区间内无任何可达人数，并给出区间两侧最近的可达
人数（`Below`/`Above`），可由同样的折半枚举独立验证；当所有组大小的
gcd > 1 时附带同余证书（可达人数必为 gcd 的倍数）。

## 使用

```sh
go build -o grayalloc .
./grayalloc examples/feasible.json     # 或: cat input.json | ./grayalloc
```

输入（`min_new`/`max_new` 与 `ratio`/`tolerance` 二选一，显式区间优先）：

```json
{
  "ratio": 0.30,
  "tolerance": 0.01,
  "groups": [{"id": "vip", "size": 500, "on_new": true}]
}
```

输出：可行时给出每组决策、新版人数、迁移用户数/组数，退出码 0；
不可行时 `feasible: false` 并附 `proof` 文本，退出码 1。

## 测试

```sh
go test ./...
```
