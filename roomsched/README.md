# roomsched — 会议室合并调度工具

相邻房间可合并成大会议室，合并与拆分（恢复）都占用准备时间，会议中途不可换房。
对最多 16 场会议，求 **拒绝权重最小** 的安排，次目标 **拆合次数最少**，并输出房间状态时间线。

## 模型约定

- 房间排成一行，只有相邻房间可合并；合并块容量为各房间容量之和。
- 每次合并/拆分耗时 `prep`，施工期间两侧房间不可用于会议；不同边界（隔墙）的施工可并行。
- 拆合采用“就近准备”策略：在需要它的会议开始前紧邻完成（首场会议之前视为一直空闲）。
- 会议固定占用一个连续房间块，中途不换房；合并块存续期间，其房间不可被单独分配。

## 算法

会议按开始时间排序后 DFS + 记忆化：状态为 `(会议序号, 分区位掩码, 各房间空闲时刻)`，
每场会议枚举“拒绝”或“放入某个容量足够的连续块”，按 `(拒绝权重, 拆合次数)` 字典序取最优。
房间数 ≤ 10，会议数 ≤ 16。

## 用法

```sh
go run .                # 运行内置演示
go run . example.json   # 从 JSON 文件读入
go test ./...           # 运行测试
```

输入格式见 `example.json`：`prep` 为准备时间，`rooms` 按物理顺序给出，
`meetings` 中 `start/end` 为半开区间，`size` 为所需容量，`weight` 为拒绝代价。

## 输出与校验

输出接受/拒绝会议清单、拆合操作序列、每房间状态时间线；
随后由独立校验器复核：容量、不换房、准备时间、**合并排他性**
（两间被合并期间不能再分别分配）、各房间时间线无重叠、账目一致。
