# bitlayout — 位级记录布局编译器

纯 Go 标准库实现。输入是本地 JSON 布局描述，输出是可复用的编码函数与
增量解码计划（`Plan`）。只支持一个明确写定的子集：

- **定宽整数**：`uint`（1..64 位）、`int`（二进制补码，1..64 位），`uint`
  可带 `enum` 合法值表；
- **数组**：元素数由先前 `uint` 字段（`lengthFrom`）决定，元素是字段组，
  可嵌套；
- **联合**：由先前标签字段（`tagFrom`）选择分支，各分支长度可不同；
- **对齐填充**：`align` 填充到指定位倍数，保留位必须为零；
- **校验字段**：`checksum` 覆盖指定已编码区间（`from` 字段起点到 `to`
  字段终点），算法 `sum`（流序字节求和取模 2^bits，末尾不足一字节右侧
  补零）。

## 位序与字节序是两个独立属性

- `bitOrder`（`msb`/`lsb`）：流位置如何映射到字节内的位。`msb` 时流位置
  0 是字节 0 的最高位；`lsb` 时是最低位。
- `byteOrder`（`big`/`little`）：多字节字段的值如何流入比特流。`big`
  先发射最高有效位；`little` 把值按 8 位分组，最低有效组先发射，组内仍
  高位在前。

四种组合语义互不依赖，测试中全部与独立逐位参考实现交叉验证。

## 编译期拒绝

`Compile` 在校验阶段拒绝：

- **向前长度引用**：`lengthFrom`/`tagFrom`/校验区间只能引用同一层级中
  先前定义的字段；
- **循环依赖**：引用边只指向先前字段，结构上不可能成环，编译器仍做显式
  DFS 环检测兜底；
- **字段覆盖**：同一层级字段名重复即拒绝；校验区间为空或倒置也拒绝；
- **未定义标签**：标签字段声明了 `enum` 时，联合必须为每个枚举值提供
  分支，且不允许枚举之外的分支标签；
- **无界分配**：数组最大元素数 × 元素最大位数的乘法溢出（如 64 位长度
  字段）直接拒绝；可用 `maxLength` 收紧上界；嵌套深度超过 8 拒绝。

## 编码：先验证，后原子写入

`Plan.Encode(obj, dst)` 分两遍执行：

1. 验证整棵对象树（字段存在性、类型、取值范围、enum、数组长度与长度
   字段一致、标签有定义）并精确计量总位数，检查目标容量；
2. 仅在全部验证通过后写入调用方缓冲区。

任何失败（包括最后一个数组元素越界、容量不足）都保证 `dst` 未被修改。

## 解码：可停在任意一位的增量会话

`Plan.NewSession(quotas)` 创建会话，`Feed`/`FeedBits` 追加输入（可停在
任意位边界），`Run` 推进状态机：

- `ErrNeedInput`：输入不足，可恢复，补数据后再次 `Run`；
- `ErrReservedBits`：对齐保留位非零；
- `ErrIllegalValue`：值越界、enum 不符、未定义标签、校验和不匹配；
- `ErrQuota`：元素数、总位数或嵌套深度超额，含长度乘法溢出。

错误携带 schema 路径（如 `telemetry.samples[2].v`）与输入位偏移。
`Result` 只在整条记录（含尾部校验）验证通过后交付——失败会话永远不
交付半个记录。

## 并发

编译出的 `Plan` 不可变，可被任意数量的编码器与解码会话并发共享；每个
会话的游标、缓冲与额度记账完全私有。`go test -race ./...` 通过（16 个
goroutine 共享同一 plan 交叉编码/逐字节增量解码，无数据竞争报告）。

## 执行开销推导

记 schema 含 F 个字段、编译后 P 条解码指令（P ≤ 2F + 分支数 + 1），
实际记录含 B 位、E 个数组元素、嵌套深度 D（≤8）：

- **编译**：Θ(F) 次字段校验 + Θ(P) 指令发射；内存 Θ(P)。校验区间、
  依赖检查均为每字段 O(1)（同层名字典查询）。
- **编码**：两遍走读，每遍 Θ(B) 位操作 + Θ(实际字段数) 次值校验；校验
  和另加 Θ(覆盖位数)。额外内存 Θ(D)（每层一张位置表）。无隐藏分配。
- **解码**：每条指令 O(1) 状态转移，总计 Θ(B) 位读取 + Θ(E) 元素帧
  记账；会话状态 Θ(D)，输出对象 Θ(记录大小)。额度检查每数组 O(1)。

实测（Apple M1 Pro，telemetry 示例，88 位记录含 8 个数组元素）：

```
BenchmarkCompile-10   10196 ns/op   （7 字段 / 13 指令的 schema）
BenchmarkEncode-10     7432 ns/op   ≈ 85 ns/bit，含完整验证与计量
BenchmarkDecode-10     8448 ns/op   ≈ 96 ns/bit，含结果对象分配
```

开销随 schema 规模（指令数 P）与实际记录大小（位数 B、元素数 E）线性
增长，与输入中未触及的分支无关。

## 验收测试覆盖

- 3 位标签 + 10 位有符号值：全部 8192 条记录 × 4 种位序/字节序组合，
  编码字节与解码结果同独立逐位参考实现逐一比对；
- 两种不同长度联合分支：全部 65536 个 16 位输入模式，错误类别与结果
  同参考实现一致；
- 跨字节数组（3 位计数 + 5 位元素）：小规模穷举 + 大计数采样；
- 尾部校验：翻转校验域每一位都报 `ErrIllegalValue` 且不交付结果；
- 整块输入的全部字节切块方式（2^(n-1) 种）与逐位停止点，结果与整块
  解码完全一致；
- 编码最后一个元素越界 / 容量不足：目标缓冲区逐字节不变；
- 竞态：`go test -race` 通过。

## 快速上手

```sh
go run ./cmd/bitlayout check  examples/telemetry.json
go run ./cmd/bitlayout encode examples/telemetry.json examples/telemetry.obj.json
go run ./cmd/bitlayout decode examples/telemetry.json 3edc94983fa227
```

`examples/sensor-lsb.json` 演示 `lsb` 位序 + `little` 字节序、联合内嵌
数组的组合。
