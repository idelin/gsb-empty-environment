# 离线上下文解析安全模型

本包面向 TypeScript 凭证宿主，在**完全离线**前提下解析 JSON-LD 上下文，并把缓存
复用建立在语义键而非 URL 字面值之上。

## 信任根

- 每个上下文对象以其确定性规范化 JSON 字节的 SHA-256 摘要作为内容标识
  （`sha256:<hex>`）。键序、空白差异不会改变标识。
- 信任清单 `TrustManifest` 枚举允许的内容标识与摘要，使用 Ed25519 对清单的
  规范化字节签名；公钥以 SPKI（base64url）内嵌，并由 `rootKeyId` 锚定。
- 解析时先验签清单，再对每个读取到的上下文重新哈希并与白名单比对。
  `@import` 只接受内容标识；任何 URL 字符串都会因不在白名单而被拒绝。

## 解析规则

- `@import` 支持字符串或字符串数组，链深硬性上限为 4；祖先帧重复访问判定为环，
  环与超深都在信任读取前后保持故障闭合。
- `@propagate: false` 通过完整状态快照/恢复实现：`@vocab`、`@base`、术语绑定、
  嵌套作用域与受保护注册都不会泄漏到外层帧。
- `@nest` 采用两趟处理：先把术语停泊到命名作用域，再通过同一套受保护碰撞引擎
  重放，因此解包后折叠到同一受保护字段的别名无法绕过保护。
- `@reverse` 与正向属性共享 IRI 索引并做交叉检查；`@type` 仅接受强制的
  `@id` 与 `@vocab`，其它类型直接拒绝。
- 未知关键字（如自定义 `@xxx`）无法暗中改写受保护语义，会触发
  `UNKNOWN_KEYWORD_REWRITE`。

## 受保护碰撞的硬拒绝

以下情况一律硬拒绝，即使取值完全相同：

- 不同内容标识对同一受保护术语的重复定义；
- 别名（含 `@nest` 解包出来的别名）折叠到已受保护的 IRI；
- 反向/正向跨方向折叠到同一受保护字段；
- 未受保护术语试图折叠到某个受保护 IRI。

唯一的例外是**同一内容标识的幂等重复**（例如菱形导入中同一叶子出现两次），
它不引入新语义，按幂等处理。

## 诊断契约

所有错误抛出 `ContextResolutionError`，其 `diagnostic` 恒为完整对象：

```json
{
  "code": "PROTECTED_ALIAS_COLLISION",
  "message": "...",
  "offendingTerm": "",
  "offendingCid": "",
  "importPath": [],
  "depth": 0,
  "detail": ""
}
```

可空/缺省信息用空字符串或空数组表达，序列化结果绝不出现 `undefined`。

## 语义缓存键

缓存键是对以下描述符整体的内容哈希：

1. 签名信任清单根（清单标识、根密钥 id、根 SPKI 公钥）；
2. 完整有序的上下文栈（每个帧的内容标识）；
3. 完整的 `@protected` 映射（含定义指纹与来源标识）；
4. 当前 `@vocab`；
5. 当前 `@base`。

`validateDescriptor` 独立核验描述符：URL 字面栈、缺帧、缺受保护映射、缺
`@vocab`/`@base` 绑定都在查找前被拒绝。缓存条目还携带**最小充分来源闭包**
（上下文栈与所有受保护定义来源的并集），闭包不足的条目不允许写入或命中。

## 离线与只读

模块图不引入任何网络能力（无 `http`/`https`/`net`/`tls`/`dns`/`undici`/
`fetch`）。验收包默认只向标准输出写报告；`--out` 是唯一可选落盘，且只写报告本身。
