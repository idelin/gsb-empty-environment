RFC 9114 HTTP/3 跑在 QUIC 传输流之上，把帧路由、关键单向流、GREASE 抗僵化保留值与 HTTP 伪头语义紧密绑定，四类规范红线极易写错：1）**关键单向流唯一性与防关闭**：每端必须通过单向流携带流类型 VarInt 开启至多 1 条 Control Stream（`0x00`）、1 条 QPACK Encoder Stream（`0x02`）与 1 条 QPACK Decoder Stream（`0x03`）；对端重复开启同类型关键流必须立刻触发 `H3_STREAM_CREATION_ERROR`，任意关键流被关闭或重置立刻触发 `H3_CLOSED_CRITICAL_STREAM`，且 Control Stream 的**第一帧必须是 `SETTINGS`**（首帧为其他任何帧报 `H3_MISSING_SETTINGS`，后续再出现第二帧 `SETTINGS` 报 `H3_FRAME_UNEXPECTED`！）；2）**GREASE 保留帧/设置 vs HTTP/2 禁用设置区分**：所有满足 `0x1f * N + 0x21` 形式的未知帧类型、单向流类型与 `SETTINGS` 标识符必须静默忽略跳过（绝不可当协议错误！）；但 RFC 9114 §7.2.4.1 明确禁止在 HTTP/3 `SETTINGS` 中出现原 HTTP/2 保留标识符 `0x02`、`0x03`、`0x04`、`0x05`（收到必须立刻报 `H3_SETTINGS_ERROR`！），且同一 `SETTINGS` 帧内出现重复 ID 同样报 `H3_SETTINGS_ERROR`！3）**流类型与帧归属矩阵及请求流状态机**：双向请求流仅接受 `HEADERS`、`DATA` 与 GREASE 帧，且合法帧序只能是可选的 1xx 信息响应头 -> 单个主 `HEADERS` -> 零或多个 `DATA` -> 至多一个尾 `HEADERS`（Trailers），任何越序或在控制流/请求流间错放帧（如请求流收 `GOAWAY`、控制流收 `DATA`）立刻报 `H3_FRAME_UNEXPECTED`；4）**严格 HTTP 伪头与 `GOAWAY` 单调截断**：校验所有伪头必须位于普通头之前、不可重复、禁止出现 HTTP/1.1 逐跳连接头（`connection`/`keep-alive`/`transfer-encoding`/`upgrade` 及值不为 `trailers` 的 `te`！），区分常规请求与 `CONNECT` 请求的伪头规则，并校验对端发出的 `GOAWAY(streamID)` 仅允许为合法客户端双向流 ID（`id % 4 == 0`！）且后续 `GOAWAY` 的 ID 严格非增（增大报 `H3_ID_ERROR`！）。为边缘接入网关交付可导入的 Go RFC 9114 HTTP/3 协议状态机与帧校验包。验收覆盖重复/关闭关键流报错、首帧非 `SETTINGS` 与重复设置 ID、GREASE 静默跳过 vs HTTP/2 `0x02..0x05` 禁用拦截、请求流 1xx+主头+DATA+Trailers 状态序、伪头与逐跳头校验以及 `GOAWAY` 四倍校验与单调递减截断。
