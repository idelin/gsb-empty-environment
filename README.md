Kubernetes 节点代理（kube-proxy）在处理 `externalTrafficPolicy: Local`、`sessionAffinity: ClientIP` 与优雅终止端点（`Terminating`）交错的场景时，极易违背数据面核心契约：配置 `externalTrafficPolicy: Local` 的外部流量若在目标节点找不到本机 `ready` 端点，一旦跨节点转发并做 SNAT 就会破坏客户端真实源 IP——正确行为是仅回退到本机 `serving && terminating` 端点，若本机仍为空则必须直接黑洞丢弃（DROP）并触发节点健康探针置为不健康！同时，已建立的 TCP 连接跟踪表项（conntrack）在后端进入 `Terminating` 状态期间必须继续把存量连接数据包路由到原后端完成优雅排空（绝不可提前重置！），但新到达的客户端连接哪怕命中了尚未过期的 `ClientIP` 粘性表项，只要原粘性后端已不再 `ready`（处于 `Terminating` 或已删除），就必须立刻打破旧粘性重新选择 `ready` 后端并刷新粘性表项！为云原生节点代理交付可导入的 Go 服务转发状态机与路由表编译包。输入为服务配置（`externalTrafficPolicy`/`internalTrafficPolicy`、`sessionAffinity` 及 `timeoutSeconds`、协议 TCP/UDP）、节点拓扑与端点变更事件流（端点 `ready`/`serving`/`terminating` 变化、端点删除）、数据包/连接流事件（新建 TCP SYN、存量 TCP 包、UDP 报文及虚拟时钟推进）。规则：1）区分外部入口流量与集群内部流量，严格按各自 `TrafficPolicy` 筛选候选后端集（含 `Local` 无本机可用端点直接 `DROP` 与健康探针状态联动，以及全无 `ready` 端点时按规范回退 `serving && terminating` 兜底！）；2）维护 `ClientIP` 粘性表（每次命中有效 `ready` 后端即重置 `timeoutSeconds` 过期时钟；原后端失活或进入 `Terminating` 时新连接立即重绑；UDP 粘性后端彻底删除时必须显式下发 conntrack 清除指令防止黑洞！）；3）维护已建立连接跟踪表（存量 TCP 流只要后端仍满足 `serving` 或尚未完全移除即持续放行至 FIN/RST 结束，彻底移除后回发 RST 并清理表项）。验收覆盖 `Local` 策略本机无端点黑洞保护与健康状态联动、存量 TCP 优雅排空 vs 新连接打破 `Terminating` 粘性、`ClientIP` 命中续期与过期重选以及 UDP 端点删除触发 conntrack 精确清理。
