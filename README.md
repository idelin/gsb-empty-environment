# dvv — Dotted Version Vectors 精确因果跟踪器

面向无主复制（Leaderless）存储的点状版本向量（Dotted Version Vectors, DVV）
去重优化实现，纯 Go 标准库，零依赖。

## 问题：传统版本向量的幽灵分支

经典版本向量把每个节点的历史压缩成连续区间 `[1..n]`。当客户端拿着
陈旧上下文写入时，新计数器（如 `a:3`）会**假装**包含它从未见过的事件
（`a:2`），造成假支配：新值静默覆盖掉并发的新数据（幽灵分支），或迫使
副本保留幻影兄弟版本。

## 方案：点状事件 + 前置向量

每次写入被打上全局唯一的**点** `(NodeID, Counter)`。一个时钟（`Clock`）=
连续前缀向量 `vv` + 前缀之外的离散点集 `dots`，精确表示该值因果上见过的
事件集合：

- `Put(key, value, ctx)`：新点 = 本节点在该键上见过的最大计数器 + 1，
  新时钟 = 上下文 ∪ {新点}。同一 Put 重放是幂等 no-op。
- `reconcile`（`Put`/`Merge`/`Sync` 共用）把版本集合归约到最小形式：
  1. 被支配版本剪枝 —— 因果覆盖不留幽灵分支；
  2. **同值并发版本融合** —— 重复写入（重试、重复广播）合并为一个版本，
     时钟取事件并集；
  3. 只有不同值的真并发才保留为兄弟版本。
- `reconcile` 满足结合律、交换律、幂等，因此副本在**乱序、重复、
  多轮广播**下必然收敛到一致状态。
- 时钟宽度为 O(节点数)，与写入次数无关：连续点折叠进向量前缀，
  只有最新点保持显式（作为值的事件标识）。

## 文件

- `dvv.go` — `Dot`、`Clock`（事件集语义：支配/并发/合并/归一化）
- `store.go` — `Store`（`Put`/`Get`/`Context`/`Merge`/`Sync`）与 `reconcile`
- `dvv_test.go` / `store_test.go` — 单元测试与乱序广播收敛模拟
- `cmd/demo/main.go` — 三副本运行样例

## 运行

```sh
go test -v ./...   # 测试
go run ./cmd/demo  # 样例：300 次高频写入 + 50 次重试 + 乱序重复广播
```
