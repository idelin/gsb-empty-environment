WireGuard 隧道协议看似极简，但其在无连接 UDP 之上实现前向安全、零中断平滑密钥轮换、抗 DoS Cookie 挑战与乱序防重放的精确状态机包含四项极易写错的硬边界：1）**三代密钥槽（`current` / `previous` / `next`）平滑交接**：每个 Peer 维护三组会话密钥对：发起方发送握手初始化后把新密钥放入 `next`，**响应方绝不可在收到首条携带该新密钥的加密数据包（含空 Keepalive）之前把 `next` 提升为 `current`**（防止握手响应包丢失导致双方密钥失步！）；一旦响应方用 `next` 成功解密首包，立刻把 `next -> current`、旧 `current -> previous` 并清空更早密钥；解密端同时支持按 `receiver_index` 命中 `current`/`previous`/`next`，而发送端始终只用 `current`；2）**硬时间与报文计数门限**：严格遵循规范常量：`REKEY_AFTER_MESSAGES = 2^60`、`REJECT_AFTER_MESSAGES = 2^64 - 2^13 - 1`、`REKEY_AFTER_TIME = 120s`、`REJECT_AFTER_TIME = 180s`、`REKEY_TIMEOUT = 5s`、`KEEPALIVE_TIMEOUT = 10s`；超过 `REKEY_AFTER_TIME`（仅由原发起方触发！）或发送计数达 `REKEY_AFTER_MESSAGES` 时异步发起新握手，但继续用当前密钥传流；一旦会话寿命超过 `REJECT_AFTER_TIME` 或计数超限，立刻**彻底拒绝加解密并清零该槽密钥**；若 `3 * REKEY_AFTER_TIME` 内仍无新会话，清零全部密钥防长期泄露；3）**TAI64N 单调时间戳与过载 Cookie 挑战**：握手初始化携带 12 字节 TAI64N 时间戳，响应方仅接受严格大于该 Peer 历史最大值的握手（拦截重放攻击！）；当节点处于高负载模式时，验证 `mac1` 后强制要求有效 `mac2`（由每 2 分钟轮换的随机秘密与源 IP/端口派生的 Cookie 计算），无效时返回 Cookie Reply 而不分配任何握手状态；4）**RFC 6479 64 位计数滑动位图防重放窗口**：为每个密钥槽独立实现 2048 位滑动防重放窗口，正确处理乱序延迟包、重复包拒绝、超大跳跃推进（超过窗口大小时整块清零并前移！）以及低序号过期包拒绝。为加密隧道引擎交付可导入的 Go WireGuard 会话轮换、Cookie 抗过载与 RFC 6479 防重放核心包。验收覆盖响应方未收首包前 `next` 不提升、三代槽无损切换与 `180s` 硬拒清零、TAI64N 严格单调拦截重放、高负载 `mac2` Cookie 挑战以及 RFC 6479 窗口边界/大跳跃/重复包全覆盖测试。
