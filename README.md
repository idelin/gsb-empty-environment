邮件投递服务有多个 MX、交叉签发证书和不同信任锚。给 Go 投递宿主写可导入的授权选择包。宿主提供已验签的候选证书边和已通过 DNSSEC 验证的记录集；每个 MX 的记录可约束叶子公钥或路径上 CA 公钥，每条还限制证书有效时段、所需用途和一组必须在同一路径成立的命名空间约束。路径不能有环，同一公钥的不同证书不能互换其名称约束；不得从甲路径取信任锚再从乙路径取用途。输入最多18张证书。为每个 MX 返回合法时间集合，随后为一批指定的投递时刻选择最少的路径证书组合覆盖全部时刻，路径可在不连续时段复用，不能仅按最远结束时刻贪心。并列按证书指纹序列排序。拒绝证书除具体未覆盖时刻外还须列出缺失的约束类别。用真实生成的交叉签发证书和独立小图穷举检查，覆盖同钥双证书、多个用途分别匹配却无共同路径、证书换日及吊销切开原先连续时段。
