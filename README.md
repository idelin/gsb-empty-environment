# 带权 Max-CSP 分支定界求解器

软约束优化求解器:当所有约束无法同时满足时,为每个软约束赋予破坏惩罚权重,
使用**分支定界(Branch and Bound)**在保证全部硬约束绝对成立的前提下,
寻找**加权违反代价最小**的全局最优赋值。

纯 TypeScript 实现,零依赖,使用 Node.js 内置测试运行器(`node:test`)验证。

## 环境要求

- Node.js >= 22.6(利用原生 TypeScript 类型擦除直接运行 `.ts`,无需编译)

## 运行

```bash
npm test        # 运行全部测试(node --test)
npm run demo    # 运行任务排期求解样例
```

## 问题模型

- **变量**:有限离散域,`{ name, domain }`
- **硬约束**:`consistent(部分赋值)` 仅当部分赋值已无法扩展为满足该约束时返回
  `false`,用于搜索中提前剪枝;最优解中硬约束绝对成立
- **软约束**:`violated(完整赋值)` + 惩罚权重 `weight`;目标最小化被违反软约束
  的权重之和

## 分支定界设计(`src/solver.ts`)

- **分支**:深度优先;变量按"关联约束最多优先"静态排序;取值按"即时惩罚增量"
  升序尝试,尽早获得优质 incumbent 以加强剪枝
- **定界**:下界 = 已完全实例化且被违反的软约束权重和(未完全实例化的软约束
  乐观估计为 0,下界可采纳,保证全局最优)
- **剪枝**:下界 >= 当前最优代价即剪去子树;硬约束一致性检查失败的分支不展开
- 附 `bruteForce` 暴力枚举求解器,用于交叉验证分支定界结果

## 验收场景:任务排期(`src/scheduling.ts`)

5 个任务(T1 需求评审 / T2 原型开发 / T3 接口联调 / T4 压力测试 / T5 发布部署)
分配到 3 个时段(周一上午 / 周一下午 / 周二上午)。

- **硬约束(3 条)**:H1 T1≠T2(设备A)、H2 T3≠T4(设备B)、H3 T5≠T2(人员)
- **软约束(5 条)**:均为"尽量周一上午",权重 S1=10、S2=8、S3=3、S4=2、S5=1

冲突结构:H1 使 S1、S4 至多满足其一(代价 >= 2),H2 使 S2、S5 至多满足其一
(代价 >= 1),故总惩罚下界为 3。全局最优恰好违反两条最次要的软约束
S4(w=2) 与 S5(w=1),总惩罚 = 3。

## 运行样例(`npm run demo`)

```
=== 带权 Max-CSP 分支定界求解:任务排期 ===

任务与可选时段: T1..T5 ∈ {1=周一上午, 2=周一下午, 3=周二上午}
硬约束: H1(T1≠T2 设备A)  H2(T3≠T4 设备B)  H3(T5≠T2 人员)
软约束: S1(w=10,T1→1) S2(w=8,T3→1) S3(w=3,T5→1) S4(w=2,T2→1) S5(w=1,T4→1)

--- 最优排期表(分支定界) ---
  T1 需求评审  ->  周一上午
  T2 原型开发  ->  周一下午
  T3 接口联调  ->  周一上午
  T4 压力测试  ->  周一下午
  T5 发布部署  ->  周一上午

违反的软约束: S4, S5 (共 2 条)
  S4: 惩罚权重 2
  S5: 惩罚权重 1
总惩罚代价: 3
搜索统计: 展开节点 17 个, 剪枝 21 次 (全空间叶节点 243 个)

暴力枚举交叉验证: 最优代价 3 (叶节点 243 个)
✔ 分支定界结果与全局枚举一致,确为全局最优。
```

## 测试结果(`npm test`)

```
✔ 存在可行解且所有硬约束绝对成立
✔ 全局最优:恰好违反 2 条最次要的软约束 S4、S5
✔ 总惩罚最小,等于理论下界 3 (S4=2 + S5=1)
✔ 分支定界结果与暴力枚举的全局最优一致
✔ 剪枝有效:展开节点数远小于全空间叶节点数 243
✔ 最优解不违反权重更高的 S1/S2/S3
✔ 随机实例交叉验证:分支定界代价 == 暴力枚举最优代价 (100 组)
✔ 硬约束不可满足时返回 null 与 Infinity
✔ 无软约束时任意可行解代价为 0
✔ 全部软约束可满足时代价为 0 且无违反
ℹ tests 10  ℹ pass 10  ℹ fail 0
```
