# tx-invariants

事务化跨字段不变量检查（TypeScript，零依赖，不使用任何响应式框架）。

## 运行

需要 Node.js ≥ 22.14（`--experimental-strip-types`）或 ≥ 23.6（免 flag）：

```sh
npm test        # node --experimental-strip-types --test test/store.test.ts
npm run demo    # node --experimental-strip-types demo.ts
```

## 设计

- **注册跨字段不变量**：`store.registerInvariant(name, check)`，`check(ctx)` 通过
  `ctx.get(field)` 读取字段，返回字符串表示违反、抛错也算违反；注册时立即在当前
  状态上校验并建立初始依赖。
- **提交前只检查受影响规则**：每次求值都记录规则实际读到的字段集合（依赖边）。
  提交时只重跑「旧依赖 ∩ 变更字段 ≠ ∅」的规则。对纯规则这是可靠的：旧依赖未变
  则分支决策与读取集合不变。
- **条件分支导致依赖变化**：被波及的规则在**事务草稿**上重新求值并重新追踪依赖，
  验证用的是草稿上的实际依赖，不沿用旧依赖；只有提交成功才持久化新依赖边。
- **共享纯计算**：`store.defineComputed(name, fn)` 注册的纯计算在同一验证轮次内
  按名称记忆化，多条不变量共享一次求值；缓存命中同样会把计算的依赖并入调用方
  的依赖集（否则会造成漏检，见测试 `randomized differential run`）。
- **失败信息**：`CommitFailure` 携带 `violations`（规则、消息、涉及字段、异常）、
  `fields`（涉及字段并集）与 `counterexample`——对事务操作做贪心 1-最小约简后的
  最小相关操作子集，`failure.replay()` 可在当前已提交状态上重放反例。
- **原子拒绝**：验证失败的提交不触碰状态、历史与依赖边；草稿与临时依赖全部丢弃。
- **隔离与回放**：读者只能拿到已提交的冻结快照，永远看不到事务中间态；订阅者
  只在提交成功后收到一次最终快照，且在订阅回调内提交会直接抛错，杜绝
  「订阅后修正」掩盖非法提交。操作是纯数据（`set`/`delete`），
  `store.history()` + `Store.replay()` 可完整回放。

## 验证

`test/store.test.ts`（Node 内置 `node:test`，16 个用例）覆盖：

- 余额类合成数值下界与总和约束同时检查、共享纯计算只求值一次
- 不相关字段不触发昂贵规则（求值计数器断言）
- 条件分支翻转后依赖边更新，后续只改 `used` 的事务被新依赖捕获（旧依赖会漏检）
- 失败返回涉及字段 + 最小可重放反例（含 1-最小性断言）
- 拒绝后状态对象同一性、依赖边、历史全部不变
- 规则抛错使提交失败；读者/订阅者看不到中间态；订阅者无法修正
- 小事务枚举对照（单/双操作全组合）与 500 轮随机差分：增量剪枝结果与
  逐条全验完全一致，且每次提交后依赖边与全量重追踪一致
