# 最小代价换行 (optimal-line-breaking)

TypeScript 实现的最优换行排版: 按**词宽、伸缩空格与断词罚分**选择最小代价断点,
节点树与字形度量全部由夹具给出, 不借浏览器布局引擎完成核心计算。零依赖,
使用 Node.js 内置测试运行器验证 (Node >= 22.6, 利用内置类型擦除直接运行 `.ts`)。

## 运行

```sh
nvm use 23        # 或任意 >= 22.6 的 Node
npm test          # Node 内置测试 (node:test)
npm run sample    # 运行样例: 贪心/DP/穷举对照/预算中断/增量编辑
```

## 代价模型

节点树 (`word` 可含断词片段, `space` 含理想宽/拉伸/收缩) 展开为
盒/胶/罚点元素流 (`src/elements.ts`)。每行 (`src/cost.ts`):

- `剩余宽 = 行宽 - 自然宽`; 剩余 >= 0 时 `劣度 = (剩余/总拉伸)^2`,
  剩余 < 0 且在收缩量内时 `劣度 = (|剩余|/总收缩)^2`;
- 最后一行剩余 >= 0 时劣度为 0;
- 断在断词点加收断词罚分, 行尾补连字符宽;
- **不可断长词** (行内无空格即单词超行宽): 允许溢出, 收 `overflowPenalty + overflowWeight * 溢出宽`,
  单独报告, 不会死循环;
- 相邻行加收 `adjacencyWeight * |上一行剩余 - 本行剩余|` (相邻行宽度差罚分)。

## 带历史约束的 DP (`src/dp.ts`)

状态为 `(a, b, h)`: 最近两个断点 `a`、`b` 与已用断词次数 `h`:

- `a` 提供上一行剩余宽 -> 相邻行宽度差罚分;
- `b` 的元素类型提供"上一行是否断词结尾" -> **禁止连续断词**;
- `h` 提供**跨行一致的断词次数上限**。

转移只走向更大断点, 单趟按断点升序松弛即可; **相同代价按较早断点决胜**
(状态转移取更小的前一断点, 终态取更小的末断点)。输出每行度量
(自然宽/剩余/伸缩/劣度/断词罚/邻行罚/溢出) 与累计成本作为决策证据。

## 对照与报告

- `src/greedy.ts`: 首次可行贪心, 仅作启发式对照, **不声称最优**;
  夹具"贪心陷阱"中贪心 1.0 vs DP 0.64。
- `src/exhaustive.ts`: 小段落穷举全部断点序列, 与 DP 同一可加代价模型交叉验证;
  超预算即**预算中断**, 单独报告且不作最优性结论。
- 报告 (`src/report.ts`) 将**负剩余宽行**、**不可断长词溢出**、**预算中断**分开列出。
- `src/incremental.ts`: 增量编辑时, 旧 DP 表中断点落在未变元素前缀内的状态
  (前沿) 成本不变, 直接作为种子复用, 只重算受影响后缀; 输出逐步证书
  (编辑定位 -> 前沿重用 -> 继续搜索 -> 最优成本 -> 全量重算交叉校验)。

## 测试结果

`npm test` (node:test, 14 项全部通过):

- DP 与穷举对照一致: 短段落 / 贪心陷阱 / 同代价决胜 / 断词约束;
- 贪心非最优样例: DP 严格更低 (0.64 < 1.0);
- 相同代价按较早断点决胜 (断点 `[1]` 而非 `[3]`);
- 断词预算 0/2/3 分别满足次数上限且成本单调不增;
- 任意相邻两行不连续断词;
- 邻行宽度差罚分权重增大 -> 相邻剩余宽差异减小 (58 -> 17);
- 不可断长词溢出并单独报告, 贪心与 DP 均终止;
- 预算中断单独报告且不声称最优;
- 增量编辑重用前沿, 成本与全量重算一致 (含段首编辑无前沿可重用情形)。
