Kubernetes Gateway API 控制面把 `Gateway`、`HTTPRoute` 与 `ReferenceGrant` 编译成统一数据面路由表时，存在四类严格规范的边界：1）`Gateway` Listener 的 `hostname` 与 `HTTPRoute` 的 `hostnames` 必须求精确通配符交集（按单级左通配符规范，`*.example.com` 匹配 `a.example.com` 与 `a.b.example.com`，不匹配裸域名 `example.com`；两者交集为空则该路由不可挂载到此 Listener！），同时校验 Listener 的 `allowedRoutes.namespaces`（`Same`/`All`/`Selector`）权限；2）跨命名空间指向其他命名空间 Service 的 `backendRef` 必须命中有效 `ReferenceGrant`（精确匹配 `from.namespace`/`from.kind` 与 `to.namespace`/`to.kind` 及空或同名 `to.name`），若某个加权后端缺少授权，规范要求仅将**该分支**编译为返回 `500` 的故障后端（保持其在总权重分母中的比例不变，绝不可把其他合法后端权重偷偷放大，也绝不可拒绝整条路由！）；3）当多条 `HTTPRoute` 竞争同一生效主机名与请求特征时，必须严格按 Gateway API 7 级确定性优先级排序消解冲突：`Exact Path` > 最长 `PathPrefix` > `RegularExpression` > 请求头匹配数多优先 > 查询参数匹配数多优先 > 显式 `Method` 匹配优先 > `creationTimestamp` 更早优先 > `namespace/name` 字典序更小优先！4）同一路径前缀 `/api` 必须按段边界匹配（匹配 `/api` 与 `/api/v1`，绝不可误匹配 `/apiv2`！）。为入口网关控制面交付可导入的 TypeScript Gateway API 路由编译与请求匹配引擎。规则完整涵盖 Listener 挂载状态报告（`Accepted`/`ResolvedRefs` 精确原因）、通配符交集计算、跨命名空间 `ReferenceGrant` 局部 500 降级与权重保真、多路由 7 级优先级合并与冲突诊断以及按路径段边界的请求路由模拟求值。验收覆盖通配符交集与裸域名不匹配、跨命名空间部分后端无 `ReferenceGrant` 返回精确比例 500、`/api` 不误配 `/apiv2`、以及 7 级优先级全部层级与同级时间戳/字典序决胜。
