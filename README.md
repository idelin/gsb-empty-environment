# lockplan — 锁文件更新规划器

在新增/变更根依赖后重新求解锁文件：**首先尽量保留原有锁定版本，
其次最小化需要下载的字节数**。求解是精确的（非启发式），并为每个
被迫变化输出原因路径；不再被任何根依赖可达的包会被删除。

## 目标函数

按字典序最小化：

1. **变更的锁定数** — 解析结果中 `(version, source)` 与锁文件不一致的包数
   （新增包不算变更，被移除的包也不算）。
2. **下载字节数** — 新增或变更包的 `size` 之和（未变化的锁定包无需下载）。

因此同一版本即使存在更便宜的来源，也不会替换已锁定的来源（见
`TestSameVersionDifferentSource`）；只有新下载的包才按字节数选源。

## 求解器

`Solve`（solver.go）从根约束出发做深度优先搜索：

- 部分赋值 = 已选候选 + 已累积约束；每次挑选可行候选最少的未赋值包
  （fail-fast），候选排序把当前锁定 pin 放在首位、其余按大小升序，
  以便尽早找到优解。
- 赋值时把依赖约束传播给子包，并立即检查与已赋值包的一致性——
  **依赖环**因此自然处理（环只是对同一包追加约束），不会死循环。
- 剪枝下界是当前部分赋值的已累积目标值；赋值只增不减，故该界可采纳，
  剪枝不损失最优性。解析结果恰好是从根可达的包闭包，不可达的旧锁定
  包即被垃圾回收。

## 原因解释

`Explain`（explain.go）对每个变化给出根到该包的最短依赖路径及原因：

- 锁定版本违反的根约束/依赖约束（含施加者）；
- 级联情况：锁定版本本身满足约束，但其自身依赖与解析结果冲突；
- 新增包的引入者；被移除包标注 "no longer reachable from any root"。

## 用法

```sh
go run . -registry example/registry.json -lock example/lock.json \
         -roots example/roots.json [-add 'name@>=1.2.0'] [-json]
```

输入为三个 JSON 文件：注册表（所有可安装候选，含 `size` 与 `deps`）、
锁文件（`name -> {version, source}`）、根需求（`name -> 约束`）。
约束语法：`*`、`>=1.2.0, <2.0.0`、`=1.0.0` 等比较子合取。

## 测试

`go test ./...`：

- `TestExhaustiveOptimality` — 300 个随机小实例（含依赖环、同版本
  多来源、陈旧锁），与枚举全部赋值的暴力参考求解器逐一比对目标值
  与可行性，核验最优性；
- 针对性强例：保留锁定、级联强制变更与垃圾回收、依赖环、同版本
  不同来源的优先级、不可满足判定。
