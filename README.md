Kubernetes 垃圾回收控制器在执行对象级联删除时，一个子对象可以同时拥有多个 OwnerReference（分别带有独立的 `controller` 与 `blockOwnerDeletion` 标记），且删除请求支持 `Foreground`、`Background` 与 `Orphan` 三种传播策略，并与对象自身的自定义 Finalizer 交错生效：若控制面在 `Foreground` 删除时把所有子对象都当作阻塞条件、忽略仍存在其他存活属主的共享子对象、或在 OwnerReference 形成引用环时无限等待，就会导致命名空间与资源永久卡死在 `Terminating`。为集群控制面交付可导入的 Go 垃圾回收依赖图与状态推进包。对象包含 UID、版本、自定义 Finalizer 列表、DeletionTimestamp、传播策略及 OwnerReference 列表（含 `uid`、`blockOwnerDeletion`）。规则：1）收到 `Foreground` 删除时自动挂上 `foregroundDeletion` finalizer，只向所有**无其他存活属主**的直接子对象发起后台删除，但仅当所有满足 `blockOwnerDeletion == true` 且指向当前对象的子对象（注意：若某子对象另有一个尚未删除的存活属主，则该子对象不被删除，且不再阻塞当前父对象！）彻底消失或已移除指向当前对象的引用后，才移除 `foregroundDeletion` finalizer；2）收到 `Orphan` 删除时挂上 `orphan` finalizer，从全部直接子对象的 OwnerReference 中仅剥离指向当前对象的条目（保留其他属主），全部剥离确认后再移除 `orphan` finalizer；3）收到 `Background` 删除时立刻允许对象在自定义 Finalizer 清空后消失，随后异步回收所有已无任何存活属主的孤立子对象；4）检测并处理 OwnerReference 引用环（如 `A <-> B` 同时带 `blockOwnerDeletion=true`），按明确环破除规则解除循环阻塞而不误删外部仍有存活属主的共享节点；5）任意对象只有在 DeletionTimestamp 非空且全部 Finalizer（含系统与自定义）为空时才彻底从存储移除。验收覆盖多属主共享子对象防误删、`blockOwnerDeletion=false` 不阻塞 `Foreground`、`Orphan` 仅剥离单属主、自定义 Finalizer 延迟释放、引用环破除以及三策略混合嵌套级联终态校验。
