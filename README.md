# 权限例外撤销求解器（exception-revocation-solver）

对"基础策略 + 临时允许/拒绝例外"的访问控制策略，求**撤销总代价最小**的例外集合，
使给定的安全性质在整个有限输入域上恢复成立，并对每条被保留的例外输出穷举核验摘要。

## 策略模型

- **请求**：有限属性集合上的一次取值，如 `{role, action, resource}`；输入域为各属性取值的笛卡尔积（全部穷举，默认上限 200 000 条）。
- **基础策略**：`baseEffect`，`allow` 或 `deny`，无任何例外匹配时的默认判定。
- **例外**：`{id, effect, priority, cost, match}`。
  - `match` 为属性约束（单值或值列表），全部命中才算匹配；空 `match` 匹配一切。
  - 评估语义：**按优先级首次匹配**——`priority` 数值小者优先；同优先级按 `id` 字典序，保证确定性。
  - `cost` 为撤销该例外的代价（非负）。
- **安全性质**：一组约束 `{id, match, must}`，表示"所有命中 `match` 的请求，判定必须为 `must`"。

## 求解算法与最优性

关键观察：可行的"保留集合"对**并集封闭**——若两个保留集合各自满足性质，则其并集也满足
（同一请求在两边或由同效规则判定、或由基础策略判定，合并后首个命中规则的效力仍然正确）。
因此存在唯一的**最大可行保留集**，由不动点迭代直接求得：

1. 从保留全部例外开始；
2. 找出某个受约束请求，其当前首个命中保留例外的效力违反要求，撤销该例外；
3. 重复至不动点。被撤销的规则在任何可行解中都必须被撤销（归纳可证），故结果是最大保留集。

由于撤销代价非负，任何其他可行解撤销的都是其超集，代价必然不差——
所以该最大保留集即**总代价最小**的撤销方案。例外数量上限为 24 条。

## 输出

- `revoked`：被撤销的例外及各自代价，`totalCost` 为总代价；
- `verification`：穷举核验统计（域大小、性质检查次数、违规数恒为 0、迭代轮数）；
- `retained`：每条保留例外的核验摘要——它在全域上实际裁决多少请求、其中多少受性质约束、
  违规数（恒为 0）、是否被高优先级规则完全遮蔽（shadowed），以及样例请求。

## 使用

```bash
npm run build                      # 需要本机可用的 tsc（TypeScript 5.x）
node dist/src/cli.js examples/policy.json
npm test                           # 编译并运行全部测试（含 200 组随机策略的暴力枚举交叉验证）
```

策略文件格式见 `examples/policy.json`。退出码：`0` 求解成功；`1` 不可行或例外超过 24 条；`2` 输入非法。
