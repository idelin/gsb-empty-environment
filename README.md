身份目录要迁移名称规范化规则，旧证书和新登录入口不能把原本不同的持有人解析成同一主体。请给 Go 目录宿主写可导入的迁移准入包。每个租户给出原始名称的有限状态语法、旧新两份确定性字符转写表和根签名的合法别名关系。每一步可输出零到两个规范符号，结束时还可输出尾符号。允许不同拼写归到同一旧主体，但若某对合法名称在新表产生同一标识而旧表不同，必须有适用于该租户与策略版本的一份完整别名证明，且禁止经由空串转写或尾符号碰撞把非别名名称折叠为同值。名称长度至多64，不允许逐个枚举；输入另给延迟界证书，需核对在所有可比较的前缀上剩余未匹配的规范符号数不超过4。不能只把每一步输出边界对齐，字符删除、展开、结束标记和两个不同长度的输入都要处理。返回可供加载器独立检查的安全证书，绑定两版语法、转写表、租户及已签别名根，更新别名后旧凭据失效。用短名称全枚举对照前缀相同尾部不同、跨字符展开、仅一个租户获准合并及给错延迟界的配置；拒绝仅给规则与证书义务，不输出可登录标识。

## migrationadmission

可导入的迁移准入包位于 `migrationadmission/`，仅依赖 Go 标准库。

- `Grammar`：每租户的原始名称 DFA，名称为长度 ≤ 64 的字节串。
- `TranscriptionTable`：确定性逐字符转写，每字符发射 0–2 个规范符号，接受状态结束时再发射至多 1 个尾符号。
- `Policy`：一个版本的语法 + 转写表；Bundle 同时绑定旧版与新版。
- `AliasClaim` / `LatenessCertificate`：ed25519 根签名的别名证明与延迟界证书。
- `Bundle` / `SignedBundle`：自包含安全证书，加载器用 `Verify(wire, trustedRoot)` 独立复核签名、租户、策略版本、epoch 与全部自动机分析结论。
- `VerifiedBundle.Admit` 返回可登录标识；`IssueCredential` / `VerifyCredential` 发行并校验 epoch 绑定的登录凭据，别名更新（新 epoch）后旧凭据返回 `ErrCredentialExpired`。

### 安全检查如何工作

碰撞检查是对两份联合（旧，新）转导器的异步产品自动机做 BFS，不枚举名称：

- 同步移动保留相同输入路径，异步移动覆盖不同长度输入、字符删除造成的空发射与多符号展开造成的缓冲；
- 两侧新标识缓冲按前缀贪心消去，首个不匹配符号即判定流永远分叉（安全）；
- 两臂都结束且缓冲同时为空时，若名称不同且旧主体不同，则必须在根签名别名集合中命中，否则返回 `ErrUnauthorizedFold`，因此空串转写折叠和尾符号碰撞都不会放过非别名名称；
- 每个节点记录两侧尚未匹配的规范符号总数，超过 4 立即返回 `ErrLatenessExceeded`；证书声明值与观测最大值必须精确相等，否则 `ErrWrongLatenessBound`；
- 新语法无接受词、或所有接受词都无法产生非空标识时返回 `ErrNoLoginIdentifier`，拒绝“只给规则与证书义务、不输出可登录标识”的配置。
