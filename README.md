# 切割规划器（一维下料优化）

接收多种长度/价格的原料棒与一批订单需求，计入固定锯缝，求
**最低采购成本**，同成本下**最少切割刀数**（再次为最少根数）的最优切割方案，
并输出每根棒的切法与余料去向。需求总件数 ≤ 22。

## 模型与规则

- 每种原料棒无限供应、按根计价；锯缝宽度固定为 `kerf`，每锯一刀消耗 `kerf`。
- 从一根棒切 `k` 件：有余料时需 `k` 刀（余料是第 `k+1` 段）；恰好分完时只需 `k-1` 刀。
- 余料 = 棒长 − 订单件总长 − 刀数 × 锯缝，**锯缝不计入可复用长度**。
- 余料 ≥ 最短订单件即判定为可复用，标注“留存入库”，否则作废料。

## 为什么最优解不需要显式追踪余料

任何“先用棒 A 切出余料 R，再从 R 切集合 T”的方案，都可以把 T 并回 A 的切割组合：
设 A 原切集合 S（k 件 k 刀），R = L − sum(S) − k·kerf。从 R 切 T 可行的两个情形
（`sum(T)+|T|·kerf ≤ R` 或 `sum(T)+(|T|−1)·kerf = R`）都恰好等价于 S∪T 在 A 上可行，
且总刀数与采购根数完全不变；链式复用同理归纳。因此显式复用余料永远不会得到更优解，
最优方案一定可以表示成若干根新棒上互相独立的切割组合——余料只需在输出时标注去向。
据此，求解只需对订单子集做精确 DP，无需把余料库存纳入状态。

## 算法

1. 展开订单为 `n ≤ 22` 个单件，预处理每个子集的件数与总长。
2. 对每个子集求“放在一根新棒上切”的最优原料（先比价格、再比刀数）。
3. 子集 DP：`dp[mask] = min (成本, 刀数, 根数)`，只枚举含最低位的子集避免重复划分。
4. 回溯输出每根棒的切法、刀数、余料及去向。

状态数 `2^22`，内存约百余 MB（TypedArray）；实际耗时取决于可行切割组合数。

## 用法

需要 Node.js ≥ 22.6（`--experimental-strip-types`，23.6+ 默认支持）直接运行，
或安装 TypeScript 后 `npx tsc --noEmit` 做类型检查。

```bash
node src/cli.ts examples/sample.json          # 文本方案
node src/cli.ts examples/sample.json --json   # 机器可读
cat input.json | node src/cli.ts              # 标准输入
node test/brute-force-check.ts                # 与暴力枚举交叉验证
```

输入格式：

```json
{
  "kerf": 5,
  "stocks":  [{ "length": 6000, "price": 100 }],
  "demands": [{ "length": 1200, "count": 4 }]
}
```

## 文件

- `src/solver.ts` — 核心求解器（纯函数 `solveCuttingStock`）
- `src/cli.ts` — 命令行入口与方案格式化
- `test/brute-force-check.ts` — 独立暴力法交叉验证（400 组随机用例）
- `examples/sample.json` — 示例输入
