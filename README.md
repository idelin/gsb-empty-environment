大型身份平台在从旧版 FIDO U2F 迁移至 WebAuthn 时，需要通过 `appid` 扩展支持历史 U2F 凭据登录。若服务端在验证断言时无条件接受任意 `appid` 覆盖 `rpIdHash`、未按 FIDO AppID and Facet Specification 校验目标 `origin` 必须属于该 `appid` 对应的受信 `TrustedFacets` 清单且二者共享有效顶级域（eTLD+1），或允许新注册的纯 WebAuthn 凭据被降级走 `appid` 路径冒用跨子域身份，攻击者可利用同一主域下被攻陷的边缘子域（如静态页面子域）窃取核心登录域的 U2F/WebAuthn 认证。为 Go 认证宿主实现可导入的 WebAuthn + U2F `appid` 扩展双轨安全验证包，严禁联网（仅用标准库 `crypto/ecdsa`/`crypto/sha256`）。组件严格实现：（1）凭据代际隔离：数据库凭据显式标记 `isLegacyU2F`；对非遗留 WebAuthn 凭据硬禁止使用 `appid` 扩展回退（`rpIdHash` 必须严格等于 `SHA256(rpId)`）；（2）`appid` 与 `TrustedFacets` 严格边界校验：校验 `appid` 为合法 HTTPS URL（禁止通配符、IP、非 HTTPS、路径穿越），验证调用方 `origin` 精确列于该 `appid` 的受信 `TrustedFacets` 列表且与 `appid` 主机共享同一有效注册域（内置公共后缀 eTLD+1 规则表，阻断 `.co.uk`/`.github.io` 等公共后缀跨租户冒充）；（3）精确执行 `clientExtensionResults.appid == true` 下的 `rpIdHash == SHA256(appid)` 验签（覆盖 `authData || SHA256(clientDataJSON)`），强制校验 `UP=1`、一次性 `challenge` 与 `signCount` 严格单调递增防克隆。附纯 WebAuthn 凭据降级拦截、公共后缀跨租户 `appid` 绕过、未列入 `TrustedFacets` 拒绝与合法遗留 U2F 迁移测试。
