# K-Core 分解与剥离器（TypeScript）

大型稀疏图的核度（Core-Number）分解：

- **批量分解**：Batagelj–Zaversnik 剥离算法，O(|V| + |E|)。等价于"动态移除度数 < K 的节点直到收敛"，一次运行得到所有节点的 Core-Number。
- **分层输出**：按核度分层（`coreLayers`），并可导出 1-core…k-core 的诱导子图（`kCoreSubgraph`）。
- **增量维护**：增删边时利用"单条边最多使核度变化 ±1、且仅影响核度 = K = min(core[u], core[v]) 的节点"这一性质，只在受影响的局部邻域内重新传播核度调整（Sariyuce et al. 的 traversal/propagate 思想），无需全图重算。

## 环境要求

Node.js ≥ 22.6（利用原生 TypeScript 类型擦除直接运行 `.ts`，无需构建步骤；开发版本为 v23.9）。

```bash
npm run demo   # 运行验收场景样例
npm test       # node:test 内置测试
```

## 项目结构

```
src/graph.ts        无向稀疏图（邻接集，稠密整数节点 id）
src/core.ts         批量核度分解 + 分层输出 + k-core 子图导出
src/incremental.ts  CoreMaintenance：增删边的局部增量核度传播（含开销统计）
demo/demo.ts        验收场景运行样例
test/core.test.ts   node:test 测试（含随机差分测试）
```

## 增量更新原理

- **插边 (u,v)**：从核度 == K 的端点出发遍历候选邻域，用乐观最大核度
  `mcd(w) = #(core>K 邻居) + #(未被驱逐的 core==K 邻居)` 判定晋升资格；
  `mcd(w) <= K` 的节点被驱逐并级联，幸存节点核度统一 +1。
- **删边 (u,v)**：收集与端点连通、核度 == K 的候选区域，在区域内做局部剥离——
  支撑度（core>K 邻居数 + 区域内邻居数）不足 K 的节点核度降为 K-1 并级联。
- 每次更新返回 `UpdateStats`（访问节点数 / 核度变化节点 / 邻接扫描次数），
  用于量化局部开销。

## 运行样例（`npm run demo`）

验收图：K5 稠密子网（0-4）+ K4 团（5-8）+ K4-e 部件（9-12）+ 悬挂链（13-16）。

```
=== 1. 批量核度分解（密集子网 + 悬挂链） ===
图规模: |V|=17, |E|=26, 最大核度=4
  core=1 层 (4 个节点): {13, 14, 15, 16}
  core=2 层 (4 个节点): {9, 10, 11, 12}
  core=3 层 (4 个节点): {5, 6, 7, 8}
  core=4 层 (5 个节点): {0, 1, 2, 3, 4}

=== 2. 1-core 到 4-core 分层子图 ===
  1-core: |V|=17, |E|=26, 节点={0, 1, ..., 16}
  2-core: |V|=13, |E|=22, 节点={0, 1, ..., 12}
  3-core: |V|=9,  |E|=17, 节点={0, 1, ..., 8}
  4-core: |V|=5,  |E|=10, 节点={0, 1, 2, 3, 4}

=== 3. 加入桥接边 (11,12)：局部核度 2 -> 3 ===
  增量更新: K=2, 访问节点=4, 核度变化节点={9, 10, 11, 12}
  插入后部件核度: 3, 3, 3, 3
  与全局重算结果一致: true

=== 4. 删除桥接边 (11,12)：核度回落 3 -> 2 ===
  增量更新: K=3, 访问节点=4, 核度变化节点={9, 10, 11, 12}
  与全局重算结果一致: true

=== 5. 大规模图上的局部更新开销对比 ===
图规模: |V|=11604, |E|=15605, 最大核度=7
  增量更新: 访问节点=4, 核度变化=4, 邻接扫描=24,   耗时≈0.1ms
  全局重算: 处理节点=11604,      邻接扫描=31212, 耗时≈1.7ms
  局部/全局节点开销比: 3.45e-4
  与全局重算结果一致: true
```
