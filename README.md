SRE 告警平台同时用长短双窗口错误预算燃烧率减少误报，并按服务依赖图抑制由上游故障引发的告警风暴；但若服务间存在循环依赖，朴素抑制会把环内所有服务的告警互相吞掉导致零告警漏报。给告警求值引擎交付可导入的 Go 判定与抑制包。输入各服务的 SLO 目标、每分钟成功/错误请求计数序列、多档双窗口燃烧率规则（每档要求长窗与短窗燃烧率同时严格大于阈值才触发）、服务间强依赖有向图和临时静默时间窗。规则：先按精确分母（窗口总请求数为零时燃烧率记为 0 不除零）评估每服务在查询时刻是否处于触发态；再在依赖图上仅对强连通分量缩点后的真上游触发节点抑制其严格下游（同一强连通分量环内节点互不抑制，且已被静默窗口屏蔽的上游节点不得再用来抑制下游告警，以免静默掩盖衍生事故）。组件返回查询时刻精确的根因告警集、被抑制告警及其抑制来源，以及被静默告警集。验收用朴素图可达与窗口重算对照，覆盖双窗仅一窗超标不触发、环状依赖全部保留为根因不被互相吞灭、上游被静默时下游正常报出，以及零流量窗口无 NaN。
