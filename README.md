值班机要重建一次遥测丢包期间可能发出的整串通知，而不是逐分钟猜触发与否。提供告警服务可导入的 Go 包，并接入值班机的通知回调：恢复服务选中一条历史后，将对应失败数逐桶喂给值班机，仅在翻页时调用 Notify(bucket)，值班机不得直接读取预选位串。输入中每个桶有已知请求量及未知整数失败数（0 到请求量）；采集器给任意重叠半开桶区间的失败总数上下界。机内两个滑窗各有自己的正数宽度和有理阈值，开头截到首桶；两窗均非零流量且失败比均达到阈值才算本桶燃尽。连续两个燃尽时翻页，之后静默到连续两个不燃尽才重新武装；重新武装的桶自身不能触发。初始已武装且无历史。返回所有相容计数补全生成的不同翻页位串的精确数量，并按时间顺序以 0<1 的字典序反选第 k 个位串及一组能重放它的失败数。无解和 k 越界分开报告。同一位串即使有许多补全也只数一次；不同窗口与翻页条件共享一份补全。最多 22 桶，计数与阈值分子分母是 uint64；不按单个请求展开，也不做按桶容量增长的动态规划。把返回的分配送入与符号规划分开的逐桶告警回调，验证位串，再用小容量枚举全部分配去重对照数量、排名及见证。包括静默跨两个滑窗、同一通知有指数多补全、两个局部可行通知不能共存、空流量和阈值交叉乘积溢出。
