# 采购规划器（Procurement Planner）

多供应商、多物料的采购优化器。在满足全部物料需求的前提下，求**含运费的最低总成本**采购方案，完整处理：

- **起订量（MOQ）**：每个供应商-物料有最小起订量；
- **整包倍数**：只能按整包采购（包数为非负整数）；
- **整单阶梯折扣**：按单个供应商整张订单的**折前金额**命中阶梯，**整单**享受折扣；
- **供应商交付上限**：供应商总产能上限，以及单项物料交付上限；
- **有上限的超购**：每种物料允许超购到 `demand × (1 + maxOverbuyRatio)`；
- **运费**：固定运费 + 按件运费，折前金额满额可免固定运费；
- **最多六家供应商**：方案使用的供应商家数上限（默认 6，可配置）。

零依赖纯 TypeScript，Node.js ≥ 22.6（利用原生 type stripping）即可直接运行。

## 为什么不能把整单折扣拆成单价贪心

整单阶梯折扣是**订单级别**的非线性成本：是否命中阶梯取决于整张订单的合计金额，
把它折算成“每件便宜多少”再贪心地逐项分配，会系统性错过两类最优结构：

1. **凑单触发阶梯**：向某供应商多买（甚至在超购上限内超购）使订单跨过门槛，
   整单打折后总成本反而更低（见 `test/solver.test.ts` 中“为触发整单阶梯而主动超购”）；
2. **订单合并**：把多种物料集中到一家以合并固定运费、跨过阶梯门槛，
   而不是每种物料各自选“单价最低”的供应商。

因此本求解器始终按**整单真实成本**（`src/evaluate.ts` 的 `supplierOrderCost`）核算，
折扣、运费在任何一步决策中都不被拆成单价。

## 算法

`src/planner.ts` 的 `plan()` 组合两层求解器：

1. **启发式（`src/heuristic.ts`）**：多起点随机构造（每步选“整单成本增量”最小的渠道）
   + 局部搜索（包数调整、删行、同物料跨供应商全部/部分转移、凑单到下一阶梯门槛），
   产出优质可行解作为上界；
2. **精确求解（`src/exact.ts`）**：
   - 把每家供应商的订单成本按折前金额切成若干**金额段**（阶梯门槛与免运费门槛为断点），
     每段内折扣率与固定运费都是常数，问题逐段线性；
   - 枚举“每家供应商落在哪个金额段 / 不使用”的组合（受供应商家数上限约束），
     内部节点用 **LP 松弛**（两阶段单纯形，`src/simplex.ts`）算出下界剪枝；
   - 叶子上做**整数分支定界**：包数取整分支 + 起订量半连续分支（`x=0` 或 `x≥minPacks`）；
   - 预算（时间 / LP 次数）耗尽则返回当前最优可行解，`provenOptimal=false`。

## 输入模型

```jsonc
{
  "maxOverbuyRatio": 0.1,      // 全局默认超购上限比例
  "maxSuppliers": 6,           // 方案最多使用的供应商家数
  "demands": [
    { "materialId": "螺丝M6", "demand": 1200, "maxOverbuyRatio": 0.05 }
  ],
  "suppliers": [
    {
      "id": "甲五金",
      "capacity": 2800,                 // 总交付上限（件）
      "freight": { "fixed": 60, "perUnit": 0.01, "freeAboveSubtotal": 900 },
      "discountTiers": [
        { "minSubtotal": 800,  "discountRate": 0.04 },
        { "minSubtotal": 1500, "discountRate": 0.09 }
      ],
      "items": [
        { "materialId": "螺丝M6", "unitPrice": 0.45, "moq": 200, "packSize": 100, "maxQty": 1500 }
      ]
    }
  ]
}
```

## 使用

```bash
node src/cli.ts examples/example.json   # 命令行求解并打印方案
npm test                                # 运行全部测试
```

编程接口：

```ts
import { plan } from './src/planner.ts';
const result = plan(problem, { timeLimitMs: 8000, nodeLimit: 200000 });
// result.status: 'optimal' | 'feasible' | 'infeasible'
// result.orders[].tierRationale: 每张订单的阶梯触发依据
```

## 输出

- 每家供应商的采购明细（物料、包数 × 每包件数、单价、金额）；
- 每张订单的折前金额、命中阶梯、折扣额、运费、小计；
- **阶梯触发依据**：如 `折前金额 ¥990.00 达到阶梯#1（门槛 ¥800.00），整单享 4.0% 折扣；距下一档门槛 ¥1500.00 还差 ¥510.00`；
- 每种物料的需求 / 实采 / 超购比例；
- 求解统计（LP 次数、分支节点数、耗时、是否证明最优）。

## 语义约定

- 阶梯按**折前金额**判定，折扣作用于该供应商**整张订单**的货款；
- `freeAboveSubtotal` 达到后免除**固定运费**，按件运费始终计入；
- 超购上限是硬约束：每种物料采购总量不得超过 `demand × (1 + maxOverbuyRatio)`；
- 需求必须全部满足，否则返回 `infeasible`。
