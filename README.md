分布式协调存储（etcd）的 Watch 机制允许客户端从任意历史修订号 `startRev` 开始追赶并无缝切入实时事件流，同时后台可随时执行 `Compact(rev)` 裁剪历史版本、租约过期又会在单一修订内原子删除绑定键集合；如果压缩把 `<= rev` 的最新存活版本误删、删除不存在的键错误递增了全局修订号，或者 Watch 从历史重放切换到实时广播的瞬间丢失/重复推送某个边界修订，上层控制器就会出现永久状态漂移。为键值存储内核交付可导入的 Go MVCC 引擎与多路 Watch 调度包。键值元数据维护全局单调递增 `Revision` 与每键 `CreateRevision`、`ModRevision`、`Version`（删除后重置为 0，再次写入重新从 1 开始并刷新 `CreateRevision`；删除已不存在的键不得产生新修订号，但覆盖写入同值须递增 `Revision`、`ModRevision` 与 `Version`！）。支持 `Put`、`DeleteRange`、原子事务 `Txn`（单事务内多次写入共享同一主修订号 `MainRev` 与递增 `SubRev`）、租约绑定与 `ExpireLeases(now)`（单次原子修订清除过期租约全部键并通知 Watch）。`Compact(compactRev)` 拒绝大于当前最新修订或小于已压缩修订的请求，裁剪所有被覆盖的旧历史及 `<= compactRev` 的删除墓碑，但严格保留在 `compactRev` 时刻仍存活的各键最新版本。Watch 支持单键、前缀与 `[key, rangeEnd)` 区间过滤、`prevKV` 附带删除/更新前值以及历史追赶到实时订阅的原子交接：若 `startRev < compactedRev` 立即返回 `ErrCompacted` 并附带当前压缩修订；正常订阅保证严格按 `(MainRev, SubRev)` 顺序交付、不重不漏，且在压缩发生后若滞后 Watch 被迫落于压缩水位之下须及时以 `ErrCompacted` 取消。验收覆盖空删不涨修订、单事务多键同 `MainRev` 递增 `SubRev`、租约原子过期、压缩保留边界活键并清墓碑、历史->实时无缝交接无重漏以及滞后 Watch `ErrCompacted` 拦截。
