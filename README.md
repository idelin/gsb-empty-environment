# stablematch — 带并列偏好与岗位容量的最大弱稳定匹配求解器

## 问题定义

- 双方偏好表均可含**并列**(同一内层数组中的对象名次相同)。
- 岗位带**容量**, 申请者可**未匹配**, 偏好表可**不完全**(不在对方表中即不可接受)。
- **弱稳定性**: `(申请者 a, 岗位 j)` 构成阻挡对, 当且仅当
  - `a` 未匹配, 或**严格**偏好 `j` 胜于当前岗位; **且**
  - `j` 有空余名额, 或**严格**偏好 `a` 胜于某位在岗者。
- 目标: 在至多 10 名申请者的前提下, 求**规模最大**的弱稳定匹配。

## 方法

对所有匹配做带回溯的穷举(仅以"剩余申请者全部匹配也无法达到当前最优规模"
做规模剪枝), 逐一做弱稳定判定, 取规模最大者。最优性由穷举保证,
**不**通过对并列偏好做任意打破后运行 Gale-Shapley 得出——后者可能得到
更小的匹配(见 `TestTiesNotBrokenArbitrarily`: 任意打破并列只得规模 1,
而最大弱稳定匹配规模为 2)。

## 输入格式 (JSON)

```json
{
  "applicants": [
    {"name": "a1", "preferences": [["j1"], ["j2", "j3"]]}
  ],
  "jobs": [
    {"name": "j1", "capacity": 2, "preferences": [["a1", "a2"]]}
  ]
}
```

`preferences` 按偏好从强到弱排列, 内层数组为一组并列; `capacity` 省略时为 1。

## 运行

```sh
go run . examples/hospital.json   # 或从 stdin 读入
go test ./...
```

## 输出

- 匹配规模与穷举统计(检查匹配数、弱稳定数、达到最大规模数);
- 每个岗位的在岗名单与未匹配申请者;
- **阻挡对检查证据**: 对所有互相可接受但未配对的组合, 逐一说明其
  为何不构成阻挡对(申请者侧不严格偏好 / 岗位已满且不严格偏好),
  并给出阻挡对总数(应为 0)。
