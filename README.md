# 云权限条件求值组件

一个 IAM 风格的权限评估内核：基于资源标识通配、嵌套条件键、资源层级与标签继承、
以及跨账号信任重算，给出 `allow` / `deny` 决策与可区分的拒绝原因。

## 模块结构

- `src/matcher.ts`：资源标识/动作通配匹配，`*`、`?` 与按 ARN 冒号分段匹配。
- `src/condition.ts`：条件求值器，支持嵌套 `and` / `or` / `not`、字符串/数值/布尔
  操作符、`ForAnyValue` / `ForAllValues` 量词与 `${...}` 策略变量。
- `src/hierarchy.ts`：资源树，提供继承链查询、标签继承（子级覆盖同名标签）、
  沿继承链收集策略，并校验缺失父节点与环。
- `src/policy.ts`：单组策略评估，显式拒绝优先，区分条件为假与条件键缺失。
- `src/trust.ts`：跨账号信任（AssumeRole）评估，条件按实际请求主体重新求值。
- `src/engine.ts`：聚合身份策略与资源策略的顶层评估器。

## 决策与原因

条件求值采用三值逻辑：`true` / `false` / `null`（键缺失）。

- 显式拒绝：`Deny` 语句作用域与条件均命中 → `explicit-deny`，优先级最高。
- 条件键缺失：本可命中的 `Allow` 语句引用了上下文中不存在的键 →
  `condition-key-missing`，并在 `missingKeys` 中列出键名。
- 无条件命中：没有任何 `Allow` 生效 → `no-matching-statement`。
- 信任场景额外使用 `trust-principal-mismatch` 与 `trust-account-mismatch`。

同一条件键在 `and` 中多次出现时，约束取交集（最严）：任一约束为假则整体为假，
显式为假会覆盖键缺失的 `null`；`not` 作用于缺失键时仍保持缺失，不会误判为真。

## 层级与继承语义

- 资源标签沿父级到子级合并，子资源同名标签覆盖祖先标签；条件通过
  `aws:ResourceTag/*` 读取合并后的标签。
- 资源策略沿继承链全部参与评估；父级 `explicit-deny` 在子资源上无法被子级
  `Allow` 或身份策略覆盖。
- 身份策略与资源策略需同时允许；任一侧显式拒绝即整体拒绝。

## 跨账号信任

`evaluateTrust` 先匹配主体（支持通配），再用实际请求主体的标签与属性重算条件，
而不是使用角色所属账号的上下文。

## 运行测试

```bash
npm test
```

测试位于 `test/`，覆盖通配匹配、嵌套条件与同键取最严、拒绝原因区分、
父级拒绝覆盖、继承标签求值与跨账号信任重算等场景。
