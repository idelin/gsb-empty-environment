DNSSEC 验证解析器最难写对的并非 RSA/ECDSA 验签本身，而是 RFC 4034/4035/5155 规定的**规范名称排序、通配符标签数校验以及 NSEC / NSEC3（含 Opt-Out！）否认证明（Denial of Existence）**：1）**DNS 规范排序与通配符扩展校验**：对 RRset 进行规范排序（按最右标签优先逐标签不区分大小写字节序比较，并按 RDATA 排序去重！）计算签名摘要；验签通过后必须核对 RRSIG 的 `Labels` 字段：若 `Labels < countLabels(ownerName)`，说明该应答由通配符 `*.<suffix>` 合成，解析器必须额外核验权威区存在覆盖精确查询名（证明无更具体节点遮挡通配符！）的 NSEC/NSEC3 记录，否则立刻判 `Bogus`！2）**DS -> DNSKEY 信任链与有效期窗口**：支持从锚点 DS（SHA-256 Digest + KeyTag 计算）验证子区 DNSKEY（必须检查 `ZONE` 位与协议号=3，拒绝 `REVOKE` 密钥），校验 RRSIG 的 `Inception <= now <= Expiration`（考虑 RFC 1982 32 位序列号回绕算术！）；3）**NSEC3 迭代哈希与三元组 NXDOMAIN 证明**：实现 RFC 5155 NSEC3 规范迭代哈希（`H_0 = SHA1(wire(name) || salt)`，`H_k = SHA1(H_{k-1} || salt)` 迭代 `iterations` 次并按 Base32hex 编码）；验证 `NXDOMAIN` 时必须完整构造并验证三项证明：(a) 找到存在且被 NSEC3 精确匹配的 **Closest Encloser**；(b) 存在一条 NSEC3 区间（含回绕区间 `owner > nextHashed`！）严格覆盖 **Next Closer Name**（证明该子树不存在！）；(c) 存在一条 NSEC3 区间严格覆盖 **`*.<Closest Encloser>`**（证明无通配符可匹配！）；4）**NODATA 与 Opt-Out 不安全委托区分**：对 `NODATA` 验证精确匹配 NSEC3 的类型位图不含查询类型且不含 `CNAME`（若是 DS 查询遇非权威委托且覆盖 Next Closer 的 NSEC3 携带 `Opt-Out=1`，则正确判为 `Insecure` 而非 `Bogus`！）。为递归解析器交付可导入的 Go RFC 4035/5155 DNSSEC 与 NSEC3 验证核（使用真实 ECDSA P-256 / SHA-256 / SHA-1 密码原语）。验收覆盖规范排序与通配符 `Labels` 遮挡检测、DS->DNSKEY 信任链、NSEC3 迭代哈希与回绕区间覆盖、NXDOMAIN 三元组证明缺一即 `Bogus` 以及 Opt-Out 不安全委托精确判 `Insecure`。
