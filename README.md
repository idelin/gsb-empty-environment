# ttlcache — 分层时间感知（TTL/TTD）LRU 双重索引器

仅使用 Go 标准库实现的并发安全缓存，每个对象同时挂载在两个索引上：

| 索引 | 数据结构 | 职责 | 复杂度 |
| --- | --- | --- | --- |
| 访问热度索引 | 双向链表 `container/list` | 命中时 O(1) 提升至队首，容量超限时从队尾逐出最冷对象 | O(1) |
| 到期时间索引 | 小顶堆 `container/heap` | 按生效截止时间排序，后台收割协程对准堆顶设定时器，单次唤醒批量剔除全部死对象 | 弹出 O(log n)，批量摊还 |

## 时间语义

- **TTL（绝对过期）**：插入时确定硬上限 `absolute = now + ttl`，任何访问都不会延长它。
- **TTD（滑动过期）**：每次命中将生效截止时间续期为 `now + sliding`，但永不突破 `absolute`。
- 读取时若判定已超时，**当次操作内同步剔除**并立即返回空；后台收割协程负责批量清理无人访问的死对象。

## 关键文件

- `cache.go` — 双重索引缓存实现（`New` / `Set` / `Get` / `Delete` / `Len` / `Close`）
- `cache_test.go` — 单元测试与验收场景测试
- `example_test.go` — godoc 可运行示例
- `cmd/demo/main.go` — 完整运行样例

## 运行

```sh
go test -race -v ./...   # 测试（含 100 对象验收场景）
go run ./cmd/demo        # 运行样例：观察批量回收与零泄漏
```

## 验收场景（TestAcceptance / demo）

1. 插入 100 个对象，TTL 分布在 10ms~100ms；其中 10 个热对象带 30ms 滑动窗口；
2. 后台协程以 5ms 间隔高频访问热对象 —— 滑动续期使其存活，但绝对硬上限最终截断；
3. 冷对象在各自 TTL 之后读取立即返回空；
4. 后台收割协程批量回收全部死对象，`map` / 链表 / 堆三个索引最终全部清空，内存零泄漏。
