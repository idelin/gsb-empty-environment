# batchlot

Go 批次（lot）台账库：入库、拆分、合并、出库与血缘感知撤销。所有数量均为整数。

## 模型

- 批次是有向来源图的顶点，操作（inbound / split / merge / outbound）是从输入批次指向输出批次的边。
- 每个操作记录 `Inputs`（消耗的批次及数量）与 `Outputs`（产出的批次及数量）。
- `Consumers(batchID)` 与 `Op(opID)` 对外暴露整张来源图。

## 操作语义

- `Inbound(qty)`：登记根批次。
- `Split(src, parts)`：部分拆分，`parts` 之和可小于剩余量，余量留在源批次。
- `Merge(sources)`：按指定份额合并多个来源；份额可为部分量，多个合并可共享同一来源。
- `Outbound(src, qty)`：出库消耗。
- 所有多步操作先校验后变更，任一来源不足或非法即整体失败，不产生部分状态（原子失败）。

## 撤销

- `Undo(opID)` 仅当该操作产出的每个批次仍完整且无活跃后代操作依赖时成功；
  若后代已被消费（出库或再变换），返回 `*UndoError`，其 `Chain` 给出从被撤销操作
  到阻塞消费点的依赖链（如 `OP1 -> B1 -> OP2 -> B2 -> OP3`）。
- 判定基于血缘而非总量：即使全库总量足够，也不能撤销祖先操作；须先撤销后代。
- 撤销出库会把数量退回来源批次。

## 守恒校验

`Verify()` 遍历全图做逐批守恒检查：

- 每个存活批次：`remaining == initial - Σ(活跃操作的消耗份额)`；
- 被撤销创建的批次：`remaining == 0`；
- 每个活跃的拆分/合并操作：`Σinputs == Σoutputs`。
