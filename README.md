# timemap

多轨时间线压缩工具：压缩长空闲段，保留事件次序与同刻关系；所有压缩段共享同一条
单调分段线性映射。鼠标拖动区间与音频连续段为受保护段，不可压缩。全部时间用
有理数（`math/big.Rat`）精确表示，帧取样统一半偶舍入（round-half-even）。

## 构建与测试

```sh
go test ./...
go run ./cmd/timemap examples/spec.json
```

## 原理

1. **切分**：以受保护段边界与事件时刻为切点，把时间轴切成若干段，段内不含事件、
   不跨越保护边界。
2.**定斜率**：受保护段斜率 1（1:1）；空闲段时长 ≥ `min_idle_gap` 的压缩到
   `compressed_duration`（斜率 = 目标/原长）；其余空闲段保持 1:1。
3. **共享映射**：各段顺序拼接成一条严格递增的分段线性映射，所有轨道共用。
   严格递增保证事件次序、同刻关系与全局可逆性。
4. **帧取样**：轨道有有理起点与采样间隔，帧号 = round_half_even((t - 起点)/间隔)，
   所有轨道同一规则。
5. **反向定位**：帧 n 对应压缩时间半开桶 [起点+(n-1/2)·间隔, 起点+(n+1/2)·间隔)，
   两端经逆映射回原时间区间。

## 输出（CLI 报告）

- 正反映射断点表
- 每段压缩理由（受保护 / 空闲压缩 / 空闲保留）
- 每轨偏移证据（原起点、映射起点、位移、采样间隔）
-核对：映射严格递增、关键点精确往返、压缩段与保护段不重叠、事件次序与同刻保持
-跨轨同步点：同一原时刻映射到同一压缩时刻，且落在各轨自身帧桶内
-反向查询：帧号 → 原时间区间

## 输入格式（JSON）

```json
{
  "min_idle_gap": "30",
  "compressed_duration": "2",
  "events": [{"id": "cut", "t": "0"}],
  "protected": [{"id": "drag-1", "kind": "drag", "start": "10", "end": "20"}],
  "tracks": [{"id": "video", "start": "0", "interval": "1/30"}],
  "sync_points": ["5"],
  "reverse_queries": [{"track": "video", "frame": 60}]
}
```

有理数可写成分数（"1/30"）、小数（"1.25"）或整数。任一校验失败时 CLI 以非零码退出。
