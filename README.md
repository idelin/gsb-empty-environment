# phasequota

CPU / IO 两阶段额度调度器。任务依次申请各阶段额度，阶段切换时**先原子释放
旧额度、再等待新额度**，不“持有旧额度等待新额度”，从而避免循环等待死锁。

## 设计要点

- **额度池**：每个阶段用带缓冲 channel 实现计数信号量（标准库 `chan`），
  容量即初始额度，`Acquire`/`Release` 对应接收/发送 token。
- **取消**：获取额度用 `select { case token <- ; case <-ctx.Done() }`，
  容量为 0 的阶段会一直阻塞，直到 `ctx` 取消而退出。
- **阶段切换（无死锁）**：
  1. 释放旧阶段额度（其它等待者立即可用）；
  2. 清空持有状态，进入**半转换**状态（不持有任何额度）；
  3. 等待新阶段额度，可被 `ctx` 取消；
  4. 成功后记录新状态。
  
  因为等待期间不持有旧额度，两个任务互换 CPU/IO 阶段时双方都能拿到对方
  释放的额度，持续取得进展。
- **异常归还**：`Scheduler.Run` 用 `defer task.Release()` 兜底；工作返回
  `error` 或 `panic` 都会在退出前归还当前额度，panic 归还后继续上抛。
- **测试注入**：阶段工作是 `Work func(ctx) error`，执行/阻塞时机由测试用
  channel 闸门控制，成功、失败、panic 均由测试注入，不依赖真实时钟。

## 运行

```bash
# 竞态检测 + 测试（含可运行 Example）
go test -race -count=1 -v ./...

# 运行样例
go run ./cmd/quota-demo
```
