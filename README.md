# 冷热对象迁移模拟器 (hot/cold migration simulator)

模拟对象从本地（热层）迁移到远端（冷层）的全过程。核心问题：**上传成功后，何时才能安全删除本地副本？**

答案是一个状态机：只有当「目标回读摘要与版本一致」**且**「迁移决议已持久化」之后，才允许回收本地副本。

## 运行

需要 Node ≥ 23.6（原生运行 TypeScript，无需编译）：

```sh
node src/main.ts        # 或用任意 >= 23.6 的 node
```

输出 7 个场景的 PASS/FAIL；决策日志写入 `data/<scenario>/decisions.jsonl`。

## 状态机

```
LOCAL_ONLY ──upload──> UPLOADING ──applied──> AWAITING_RECEIPT
                           ^                      │  │
                           │            receipt ✓ │  │ receipt 丢失/超时
                           │                      ▼  ▼
                           │                    VERIFYING ──digest 一致──> PERSISTING_DECISION
                           │                      │                            │
                           └──── digest 不匹配 ───┘                   persisted │
                           （目标损坏/过期，重传）                                ▼
                                              ┌── 有打开句柄 ── RECLAIM_BLOCKED ──句柄排空──┐
                                              ▼                                            ▼
                                        RECLAIMED（删除本地副本）
任何状态下本地写入新版本 ──> 中止当前迁移，回到 LOCAL_ONLY 重新迁移新版本
```

回收的硬性条件（全部满足，`src/migrator.ts` 的 `doReclaim` 强制检查）：

1. 目标回读 digest == 迁移版本的 digest；
2. `(objectId, version, digest)` 的迁移决议已**持久化**到 append-only 日志（`src/decisionLog.ts`）；
3. 没有打开的本地读句柄（否则进入 `RECLAIM_BLOCKED`，句柄排空后再删）；
4. 本地当前版本仍是被迁移的版本（无更新竞争）。

关键规则：

- **旧回执不能确认新版对象**：回执携带 `(version, digest)`，与当前迁移版本不一致即拒绝。
- **回执丢失**：超时后直接探测目标做回读校验，不依赖回执也能完成确认。
- **更新竞争**：迁移期间本地写入新版本，立即中止旧迁移；远端按版本号 last-writer-wins，旧上传不会覆盖新数据；本地版本号单调递增、回收后不重置（元数据目录语义，`src/stores.ts`）。
- **目标损坏**：回读 digest 不匹配 → 重传，本地副本全程保留。

## 安全不变式

每个事件处理后检查（`src/simulator.ts`）：

> 对每个对象，其当前版本至少存在**一份有效副本**（本地 digest 匹配，或远端 digest 匹配）。

## 故障模型与边界

注入三类故障：回执丢失、更新竞争、目标损坏（位翻转）。损坏注入限定在**未验证的迁移窗口**（上传中/等回执/校验中）——这是状态机负责检测的区间。回读验证通过、决议持久化之后，字节的所有权已移交给冷层，其自身的持久性（校验和、冗余）不在本模拟器范围内；跨两个存储系统本就无法原子地「边验证边删除」，交接点只能定义在持久化的迁移决议上。

## 场景

1. 正常路径：上传 → 回执 → 回读验证 → 持久化决议 → 回收。
2. 回执 100% 丢失：超时探测目标，仍完成确认与回收。
3. 更新竞争：迁移中写入 v2，v1 旧回执被拒绝，最终回收的是 v2。
4. 目标损坏：回读发现 digest 不匹配，重传后恢复。
5. 读句柄持有期间删除被推迟，句柄释放后才回收。
6. 负面对照：naive 策略（仅凭回执就删除）在目标损坏时丢失数据——不变式被破坏，反证状态机的必要性。
7. 压力测试：20 对象 × 4 组种子/故障率，随机更新/损坏/回执丢失/句柄，不变式全程成立且全部对象最终完成迁移。

## 文件

- `src/types.ts` — 领域类型与状态定义
- `src/migrator.ts` — 每对象迁移状态机
- `src/stores.ts` — 热层（句柄/版本）与冷层（版本守卫/损坏注入）
- `src/decisionLog.ts` — 持久化迁移决议日志（JSONL，同步落盘）
- `src/simulator.ts` — 离散事件模拟器、故障注入、不变式检查
- `src/main.ts` — 7 个验证场景
