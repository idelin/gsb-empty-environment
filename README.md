ARM64 Type-1 超管（EL2）在隔离多个客体虚拟机时，若某虚拟机的 `HCR_EL2` 寄存器漏设 `VM=1`（Stage-2 翻译未启用）、漏设 `TSC`/`TWE`/`TVM`/`TACR` 导致客体直接操作敏感系统寄存器或绕过超管陷阱、多台虚拟机共享同一非零 `VMID`（`VTTBR_EL2[63:48]`）引发 TLB 跨机缓存污染，或超管在拦截模拟 MMIO 寄存器写（如虚拟 GIC Distributor / 虚拟 PCI 配置空间）时未校验 `IPA + access_size` 边界与 4/8 字节对齐，恶意客体内核可跨机窃听或破坏相邻虚拟机的设备状态。为 C++17 虚拟化安全审计宿主实现可嵌入、零外部依赖、`-Wall -Wextra -Wconversion -Werror` 编译通过的 ARM64 EL2 超管配置与 MMIO 模拟边界验证库。输入为各虚拟机的 `HCR_EL2`/`VTTBR_EL2`/`VTCR_EL2` 寄存器状态、稀疏 Stage-2 页表、虚拟设备 MMIO 区域描述符表以及客体触发的 `ESR_EL2` Data Abort MMIO 模拟访问序列。验证库精确执行：（1）校验全量虚拟机 `HCR_EL2` 必置 `VM=1` 且关键安全陷阱位合规、校验不同隔离域虚拟机绝不复用相同 `VMID`（拦截 TLB 跨机别名）；（2）校验每台虚拟机的 Stage-2 映射不重叠超管 EL2 自身物理内存或他机物理内存，且对模拟 MMIO 区间必须保持未映射（确保必陷 EL2 而非直通物理设备）；（3）审计每条 `ESR_EL2` MMIO 模拟访存（解析访问宽度 1/2/4/8 字节、读写方向与 `IPA`）：硬拦截非对齐跨设备边界访问、`IPA + size` 越出所属设备寄存器窗口或命中只读/保留寄存器写操作，输出具体违规虚拟机 ID、寄存器/IPA 与见证。附 `VMID` 碰撞、漏设 `HCR_EL2.VM`、MMIO 直通泄漏与跨边界 8 字节写测试。
