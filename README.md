# netsim

Go 包级网络仿真器：节点通过**有容量的有向边队列**传输包，发送**阻塞不丢包**，
路由表静态给定。输出每个包的端到端延迟，能检测死锁并给出证据，
并支持对小网络做**全状态空间穷举验证**。

## 模型

- `Edge`：有向 FIFO 队列，容量 `Capacity`（缓冲槽数），每跳传输耗时 1 tick。
- `Packet`：在 `InjectTick` 于 `Src` 进入注入队列，按路由表逐跳转发到 `Dst`。
- 路由：`SetRoute(node, dst, next)` 给定下一跳表；`NewSim` 校验每包路由完整且无环。

### Tick 语义（先接收，再统一提交发送）

1. **接收阶段**（确定性）：每条边队首包若已到达目的节点则被消费（记录投递时刻）。
2. **发送阶段**（快照 + 原子提交）：所有转发/注入决策都基于接收后的同一快照计算，
   暂存为 `Move` 集合后一次性提交。

**节点遍历顺序无关**：每条有向边只被其源节点写入、只被其目的节点读取，
不同节点的决策不共享任何边，因此提交结果与节点遍历顺序无关
（`TestNodeOrderIndependence` 用多种顺序验证逐 tick 状态完全一致）。

**保守容量规则**：同一 tick 内离开某边释放的槽位，要到下一 tick 才能被新包使用——
这是"统一提交"的直接推论，也是顺序无关性的保证。

**阻塞不丢包**：目标边满时包留在原地（队首阻塞）；每 tick 每条入边最多移动队首一包、
每节点最多注入一包。不变量（包守恒、不重复、不超容量）由 `CheckInvariants` 逐状态检查。

## 死锁证据

`Run` 在"有未投递包且无任何可行移动"时判定死锁（确定性仿真下状态将不再变化）。
`DeadlockEvidence` 输出：

- 死锁时刻的完整状态快照（各边队列内容、注入队列、已投递集合）；
- 每个被阻塞的队首包及其等待的满边；
- **wait-for 环**（循环等待链），如 `cycle: 1 -> 2 -> 0 -> 1`。

## 状态穷举验证

`Enumerate(maxStates)` 对小网络穷举所有可达状态：每个 tick 枚举候选发送的
所有非空兼容子集（即"只要能动就至少动一步"的调度族；空子集会因 tick 进入
状态哈希而导致状态空间无界，且不会掩盖死锁——死锁是根本没有候选的状态）。
报告：

- 可达状态数 / 转移数；
- 成功终态数（全部投递）与**死锁终态数**（附一个死锁样本）；
- 每包延迟在所有成功终态上的 min/max；
- 所有状态上的不变量违例（包丢失/重复/超容量）。

示例结论（3 节点环、容量 1）：2 个包时所有调度都送达（无死锁）；
3 个包时 27 个成功终态 + 3 个死锁终态——死锁是调度相关的，穷举能同时看到两者。

## 使用

```sh
go test ./...        # 单元测试（含顺序无关、守恒、死锁、穷举）
go run ./cmd/netsim  # 演示：健康网络延迟表 / 环形死锁证据 / 穷举报告
```

注意：Go 1.11 需要模块模式（`GO111MODULE=on`，或不在 GOPATH 内即可自动启用）。

## 文件

- `netsim.go` — 拓扑、路由、状态、tick 转移（接收/候选/兼容/提交）、确定性运行
- `evidence.go` — 状态哈希与快照、不变量检查、wait-for 环与死锁证据
- `enumerate.go` — 小网络全状态空间穷举
- `netsim_test.go` — 测试
- `cmd/netsim/main.go` — 演示 CLI
