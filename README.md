Linux ext4 的物理块日志（JBD2）在“元数据块释放后被复用为普通数据块”的场景下存在极其致命的崩溃恢复陷阱：事务 `T1` 将块 `B` 作为元数据写入日志并提交；随后事务 `T2` 释放块 `B`，系统将其重新分配给普通文件直接覆盖写入主盘数据，同时在 `T2` 的日志中写入一条 `REVOKE(B, seq=T2)` 记录；若此时系统掉电重启，恢复程序如果直接从头重放日志就会把 `T1` 日志里的旧元数据写回主盘，静默破坏已被 `T2` 复用的用户数据！同时，如果某元数据块的前 4 字节恰好等于 JBD2 日志头魔数 `0xc03b3998`，写入日志时必须清零前 4 字节并在描述符条目置 `FLAG_ESCAPE`，恢复重放时再精准还原该魔数！为文件系统存储层交付可导入的 Go 环形物理块日志写入与三趟崩溃恢复包。模拟定长主盘块数组与固定大小环形日志区（含 Superblock 起始序列号/头块、Descriptor 块、Data 块、Revoke 块与 Commit 块，每块带校验和）。规则：1）支持事务追加元数据块（自动检测魔数碰撞置 `FLAG_ESCAPE`）、写入 `REVOKE` 块列表与 Commit 块（支持模拟任意字节撕裂写与环形日志回绕覆盖旧已检查点事务！）；2）实现严格 JBD2 三趟崩溃恢复：`PASS_SCAN` 从 Superblock 起点沿环形日志顺次扫描，核验连续递增序列号、Descriptor/Revoke/Data/Commit 完整校验和，遇到校验失败、序列号断层或缺失 Commit 块即锁定最后一个完整提交事务 `max_tx`（忽略后续未提交尾部！）；`PASS_REVOKE` 扫描 `[start_tx, max_tx]` 内全部 Revoke 块，为每个块号记录其**最大**撤销事务号 `max_revoke_tx[B]`；`PASS_REPLAY` 仅重放满足 `tx > max_revoke_tx[B]` 的日志数据块（`tx <= max_revoke_tx[B]` 绝对跳过不覆盖主盘！），并对带 `FLAG_ESCAPE` 的块精确恢复前 4 字节魔数；3）支持恢复后推进检查点截断并验证崩溃恢复幂等性（对同一磁盘镜像连续运行多次恢复结果逐字节一致！）。验收覆盖 `T1` 写元数据 + `T2` 复用并 `REVOKE` + `T3` 再次分配写回（`T3 > T2` 须重放而 `T1 < T2` 须拦截！）、魔数转义还原、环形日志回绕覆盖、未提交撕裂事务截断与多次恢复幂等性。
