# 合成设备维修选择（maintenopt）

在维修窗口内选择设备维修集合并把工时落位到班次，使**明示分数收益**最大化。
纯 Python 3.11 标准库实现，精确分支定界，**不调用任何求解器**。

> 说明：失效风险分数仅作为题内权重（收益系数），不解释为真实失效概率。
> 全部约束数据为合成整数或有理数（`fractions.Fraction` 精确运算）。

## 问题模型

- **窗口**：若干班次（shift），班次 `k` 长 `len_k` 个整数槽；班次间为不可用间隔。
- **停机组**：组 `g` 的同时维修上限为 `limit_g`（工位数）。因班次内各槽等价，
  约束以聚合形式表达：
  - 组 `g` 在班次 `k` 的总负载 `≤ limit_g · len_k`（同组同时维修数不超限）；
  - 单个作业在同一班次内的工作量 `≤ len_k`（一台设备同一时刻只占一个工位）。
- **作业（合成设备）**：工时 `d_i`（正整数槽）、风险分数 `s_i`（非负有理数）、
  启动成本 `c_i`（非负有理数）。
- **中断恢复**：作业可跨班次拆分；占用 `m_i` 个班次则计 `m_i · c_i`
  启动成本（首个班次 1 次启动，之后每次跨班恢复各计 1 次额外启动）。
- **目标**：`max Σ s_i − Σ m_i · c_i`（明示的分数收益，扣除启动成本）。

## 求解与状态三分

`solve(instance, max_nodes=None)` 返回 `Result`，状态严格分开：

| 状态 | 含义 |
|---|---|
| `OPTIMAL` | 搜索树在预算内耗尽，返回解已被证明最优 |
| `FEASIBLE` | 节点预算耗尽，返回已找到的可行解（最优性未决） |
| `BUDGET_UNDECIDED` | 预算耗尽且未评估任何节点（如 `max_nodes=0`），无可报告解 |

- 上界：`当前值 + Σ 剩余作业 max(0, s_i − c_i)`（每个作业至少占一个班次）。
- 作业按净收益上界降序展开，尽快获得好现任解；结果确定性可复现。
- `brute_force(instance)` 为独立参考实现（子集枚举 + 组内 DP），用于交叉验证。

## 运行

```bash
python3.11 main.py                          # 运行样例

```

## 运行样例（实际输出）

```text
=== 样例 1：预算不限（应证最优） ===
[样例1] 状态: optimal (扩展节点 102)
  净收益: 127/4 (=31.7500)
  选中 P1: 晚班+3
  选中 P2: 早班+4, 中班+1，占用 2 班
  选中 P3: 中班+2
  选中 V1: 早班+2
  选中 V2: 早班+3
  选中 V3: 早班+1
  选中 V4: 晚班+4

=== 样例 2：节点预算=3（可行但未证最优） ===
[样例2] 状态: feasible (扩展节点 3/3)
  净收益: 17 (=17.0000)
  选中 P1: 中班+2, 晚班+1，占用 2 班
  选中 P2: 早班+4, 中班+1，占用 2 班

=== 样例 3：节点预算=0（预算未决） ===
[样例3] 状态: budget_undecided (扩展节点 0/0)
  无可报告解（预算未决）

=== 样例 4：中断恢复计额外启动成本 ===
[样例4] 状态: optimal (扩展节点 14)
  净收益: 8 (=8.0000)
  选中 F1: 白班+3, 夜班+2，占用 2 班
  选中 F2: 夜班+2
```

样例 4 中 `F1` 工时 5 超过单班长度，必须跨 2 班：净收益 `10 − 2×3 = 4`；
`F3` 跨班后净收益为 0，被最优解排除。

## 测试结果

`python3.11 -m unittest discover -s tests`：**22 个测试全部通过（OK）**，覆盖：

- 状态三分：零预算 → `BUDGET_UNDECIDED`；小预算 → `FEASIBLE`；不限预算 → `OPTIMAL`；
- 最优性：样例及 30 个随机合成实例与独立暴力参考 `brute_force` 逐一比对一致；
- 约束：同组同时上限（聚合容量）、单作业单班上限、工时完整分配；
- 中断成本：跨班作业计额外启动、净收益为负的中断作业被拒绝；
- 精确有理数：`1/3 + 1/3 + 1/3` 精确等于 `1`；结果确定性；
- 数据校验：非法时长/上限/负分数/未知组/重复 id 等均抛 `ValueError`。
