# 分组限流模拟器（groupsim）

按轮分配的限流模拟器：为各组保留最低额度（保底），空闲份额暂借给其他组；
组恢复活跃后下一轮收回借额，已发出的许可不撤回。

## 模型

- 每轮流程：先按顺序应用本轮事件（`request` / `cancel`），再进行本轮分配。
- 分配分两阶段：
  1. **保底**：每个有待批准请求的组先获得 `min(需求, 保底额度)`；
  2. **暂借**：剩余容量（含无需求组让出的保底份额）按组轮询借给仍有需求的组，
     此类许可标记 `borrowed: true`。
- 组恢复活跃（重新出现待批准请求）后，下一轮其保底额度自动被保留，即收回借额；
  收回只影响后续分配，历史轮次已发出的许可不撤回。
- 取消事件只移除尚未批准的请求；对已发出的许可无效。

## 不变量（每轮输出后自动验证）

1. **保底**：各组获批数 ≥ `min(本轮需求, 保底额度)`（要求配置满足保底总和 ≤ 总容量，否则拒绝运行）；
2. **总量**：每轮发出的许可数 ≤ 总容量；
3. **组内先来先服务**：同组许可的批准顺序与请求到达顺序一致。

任一不变量被破坏时进程以退出码 1 结束。

## 输入格式（JSON，文件或标准输入）

```json
{
  "capacity": 10,
  "groups": { "A": 4, "B": 4, "C": 2 },
  "rounds": [
    { "events": [
      { "type": "request", "group": "A", "id": "a1" },
      { "type": "cancel", "id": "a1" }
    ]}
  ]
}
```

## 运行

```sh
go run . -f examples/demo.json     # 或：cat examples/demo.json | go run .
go test ./...                      # 不变量单元测试 + 随机场景验证
```

输出为每轮的许可序列（`grants`，含 `borrowed` 标记）、各组需求/获批统计（`stats`）
以及三条不变量的验证报告（`report`）。
