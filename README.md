# Lease Read Optimizer — 基于租约的多副本强一致读优化器

分布式数据库只读优化技术：主节点租约有效期内，只读请求**无需**向从节点发起网络协商，
直接本地读取最新已提交数据，同时保证**严格线性一致性**。

## 核心原理

```
租约时间轴（主节点本地时钟）
│◄──────── 租约有效期 ────────►│
│      ◄── 绝对安全窗口 ──►│ε│◄── 100ms 降级阈值 ──►│
│      零网络开销本地读     │  全量心跳确认后再读     │
```

- 从节点收到心跳后承诺：在 `promisedUntil`（本地时钟）之前不选举新主；
- 主节点只要满足 `剩余租约 − 最大时钟偏移 ε ≥ 100ms`，集群中即不可能存在其他主，
  本地副本必为最新已提交数据 → **零网络开销本地读**；
- 剩余租约不足 100ms 时自动降级：向**全部**从节点并行心跳，多数派确认并续期后才读；
- 多数派不可达时**拒绝读**，宁可不可用也绝不违反线性一致性。

## 目录结构

- `src/clock.ts` — 可注入时钟（真实/手动），保证测试确定性
- `src/lease.ts` — 租约管理器：绝对安全窗口判定（扣除时钟偏移 ε 与 100ms 阈值）
- `src/transport.ts` — 网络传输抽象 + 带延迟/分区故障注入/调用计数的模拟实现
- `src/follower.ts` — 从节点：心跳响应与租约承诺
- `src/primary.ts` — `LeaseReadOptimizer`：快速路径 / 降级路径读
- `test/lease-read.test.ts` — Node.js 内置测试（`node:test`）
- `examples/demo.ts` — 运行样例

## 运行

```bash
npm test     # Node.js 内置测试（7 个用例，含 1 万次并发读验收）
npm run demo # 运行样例：安全窗口 / 自动降级 / 多数派不可达三场景
```

要求 Node.js ≥ 22.6（利用原生 TypeScript 类型擦除直接运行 `.ts`，无需编译）。

## 实测结果

```
[场景1] 租约剩余 5000ms，处于绝对安全窗口
  完成 10,000 次并发读，耗时 4.7ms
  吞吐 ≈ 2,133,201 reads/s
  网络调用次数 = 0（零网络开销 ✓）

[场景2] 租约剩余 30ms，低于 100ms 阈值
  读路径来源 = quorum-confirmed（降级 ✓）
  本次读网络调用 = 5 次（全量心跳确认）

[场景3] 多数派不可达 → 拒绝读（线性一致性 ✓）
```

测试：`7 passed / 0 failed`，其中 1 万次并发读断言 `networkCallCount === 0`。
