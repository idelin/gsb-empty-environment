# DNS 名称线格式解码器（取证台）

从抓包回放的整包数据中解码 DNS 压缩名称，修复“压缩指针跳转后的偏移被当成
下一字段位置”的问题：指针结束后返回的是指针自身两个字节之后的位置，而不是
指针目标名称的尾部。

## 输入

stdin 每行一个 JSON 对象：

```json
{"hex": "<整包十六进制，允许空白>", "at": [名称起始偏移, ...]}
```

- `hex`：整个数据包的十六进制文本，解码失败时本行所有结果为 `null`。
- `at`：一组名称起始偏移（字节，从 0 开始），允许前向引用。

## 输出

每行输出一个与 `at` 等长的 JSON 数组。单项有效时为
`[标签十六进制数组, 原位置下一字节偏移]`，无效时为 `null`。

- 标签数组按域名顺序排列，每个标签是其原始字节的两位小写十六进制字符串
  数组，不含长度字节；根标签（长度 0）不输出，因此根名称为 `[]`。
- “原位置下一字节偏移”指编码名称在该起始位置所占字节之后的第一个字节：
  普通名称取根标签之后，遇到压缩指针则取该两字节指针之后（指针目标名称
  继续解析，但不影响这个偏移）。

示例：

```text
输入: {"hex":"03666f6f03636f6d00c000","at":[0,9]}
输出: [[[["66","6f","6f"],["63","6f","6d"]],9],[[["66","6f","6f"],["63","6f","6d"]],11]]
```

其中偏移 9 是指向偏移 0 的两字节压缩指针，下一字节偏移为 11，而不是 9。

## 有效性规则

出现以下任一情况，该名称（以及引用它的名称）判为无效，输出 `null`：

- 压缩指针环，包括自环与多跳环（0x11 前缀两字节指针）。
- 保留前缀：首字节高两位为 `01` 或 `10` 的标签类型。
- 越界：起始偏移、指针目标、标签内容或第二指针字节超出包长。
- 展开后的名称超过 255 字节，长度口径含每个长度字节和根标签；恰好 255
  字节合法。

## 共享后缀与复杂度

每个包偏移的解码结果按偏移记忆化（`name/decoder.go`），每个偏移最多解析
一次。多个起点共享同一条后缀链时，链不会按起点数量被重复遍历；总读取字节
数相对包长为线性，而不是“包长 × 起点数”。`Decoder.Reads()` 暴露实际读取
计数，测试用它约束长共享链场景。

## 构建与测试

```sh
go build -buildvcs=false .
go test -buildvcs=false ./...
```

测试覆盖多跳/前向指针、指针环、保留前缀、各类越界、255/256 字节边界以及
多起点共享后缀与共享长链。
