# gsb — 分片成员表反熵同步

两个分片集群恢复连接后，用摘要交换 + 区间拉取的反熵协议合并成员表，
避免全量广播挤满链路。仅使用 Go 标准库。

## 记录模型与合并

- 记录为 `(nodeID, incarnation, state)`(`record.go`)。
- 合并序:incarnation 大者胜；同 incarnation 按 `alive < suspect < dead`。
- `Merge` 是有限格上的 join(交换、结合、幂等),因此**旧响应永远覆盖不了
  新记录**:同步进行中本地继续更新也是安全的,重复、乱序、过期的投递
  都只会被合并吸收。

## 分片

- `ShardOf(nodeID) = FNV1a(nodeID) % numShards`,固定哈希,纯函数,同配置
  的节点对分片归属必然一致(`table.go`)。
- 分片只是传输索引,记录是全局的:节点跨分片配置变更(numShards 不同)时,
  摘要边界不可比,退化为拉取对方全部分片,合并规则不变,仍然收敛。

## 协议(每轮)

1. **摘要交换**:发起方发送全部 `Digest`,对方回自己的。`Digest` 绑定
   分片边界(shard 索引 + numShards)、记录数和规范序内容哈希
   (`HashRecords`),并携带分片快照版本。
2. **只拉不一致分片**:摘要不一致(或配置不同)的分片,按 NodeID 升序
   分页拉取。
3. **游标绑定快照**:`RangeRequest{After, Snapshot}`。服务端发现
   Snapshot 已过期 → 返回 `Restart`,客户端从头部重拉,**绝不跳过记录**。
   响应都携带快照版本;分页在字节预算内至少含一条记录,保证游标必然前进。
4. **整片校验后落库**:拉取的分片先缓冲,收齐后重算摘要与响应里的
   `Final` 摘要比对,通过才 `Apply`。不完整响应、伪造摘要、重复区间
   都在这一步(或游标过滤 `filterRange`)被拦截。
5. **字节上限**:请求/响应都有 `MaxReqBytes`/`MaxRespBytes`,超限即拒绝。

## 信任分数

`Trust` 只用于探测调度(加权无放回抽样决定每轮访问顺序),分数有下限
`TrustFloor > 0`,任何 peer 都不会被饿死;分数**从不**参与记录接受判断,
合法的新 incarnation 总能恢复(见 `TestTrustCannotBlockRecovery`)。

## 终止性论证(有限稳定数据 + 公平轮询)

- **格有限**:节点集合有限、incarnation 有上界、状态三值,故全表构成
  有限格 L;`Apply` 是 join,本地表在 L 中单调不减。
- **公平轮询**:每个有序对 (A,B) 被无限次探测;故障(丢包、截断、伪造、
  重复、取消)只发生有限次(或最终以正概率出现干净轮)。
- **每轮有进展**:若 A、B 表不一致,则某分片内容不同 → 摘要(绑定边界+
  计数+内容哈希)不一致 → A 拉取该分片;游标保证不漏(快照失效即重启)、
  每页至少一条记录保证前进;整片校验通过才落库,落库使 A 在 L 中严格
  上升,除非 A 已覆盖 B。
- **有限格 + 严格上升 ⇒ 有限轮后静止**:所有有序对摘要一致 ⇒ 各表相等,
  且等于独立全量合并模型 `FullModel`(join 的幂等/交换/结合律)。
  此后每轮只剩摘要交换,零记录传输(`TestTerminationUnderFairPolling`
  验证收敛与静默;`Sim.Converged` 用模型逐表核对)。
- 注:哈希碰撞会打破"内容不同 ⇒ 摘要不同"。64 位 FNV 下概率可忽略;
  要确定性保证可把摘要换成全量比较,协议其余部分不变。

## 测试与回放

```sh
go test ./...          # 合并格、摘要绑定、快照重启、分页、各故障场景、终止性
go run ./cmd/replay -scenario clean|faults|reshard|cancel [-nodes 6 -shards 8 -seed 1]
```

回放 CLI 打印每轮(每 sweep)的请求/响应字节、拉取记录数、游标进度、
重启与拒绝计数,结束时用独立全量合并模型逐节点校验最终表。
