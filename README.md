现场设备能验证活跃槽的度量和回滚计数器，却不能在重启前读出刚写入的备用槽。前一版更新器按完整内部状态规划，每个真实状态都能找到安全路径，实际设备却可能因为不能区分这几个状态而选错操作。给 Go 更新宿主实现可导入的策略规划包。组件、镜像摘要、签名根和不可下降的计数器仍由输入给出；每种写入声明可能的持久结果及相应公开观测，断电后所有尚未认证完成的槽只能作为未知候选，不能当作已成功写入。宿主只根据目前为止的公开观测选下一步，恢复组合必须对同一观测下所有可能的持久结果都有效。要求在最多一次断电、任意合法中断位置下保证每一步都能离线引导，并最终达到指定签名镜像；不可用“如果知道真实槽内容就这样做”作为恢复办法。返回最坏操作数最少的观测分支策略及独立可核验的安全不变量。明确定义无法区分但必须采取不同动作的状态应如何拒绝规划。给出一套很小的完整状态参考，覆盖切换前写入未知、提前烧录计数器导致某个隐藏状态失去最后恢复路径、同一操作成功和断电得到相同观测，以及重启后读回度量才可安全分支。只在内存中模拟。
