NVMe Zoned Namespaces（ZNS）SSD 取消了设备内部昂贵的随机写 FTL，改为向主机暴露严格顺序追加的 Zone 模型，主机侧存储引擎必须精确遵守 NVMe ZNS 协议状态机与资源限额并协同完成冷热分层垃圾回收，四处规范硬约束极易违规：1）**Zone 七态生命周期与严格写指针（`WritePointer`）**：每个 Zone 维护状态 `EMPTY`、`IMPLICITLY_OPEN`、`EXPLICITLY_OPEN`、`CLOSED`、`FULL`、`READ_ONLY`、`OFFLINE` 以及 `SLBA`、`ZoneCapacity`（注意 `ZoneCapacity <= ZoneSize`，可写区域止于 `SLBA + ZoneCapacity` 而非 `ZoneSize`！）和当前 `WritePointer`；任何普通写入的起始 LBA 必须严格等于 `WritePointer`（否则报 `InvalidZoneWrite`！），支持 `ZoneAppend` 自动原子返回分配的写入 LBA 并推进 `WritePointer`；写满 `ZoneCapacity` 自动转 `FULL` 并释放活跃/打开槽位；2）**`MAX_OPEN_ZONES (MOR)` 与 `MAX_ACTIVE_ZONES (MAR)` 硬件槽位约束**：隐式打开（直接对 `EMPTY`/`CLOSED` 区写入）与显式打开（`ZoneOpen`）共同计入 `Open` 槽位，而 `IMPLICITLY_OPEN + EXPLICITLY_OPEN + CLOSED` 共同计入 `Active` 槽位！当 `Open` 槽位已满且发生新的打开请求时，按 NVMe 规范**只允许自动驱逐（转为 `CLOSED`）一个 `IMPLICITLY_OPEN` 区**来腾出槽位——若当前全为 `EXPLICITLY_OPEN` 区则必须报 `TooManyOpenZones`；若 `Active` 槽位已满且试图激活新 `EMPTY` 区必须报 `TooManyActiveZones`（`ZoneFinish` 可强制填满转 `FULL` 释放 `Active` 槽位！）；3）**主机侧逻辑地址映射与冷热分层追加**：基于逻辑块映射表 `LBA -> (zoneID, offset)` 与无效块位图，将高频覆盖热数据与低频冷数据路由至不同开放 Zone，避免冷热混写导致高写放大（WAF）；4）**原子垃圾回收（GC）与 `ZoneReset` 安全回收**：选择有效块占比最低的 `FULL`（或指定）Zone，将尚有效的逻辑块按原子比较交换迁移到目标 GC Zone 并更新映射表（绝不可覆盖在此期间已被新写入更新过的热块！），确认原 Zone 有效块归零后再执行 `ZoneReset` 重置回 `EMPTY` 并统计精确写放大率（WAF）。为闪存存储引擎交付可导入的 Go NVMe ZNS 状态机与主机侧冷热分层 GC 引擎。验收覆盖 `ZoneCapacity < ZoneSize` 边界与错位写拦截、`MOR`/`MAR` 槽位满时仅驱逐 `IMPLICITLY_OPEN` vs 保护 `EXPLICITLY_OPEN`、并发覆写期间 GC 不覆盖新版本以及冷热分离对比混写显著降低 WAF。
