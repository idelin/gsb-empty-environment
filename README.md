# htblimit — 树状令牌桶限速器（离散事件模型）

纯 Go 标准库实现（`math/big.Rat` 有理数运算），整数 tick 时钟，不发真实网络流量。

## 设计规则

- **沿路径原子扣减**：每包必须在根到叶的每个桶上都有额度；要么全路径扣减（并返回逐跳证据 `Deduction{Before, After}`），要么一分不扣，包留在队列里。
- **有理速率补充**：速率是有理数 token/tick，余额用 `big.Rat` 精确累积，不丢小数（如 1/3 token/tick）。
- **取消不耗令牌**：排队包不持有令牌，`Cancel` 只动队列。
- **运行中重挂租户**：`Reattach` 原子迁移子树——未发送队列和桶内保留令牌随节点一起走；旧/新路径先结算再移动；拒绝成环和移动根。
- **速率变化不重复补充**：补充是惰性的（按上次结算 tick 懒算），没有计时器；`SetRate` 先按旧速率结算到当前 tick 再切换，旧速率绝不会再补一次。
- **重复 tick 不重复补充**：`Advance` 到当前或过去 tick 是 no-op。
- **子桶有额度父桶不足不可发**：原子预检任一祖先不足即拒绝。
- **大包超容量**：`RejectOversize` 明确拒绝；`AllowDebt` 允许桶余额变负（债务），由后续补充偿还，偿还前不可再发。

## 独立逐事件账本验证

`htb/ledger.go` 的 `Ledger` 是与树不共享状态的独立账本，逐事件重放（advance/send/cancel/setrate/reattach），每个事件后校验：

- 树中每个桶余额与账本一致；
- 任一祖先（及所有节点）额度不透支（`RejectOversize` 下余额非负）；
- 余额不超过容量；
- 守恒：`余额 == 初始 + 累计补充 - 累计扣减`；
- 发送证据路径与账本自行维护的祖先链一致，逐跳 `Before/After` 精确衔接。

`htb/interleave_test.go` 枚举发送/取消/补充/重挂/变速的全部交错序列
（深度 4，两种债务策略各约 9500 条完整序列），并用固定种子的
300 步随机长序列（80 条）补充覆盖，每个事件后都跑账本校验。

## 运行

```sh
# Go 1.11 需要显式打开模块模式
GO111MODULE=on go test ./...   # 全部测试（含交错枚举）
GO111MODULE=on go run ./cmd/demo
```

## 布局

- `htb/htb.go` — 树、桶、发送/取消/补充/重挂/变速，逐跳扣减证据
- `htb/ledger.go` — 独立逐事件账本验证器
- `htb/htb_test.go` — 单元测试（有理补充、重复 tick、原子性、债务、重挂、变速、证据链）
- `htb/interleave_test.go` — 交错枚举 + 随机长序列的账本验证
- `cmd/demo/main.go` — 运行样例
