现代增量构建系统（Ninja/Bazel/Shake）不仅包含静态构建图，还支持编译期动态发现依赖（`dyndep`，例如扫描头文件或 Fortran/C++20 模块导入表后再向图里追加新依赖边）以及基于内容哈希的早停优化（Early Cutoff：当上游编译产物内容哈希与上次构建完全一致时，即使源文件注释改过导致上游重跑，下游所有依赖者也必须跳过重编！）；如果构建调度器在多输出规则（一条规则同时产出 `a.o` 和 `a.d`）中只按规则粒度记哈希而非按单个输出文件记哈希，或在动态加边时未即时检测新形成的依赖环，就会出现漏编（错误复用过时产物）或整图反复全量重编。为构建运行时交付可导入的 TypeScript 增量构建引擎。构建图由源节点、构建规则（含静态输入、动态发现依赖钩子、多输出文件集合、可选 `volatile` 易变标志与确定性动作函数）以及持久化构建追踪账本（记录各规则上次执行时全部静态+动态输入内容哈希与各独立输出内容哈希）构成。规则：1）支持增量多轮构建，利用内容哈希实现精确早停——当某规则某个输入变脏迫使其重跑，若其产出的输出文件 `out1` 哈希未变而 `out2` 哈希改变，则仅依赖 `out1` 的下游规则必须跳过执行，依赖 `out2` 的下游必须重跑！2）支持动态依赖发现：规则在静态输入就绪后先解析其 `dyndep` 声明的新依赖节点，将这些新边纳入当前构建并等待新依赖全部完成后再执行动作；若动态加边形成静态或动态环路，必须立即报错指出精确环路径而绝不死锁；3）若上次构建记录的某动态依赖文件本轮已变动，即使静态输入未变也必须触发该规则重核；4）正确处理并发度上限 `maxJobs` 下的拓扑调度、失败取消隔离（保留已完成产物的有效缓存）与 `volatile` 节点强制重跑（但若 `volatile` 输出哈希不变下游仍可早停！）。验收覆盖注释改动触发早停跳过深层下游、多输出规则仅单输出变化精准传播、动态依赖发现新增依赖与动态环路拦截、跨轮删除/变更旧动态依赖触发重编以及增量构建与全新干净构建最终产物逐字节一致。
