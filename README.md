# bptree — 页式 COW B+ 树（Go 标准库）

为本地索引的持续写入场景提供**固定版本的范围扫描**：写事务 copy-on-write，
提交产生新根；旧读者持有旧根，导出任务可以长时间扫描而不被写入干扰。
仅依赖 Go 标准库。

## 特性对应

| 需求 | 实现 |
| --- | --- |
| 整数键、字节值、页容量为参数 | `int64` 键；值 ≤ `MaxValueSize`(128B)；`Open(path, capacity)` |
| 写事务 COW，提交生成新根 | `DB.Update(fn)`：全部改动写新页，最后写元页发布新根 |
| 旧读者持有旧根 | `DB.Snapshot()` 钉住当前根，直到 `Close()` |
| 左闭右开范围 | `Snapshot.Scan(start, end)` 扫描 `[start, end)`，空范围返回空 |
| 跨叶不跳进新树 | 迭代器只跟随**本快照所属提交**写入的叶链；其余情况按 key 在钉住的树内重新定位（见下） |
| 重复键覆盖 | `Tx.Put` 同键覆盖 |
| 删除借位/合并/根收缩 | `Tx.Delete` → `rebalance`（左右借位、左右合并），根 0 键时收缩 |
| 写失败不发布新根 | 提交协议：先写数据页→再写元页→sync；任何失败回滚页分配，根不变 |
| 快照关闭后迭代报错 | 迭代器/快照所有操作返回 `ErrSnapshotClosed` |
| 回收只删不可达页 | `DB.Reclaim()` 从当前根+所有快照根做可达性标记，其余页回收复用 |
| 独立校验器 | `DB.Validate(root)`：键序、分隔键=右子树最小键、叶同深度、容量、页引用唯一合法、本提交叶链一致 |
| 页文件损坏检查 | 每页 CRC32 校验和；`CheckIntegrity()` 全量校验；读路径即时检测 |

## 关键设计

**页与提交**。页固定 4096 字节，页 0 为元页（当前根、提交序号、容量、页数，
带校验和）。每次提交序号 +1，新页打上该序号（version）。COW 事务内复制的
节点分配新页号，旧页永不修改，因此任何历史根都可随时重放。

**叶链与跨版本迭代**。叶页带 `next` 链，但链只在**写入它的那次提交**内可信：
后续提交复制叶页时不会回改旧页的 `next`（旧页不可变）。因此迭代器跨叶时：

- 当前叶 `version == 快照提交序号` → 链是本次提交写的，直接跟随；
- 否则（共享的旧叶，其 `next` 可能指向已被新版本替换的页）→ 放弃链接，
  用最后返回的 key 在**钉住的根**内重新下行定位（`seekGT`）。

提交前 `fixLeafLinks` 会把本事务创建的所有叶的 `next` 修正为新树的中序顺序，
保证上述不变量。校验器只对本提交版本的叶检查链一致性。

**回收**。`Reclaim` 在写锁内从「当前根 ∪ 所有活跃快照根」做 BFS 标记，
未标记且未空闲的页写为 free 页并进入空闲链表复用。由于只回收所有活动根
均不可达的页，任何迭代器都不可能读到被回收的页。

## 使用

```go
db, _ := bptree.Open("index.db", 16)   // capacity = 每节点最大键数
defer db.Close()

db.Update(func(tx *bptree.Tx) error {  // 写事务：COW，提交发布新根
    tx.Put(42, []byte("hello"))
    return tx.Delete(7)
})

snap := db.Snapshot()                  // 钉住当前版本
defer snap.Close()
it := snap.Scan(10, 20)                // [10, 20)
for it.Next() {
    k, v := it.Key(), it.Value()
    _ = k; _ = v
}
if err := it.Err(); err != nil { /* ErrSnapshotClosed 等 */ }

db.Validate(db.Root())                 // 独立结构校验
db.Reclaim()                           // 回收所有活动根均不可达的页
db.CheckIntegrity()                    // 页文件损坏检查
```

## 测试

```sh
go test ./...        # 功能 + 参考模型对照 + 并发
go test -race ./...  # 竞态检测
go run ./cmd/demo    # 最小复现样例：长扫描与叶分裂/合并写入交错
```

- `ref_test.go`：以**不可变有序映射**为参考模型，400 轮随机写事务
  （capacity=4，持续触发叶分裂/合并/根收缩）交错长扫描，扫描中途还插入
  额外写事务；逐键比对无重漏、旧值稳定，并周期性 `Validate` 与 `Reclaim`。
- `iterator_test.go`：快照隔离（扫描期间覆盖写+分裂+合并）、空范围、
  快照关闭后迭代报错、慢扫描交错写。
- `db_test.go`：基本读写覆盖、删除借位/合并/根收缩、事务函数失败与
  注入写失败均不发布新根、重开持久化。
- `reclaim_test.go`：回收保留活跃根、关闭快照后可回收、页复用。
- `corrupt_test.go`：数据页/元页损坏可被检测。
- `cmd/demo`：最小复现样例。
