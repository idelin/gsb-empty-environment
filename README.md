堡垒机与基础设施认证网关在离线校验 OpenSSH 证书（`PROTOCOL.certkeys`）与二进制密钥吊销列表（KRL，`PROTOCOL.krl`）时，若忽略无法识别的 `critical options`（如自定义强制约束）而放行登录、未严格校验 `source-address` CIDR 白名单（含 IPv4/IPv6 混合列表）或漏解析 KRL 中按证书 `serial` 区间/位图及 `key_id` 的吊销段，已离职员工或窃取证书的攻击者可绕过 IP 限制、强行执行任意命令或继续使用已吊销证书登录生产节点。为 Go 认证宿主实现可导入的原始二进制 OpenSSH 证书与 KRL 解析及准入验证包，严禁联网与严禁依赖外部 SSH 库（仅用标准库 `crypto/ed25519`/`crypto/ecdsa`/`crypto/sha256`/`net/netip`）。组件严格实现：（1）按 SSH Wire Format（4 字节大端长度前缀）解析 `ssh-ed25519-cert-v01@openssh.com` / `ecdsa-sha2-nistp256-cert-v01@openssh.com` 证书，验签 CA 公钥（拒绝未列入受信 CA 且拒绝用户证书/主机证书 `cert_type` 混用）、校验 `valid_after <= now < valid_before` 及 `valid_principals` 精确匹配（非空且禁止通配符滥用）；（2）严格校验 `critical options`（仅识别 `force-command` 与 `source-address`，遇到任何未知 critical option 必须硬拒绝；校验 `source-address` 合法 CIDR 列表包含客户端 IP，且存在 `force-command` 时强制覆盖请求命令）与 `extensions` 白名单；（3）完整解析 `SSHKRL\n\0` 二进制 KRL 文件（支持 `KRL_SECTION_CERTIFICATES` 下的 `SERIAL_LIST`/`SERIAL_RANGE`/`SERIAL_BITMAP`/`KEY_ID` 及 `KRL_SECTION_EXPLICIT_KEY`/`FINGERPRINT_SHA256` 段，核对 CA 匹配），检出任意命中吊销的证书或底层公钥。附未知关键选项拒绝、IPv4/IPv6 CIDR 拦截、KRL 序列号位图/区间吊销与 cert_type 混淆测试。
