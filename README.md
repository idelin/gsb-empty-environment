# fsreplay — 合成文件树操作日志重放工具

在合成文件树上重放 `create` / `rename` / `unlink` 操作日志。
节点 ID 稳定（创建时分配、永不复用），路径只表示节点当前位置。

## 语义

- **create**：父目录必须存在，目标名不得占用；分配全新 ID。
- **rename**：目录可整体搬移（子树身份不变）；目标已存在时按类型匹配
  原子替换（文件换文件、空目录换空目录）；禁止把目录移入自己的子树
  （父环）；目标父目录缺失则失败。
- **unlink**：文件或空目录；根不可删。
- **原子性**：每个事务先完成全部校验再提交，失败不会留下半个改名。

## 双重模型核对

重放引擎同时在两棵独立实现的树上执行每条日志：

- `tree.go`：指针树（子节点 map）。
- `verify.go`：扁平记录模型（无子指针，靠扫描找子节点、沿父链推路径）。

每步之后比对两者的 `路径 -> ID` 映射，不一致即报错中止。
`Checker` 同时审计日志本身：序号重复、序号缺口、先删后重建同路径
（重建必须获得新身份，复用旧 ID 视为问题）。

## 用法

```sh
go build -o fsreplay .
./fsreplay examples/demo.log   # 或从 stdin 读入
go test ./...
```

日志为 JSON Lines，每行一个事务：

```json
{"seq":1,"op":"create","path":"/a","type":"dir"}
{"seq":2,"op":"rename","src":"/a","dst":"/b/a"}
{"seq":3,"op":"unlink","path":"/b/a"}
```

输出每步的操作结果、涉及的身份变迁，以及该步之后完整的
`路径 -> ID` 映射；末尾汇总重建记录与日志问题。
存在日志问题、失败事务或模型分叉时退出码为 1。
