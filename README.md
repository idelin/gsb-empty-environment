现代文件系统（ext4/XFS）用 Extent 树映射文件逻辑块到物理块，并通过单一最高位区分已初始化区段（最大长度 `32768` 块）与 `fallocate` 预分配但尚未写入数据的未写区段（Unwritten Extent，最大长度 `32767` 块，读时必须返回全零而非磁盘残留数据！）；当向未写区段正中写入几块数据、或执行 `PUNCH_HOLE`/`COLLAPSE_RANGE`/`INSERT_RANGE` 时，区段劈分、邻接合并与逻辑偏移平移极易产生长度超限或覆盖错位。为文件系统元数据引擎交付可导入的 Go Extent 树管理器。每条区段记录 `(logicalStart, length, physicalStart, unwritten)`，保持严格按 `logicalStart` 升序互不重叠。实现操作：1）`Preallocate(lStart, len, keepSize)`：仅对空洞分配未写区段（已有已写或未写区段保持原样不覆盖！），超 `32767` 块自动切分；2）`Write(lStart, len)`：对命中的未写区段原地转换为已写（局部命中时精确劈成左未写、中已写、右未写），对空洞分配新物理块并标为已写，随后仅在物理连续、逻辑连续、同 `unwritten` 状态且总长不超过对应上限（已写 `32768` / 未写 `32767`）时向左向右自动合并；3）`PunchHole(lStart, len)`：打洞释放区间内所有已写与未写物理块并劈分残段，返回精确释放的物理块区间列表；4）`CollapseRange(lStart, len)` 与 `InsertRange(lStart, len)`：在边界校验通过（区间须非空、不越出文件尾等）后移除或插入逻辑空洞并平移所有后续区段的 `logicalStart`，平移后重新尝试与左邻合法合并。验收以逐逻辑块状态数组（含物理块号与未写标志）作全操作等价对照，覆盖 32767/32768 合并上限、未写区段正中写入三段劈分、`Preallocate` 跳过已写块、以及打洞与折叠/插入后物理块零泄露。
