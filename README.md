# parkingfee 停车计费工具

处理缺失一次进出事件的停车记录: 在**最多补 1 个事件**的条件下恢复合法停车段,
输出**最低与最高可能费用**及对应的**补事件时间区间**。
当费用无法唯一确定时, 工具只给出范围, 绝不猜测单一账单。

## 构建与运行

```sh
go build -o parkingfee .
./parkingfee [flags] <events.json | ->   # "-" 表示从标准输入读取
```

参数:

| 参数 | 说明 | 示例 |
| --- | --- | --- |
| `-free` | 每段免费时长(必填语义见下) | `15m` |
| `-unit` | 计费单位, 每段不足一单位向上进位, 默认 `1h` | `30m` |
| `-rate` | 每计费单位价格(元), 必填 | `2.5` |
| `-daily-cap` | 每个自然日封顶(元), `0` 表示不封顶(默认) | `30` |
| `-since` | 补事件时间下界(RFC3339), 可选 | `2026-10-01T08:00:00+08:00` |
| `-as-of` | 补事件时间上界(RFC3339), 可选 | `2026-10-01T20:00:00+08:00` |
| `-json` | 以 JSON 格式输出 | |

事件文件为 JSON 数组, 每条事件含 `time`(RFC3339)与 `type`(`in`/`out`):

```json
[
  {"time": "2026-10-01T08:00:00+08:00", "type": "in"},
  {"time": "2026-10-01T09:30:00+08:00", "type": "out"}
]
```

## 计费语义

对单个停车段 `[进场, 出场]`:

1. 计费时长 = `max(0, 停车时长 - 免费时长)`;
2. 计费单位数 = 计费时长按 `unit` **向上进位**, 段费用 = 单位数 × 单价;
3. 若设置日封顶, 段费用不超过 `段跨越的自然日数量 × 日封顶`
   (自然日按进场时间所在时区划分)。

事件时间精度为秒; 任意两条事件时间不得相同。

## 缺失事件恢复

- 合法记录为进出交替、先进后出的偶数条序列。偶数条且合法 → 记录完整, 直接计费。
- 奇数条 → 恰好缺失 1 个事件。工具枚举所有能使序列合法的插入位置
  (位置唯一确定事件类型), 每个位置对应一个补事件时间可行区间
  (介于相邻事件之间; 在首尾时可能无界, 可用 `-since`/`-as-of` 限定)。
- 其余情形(偶数条不合法、奇数条无法修复)→ 报错, 说明缺失超过 1 个事件。

## 费用极值与补事件区间

补事件时间为变量 `t` 时, 总费用是关于 `t` 的分段常值函数
(只在计费单位边界与自然日边界处变化)。工具枚举全部费用分段, 精确求得:

- **最低费用**及达到它的补事件时间区间;
- **最高费用**及达到它的补事件时间区间;
- 若补事件时间无界且单价为正, 最高费用报告为**无界**;
- 若最低 = 最高, 报告费用唯一确定(仍给出补事件时间区间)。

## 示例

```sh
$ echo '[{"time":"2026-10-01T08:00:00+08:00","type":"in"}]' > ev.json
$ ./parkingfee -free 15m -unit 30m -rate 2 -daily-cap 20 -as-of 2026-10-01T20:00:00+08:00 ev.json
记录缺失 1 个事件, 已在最多补 1 个事件的条件下恢复合法停车段。
费用无法唯一确定, 给出可能范围(不猜测单一账单):
  最低费用: ¥0.00
    方案: 补 out, 位置: 末条事件 2026-10-01T08:00:00+08:00(in) 之后
      补事件时间: 2026-10-01T08:00:01+08:00 ~ 2026-10-01T08:15:00+08:00
  最高费用: ¥20.00
    方案: 补 out, 位置: 末条事件 2026-10-01T08:00:00+08:00(in) 之后
      补事件时间: 2026-10-01T12:45:01+08:00 ~ 2026-10-01T20:00:00+08:00
```
