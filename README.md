# 信息流降密边界

机密报告服务希望把Go信息流标签检查包嵌入表达式执行器。标签为至多16个秘密来源的集合，表达式含常量、来源读取、加法、条件、局部变量和输出；显式值依赖及条件控制依赖都必须传播。唯一降密操作携带可信授权对象，只能移除对象允许的来源，授权绑定当前请求与表达式节点且一次使用；攻击者可构造AST、重复或跨请求引用授权，但不能伪造授权注册器。实现执行器、授权注册器及事件审计，公开输出只能标签为空；分支内部降密不能洗掉外围控制依赖，失败不得产生部分公开输出或消耗授权。给出嵌套条件泄露、授权重用、失败回滚和正常定点降密的可运行测试，明确并发请求的原子性。

## 设计要点

- **标签**:`Label` 为 16 位位掩码(`ifc.go`)。运行时值把标签拆成 `data`(显式值依赖)与 `pc`(条件控制依赖)两轨;进入分支时条件标签并入 `pc`,`Declassify` 只清 `data` 中被授权的来源,因此分支内降密洗不掉外围控制依赖。
- **降密授权**:`Registry.Issue` 签发绑定 `(RequestID, NodeID)` 的一次性 `Authorization`;`Consume` 在单把互斥锁内原子完成"存活校验 + 请求/节点匹配 + 核销",伪造(非本注册器签发)、跨请求、跨节点、重复使用分别返回不同错误。
- **失败原子性**:`Evaluator.Run` 缓冲全部公开输出,任一表达式失败即丢弃缓冲并 `Restore` 本次已消费的全部授权——不产生部分公开输出,也不消耗授权。
- **审计**:`AuditLog` 并发安全,记录 `OUTPUT` / `DECLASSIFY` / `ROLLBACK` 事件。
- **并发原子性**:注册器所有状态变更在同一互斥锁下串行化;并发请求竞争同一授权时恰好一个成功,失败者的回滚不会复活已被他人消费的授权(见 `TestConcurrentAtomicity`,`go test -race` 验证)。

## 运行测试

```sh
go test -race -count=1 ./...
```
