# 目录引荐跟随范围与凭据携带限制

## 引荐判定包

可导入包路径：`example.org/netsec/q0803/referral`（仅依赖标准库）。

核心 API：

- `referral.Policy{AllowedHosts: ...}`：可信目录主机白名单，比较时统一转小写；
  条目可以是裸主机名（匹配任意端口）或 `host:port`，ldaps 缺省端口归一为 636。
- `Policy.Decide(origin, chain, referralURL)` 返回 `Decision`，`Follow` 为真时
  `Rebind` 仅在第一跳携带原绑定凭据，后续跳转一律匿名重绑。
- `Chain` 记录已跟随节点，深度上限 `MaxDepth = 3`；同一主机、端口、DN 重复即
  判定为环（含指回原请求地址 `Origin.Addr` 的情况）。

判定规则：

1. 传输不允许降级：只跟随 `ldaps://`，或原连接为 StartTLS 且引荐 URL 携带
   StartTLS 扩展（OID `1.3.6.1.4.1.1466.20037`）；加密到明文一律拒绝
   （`ReasonDowngrade`）。
2. 引荐主机必须命中白名单（`ReasonHostNotWhitelisted`）。
3. 引荐 DN 先做百分号解码与 RFC 4514 反转义，再比较是否位于 `SearchBase`
   之下；含 `..` 穿越段或越界均拒绝（`ReasonDNOutOfScope`）。
4. 原绑定为匿名时，整条引荐链保持匿名；非匿名凭据只允许在首个跟随的白名单
   主机上重新绑定一次，不随链继续转交。

运行测试：`go test ./...`

目录客户端遇到服务端返回的引荐（referral）时，会自动用同一份绑定凭据去连引荐里的地址，攻击者控制或污染一个目录服务，返回指向自己机器的 ldap 地址，就能拿到用户的明文口令。Go目录访问库需要可导入的引荐跟随判定包，输入原请求的地址与是否已用加密传输、引荐地址列表、调用方的可信目录主机白名单和已绑定的身份：只跟随 ldaps，或原连接已用 StartTLS 且引荐也要求 StartTLS，从加密降到明文的引荐一律不跟随；引荐主机须在白名单内，按小写比较，ldaps 缺省端口取 636；引荐地址里的 DN 必须在调用方给的搜索根之下，含 .. 或百分号编码的 DN 解码后再比较；绑定凭据只用于白名单主机，且只在跟随时重新绑定一次，不得沿引荐链继续转交；引荐深度不超过 3，出现环（同一主机、端口与 DN 重复）即停止；原连接为匿名绑定时，引荐也只能匿名。用降级到明文、主机不在白名单、引荐环、DN 越界和凭据转交验证。
