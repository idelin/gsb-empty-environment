# hier-graph

将多表记录与增量变更组装为带稳定实体 ID 的层级图。纯 TypeScript（Node ≥ 23.6
原生类型擦除，无需编译步骤），零依赖，使用 Node.js 内置测试运行器。

## 运行

```sh
npm test        # node --test "test/*.test.ts"（21 个测试）
npm run sample  # 重放 sample/events.json 并与全量重建对照
```

## 模型

- **实体**：稳定 ID；字段集合 + 父子链接 + 子树聚合统计（`nodeCount`、`weightSum`）。
- **来源**：每个来源有优先级（`sample/events.json` 中 crm=10, erp=5, web=5）。
- **事件**：`upsert` / `delete`，按批次（JSON 兼容树）提交；对象键无序、数组有序。
- **`@parent` 保留字段**：父关系作为特殊字段参与同一套裁决，因此父关系更正、
  来源删除后的父链接回退都走统一逻辑。

## 语义规则

- **字段裁决**：每个字段保留每个来源的最新贡献（含来源、版本、来源内路径）。
  优先级高者胜；平级且值不同 → **未决冲突**（`effective=null`），绝不任选；
  平级同值不算冲突。
- **版本**：同来源版本单调递增，旧版本事件以 `STALE_VERSION` 拒绝并定位路径。
- **幂等**：`eventId` 跨批次去重，重复事件跳过，统计不双计。
- **孤儿队列**：子先于父到达时进入孤儿队列（`pendingParentId`），父出现后自动
  接续，子身份与字段不变。
- **父关系更正**：移动整棵子树；统计只沿受影响的新旧祖先链增量传播
  （`drainTouched` 可观测）。成环（如把 A 移入其后代 B）在提交前预检，
  **原子拒绝**——字段、链接、统计全部不变。
- **删除**：显式策略 `orphan`——父被删除时子保留身份进入孤儿队列等待接续，
  绝不静默级联删除；实体仅当所有来源都删除后才移除。
- **来源回退**：来源删除其记录后，字段回退到其他来源保留的旧贡献
  （旧快照可还原旧来源）。
- **错误定位**：所有错误携带 JSON Pointer 路径（如 `/events/1/entity/parentId`），
  字段血缘记录来源数据中的具体路径。
- **全量重建对照**：`compareWithRebuild` 从空仓库重放全部事件，增量结果必须与
  全量重建快照深度相等（键序无关）。

## 布局

- `src/json.ts` — JSON 类型、键序无关深比较、规范化、JSON Pointer
- `src/fields.ts` — 字段级血缘与确定性裁决
- `src/graph.ts` — 层级图：挂载/摘离、环检测、孤儿队列、子树统计增量传播
- `src/store.ts` — 事件校验（预览-提交两段式，保证原子性）、幂等、快照、血缘查询
- `src/rebuild.ts` — 全量重建与对照
- `src/sample.ts` + `sample/events.json` — 可重放样例（6 个批次覆盖全部场景）
- `test/` — 21 个 Node 内置测试
