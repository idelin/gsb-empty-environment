# PRIORITY_UPDATE帧状态膨胀

HTTP 服务器按 RFC 9218 处理优先级信号，攻击者可对从未开启或已关闭的流连发 PRIORITY_UPDATE，或在字段值里放畸形结构化字段让服务端状态膨胀。为Go服务端写供帧处理循环调用的优先级状态包，本题统一采用 HTTP/2 帧布局：PRIORITY_UPDATE（类型 0x10）负载为 4 字节流号加 Priority Field Value；流号为 0 或为偶数（请求流须为奇数）按连接错误；字段值按结构化字段字典解析，u 取 0 到 7 的整数、i 取布尔，未知键忽略，重复键以最后一个为准，任一已识别键类型错误则整个字段值丢弃并保持默认 u=3、i=false；尚未打开的流最多保留 64 个待定条目，超出时淘汰最旧的；流关闭后丢弃其条目，之后到达的更新忽略。用偶数流号、u=8、重复键、i 取整数、条目淘汰和关闭后更新验证。
