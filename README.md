# auditmerge — 哈希链审计日志合并

每条日志项包含**前项摘要**（`prev_hash`）与**单调序号**（`seq`），
`hash = SHA-256(seq ‖ payload ‖ prev_hash)`，任何改动都会破坏链条。

## 合并规则（`auditlog.Merge`）

- **只接受一致链**：先逐项校验自哈希，再从创世项逐序号检查链接；
  任何断链、缺段都会终止前缀，绝不跳号。
- **副本可缺段**：多来源取并集，同一序号的相同条目自动去重；
  所有副本都缺的段，前缀停在缺口处（`gap`）。
- **分叉不选边**：同一序号出现两个自洽但互斥的版本时，两条分支都
  作为证据保留在 `Forks`，前缀停在分叉前（`fork`），等待人工裁决。
- **不按最大序号选日志**：更长或序号更高的副本只有在哈希链一致时
  才被采信；伪造的长链无法扩展可信前缀。

输出为**最长共同可信前缀**：从创世项开始、哈希链完整、且所有覆盖
该序号的副本一致认可的最长连续段。

## 使用

```sh
go test ./auditlog/            # 删除 / 重复 / 篡改 / 分叉 / 最大序号陷阱 测试
go run ./cmd/auditmerge a.json b.json   # 合并副本，stdout 输出可信前缀
```

退出码：分叉时为 `2`（证据已保留，未自动选边），其余情况为 `0`。

## 副本 JSON 格式

```json
{
  "name": "node-a",
  "entries": [
    {"seq": 1, "payload": "op-1", "prev_hash": "00..00", "hash": "<hex>"}
  ]
}
```
