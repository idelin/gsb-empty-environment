基础设施即代码（IaC，如 Terraform/OpenTofu）的变更规划与执行图引擎在把声明式配置、当前远端漂移状态与生命周期规则编译为安全 DAG 时，藏着四条一旦写错就会引发生产中断的图变换法则：1）**`create_before_destroy`（CBD）向上游传递传播**：若资源 `A` 依赖 `B`，当 `A` 声明 `create_before_destroy = true` 且 `B` 也因 `ForceNew` 属性变更需要替换（Replace = Delete + Create）时，必须自动把 `CBD` 属性沿依赖边向上游传播给 `B`——执行顺序须变为 `Create(B') -> Create(A') -> Destroy(A) -> Destroy(B)`（否则先删旧 `B` 会瞬间摧毁仍在服役的旧 `A`！）；而若上游 `B` 带有 `forbid_cbd = true`（如云端全局唯一静态名称冲突无法两份并存！），规划器必须精确报 `CBD_CONFLICT` 并输出冲突依赖路径链而非静默违例！2）**`replace_triggered_by` 级联替换与 `prevent_destroy` 全局红线**：某资源自身无变更但通过 `replace_triggered_by` 引用了发生更新或替换的上游资源时，必须级联升级为 `Replace`；只要最终计划中任意动作（无论直接删除还是 `ForceNew`/`replace_triggered_by` 触发的替换销毁！）涉及标有 `prevent_destroy = true` 的资源，必须立刻阻断整份规划并列出触发链路！3）**`-target` 精准子图闭包反转**：正常 `apply -target=X` 仅纳入 `X` 及其全部上游传递依赖（排除无关资源）；而 `destroy -target=X` 必须反转方向，仅纳入 `X` 及其全部下游传递依赖（所有依赖 `X` 的孤儿资源必须先于 `X` 销毁！）；4）**远端漂移检测、依赖环拦截与依赖分离的替换图调度**：区分 `NoOp`/`Create`/`UpdateInPlace`/`Destroy`/`CreateThenDestroy`/`DestroyThenCreate`，将每个替换资源拆分为独立的创建/销毁节点并精确接线，校验合成后的动作执行图严格无环（有环报极小环！）并按最大并发度输出分波次执行计划与失败时的最小影响中断（仅跳过下游依赖失败节点的动作，独立分支继续完成！）。为云资源编排控制面交付可导入的 Go IaC 依赖规划与执行图引擎包。验收覆盖 `CBD` 多层向上传播、`forbid_cbd` 冲突链报错、`replace_triggered_by` 触发 `prevent_destroy` 拦截、`apply` vs `destroy` 下 `-target` 正反闭包方向、替换拆节点后环检测以及单分支失败局部阻断验证。
