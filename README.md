# oplog-recovery：操作日志状态恢复

从操作日志恢复确定性状态。纯 TypeScript（可擦除语法），零依赖，不借用任何响应式框架；
用 Node.js 内置 `node:test` 验证（Node ≥ 22.6，`--experimental-strip-types` 直接运行 `.ts`）。

## 设计

- **日志即事实**：每条记录 `{seq, prev, body, hash}`，`hash = sha256(canonical({seq, prev, body}))`，
  形成哈希链；任一前缀的摘要 = 该前缀末条记录的哈希。规范化序列化与 JSON 语义对齐
  （忽略 `undefined` 键、键序无关），保证同一逻辑内容摘要唯一。
- **检查点绑定前缀摘要**：检查点携带 `uptoSeq + prefixHash + 已提交状态 + 已应用操作 ID +
  已确认副作用 + 待确认副作用`，并有自身摘要防篡改。只有 `prefixHash` 与日志实际前缀
  摘要一致时才可作为恢复基点，否则拒绝。
- **事务**：`tx.begin / op(tx) / tx.commit | tx.abort`。暂存操作只在提交时落库，
  读者（`getState()`）永远看不到中间态；中止的写入永不生效。
- **副作用确认**：`effect` 记录是外部动作的确认回执。回放前预取扫描确认集，
  已确认的外部动作绝不重复触发；未确认的按 at-least-once 重发。
  检查点携带 `pendingEffects`（已触发未确认），压缩后恢复仍会重新驱动。
- **逆补丁反向步进**：每条 `op` 记录携带写入时计算的 `inverse` 补丁，
  `stepBack()` 精确撤销（含事务提交/中止的反向恢复）；`cancel()` 丢弃未提交事务。
- **损坏零容忍**：序号断裂、prev 指针不符、哈希不符一律抛 `LogCorruptionError(seq)`，
  定位到操作序号，绝不跳过损坏记录继续冒充成功。
- **对照基准**：`src/differential.ts` 是与主解释器不共享解释逻辑的独立全日志解释器，
  所有恢复路径（全量 / 检查点增量 / 压缩段 / 逐步 / 回退）在测试中逐点与其对照。

## 需求映射

| 需求 | 实现 |
| --- | --- |
| checkpoint 绑定前缀摘要 | `Checkpoint.prefixHash`，`recover()`/`compact()` 校验 |
| 逐步、回退、取消 | `Interpreter.step() / stepBack() / cancel()` |
| 日志损坏定位到操作序号 | `LogCorruptionError.seq`（`verifyChain`/`assertChain`/`step`） |
| 分支、事务提交、副作用确认 | `branch` / `tx.*` / `effect` 记录类型 |
| 只应用完整提交 | 暂存区提交时才落库；崩溃遗留的打开事务不生效 |
| 不重新触发已确认外部动作 | 确认集预取 + `pendingEffects` 跨检查点传递 |
| 反向步进逆补丁 | `op.inverse`，`applyInverse` |
| 检查点回收 | `compact()`（哨兵锚点）+ `reclaimCheckpoints()` |
| 损坏中间记录不可跳过 | 严格校验即抛错，无 skip 路径 |
| 逐故障点恢复 vs 独立全日志解释器 | `test/fuzz.test.ts`、`test/chain.test.ts` 逐点对照 |
| 前缀摘要不符拒绝拼接 | `spliceBranch()` 抛 `SpliceError` |
| 不用响应式框架 | 零依赖，仅 `node:crypto`/`node:test` |
| 状态操作可回放 | `kv.set` / `kv.add` 确定性操作 |
| 读者不能看到事务中间态 | `getState()` 仅返回已提交状态 |
| 重复操作 ID 不重放两次 | `appliedOpIds` 去重（写入端拒绝 + 回放端跳过） |
| 缺中间操作不能跳过 | seq 连续性校验，缺口即损坏 |
| 恢复后最终摘要等于原状态 | `stateSummary()` 三方比对（原状态/恢复/独立解释器） |

## 运行

```bash
nvm use 22.14.0   # 或任何 >= 22.6 的 Node
npm test          # node --experimental-strip-types --test test/*.test.ts
npm run demo      # node --experimental-strip-types demo/run.ts
```

## 目录

- `src/types.ts` — 记录/操作/补丁/检查点类型与错误类型
- `src/hash.ts` — 规范化序列化、记录/检查点/状态摘要
- `src/ops.ts` — 状态操作应用与逆补丁
- `src/log.ts` — 写入器、链校验、分叉与拼接、压缩哨兵
- `src/interpreter.ts` — 解释器（逐步/回退/取消/副作用去重）
- `src/checkpoint.ts` — 检查点创建/校验/恢复/压缩/回收
- `src/differential.ts` — 独立全日志解释器（对照基准）
- `test/` — 6 个测试文件，32 个用例（含差分模糊测试）
- `demo/run.ts` — 端到端演示

## 运行样例（`npm run demo`）

```
=== 1. 原始执行（写日志，外部动作恰好执行一次） ===
  写入 op-1..op-2（开户）
  事务 tx-1 暂存中，读者看到的 balance:ada = 100（中间态不可见）
  tx-1 提交后，读者看到的 balance:ada = 70
  [外部系统] 执行动作 eff-email-1
  eff-email-1 已确认（回执入日志）
  tx-2 已取消（abort），其写入永不落库
  [外部系统] 执行动作 eff-points-1
  *** 崩溃！eff-points-1 的确认尚未写入日志 ***
  原始状态摘要: c2a247cbd1632a91…  (日志 12 条)
=== 2. 崩溃恢复（独立全日志解释器对照） ===
  [恢复] 重新触发未确认的外部动作 eff-points-1
  恢复摘要 == 原始摘要: true
  恢复摘要 == 独立解释器: true
  重发的外部动作: ["eff-points-1"]（eff-email-1 已确认，不重发）
=== 3. 逐步、反向步进（逆补丁）、取消 ===
  前进 5 步（tx-1 未提交）: balance:ada=100（中间态不可见）
  前进第 6 步（tx-1 提交）: balance:ada=70
  回退 1 步（逆补丁撤销 tx-1 提交）: balance:ada=100
  再回退 2 步（撤销暂存的转账操作）: balance:ada=100
  重新前进到底: 摘要一致=true
  打开的事务可以取消: cancel()=true，状态不受影响 balance:ada=100
=== 4. 分支与拼接（前缀摘要校验） ===
  拼接成功: 4 条，链校验 ok=true
  伪造基点摘要 → 拼接被拒绝: 前缀摘要不符：分支声明 baseHash=aaaaaaaaaaaa…，主干实际=6057852c6cfb…
=== 5. 检查点、日志压缩与回收 ===
  检查点 cp@6 绑定前缀摘要 d6c7401c0dd5162b…
  压缩回收前 6 条历史，保留尾部 6 条（首条 prev 链接到检查点摘要）
  从压缩段恢复: 使用检查点=cp@6，摘要一致=true
  增量恢复重发的动作: ["eff-points-1"]（已确认的不重发）
=== 6. 日志损坏定位到操作序号（不可跳过冒充成功） ===
  日志损坏 @ 操作序号 seq=4: 记录哈希与内容不符（疑似篡改）
  日志损坏 @ 操作序号 seq=5: 序号断裂：期望 5，实际 6（缺中间操作不可跳过）
=== 完成 ===
  最终校验: 恢复后最终摘要等于原状态 → true
```
