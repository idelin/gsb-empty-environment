# Mealy 转移覆盖测试规划器

确定性 Mealy 机的自适应转移覆盖测试规划。仅使用 Python 3.11 标准库，
不依赖任何自动机库或规划库。

被测设备是黑盒：只能看到每次输入后的输出标签，看不到内部状态；reset
只在部分状态可用且计入成本。模型（状态、输入、输出、初始候选集合、可
reset 状态、正整数操作成本）由 JSON 给出，格式见 `mealy.py` 的模块文档
字符串及 `samples/` 下的四个样例。

## 语义

- **信念节点**：由于机器确定、策略是观测历史的函数，每个初始候选状态
  沿每个输出分支恰好诱导一条实际轨迹。节点因此是若干 *world* 的集合，
  `world = (当前状态, 该轨迹已执行的转移集合)`。
- **安全动作**：输入必须对所有候选状态有定义；reset 必须对所有候选
  状态合法（其成本计入计划）。
- **确定覆盖**：一次转移只有在该分支中**所有**可能实际轨迹都执行过它
  时才记作确定覆盖，即各 world 覆盖集合的**交集**。不同隐藏状态分别
  可能覆盖的边绝不合并成"已覆盖"（见反例 CE-1）。
- **目标**：每个输出分支终止时，交集覆盖全部"从初始候选可达的转移"
  （经转移边与 reset 边可达的源状态所发出的已定义转移）。
- **目标函数**：最小化最坏分支总成本（AND 分支取 max，OR 选择取 min）。

## 算法（`planner.py`）

精确 AND/OR 搜索：

- OR 节点：枚举所有安全动作；AND 节点：按该动作在此信念下可能产生的
  每个输出分裂子节点。
- 节点成本 = 动作成本 + 各输出分支子成本的最大值；取所有动作的最小值。
- **预算**：`--budget N` 限制扩展节点数。预算耗尽返回 `unknown` 与有效
  下界（可采纳启发式经 min/max 传播）和已找到的最优完整策略成本上界；
  绝不把"没找到"当成"无解"。启发式：每个 world 尚未覆盖的转移数 ×
  最小输入成本，取各 world 最大值（每条轨迹对每个缺失转移至少还需
  一次输入，故可采纳）。
- **无解解释**：(1) 预检查——若某可达转移的源状态从某初始候选出发
  （即使用 reset）不可达，则该轨迹永远无法执行它，直接判无解并指出
  阻塞的候选状态与转移；(2) 搜索中的死端——列出候选集合、每个输入在
  哪些状态无定义、reset 被哪些候选阻塞（不可安全区分/不可安全动作
  情况）；(3) 无进展循环——信念以相同覆盖重现，说明无法回到未覆盖边
  的状态（如不可逆汇点）。

## 状态空间削减

- **R1 world 合并**：当前状态与覆盖集合都相同的轨迹合并为同一 world。
- **R2 目标转移集收缩**：只要求覆盖从初始候选可达的转移，不可达转移
  不进入目标集。
- **R3 精确记忆化**：已求出精确最优成本的节点直接复用（AND/OR 图
  而非树搜索）。
- **R4 无进展环剪枝**：节点包含完整覆盖信息，沿分支重复出现同一节点
  意味着零进展；任何含此循环的策略都可严格缩短，故剪枝保持完备性与
  最优性，同时保证每个策略都是有限树。
- **R5 自环动作跳过**：唯一效果是把节点变成自身的动作直接跳过。
- **R6 可采纳下界**：预算截断时用于传播有效上下界（见上）。

## 终止性论证

发出的策略是**有限 JSON 树**（结构上不存在节点引用/循环）：由 R4，
沿任何分支节点互不重复，而节点空间有限，故每条根到叶路径有限，验证器
`verifier.py` 按结构遍历必然终止。验证器绝不假设"无限循环最终会覆盖"：
凡不到达 goal 叶的执行都直接报错。

## 独立验证器（`verifier.py`）

与规划器不共享搜索代码。枚举每个实际初始状态沿策略产生的轨迹，检查：
动作在实际状态合法（输入有定义 / reset 被允许）、每个产生的输出都有
对应分支、按模型成本表累计成本；按 goal 叶分组后对轨迹覆盖取**交集**
检验确定覆盖；重算最坏成本并与策略声明值比对。策略树中不可达的部分
无法被检验，只给警告。

## 穷举交叉核验（`bruteforce.py`）

独立重实现的小深度穷举：对深度 ≤ D 的**所有**策略树求最优值
（按 (节点, 剩余深度) 记忆化）。测试断言：穷举值 == 规划器最优值，
且深度减一时穷举值不小于最优值。

## 样例（`samples/`）

| 样例 | 说明 | 结果 |
|---|---|---|
| `same_output_different_edges` | 同一输出 0 掩盖不同内部边 (s0,a)/(s1,a) | 最优成本 7 |
| `partial_reset` | s1 不可 reset，必须绕行 s2 才能 reset | 最优成本 9 |
| `sink_lost_coverage` | 进入不可逆汇点后丢失 (s0,a)/(s0,b) 之一的覆盖机会 | 无解（附解释） |
| `identify_then_act` | y 在 p1 无定义、z 在 p0 无定义，必须先用 x 探测再按输出分支选动作 | 最优成本 4 |

## 反例（测试中被验证器拒绝）

- **CE-1 并集覆盖作弊**：`same_output_different_edges` 上执行 b,a,b
  后各轨迹覆盖的并集含 3 条边，看似接近完成，但确定覆盖（交集）只有
  `{(s1,a),(s1,b)}`，缺少 `(s0,a)`、`(s0,b)` —— 验证器拒绝。
- **CE-2 非法 reset**：`partial_reset` 初始信念含 s1，此时 reset 对
  实际状态 s1 非法 —— 验证器拒绝。
- **CE-3 不安全输入**：`identify_then_act` 初始信念上直接用 y，而 y
  在 p1 无定义 —— 验证器拒绝。
- **CE-4 缺失输出分支**：策略只处理探测 x 的输出 0，来自 p1 的轨迹
  产生输出 1 后无分支可走 —— 验证器拒绝。
- **CE-5 虚报成本**：把合法策略的声明成本改小 1 —— 验证器拒绝。
- **CE-6 预算耗尽 ≠ 无解**：`--budget 3` 时返回 `unknown`、下界 4
  （≤ 最优 7），明确标注这不是无解证明。

## 运行

```sh
python3.11 planner.py samples/same_output_different_edges.json --policy-out policy.json
python3.11 verifier.py samples/same_output_different_edges.json policy.json
python3.11 bruteforce.py samples/partial_reset.json --depth 10
python3.11 run_tests.py
```

## 实际测试结果

`python3.11 run_tests.py`：21 个测试全部通过（最优值、穷举交叉核验、
验证器接受/拒绝、无解解释、预算上下界、自适应策略形状、不合并隐藏边
的内部语义检查）。三个可解样例的规划器最优值（7、9、4）与独立穷举
搜索完全一致；各策略均通过独立验证器，重算成本与声明一致。
