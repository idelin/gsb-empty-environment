# BGP黑洞社区准入

运营商允许客户用黑洞社区把遭受攻击的地址丢弃，攻击者通过自己的会话把别人的 /32 带上黑洞社区发出去，让对方的服务从全网消失。为Go路由策略组件写可导入的黑洞通告准入包，输入客户会话的授权前缀集合（含各自的最大前缀长度）、通告（前缀、社区列表、AS 路径、下一跳）、黑洞社区值和黑洞下一跳：带黑洞社区的前缀必须是授权前缀的子前缀，且长度恰为 32（IPv6 为 128），授权项里的最大前缀长度字段不影响这一要求；AS 路径首个 ASN 必须是客户 ASN；准入后只保留黑洞社区与 no-export 两个社区，其余社区全部去掉，并把下一跳改写为黑洞下一跳；不带黑洞社区的前缀按授权项的最大前缀长度检查；同一通告既带黑洞社区又带客户设置的传播范围社区时，只保留 no-export。用越权 /32、非 /32 的黑洞前缀、AS 路径首跳错误、社区组合和普通前缀验证。
