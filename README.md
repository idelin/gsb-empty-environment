图像安全网关在将用户上传的 WebP（RIFF 容器，含 `VP8 `/`VP8L`/`VP8X`/`ALPH`/`ANIM`/`ANMF`）送入底层解码库前，若未做原始字节级容器与帧头审计，攻击者可构造畸形 RIFF 块长度整数溢出、遗漏奇数长度块后的 1 字节零填充造成后续块解析错位（Chunk Smuggling）、在 `VP8X` 扩展画布与实际 `VP8`/`VP8L`/`ANMF` 帧尺寸之间制造矛盾或越界偏移触发堆溢出（类 CVE-2023-4863 前置畸形样本），或在容器末尾夹带未声明载荷。为 C++17 媒体安全宿主实现可嵌入、零外部依赖、`-Wall -Wextra -Wconversion -Werror` 编译通过的原始字节级 WebP/RIFF 安全审计库。库从偏移 0 起严格校验：（1）RIFF 12 字节头：魔数 `RIFF` + 32 位小端 `fileSize`（精确校验 `fileSize + 8 == input.size()`，无 32 位回绕且禁止尾随隐藏数据）+ `WEBP` 标识；（2）逐块顺序解析：校验每个 8 字节块头（FourCC + `chunkSize`）无溢出越界；奇数 `chunkSize` 后必须存在 1 字节 `0x00` 填充（硬拒绝非零填充藏毒或缺失填充）；区分简单格式（仅单个 `VP8 ` 或 `VP8L`）与扩展格式（首块必为 10 字节 `VP8X`，标志位与实际出现子块 `ICCP`/`ALPH`/`EXIF`/`XMP `/`ANIM` 严格一致，拒绝重复冲突帧块）；（3）解析 `VP8 ` 帧头（3 字节帧标签 + `0x9d 0x01 0x2a` 起始码 + 14 位宽高）、`VP8L` 头（`0x2f` 签名 + 位打包 14 位宽高）及 `ANMF` 帧偏移/尺寸，校验画布与每帧 `x + width <= canvasWidth`、`y + height <= canvasHeight` 且像素总数不超宿主配额。附合法简单/动图 WebP 样本与非零奇偶填充、RIFF 长度回绕、`VP8X` 标志与子块矛盾及 `ANMF` 越界画布测试。
