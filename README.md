分布式任务执行引擎（Ray 架构）去中心化地把每个不可变对象的生命周期交给创建它的 **Owner Worker** 管理，通过分布式引用计数、借用引用（Borrowed Reference）跨节点传递与基于所有权的血缘重建（Lineage Reconstruction）同时避免中心瓶颈与悬空回收，四处分布式边界极易出错：1）**Owner 集中计数与跨 Worker 借用引用（Borrowing）协议**：当 Owner `W0` 创建对象 `X` 并把 `X` 的引用作为参数传给远端任务 `W1`，`W1` 在执行中又把 `X` 嵌套封装进新对象 `Y`（或传给 `W2`）时，`W1` 属于 **Borrower**——`W1` 返回前绝不可直接让 `W0` 把 `X` 的引用计数清零，必须在任务完成回执中把“仍在持有 `X` 的新借用者 `W2`（或包含 `X` 的容器对象 `Y`！）”列表回传给 `W0`；`W0` 必须等新借用者确认登记后再扣减 `W1` 的提交计数，彻底消除先减后加竞态导致的悬空对象提前回收！2）**嵌套对象引用链（ObjectRef-in-ObjectRef）保活**：当对象 `Y` 的载荷里序列化了 `X` 的 `ObjectRef` 时，`X` 必须与 `Y` 的生命周期绑定（只要 `Y` 仍存活，`X` 的计数不可归零；`Y` 彻底销毁后级联通知 `X` 的 Owner 释放！）；3）**节点宕机与血缘重建（Lineage Reconstruction）**：每个对象在 Owner 处保存可重算血缘（产生它的 Task 规格与输入 `ObjectRef` 列表）及血缘预算上限；当仅存放 `X` 副本的 Plasma 节点宕机导致所有副本丢失但 **Owner `W0` 仍存活** 时，自动递归触发上游血缘任务重算并重新定位新副本（若中间依赖也丢失则级联递归重建，且受 `maxTaskRetries` 限制！）；一旦 **Owner `W0` 自身宕机**，直接向所有等待该对象的下游返回 `OwnerDiedError`，不做无主重建；4）**内存反压与本地磁盘溢出（Object Spilling）**：节点对象存储满时，优先淘汰引用计数归零的死对象，若仍不足则仅将无正在读取 Pin 锁的存活对象溢出到外部存储并保留元数据，并在所有引用归零后连同溢出文件一并清理。为分布式计算运行时交付可导入的 TypeScript 所有权引用计数、嵌套借用传递与血缘重建引擎。验收覆盖 `W0 -> W1 -> W2` 借用传递无悬空竞态、嵌套 `ObjectRef` 级联保活与释放、数据节点宕机递归血缘重建 vs Owner 宕机报 `OwnerDiedError` 以及溢出/Pin 锁保护与零泄漏回收。
