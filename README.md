# snapcatchup

快照追赶模拟器：leader 向落后副本分块传输快照，传输期间日志继续追加；
副本只有在全部块完整且一致时才原子替换状态，随后只重放快照索引之后的日志。

## 设计

- **快照代次（generation）**：`Leader.TakeSnapshot` 每次递增代次并压缩日志。
  副本收到更高代次的块时丢弃旧的部分传输；低于等于已安装代次的块一律视为过期忽略。
- **块校验**：每个 `Chunk` 携带其负载的 CRC32；`SnapshotMeta.Checksum` 是整个快照
  负载的 CRC32。单块校验失败即拒绝且不落盘；全部块收齐后还要通过整体校验才允许安装。
- **安装边界**：安装前先写 `installing` 标记（begin），状态解码、快照数据与
  `installed` 元数据落盘后才删除标记并清理暂存区（commit）。崩溃恢复时：
  标记存在且暂存块完整一致 → 前滚完成安装；否则丢弃标记与部分暂存，重新传输。
- **重放边界**：`Follower.Replay` 跳过 `Index <= LastIndex` 的条目，只应用快照
  索引之后的日志。

## 文件

- `leader.go` — 日志追加、快照生成与压缩、分块服务
- `follower.go` — 收块、校验、安装边界、恢复、日志重放
- `store.go` — 持久化暂存区（内存 / 文件两种实现）
- `snapshot.go` / `statemachine.go` — 元数据、块与状态机定义
