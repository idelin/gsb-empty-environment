容器镜像构建器与固件解包服务在处理不可信 TAR 归档（POSIX ustar / GNU / PAX 扩展头）时，若仅用高层库顺序解压而未校验底层 512 字节头块一致性，攻击者可利用 PAX `path`/`linkpath` 扩展头与 ustar `name`/`prefix` 的多义性冲突、GNU 长名（`L`/`K`）与 PAX 混用、先建符号链接再借其写入目标目录外文件、硬链接指向受限文件、同名重复条目覆盖审计通过的脚本，或塞入 `TypeChar`/`TypeBlock`/`SUID` 条目实现提权与任意文件写。为 Go 制品安全宿主实现可导入的原始字节级 TAR/PAX 安全准入审计包，严禁依赖 `archive/tar` 替代底层 512 字节块头校验，严禁联网。组件直接逐块解析 512 字节头与载荷：（1）校验标准无符号/有符号八进制头校验和（硬拒绝畸形八进制、负大小、整数溢出与非零填充藏毒）及末尾双零块 EOF 规范（拦截 EOF 后尾随隐藏数据）；（2）精确解析 PAX 全局头（`g`）、局部头（`x`）及 GNU 长名（`L`/`K`），校验 PAX 记录长度前缀与换行格式，硬拒绝重复冲突的 `path`/`linkpath`/`size` 覆写及未消费的孤立扩展头；（3）维护规范化虚拟目录树执行完整路径安全审计：硬拒绝绝对路径、`..` 穿越、反斜杠混淆、重名覆盖（含大小写折叠冲突）、指向目录树外部或穿透符号链接的硬链接/符号链接、以及任何字符/块设备（`3`/`4`）、FIFO（`6`）与 `SUID`/`SGID` 权限位；同时按实际解压字节上限防止稀疏文件/超大文件炸弹。附 PAX/ustar 冲突、先符号链接后写逃逸、重名覆盖、EOF 尾随藏毒与设备节点拦截测试。
