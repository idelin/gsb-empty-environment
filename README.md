# configreduce — 保持依赖合法的失败配置缩减工具

给定一个确定性判定程序，对失败配置做自动缩减，输出一个 **1-极小** 的失败集合：
再删除其中任何单项（含被迫级联删除的依赖者）都不再复现目标测试失败。

## 特性

- **依赖合法**：配置项之间可声明依赖（`item: dep1 dep2`）。缩减过程中所有送判的
  候选配置都经过“删除闭包”修复——删除某项时，其全部传递依赖者一并删除，
  保证每个候选配置始终满足依赖约束。
- **1-极小输出**：先按 ddmin 递增粒度整块删除，再做单项删除收尾，
  直到任何单项删除都不再失败。
- **判定缓存**：缓存以规范化配置（去重 + 排序）为键，相同集合无论顺序如何
  只真实判定一次；统计中区分实际判定次数与缓存命中次数。
- **区分失败类型**：判定结果分为“通过 / 目标测试失败 / 编译失败”，
  只有目标测试失败被视为要保留的失败，编译失败单独统计。
- **确定性**：所有迭代均按排序后的顺序进行，相同输入产生相同结果与判定次数。

## 用法

```
go build -o configreduce .
./configreduce -oracle "<判定命令>" [-deps <依赖文件>] <配置项...>
```

判定程序契约：配置项作为命令行参数追加给判定命令，退出码含义：

| 退出码 | 含义         |
| ------ | ------------ |
| 0      | 通过         |
| 1      | 目标测试失败 |
| 2      | 编译失败     |
| 其他   | 执行错误     |

依赖文件每行格式：`配置项: 依赖1 依赖2 ...`（`#` 开头为注释）。

## 输出示例

```
=== 缩减结果 ===
最终配置（3 项）: common.h main.c util.c
实际判定次数: 10（缓存命中: 6）
判定分布: 通过=6, 目标测试失败=3, 编译失败=1
1-极小性: 已保证（任何单项删除均不再复现目标测试失败）
```
