# TOML表劫持

应用把用户上传的 TOML 片段合并进主配置，攻击者在片段里用点号键、带引号的键与重复表头去改写 [security] 表。为Go的配置服务写可导入的 TOML 片段准入包（TOML 1.0.0）：片段内每个键的完整路径先按 TOML 键语法解析（裸键、带引号键、点号键，允许空白，引号键里的 \u 转义先还原再比较），再要求第一段必须是 user，例如 `user.a = 1` 通过，`"\u0073ecurity".x = 1` 拒绝；表头与点号键对同一张表重复定义、内联表后续追加、`[a]` 与 `[[a]]` 混用均拒绝；片段超过 64 KiB 拒绝。测引号与转义变体、重复表头、内联表追加、空白变体。

## 使用

```go
import "example.org/netsec/q0499"

if err := netsec.ValidateFragment(uploaded); err != nil {
    // 拒绝该片段
}
```

也可使用 `ValidateFragmentString`、`ValidateFragmentReader` 或别名 `Validate`。`MaxFragmentSize`（即 65536 字节）是允许的最大片段大小。

准入规则：

- 所有顶层键/表头路径的第一段在解码后必须严格等于 `user`。
- 裸键、基本引号键、字面量引号键、点号键和分隔符周围空白均按 TOML 1.0.0 解析。
- 基本引号键中的 `\uXXXX`/`\UXXXXXXXX` 先解码再比较；字面量引号键不处理转义。
- 同一路径的表头、点号键表定义、普通键重复定义均拒绝。
- 内联表封闭，任何后续点号键或表头都不能向其追加内容。
- `[path]` 与 `[[path]]` 不能对同一路径混用；`[[path]]` 本身可重复。
- 片段大小按字节计，超过 65536 字节直接拒绝。
