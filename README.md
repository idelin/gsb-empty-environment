PostgreSQL 的可写公用表表达式（Data-Modifying CTE，例如 `WITH moved AS (DELETE FROM a WHERE ... RETURNING *), bumped AS (UPDATE a SET ... RETURNING *) INSERT INTO b SELECT ...`）拥有两项令传统语句执行器极易出错的核心语义：1）**统一初始快照与零 Halloween 效应**——无论语句中包含多少个串联或并列的 `INSERT`/`UPDATE`/`DELETE` CTE 以及顶层主查询，所有语句部分都只看见该整条 SQL 开始执行之前的**同一张初始表快照**（绝不可看见同一语句内其他 CTE 刚刚 `INSERT` 或 `UPDATE` 写入的新行，也绝不可用自身刚 `UPDATE` 的结果再次被自身扫描命中！各 CTE 之间唯一的数据传递通道是各自物化的 `RETURNING` 结果集！）；2）**强制完整执行与跨 CTE 同物理行冲突仲裁**——即使主查询的 `SELECT` 或 `LIMIT 0` 没有读取某个数据修改 CTE 的 `RETURNING` 输出，规范仍要求该 CTE 必须完整执行到结束（绝不可被惰性求值跳过！）；而当语句中两个不同的写子句（如 `CTE1` 与 `CTE2`，或 `CTE1` 与主查询）先后试图修改或删除**同一条初始物理行 `rowID`** 时，引擎必须按确定性语句内并发语义精准检测并处理（识别已被同语句另一子句 `DELETE` 或 `UPDATE` 过的 `rowID`：支持严格模式抛出 `CONCURRENT_SELF_MODIFY` 或按 PostgreSQL 语义在第二子句跳过对已删/已改行的重复覆写并记录精确审计差异，绝不可基于过时初始快照二次覆写导致第一子句的修改丢失或已删行复活！）。为关系数据库执行引擎交付可导入的 Go 可写 CTE 规划与执行包。支持任意依赖拓扑（DAG，检测循环引用报错）的多重 `INSERT`/`UPDATE`/`DELETE` CTE（含 `RETURNING`）与主查询、语句级原子回滚（任一子句违背主键/唯一/CHECK 约束时整条语句零变更回滚！）以及基于行版本号的初始快照表存储。验收覆盖多 CTE 同快照隔离防看见彼此写入、自更新防 Halloween 效应、未引用 CTE 仍完整执行副作用、跨 CTE 命中同一物理行不丢失修改不复活已删行以及约束失败整语句原子回滚。
