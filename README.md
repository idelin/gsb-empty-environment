对象存储网关在验证兼容 AWS Signature Version 4（SigV4）的头部签名与 Query 预签名 URL 请求时，若未严格按规范执行路径双重 URI 编码规范化、未对同名多值 HTTP 头按规范修剪合并导致代理与后端解析不一致（头走私）、未强制校验 `host` 与 `x-amz-date` 必须列于 `SignedHeaders`、接受超过 7 天（604800 秒）的 `X-Amz-Expires` 或允许未授权请求使用 `UNSIGNED-PAYLOAD` 跳过请求体完整性校验，攻击者可篡改未签名头、延长预签名有效期或替换请求体实现越权读写。为 Go 认证网关宿主实现可导入的 SigV4（Header 与 Presigned URL 双模式）完整规范化与验签防绕过包，严禁联网（仅用标准库 `crypto/hmac`/`crypto/sha256`）。组件严格实现：（1）按 AWS SigV4 规范构建 `CanonicalRequest`（严格区分 S3 单次编码与非 S3 双重 URI 编码、规范排序查询参数并保留空值 `=`、全部头名小写排序且连续空白折叠为单空格、同名多值头逗号拼接）；（2）严格安全门禁：硬拒绝重复/冲突的 `Authorization` 或 `X-Amz-Signature`、要求 `SignedHeaders` 必须包含 `host`（头部模式还须包含 `x-amz-date` 及存在时的 `x-amz-content-sha256`/`x-amz-security-token`）、校验请求时间窗（头部模式 `±15` 分钟，预签名模式 `1 <= X-Amz-Expires <= 604800` 且未过期）；策略禁止非 TLS/高敏写操作使用 `UNSIGNED-PAYLOAD`，否则强制重算实际请求体 SHA-256 与 `x-amz-content-sha256` 恒定时间比对；（3）精确实现 4 级派生密钥链（`kDate → kRegion → kService → kSigning`）与 `HMAC-SHA256` 恒定时间验签，并校验 `Credential` 中的 `region`/`service` 精确匹配本地端点防跨区跨服务重放。附规范化测试向量、遗漏 `host` 签名拦截、`X-Amz-Expires` 超窗、多值头走私与 `UNSIGNED-PAYLOAD` 拦截测试。
