漏洞聚合依赖供应商的 VEX 声明抑制误报，攻击者可伪造 not_affected 压掉真实漏洞。为Go门禁实现供漏洞聚合调用的 VEX 采信包：CycloneDX 的 analysis.state 取 exploitable、in_triage、false_positive、not_affected、resolved；not_affected 须带 justification（如 code_not_present、code_not_reachable、requires_configuration、protected_by_mitigating_control），缺失或未知枚举按未采信；声明的 affects 须同时匹配 bom-ref 与 purl 精确版本范围（含语义化版本区间、预发布标签及通配符边界，拒绝未受限任意版本），签发者须在该组件供应商的受信集合内且由宿主注入验签通过，且声明时间不早于组件版本发布且不超过声明自身过期时间；同一组件存在多份冲突 VEX 声明时，exploitable/in_triage 优先于 not_affected，不得因后续签发者的 not_affected 覆盖高危状态；被采信的 not_affected 才压制告警，其余保持原告警。用缺 justification、冲突声明覆盖、签发者不符、预发布版本越界、旧声明和合法抑制验证。
