# 全局读视图对齐器（Global Read-View Aligner）

分库分表集群的全局快照读取器。各分片产生独立的本地提交时间戳，对齐器协调各分片的
CDC 流，找到全局因果闭合的安全时间戳 `T_Safe`，确保跨分片读取看到完全自洽的数据集。

## 核心语义

- **水位线基线**：`base = min(各分片 heartbeat 水位线)`；任一分片未心跳则无法保证事件完整性，阻塞。
- **因果闭合**：跨分片事务（如转账）由 `txnId` 关联并声明 `expectedParts`。
  只要事务未收齐全部参与者事件，对齐器拒绝生成查询视图——杜绝“只有转出、没有转入”的半事务快照。
- **T_Safe**：`min(各分片水位线, 未闭合事务首事件 commitTs - 1)`；快照内绝不允许出现半事务（防御性不变量兜底）。

## 运行

```bash
npm test    # Node.js 内置测试（node --test，原生 TypeScript type-stripping）
npm run demo  # 跨分片转账演示
```

要求 Node.js >= 23.6（原生运行 `.ts`，无需编译）。

## 运行样例输出

```
--- 跨分片转账：A(分库1) 向 B(分库2) 转账 30 ---

[转出已提交/转入未就绪] ❌ 阻塞：事务未因果闭合：txn-1（已收到部分事件，等待其余分片事件就绪） | pending=[txn-1]
[转入转出全部就绪] ✅ 快照就绪 T_Safe=10 balances={"A":70,"B":80} 总资金=150
```

## 测试结果

```
ℹ tests 6
ℹ pass 6
ℹ fail 0
```

覆盖场景：
1. 只有转出事件时绝对阻塞（钱不得凭空消失）
2. 转入转出全部就绪后输出一致性快照，资金守恒（150 → 150）
3. 分片未上报水位线时阻塞
4. `T_Safe` 必小于未闭合事务首事件时间戳
5. 多笔并发双向转账全部闭合后快照自洽
6. 事件乱序到达（转入先于转出）同样保证闭合语义

## 结构

- `src/types.ts` — CDC 事件 / 心跳 / 读视图类型
- `src/aligner.ts` — 对齐器核心（水位线 + 因果闭合 + 快照物化）
- `src/shard.ts` — 分片模拟器（独立本地提交时间戳）
- `test/aligner.test.ts` — Node.js 内置测试
- `examples/transfer-demo.ts` — 跨分片转账运行样例
