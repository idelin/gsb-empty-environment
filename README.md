# 密钥隔离域最优分配

签名集群需要把一批请求分配给多个硬件隔离域，同一敏感租户的两个审批角色不得落在同一域。写供Go调度宿主调用的规划包，输入至多二十请求、至多六个候选域的密钥用途与容量、请求兼容关系及隔离约束；精确最小化启用域数再最小化总延迟成本，不可行时返回可复核冲突集合。执行器按计划原子预留所有容量，失败不部分占用。用小实例穷举核对共享密钥与角色冲突。

## 包结构

模块路径为 `example.org/netsec/q0116`，包名 `netsec`。

- `types.go`：`Request`、`Domain`、`Input`、`Plan`、`ConflictSet` 等输入输出类型。
- `planner.go`：入口 `Solve(in Input) (*Plan, *ConflictSet, error)` 与输入校验。
- `solver.go`：约束建模（密钥用途、容量、审批角色与显式隔离）、成本表与域子集枚举。
- `bb.go`：分支定界搜索，动态 MRV 选请求、增量容量/冲突检查、成本下界剪枝。
- `conflict.go`：不可行时提取包含意义下的最小不可行请求子集，并附成对冲突与容量原因。
- `executor.go`、`memstore.go`：原子预留执行器与一个并发安全的内存容量存储实现。

## 优化语义

`Solve` 按固定顺序优化两个目标：

1. 先最小化启用域数：按启用域数从小到大枚举域子集，第一个可行基数即最优。
2. 同一基数下最小化总延迟成本：每个子集用分支定界求精确最小成本。

隔离约束有两个来源：

- 自动派生：同一租户的任意两个带审批角色的敏感请求必须落在不同域（保守解释，角色不同也隔离）。
- 显式声明：`Input.MustSeparate` 中的请求对强制分域。

密钥用途与容量按 `Domain.Purposes[purpose]` 建模；域只有在某用途上提供正容量时才能服务该用途的请求，且同域同用途的请求共享容量池。

## 不可行复核

不可行时返回 `ErrInfeasible` 与非空 `ConflictSet`：

- `RequestSubset` 是包含意义下最小的不可行子集，删除其中任一请求后剩余问题可行。
- `PairConflicts` 列出子集内全部隔离对及其来源（`approval_role` 或 `explicit`）。
- `Reasons` 给出用途不支持、用途总容量不足、单请求容量超过任一单域等可复核事实。

## 原子预留

`Executor.Execute` 按 `(域, 用途)` 聚合计划需求，逐笔调用宿主实现的 `Reserver`。任一笔失败即按逆序 `Release` 已成功的预留，保证失败时不留下任何部分占用。

## 测试

- `exhaustive_test.go`：对 400 个随机小实例独立枚举全部 `域^请求` 分配，逐项核对启用域数、成本与最小冲突子集。
- `planner_test.go`：共享密钥容量、角色隔离、显式隔离、双目标排序等确定性用例。
- `executor_test.go`：全量预留、失败回滚、计划校验与超额订阅拒绝。
- `stress_test.go`：20 请求 × 6 域上限下的性能与不可行冲突规模。
