删除机密卷时，磁盘数据保留但所有可解密密钥副本必须失效。写供Go卷宿主调用的销毁协调包：密钥副本有持久位置、副本代次与活跃租约，先原子封禁新租约并等待或强制撤销在途租约，再收集各副本带签名的擦除确认；任一未知副本、代次不匹配或仅部分擦除均使结果为未完成而不得标记已销毁。崩溃后沿销毁事务继续且保持幂等，不能恢复可用状态或因卷名重用而把新卷的租约或确认混入旧销毁事务。用故障存储测试并发租约撤销、迟到确认、部分写失败恢复与卷名重用。

## `destruct` 包

代码位于 `destruct/`，模块路径 `prescreen.local/ps-310314f1df/destruct`，仅依赖 Go 标准库。

### 身份与状态机

- 卷使用不可复用的 `VolumeID` 标识，人类可读名称只是标签；同名新卷一定拿到新 `VolumeID`，事务、租约、确认全部按 `VolumeID`/`TxnID` 关联，名称重用无法串入旧事务。
- 销毁事务 `DestroyTxn` 在卷被封禁之前先持久化，状态只能单向前进：`sealing -> erasing -> destroyed`，不存在回到 `usable` 的路径。
- `sealing`：卷以 CAS 原子地 `usable -> destroying`，此后 `GrantLease`/`RenewLease` 一律拒绝；在途活跃租约先按宽限期等待自然到期，再强制撤销，确认无活跃租约后才进入 `erasing`。
- `erasing`：按事务创建时冻结的副本快照逐副本调用 `Eraser.Erase`，对每个 `Confirmation` 校验归属卷/事务、副本身份、持久位置、副本代次与 Ed25519 签名。未知副本、位置/代次不符、签名无效或缺确认都会返回 `IncompleteError`（包装 `ErrDestructionIncomplete`），事务保持打开，绝不标记已销毁。
- 全部快照副本都有有效确认后才把事务与卷 CAS 到 `destroyed`。

### 崩溃恢复与幂等

- 每次状态翻转和每份确认都先落盘再继续；`Recover` 或重复 `Destroy` 从持久化事务的当前阶段续跑。
- 事务采用（CAS 乐观锁 + 冲突后重读采纳）收敛，确认写入是带内容比对的幂等 create，重试不会产生重复确认或重复擦除。
- 已被取代的孤儿事务快照在恢复时跳过，只有卷记录指向的权威事务会被执行。

### 存储与故障注入

- `Store` 接口提供卷、租约、事务、确认的 CAS 持久化原语；`MemDisk` 可在 `MemStore` 重建后存活，模拟进程重启后磁盘仍在。
- `FaultStore` 包装任意 `Store`，按操作名（`CreateTxn`、`CompareSwapVolume`、`PutConfirmation` 等）注入两类故障：`FaultError`（本次写失败、进程存活）与 `FaultCrash`（模拟崩溃，需用同一磁盘重开存储），并支持 `Arm()` 在环境搭建完成后再武装故障脚本。

### 测试

`go test ./...`，竞态检测用 `go test -race ./...`。覆盖：

- 正常销毁与重复调用幂等；
- 并发租约授予/续期与撤销（`-race`）；
- 迟到确认、未知副本、外卷/外事务确认、坏签名、事务关闭后的确认；
- 副本代次不匹配与部分擦除恢复；
- 对全部七类写操作的崩溃切割扫描与瞬时写失败扫描；
- 部分写失败后 `Recover` 沿事务续跑、无重复确认；
- 卷名重用下租约与确认的身份隔离、孤儿事务跳过。
