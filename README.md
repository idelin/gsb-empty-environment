# dircopy

目录复制工具（C++17），保留根目录内部的硬链接关系，符号链接按链接复制，
并对扫描后发生身份变化的源项拒绝复制、保留报告。

## 构建与测试

```sh
make          # 生成 dircopy 与 unit_tests
make test     # 运行单元测试 + 集成测试
```

## 用法

```sh
./dircopy <src-root> <dst-root> [--report <file>]
```

退出码：`0` 成功；`1` 致命错误（如目标已存在）；`2` 有条目被拒绝（详见报告）。

## 设计

两阶段执行（`src/copy_engine.cpp`）：

1. **扫描**：`lstat` 遍历源根（不跟随符号链接），记录每个条目的
   `(设备号, inode)` 身份，并为普通文件建立 `FileId -> 首个根内路径` 集合。
   只有遍历到的根内路径才会进入该集合，因此根目录之外的同 inode 对象
   （例如指向外部文件的硬链接）永远不会被自动纳入复制结果。
2. **复制**：按扫描顺序创建目标。普通文件若其 `(dev, inode)` 已在本次
   复制中成功落地，则用 `link(2)` 在目标内重建共享关系；否则复制内容
   （临时文件 + `rename` 原子落位，失败时清理临时文件）。符号链接用
   `readlink`/`symlink` 单独复制，绝不跟随。

每个条目在复制前都会重新 `lstat` 校验 `(dev, inode, 类型)` 与扫描快照一致；
打开文件后再 `fstat` 复核，关闭 TOCTOU 窗口。身份已变化的条目被拒绝并
记入报告（`--report` 文件与 stderr），其余条目继续复制。

跨设备安全性：硬链接组以 `(dev, inode)` 二元组为键，不同设备上相同的
inode 号不会被混为一谈（见 `tests/unit_tests.cpp` 的键控测试）。

## 测试覆盖（`tests/integration.sh`）

- 根内硬链接组在目标中共享同一 inode（按 inode 身份而非字节比对验证）
- 同内容、不同 inode 的文件在目标中保持独立
- 符号链接（含悬空链接）按原目标字符串重建
- 根外同 inode 对象不被纳入
- 扫描后源身份变化（同路径新 inode）被拒绝并写入报告
- 部分失败：失败项无残留（含临时文件），其余项正常复制，报告保留
- 不支持的类型（fifo 等）被拒绝
- 跨设备复制：检测到可写的第二设备时执行真实跨设备验证，否则跳过
  （键控逻辑由单元测试覆盖）

测试钩子：环境变量 `DIRCOPY_TEST_GATE` 指向一个文件时，工具会在扫描结束、
复制开始前等待该文件出现，供集成测试在两阶段之间篡改源树。
