# tablefixer — 表约束修复器（仅删除行）

给定一组表及其约束，计算**总删除权重最小**的行删除方案，使保留数据同时满足：

- **唯一键**：同一表内同一唯一键（支持复合键）取值至多保留一行；
- **外键**：子行保留 ⇒ 至少一个候选父行保留；删除父行会**级联**删除其子行；
- **行间冲突**：用户指定的冲突集合内至多保留一行。

## 关键设计：全局求解，而非逐约束拼接

三类约束在同一棵分支定界搜索树上联合求解。逐约束分别修复再把局部解拼起来
不是全局最优——例如 `examples/shop.json` 中，唯一键要求 `users#u1`(w=1) 与
`users#u2`(w=5) 删一个：只看唯一键会删权重小的 u1，但 u1 挂着 w=100 的订单
`orders#o1`，级联删除后总代价 101；全局最优是删 u2（级联删掉 w=4 的
`orders#o2`），总代价 9。求解器保证返回全局最优（`Optimal: true`）。

## 算法

- 分支定界：逐行决策"保留/删除"，优先尝试保留以快速获得优质可行解；
- 不动点约束传播：保留一行 ⇒ 删除同唯一键组/冲突集中的其余行；删除父行 ⇒
  级联删除失去全部候选父行的子行；保留子行且仅剩一个候选父行 ⇒ 强制保留该父行；
- 上界剪枝：每个唯一键组/冲突集合的未定成员至多保留一个（每行权重至多被
  扣减一次，保证上界合法）；
- 规模上限 25 行（`-max-rows`），超出报错；另设节点数保险丝，极端情况下
  退回当前最优可行解并在输出中标记 `optimal: false`。

## 用法

```sh
go run . examples/shop.json          # 文本报告
go run . -format json examples/shop.json
cat spec.json | go run .             # 标准输入
go test ./...
```

## 输入格式

```json
{
  "tables": [
    {"name": "users",
     "unique_keys": [["email"], ["tenant", "slug"]],
     "rows": [{"id": "u1", "weight": 1, "fields": {"id": 1, "email": "a@x.com"}}]}
  ],
  "foreign_keys": [
    {"name": "orders_user", "child_table": "orders", "child_field": "user_id",
     "parent_table": "users", "parent_field": "id"}
  ],
  "conflicts": [
    {"name": "same-person", "rows": ["users#u1", "users#u2"]}
  ]
}
```

- 行以 `表名#id` 引用；`weight` 省略时默认为 1，必须非负；
- 外键父字段不唯一时，子行可有多个候选父行，只需至少一个保留；
- 子行外键字段缺失或为 null 按 SQL 语义视为无引用（不施加约束）；
  字段有值但父表无匹配 ⇒ 悬空引用，必删；
- 冲突集合采用团语义：集合内任意两行不得同时保留。

## 输出

1. **删除计划**：每个被删除行及其**原因闭包**——唯一键/冲突直接原因，或
   外键级联原因（递归携带父行的删除原因，直到根因）；
2. **保留表**：按表列出保留行；
3. **保留表核验**：对保留集重新检查全部约束并报告 PASS/FAIL
   （有违规时进程退出码为 1）。
