分布式与联邦查询优化器把过滤、聚合、连接与 `ORDER BY ... LIMIT L OFFSET O` 尽可能下推到各个远程数据分片执行，以大幅削减网络传输；但只要下推边界漏判一项就会输出错误结果：1）**Top-K `LIMIT`/`OFFSET` 修正下推**：查询含 `ORDER BY k LIMIT L OFFSET O` 跨多个分片扫描时，绝不能把 `OFFSET O` 原样下推给每个分片（否则每个分片各自丢弃前 `O` 行会直接漏掉全局前 `O+L` 行！）——必须向每个分片下推 `ORDER BY k LIMIT (L + O)`（无 `OFFSET`），在协调节点执行全局归并排序后再截取 `[O, O+L)`；且若无 `ORDER BY` 仅有 `LIMIT`/`OFFSET`，须按确定性分片顺序收集或安全下推 `L+O` 保证零漏行；2）**分组聚合两阶段下推与 `HAVING` 禁忌**：若 `GROUP BY` 键集完整包含表的分片分布键（Co-located），则单阶段完整聚合与 `HAVING` 可全部下推到分片独立执行；若 `GROUP BY` 未涵盖分片键，则只能拆分为两阶段聚合（分片做局部 `PartialAgg`：`COUNT->SUM`、`AVG->(SUM, COUNT)`、`MIN/MAX->MIN/MAX`，协调节点做 `FinalAgg`），且**绝不可**把 `HAVING` 或非分解式 `COUNT(DISTINCT x)`（当 `x` 非分片键！）提前在分片裁掉或合并！3）**Co-located 分片连接与外连接下推判定**：两表等值连接可完全下推为各分片本地连接，当且仅当两表采用兼容分片函数与完全一致的分片映射表、连接等值键覆盖分片键、且不混入 `VOLATILE` 函数或破坏外连接空值匹配规则（例如跨不同排序规则 `COLLATE` 的字符串等值键不可错误下推！）；4）支持谓词按 `IMMUTABLE`/`STABLE`/`VOLATILE` 安全分级下推（含 `VOLATILE` 如 `random()` 的过滤绝不可下推重复求值或跨连接重排！）。为分布式查询优化层交付可导入的 Go 联邦下推规划与多节点模拟执行验证包。验收在多分布方式（Hash/Range/Replicated）多节点表上，对照“全量拉回单机求值”参考器，验证 `LIMIT+OFFSET` 修正下推、非分片键 `HAVING` 拦截、`AVG`/`COUNT(DISTINCT)` 两阶段拆分、Co-located 连接下推、异 `COLLATE`/`VOLATILE` 禁下推及所有查询结果 100% 逐行一致。
