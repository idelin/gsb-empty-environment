深度学习框架的 GPU 显存缓存分配器（PyTorch CUDACachingAllocator 模式）通过大小池分离、段内块分裂合并避免频繁向驱动申请显存；但在多异步计算流/通信流并发场景中，张量常在流 A 上分配并早早调用 `free`，却仍被流 B 上的异步算子读取——若分配器在流 A `free` 时就把显存块放回空闲池复给后续算子，就会触发极难排查的跨流写后读静默数值损坏！必须通过 `recordStream(ptr, streamB)` 将该块转入延迟释放队列，直到流 B 上记录的同步事件全部完成后才真正回收并允许与同段邻块合并。为训练/推理运行时交付可嵌入的 C++20 头文件与静态库组件，供张量引擎直接调用实现流感知显存块缓存分配器。规则：1）支持 512 字节向上对齐、Small Pool（申请 `<= 1 MiB`，以 `2 MiB` 段向模拟底层显存池切分）与 Large Pool（申请 `> 1 MiB`，以 `20 MiB` 或大块向上对齐段申请），每流维护按块大小有序的空闲集合执行精确 Best-Fit 分裂（保留剩余尾块且严格标记所属 `segment_id`，**绝不跨不同 segment 合并物理相邻块**！）；2）实现 `allocate(size, stream)`、`free(ptr)` 与 `recordStream(ptr, otherStream)`：若 `free(ptr)` 时该块登记了除创建流外的其他流，绝不立即可分配，而是为每个已登记流插入模拟异步事件点挂入隔离队列；仅当外部推进各流事件进度调用 `processEvents()` 确认该块关联的**全部**流事件均已完成，才将其退回原创建流的空闲池并与同段前后空闲块双向合并；3）当模拟显存达到 `memoryLimit` 且当前流空闲块不足时，按固定升级路径自救：先轮询推进已完成跨流事件释放块 -> 尝试释放整段全空闲的 Segment（含从其他流释放空段！）返还底层池再重新申请 -> 若仍不足则精确抛出 OOM 并输出实时已分配字节、已保留字节、跨流隔离字节与碎片率统计。验收覆盖跨流 `recordStream` 防提前复用（事件未完成前绝不重分配、全流完成后自动合并回收）、同段双向合并 vs 跨段禁止合并、紧显存上限触发回收整段空 Segment 自救避免假 OOM，以及全生命周期字节守恒（活跃 + 隔离 + 空闲 == 已保留总段字节）。
