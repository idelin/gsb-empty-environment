# btree — 可崩溃恢复的磁盘 B 树（纯标准库）

单文件、追加写（append-only）、写时复制（COW）的 B+ 树，支持插入、
重复键覆盖、范围扫描、历史快照；节点拆分对崩溃可恢复，父子指针与
叶链在每次提交后保持一致。所有数据都存放在调用方指定的目录下的
`btree.db` 一个文件里。

## 设计

### 逻辑节点 ID + 映射表间接寻址

- 节点用**逻辑 ID** 寻址；`map[nodeID] -> 文件偏移` 的映射表随每次
  提交整体重写并随超级块一起原子发布。
- 父子指针、叶链 `next` 指针存的都是逻辑 ID。COW 改写叶子时
  **ID 不变、偏移变**，前驱叶子的 `next` 指针因此天然保持有效——
  这是叶链一致性的关键（朴素 COW 每次改写叶子都会让叶链失效）。
- 拆分：左节点保留原 ID，右兄弟分配新 ID；`left.next = right`，
  `right.next = 旧 next`，分隔键沿 COW 路径向上插入。
- 内部节点不变式：`keys[i] == children[i+1] 子树的最小键`。插入更小
  键导致子树最小键下降时，沿 COW 路径向上刷新分隔键。

### 文件布局

```
[0:4096]     超级块槽 0
[4096:8192]  超级块槽 1
[8192:]      追加写数据区：节点页 + 映射表段
```

超级块 = 提交记录：magic、版本、代际号 gen、pageSize、节点数、
根节点 ID、映射表偏移、数据区末尾，外加 CRC32。代际号 g 写入槽
`g % 2`（乒乓双槽）。

### 提交协议（每次 Insert 即一个事务）

1. 把所有脏节点页**追加**写到 `dataEnd`（旧页原样保留）；
2. 追加写新映射表；
3. `fsync` 数据；
4. 写超级块槽 `(gen+1) % 2`；
5. `fsync`。

恢复：读两个超级块槽，校验 magic + CRC，取**代际号最大的有效槽**，
加载其映射表，把文件截断到 `dataEnd`（丢弃未提交的尾部垃圾）。

- 崩溃发生在第 4 步完成之前 → 旧代际完整可见 → **旧完整状态**；
- 崩溃发生在第 4 步之后 → 数据已先 fsync → **新完整状态**；
- 不存在可观察的中间态。"叶子已写但父节点未发布"（本实现中即
  数据页已落盘而超级块未发布）必然恢复到旧完整状态，见
  `TestLeafWrittenParentNotPublished`。

### 快照

`Snapshot` 固定 `(gen, rootID, 映射表副本)`。文件只追加不改写，
所以旧快照**永远有定义**：根分裂只是发布了新根 ID，旧根与旧映射表
原封不动。崩溃前取得的快照在崩溃后依然可读。

## 进程崩溃恢复与断电保证的边界

**保证（假设 fsync 可信）：**

- 单次 Insert 原子：恢复后要么是完整的旧状态，要么是完整的新状态。
- 数据页/映射表的撕裂写无害：未被任何已发布超级块引用，恢复时截断。
- 超级块槽撕裂写：CRC 校验失败，回退到另一个槽的旧代际
  （`TestTornSuperblockWrite`）。
- 恢复后数据库可继续接受提交。

**边界（不保证）：**

- 依赖 `fsync` 真的把数据刷到持久介质。对操作系统/硬件谎报
  write-back 缓存刷新的情况（掉电时缓存未落盘）无能为力——这是
  所有本地存储引擎的共同边界。
- 两个超级块槽位于不同 4KiB 区域；假定一次掉电不会同时损毁两个
  不相关扇区（企业级掉电保护盘之外无法绝对保证）。
- 创建数据库（首次格式化）不是崩溃原子的：空文件之外的半初始化
  文件会被判为 `ErrCorrupt`，需删除重建。
- 空间只增不减：没有空闲页回收/压缩，长期运行需重写文件（暂未实现
  compaction）。
- 单写者进程内互斥；没有跨进程文件锁，多进程同时打开同一文件
  属于未定义行为。
- 无删除操作（API 未提供）。

## 使用

```go
db, _ := btree.Open("/path/to/dir", &btree.Options{PageSize: 512})
db.Insert([]byte("k1"), []byte("v1"))      // 重复键 = 覆盖
v, found, _ := db.Get([]byte("k1"))
db.Scan([]byte("a"), []byte("z"), func(k, v []byte) bool { return true })
snap, _ := db.Snapshot()                    // 历史快照，长期有效
it := snap.Iterator(nil, nil)               // 跨叶扫描，无重复无遗漏
db.Check()                                  // 结构一致性校验
```

故障注入：`Options.FaultHook func(fp btree.FaultPoint) bool`，在提交
协议的 5 个阶段（每数据页写后 / 数据写完 / 数据 fsync 后 / 超级块
写后 / 超级块 fsync 后）回调，返回 `true` 即模拟进程崩溃，句柄进入
死亡状态（后续操作返回 `ErrCrashed`），重新 `Open` 即走恢复路径。

## 测试与样例

```sh
go test ./...        # 全部测试（含故障注入矩阵，fsync 密集，约 1 分钟）
go run ./cmd/btree-demo [dir]
```

- `btree_test.go`：基本增查、128 字节小页高频拆分（叶/内部/根分裂，
  每 50 次插入全量校验父子指针与叶链）、重复键覆盖、重开持久化、
  扫描边界、键值大小限制。
- `recovery_test.go`：提交协议全阶段 × 多页偏移的崩溃矩阵（新键与
  重复键覆盖两组），恢复态必须恰为旧或新完整状态；"叶子写好但父
  未发布"的精确新旧边界；超级块撕裂写。
- `snapshot_test.go`：400 次插入期间每 10 次取一个快照，根多次分裂
  后 40 个历史快照逐一校验仍可完整扫描。
