# incbuild — 增量构建计划器

区分**内容依赖**与**顺序依赖**的增量构建计划器（Go 实现）。

## 核心语义

- **内容依赖（ContentDep）**：依赖内容变化才传播失效。失效只沿此类边传播。
- **顺序依赖（OrderDep）**：只约束调度顺序，任何变化都不会使下游失效。
- **动态发现依赖**：任务运行中可通过 `ctx.DependContent/DependOrder` 或
  `ctx.ReadFile`（隐式内容依赖）发现新依赖。若新发现的依赖尚未构建或已过期，
  本次运行结果会被丢弃（绝不提交过期结果），待生产者补齐后重新运行该任务。
- **运行期源文件变更**：任务通过 `ctx.ReadFile` 读取的文件在运行结束后会被
  重新校验；若运行期间被修改，结果丢弃并重跑（超过重试上限则报错）。
- **生成文件校验**：输出文件缺失或被外部篡改都会使生产者重建；若重新生成的
  内容与原内容一致，则失效不再向下游传播（early cutoff）。
- **最短原因链**：每个重建节点输出最短的失效原因链（`Result.Reasons`），
  被丢弃的尝试记录在 `Result.Notes`。

## 布局

- `planner/` — 计划器核心（`Build` 调度循环、脏检查、拓扑排序、状态提交）
- `planner/planner_test.go` — 菱形依赖 + 最短链、顺序依赖、生成文件校验、
  运行期源文件变更、动态发现补排 等场景的验证
- `cmd/demo/` — 演示程序，打印每次构建的最短原因链

## 运行

```sh
export GO111MODULE=on
go test ./planner/ -v
go run ./cmd/demo
```

状态可通过 `Planner.SaveState/LoadState` 以 JSON 持久化，实现跨进程增量。
