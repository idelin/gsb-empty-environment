# ir-opt：有分支整数中间码的安全优化库

针对 32 位有符号整数 IR（赋值 / if-else 分支 / return），其中**溢出与除零是可见错误**。
优化器做常量传播、常量折叠与不可达代码删除，并严格保证：优化前后程序的
**运行结果与完整错误轨迹（语句 id 序列 + 错误种类 + 出错节点 id）完全一致**。

## 正确性不变式

1. **不丢弃可能抛异常的求值**。`x*0`、`0*x`、`0/e`、`e-e` 一律不折叠——被丢弃的
   子表达式可能溢出或除零。只做恒等元化简（`e+0`、`e-0`、`e*1`、`e/1`），
   它们保留对 `e` 的恰好一次求值。
2. **只折叠不会出错的常量表达式**。`1/0`、`I32_MIN/-1`、`-I32_MIN` 等保留原节点，
   让错误在运行时、同一节点 id 处发生（错误位置不变）。
3. **只删确定不可达的代码**。条件被常量传播证明为常量时才删除另一分支；
   无条件 `return` 之后的语句同理。`if` 节点本身保留（死分支置空），
   因此执行轨迹中的语句 id 与原程序一一对应。
4. 分支汇合处做常量环境合并：仅当所有存活路径对某变量给出**相同**常量时，
   该变量在汇合后才视为常量。

## 结构

- `src/ir.ts` — IR 定义；每个节点带稳定 id 作为执行位置
- `src/interp.ts` — 解释器，抛出 `overflow` / `divzero` / `undef` 并记录轨迹
- `src/opt.ts` — 优化器（常量传播/折叠、恒等元化简、不可达分支与死代码删除）
- `src/randgen.ts` — 带种子的随机程序生成器（数值偏向 `I32_MIN/MAX` 等边界）
- `src/difftest.ts` — 原解释器 vs 优化后解释器的结果与轨迹比对
- `src/main.ts` — 9 个定向测试 + 模糊测试入口

## 运行

环境离线无法安装 TypeScript 时，`tools/build.mjs` 会回退使用本机 Cursor
内置的 TypeScript 编译器 API；有 `typescript` 依赖时优先使用之。

```sh
npm test                 # 构建 + 定向测试 + 默认 5000 个随机程序
node dist/main.js 50000 100001   # 指定数量与起始种子
```

最近一次验证：50000 个随机程序（ok/溢出/除零约 2.3万/1.9万/0.76万），
节点数减少约 31%，结果与错误轨迹 **0 失配**。
