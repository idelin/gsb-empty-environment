集群升级批量排空多个节点时，单个业务 Pod 可能同时被多条 PodDisruptionBudget（PDB）选中，而 PDB 允许用整数或百分比指定 `minAvailable`（向上取整）或 `maxUnavailable`（向下取整，但至少为 0），按节点硬串行排空太慢，盲目并发驱逐又会踩破重叠 PDB。为运维编排内核交付可导入的 Go 排空求解包。输入集群中所有运行中 Pod（含所在节点、标签与当前是否 Ready）、目标待排空节点集合、同时允许存在驱逐动作的最大节点数 K，以及 PDB 列表（标签选择器、`minAvailable` 或 `maxUnavailable` 整数/百分比）。规则：每一驱逐波次同时选出一个待驱逐 Pod 子集（来自至多 K 个目标节点），要求驱逐该子集后，每条 PDB 的剩余 Ready 副本数均不低于其要求下限（本波次被驱逐的 Pod 立即变为不可用，波次结束时假设被驱逐 Pod 均已在非目标健康节点上重建并 Ready，随后进入下一波次）；若某目标节点上的 Pod 无论如何单条驱逐都违反某条 PDB（如 `minAvailable == currentReady` 且无其他非目标 Ready 副本），须明确报出死锁 Pod 与卡住它的精确 PDB 编号。在目标待排空 Pod 总数不超过十时，求清空全部目标节点的最少波次数及对应每波驱逐集合（并列按每波次驱逐节点数和最小，再按波次字典序最小）。验收用状态空间 BFS 核对最少波次与全部 PDB 不变量，覆盖单 Pod 同时命中两条 PDB 取更严约束、百分比 `minAvailable` 向上取整与 `maxUnavailable` 向下取整差异、未 Ready 副本提前占用不可用配额导致本波不可驱逐，以及永久死锁报错。
