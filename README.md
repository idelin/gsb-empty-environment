# recovery — 任务流水线恢复规划器

基于内容摘要（SHA-256）的增量恢复引擎：任务消费并产生带版本的文件，
文件损坏或被编辑时，只重跑受影响任务及其后继，已成功独立分支直接复用。

## 核心机制

- **内容摘要快照**：每个任务成功运行后，记录其全部输入/输出文件的
  SHA-256 摘要（`inputDigest` / `outputDigest`）。
- **损坏检测**：`Recover` 扫描发现两类脏任务——自身产物摘要与记录不符
  （被损坏/删除），或源文件输入（无生产者）被外部修改。
- **失效传播与提前阻断**：按拓扑序重跑脏任务；仅当某产物的新摘要与
  上次记录不同时才将下游消费者标脏。重跑产物内容相同则阻断继续失效
  （early cutoff）。
- **失败重试**：任务失败按 `maxRetries` 重试，每次尝试计入 `ExecCount`；
  重试耗尽则报错并阻断下游。

## 验证（`go test ./...`）

- 全量重建每个任务恰好执行一次；恢复结果与全量重建产物逐字节一致。
- 损坏叶子/中间产物只重跑生产者，内容相同不波及后继（执行次数核对）。
- 源文件编辑沿依赖链传播，独立分支执行次数为 0。
-  flaky 任务在重试预算内成功（计数 = 失败次数 + 1）；永久失败重试
  耗尽后报错，下游执行次数为 0。

注意：需要 Go 1.11+；本环境需 `GOCACHE=/private/tmp/gocache GO111MODULE=on`。
