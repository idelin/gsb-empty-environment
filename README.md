自动化证书颁发机构（CA）在执行 ACME（RFC 8555）的 `HTTP-01`、`DNS-01` 与 `TLS-ALPN-01` 域名控制权验证（DCV）时，若允许 `HTTP-01` 重定向到内网/回环/元数据 IP（SSRF）、未限制重定向跳数与端口（仅允许 80/443）、未按多视角签发校验（MPIC，Multi-Perspective Issuance Corroboration）要求多数独立地理观测点同时通过，或漏检 `TLS-ALPN-01` 证书的关键 `id-pe-acmeIdentifier`（OID `1.3.6.1.5.5.7.1.31`）扩展与单 DNS SAN 约束，攻击者可利用局部 BGP 劫持或开放重定向骗签任意域名的可信证书。为 Go CA 安全宿主实现可导入的 ACME DCV 与 MPIC 联合校验引擎包，严禁真实联网（网络/DNS 探测通过注入的确定性模拟接口完成）。组件严格实现：（1）密钥授权计算（`keyAuth = token + "." + Base64URL(JWK_Thumbprint)`）与三类挑战精确验证：`HTTP-01` 校验路径 `/.well-known/acme-challenge/<token>`、硬拒绝指向私有/回环/链路本地/保留 IPv4 与 IPv6（含 IPv4-mapped IPv6）的初始或重定向目标、限制端口仅 80/443 且跳数 ≤5；`DNS-01` 校验 `_acme-challenge.<domain>` TXT 记录等于 `Base64URL(SHA256(keyAuth))` 并拒绝悬空 CNAME 环路；`TLS-ALPN-01` 校验协商 ALPN 为 `acme-tls/1`、自签证仅含 1 个匹配的 DNS SAN 且带 `critical=true` 的 `id-pe-acmeIdentifier` ASN.1 OCTET STRING 精确等于 `SHA256(keyAuth)`；（2）实现 MPIC 法定人数决策（主视角必须通过 + 远程多视角按规范最大允许失败数裁决，任一视角检出 CAA 禁止即全局拒签）。附 SSRF 内网重定向拦截、非关键 `acmeIdentifier` 拒绝、局部 BGP 劫持单视角成功但 MPIC 拒签与 CAA 阻断测试。
