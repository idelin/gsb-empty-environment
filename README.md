硬件安全密钥（FIDO2 / CTAP2.1）认证器在实现 `clientPin` PIN/UV Auth Protocol Two（`pinUvAuthProtocol=2`）与带权限范围的 `pinUvAuthToken` 时，若密钥派生未严格区分 HMAC 密钥与 AES 密钥、允许已绑定某 `rpId` 的令牌跨站点用于 `makeCredential`/`getAssertion`，或连续输错 PIN 时未先递减持久化重试计数器再执行比对，物理攻击者可通过断电重放无限爆破 PIN 或借低权限令牌执行凭证管理（`cm`）。为 Go 认证器安全宿主实现可导入的 CTAP2.1 PIN/UV Auth Protocol Two 密码状态机与权限强制核验包，严禁联网（仅用 Go 标准库 `crypto/ecdh`、`crypto/aes`、`crypto/cipher`、`crypto/hmac`、`crypto/sha256`）。组件严格按 FIDO CTAP 2.1 规范实现：（1）P-256 ECDH 共享密钥经两次独立 HKDF-SHA-256 派生 32 字节 `hmacKey`（info=`CTAP2 HMAC key`）与 32 字节 `aesKey`（info=`CTAP2 AES key`），实现带随机 16 字节 IV 的 AES-256-CBC 加解密与全 32 字节 HMAC-SHA-256 认证（区别于 Protocol 1 的 16 字节截断）；（2）严格重试与防断电爆破状态机：每次 `getPinToken` 校验前必须先持久化 `retries = retries - 1`（总上限 8 次，单次上电连续错 3 次强制要求重启，归零永久锁定直至硬件重置），校验通过才恢复满额并签发全新随机 `pinUvAuthToken`；（3）令牌权限（`mc`/`ga`/`cm`/`be`/`lbw`）与 `rpId` 强绑定：消费令牌执行操作时必须校验 HMAC 匹配、请求动作位在签发权限内且目标 `rpId` 全等，且每次调用 `getKeyAgreement` 重新轮换密钥或超期即作废旧令牌。附跨 RP 越权、低权升 `cm`、断电重放爆破与 Protocol 1/2 降级混淆测试。
