# genagg：分代屏障聚合器与事件标签核对

多个生产分区并发发起重置（reset）。每个事件携带不可变标签
`(partition, gen, seq)`，每个屏障携带标签 `(partition, gen)`：

- 屏障前事件计入旧代，屏障后事件计入新代；
- 分区乱序到达屏障，已越过分区的屏障后事件按分区分别缓存（`newSum`）；
- 只有全部预期分区到齐，才发布旧代终值并轮换到新代，缓存值成为新代基数。

## 标签语义（正确性不变量）

- **去重**：事件按 `(partition, seq)` 标签去重，重放/重投幂等；
- **屏障幂等**：重复屏障（已越过）、过期屏障（`gen < 当前代`）、
  跳跃屏障（`gen > 当前代`）一律无副作用；
- **退出**：分区退出即从预期集合移除；已计入旧代的值保留，
  缓存中的屏障后值随分区丢弃；退出恰好补齐集合时立即发布；
- **恢复**：崩溃分区从检查点重放日志并重发屏障，靠标签幂等，
  即使重放跨代到达也不会重复计数；
- **协议违规**：事件标签与分区屏障位置不一致（如屏障前出现
  `gen+1` 事件）返回 `*ProtocolError`，不计入。

假设：单分区投递有序（FIFO）；分区最多领先聚合器一个屏障。

## 核对方法

`Model`（model.go）是独立的参照实现：不做任何缓存与轮换，纯按标签
代数计算每代终值。`TestModelCrossCheck` 生成随机轨迹（乱序交织 +
事件重放 + 重复屏障 + 分区退出 + 迟到消息），同时喂给 `Aggregator`
和 `Model`，断言两者发布序列完全一致，且代编号连续、每代只发布一次。

```sh
go test ./...        # 场景测试 + 500 条随机轨迹交叉核对
go test -race ./...
```
