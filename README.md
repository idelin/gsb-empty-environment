# intwire — 有符号 / 无符号 / 任意精度整数线格式 + JSON 桥

纯 Go 标准库实现。`Value` 把三件事分开保存：原始词法（`Raw`）、精确值
（`U` / `I` / `B`）、位宽约束（`Width`）。

## 支持的序列化范围（自定义）

- 固定位宽：u8/u16/u32/u64、s8/s16/s32/s64，构造与解码时都做范围检查；
  负数无法进入无符号字段（类型系统 + 解码双重拒绝）。
- 任意精度：`KindBig`，线格式字节长度上限 `MaxBigBytes = 65536`，
  JSON 词法十进制位数上限 `MaxDecimalDigits = 200000`，超限即拒绝。
- 解码不执行任何宿主代码：只验证字节并构造整数；长度先验证（上限 +
  剩余输入）再分配。

## 二进制线格式（多版本）

首字节为版本号，解码器按版本分发，混合版本流可顺序解码。

- **V1**：`tag = kind<<6 | width/8`；定宽值用最短 varint（有符号先
  zigzag）；大整数为最短二进制补码（`0` 编为单字节 `0x00`）。
- **V2**：kind、width 各占一字节；大整数为 符号字节 + 最短大端幅值。

**规范性**：同值只有一种规范编码。非最短 varint（尾部零组）、冗余符号
扩展（前导 `0x00`/`0xFF`）、负零、前导零幅值一律拒绝；且解码出错时
位置不前进，绝不消费下一字段。

## JSON 桥

- 规范封套：`{"k":"u|s|big","w":64,"v":"<十进制字符串>"}` —— 精确值
  永远走字符串标签，规避 float64 的 53 位精度丢失。
- 裸 JSON 数字 / 带引号词法（如 `1e400`、`2.5e3`）按**文本词法**解析：
  先扫描判断是否为整数、是否超额度，再做任意精度运算；全程不经过
  宿主浮点。
- `StreamEncoder` / `StreamDecoder` 以 `json.RawMessage` 逐元素流式
  读写，原始词法保留在 `Value.Raw`。

## 运行

```sh
go test ./...    # 22 个测试：穷举小范围+极值、随机大整数对照 math/big、
                 # 非规范拒绝、u64 最大值往返、53 位边界、流式桥等
go run ./cmd/demo
```
