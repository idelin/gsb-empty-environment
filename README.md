微服务认证网关在校验 JWS（RFC 7515）及未编码载荷扩展（RFC 7797 `b64=false`）签名令牌时，若信任令牌保护头中的 `jku`/`x5u` 自动拉取外部密钥（SSRF + 攻击者自控公钥）、未对 `kid` 做白名单约束直接拼入文件路径或查询语句（路径穿越/注入）、未强制 `b64=false` 时 `crit` 必须包含 `"b64"`，或允许 `alg=none`/用 RSA 公钥字节作为 `HS256` HMAC 密钥（算法混淆），攻击者可任意伪造高权限 JWT/JWS。为 TypeScript 认证宿主实现可导入的零外部依赖 JWS/RFC 7797 严格解析与安全准入校验组件（密码验签使用 Node 内置 `crypto`）。组件严格执行：（1）硬拒绝 `alg="none"` 及任何未列入服务端密钥绑定白名单的算法（每把密钥显式绑定唯一允许的 `alg` 与密钥类型，彻底阻断 RS256→HS256 混淆）；（2）头部安全门禁：硬拒绝重复 JSON 键、硬禁止 `jku`/`x5u`/`jwk`/`x5c` 外部或内嵌未授信密钥来源（除非显式策略开启且严格限定 HTTPS 白名单主机并禁止内网/重定向），强制 `kid` 仅匹配安全正则且精确命中本地预注册密钥表（拦截 `../`、NUL、通配与注入字符）；（3）RFC 7797 `b64` 扩展精确验证：当出现 `b64` 头时其值必须为布尔型，若 `b64===false` 则 `crit` 必须显式包含 `"b64"` 且验签输入必须按原始未 Base64URL 编码的载荷字节拼接（同时拒绝在紧凑序列化中把含 `.` 的未编码载荷造成分段歧义）。附 RS256→HS256 混淆、`jku` 恶意 URL、`kid` 路径穿越、缺失 `crit` 的 `b64=false` 与重复 JSON 键测试。
