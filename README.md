# alpha-compositing-exact

8 位透明度合成库：内部全部使用精确有理数（BigInt 分数）运算，比较“一次性合成”
与“分组后量化”的差异，并搜索输出最小反例。

运行（Node >= 23.6，原生类型擦除直接执行 TypeScript）：

```sh
npm start
```

## 规则（题内线性规则，不调用图形库默认混合）

- 内部表示：精确预乘颜色，r/g/b/a 均为 [0,1] 内的有理数（`Frac`）。
- 合成算子：Porter-Duff `over`，逐通道线性：
  `out.c = top.c + bottom.c * (1 - top.a)`（c 含 r/g/b/a）。
- 输入格式：非预乘（straight）与预乘（premultiplied）8 位 RGBA 均可；
  预乘输入校验通道不超过 alpha。
- 零透明度特判：
  1. straight 输入 `a=0`：颜色通道无意义，归全透明 `(0,0,0,0)`；
  2. premultiplied 输入 `a=0`：颜色通道必须全 0，否则报错；
  3. 输出反预乘时精确 alpha 为 0（或量化为 0）：颜色通道输出 0，避免 0/0。
- 量化：round-half-up 到最近的 8 位整数。

## 一次性 vs 分组量化

- 一次性：所有图层精确合成，最后只量化一次。
- 分组：每组精确合成 → 量化为 8 位 straight → 重新解析 → 组间合成 → 再量化。
  中间量化丢失的信息即差异来源（`src/compare.ts`）。

## 最小反例

2 层可证无差异（straight 8 位输入经 解析→量化 是恒等映射，单层组等价于不分组），
故最小规模为 3 层 2 组。搜索（`src/search.ts`）用纯整数精确运算快速扫描，
候选再由 `Frac` 库复核。最小性按“层数 → 组数 → 最大分量 → 字典序”排序。

程序找到的最小反例（所有分量 ∈ {0,1}）：

```
L1 = (0,0,0,1)   底层
L2 = (0,0,0,1)
L3 = (1,1,1,1)   顶层
分组：{L1} + {L2,L3}
```

- 一次性：精确 alpha = 194311/16581375，精确通道 r = 1/65025；
  反预乘 255/194311 ≈ 0.00131 → ×255 ≈ 0.335 → 量化为 **0**。
- 分组：{L2,L3} 精确通道 1/65025、alpha 509/65025，反预乘 1/509 → ×255 = 255/509
  ≈ 0.50098 → 量化为 **1**（信息丢失），最终输出通道为 **1**。
- 结果：一次性 `(0,0,0,3)` vs 分组 `(1,1,1,3)`，r/g/b 三个通道不同。

## 文件

- `src/fraction.ts` — 精确有理数（BigInt，恒约分）
- `src/color.ts` — 颜色模型、两种输入格式、over、量化、零透明度特判
- `src/compare.ts` — 一次性 / 分组量化两条合成路径
- `src/search.ts` — 最小反例搜索（整数快速扫描）
- `src/main.ts` — 自检、演示、搜索、精确复核报告
