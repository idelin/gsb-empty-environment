一组前端节点滚动替换握手策略时，单看新旧配置清单都没有弱套件，中间态仍可能优先选择旧认证方式。配置发布器需要一个可导入的 Go 判定包，在接受发布计划时调用它。客户端能力由至多 48 个布尔位表示，合法能力用给定变量序的有序决策图描述；每台节点有新旧两份有序规则，首个满足能力条件的规则给出认证级别或拒绝。客户端沿给定回退序列访问节点，只在拒绝时尝试下一台。对每个能力向量分别取全旧和全新结果，过渡期的实际结果不能比两端都弱，且两端均能连接时中间态不得拒绝。发布前最多 14 个节点要各切换一次，节点间有先后依赖和同批原子切换组，输入还给出每个维护窗口可切换的节点集合。求使用窗口最少的合法方案，同长按每批排序后的节点编号序列取字典序最小；无解须给可核验的阻断依据，有能力反例时返回按位序最小者。不能枚举全部能力向量。用不超过六位的穷举模型验证拒绝回退、同批可行而拆开不可行、等价规则划分和零个合法客户端。
