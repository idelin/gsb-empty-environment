# 握手后身份升级隔离

长连接允许会话开始后请求更强客户端身份，验证进行中不能让受保护消息沿用旧权限。实现供Go协议宿主调用的身份升级组件，每次请求绑定唯一上下文，应用消息按所需身份等级排队，只有匹配上下文的证书与完成验证都成功才统一放行；旧等级消息可继续。用乱序认证回调测试重复请求、升级失败、取消及半关闭，保证未通过身份的内容从未进入受保护回调。

## 组件

- `Gate`：协议宿主持有的身份门，内部按等级排队，受互斥锁保护，可并发调用。
- `BeginUpgrade(ctx, level)`：生成随机唯一上下文 ID，返回绑定该请求的 `context.Context`；支持多个升级并发进行，回调乱序也不会串上下文。
- `Submit(Message)`：旧等级消息立即进入 `Sink.Deliver`；更高等级消息在门内排队，不接触受保护回调。
- `CompleteUpgrade(ctx, id, Credential)`：凭证必须绑定同一个上下文 ID（否则 `ErrContextMismatch`），且 `Verifier.Verify` 成功，二者同时满足才提升等级并按到达顺序统一放行；同一上下文的重复回调返回 `ErrUnknownContext`。
- `CancelUpgrade(id, cause)` / 父上下文取消 / `HalfClose()`：未满足的排队消息进入 `Sink.Reject`，绝不降级放行；半关闭后所有方法返回 `ErrClosed`。

## 不变量

- 未通过身份的载荷不会调用 `Sink.Deliver`（测试以记录型 sink 断言）。
- 每条被接收的消息最终恰好一次 `Deliver` 或 `Reject`。
- 一个上下文失败或取消不影响其他仍在进行的升级。
- 升级终止后其上下文被取消，无 goroutine 泄漏（测试含泄漏检查与 `-race` 验证）。

## 测试

`go test -race ./...` 覆盖：乱序双上下文回调、重复请求、验证失败、显式取消、父上下文取消、半关闭、跨上下文凭证、未知上下文、验证中途取消与并发压力。
