# recover-planner

在有限磁盘额度内规划恢复执行顺序：压缩块下载 → 临时块解压 → 原子发布。
输入依赖 DAG、各阶段空间占用与释放时点，输出最小化磁盘峰值的执行顺序，
并始终给出**已证可行上界**与**合法下界**（预算中断时同样成立）。

## 模型

每个块依次经历三个阶段，磁盘占用随事件时间线变化：

| 事件 | 占用变化 | 说明 |
|---|---|---|
| 下载完成 | `+compressed` | 压缩块落盘 |
| 解压中 | `+temp` | 临时未压缩数据与压缩包共存（峰值候选） |
| 原子发布 | `-compressed -temp +final` | 瞬间换入最终数据 |

释放时点：

- 压缩包在解压完成后立即释放；
- 临时块在原子发布瞬间释放；
- 最终块在其**所有**依赖者发布之后释放，除非它是输出块（默认取 DAG 汇点），输出块保留到结束。

关键语义：

- **共享块只算一次**：被多个下游依赖的块只下载/解压/占用一次（DAG 而非树）。
- **峰值 ≠ 最终大小**：峰值是时间线上的最大瞬时占用；中途的压缩包+临时块会抬高它，
  非输出块的提前释放又会压低结束时的占用。两者都必须按事件流复算，不能取最终大小。

## 用法

```sh
go run ./cmd/recover-plan -spec examples/diamond.json -budget 5s
```

输入（JSON）：

```json
{
  "blocks": [
    {"id": "a", "compressed": 5, "temp": 10, "final": 4},
    {"id": "b", "compressed": 3, "temp": 6,  "final": 2, "deps": ["a"]}
  ],
  "outputs": ["b"],
  "quota": 20
}
```

输出（JSON）：

- `order` / `peak`：最优（或当前最优）执行顺序及其峰值；
- `upperBound`：已证可行上界 —— 等于 `order` 真实复算出的峰值；
- `lowerBound`：合法下界 —— 任何顺序都不可能低于它（见下）；
- `optimal` / `exhausted`：搜索空间是否已在预算内枚举完；
- `feasible` / `provablyInfeasible`：相对 `quota` 的可行性判定
  （`lowerBound > quota` 时即可证明不可行）。

## 算法

1. **下界**（与顺序无关，两条论据取 max）：
   - 块 `i` 解压瞬间，`compressed[i]+temp[i]` 共存，且其所有依赖的最终块必然仍在盘
     （依赖要等全部下游发布后才释放）：`peak ≥ compressed[i]+temp[i]+Σ final[deps(i)]`；
   - 运行结束时恰剩全部输出块：`peak ≥ Σ final[outputs]`。
2. **上界**：任意构造出的合法顺序，其复算峰值即为已证可行上界。
   初始解用贪心表调度（每步在就绪块中选一阶导最优：(峰值, 占用) 字典序最小），
   再用保拓扑的相邻交换下降改进。
3. **精确求解**：小块数 DAG（默认 ≤ 12）枚举全部拓扑序并复算，
   分支定界剪枝（部分调度的峰值单调不减，≥ 当前最优即剪）；命中下界可提前终止。
4. **预算中断**：`-budget` / `Options.MaxNodes` 耗尽时立即停止，
   返回当前最好的 `upperBound` 与 `lowerBound`，`optimal=false`，界仍然合法。
