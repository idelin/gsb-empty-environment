# 数据保留期限传播

安全日志经过多级派生后不能无限延长最早来源的保留期限。实现供Go数据宿主调用的期限传播包，节点可复制、合并、匿名化和定期重建；普通派生取最早期限，匿名化只有具备给定证明标签才能改用独立期限。增量更新依赖图并解释每个最早期限来源，用循环、撤销证明和迟到来源测试。

## 模型与语义

包 `netsec` 维护一张保留期限依赖图，边 `src -> dst` 表示 `dst` 由 `src` 派生。

- 来源节点（`KindSource`）的期限由宿主直接设定；零值 `time.Time` 表示“暂不受限”。
- 普通派生（复制 `AddCopy`、合并 `AddMerge`、定期重建 `AddRebuild`）的生效期限取全部上游的最早期限，因此任何多级派生都不能延长最早来源的保留期限。
- 匿名化节点（`AddAnonymize`）默认同样取最早期限；只有当它携带的证明标签经 `IssueAttestation` 签发且仍然有效、并申请了独立期限时，才改用独立期限，此时它成为传播屏障，上游约束不再穿过它。
- `RevokeAttestation` 撤销标签后，屏障立即失效，节点与其下游重新按最早期限收敛。

## 增量更新与定期重建

- 所有变更（加节点、`AddEdge` 加边、改来源期限、签发/撤销证明、改独立期限）只重算受影响节点的下游闭包。
- 重算先在受影响子图上用 Kosaraju 求强连通分量（SCC），按“上游在前”的拓扑序对每个 SCC 做不动点迭代：无环时等价于普通拓扑传播，有环时循环内节点收敛到同一最早期限；屏障节点锁定独立期限，循环无法借由它延长保留期限。
- `Rebuild` 从零全量重算整张图，不改变任何节点、边或证明状态，供宿主定期校验增量结果。

## 来源解释

`Explain(id)` 返回 `Explanation`：

- `Determining`：真正决定最早期限的来源（含一条可验证的依赖路径）；
- `OtherSources`：仍约束该节点但期限更晚的来源；
- `Independent`：节点是否凭有效证明采用独立期限；
- `InCycle` / `Cycles`：节点是否处于循环及具体环路。

追溯在有效匿名化屏障处停止，因此解释结果与传播语义一致。

## 测试

`go test ./... -race -count=1` 覆盖：基础多级传播、无约束来源、匿名化无证明/签发/撤销/重签、循环与自环、循环中的屏障、迟到来源（零期限后补设与增量加边）、解释路径与环路、全量重建与增量结果等价的随机属性测试，以及并发访问。
