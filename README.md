# 安全审计日志前缀恢复

审计写入服务要区分掉电撕裂和中段篡改，不能遇到坏记录就悄悄截断。写供Go服务调用的日志包，每条记录含序号、前项摘要、载荷长度与HMAC，段末有独立签名封条；只允许未封口段的物理尾部是不完整记录，完整但认证失败一律报告篡改。用标准库密码组件和故障文件测试跨段拼接、尾部丢失及重启追加，不覆盖损坏证据。

## 实现

代码位于 `auditlog/`，故障注入位于 `auditlog/faultfile/`。

- `auditlog`：仅依赖标准库（`crypto/hmac`、`crypto/sha256`、`crypto/ed25519`）。
  - 记录帧：魔数/版本/标志、8 字节序号、4 字节载荷长度、32 字节前项 SHA-256 摘要、
    载荷，以及覆盖序号/长度/前项摘要/载荷的 HMAC-SHA-256。
  - 封条帧：段末独立 Ed25519 签名，覆盖段序号、记录数、序号区间、前一封条摘要和
    最后一条记录摘要；封口后 `.part` 原子改名为 `.log` 并 fsync 目录。
  - 撕裂判定：只有未封口 `.part` 的物理尾部允许不完整帧，结果进入 `Report.TornTails`；
    完整帧 HMAC/签名失败、链断裂、缺封条、段序错乱一律返回 `*TamperError`。
  - 恢复：`Open` 先全量校验；存在撕裂尾部时保留原文件不覆盖，在新段从最后一条已认证
    记录续链追加。写入或 Sync 失败会冻结 `Writer`，必须重新 `Open`。
- `auditlog/faultfile`：把内存缓冲与磁盘持久化状态分离的故障文件，可模拟部分落盘
  （撕裂 flush）与掉电丢弃未同步字节。

## 验证

```sh
go vet ./...
go test -race -count=1 ./...
```

测试覆盖跨段拼接/删除/重复段、尾部丢失与撕裂恢复、封条签名与追加数据、
截断、重启追加、并发追加、空载荷与错误密钥等场景。
