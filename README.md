IPv6 分段重组存在两项常被误按 IPv4 习惯写错的强制规范：RFC 5722 严禁任何形式的字节重叠（哪怕两个分段在重叠区间的字节内容完全一模一样，只要偏移区间存在 1 字节交集，也必须立刻整包丢弃该重组缓冲并静默放弃，绝不可覆盖或保留先到片！），且 RFC 8200 规定仅当重组超时发生时缓冲区内已收到首片（`offset == 0`）才允许回发 ICMPv6 Time Exceeded，同时必须保留原不可分片扩展头并精确更新紧邻 Fragment Header 之前那个扩展头的 `Next Header` 字段。为三层协议栈交付可导入的 Go IPv6 分段重组与 PMTUD 状态机。重组器按 `(SrcIP, DstIP, FragmentID)` 索引重组队列：1）解析 8 字节 Fragment Header（`NextHeader`、13 位 `FragmentOffset` 乘以 8 字节、`M` 标志与 32 位 `Identification`），原子分段（`offset == 0 && M == 0`）不入缓冲直接剥离 Fragment Header 独立交付；2）校验非末片（`M == 1`）载荷长度必须为 8 字节整数倍（否则丢弃并生成 ICMPv6 Parameter Problem 指向 Payload Length！），校验重组后总长 `<= 65535` 字节，检测重复末片或任意 1 字节偏移重叠时立即按 RFC 5722 销毁整个重组会话并拒绝后续同 ID 迟到片重开污染；3）集齐从 0 到末片无缝覆盖的全部字节后，按规范用首片 Fragment Header 的 `NextHeader` 覆盖不可分片头链末端的 `NextHeader` 并重算 IPv6 Payload Length 输出完整报文；4）60 秒超时清理时严格区分“已收首片发 Time Exceeded”与“未收首片静默丢弃”，并受内存配额防重组缓冲耗尽。PMTUD 模块维护每目的地址有效 PMTU（处理 ICMPv6 Packet Too Big 降至通告值且强制不低于 `1280` 最小链路 MTU——收到 `< 1280` 时将 PMTU 钳位为 `1280` 并标记需要附带原子 Fragment Header！），并在超时周期后尝试回探更大 MTU。验收覆盖逐字节相同重叠片触发整包销毁、非 8 字节倍非末片 Parameter Problem、缺首片超时静默 vs 含首片超时回发 ICMPv6、原子分段直通、不可分片扩展头链 `NextHeader` 精确回写以及 `< 1280` PTB 钳位处理。
