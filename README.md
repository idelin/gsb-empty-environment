# 安全虚调用目标集合

二进制防护服务想精确限制虚调用目标而不把同名方法都允许。写供Go分析宿主调用的类型集合包，输入类继承图、对象分配点、向上转型和字段赋值，虚调用按对象可能动态类型与方法覆盖关系解析；共享虚基类槽若有多个互不为祖先的最终覆盖则报告歧义，非虚重复基类按子对象路径区分，继承环拒绝。结果带分配来源路径，以有限对象执行模型验证候选目标不能漏真调用。

## 实现

代码位于 `typeset` 包（`example.org/netsec/q0395/typeset`），宿主通过以下入口接入：

- `NewAnalyzer` 校验继承图：拒绝未知基类、重复直接基类与继承环，并预计算祖先关系。
- `SubobjectTableFor` 展开一个最派生对象的子对象 DAG。虚继承的基类塌缩为单一共享子对象；非虚重复基类保留各自独立的规范路径键。
- `OverrideTableFor` / `Resolve` 按“最派生对象 + 接收者子对象”计算最终覆盖。候选声明取子对象 DAG 中该子对象的祖先与后代节点，再按类继承关系做遮蔽；剩余互不为祖先的声明记为 `Ambiguous`，而不是任选一个目标。
- `Analyze` 在有限抽象解释上处理 `AllocFact`、`CopyFact`、`CastFact`、`FieldStoreFact`、`FieldLoadFact`，再解析 `CallFact`。字段单元按（对象，子对象，字段名）区分，对象与重复基类不会串扰。
- 每个 `ResolvedTarget` 都带 `Origin`：分配点、最派生类型和具体子对象路径；无虚槽、空接收者和歧义分别通过 `NoSlot`、`EmptyRecv`、`Ambiguities` 暴露。

## 有限对象执行模型与健全性

`ConcreteProgram` 是确定性的有限指令序列，`Execute` 给出具体运行轨迹，`CheckSoundness` 会：

1. 执行具体程序得到真实虚调用；
2. 将同一程序翻译成事实并运行抽象分析；
3. 断言每条真实调用都存在匹配的允许目标（含分配来源与规范子对象键）。

`GenerateProgram` 生成只含良态分发的随机有限程序；`typeset_test.go` 用 200 个随机种子持续验证候选集合不漏真调用。
