# age头部收件人一致性

Go 实现的 age 兼容头部解析与解密入口，核心目标是保证「先解出文件密钥、再校验覆盖头部全部字节的
HMAC、最后才允许读取载荷」的顺序不可被绕过。

## 安全模型

解密严格按以下顺序进行（见 `age.go` 的 `Decrypt` 与 `header.go` 的 `ParseHeader`）：

1. `ParseHeader` 只解析不采信，返回处于封存状态的 `PayloadReader`；此时读取只会得到
   `ErrHeaderNotAuthenticated` 和 0 字节。
2. 由 `Identity`（如 `ScryptIdentity`）从收件人行解出文件密钥。
3. `Header.VerifyMAC` 用恒定时间比较校验 HMAC-SHA256，其输入是版本行到 `---` 的头部原始字节；
   未知类型的行原样保留并参与 MAC。
4. 仅当校验通过，`PayloadReader` 才解封并解密 STREAM 载荷。

scrypt 收件人行必须是唯一一行（加密、解密两侧都强制），X25519 等基于密钥的收件人可多行并存。

## 运行测试

```
go test ./...
go test -race ./...
```

测试覆盖：

- 删行、增行、改 scrypt 参数、混合收件人等篡改样例，断言校验前载荷读取器返回 0 字节；
- 未知类型行被保留且参与 HMAC；
- ChaCha20-Poly1305（RFC 8439）与 scrypt（RFC 7914）的官方测试向量；
- 正常往返、错误口令、载荷篡改、截断载荷及 STREAM 分块边界。

仅依赖 Go 标准库（离线、无 module 下载）。

age文件头的收件人行被篡改时，攻击者可删除或替换收件人，使接收方用另一路径解出文件密钥。为Go加解密库实现头部解析包，供解密入口调用：先由收件人行取得文件密钥，再校验覆盖头部全部字节的HMAC，之后才允许读取载荷；scrypt收件人行必须是唯一一行，未知类型行保留并参与MAC。用删行、增行、改参数和混合收件人样例验证校验前载荷读取器不返回字节。
