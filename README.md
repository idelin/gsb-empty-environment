企业邮件出站中继（MTA）在向外部域投递邮件时，若未联合落实 MTA-STS（RFC 8461）与 DANE TLSA（RFC 6698 / RFC 7672），中间人可通过剥离 `EHLO` 响应中的 `STARTTLS` 宣告、伪造未授权 MX 主机名、用弱通配符证书冒充目标 MX，或注入旧策略降级 `enforce` 为 `testing`/`none`，从而窃听或篡改全量邮件。为 Go 邮件安全宿主实现可导入的 MTA-STS 与 DANE TLSA 联合策略解析及 TLS 证书准入验证包，严禁联网（使用标准库 `crypto/x509`/`crypto/sha256`/`crypto/sha512`）。组件严格实现：（1）解析并校验 MTA-STS 策略文本（强制 `version: STSv1`、`mode` 仅限 `enforce`/`testing`/`none`、非负 `max_age`、至少一条 `mx` 项，拒绝重复冲突键与非法换行）；实现符合 RFC 8461 Section 4.1 的 MX 匹配（通配符 `*.example.com` 仅匹配单级子域，严禁匹配根域或多级子域）；并维护策略缓存防降级逻辑（新策略抓取失败时未过期的 `enforce` 策略不得降级为明文）；（2）解析 DNSSEC 已验证的 DANE TLSA 记录（Usage `2` DANE-TA / `3` DANE-EE、Selector `0` 整证 / `1` SPKI、MatchingType `0` 原文 / `1` SHA-256 / `2` SHA-512），结合对端证书链精确验真（注意 `DANE-EE` 允许跳过 PKIX 链但仍须校验证书/SPKI 与 TLSA 摘要恒定时间一致，且若存在有效 TLSA 则优先于 MTA-STS 强制加密）；（3）在 `enforce` 模式或存在有效 TLSA 时，若对端未提供 `STARTTLS` 或证书/MX 校验不通过一律硬阻断投递。附 STARTTLS 剥离、多级通配符越界、`DANE-EE`/`DANE-TA` 摘要错配与缓存降级对抗测试。
