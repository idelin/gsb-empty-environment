# 控制流类别合法但能力仍被劫持

运行时按目标类别检查间接调用，却担心同一类别内的指令片段被串成未授权文件读取。为Go安全评审宿主实现可调用的有界链搜索包，所有执行都发生在内存模型中：4个8位寄存器、16字节内存，片段最多16个，每片段有类别、最多4条操作及结束方式；操作只含常量、模256加法、异或、load、store、grant和readProtected，结束为halt或按指定寄存器值选择片段ID的间接跳转。每个跳转点给允许类别集合，类别不符即拒绝；grant仅在当前片段ID属于宿主的可信授予集合时产生能力，readProtected无能力执行即构成漏洞。所有未指定寄存器和内存初值由宿主给定，初始没有能力；load/store地址取寄存器值，超出16字节立即陷阱，目标ID不存在也陷阱。攻击者只能设置入口寄存器与调用方指定的最多2个内存字节，候选值集合给定，不能改变片段。搜索至多8次片段转移，输出每一步均通过类别检查但最终未授权读取的字典序最小输入和链；超工作预算报未知，无见证仅报界内未发现。用类别相同却语义危险、必须经过可信grant、越类跳转及写内存影响后继目标的案例交叉核验。
