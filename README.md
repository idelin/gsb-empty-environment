XMPP 宿主在一条服务器间流上逐次验证多个域，断线恢复后可能收到旧流上排队的 stanza。给 Go 路由器写可导入的入口授权组件。流身份绑定对端证书公钥、启动随机数和会话代次；每份域授权还绑定域名规范值与生效区间，别名授权可收窄到指定本地部分集合，但不能改写原始发送者。客户端绑定、服务器域验证和恢复票据是三种不同证据，不可互换。验证要保留“属性缺失、显式空值、存在且有效”三种状态，服务器间的缺失来源不能由该流唯一已认证的域补写。对一批跨域投递，宿主提供可能乱序的域撤销、重绑定和待投递帧，要求在真正将帧交给路由前使用原流身份和同一代次核对来源、目的托管域，以及此前留存的授权收据。若启动随机数变了，即使两端显示名称相同也不得沿用旧流凭据。设计可回放的判定记录，让缺少原始属性和缺少授权证据可分别诊断；用两个域同流、独立域撤销、同名新流、带额外斜杠的合法资源和客户端同裸 JID 不同资源测试，比较实际路由回调次数与流关闭原因。
