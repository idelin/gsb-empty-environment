高并发 VPN 边界网关在遭遇海量伪造握手包（`Handshake Initiation`）洪泛时，依赖 WireGuard 协议的负载缓解机制（MAC1、MAC2 与 `Cookie Reply`）在不执行昂贵 Curve25519 运算的前提下先过滤伪造源 IP。若网关未正确计算 `mac1`（`BLAKE2s-128(HASH("mac1----" || Spub_r), msg_alpha)`）与 `mac2`（以对端最新有效 Cookie 为键的 `BLAKE2s-128`）、未按 2 分钟周期轮换服务端随机密钥 `Rm` 导致旧 Cookie 永久有效，或在加密 `Cookie Reply` 时复用 24 字节随机 Nonce、未把原包 `mac1` 作为 AEAD 附加认证数据（AAD），攻击者可重放他人的 Cookie 发动 CPU 耗尽攻击或伪造 Cookie Reply 劫持客户端重试状态。为 C++17 网络安全宿主实现可嵌入、零外部依赖、`-Wall -Wextra -Wconversion -Werror` 编译通过的 WireGuard `MAC1`/`MAC2` 与 `Cookie Reply` 协议验证库（内置 BLAKE2s-256/128、HChaCha20 与 XChaCha20-Poly1305）。库严格实现：（1）按 WireGuard 白皮书 Section 5.4.4/5.4.7 精确计算与恒定时间校验 `mac1` 和 `mac2`，未过 `mac1` 的报文一律静默丢弃；（2）过载模式状态机：过载时对无合法 `mac2` 的报文不触发 DH 握手，而是基于当前 `Rm` 与客户端 `(src_ip, src_port)` 派生 16 字节 Cookie，生成唯一 24 字节 Nonce 并以 `HASH("cookie--" || Spub_r)` 为密钥、触发包 `mac1` 为 AAD，用 XChaCha20-Poly1305 封装 `Cookie Reply`；（3）支持 `Rm` 120 秒轮换（拒绝超过生命周期的过期 Cookie 与跨 IP 盗用 Cookie），客户端侧正确解密 `Cookie Reply`（校验 AAD 匹配最近发送的 `mac1`，拒绝伪造/错配响应）并在后续重发握手包中填充有效 `mac2`。附内置密码原语向量、过载无 `mac2` 拦截、跨 IP Cookie 盗用、`Rm` 过期与 AAD 篡改对抗测试。
