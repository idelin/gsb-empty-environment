# CABAC 内核（Go 标准库实现）

仿视频编码标准（H.264/AVC 风格）的上下文自适应二进制算术编码
（Context-Adaptive Binary Arithmetic Coding）内核，作用于结构化指令序列。

## 设计

- **算术编码内核**（`cabac.go`）：9 比特区间（初值 510）、`rangeTabLPS`
  四档量化区间细分表（H.264 Table 9-44）、比特级重归一化、
  outstanding 跟随比特进位传播、首比特吞并与 9 比特解码器初始化对齐。
- **概率状态机**（`cabac.go`）：每个上下文持有 64 级概率状态编号
  `pStateIdx` 与大概率符号 `valMPS`。命中 MPS 时状态号 +1（概率更尖锐），
  命中 LPS 时沿 `transIdxLPS` 回落，状态 0 处翻转 MPS——
  随历史命中持续微调概率状态，追踪符号流的局部统计特性。
- **上下文建模**（`instr.go`）：不同语法元素持有独立上下文组——
  操作码一元码首 bin 按"上一条指令类别"分 4 个上下文（榨取连续指令间的
  统计相关冗余），一元码第二/尾部 bin 与操作数各比特位置另有独立上下文。
- **指令语法**：8 操作码极简指令集，截断一元码二值化操作码 +
  4 比特定长操作数；`GenerateTrace` 用"热区/冷区"马尔可夫链生成
  高频 NOP 占主导的结构化指令序列。

## 运行

```sh
go test -v ./...     # 测试（含收敛与压缩率验收）
go run ./cmd/cabac-demo   # 运行样例
```

## 实测结果

`go run ./cmd/cabac-demo`（20 万条指令，NOP 占比 98.7%）：

```
收敛过程（有效编码位长）:
  第      1 -   1000 条: 0.236 比特/指令
  第   1001 -   2000 条: 0.204 比特/指令
  第   2001 -   5000 条: 0.207 比特/指令
  第   5001 -  10000 条: 0.213 比特/指令
  第  10001 -  20000 条: 0.185 比特/指令
  第  20001 -  50000 条: 0.182 比特/指令
  第  50001 - 100000 条: 0.178 比特/指令
  第 100001 - 200000 条: 0.186 比特/指令

整体压缩率对比:
  CABAC 上下文自适应            4616 字节  (0.185 比特/指令)
  单上下文自适应模型             10958 字节  (0.438 比特/指令)
  静态 0.5 概率模型             27621 字节  (1.105 比特/指令)
  定长编码                     175000 字节  (7.000 比特/指令)

CABAC 相对节省: 单上下文 57.9% | 静态模型 83.3% | 定长 97.4%

```

高频指令有效位长随编码推进收敛至约 0.2 比特；整体码率大幅领先
无上下文的静态模型（约为静态模型的 1/6、定长编码的 1/38）。
