# 源映射路径隐私隔离

线上错误页面需要展示源码位置，但源映射可能泄漏构建机绝对路径和未发布源文件。给Go符号服务实现可导入的映射裁剪包，输入有序生成位置到原位置映射及允许源码集合，保留原有区间查询语义，不可通过删除条目让前一许可映射延伸进入禁区。用随机查询对照原映射的允许部分，覆盖缺失段与多文件切换。

## 包：`netsec`（模块 `example.org/netsec/q0306`）

### 数据模型

- `GenPos{Line, Col}`：生成代码中的位置；`OrigPos{Source, Line, Col}`：原文件位置。
- `Entry{Gen, Orig}`：一条映射；`Orig == nil` 表示只占位、不含可发布原位置的边界条目。
- `NewMapping(entries)` 校验生成位置严格递增后返回不可变 `Mapping`。
- `Mapping.Lookup(pos)` 保持标准 source map 的区间（前驱）查询语义：返回 `pos` 处最后一个
  生成位置不大于 `pos` 的条目；`pos` 早于首条目时 `ok == false`；命中边界时 `Orig == nil`。

### 裁剪语义：`Mapping.Trim(sources)` / 包级函数 `Trim`

输入允许源码集合 `AllowedSources`，输出绝不引用任何未允许的源（如构建机绝对路径、
未发布文件），并完整保留区间查询语义：

- 允许条目与既有的 `nil` 边界原样保留；
- 每个**连续禁用段**（含位于映射开头的段）整体替换为一个位于该段首个生成位置的
  `nil` 边界条目；
- 因此直接删除首条禁用条目导致的“前一允许映射延伸覆盖禁区”问题被边界切断：禁区内任意
  位置的前驱查询都得到“无原位置”，允许区的查询结果与原映射逐点一致。

### 测试

- 确定性用例：开头/中间/结尾禁用段、缺失段（行跳跃 gap）下的前驱语义、边界位置精确性。
- 多文件切换：允许与禁用源交替出现，验证每个禁用段都被独立边界阻断。
- `TestTrimRandomDifferential`：固定种子随机生成有序映射与允许集合，用随机查询把裁剪结果
  与由原映射推导的 oracle 逐点对照（含越界前、越界后及 gap 查询），并断言输出不含禁用源、
  仍为合法严格有序映射。

运行：`go test ./...`（另含 `go vet`、`-race` 与覆盖率检查）。
