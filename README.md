# write-skew-guard：写倾斜检测与声明式约束断言器

将跨多行的业务约束（如"医生值班表至少有 1 人值班"）转化为**显式谓词断言**；
事务在**提交阶段**于"已提交状态 + 本事务写集"的叠加视图上重验谓词，
并结合**读集版本检测**识别并发交叉修改（写倾斜），违例事务被精准中止并安全回滚。

## 架构

```
src/store.ts    事务引擎：快照读、写集缓冲、串行化提交管线（互斥锁）
                ├─ 防线1 写倾斜检测：读集版本号校验，发现交叉修改即中止
                └─ 防线2 不变量重验：提交前在叠加视图上重跑相关谓词
src/roster.ts   领域层：医生值班表 + 声明式不变量注册
test/           Node.js 内置测试（node:test）
examples/       运行样例：A/B 医生并发请假攻防演示
```

关键设计：

- **声明式约束**：`store.defineInvariant({ name, tables, assert })`，
  谓词与业务流程解耦；仅当事务写集触及 `tables` 时才重验，精准且零浪费。
- **串行化提交**：所有提交经 Promise 链互斥执行，重验期间无其它提交插入，
  因此并发冲突中**先提交者生效、后提交者被中止**，不会出现双输或双赢。
- **双重检测**：读集版本校验（`WriteSkewError`，报告冲突键）+
  谓词重验（`InvariantViolationError`，报告不变量名），任一触发即回滚。

## 运行

要求 Node.js ≥ 22.6（22.x 需加 `--experimental-strip-types`；≥ 23.6 原生支持 TS）。

```bash
npm test    # 运行全部测试
npm run demo # 运行验收场景演示
```

## 验收场景（npm run demo 实际输出）

医生 A、B 同时值班；A 请假时看到 B 在岗，B 同时请假时看到 A 在岗——
两事务的快照各自合法，但若都提交，值班人数将从 2 跌为 0（写倾斜异常）：

```
初始在岗: A, B

--- A 与 B 并发申请请假 ---
  [A] 读到在岗名单: A, B
  [B] 读到在岗名单: A, B

--- 提交结果 ---
  A 请假事务: 提交成功
  B 请假事务: 已中止 -> 事务已中止：检测到写倾斜，读集被并发修改 -> duty_roster:A

最终在岗: B
✔ 不变量保持：值班表至少有 1 人值班
```

## 测试结果（npm test，6/6 通过）

```
✔ 验收场景：A、B 并发请假，系统精准中止其中一人，值班人数不降为 0
✔ 单事务违反不变量：最后一人请假被直接拒绝
✔ 写倾斜检测：中止错误中报告被并发修改的读集键
✔ 无冲突并发：A 请假与 C 新排班互不影响，双双提交
✔ 顺序执行：A 先请假成功后，B 的请假被不变量拦截
✔ 不变量仅在被触及表时重验：无关表写入不触发校验
ℹ tests 6  ℹ pass 6  ℹ fail 0
```
