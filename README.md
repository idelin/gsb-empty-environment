# Snowflake代理侧客户端枚举限额

Snowflake 类桥接的代理会收到匹配到的客户端地址，审查方可以大量运行代理并轮换代理标识来枚举客户端。给Go经纪服务写供代理轮询与客户端 offer 匹配调用的限额包，以下为本题规定：每个代理所在 IPv4 /24 或 IPv6 /48 前缀，在滚动一小时内最多收到 20 个不同客户端的 offer，无论代理标识如何更换；同一客户端对同一前缀重复只计一次；限制型 NAT 的客户端只能匹配到非限制型 NAT 的代理，代理自报的 NAT 类型与其最近一次探测结果冲突时以探测结果为准；每个 offer 最多交给一个代理；达到限额的前缀被跳过而不报错。用轮换标识的同前缀代理、重复客户端、NAT 谎报、一小时窗口边界验证。

## 实现

包 `netsec` 的核心类型是 `Limiter`，线程安全，可直接嵌入经纪服务：

- `Enqueue(Offer)`：客户端 offer 入队，按 `Offer.ID` 幂等去重。
- `Poll(Proxy)`：代理轮询，按 FIFO 扫描队列，返回首个同时满足 NAT 规则与前缀限额的 offer；无可用 offer 返回 `(nil, nil)`，达到限额的前缀被静默跳过。
- `RecordProbe(proxyID, nat, at)`：记录代理最近一次 NAT 探测结果；存在探测结果时覆盖自报 NAT，更新的探测覆盖更旧的。
- `Stats()` / `Sweep()`：前缀占用快照与过期前缀状态回收。

### 关键语义

- 前缀键由 `prefixOf` 计算：IPv4 取 /24，IPv6 取 /48；IPv4 映射的 IPv6 地址先 `Unmap`，避免同一主机产生两个键。
- 滚动窗口为半开区间 `(now-1h, now]`，每个“前缀 × 客户端”只保留最近一次投递时间；窗口内不同客户端数达到 20 后新客户端被跳过，已在窗口内的客户端重复投递不新增名额。
- NAT 匹配仅限制限制型客户端：限制型客户端只能交给有效 NAT 为非限制型的代理；有效 NAT 取“最近探测结果优先，其次自报值，均缺失按非限制型”。
- offer 一旦在 `Poll` 中交付即从队列移除并记入 `assigned`，保证最多交付一次。

## 测试

`limiter_test.go` 与 `limiter_window_test.go` 通过注入的假时钟覆盖：

- 同 /24、/48 前缀下轮换代理标识共享限额，第 21 个不同客户端被跳过且不报错；
- 同一客户端对同一前缀重复投递只占一个名额；
- 代理谎报 NAT（双向）被探测结果纠正，以及探测结果的新旧覆盖；
- 滚动一小时窗口在 59m59s 仍限额、超过一小时后名额释放并可补位；
- offer 幂等入队与最多一次交付、无效入参报错、并发轮询下恰好一次交付。
