电子合同与文档安全网关验签 PDF 文件时，若仅核对数字签名自身的 `ByteRange` 哈希有效而不深究签名之后追加的增量更新（Incremental Update），攻击者可利用 PDF Shadow Attack（隐藏/替换/覆盖可见页面对象、表单值或注解）在不破坏原签名的前提下篡改阅读器展示内容。为 Go 文档安全网关实现可导入、直接解析原始 PDF 二进制字节切片的增量更新结构与签名覆盖准入验证包，严禁依赖外部 PDF 解析库。组件从文件尾部反向定位所有 `%%EOF` 与 `startxref` 偏移，完整解析传统 `xref` 表与交叉引用链（`/Prev` 指针、拒绝循环引用与越界偏移）及多代对象修订快照，提取签名词典中的 `/ByteRange [off1 len1 off2 len2]` 与 `/Contents` 十六进制占位区间。安全准入判定严格检查：（1）`ByteRange` 首段必须从文件偏移 `0` 开始，两段之间恰好仅排除 `/Contents` 的 `<...>` 原始十六进制串（拒绝任何额外夹带字节或前后重叠），且签名覆盖范围必须完整包含其声明修订版的交叉引用与 `trailer`；（2）若签名末段之后仍存在增量更新字节，逐对象比对修订后与签名冻结修订版的差异——仅允许白名单内的合法非破坏性操作（如追加新签名字段、DSS 长期验证词典），任何对已有页面 `/Contents`、`/Resources`、`/MediaBox`、`/Catalog`、`/Pages` 树或已签表单字段值 `/V` 的重定义、对象号复用遮蔽或自由表删除均直接判定为 Shadow Attack 拒收。联合注入的哈希与验签回调，用字节级构造的合法双签 PDF 与隐藏内容替换、ByteRange 夹带、伪造 `/Prev` 循环攻击样本实测拦截。
