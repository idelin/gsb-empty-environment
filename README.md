# 会话新鲜值等价重命名

认证模型每次产生随机数都会扩大状态空间。写供Go符号验证宿主调用的规范化包，新鲜原子只按产生会话和相等关系区分，固定公开常量不能重命名；状态规范化同时重写消息队列、角色变量和攻击者知识。输出置换证书，用随机原子名称重命名验证规范状态相同，而跨会话混用保持可区分。

## 实现

规范化包位于 `canon/`（模块 `example.org/netsec/q0465/canon`），无第三方依赖。

- 术语：`Const`、`Fresh`、`Tuple`、`SymEnc`、`PKEEnc`、`FuncApp`，均实现 `Term`。
- 状态：`State{Queue, Roles, AttackerKnowledge}`，分别对应消息队列、角色变量与攻击者知识。
- 入口：`canon.Canonicalize(s) (*State, *Certificate)`，输入不被修改，返回深拷贝。

### 规范化规则

- 新鲜原子只由 `(产生会话, 会话内首次出现序号)` 标识，规范名为 `Fresh{Session, "c<n>"}`；
  具体 `UID` 仅用于区分同一运行内的不同原子，重命名随机数不影响规范状态。
- 同一会话内，按固定遍历顺序（消息队列 → 按 `(会话, 角色)` 与变量名排序的角色变量 →
  按结构键排序的攻击者知识）做先序遍历，第 1 个新原子为 `c0`，第 2 个为 `c1`，依此类推。
- 公开常量与函数名（`Const.Name`、`FuncApp.Func`）原样保留，永不重命名。
- 队列顺序有语义意义并被保留；角色状态与攻击者知识是集合，输出按确定性顺序排列，
  使相等状态可逐切片比较。
- 置换不跨越会话边界：不同会话即使序号相同（都是 `c0`）也因 `Session` 不同而可区分。

### 置换证书

`Certificate` 记录每条 `(原始 AtomRef) -> (规范 CanonicalAtom)` 映射：

- `IsBijection()` 校验源/目标唯一、不跨会话、每会话序号从 0 密集递增。
- `RenameState` / `RenameTerm` 应用置换，`ReverseRenameState` /
  `ReverseRenameTerm` 应用逆置换，可还原原状态的全部术语。
- `CanonicalName` 查询单个原子的规范名，供宿主做状态去重与等价判定。

### 验证

`go test ./...` 覆盖：随机原子名重命名后规范状态相同、常量与函数名不重命名、
跨会话混用保持可区分、共享原子在队列/角色/知识中得到同一规范名、证书双射与可逆、
输入不被修改以及布局无关性。
