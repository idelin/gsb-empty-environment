企业单点登录服务提供商（SP）在校验 IdP 返回的 SAML 2.0 XML Response/Assertion 时，若验签逻辑按 `Reference URI="#id"` 定位节点而业务层改用 XPath `//Assertion/Subject/NameID` 提取身份，或直接用常规 XML 解析器拼接文本节点忽略内嵌注释，攻击者可通过 XML 签名包装（XSW1–XSW8）塞入伪造的未签名断言，或在 `<NameID>admin<!-- -->@evil.com</NameID>` 中插入注释造成身份截断冒充管理员。为 Go 身份认证宿主实现可导入的 SAML 2.0 断言防包装与防注释截断安全验证包，严禁联网与严禁依赖外部 XML 签名库（基于 Go 标准库 `encoding/xml` 与 `crypto/rsa`/`crypto/ecdsa`/`crypto/sha256`）。组件严格解析原始 XML 字节流：（1）硬拒绝 DTD/`<!DOCTYPE`/`<!ENTITY`（阻断 XXE 与十亿笑弹）、重复 `ID` 属性、多 `<Assertion>` 或多 `<Signature>` 混淆，以及在 `<NameID>`/`<Issuer>`/`<Audience>` 等安全敏感元素内出现任何 XML 注释节点或处理指令；（2）实现 Exclusive XML Canonicalization（Exc-C14N）子集与 `Reference URI` 精确单目标绑定：强制校验被签名元素的完整树路径必须为合法根 `<Response>` 或其唯一直接子 `<Assertion>`，且业务提取的 `Issuer`/`NameID`/`Attributes` 只能直接读取自已验签通过的那唯一同一节点（彻底阻断 XSW1–XSW8，含签名移入 `<Extensions>` 或包装为兄弟/子节点变种）；（3）强制核验 `SignatureValue`、DigestValue、`NotBefore`/`NotOnOrAfter` 时间窗、`AudienceRestriction`、`Recipient` 及 `InResponseTo` 与单次断言 `ID` 防重放。附覆盖 XSW1–XSW8 变种、NameID 注释截断、XXE 注入、重复 ID 与合法签名的完整测试集。
