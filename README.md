# Exact Continuous-Time Poisson Process Simulation

Python 3.11, standard library only. Events are generated by **exact inversion
of the cumulative hazard** — never by discretising time into per-tick
Bernoulli trials.

## Files

- `poisson_process.py` — simulator module (streams, pieces, engine, analytic expectations)
- `test_poisson_process.py` — `unittest` suite (17 tests)
- `sample_run.py` — runnable demo (`python3.11 sample_run.py`)

## Features

- **Homogeneous process**: exponential inter-arrival times `Exp(1) / rate`.
- **Piecewise-constant intensity**: exact interval handling; zero-intensity
  (even very long) intervals are skipped and consume no random draws.
- **Piecewise-linear NHPP**: exact per-interval hazard integrals
  (trapezoids) with the numerically stable inverse
  `x = 2h / (λ0 + √(λ0² + 2·m·h))`, valid for `λ0 = 0`, `m → 0`, and `m < 0`.
- **Half-open intervals** `[t_start, t_end)`: a hazard budget exhausted
  exactly at a boundary emits the event once, at the start of the next
  interval — boundaries never duplicate events.
- **Block == whole**: each event consumes exactly one `Exp(1)` variate and
  event hazard targets are cumulative sums of the variates. The simulator
  carries the pending target and the generated hazard integral across calls,
  so block-wise and one-shot generation consume the identical Exp(1)
  sequence: event counts and draw counts are exactly equal, event times
  agree to ~1e-15 (floating-point order of equivalent hazard arithmetic).
- **Intensity version switch**: call the next `generate_*` from the switch
  time onward — existing events are never resampled.
- **Checkpoint / recovery**: `simulator.checkpoint()` /
  `PoissonSimulator.recover(cp)` snapshot and restore the RNG state plus
  hazard bookkeeping; recovery replays the tail exactly.
- **Caller-injected random source**: `PoissonSimulator(stream=...)` accepts
  any object with `next() -> Exp(1)`; the default `ExponentialStream(seed)`
  records `seed` and `draws`, and every call logs a `SampleRecord`
  (seed, sample size, draws used) into `simulator.history`.
- **Replayable**: same seed ⇒ identical event times.
- **Validation**: negative intensity raises `ValueError` everywhere.

## Exact vs empirical

- `[EXACT]` analytic expected counts are exact integrals of the intensity:
  `expected_count_homogeneous`, `expected_count_piecewise_constant`,
  `expected_count_piecewise_linear`.
- `[EMPIRICAL]` simulation-based means are estimates; tests compare them
  against the analytic references at ~5 standard errors with fixed seeds.

## Usage sketch

```python
from poisson_process import PoissonSimulator, expected_count_piecewise_linear

sim = PoissonSimulator(seed=42)                 # caller-injected random source
events = sim.generate_piecewise_linear(
    [(0.0, 0.0), (3.0, 3.0), (6.0, 1.0)],       # (t, lambda) knots
    t_start=0.0, t_end=6.0,
)
cp = sim.checkpoint()                           # snapshot for recovery
more = sim.generate_homogeneous(rate=2.0, t_start=6.0, t_end=10.0)
assert sim.history[-1].seed == 42               # seed + sample size recorded
reference = expected_count_piecewise_linear([(0.0, 0.0), (3.0, 3.0), (6.0, 1.0)])
```
