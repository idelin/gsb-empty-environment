# orset — 离线集合复制库（Observed-Remove Set）

Go 实现的离线可复制集合（OR-Set，带墓碑），支持并发写、合并与安全的历史压缩。

## 语义

- **唯一标签**：每次 `Add` 为元素分配全局唯一标签 `Dot{Replica, Seq}`（副本 ID + 单调序号）。
- **观察删除**：`Remove` 只为本副本已观察到的标签打墓碑；其他副本上并发产生的新标签不受影响，因此"删除后并发重加"不会被吞掉。
- **合并**：`Merge`/`Sync` 满足交换律、结合律、幂等（状态型 CRDT）；活跃标签 = 添加标签 − 墓碑标签。
- **安全压缩**：`GC` 仅当**所有已知副本**的版本向量都覆盖了产生墓碑的删除操作时，才丢弃该删除记录。确认信息通过矩阵时钟（`acks`）随合并 gossip 传播，可经中间副本传递。离线副本未确认前，墓碑一律保留——否则离线副本重新上线时会用旧状态把已删元素"复活"。

## API

```go
a := orset.New("A", "A", "B", "C") // id + 集群成员（GC 安全边界）
a.Add("x")                          // 返回唯一标签 Dot
a.Remove("x")                       // 只移除已观察到的标签
a.Contains("x"); a.Elements(); a.LiveTags("x")
orset.Sync(a, b)                    // 双向反熵同步（或单向 a.Merge(b)）
a.GC()                              // 返回丢弃的墓碑数；未全员确认时返回 0
a.TombstoneCount()
```

## 验证

```sh
go test ./...              # 单元测试：并发重加、观察删除、合并性质、GC 安全
./scripts/partition-test.sh # 三副本分区场景脚本
```

分区脚本场景：A/B/C 全连接 → A 添加 `x` 并同步 → C 离线分区 → A 删除 `x` 同时 B 并发重加 → A↔B 同步（重加存活）→ C 离线期间 GC 不得丢弃墓碑 → 分区恢复后三方收敛于 `x` 存在（存活标签为 B 的重加标签）→ 全员确认后 GC 压缩墓碑 → 再同步无复活。
