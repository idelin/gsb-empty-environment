CDN 共享边缘缓存严格遵循 RFC 9111 时，稍有疏忽就会返回错误租户内容或漏失效脏数据：同一 URL 下带 `Vary` 头的多个变体必须按规范化请求头字段（折叠多余空白、拼接多行同名头、字段名不区分大小写）精确选择，且遇到 `Vary: *` 永远不可复用；共享缓存计算新鲜度时 `s-maxage` 优先于 `max-age` 再优先于 `Expires` 再退回启发式新鲜度，且 `Age` 须依据 `Date`、`response_time`、`request_time` 与原 `Age` 精确补偿网络往返延迟；条件请求 `If-None-Match` 必须用弱比较（`W/"abc"` 匹配 `"abc"`），而 `If-Match` 与 `If-Range` 必须用强比较（弱 ETag 永远不匹配！）；收到非安全方法（`POST`/`PUT`/`DELETE`）的 2xx/3xx 响应后，不仅要失效请求目标 URI，还必须按 RFC 9111 §4.4 失效同源的 `Location` 与 `Content-Location` 关联缓存项！为边缘代理交付可导入的 TypeScript RFC 9111 共享缓存决策与状态引擎。规则：1）支持存储准入判定（检查状态码默认可缓存性、`no-store`、`private` 在共享缓存禁存、`Authorization` 头仅在显式含 `public`/`s-maxage`/`must-revalidate` 时允许共享缓存！）；2）实现精确 `Age` 与新鲜度计算，区分 `fresh`、`stale`（支持 `stale-while-revalidate` 异步后台回源窗口与 `stale-if-error` 5xx 降级窗口，但在 `must-revalidate`/`proxy-revalidate`/`s-maxage` 与请求 `max-stale`/`min-fresh`/`max-age=0`/`no-cache` 交错时严格按优先级裁决！）；3）完整实现 `Vary` 二级键匹配、`Vary: *` 禁复用、304 Not Modified 回源合并响应头（更新 `Cache-Control`/`ETag`/`Expires`/`Date` 而保留原实体表示头与状态码）以及 `If-None-Match`/`If-Modified-Since`/`If-Match` 强弱校验；4）实现非安全方法成功响应后的同源目标 URI + `Location` + `Content-Location` 级联失效（跨源 URL 绝不可触发失效！）。验收覆盖 `s-maxage` 覆盖 `max-age`、`Authorization` 共享缓存禁令、`Vary: *` 与多头折叠匹配、弱/强 ETag 比对差异、304 合并保留原实体头、`stale-while-revalidate` 与 `must-revalidate` 冲突及同源/跨源写失效边界。
