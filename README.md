AMQP 0-9-1 代理将 Direct、Fanout、Topic（支持点分通配符 `*` 匹配恰好一词、`#` 匹配零到多词）和 Headers（支持 `x-match=all/any` 且须忽略所有 `x-` 前缀头！）交换机级联起来，再叠加 Alternate Exchange（无法路由时的兜底交换机）与 Dead-Letter Exchange（死信重试路由）；若同一队列通过多条绑定同时命中一条消息却未按队列去重、或死信在两个队列间因 TTL 过期形成死循环，代理就会产生重复投递风暴或无限死信震荡。为消息代理核心交付可导入的 Go AMQP 0-9-1 路由与死信流转包。实现四类交换机及 Exchange-to-Exchange 绑定（支持多跳 E2E 级联并防范 E2E 绑定环路导致无限递归！）：Topic 路由树正确处理空路由键匹配 `#` 不匹配 `*`、连续 `#.#` 等价归一、多段通配回溯；Headers 交换机忽略键名以 `x-` 开头的头与绑定参数，精确执行 `all`/`any` 值相等匹配；单次发布对命中的同一目标队列严格去重只投递一次，若最终零队列命中且配置了 `alternate-exchange` 则自动转投兜底交换机（同样防环！）。实现死信投递 `DeadLetter(msg, queue, reason)`（reason 分 `rejected`、`expired`、`maxlen`）：按 RabbitMQ/AMQP 规范更新 `x-death` 历史栈（合并同 `(queue, reason, exchange, routing-keys)` 条目计数递增并前置到栈顶，同时维护 `x-first-death-*` 字段），并严格执行死信环路检测——当一条消息的整个死亡历史仅由自动原因（`expired`/`maxlen`）构成且即将重新进入历史中已出现过的同一队列时直接丢弃防无限死循环，而若环路中存在人为 `rejected` 原因则按规范允许继续投递！验收覆盖空键匹配 `#` 与复杂 `*`/`#` 回溯、Headers 忽略 `x-` 头、多绑定同队列去重、E2E 环路与 Alternate Exchange 兜底，以及纯 TTL 死信环拦截 vs 含 `rejected` 环放行。
