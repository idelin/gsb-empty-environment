# 流式风控规则引擎（滑动窗口 + 规则版本热切换）

TypeScript 实现的流式风控决策组件，零第三方依赖，使用 Node.js 内置测试运行器验证。

## 能力

- **复合规则条件**：单笔交易特征（类型 / 金额 / 币种）AND 滑动窗口历史聚合（频次、累计金额），
  如「10 分钟内转账超 3 次且累计金额超 1 万」。
- **规则版本热切换**：`updateRules()` 后新请求立即按新版本裁定；
  已通过 `beginSession()` 锁定的长事务会话全程按旧版本裁定，平稳过渡，会话结束（`endSession()`）后回到当前版本。
- **审计日志**：每次裁决记录实际使用的规则版本号、动作与命中规则。

## 环境要求

Node.js >= 23.6（原生 TypeScript 类型擦除，无需编译、无需安装依赖）。

## 运行

```bash
npm test        # node --test "test/*.test.ts"
npm run demo    # 重放验收场景
```

## 验收场景（src/demo.ts）

- t=90：长事务会话 `S-LONG` 开始，锁定规则 `v1`（10 分钟 >3 次且 >10000 才拦截）。
- t=100：规则库热切换为更严格的 `v2`（>2 次且 >5000 即拦截）。
- t=101：会话内第 4 笔（窗口累计 9500）按 `v1` **放行**；另一账户新请求 3 笔累计 6000 按 `v2` **拦截**。
- 审计日志中两者分别标记 `version=v1` / `version=v2`。

## 结构

- `src/types.ts` — 交易、规则、裁决、审计类型定义
- `src/engine.ts` — 引擎：滑动窗口聚合、规则匹配、版本锁定与热切换
- `src/rules.ts` — 规则库 v1（宽松）/ v2（严格）
- `src/audit.ts` — 追加式审计日志
- `src/demo.ts` — 验收场景运行样例
- `test/engine.test.ts` — 9 个 node:test 用例（窗口、隔离、热切换、会话过渡、验收边界、审计）

## 设计说明

- 时间采用事件携带的逻辑时间戳（秒），测试可确定性重放；生产环境由上游事件时间驱动。
- 窗口聚合包含当前这笔交易；被拦截的尝试同样计入历史频次（风控惯例）。
- 历史按账户隔离存储，查询时按窗口过滤，并裁剪 1 小时前的记录防止无限增长。
