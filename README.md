单点登录服务提供方（SP）在验证 SAML 2.0 断言时，若 XML 解析器接受 DTD/外部实体、忽略独占规范化（Exc-C14N）命名空间继承，或验签定位的 `ID` 节点与业务层读取的 `<Assertion>` 节点不一致，攻击者可通过 XML 签名包装（XSW1–XSW8）或注释截断（`admin<!-- -->.evil.com`）伪造任意管理员身份。为 TypeScript 身份宿主实现可导入、零第三方 XML/签名依赖（仅用 `node:crypto`）的 SAML 2.0 原始 XML 解析、Exc-C14N 规范化与防 XSW 验签引擎。解析器从原始 UTF-8 字节构建严格 DOM：硬拒绝 `<!DOCTYPE`、`<!ENTITY`、处理指令欺骗、重复属性名、非法命名空间重绑定与全文档内重复 `ID` 属性；完整实现 Exclusive XML Canonicalization 1.0（含属性按命名空间 URI+本地名字典序排序、空白与字符实体规范转义、`InclusiveNamespaces PrefixList` 可见命名空间精确输出、以及规范去注释与保留注释两种模式，防止注释拼接拆分 `NameID` 文本节点）。验签与语义提取严格耦合：要求 `<Signature>` 仅含单一 `<Reference URI="#...">`，其 Transforms 仅允许 `enveloped-signature` 与 `xml-exc-c14n`，用真实 RSA-SHA256 校验 `<SignedInfo>` 与 `<DigestValue>` 后，业务主体（`Issuer`/`Subject`/`NameID`/`Conditions`/`AudienceRestriction`/`NotBefore`/`NotOnOrAfter`/`AttributeStatement`）必须直接且唯一地从该已验签 DOM 子树提取，严禁再次按标签名全局搜索未签名的克隆或包装节点。内置覆盖 XSW1–XSW8、注释截断 `NameID`、命名空间遮蔽与双 `ID` 冲突的攻击测试集，验证全部伪造响应均被拒收且合法签名断言正常通过。
