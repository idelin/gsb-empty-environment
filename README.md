零信任服务网格在跨集群验证工作负载的 SPIFFE X.509-SVID 与 JWT-SVID 时，若将所有联邦信任域（Trust Domain）的根证书混入同一全局根池而不按 SVID URI 中的信任域严格隔离验签，或未拒绝含相对路径段（`..`/`.`）、百分号编码、query/fragment 或多 URI SAN 的畸形 SPIFFE ID，被攻陷的外部合作方信任域 CA 可任意签发本域核心支付服务的合法 SVID 实现横向冒充。为 Go 零信任认证宿主实现可导入的 SPIFFE X.509-SVID 与 JWT-SVID 联邦验证及信任包轮换管理包，严禁联网（仅用标准库 `crypto/x509`/`crypto/ecdsa`/`crypto/rsa`/`crypto/sha256`）。组件严格实现：（1）SPIFFE ID 语法与规范化硬校验：必须为 `spiffe://<trust-domain>/<path>`，限制总长 ≤2048 字节、信任域仅含小写字母/数字/`-`/`.`/`_`（≤255 字节），路径严禁空段、`/.`、`/..`、尾部 `/`、userinfo、端口、query（`?`）、fragment（`#`）与非合法字符；（2）X.509-SVID 严格验签：叶子证书必须且仅含 1 个 URI SAN、严禁 `IsCA=true`、KeyUsage 须含 `DigitalSignature` 且不得含 `CertSign`/`CRLSign`，并且必须严格使用该 SPIFFE ID 所属信任域对应的独立 Trust Bundle 根池验链（彻底阻断跨信任域签发冒充）；（3）JWT-SVID 验证：拒绝含多个 `aud` 均不匹配本地受众、`sub` 非合法 SPIFFE ID、缺失 `exp` 或算法混淆的令牌，仅使用 `sub` 所属信任域 Bundle 中的对应 `kid` 公钥验签，并支持联邦 Bundle 原子热轮换与吊销旧密钥。附跨信任域 CA 越权签发、畸形路径穿越 SPIFFE ID、多 URI SAN 混淆与 Bundle 轮换测试。
