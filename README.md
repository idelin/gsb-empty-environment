高安全 VPN 网关在实现 IKEv2（RFC 7296）及抗量子预共享密钥扩展（RFC 8784 PPK）与加密消息分片（RFC 7383 `SKF`）时，若在 `IKE_AUTH` 阶段放任未验证的畸形/超大 `SKF` 分片耗尽重组内存、接受重复或冲突的 `Fragment Number` 覆盖已收分片，或在 PPK 强制模式下允许中间人剥离 `USE_PPK` 通知静默降级为纯经典 DH 密钥，攻击者可实施分片内存耗尽 DoS 或“先截获后量子解密”降级攻击。为 Go VPN 安全宿主实现可导入的 IKEv2 RFC 8784 PPK 混合派生与 RFC 7383 分片安全重组状态机包，严禁联网（仅用标准库 `crypto/hmac`/`crypto/sha256`/`crypto/aes`/`crypto/cipher`）。组件严格实现：（1）RFC 7383 分片重组与加密认证隔离：按 `(SPIi, SPIr, MessageID)` 维护有界重组槽，硬拒绝 `FragmentNumber==0`、`FragmentNumber > TotalFragments`、`TotalFragments` 超过策略上限、同消息 `TotalFragments` 前后矛盾及重复分片覆盖；强制先对每个 `SKF` 分片执行 AEAD 认证解密通过后才计入重组，认证失败直接丢弃且不释放/污染已有合法分片，并严格控制半开重组总内存上限与超时回收；（2）RFC 8784 抗量子密钥混合：当策略要求 `PPK_REQUIRED` 时硬拒绝缺失 `USE_PPK` 或 `PPK_IDENTITY` 的对端；按规范用 `SKEYSEED` 派生 `SK_d`/`SK_pi`/`SK_pr`，并用 `prf+(PPK, SK_d/SK_pi/SK_pr)` 精确二次混合生成 `SK_d'`/`SK_pi'`/`SK_pr'`，验证 `AUTH` 载荷绑定混合后的 `SK_pi'`/`SK_pr'`（非原经典密钥）。附伪造 `SKF` 覆盖攻击、`TotalFragments` 矛盾、PPK 剥离降级拦截与 RFC 8784 混合派生向量测试。
