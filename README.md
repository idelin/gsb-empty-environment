分布式块归档服务端同时为多文件提供共享只读块缓存并支持稀疏零洞扩展时，若缓存键遗漏文件身份或混淆零洞与实块，将导致跨文件数据投毒，给 Go 块服务实现可导入的多文件读取证明与隔离缓存组件。文件按 4096 字节分块，叶子哈希绑定域标记、文件 ID、版本号、块索引、有效长度与数据，并明确区分经过签名的稀疏零洞区间（sparse zero-hole extent）与全零实数据块；非二次幂区间按最大小于长度的二次幂切分。清单签名绑定文件身份、长度、严格单调版本号（`Version == 0` 在所有入口包括首条清单均硬拒绝）、前版根与本版根；若发现同一 `(FileID, Version)` 存在两份不同根的有效签名清单（模棱两可分叉），立即隔离该文件并拒绝新挂载，同时保证已持有合法旧版句柄的读操作继续受旧根保护。共享块缓存键必须同时绑定 `FileID`、`Version` 与 `Root`，跨文件或跨版本即使内容哈希相同也不得绕过各自证明校验。提供全量建树参考验证分叉隔离、稀疏零洞、版本 0 拒收与跨文件缓存隔离。
