宿主启动低权限子进程时要从自己的句柄表交接一组能力，若两个描述符引用同一打开对象，按描述符逐个核对容易遗漏可写别名。给 Go 启动宿主写可导入的交接规划包，输入是抽象句柄表，每项含槽号、不可回绕的槽代次、打开对象身份、可读写权限及执行时自动关闭标志。子进程声明若干角色，每个角色列出允许的对象身份集合、所需权限和是否允许与指定角色共享打开对象；禁止交接任何含额外权限的句柄。计算满足全部角色、使用源对象数量最少的分配方案，并列取角色顺序下字典序最小的槽号序列。重排到固定目标槽时允许循环，宿主最多提供一个临时槽；规划期间不能覆盖后续还需读取的源。验证器逐步模拟这份计划，要求临时槽在跨权限边界前关闭，未选句柄均不得继承。最后交接前由宿主原子比较所有相关槽代次和对象身份，任何不一致即撤销整次交接。用独立穷举核验小表最优解，覆盖局部最小匹配导致整体无解、同对象额外写权限、三槽环、并发换槽及安装中途失败。

## handover 包

可导入包路径：`prescreen.local/ddd-10451-v2/handover`

- `types.go`：`Handle`、`Role`、`Perm`、`Plan`、`Op` 等抽象模型。
- `planner.go`：`BuildPlan` 用带回溯的搜索求最少源对象数、角色顺序下字典序
  最小槽号序列；精确权限匹配拦截可写别名，共享需角色双方互相许可。
- `rearrange.go`：把分配结果重排到固定目标槽。含空槽的连通分量走 `Move`
  链，无空槽分量走环；二元环合并为 `ParSwap` 并发交换，更长的环只用宿主
  提供的唯一临时槽旋转，且每次写入目的地均为空，不覆盖待读源。
- `validator.go`：`Plan.Validate` 逐步模拟，强制临时槽在权限屏障处为空、
  并发交换槽对互不相交、未选句柄最终全部 `cloexec`。
- `executor.go` / `memtable.go`：`VerifyExpectations` 在安装前原子比较相关
  槽的代次与对象身份；`Commit`/`CommitWithFault` 执行计划并在任一步失败时
  按快照整体回滚。`MemTable` 是带锁的内存参考实现。

### 测试

- `brute_test.go` 是独立于规划器的全枚举参考求解器；`TestFuzzAgainstBruteForce`
  对 300 个随机小表交叉核验最优对象数、字典序槽序列与可执行性。
- 指定场景：局部最小匹配陷阱、同对象额外写权限、三槽环、并发换槽、
  安装中途失败与代次/身份篡改，另含混合权限环的屏障测试与输入校验。
- 运行：`go test ./...`，竞态检测：`go test -race ./...`。
