# 合单拣货规划器 (batch-picking-planner)

在小型通道图上求解**总行走距离 + 拆单成本**最小的合单拣货方案（精确解，最多 12 个拣货项）。

## 模型

- 多个订单的拣货行（订单 × 货位 × 数量）可合并到同一车次，同货位不同订单的数量分别归属。
- 每趟车容量有限（按件数），从发货点出发并返回。
- 一个订单若被拆到 t 趟，产生 `(t-1) × splitCost` 的拆单成本。
- 目标：最小化 `Σ 每趟最短巡回路线长度 + Σ 订单拆单成本`。

## 算法（精确 DP）

1. **Floyd-Warshall**：通道图全源最短路（`src/graph.ts`）。
2. **Held-Karp**：对每个货位子集求发货点出发的最优巡回成本与访问顺序（`src/planner.ts`）。
3. **集合划分 DP**：对 ≤12 个拣货项枚举划分；拆单成本按"每趟计费不同订单数，最后减去常数 `splitCost × 订单数`"分解，恰好等于 `Σ (t-1)×splitCost`。

复杂度约 `O(3^n + 2^m·m²)`（n 为拣货项数，m 为货位数），n=12 时秒级内完成。

## 运行

需要 Node ≥ 22.6（原生 TypeScript 类型擦除），或先用 `tsc` 编译。

```bash
node src/main.ts                 # 内置演示场景
node src/main.ts scenario.json   # 自定义场景（结构见 src/types.ts 的 Scenario）
node scripts/verify.ts           # 与暴力枚举对拍 300 个随机案例
npm run typecheck                # 需要本地安装 typescript
```

## 输出

每趟车次给出：载荷、行走距离、完整路线节点序列、每个停靠货位上**按订单区分的拣货数量**；
末尾汇总每个订单的分趟情况与总成本分解（行走 + 拆单）。
