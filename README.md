# vrec — 单写多读的版本化记录存储（Go，仅标准库）

一个用 Go 标准库从零实现的 **单写多读（single-writer / multi-reader）版本化
KV 记录存储**，带固定版本读事务、墓碑删除、以最老活跃读版本为界的垃圾回收，
以及可注入的故障点。所有数据文件都放在调用方 `Open(dir, ...)` 指定的目录内。

## 语义与不变量

- **单调版本号**：每次 `Txn.Commit` 产生一个全局新版本；同一事务对多个键的修改
  属于同一版本，全部成功或全部中止。
- **读事务固定版本（快照隔离）**：`BeginReader` 时记录当时的已提交版本 `snap`，
  此后只看到 `版本 <= snap` 的节点。**新写入对老读者不可见；删除时老读者仍读到
  被删除之前的旧值。**
- **删除即墓碑**：`Delete` 追加一个墓碑节点，从不就地改写历史。
- **单写多读**：同一时刻只允许一个活跃写事务（第二个 `Begin` 返回
  `ErrTxnReentrant`）；读事务可任意多个。
- **长读不阻塞新写，但限制回收**：读事务只在单次 `Get` 期间短暂持锁，从不跨
  调用持锁，因此写入不会被长读卡住；但每个读事务登记其快照版本，GC 的回收
  水位 = 所有活跃读/写事务中最老的版本，水位之下可能被老读者读到的链前缀不释放。
- **关闭旧读者后才可释放链前缀**：老读者 `Close` 后，下一次 `RunGC` 才会推进
  水位并释放它保护的前缀节点。

## GC 水位规则

设水位 `W = min(所有活跃读事务/写事务登记的版本)`；没有活跃事务时 `W = head`。

对每个键的版本链（升序），GC 保留：

- 存在活跃事务时：所有 `版本 > W` 的节点，加上 `版本 <= W` 的**最新一个边界
  节点**（它正好是老读者在该键上能看到的那一版）；更早的前缀释放；
- 无活跃事务时：只保留链顶；链顶是墓碑时整条键丢弃（墓碑无需再遮蔽历史）。

压缩采用「写临时文件并 `fsync` → 原子 `rename` → `fsync` 目录」，崩溃不会留下
无法重放的日志。

## 目录与持久化格式

调用方指定目录内只有两个可能的名字：

| 文件 | 作用 |
| --- | --- |
| `wal.log` | 只追加日志（提交帧 + 压缩边界帧） |
| `wal.log.compact.tmp` | GC 临时文件；崩溃残留会在下次 `Open` 时清除 |

帧为长度自描述 + CRC32-C（小端）：魔数、标志（墓碑/压缩）、键长、值长、版本、
CRC、键、值。重放时任何短读、坏魔数或坏 CRC 都视为日志尾部（断电只能损坏尾部），
`Open` 会把文件截断到最后一个完整帧之后。

## 进程崩溃恢复与断电保证的边界

**保证的部分**

- 一次提交在所有帧 `write` 并 `fsync` 成功**之后**才算提交；此后操作系统崩溃或
  断电，重启 `Open` 重放 WAL 会完整恢复该事务（见 `TestFailpointTxnSyncSimulatedCrash`）。
- 提交点之前（尚未落盘）发生进程死亡：已提交状态与 WAL 都不受影响，事务干净消失。
- 帧写入/同步失败或日志尾部撕裂：重启时按 CRC 截断尾部，已确认的前缀完整
  （见 `TestTornTailIsTruncatedOnReopen`）。
- GC 各阶段崩溃：`rename` 前死亡 → 仍是旧 WAL，临时文件被清理；`rename` 后、
  目录 `fsync` 前死亡 → 旧或新 WAL 都能重放出一致状态，墓碑语义不丢。

**明确不保证（边界）**

- **不提供跨进程并发打开**：一个目录假定单进程使用，没有文件锁 / 多写者协调。
- **不规避存储介质谎报刷盘**：耐久性依赖操作系统与硬件对 `fsync` 的真实语义；
  在磁盘自身回写缓存丢失等场景下无法额外保证。
- **目录项耐久性依赖目录 `fsync`**：GC 的 rename 之后若目录 fsync 未完成且介质
  掉电，理论上可能回退到旧目录项；代码已确保“旧或新”两种日志各自自洽。
- **注入的 `ErrSimCrash` 只模拟语义**（实例立即进入不可用的 `faulted` 状态），
  并不真的杀死进程；真实进程死亡由重放路径覆盖。

## 故障注入点

`Options.FailHook func(FailContext) error`，返回非 nil 即注入故障，返回
`vrec.ErrSimCrash` 表示“进程立即消失”：

- `StageTxnWrite`：提交帧落盘前（可干净中止，存储保持健康）
- `StageTxnSync`：帧已 `fsync`、内存发布前（重启后事务仍在）
- `StageGCWrite`：压缩临时文件写入前（原 WAL 完好）
- `StageGCRename`：临时文件已 fsync、原子改名前
- `StageGCDirSync`：已改名、目录 fsync 前（新旧日志都可能生效）

## 错误约定（显式、可 `errors.Is`）

- `ErrTxnClosed`：事务/读视图结束后再用，或重复 `Commit/Rollback/Close`。
- `ErrTxnReentrant`：单写者已活跃时再次 `Begin`；同一事务实例被并发重入。
- `ErrNotFound`：键不存在或快照版本上为墓碑。
- `ErrFaulted`：此前发生不可判定故障，实例拒绝继续服务，需重新 `Open`。
- `ErrClosed`：数据库重复关闭。`ErrEmptyKey`：空键。

## 快速开始

```bash
go test -race -count=1 ./...
go run ./cmd/vrec-demo [可选数据目录]
```

## 运行样例（实际输出）

```
数据目录: .../vrec-demo

== 1) 提交三个版本；读者固定在 v2 ==
老读者快照版本 = 2
读者(v2) 读 alice = "A2"
最新读者(v3) 读 alice = "A3"
alice 的版本链: v1="A1" v2="A2" v3="A3"

读者(v2) 读 alice = "A2"
新读者读 alice -> ErrNotFound（墓碑）
alice 的版本链: v1="A1" v2="A2" v3="A3" v4=tomb

== 3) 老读者打开时执行 GC：只能回收水位之下的前缀，v2 边界保留 ==

读者(v2) 读 alice = "A2"

== 4) 关闭老读者后再次 GC：链前缀全部释放 ==
GC 水位=4 保留节点=0 释放节点=3 WAL 103->21 字节
alice 的版本链: <空>

== 5) 长读不阻塞写：读者长期打开，期间连续写入 ==

```

## 测试结果

`go test -race -count=1 ./...` 全部通过（18 个测试，含并发竞态检测）：

快照隔离与墓碑、GC 水位与链前缀释放（含部分前缀、整键墓碑丢弃）、重复关闭/
重入/单写者拒绝、长读不阻塞写、重开持久性、压缩 WAL 重放、各注入点崩溃恢复、
WAL 撕裂截断等。详细用例见 `vrec/*_test.go`。

## 代码结构

- `vrec/db.go`：DB、快照登记、注入点、打开与重放调度
- `vrec/wal.go`：WAL 帧编码、CRC、重放与尾部判定
- `vrec/reader.go`：固定版本读事务
- `vrec/txn.go`：写事务（单写者、读己写、提交/回滚）
- `vrec/gc.go`：以最老活跃读版本为界的回收与崩溃安全的压缩
- `vrec/misc.go`：Close、Stats、History、View 等辅助
- `cmd/vrec-demo/main.go`：可运行样例
