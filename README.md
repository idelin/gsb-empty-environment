广播服务把群组密钥封装给树上的设备。每把封装能力覆盖一个子树减去至多一个后代子树，每台设备只有其已认证代次的能力。给 TypeScript 发送宿主写可导入的头部规划和验收组件：输入为稀疏的48位设备编号空间、合法订阅区间、撤销区间、轮换前后可用能力及签名目录根。头部必须恰好覆盖合法设备，不得让任一撤销设备用仍保留的旧能力取得新代密钥；每个被覆盖的区间都须由同一租户、同一发布代次的完整证明支持。若一份头部同时照顾旧客户端格式和新格式，实际目标设备允许的格式也是覆盖条件，不能先合并设备集合再补格式。最多18个候选封装能力，选择总编码字节最小的组合，并列取稳定编号序列最小者；使用端依独立函数从签名目录验证精确覆盖、无越权和成本。小编号空间按设备逐一对照，另核验超大空洞、子树差集相互重叠和一个撤销设备只持旧代能力。密钥由注入的封装回调处理，不接触真实设备。
