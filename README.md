配置控制器现在要判断的是：某条已经确认的日志，在一串交接后会不会被一次成功读取漏掉，而不只是相邻配置的多数派有没有交集。给复制层实现 Go 安全性判定包。输入旧写、每步交接读与写、最终读各自的可用仲裁（直接列成副本位掩码族）。入口只有旧写仲裁成员有该日志。每步环境先选择本步故障掩码：其成员本步离线且丢失数据，下一步可恢复在线但内容不会复原；故障费用按本步失去的节点及相邻两步反复掉线的机架计，具体对每个允许的相邻故障掩码对给出非负费用。此后任选与离线节点不交的本步读、写仲裁；写仲裁所有成员的日志位被覆盖为读仲裁中是否至少一份仍存在，未参与节点保留内容。旧写和最终读没有额外故障。对一个可成功完成的最终读，求读不到日志的最低整条故障费用和近因证书，若所有成功路径都能读到则报告安全；还须区分根本不存在可完成的读。另对给定费用上限求每一步后所有可达持有者集合中按包含极小的集合，并各附证书。至多 15 节点、60 步，不允许枚举完整历史，不能只保留每配置成本最小的持有者集合或忽略上一故障掩码。证书应由独立回放器逐步检查仲裁资格、离线/持有者两种状态以及费用。用短场景全历史枚举比较，覆盖读不到旧内容的合法交接主动覆盖最后一份、相邻每对均存在相交仲裁但整链仍可能丢失、以及故障后恢复在线不等于恢复日志。
