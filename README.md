# Kerberos式重放缓存分区

服务票据可能在时钟回拨和多进程重启后被重复接受。为Go认证宿主写可导入的重放拒绝组件，调用方先完成密码学验证，再提交客户端主体、服务主体、票据摘要、客户端时间及微秒序号；窗口内同键只成功一次，接受记录先持久化再授权。持久时钟下界不得回退，过远未来请求拒绝而不推进下界。用注入存储在每个写入点断电，核对并发进程的唯一接受结果。

## 实现

可导入包：`example.org/netsec/uid1262/replay`

- `replay.Cache.Accept` 在调用方完成密码学验证之后使用，入参为 `replay.Key`（客户端主体、服务主体、票据摘要、客户端时间、微秒序号）。
- 接受顺序：未来时间预检（不触存储）→ 跨进程锁 → 读日志 → 下界/重放判定 → 追加接受记录并 fsync → 追加单调时钟下界并 fsync → 授权返回。
- 时钟下界取滚动窗口下界与持久水印的较大值，主机时钟回拨不会使其降低；过远未来请求在任何写入之前返回 `ErrFuture`。
- `replay.FileStorage` 基于 `flock` 协调多进程，帧带 CRC-32，每次追加后 `fsync`；撕裂尾部在下一次加锁时自动截断修复。
- `replay.FaultyStorage` 与 `FileConfig.Hook` 可在每个写入点注入“写前断电 / 写后断电 / 半写断电”。

## 验证

- `go test ./...`：功能、时钟回拨、重启、撕裂尾部修复、断电注入（每个写入点 × 三种故障）以及真实子进程并发（re-exec 测试二进制，共享 `flock` 日志）。
- `go test ./... -race`：竞态检测。
- 并发进程场景断言同一票据键恰好一次 `ACCEPTED`、其余全部 `REPLAY`，且持久日志中接受记录与单调水印数量一致、水印永不回退。
