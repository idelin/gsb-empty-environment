# SMB预认证哈希在重连时被清零

SMB 3.1.1客户端在多通道和会话重连时若重置preauth integrity hash，攻击者可在第二条连接降级dialect或篡改协商上下文。请实现供C++20 SMB客户端调用的可导入协商状态组件，按每条TCP连接从全零值开始顺序哈希原始NEGOTIATE请求/响应及SESSION_SETUP消息，禁止重编码；最终会话身份绑定dialect、cipher、signing算法、server GUID、证书/主机身份和hash。多通道加入前必须用已认证会话密钥验证该通道自己的完整preauth链，重连只能依据原会话导出的不可变身份，不能接受更低dialect或不同GUID。重复上下文、未知必选算法、消息截断和异步连接失败不发布部分会话。用第二通道降级、重连清零、原始字节改写、GUID替换、乱序完成和合法多通道验证所有通道继承同一安全协商。
