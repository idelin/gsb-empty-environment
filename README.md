# budget_coverage：带预算的最大覆盖（贪心 + 枚举精确参考 + 可恢复分支定界）

Python 3.11+，仅用标准库（`fractions.Fraction` 精确有理数）与 `unittest`，不调用任何求解器。

## 问题定义

- 元素带非负权重，集合带非负成本，预算 `budget`；目标：在预算内选集合，最大化被覆盖元素的权重和。
- **重复覆盖只计一次**：元素被覆盖 ≥ 1 次即计入权重。
- 扩展硬约束：
  - **依赖**：选集合 i 必须同时选其依赖闭包；
  - **互斥**：每个互斥组中至多选一个集合；
  - **最低覆盖次数**：元素 e 至少被覆盖 `min_coverage[e]` 次（收益仍只计一次）。
- 数据只接受合成整数/有理数（`int` / `Fraction` / `"3/4"` 字符串），**拒绝 float** 以保证精确性。

## 状态语义（严格分开）

| 状态 | 含义 |
|---|---|
| `OPTIMAL` | 搜索完成，已证明最优 |
| `FEASIBLE` | 有可行解（下界），但搜索预算耗尽、最优性未证明，附可靠上界 |
| `INFEASIBLE` | 已证明无可行解 |
| `UNDECIDED` | 搜索预算耗尽且暂无可行解（预算未决），附剩余子树上界 |

贪心只返回 `FEASIBLE` 或 `UNDECIDED`——**只运行贪心不能声称最优**。

## 结构

- `budget_coverage/model.py` — 问题模型、可行性检查、`delete_set`（version 递增）、实测差距
- `budget_coverage/greedy.py` — 贪心：零成本候选永远优先（不除零）→ 性价比 → 最低覆盖修复
- `budget_coverage/exact.py` — 全子集枚举精确参考（默认上限 20 个集合）
- `budget_coverage/branch_bound.py` — 可恢复分支定界（显式栈 + `snapshot()`/`restore()`）
- `budget_coverage/witness.py` — 见证固化与动态删集合后的重验
- `examples/run_sample.py` — 运行样例
- `tests/` — 30 个 unittest 用例

## 分支定界说明

- **上界（可靠）**：当前已计收益 + 分数背包松弛。每个未定集合的边际收益按当前未覆盖元素计算，
  集合间重叠被重复计入（只会高估）；忽略依赖/互斥/最低覆盖（放松约束只会抬高上界）。
  零成本集合的收益全额计入，不做任何除法。
- **剪枝**：`budget` / `mutex` / `dependency` / `min_coverage`（硬约束，子树不可行）与
  `bound`（子树上界 ≤ 当前最优）。每次剪枝记录 `PruneRecord`，含路径、原因与具体数值的界限理由。
- **可恢复**：`snapshot()` 产出可 JSON 序列化的快照，`restore()` 校验问题版本后恢复；
  问题变更（如删集合）后旧快照被拒绝。

## 测试

```
$ python3 -m unittest discover -s tests
..............................................................
----------------------------------------------------------------------
Ran 30 tests in 1.264s

OK
```

要点覆盖：分支定界与全子集枚举在 10 个随机实例（含依赖/互斥/最低覆盖/零成本）上逐一核验一致；
快照恢复与一次性运行结果完全相同；部分搜索的上界始终 ≥ 精确最优；零成本集合不触发除零；
空集不增加收益；贪心永不声称最优；删集合后旧见证/旧快照一律需重验。

## 说明

- 差距报告仅为实测值；本库**不为启发式编造近似保证**。
- 精确参考受枚举规模限制（默认 ≤ 20 个集合）；更大实例请用分支定界并按需给搜索预算。
