# 抑制单元补充保护

匿名统计表隐藏一个小计数后，行列总和仍可能恢复它。写供Go发布宿主调用的补充抑制包，表最多四乘四，已知非负整数上下界与行列和；选择最低成本额外隐藏单元，使每个原敏感单元至少有两个可行值，成本相同按坐标排序。返回每个敏感单元的两份完整表见证，用穷举小值域核对。

## 实现

代码位于子包 `suppress/`（导入路径 `example.org/netsec/q0437/suppress`），
面向至多 4×4 的非负整数表。

- `suppress.Solve`：枚举非敏感单元子集求最低成本额外抑制集合，同成本取
  行优先坐标序最小者，并为每个敏感单元重建两份完整表见证。
- 保护判据：抑制集合 H 内的「行-列」二部图中存在一条经过敏感单元的
  交错环，沿环做一个单位转移后仍满足全部上下界与行列和。可行性用
  Dinic 整数最大流判定（`flow.go`），环枚举见 `protection.go`。
- `suppress.Enumerate` / `suppress.Verify`：在小值域上穷举全部可行表，
  按公开单元指纹分组，权威核对每个敏感单元是否存在两个不同可行值，
  并校验见证、成本与抑制集合。
- 失败类别用哨兵错误暴露：`ErrInvalidProblem`、`ErrInfeasible`、
  `ErrUnprotectable`、`ErrDomainTooLarge`，宿主可用 `errors.Is` 判别。

## 测试

`go test ./...` 运行经典 2×2/3×3 案例、成本与坐标序、边界与错误处理，
以及 300 组随机用例下流/环判据与穷举预言机的对拍。
