# 取证规划器 (forensics-planner)

按布尔表达式检查验收条目，在证据成本、有效期与互斥执行条件约束下，
求覆盖全部验收条目的**最低成本**取证计划（默认最多 25 项证据）。

## 输入

JSON（文件或标准输入），见 `sample.json`：

- `asOf`：取证基准日 `YYYY-MM-DD`（缺省为今天）。`validUntil` 早于基准日的证据**过期不计入**（有效期含当日）。
- `maxItems`：计划证据数上限，缺省 25。
- `evidence[]`：`id`、`cost`、`validUntil`、`mutexGroup`（同组证据互斥，不可同时采集）。
- `criteria[]`：`id` 与 `expr` 布尔表达式，支持 `AND`/`OR`（及 `&&`/`||`、`&`/`|`）与括号。
  语义严格区分：`AND` 需**全部满足**，`OR` **任一满足**即可。

## 使用

```sh
go build -o fp .
./fp -f sample.json        # 文本报告
./fp -f sample.json -json  # JSON 输出
cat sample.json | ./fp     # 标准输入
go test ./...              # 运行测试
```

## 输出

- 可行时：最低总成本、采集清单，以及每条验收的**满足路径**
  （AND 列出全部分支，OR 标明所选分支及“任一分支满足即可”）。
- 不可行时：每条验收的**未满足原因**，区分——
  - 证据已过期（不计入）或不存在导致的结构性不可满足；
  - 互斥执行条件 / 数量上限导致的组合不可行；
  - 本身可满足但被其它不可满足条目拖累。

## 实现要点

- `expr.go`：表达式词法/语法分析为 AST，位掩码求值，解释器生成满足路径与未满足原因。
- `planner.go`：先剔除过期证据，候选按成本升序做分支定界（乐观上界剪枝 +
  互斥组位掩码 + 数量上限），保证最优解；候选上限 60 项。
- `main.go`：CLI 与报告渲染。
