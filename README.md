数据库兼容层升级后，测试宿主记录了事务的开始、请求完成与提交，但同一时间桶内的事件顺序丢失了。请提供宿主可导入的 Go 包，判定一份记录能否由以下快照隔离内核产生，并返回可由独立内核重放的完整事件顺序。不同桶严格有序，桶内须保持每个事务的程序顺序；开始时冻结已提交映射，之后的读取优先取自身最近写入，否则读冻结值。写入和删除均记入写集，即使最终值与原值相同；若自开始以来已提交的其他事务触及本事务写集中的任何键，提交必须失败，否则必须成功。失败事务的写入不可见。初始映射、每次读得的值或缺失、每次提交的成败均由输入给出。最多 12 个事务、80 个事件，每桶最多 14 个事件。若有多个见证，选整个事件编号序列字典序最小者；若无见证，定位第一个无法完整处理的桶，按所有可达前缀而非一次贪心重放判断。交付见证校验器，测试包括同值写也导致冲突、删除后读自己的缺失值、写偏斜合法，以及同一桶的局部最小合法顺序会让后续读值失配。
