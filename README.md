# 大事务分片传输与内存保护限流器

针对“单个事务包含百万级行变更”场景的保护机制：事务尺寸突破阈值时自动切分为
多个带阶段标记的子分片（Chunk）流式传输；内存超额时溢写临时磁盘，防止接收端
OOM 崩溃；接收端逐片校验，追踪总事务完整性。

## 运行环境

- Node.js >= 22.6（使用内置 `node:test` 与 `--experimental-strip-types`，零第三方依赖）
- 仓库内含 `.nvmrc`（v22.14.0），使用 nvm 可直接 `nvm use`

```bash
npm test    # 运行全部 20 个测试（含 50 万行验收用例）
npm run demo  # 运行 50 万行 -> 100 批次传输样例
```

## 组件

| 模块 | 职责 |
| --- | --- |
| `src/chunker.ts` | 大事务分片器：从异步行源流式读取，按 `chunkSize` 切分，产出 `BEGIN -> DATA* -> END` 阶段标记分片；任意时刻仅驻留一个分片的数据 |
| `src/memory-guard.ts` | 内存保护限流器：按字节计数的异步信号量，在途字节达上限即挂起生产者形成背压；支持 `abort()` 防止异常路径死锁 |
| `src/spill-queue.ts` | 内存+磁盘混合 FIFO 队列：内存超阈值后溢写临时文件（长度前缀帧），磁盘有积压时新元素继续落盘以保证全局 FIFO，关闭时清理临时文件 |
| `src/transporter.ts` | 传输管线：生产者（分片→限流→入队/溢写）与消费者（出队→投递→释放额度）协作，上报在途峰值/溢写量等统计 |
| `src/tracker.ts` | 接收端完整性追踪：校验 seq 连续、BEGIN/END 阶段、逐片校验和、总行数/总分片数/全事务滚动校验和（FNV-1a） |
| `src/memory-monitor.ts` | 堆内存采样监控器，用于验收峰值内存 |

## 数据流

```
源库行源(AsyncIterable) ──> splitTransaction ──> MemoryGuard.acquire(背压)
                                                        │
                                              SpillQueue(内存超额→临时磁盘)
                                                        │
                                    sink(chunk) <── 出队(内存优先, 磁盘读回)
                                        │
                              TransactionTracker 逐片校验完整性
```

## 验收场景（`test/e2e.test.ts` / `examples/demo.ts`）

源库一次大更新产生 **500,000** 条变更，切分为 **100** 个批次（每批 5,000 行）
流式传输，接收端逐片校验事务完整性，全程采样堆内存：

- 限流上限 2MB（在途字节峰值实测 1831KB）
- 队列内存阈值 512KB，超出部分溢写临时磁盘（实测溢写约 61MB）
- 峰值堆内存增量（传输期间峰值 − GC 后基线）须 < 10MB

内存口径说明：Node 进程基线堆约 8MB，绝对 RSS 无法小于 10MB，故以
**传输引起的堆内存增量**为验收指标。运行脚本通过
`--max-semi-space-size=1 --max-old-space-size=12` 模拟内存受限的接收端
（对应容器内存限额场景），强制 V8 及时回收；若设计存在真实的内存驻留
（如 50 万行被一次性持有），进程将直接 OOM 失败——因此该约束同时是对
“内存有界”的强验证。
