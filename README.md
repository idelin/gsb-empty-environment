容器运行时与沙箱宿主加载经典 BPF（cBPF）`seccomp_filter` 拦截高危系统调用（如 `execve`/`ptrace`/`bpf`）时，若过滤程序未在检查 `seccomp_data.nr` 之前严格核对 `seccomp_data.arch`（`AUDIT_ARCH_X86_64`），或漏查 x32 ABI 标志位（`nr | 0x40000000`）、仅校验 64 位参数的低 32 位而忽略高 32 位，攻击者可通过 `int 0x80` 切入 32 位兼容态、置位 x32 掩码或构造高位非零参数直接绕过沙箱策略。为 C++17 沙箱安全宿主实现可嵌入、零外部依赖、`-Wall -Wextra -Wconversion -Werror` 编译通过的 `sock_filter` cBPF 指令级静态与符号验证库。库首先按内核 cBPF 验证规则校验指令流完整性（长度上限 4096、禁止向后跳转与越界跳转、禁止读取未初始化寄存器与越界 `seccomp_data` 偏移、所有路径必达 `BPF_RET`）；随后在控制流图上执行路径敏感区间/位掩码符号分析，针对给定的禁止系统调用策略集（含目标架构、禁用的 64 位号、以及关键参数的 64 位禁止掩码/值），精确判定：（1）是否存在任意非 `AUDIT_ARCH_X86_64`（如 `AUDIT_ARCH_I386`）或带 `0x40000000` x32 标志的输入能到达 `SECCOMP_RET_ALLOW`；（2）是否存在禁用系统调用或仅检查低 32 位而放过带非零高 32 位参数（如 `clone` 标志或 `openat` 参数）的绕过路径，并在检出违规时构造出具体的 `(arch, nr, args[6])` 逃逸见证输入。附含 x32 绕过、compat 32 位逃逸、64 位参数截断与合规白名单过滤器的测试集。
