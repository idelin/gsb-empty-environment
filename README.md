# leftmost-longest-regex

一个带捕获区间的正则匹配库（TypeScript 实现），支持分组、并集、连接和星号，
采用「最左起点 + 最长整体匹配 + 按组顺序选最长捕获」的语义。

## 语法

```
alt    := concat ('|' concat)*     -- 并集（允许空分支）
concat := repeat*                  -- 连接（允许为空，即空模式）
repeat := atom '*'*                -- 星号（可叠用，如 a**）
atom   := '(' alt ')' | '\' 任意字符 | 普通字符
```

- 捕获组按左括号出现顺序编号 1..n。
- 元字符 `( ) | * \` 需用 `\` 转义后作为字面量。
- 空模式、空分支（如 `(|a)`）均合法，匹配空串。

## 匹配语义

对输入串做非锚定搜索：

1. **最左起点**：取存在匹配的最小起始位置。
2. **最长整体匹配**：在该起点下取结束位置最大的匹配。
3. **按组顺序选最长捕获**：在整体区间相同的所有匹配路径中，按组号
   1..n 依次比较——参与的组优先于未参与的组；参与的组中捕获更长的优先；
   仍并列时取起点更早者（仅为确定性兜底）。
4. **星号与捕获**：组在星号内时记录**最后一次迭代**的区间。
5. **零长度循环保护**：星号的一次迭代若匹配空串，则该次迭代是星号的
   最后一次迭代（其捕获仍然生效，但不再继续迭代）。非空迭代严格推进
   位置，因此枚举必然终止，不会卡死。
6. **未参与组 vs 空组**：未参与的组输出 `undefined`；参与了但匹配空串
   的组输出 `start === end` 的区间。两者严格区分。

示例：`(a|ab)(c|bcd)` 作用于 `abcd` → 整体 `[0,4)`，组 1 为 `[0,1)`（`a`），
组 2 为 `[1,4)`（`bcd`）。注意这与宿主语言回溯式正则（先到先得，会给出
`a` + 未匹配）不同，本库不采用宿主正则语义。

## API

```ts
import { compile } from 'leftmost-longest-regex';

const re = compile('(a*)(b*)');
const m = re.exec('aab');
// m.span      => { start: 0, end: 3 }   整体匹配区间
// m.text      => 'aab'
// m.groups[0] => { start: 0, end: 3 }   整体
// m.groups[1] => { start: 0, end: 2 }   组 1
// m.groups[2] => { start: 2, end: 2 }   组 2（参与但为空）
// 未参与的组为 undefined
```

- `new Regex(pattern)` / `compile(pattern)`：编译；语法错误抛异常。
- `re.exec(input)`：返回 `Match | null`。
- `re.test(input)`：是否存在匹配。
- `re.groupCount`：捕获组数量。

## 实现

- `src/ast.ts`：AST 定义与递归下降解析器。
- `src/matcher.ts`：匹配引擎。对每个 `(AST 节点, 输入位置)` 计算「结束位置
  → 到达该位置的所有不同捕获向量」集合并做记忆化；星号用队列做宽度优先
  展开，零宽迭代只记录不继续展开。捕获向量不做偏好剪枝（外层星号的后续
  迭代可能只覆盖部分组，局部较差的向量仍可能全局最优），仅按哈希去重。
- `src/index.ts`：公开 API（`Regex` / `compile` / `Match`）。

复杂度：不同捕获向量的数量在最坏情况下随组数指数增长（POSIX 式子匹配
语义的固有特性）；典型模式接近线性，多组深层嵌套星号可能较慢。

## 测试

不依赖宿主正则作参考答案（宿主语义不同），采用两条独立路径互查：

- `test/oracle.ts`：独立的暴力枚举 oracle——递归枚举每个起点下的**全部
  匹配结局**（结束位置 + 完整捕获向量，仅丢弃完全相同的重复结局），并用
  独立书写的选择逻辑挑出胜者。未参与组用 `null` 表示（引擎用
  `undefined`），与引擎不共享任何匹配/选择代码。
- `test/semantics.test.ts`：按语义规则手工推导的用例（最左最长、组优先
  级、未参与 vs 空组、星号末次迭代、零长度循环、嵌套空分支、转义、语法
  错误等）。
- `test/exhaustive.test.ts`：差分测试——
  1. 手工语料（大量嵌套空分支模式）× `{a,b}` 上长度 ≤ 5 的全部串；
  2. 固定种子随机生成的 250 个模式（限制星号嵌套 ≤ 2、组数 ≤ 6）×
     `{a,b}` 上长度 ≤ 4 的全部串；
  3. 12 组三层嵌套星号的压力模式 × 长度 ≤ 3 的全部串。
  每个 (模式, 串) 同时比较**最终胜者**和**每个起点下的完整结局集合**。

运行：

```sh
npm test        # 编译并运行全部测试
# 或者指定其他 tsc：
TSC=/path/to/typescript/bin/tsc npm test
```
