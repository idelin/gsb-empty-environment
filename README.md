# 重入调用能否突破提款上限

合约回归平台要发现“先外调、后扣减”在回调重入时造成的超额转账。请做可导入的Go交易解释包，只执行本题的内存模型：账户初始余额、合约现金和整数提款额由调用方给出；指令为当前余额是否至少为本次提款额的比较分支、按本次提款额余额加减、cashSend、externalCallback、return、revert，所有金额为0到255的数学整数，越界即revert。cashSend按本次提款额扣合约现金并记收款额，externalCallback可由攻击者选择重入同一入口或立即返回，最多深度4、总指令100步；子调用revert回滚子调用全部余额与转账，externalCallback指令的静态参数指定父调用遇子失败时继续或revert，父revert连同成功子调用一起回滚。输入不超过30条指令，搜索调用方给定的最多8种允许的单次提款额，各层分别选择，报告最终已提交收款额大于初始余额的最短调用树，等长按提款额序列排序。提供独立回放及按每层快照的回滚证据，验证先扣减的安全版本、父失败撤销子转账、现金不足及回调拒绝。超步数标未知，不能把回滚前暂态转账当成成功攻击。
