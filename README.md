# 螃蟹脚并发加锁协议（Latch Crabbing / Coupling）— TypeScript 版

在 B+ 树上实现多线程遍历的经典并发控制协议：遍历**自上而下**逐节点加读/写锁，
子节点锁到手后才释放父节点锁（coupling）；若子节点**安全**（keys 未满，插入不会
引发分裂/借调），写操作会**提前释放所有祖先锁**，从而大幅提高并发吞吐。

## 文件结构

- `src/latch.ts` — 异步读写锁 `RwLatch`：读共享、写互斥、FIFO 公平（防写者饥饿），附全局统计
- `src/bptree.ts` — B+ 树 + 螃蟹脚协议（`get` 读路径 / `insert` 写路径 / 根分裂重启）
- `src/demo.ts` — 运行样例：10 读任务 + 5 写任务并发压测
- `test/crabbing.test.ts` — Node.js 内置测试（`node:test`）

> 说明：Node 为单线程事件循环，这里用异步任务模拟并发线程——`await` 点即线程
> 切换点，锁的获取/释放语义与多线程模型完全一致。协议本身与线程模型无关。

## 协议要点

**读（get）**：逐节点 `read-latch`，子锁到手立即释放父锁。任一时刻最多持有路径上
相邻两把读锁，高层节点几乎零占用；多个读者共享同一节点读锁，无阻塞高速穿越。

**写（insert）**：路径加 `write-latch`；子节点安全（`keys.length < maxKeys`）即释放
全部祖先锁，只保留不安全区段。叶子溢出后的分裂沿仍持有锁的链向上传播，区段顶端
必为安全节点，传播必然有界。根满时在写锁独占下分裂根使树长高，随后重启遍历。

**无死锁论证**：所有锁只按"根 → 叶"的偏序获取，任一操作持有的锁构成树中一条向下
路径，不存在循环等待 ⇒ 无死锁。FIFO 队列保证无饥饿。

**过期根防护**：加锁后复核 `root === this.root`，防止并发根分裂期间用到已脱落的旧根。

## 运行

```bash
npm run demo   # 运行样例（Node >= 22.6，原生运行 TypeScript）
npm test       # node:test 内置测试
```

验收边界覆盖：

- **10 读线程 + 5 写线程并发**：测试 3 与 demo 均为该配置；
