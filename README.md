# 索引重建工具（Go）

旧索引持续对外服务，新索引从一致性快照构建后追赶增量，满足切换条件后才提升为主索引。

## 核心机制

- **冻结版本**：`Begin` 先注册变更监听再取快照，快照版本即冻结版本，快照与变更流之间无空隙。
- **追赶增量**：`CatchUp` 重放冻结版本之后的全部事件；投递层可乱序、重发、丢失（故障注入）。
- **按键版本消重**：`Index.Apply` 只在事件版本高于该键当前版本时应用；删除留墓碑，防止乱序旧事件复活已删键。
- **切换条件**（`TrySwitch`，三者同时满足）：
  1. 新索引水位 ≥ 冻结版本；
  2. 所有未确认变更已处理（`Unacked` 为空，按源库变更逐键确认，含墓碑）；
  3. 以源库全扫描为参考的全量校验通过（缺失 / 残留 / 值或版本分歧均拒绝）。
- **水位证据**：每次切换尝试返回 `Evidence`，含冻结版本、源库版本、新旧索引水位、未确认变更清单、校验结果与切换决定。

## 结构

- `rebuild/store.go` — 源库：版本化 KV、追加式变更日志、变更监听
- `rebuild/index.go` — 索引：按键版本消重、墓碑、水位
- `rebuild/rebuild.go` — 重建器：冻结、追赶、未确认跟踪、切换门控
- `rebuild/validate.go` — 全扫描校验器与水位证据
- `main.go` — 演示：场景 A（构建中删除+补录，乱序重发下切换成功）；场景 B（事件丢失，切换被拒，旧索引继续服务）

## 运行

```sh
export GO111MODULE=on
go test ./...   # 单元测试：消重、删除、补录、切换成功/失败、水位证据
go run .        # 演示两个场景并打印新旧索引水位证据
```
