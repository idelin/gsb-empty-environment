发送端常把一封邮件加密后投递给多个收件人，但每个收件人可能有多把已认证设备密钥，地址别名与转交授权也会变化。给 Go 邮件宿主写可导入的加密投递规划包。设备能力声明由宿主验签，绑定稳定邮箱身份、设备代次、允许算法和有效期；别名只能通过有期限的签名边归到同一身份，合并后的地址显示名不能充当证据。投递请求给出各收件人必须覆盖的设备组、禁止同一信封共存的保密身份对和全局算法偏好。每份信封只能用一个算法，包含的每一把公钥都须在同一发布时间拥有对该算法的授权；两个设备组可共用同一把密钥仅当它确属同一主体。选信封数最少的方案，其次使最弱信封的算法等级尽可能高，再按稳定编号决胜。至多18个设备组。输出完整授权证书供独立投递端校验；提交前如证书吊销或收件组变更，只能重新规划，不能私自兜底降级。用小规模穷举对照需要拆封、贪心选最强算法导致多一份信封、证书区间仅在端点相接、同名异身份及盲抄送身份不能共同披露。

## cryptoplan

实现位于 `cryptoplan/`，导入路径 `prescreen.local/ddd-10544-v2/cryptoplan`。

- 证据模型：`DeviceCert` 是宿主 Ed25519 验签的设备能力声明，绑定稳定邮箱身份、
  设备代次、允许算法与半开有效期 `[NotBefore, NotAfter)`；`AliasEdge` 是带期限的
  签名归并边，地址只能通过边归并到身份，显示名不参与任何证据判断。
- 规划目标：在至多 18 个设备组上，依次按“信封数最少 → 最弱信封算法等级最高 →
  稳定编号规范字典序”求最优分组；每份信封只用一个算法，信封内每把公钥都必须在
  统一发布时间持有该算法授权；跨组共用公钥仅在确属同一稳定身份时允许。
- 保密约束：`ForbiddenPairs` 中的稳定身份对（如 To 与 BCC）不会出现在同一信封，
  盲抄送身份不会与其他收件人共同披露。
- 输出与复检：每个信封携带完整授权证书与所需归并边，独立投递端可用 `VerifyDelivery`
  复核签名、有效期、单算法授权、保密隔离、设备覆盖与输入摘要；提交前 `Recheck`
  一旦发现证书吊销或收件组/视图变化，返回 `ErrRevoked` 或 `ErrInputChanged`，
  调用方只能重新 `PlanDelivery`，包内不提供静默降级路径。
- 测试：覆盖保密身份拆封、锁定式贪心多一份信封的反例、半开区间端点相接、同名异
  身份、BCC 隔离、吊销与收件组变更、签名篡改、跨身份公钥冲突，以及 200 组随机
  小规模实例与独立受限增长字符串穷举的逐案对照。
