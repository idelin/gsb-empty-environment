# BLS聚合公钥注册与持有证明

## 实现

可导入子包 `blsregistry/`（模块 `example.org/netsec/q0817`），配对运算与
哈希到曲线通过 `Engine` 接口由调用方注入，生产环境可接入 BLS12-381
最小公钥方案（G1 公钥、G2 签名）的实现。

- `engine.go`：`G1Point`/`G2Point`/`Scalar`/`Engine` 抽象，以及两个不同的
  域分隔标签 `DomainSignature` 与 `DomainProofOfPossession`。
- `registry.go`：并发安全的验证者注册器、持有证明校验、同消息聚合验证
  （`VerifyAggregateSameMessage`）与不同消息聚合验证
  （`VerifyAggregateDistinctMessages`），失败原因通过哨兵错误返回。
- `sign.go`：普通签名与持有证明签名辅助函数。
- `mockengine_test.go`：仅用于测试的模拟引擎，按生成元标量表示群元素并
  模拟多配对等式；不具备密码学安全性，禁止在生产代码使用。
- `registry_test.go`：覆盖无持有证明的恶意公钥（rogue-key）、标签混用、
  位图长度不符、重复消息、阈值不足、无穷远点公钥与重复注册等场景。

### 接入要点

1. 实现 `Engine` 接口（哈希到曲线须把域分隔标签纳入 DST）。
2. `NewRegistry(engine, quorum)` 建集合，注册前用
   `SignProofOfPossession` 生成持有证明。
3. 同消息聚合传入位图与聚合签名；不同消息聚合按选中验证者顺序传入两两
   不同的消息。位图长度必须等于集合大小，选中数低于 `quorum` 一律拒绝。

委员会用 BLS 聚合签名证明多数同意，攻击者注册一个由他人公钥推导出来的恶意公钥，就能单独伪造出看似所有人都签过的聚合签名。给Go共识节点实现可导入的验证者注册与聚合验证包，配对运算与哈希到曲线由调用方注入：注册公钥必须附带持有证明，即对自己的公钥字节签名，使用与普通签名不同的域分隔标签（持有证明标签与签名标签不得相同）；未通过持有证明的公钥不得进入验证者集合，同一公钥重复注册忽略；同一消息的聚合签名验证中，聚合公钥只由集合内且位图选中的公钥相加得到，位图长度须等于集合大小，选中数低于阈值拒绝；对不同消息的聚合，消息两两不同才接受，有重复消息时拒绝；公钥为无穷远点时拒绝。用无持有证明的恶意公钥、两种标签相同、位图长度不符、重复消息和阈值不足验证。
