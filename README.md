# npm导出条件差分与已审入口

依赖包 package.json 的 exports 里可以放自定义条件，攻击者发布的依赖用 development 或 deno 之类的条件把未经审查的入口放在 default 之前，让带用户附加条件的构建选中它。为TypeScript构建网关写可导入的条件差分解析包：对同一说明符解析两次，条件对象按键顺序取第一个匹配的键，嵌套内无匹配则回到上层的下一个键，null 表示封锁；第一次只用调用方给的基线条件（如 import、node、default），第二次再加用户传入的附加条件；附加条件名不在调用方的允许集合内时视为未传入；两次入口文件相同则放行；不同时，新入口须在调用方登记的已审查文件 SHA-256 表内，否则拒绝，并在输出里标出是哪个附加条件、哪个键使入口改变；被选中的入口还须存在于包的文件清单内。用 development 前置条件、已审查入口放行、允许集合外条件、null 封锁和清单缺失验证。
