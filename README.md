# 签名否定区间缓存越过证明范围

递归解析器会用已验签NSEC记录直接回答后续不存在查询，区间边界或通配符证明用错就会把真实名称判不存在。给Go解析宿主实现可导入的签名否定缓存包：域名是规范小写标签序列，比较按DNSSEC规范从根侧标签到叶侧逐字节进行，名称均属于固定zone且不得等于zone之外的父名；owner等于next表示覆盖除owner外的整个zone环；NSEC项含owner、next、类型位图、原始TTL、RRSIG过期时刻与验证回执ID，环形区间(owner,next)在owner≥next时跨末尾。只接收调用方已验证且回执绑定zone、owner、next、位图和签名过期的项；有效期取插入时刻加TTL与签名过期的较早者。查询精确等于owner时仅位图缺少类型可证明NODATA；普通NXDOMAIN须有一条有效NSEC严格覆盖查询名，并另有证明覆盖根据当前有效记录计算的通配符名*.<closest-encloser>，closest-encloser必须由缓存中的存在证据逐层确定，不能从否定项猜测。多个NSEC可组合但须同zone和验证代次，过期或被更高序列区数据替换后立即失效。实现逐名查询与缓存更新，输出用到的最小证明项；用至多三标签、每标签两值的完整名字全集参考核对环绕、owner边界、空非终结、通配符存在和NODATA/NXDOMAIN区分，缓存证据不足必须返回需上游查询。
