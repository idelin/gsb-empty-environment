# 前缀哈希MAC的长度扩展伪造

旧接口用SHA256(secret||message)认证请求，攻击者知道一条消息和标签后可追加字段而无需密钥。给Go安全实验宿主实现可导入的攻击验证与迁移包：实现标准SHA-256压缩状态导入，输入原message、32字节tag、猜测secret长度区间1至64和suffix；对每个长度构造SHA-256填充80||(从secret起算的从secret起算的总位长大端64位，长度按模2^64编码，长度按模2^64编码)，从tag八个大端状态字继续压缩suffix，输出forgedMessage=message||padding||suffix及forgedTag。测试服务器回调只接消息与tag并内部持密钥，包不得读取密钥；找到首个被接受长度时返回查询次数和完整见证，均失败则报告区间未命中。迁移后的验证入口改用HMAC-SHA256，规范请求还必须以大端长度前缀绑定方法、路径和正文，比较常量时间；同一原标签和任意suffix均不能通过。自行实现的SHA-256状态继续须用标准库对随机已知prefix拼接做交叉验证，但不得通过调用私有运行时符号。覆盖secret长度使总长恰跨块、空message、空suffix、错误tag和suffix含现有分隔符，明确攻击只证明题内前缀MAC错误，不声称SHA-256碰撞。
