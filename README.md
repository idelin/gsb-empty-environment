# 有限域加法分享的多方求和模拟

用 Python 3.11（仅标准库，测试用 unittest）模拟多方安全求和的协议流程：
参与集合承诺、分享、掉线确认、恢复与聚合，并用有限域状态探索核验
每轮输出与实际参与输入的守恒性。

- 本项目**仅模拟协议流程**，用于教学与状态探索，**不作任何密码学安全背书**，
  **不是生产级密码协议的实现**。
- **仅处理合成数据**；请勿用于真实敏感数据。

  - **串谋（collusion）抵抗**：份额对模拟协调者（`Round` 对象）可见，
    未建模任何门限隐私或抗串谋性质；
  - **认证与身份真实性**：消息无 MAC/签名，假冒、篡改不在威胁模型内；
  - 网络敌手、侧信道、可用性攻击等现实威胁。

  **不作为形式化隐私或安全证明**。

## 参数与定义

| 名称 | 含义 |
| --- | --- |
| `p` | 有限域模数，默认 `2**127 - 1`（梅森素数），所有运算在 mod p 下进行 |
| `n` | 承诺参与方数量 |
| `t`（threshold） | 完成一轮所需的最少活跃方数量，t ≥ 2 |
| `round_id` | 轮次标识，每份份额都携带，用于轮次隔离 |
| 承诺集合 | 承诺阶段结束后固定的参与方集合，之后不可再加入 |
| 掉线集合 | 掉线确认阶段声明的、属于承诺集合的无响应方 |
| 活跃方 | 承诺集合 − 掉线集合 |
| 覆盖集合 | COMPLETE 轮次输出实际覆盖的参与方（即活跃方），随结果明确标注 |

加法分享：秘密 `s` 拆为 `n` 个份额 `v_0..v_{n-1}`，满足
`sum(v_i) ≡ s (mod p)`；还原必须集齐全部 `n` 份，缺任何必要份额即失败。

## 轮次阶段

1. **参与集合承诺**：参与方登记，关闭后集合固定，迟到加入与重复承诺被拒绝。
2. **分享**：每个承诺方把输入拆成 `n` 份分发给全体承诺方。
   旧轮份额、重复重传、未承诺方的份额一律拒绝。
3. **掉线确认**：声明掉线集合（必须是承诺集合的子集）。
4. **恢复**：活跃拥有方释放其发往已确认掉线方的份额（恢复材料），
   用于补偿因掉线丢失的总和贡献；**恢复材料只能用于声明掉线方**。
   注意：恢复的是"总和贡献"，不是掉线方输入——掉线方自身持有的份额
   随掉线丢失，其秘密无法完整重构，因此被排除在覆盖集合之外。
5. **聚合**：活跃持有方提交部分和（其持有的活跃拥有者份额之和），
   加上恢复材料得到总和（mod p）。

## 协议性质（模拟内保证）

- 分享与还原在 mod p 下一致：`reconstruct(split(s)) ≡ s (mod p)`。
- 轮次隔离：不同轮次的份额不能混用（投递与还原两层都校验 `round_id`）。
- 旧轮分享与重复重传被拒绝。
- **阈值不足（活跃方 < t）时返回 INCOMPLETE，不输出任何数值**，
  绝不用部分和冒充总和；COMPLETE 结果总是明确标注覆盖集合。
- 缺少必要份额/恢复材料/部分和时返回 INCOMPLETE。
- 恢复材料只能针对已确认掉线方释放；掉线方不能参与恢复与聚合。
- 守恒核验：COMPLETE 轮次的输出 ≡ 覆盖集合实际输入之和 (mod p)。

## 测试结果

`python3 -m unittest discover -s tests`：**31 个测试全部通过（OK）**，覆盖：

- `tests/test_sharing.py`：mod p 分享/还原一致性（含 0、p−1、越界输入）、
  缺份额失败、跨轮/跨拥有者混用拒绝、重复份额拒绝、份额取值域检查。
- `tests/test_protocol.py`：完整流程（无掉线/有掉线/模 p 回绕）、
  阈值不足与全员掉线返回 INCOMPLETE、旧轮份额/重复重传/迟到份额/
  未承诺方/重复承诺拒绝、恢复材料越权与缺失、掉线方禁入聚合。
- `tests/test_verification.py`：守恒核验成立与篡改检测、
  INCOMPLETE 不可核验、100 个随机状态探索零违规。
