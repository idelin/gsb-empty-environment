# 安全配置三方合并

安全基线更新与本地例外同时修改配置时，普通文本合并会丢掉拒绝规则。为Go配置宿主实现结构化三方合并包，配置是有序首匹配规则表，每条规则为有限字段集合的合取；仅当合并后决策在各自独立改动覆盖区内保持一致才自动合并，否则返回最小反例输入。字段域由调用方给出且总组合不超过百万。用穷举核对规则重排、删除与新增的语义冲突。

## 用法

入口为 `netsec.Merge(defaultDecision, domains, base, local, remote)`：

- `domains` 给出各字段的合法取值域，取值总数（笛卡尔积）不得超过 1,000,000。
- `base` / `local` / `remote` 是有序首匹配规则表，每条 `Rule` 的 `Match` 为字段
  相等条件的合取，命中时决策为 `Decision`。
- 合并在穷举出的整个输入空间上逐点进行：仅当本地与远端对同一输入都偏离基线且
  结果不一致时判定冲突；单边改动直接采纳，因此规则重排、删除、新增的语义差异
  都按决策函数而非文本比对。
- 无冲突返回规则彼此互斥的规范首匹配表；有冲突返回 `*netsec.Conflict`，其
  `Counterexample.Input` 是最小部分输入，未列出的字段取任意值冲突均成立。

测试以独立的朴素首匹配评估器为参照，对随机生成的三张表逐点穷举核对合并结果与
反例最小性（`go test ./...`）。
