# JWE口令派生迭代与压缩预算

服务接受用户提交的 JWE 令牌，攻击者把 PBES2 的迭代次数 p2c 写成十亿，或用压缩比极高的 zip 头让服务在验证之前耗尽 CPU 与内存。为TypeScript认证网关写可导入的 JWE 头准入包，输入受保护头 JSON、压缩载荷长度和调用方预算：alg 为 PBES2-HS256+A128KW、PBES2-HS384+A192KW 或 PBES2-HS512+A256KW 时，p2c 须是整数，且在 1000 到调用方给的上限之间（含边界），p2s 须是 base64url 编码，解码后至少 8、至多 64 字节；zip 只允许缺省或 DEF，解压后输出上限由调用方给出，压缩比超过 100 倍时拒绝；crit 里列出的名称必须全部被理解；重复的头参数名拒绝；alg 为 dir 或 RSA1_5 时拒绝；以上判定必须在做任何密钥派生之前完成。用 p2c 为十亿、p2s 只有 4 字节、压缩炸弹、重复键和 RSA1_5 验证。
