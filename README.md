# 多粒度锁（MGL）与意向锁调度器

TypeScript 实现的多粒度层次锁管理器，支持 **库 → 表 → 行** 三级锁层次与
**IS / IX / S / SIX / X** 五种锁模式。无需任何依赖，Node.js ≥ 23.6 直接运行
（利用原生 TypeScript 类型擦除与内置 `node:test` 测试框架）。

## 设计要点

- **意向锁自动传播**：加行级 S/X 锁前，自动在父级表和库上加 IS/IX；
  表级 S/X 同理在库上加意向锁（`lockRow` / `lockTable` / `lockDatabase`）。
- **O(1) 冲突判定**：每个锁节点维护"聚合模式计数"（含后代行锁传播上来的
  意向锁）。表级锁请求只需读取表节点自身的聚合计数即可判定冲突，
  **绝不遍历表内行节点**——`stats.rowNodesExamined` 恒为 0，测试对此断言。
- **FIFO 公平调度**：每节点一个等待队列，兼容的连续请求可成组授予
  （如多个 S），后来的请求不得插队越过等待中的不兼容请求，避免饥饿。
- **锁升级**：同一事务重复加锁按规则合并（S+IX→SIX，S+X→X 等）。
- **超时与事务释放**：`lock(..., { timeoutMs })` 支持等待超时；
  `releaseAll(txn)` 用于提交/回滚时释放事务全部锁。

## 兼容矩阵

| 已持有 \ 请求 | IS | IX | S | SIX | X |
|---|---|---|---|---|---|
| IS  | ✓ | ✓ | ✓ | ✓ | ✗ |
| IX  | ✓ | ✓ | ✗ | ✗ | ✗ |
| S   | ✓ | ✗ | ✓ | ✗ | ✗ |
| SIX | ✓ | ✗ | ✗ | ✗ | ✗ |
| X   | ✗ | ✗ | ✗ | ✗ | ✗ |

## 验收边界

事务 A 持有表 T 中行 R1 的 X 锁（表 T 带 IX）；事务 B 请求表 T 的整表 X 锁。
系统由 **IX 与 X 互斥** 直接在表节点上判定并阻塞 B，聚合计数检查每次 ≤ 5 个
条目（O(1)），行节点访问数为 0——即使表内存在成千上万个行节点也一样。

## 运行

```bash
npm test    # Node.js 内置测试（10 个用例）
npm run demo  # 运行验收场景演示
```

## 文件结构

- `src/mgl.ts` — 锁管理器：兼容矩阵、意向锁传播、FIFO 调度、锁升级、超时
- `test/mgl.test.ts` — 基于 `node:test` 的 10 个测试用例（含验收边界）
- `examples/demo.ts` — 验收场景的可运行演示
