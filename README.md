# 采购规划器（Procurement Planner）

同时处理 **起订量（MOQ）**、**整包倍数**、**整单阶梯折扣**、**供应商交付上限**，
在满足多种物料需求且允许 **有上限的超购** 的前提下，求 **最低含运费** 的精确采购方案。
支持最多 **6 家供应商**，输出每家供应商的 **阶梯触发依据**。

## 运行

环境要求：Node.js ≥ 22.6（利用原生 TypeScript 类型擦除，无需编译、无第三方依赖）。

```bash
npm run demo                          # 内置演示（6 家供应商 / 4 种物料）
node src/main.ts examples/demo.json   # 指定场景文件
node src/main.ts examples/tier-chasing.json  # 阶梯凑单演示
npm test                              # 与暴力枚举对照的最优性自测（200 组随机用例）
DEBUG_DP=1 node src/main.ts examples/demo.json  # 打印每层 frontier 规模
```

## 场景 JSON 格式

```jsonc
{
  "maxOverbuyRatio": 0.1,          // 全局默认超购比例上限
  "materials": [
    { "id": "芯片A", "demand": 40, "maxOverbuy": 5 }  // maxOverbuy 可省略（用比例折算）
  ],
  "suppliers": [                   // 最多 6 家
    {
      "id": "S1", "name": "华强电子",
      "freight": 60,                    // 下单即收的固定运费
      "freeFreightMinSubtotal": 500,    // 可选：折前小计达到即免运费
      "maxTotalQty": 250,               // 可选：整单交付总量上限
      "tiers": [                        // 整单阶梯折扣，按门槛升序
        { "minSubtotal": 800,  "discountPct": 5 },
        { "minSubtotal": 2000, "discountPct": 10 }
      ],
      "items": [
        {
          "materialId": "芯片A",
          "unitPrice": 15.0,
          "moq": 20,              // 起订量：买了就必须 >= 20
          "packMultiple": 10,     // 整包倍数：数量必须是 10 的整数倍
          "maxQty": 45            // 可选：该物料交付上限
        }
      ]
    }
  ]
}
```

## 求解方法（为什么不拆单价贪心）

整单阶梯折扣的成本取决于 **该供应商整张订单的折前小计**，把它折算成
“有效单价”再按单价贪心分配，会在门槛附近产生系统性错误（该凑单时不凑、
或把不该集中的订单集中到一家）。本工具的做法：

1. **逐供应商动态规划**：状态为「各物料已购量向量」，逐层考虑每家供应商；
   每个供应商的整单成本按其折前小计命中阶梯后 **一次性整体计算**
   （折扣 + 运费 + 免运费门槛 + 整单交付上限），折扣从不拆成单价。
2. **精确去重**：每层只按（状态 → 最低成本）去重，不做任何在交付上限 /
   起订量场景下不安全的支配剪枝，保证全局最优。
3. **剪枝**：贪心构造 incumbent 上界 + 可采纳下界
   （剩余需求 × 剩余供应商最低可能有效单价）提前剪枝。
4. **输出依据**：每家供应商列出折前小计、命中的阶梯门槛与省下的金额、
   距下一档的差距，以及未触发折扣时的差距说明。

`src/selftest.ts` 用独立实现的暴力枚举在 200 组随机小场景上逐一核对，
确认动态规划结果与暴力最优完全一致（含不可行判定）。

## 复杂度与限制

- 精确算法，状态空间随「物料种类 × 超购粒度 × 整包精细度」指数增长。
  经验范围：物料 ≤ 5 种、每种物料（需求+超购上限）/ 整包 GCD ≤ 数十 时秒级求解。
- 超出规模时求解器会抛出明确错误（默认状态上限 5,000,000，可用
  `solveProcurement(scenario, maxExpansions)` 调整），此时请收紧超购上限、
  增大整包倍数或拆分问题。
- 超购上限是 **硬约束**：若起订量/整包会迫使超购越限，该采购向量被排除；
  全部越限时返回不可行及原因。

## 文件

- `src/types.ts` — 场景与数据结构定义
- `src/solver.ts` — 精确求解器（DP + 下界剪枝 + 阶梯整体计价）
- `src/main.ts` — CLI 与报告输出（含阶梯触发依据）
- `src/selftest.ts` — 暴力枚举对照自测
- `examples/demo.json` — 6 供应商 / 4 物料综合演示
- `examples/tier-chasing.json` — 证明“凑单触发整单折扣优于单价便宜”的最小示例
