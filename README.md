Kubernetes 动态资源分配（DRA, `ResourceSlice` + `ResourceClaim`）允许单个声明同时请求多类异构设备（如多张 GPU、RDMA 网卡与可切分显存实例），不仅要满足单个设备的属性筛选与可共享容量（`AllowMultipleAllocations` + `ConsumedCapacity`）扣减，还要满足跨请求的联合约束（`MatchAttribute` 要求多个请求的所选设备必须共享同一拓扑属性如 `nvlink-domain`、`DistinctAttribute` 要求所选设备必须分散在不同故障域或物理卡上！）。若分配器按请求顺序贪心选卡，极易在前一个请求选错拓扑域或占掉唯一可切分设备，导致原本存在全局合法解的声明被误判调度失败，或释放失败声明时发生容量泄漏。为容器调度器交付可导入的 Go DRA 资源分配与回滚求解包。输入为各节点发布的 `ResourceSlice` 设备池（每设备含唯一 ID、驱动名、静态属性表、是否允许共享及各资源维度总容量/已用容量）、待分配 `ResourceClaim`（含多个子请求，每子请求指定驱动、数量 `count` 或 `All`、属性过滤条件、独占/共享容量需求，以及跨子请求的 `MatchAttribute`/`DistinctAttribute` 约束列表）与节点集合。规则：1）对单节点执行带剪枝的精确回溯分配求解——同时处理独占设备互斥（一卡不可重分）与共享设备多维容量累加不超限、验证全部 `MatchAttribute`（同值相等）与 `DistinctAttribute`（两两互异，含同一子请求内多张卡之间的互斥！）；2）支持在多候选合法方案中按确定性目标选优（优先最小化新启用的独占/共享设备总数以降低碎片 -> 优先利用剩余容量最紧凑设备 -> 设备 ID 字典序最小）；3）支持对多个 `ResourceClaim` 执行原子批量分配与释放（任一子请求或跨声明约束无解时零副作用回滚，已分配容量守恒不泄漏，且重复释放幂等报错）。验收覆盖贪心失败但回溯有解的跨拓扑 `MatchAttribute`/`DistinctAttribute` 联合约束、独占与可切分共享容量混合分配、最小碎片选优及失败原子回滚与容量守恒验证。
