# cache-key-auditor

构建缓存键审计器：比较缓存键中**声明的输入**与构建**实际使用的输入**（环境变量、
工具版本、条件读取），在有限可枚举的输入域上找出「输出变化但键不变」的输入对，
返回**最小反例**，并区分**仅影响日志**与**影响产物**的差异。

## 模型

一个构建被建模为（见 `src/model.ts`）：

- `inputs`：有限域输入变量，分三类 —— `env`（环境变量）、`tool`（工具版本）、
  `conditional-read`（条件读取，仅当 `readWhen` 满足时构建才会读取）；
- `key(assignment)`：声明的缓存键函数；
- `run(assignment)`：实际构建，产出 `{ artifact, logs }`。

## 审计方法（`src/audit.ts`）

1. 枚举输入域的笛卡尔积，计算每个赋值的键与输出；
2. 单变量敏感性分析，得到「键声明的输入」与「输出使用的输入」两组集合，
   其差集 `undeclaredButUsed` 即缓存错误命中的根因；
3. 按差异变量数（汉明距离）递增搜索「键相同、输出不同」的输入对，
   用包含最小性剪枝：差异集若包含某个已知最小反例集则整枝跳过，
   最终只报告**包含最小**的反例（每个差异集 × 差异类型保留一个见证）；
4. 反例分类：`artifact`（产物不同，缓存命中会返回错误产物）或
   `log-only`（产物一致、仅日志不同）。

两类典型的最小反例：

- **未声明输入**（距离 1）：翻转一个不在键中的变量即改变输出；条件读取变量的
  见证会自动落在读取条件满足的上下文里；
- **键编码有损**（距离 ≥ 2）：变量都已声明，但键对它们的编码有碰撞
  （如只记录两个 flag 的和），联合翻转可保持键不变。

## 运行

需要 Node.js ≥ 23.6（原生类型擦除，直接运行 TypeScript）：

```sh
node src/cli.ts                          # 审计内置的缺陷示例
node src/cli.ts --build sound            # 对照组：健全的键，应无反例
node src/cli.ts --max-distance 2         # 限制反例搜索深度
node src/cli.ts --json                   # 机器可读输出
node --test 'test/*.test.ts'             # 测试
```

如需 `tsc` 类型检查：`npm install` 后执行 `npx tsc --noEmit`
（`tsconfig.json` 已启用 `erasableSyntaxOnly`，保证与运行时类型擦除兼容）。

## 接入真实构建系统

把构建系统描述为一个 `BuildSpec`：输入变量及其有限取值域、键函数（复刻构建
系统的键计算逻辑）、`run`（在隔离环境中以给定输入执行构建并收集产物哈希与
日志），然后调用 `audit(spec)`。注意枚举成本随变量数指数增长，可用
`maxDistance` 限制搜索深度换取时间。

## 限制

- 输入域必须有限可枚举；连续或超大域需先离散化；
- 完整枚举是指数级的，`maxDistance` 只保证「距离 ≤ d 内」的最小性结论；
- `run` 应当是确定性的，非确定构建会产生噪声反例。
