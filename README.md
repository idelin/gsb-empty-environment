# annmerge

基于稳定字符 ID 的协作文本标注合并器（Go）。标注范围不依赖字符的当前位置下标，
因此远端插入不会把格式"推"到错误的字符上。协议为自定义格式，不声称兼容任何
现有协作编辑库。

## 操作协议（`Op`）

| kind      | 字段                                                         |
|-----------|--------------------------------------------------------------|
| `insert`  | `id`, `parent`（前驱字符 ID 或 `@root`）, `char`             |
| `delete`  | `id`, `target`（删除字符，保留为墓碑锚点）                    |
| `annotate`| `id`, `annID`, `left`/`leftIncl`, `right`/`rightIncl`, `attrs`, `time` |
| `undo`    | `id`, `undo`（被撤销的 `annID`）                              |

## 语义规则

- 文本序列仅由"按前驱 ID 插入"构成；并发同前驱的插入按操作 ID 降序排列
  （ID 大者更靠近共同前驱），与投递顺序无关。
- 删除保留墓碑，墓碑继续充当标注锚点；删除字符不会删除任何标注。
- 标注引用左右锚点字符 ID，端点包含性各自独立。字符 `i` 被覆盖当且仅当
  它在**最终锚点序列**中的位置满足
  `i > left || (leftIncl && i == left)` 且 `i < right || (rightIncl && i == right)`。
  新字符是否继承标注只由该规则决定，不按消息到达时的位置决定。
- 同一属性键被多个存活标注覆盖时，以 `(time, 操作ID)` 字典序最大者生效。
- `undo` 按标注 ID 精确撤销；被撤销标注不参与属性求值。
- 输出为连续且属性完全相同的最小 run 列表（`Engine.Runs`）。

依赖未满足的操作（前驱/锚点/被撤销标注尚未到达）会被缓冲重试，见
`Engine.ApplyAll`。

## 文件

- `merge.go` — 合并引擎（树形序列 + 逐字符求值 + run 归并）。
- `reference.go` — 逐字符参考求值器：用根路径排序独立重建序列，逐字符独立
  求值，用于交叉校验引擎。
- `merge_test.go` — 测试：枚举 8 个操作的全部 40320 种投递排列验证最终文本与
  属性一致；并覆盖左端插入、右端插入、两锚点删除、空区间、相互重叠撤销、
  同 logicalTime 按操作 ID 决胜等场景。
