# kvstore

仅依赖 Go 标准库的日志结构（LSM 风格）键值存储。所有文件都放在 `Open(dir, ...)` 指定的目录中。

## 设计

- **追加写**：`Put`/`Delete` 只向活跃段追加记录（删除是墓碑记录），绝不原地修改。
- **记录格式**：`| crc32(4B) | keyLen(4B) | valLen(4B) | flags(1B) | key | value |`，CRC 覆盖其后全部字节，`flags` 最低位为墓碑。
- **启动重建索引**：按 `MANIFEST` 列出的顺序扫描各段，重放记录得到 `key -> (段id, 偏移, 长度)` 的内存索引；墓碑从索引中移除该键。
- **段轮转**：活跃段超过 `MaxSegmentBytes` 后新建活跃段，并持久化新清单。
- **压缩**：`Compact` 把全部不可变段合并成一个新段，仅保留当前可见记录（被覆盖的旧值与墓碑全部丢弃），然后原子切换清单。
- **并发读安全**：读者在持读锁时 `pin` 段句柄（引用计数 +1），读完 `unpin`。压缩把旧段移出段表后标记"待回收"，只有引用归零才真正关闭并删除文件——旧读者结束前旧段不会被回收，读者永远读不到已回收文件。

## 崩溃恢复

清单切换是唯一的原子提交点：`MANIFEST.tmp` 写完并 fsync 后 `rename` 为 `MANIFEST`，再 fsync 目录。

- **rename 前崩溃**：旧 `MANIFEST` 完好，新段是孤儿文件，重启时删除孤儿、丢弃 `MANIFEST.tmp`。
- **rename 后崩溃**：新 `MANIFEST` 已生效，旧段成为孤儿文件，重启时清理。
- **活跃段尾部撕裂**：崩溃/断电可能留下写了一半的尾部记录，扫描时按长度 + CRC 识别，截断到最后一条完整记录后继续工作。
- **已落盘未应答**：记录字节完整落盘后、应答前崩溃，重启扫描会重放该记录——调用方未收到成功，但数据可见（日志结构的正常语义）。

## 断电保证边界

- `SyncWrites: true`：`Put`/`Delete` 在 `fsync` 段文件后才返回，已应答的写保证 durable（以硬件/文件系统尊重 fsync 为前提）。
- `SyncWrites: false`（默认）：写进入操作系统页缓存即返回，断电可能丢失最近未落盘的写；进程崩溃（非断电）不丢，因为页缓存仍在。
- 清单与段文件的创建都伴随文件 + 目录 fsync，保证重启后命名空间一致。
- 不保证的场景：存储介质虚报 fsync、文件系统本身损坏、不可变段被外部篡改（打开时拒绝加载损坏的不可变段）。

## 故障注入点（`Faults`，仅测试使用）

| 注入点 | 触发时机 | 崩溃语义 |
| --- | --- | --- |
| `AfterRecordAppend` | 记录写入活跃段后、fsync/索引更新前 | 已落盘未应答 |
| `BeforeManifestRename` | `MANIFEST.tmp` fsync 后、rename 前 | 切换前中断 |
| `AfterManifestRename` | rename 完成后、目录 fsync/内存切换前 | 切换后中断 |

测试中以 `panic` 注入模拟进程被杀，`recover` 后重新 `Open` 同一目录验证恢复。

## 运行

```sh
go test -race ./kvstore/   # 全部测试（含并发、崩溃恢复）
go run ./cmd/demo          # 运行样例
```
