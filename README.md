# 热补丁线程切换证明

代码页热替换时，线程可能暂停在旧指令序列内部。为Go补丁控制宿主实现协调组件，补丁计划给出允许迁移的旧新指令边界对应，冻结后读取所有线程位置，只有可映射位置才修改，其他线程等待自然离开或失败退出；写入与指令缓存刷新全部完成后统一恢复。用模拟线程测试迟到冻结、复用线程ID和刷新失败。

## 组件

- `plan.go`：`Plan` 描述一次热替换，包含补丁区域、整页旧/新字节和旧新指令边界映射 `OldToNewPC`；仅映射表中的旧 PC 允许迁移。
- `host.go`：宿主抽象 `Host`（枚举/冻结/恢复线程、读写 PC、读写代码页、刷新指令缓存）与错误定义；线程以 `(ID, Gen)` 引用，ID 复用时旧引用按世代失效。
- `coordinator.go`：`ApplyPatch` 协调器，每轮先冻结全部线程并在 `FreezeWait` 内轮询迟到冻结，再读取 PC 分类：
  - 命中边界映射 → 提交后重定向到新 PC；
  - 位于补丁区外 → 不动；
  - 位于区内但不可映射 → 恢复全部线程，等待其自然离开后重试，超过 `MaxAttempts` 返回 `ErrRetriesExhausted`；
  - 已退出/旧世代引用 → 跳过。
  提交顺序为写新字节 → `FlushICache` → 重定向 PC；刷新失败或屏障后线程消失时回滚旧字节、旧 PC 并恢复线程，最后统一恢复所有冻结线程。
- `sim.go`：内存版模拟宿主 `SimHost`/`SimThread`，支持冻结延迟、线程退出与 ID 复用、缓存刷新失败注入。

## 测试

`go test ./...`（`-race` 同样通过）覆盖：

- `TestBasicMigration`：边界线程迁移、区域外线程不动、统一恢复；
- `TestLateFreeze`：一个线程延迟冻结，协调器在全部冻结前不得打开屏障；
- `TestReusedThreadID`：冻结后线程退出且 ID 被新世代复用，旧引用不被重定向，新世代在不可映射位置阻塞重试、离开区域后补丁成功；
- `TestFlushFailure`：指令缓存刷新失败时页面与 PC 全部回滚、线程恢复并返回错误；
- `TestUnmappableGivesUp`：线程始终停在不可映射指令上，重试耗尽后失败且页面保持不变。
