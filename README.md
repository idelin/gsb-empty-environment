# 多项目发布规划器

在依赖同步发布约束下，求**批次数最少**的发布计划。

## 约束语义

- 若 A 依赖 B，且二者不在同一依赖环上，则 B 必须在**严格更早**的批次发布；
- 同一依赖环（强连通分量）上的项目**必须同批发布**（这是被允许且被强制的）；
- 每批项目数不超过 `capacity`；
- 项目数最多 18 个。

## 输出

- 可行时：最少批次计划，每批附“被一起发布的原因”（依赖环强制同批 / 前置依赖所在批次 / 因容量顺延等）；
- 不可行时：不可行见证——一个大小超过容量的依赖环，含具体环路径（如 `a → b → c → a`）。
  不可行当且仅当存在这样的环：环上项目必须同批，任何计划都装不下。

## 算法

1. Tarjan 求强连通分量并缩点；任一分量大小超过容量即返回不可行见证（含具体环）。
2. 在缩点后的 DAG 上做子集 DP：状态为“已发布的分量集合”（位掩码，≤ 2^18），
   转移为选一个“当前可发布且关于容量极大”的分量子集作为下一批。
   极大性限制不丢最优解：任何已就绪项目提前到当前批不会破坏可行性（交换论证）。
3. 由 DP 回溯出批次划分并生成原因说明。

## 运行

需要 Node.js ≥ 22.6（直接运行 TypeScript，类型擦除）。

```sh
node src/cli.ts examples/release.json   # 或 cat input.json | node src/cli.ts
node test/verify.ts                     # 单元测试 + 2000 例随机交叉验证 + 18 项目性能用例
```

## 正确性核验

`test/verify.ts` 中的穷举核验器（`src/brute.ts`，与求解器完全独立实现）在项目级别
枚举所有分批方案求最少批次；随机小例（1–7 个项目、随机依赖与容量）逐一对比：
求解器与穷举的最少批次数一致、不可行判定一致，且每个计划都通过独立的合法性校验
（分区完整、容量达标、依赖顺序满足）。

## 输入格式

```json
{
  "capacity": 3,
  "projects": [
    { "name": "core" },
    { "name": "web", "dependsOn": ["core"] }
  ]
}
```
