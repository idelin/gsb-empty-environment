# 可修订的令牌桶回放引擎

限流规则复盘工具：请求可能迟到，桶容量和补充速率也可能从历史某个时刻
开始改变。引擎支持在任意历史位置补录请求、整体替换分段配置，并返回
受影响判定的最小连续修订范围；范围之外已稳定的结果保持原身份与版本。

## 文件

- `token_bucket.py` — 引擎：分段配置、增量修订、结果版本化
- `oracle.py` — 独立的全量回放 oracle（不共享引擎任何代码），用于对拍
- `test_token_bucket.py` — 测试；每次变更后与 oracle 比较完整状态序列
- `examples/revision_demo.py` — 修订消费样例

## 语义约定

- 所有数值使用 `Fraction` 精确有理数，分数速率、长时间累计均无浮点漂移。
- 配置为 `Segment(start, capacity, rate)` 列表，按 `start` 升序；每段生效
  区间为 `[start, 下一段 start)`，首段延伸至 `-inf`，末段延伸至 `+inf`。
- 事件按 `(time, seq)` 全序排列；同一时刻的请求按 `seq` 依次判定。
- 补充沿时间轴逐段积分：进入每段先按该段容量截断（处理容量收缩），再按
  速率线性补充并封顶；在事件时刻再按当时生效容量截断一次，因此配置边界
  上的同刻请求看到收缩后的水位。
- 初始状态：首个事件时刻桶是满的。每次判定消费 1 个令牌：
  `level >= 1` 放行，否则拒绝。
- 每条结果记录 `level_before / allowed / reason / level_after / version`；
  `version` 全局单调，重写即换新版本。

## 修订模型

`add_request(time, seq)` 与 `replace_config(segments)` 返回
`RevisionRange(start, end, recomputed_ids, stopped_early, note)`：
修订后事件序列中实际被重算的最小连续下标闭区间。范围之外的记录是
**同一个对象**（`is` 成立）、版本号不变；范围之内的记录全部换新版本。

- 补录请求：从插入位置起重放。配置未变，任何位置都允许提前停止。
- 替换配置：先求新旧配置作为时间函数的差异区间 `[diff_start, frozen_from)`，
  从首个 `time >= diff_start` 的事件起重放；`frozen_from` 之前不允许停止。

## 提前停止的条件

令牌桶的状态转移只依赖 `(当前时刻, 当前水位, 未来配置, 未来事件)`——
无记忆性。因此重放到某事件时，若同时满足：

1. 重算的事前水位、事后水位与该事件的旧记录**逐位相等**（`Fraction`
   精确相等，不存在浮点误差导致的无法收敛）；
2. `event.time >= frozen_from`，即从该时刻起新旧配置逐点相同；

则后续所有事件的判定与状态必然逐位相同，可以立即停止，旧记录保持身份。
只比较事前水位不够：同一水位在不同配置下未来演化不同，所以条件 2 必须
成立；而条件 1 同时保证了当前事件的判定本身不变。

封顶 `min(capacity, ·)` 是收敛的主要来源：空闲足够久后，新旧水位都被
截断到同一容量，差异被精确吸收。若配置差异延伸到无穷远
（`frozen_from = inf`）且水位始终未收敛，则重算到事件末尾——此时范围
仍然是"受影响判定"的最小连续区间。

## 验证方式

测试在每次补录/配置变更后做两类断言：

- 与 `oracle.full_replay` 比较**完整状态序列**（每个判定的时间、前后
  水位、放行结果逐一相等），而非只比较最终桶余量；
- 修订范围之外的记录保持对象身份与版本，范围之内的记录版本全部更新。

## 运行

```sh
python3 -m unittest test_token_bucket -v
python3 examples/revision_demo.py
```
