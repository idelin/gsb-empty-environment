# extsort — 有限内存外排序游标

基于 Python 3.11 标准库（仅 `argparse / hashlib / heapq / json / os / sys`）实现的外部归并排序。

## 记录模型与排序语义

- 记录为三元组 `(key, seq, value)`：`seq` 是记录在原始输入中的序号（从 0 开始）。
- 排序键为 `(key, seq)`，因此是**稳定排序**：键相同的记录严格保持原输入顺序。
- 键必须全部为字符串或全部为数字（不允许混排、不允许布尔/数组/对象）。

## 输入 / 输出格式

输入：JSONL，每行一个对象：

```json
{"key": "apple", "value": {"any": "json"}}
```

`key` 必填，`value` 可选（缺省为 `null`），可以是任意 JSON 值。空行被跳过。

输出：JSONL，每行一个对象，按 `(key, seq)` 升序：

```json
{"key": "apple", "seq": 0, "value": {"any": "json"}}
```

## 命令行

```bash
python3 extsort.py INPUT OUTPUT \
    [--memory-records N]   # 内存预算：最多缓存的记录数（默认 1000）
    [--fan-in K]           # 合并扇入上限，即同时打开的段文件数（默认 8）
    [--work-dir DIR]       # 临时段与清单目录（默认 <OUTPUT>.extsort-work）
    [--keep-work]          # 成功后保留工作目录（默认成功后清理）
```

退出码：`0` 成功；`1` I/O 错误；`2` 输入格式错误 / 段损坏 / 清单不一致。

## 资源约束

- **内存预算以记录数计**：分段阶段最多在内存中缓存 `--memory-records` 条记录；
  合并阶段为流式 k 路游标（`heapq.merge`），堆中最多 `fan_in` 条记录。
- **扇入受文件句柄预算约束**：任何时刻打开的段文件不超过 `--fan-in` 个；
  段数超过扇入时自动进行多轮合并。

## 中断恢复与损坏处理

- 工作目录中的 `manifest.json` 记录：输入指纹（大小 + mtime，纳秒）、已消费输入
  记录数、总记录数、每个临时段的路径 / 记录数 / SHA-256。清单本身通过
  “写临时文件 + fsync + `os.replace`” 原子提交。
- 中断后重新执行同一命令即从清单恢复：已校验的段不重建、已消费的输入不重复读，
  因此**记录数不会因恢复而重复增加**；最终输出前还会校验总记录数。
- **损坏的临时段不会被静默丢弃**：段文件丢失、校验和不匹配、行解析失败、
  记录数不符都会抛出 `CorruptSegmentError`（CLI 退出码 2），且不发布任何输出。
- 输入文件在清单创建后被修改（指纹不符）会拒绝恢复，需删除工作目录重来。

## 原子输出

最终输出先写入同目录的 `<OUTPUT>.tmp-<pid>`，fsync 后用 `os.replace` 原子替换；
任何时候读者要么看到旧的完整输出，要么看到新的完整输出。

## 测试

```bash
python3 -m unittest test_extsort -v
```

覆盖：同键三条记录跨分段/多轮合并的稳定性、与 Python 内建稳定排序对拍、
分段阶段与合并阶段崩溃后的恢复、恢复后记录数不重复、段损坏/丢失/截断检测、
输入变更拒绝恢复、原子替换、空输入、CLI 端到端。所有测试数据均为合成数据。

## 已知限制（未证最优）

- 多轮合并采用简单的“按扇入分组顺序合并”，未做最优合并树（如按段大小
  Huffman 式调度）；I/O 次数未证明最优。
- 键类型须全局一致；NaN 等特殊浮点值的排序行为未定义。
- 输入指纹使用大小 + mtime，理论上存在同大小同 mtime 的伪造变更无法检测。
