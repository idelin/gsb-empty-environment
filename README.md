网关正在迁移已经认证的多路会话，旧客户端的接收队列里可能留有升级前的消息。请为 TypeScript 宿主写可导入的子协议升级准入包。新旧协议是有限的收发状态表，边声明公开消息类型、通道身份、允许发送者和接收者，以及是否授予后续写能力。每通道 FIFO 最多两帧；收发分离，不同通道可独立推进。迁移表可合并协议状态、改消息名和编码，但必须保持初始租户与授权代次，不能把在途回复归到新打开的同名子通道。对任何旧协议可达的切换状态，应用同一迁移表后，新侧能交付的公开行为都应能由旧侧匹配；新侧内部确认步不可见，正常关闭、拒绝、排队后仍不可交付为不同结果。旧侧允许的已排队合法回复也不能被迁移丢掉。需要一份供独立函数验证的精化关系证书，其中既有协议状态也有队列内容和能力持有者。宿主可以提供通道独立性提示帮助缩减搜索；验证器必须核对两步是否共享权限、队列或撤销源，不可信的独立性声明不能让检查漏掉跨通道授权。用小配置完整状态空间比对，另给八条真正独立的通道，验证内存不会按全局交错数增长。输出只用于部署准入，不发送网络消息。
