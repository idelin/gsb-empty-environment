# chunkstore

内容寻址的分块值存储。纯 Go 标准库，所有文件落在调用方指定的目录中。

## 布局

```
<dir>/blocks/<hex[0:2]>/<hex>   内容寻址块文件（sha256 摘要即文件名）
<dir>/meta/state.json           已提交的元数据事务镜像
```

## 设计

- **大值分块 + 内容摘要共享**：`Put` 以固定块大小流式切分，每块按 sha256
  摘要寻址落盘；相同内容的块只存一份，多个值天然共享。
- **元数据事务维护引用**：`meta/state.json` 保存 值→块列表 映射和每块引用计数。
  提交方式是 临时文件 + fsync + rename + 目录 fsync，单次 rename 原子生效。
- **读取校验每块**：`Get` 逐块重算 sha256 并与摘要比对，不一致返回 `ErrCorrupt`。
- **只回收无引用块，常规写入不扫描数据目录**：覆盖/删除/回滚只处理引用计数
  归零的块（计数来自内存中的元数据，提交前已算好），从不遍历 `blocks/`。
  唯一的全量扫描在显式调用的 `CollectGarbage` 中。
- **故障注入点**：`FaultInjector`（返回错误）与 `SetPointHook`（模拟崩溃的
  回调）作用于三个命名点：`block.write`、`meta.commit`、`reclaim`。

## 崩溃恢复与断电保证的边界

**保证的：**

- 块文件经 临时文件 + fsync + rename + 目录 fsync 落盘：已提交的块永远不会
  是撕裂写（torn write）的产物。
- 元数据提交是单次原子 rename：崩溃后 `state.json` 要么是完整的旧状态，
  要么是完整的新状态，不存在中间态。`Open` 时丢弃未提交的 `.tmp` 镜像。
- 已提交的值在崩溃/断电后不丢失、不可见部分写入。

**不保证的（只损空间，不损正确性）：**

- 崩溃发生在块写入与元数据提交之间 → 新块成为孤儿，泄漏空间。
- 崩溃发生在元数据提交之后、回收零引用块之前 → 零引用块泄漏空间。
- 两类泄漏都由显式的 `CollectGarbage` 扫描回收；常规写入路径绝不为此扫描。
- 磁盘静默损坏（bit rot）无法预防，但读取时的逐块摘要校验一定能发现。

