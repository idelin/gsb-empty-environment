# 工单路由分析器

分析工单路由规则在两个方面的可靠性：

1. **终止性**：是否所有输入（任意队列 + 任意字段取值组合）都会在有限步内
   到达“无规则命中”的状态；若不终止，给出可进入循环的**最小输入**、
   到达循环的最短路径以及循环本身。
2. **最终队列唯一性**：当多条规则同时命中时，不同的合法选择是否可能导致
   不同的最终队列；若可能，给出**最小输入**和两条导向不同最终队列的最短路径。

## 方法

字段取值有限，因此状态 = (队列, 各字段取值) 构成**有限状态空间**。
分析器枚举全部状态并构建迁移图（每个命中规则产生一条迁移），在图上做：

- 终止性：Kosaraju 求强连通分量，非平凡分量或自环即循环；反向 BFS 找出
  所有可到达循环的状态，取编号最小者为最小输入，BFS 给出最短路径与循环。
- 唯一性：对每个队列做多源反向 BFS，得到每个状态可终止于哪些队列；
  任一状态可终止于两个以上队列即违规，BFS 重构两条见证路径。

这是**显式状态空间探索**，而非规则间的静态引用环检查——规则互相引用
但被字段守卫隔开时不会误报（见 `TestGuardedStaticCycle`），反之字段值
变化形成的动态循环也不会漏报。

“最小输入”按状态编码字典序（队列、字段1、字段2…）取编号最小者。

## 输入格式

JSON 文件（或标准输入）：

```json
{
  "queues": ["triage", "support"],
  "fields": [{"name": "priority", "values": ["low", "high"]}],
  "rules": [
    {
      "name": "to-support",
      "when": {"queue": "triage"},
      "set":  {"queue": "support"}
    },
    {
      "name": "bounce-back",
      "when": {"queue": "support", "fields": {"priority": "low"}},
      "set":  {"queue": "triage"}
    }
  ]
}
```

- `when` 中未指定的队列/字段不参与匹配；`set` 中未指定的部分保持不变。
- 执行语义：从初始状态起，反复应用任一命中规则，直到无规则命中；
  多条规则同时命中时视为非确定选择，分析器枚举所有合法选择。

## 使用

```sh
go run . examples/loop.json      # 或: go run . < rules.json
go test ./...
```

- 退出码：0 = 全部输入终止且最终队列唯一；1 = 发现问题；2 = 输入无效。
- `-max-states N`：状态空间上限（默认 2,000,000），防止误分析超大规则集。

示例见 `examples/`：`loop.json`（循环）、`ambiguous.json`（最终队列不唯一）、
`ok.json`（健康规则集）。
