# bcast — 广播队列

一份载荷共享给多个订阅者；只有当接收集合（receive-set ledger）中所有
应收者都确认后，消息才被回收并释放容量槽位。

## 语义

- **两阶段发布**：`Begin` 预留序号与容量槽位；`Commit` 快照当前订阅者
  集合作为接收集合，消息自此可见。`Publish` = `Begin` + `Commit`。
- **不追认旧消息**：`Commit` 之后加入的订阅者不在该消息的接收集合中，
  永远收不到它。
- **退出视为确认**：`Unsubscribe` 会把离开者从所有未读消息的接收集合中
  移除，可能触发回收并释放容量。
- **取消已提交的发布**：`Cancel` 在 `Commit` 之后调用是 no-op，但仍返回
  已提交的序号；`Commit` 之前调用则丢弃预留并释放槽位。
- **容量**：预留中的发布与未回收的消息共同占用容量；满时 `Begin` 返回
  `ErrFull`，回收（全部确认 / 订阅者退出 / 无接收者立即退役）后释放。

## 验证

- `broadcast_test.go`：脚本化交错 —— 慢消费者阻塞回收、退出重入不补发
  旧消息、取消已提交仍返回序号、容量释放交错。
- `model_test.go`：以接收集合账为参照模型，随机交错
  发布/提交/取消/订阅/接收/确认/退订，每一步比对
  `Used`/`Live`/`Pending`/`Reclaimed` 账本；最后全部退订必须排空。
  另含 `-race` 并发冒烟测试。

```sh
go test ./...
go test -race ./...
```
