PromQL 引擎中两项最常写错的语义分别是**二元向量基数匹配**与**子查询时间网格对齐**：在 `A / on(instance) group_left(role, region) B` 这类多对一运算中，标签匹配组必须先按 `on(...)` 或 `ignoring(...)` 确定（若为算术运算如 `+`/`-`/`*`/`/` 或带 `bool` 修饰符的比较运算，结果会自动剥离 `__name__` 标签；而不带 `bool` 的过滤比较运算必须**保留**左侧的 `__name__` 标签！），`group_left` 要求右侧在每个匹配键下至多 1 条序列（多于 1 条立刻报基数冲突错误！），且把右侧指定的额外标签复制到结果时，若该标签已存在于左侧且值不同或重复包含在匹配键内也必须精确校验；而子查询 `expr[range:step]` 的采样点绝不是从求值时刻 `t` 倒推 `t, t-step, ...`，而是严格对齐到全局纪元整数倍网格 `floor(t / step) * step` 往前覆盖 `(t - range, t]`，并且当表达式同时带有 `@ <unix_ts>` 与 `offset <dur>`（支持负 `offset`！）时，必须先将求值时间锚定到 `@` 再减去 `offset`！为监控查询引擎交付可导入的 TypeScript PromQL 向量匹配与子查询求值包。规则：1）支持瞬时向量二元算术（`+`/`-`/`*`/`/`/`%`/`^`）、比较（含 `bool` 修饰符切换 0/1 输出 vs 过滤输出与 `__name__` 保留差异）及集合运算（`and`/`or`/`unless`）；2）完整实现 `on`/`ignoring` 与 `group_left(labels...)`/`group_right(labels...)` 的 1:1、N:1、1:N 匹配、重复键/标签冲突检测与确定性标签合并；3）支持嵌套子查询 `expr[range:step]`（含缺省 step 回退全局默认步长）、`@ start()`/`@ end()`/`@ <ts>` 与正负 `offset` 组合及外层区间聚合（`max_over_time`/`avg_over_time`/`count_over_time`/`quantile_over_time`）；4）正确处理 IEEE 754 `NaN` 与 StaleNaN 过滤语义（与 `NaN` 比较在过滤模式下丢弃、在 `bool` 模式下 `!=` 返回 1 其余返回 0！）。验收覆盖 `bool` vs 非 `bool` 比较对 `__name__` 的差异、`group_left`/`group_right` 多对一复制与右侧重复键报错、子查询全局步长对齐边界（`t` 非步长整倍数）、`@` + 正负 `offset` 组合及 `and`/`or`/`unless` 语义验证。
