内存安全运行时在自研隔离堆分配器中引入 Safe-Linking（`ptr ^ (pos >> 12)`）、随机 Canary、隔离释放队列（Quarantine）与页尾 Guard Page 防御 UAF、Double-Free 与 Tcache/Fastbin 中毒时，若释放路径未校验对齐、块头完整性或跨区段指针归属，攻击者通过单字节溢出或释放后写即可篡改空闲链表指针实现任意地址分配。为 C++17 运行时安全宿主实现零外部依赖、`-Wall -Wextra -Wconversion -Werror` 编译通过的受保护内存池分配器与堆完整性审计库（工作在调用方提供的对齐内存区域上，严禁破坏进程全局堆）。分配器维护分大小类（size-class）空闲链表、每块独立前后 Canary（绑定块地址与池密钥的混合哈希防跨块移植）、双状态位图（已分配/隔离区/空闲）及固定长度 FIFO 隔离区（防止立即重用触发 UAF）：所有空闲链表 `next` 指针按 Safe-Linking 编码并额外附带轻量校验标签；每次 `alloc`/`free` 严格校验指针落在合法托管区间且满足 16 字节对齐、在分配位图中处于精确 `IN_USE` 状态（拦截任意偏移假块与 Double-Free）、块头大小类与实际 slab 元数据一致、前后 Canary 未被破坏（检出 1 字节线性溢出）以及解链后的目标块处于合法空闲状态且不与任何已分配块重叠（拦截链表中毒与块重叠）。对外同时暴露故障注入与攻击原语自检接口，实测拦截 Double-Free、UAF 覆写 `next` 指针、伪造未对齐 Fake Chunk、跨块复制 Canary 绕过与 1 字节 Off-by-One 溢出，且全部合法高频分配释放工作负载数据零损坏。
