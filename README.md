消息中间件采用协同增量再平衡（Cooperative Rebalance）避免全组停顿，任何需要换主的分区必须先在第一轮由旧消费者主动撤回、绝不可在同一轮直接交给新消费者，第二轮才分配已撤回分区。为组协调器交付可导入的 Go 规划包。输入主题分区集合（每分区带副本所在机架集合）、消费者列表（每消费者带所属机架、订阅主题集合与当前已持有分区集合，可能含刚离线消费者遗留的无主分区与不可迁出的静态置顶约束）。目标是在所有分区均被合法订阅者持有、每消费者所获分区数极差最小（全局均衡，考虑订阅异构性）、优先满足本地机架副本命中数最大的前提下，使总迁移分区数（需撤回再重分）最少；并列按最终归属向量字典序最小。组件输出两阶段执行计划：第一轮每个消费者须保留与须撤回的分区集合及立即可分给消费者的原无主分区集合，第二轮最终归属映射，并断言任意分区在第一轮绝不同时归属两个消费者。验收在消费者不超过六、分区不超过十的小实例上用全枚举对照均衡度、机架命中数与最小迁移数，覆盖消费者退组留无主分区首轮直分、异构订阅下的非均匀最优均衡、跨机架换迁与粘性冲突，以及无任何合法订阅者时准确报错。
