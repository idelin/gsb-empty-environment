沙箱代理复制受控进程描述符时，若同进程组多线程共享文件描述符表（`CLONE_FILES`）并发调用 `dup2` 或通过未封写 `memfd`/`O_PATH` 偷换对象，仅冻结单一线程无法阻断 TOCTOU 攻击。为 C++20 沙箱代理实现可导入的 `pidfd` 能力隔离组件：目标身份绑定 `pidfd` 启动时间、exec 代次、命名空间、凭据及共享 `files_struct` 组；复制前后通过注入内核接口检查全部共享同一 fd 表的同组线程状态，若内核接口不能原子保证须冻结整个共享 fd 组后再校验并复制。新增识别并拦截未带 `F_SEAL_WRITE` 的 `memfd` 替换、`O_PATH` 描述符升级以及经 `SCM_RIGHTS` 传入的跨安全域 fd 溯源校验；返回带租约期限与操作衰减掩码的受限代理句柄而非裸 fd，且在任意并发关闭、线程退出、exec 或撤销竞态失败路径下均满足零 fd 泄漏不变量。在 `SimKernel` 中验证同组多线程并发 `dup2`、未封 `memfd` 偷换、`SCM_RIGHTS` 越域、fd 回收零泄漏与合法只读复制。
