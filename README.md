基础设施配置语言与嵌入式查询编译器常采用 Hindley-Milner（HM）类型系统来兼顾零注解推导与多态复用，但在同时引入**可扩展行多态记录（Extensible Row Polymorphism `{a: Int | r}`）**与**可变引用（`ref`、`!`、`:=`）**时，若按教科书朴素 Algorithm W 实现会立即出现两类致命类型漏洞：1）**缺失值限制（Value Restriction）导致的 unsoundness**——对 `let r = ref(nil) in (r := cons(1, nil); head(!r) + 'x')` 这类表达式，如果像纯函数一样对 `ref(nil)` 的结果类型 `Ref<List<'a>>` 做了 `forall 'a` 泛化，就会允许先写入整数再当字符串读出破坏类型安全！必须实施严格的值限制：仅当 `let x = e1 in e2` 的右部 `e1` 属于语法非扩张值（常量、变量、lambda、由语法值构成的记录/元组构造，绝不含函数应用或 `ref(...)` 分配！）时才允许泛化自由类型变量，非值则保持单态类型变量！2）**Rémy 风格行多态统一与缺席约束（Lacks Constraint）**——记录支持字段投影 `r.x`、字段扩展 `{x = e | r}` 与字段删除 `{r \ x}`，行合一（Row Unification）在两记录字段顺序不同、共有字段嵌套多态、或用同一行变量 `rho` 同时扩展两次同名字段时必须精准处理：追踪每个行变量的禁止字段集 `lacks(rho, {f1, f2})` 防止重复字段冲突，并执行完整的 **Occurs Check**（不仅检查普通类型自包含如 `'a = 'a -> Int`，还必须拦截行变量自包含如 `rho = {x: Int | rho}` 防止无限循环崩溃！）。为嵌入式策略/查询编译器交付可导入的 TypeScript HM + 值限制 + 行多态类型推导核。验收覆盖 `let` 多态实例化、值限制拦截 `ref(nil)` 漏洞、非顺序行多态记录合一与 `lacks` 重复字段拒绝、普通与行变量 Occurs Check 无限类型拦截及规范主类型输出校验。
