软件供应链网关在离线验证 OpenPGP（RFC 4880 / 9580）二进制签名与公钥证书时，若解析器混淆 Signature 包中的已哈希子包区（Hashed Subpackets）与未哈希子包区（Unhashed Subpackets）、忽略密钥吊销签名或放过尾部拼接的未签名文本/重复 Literal Data 包，攻击者无需私钥即可篡改签名创建时间、伪造签发者标识或夹带恶意代码骗过验签。为 Go 供应链安全宿主实现可导入的原始字节级 OpenPGP 数据包解码与安全验签包，严禁依赖第三方 OpenPGP 库（仅用标准库 `crypto/ed25519`、`crypto/sha256`、`crypto/sha512`）。组件按新/旧两种包头格式完整解码包长（含 1/2/5 字节长度与部分体长度，硬拒绝越界、截断与非法嵌套），解析 Public-Key/Public-Subkey（v4）、User-ID、Literal Data 与 Signature（v4）包；严格区分 Hashed 与 Unhashed 子包——强制要求 `Signature Creation Time`、`Key Expiration Time`、`Key Flags`、`Key Revocation Reason` 与 `Issuer Fingerprint` 等全部安全决策子包必须位于 Hashed 区（若仅出现在 Unhashed 区一律忽略或拒收），且遇到带关键位（`critical=1`）的未知子包必须立即拒绝整条签名。验签逻辑完整执行 RFC 4880 §5.2.4 规范摘要拼接（含 `0x04` 尾缀与大端 4 字节已哈希头长），核验主钥与签名子钥绑定签名（含双向主钥绑定防子钥盗用）、拒绝已吊销或超期密钥以及无 `Sign Data` 标志的加密子钥越权签发，并拦截单消息内混入多个 Literal Data 包或签名外未覆盖载荷。用手工构造的二进制合法签名与 Unhashed 注入、未知关键子包、吊销子钥及双 Literal 拼接样本实测拦截。
