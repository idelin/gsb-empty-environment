# volmap — 逻辑偏移到不可变物理块的区间映射

纯标准库实现的写时复制（copy-on-write）卷。逻辑地址空间被划分为
互不重叠的区间，每个区间指向一个**不可变物理块**内的某段偏移；
未映射区域即“洞”，读为零且不占用任何实体块。

## 数据模型

调用方指定一个目录，卷的全部状态都在其中：

```
<dir>/
  blk-0000000000000000   # 不可变物理块，写入后永不修改
  blk-0000000000000001
  manifest.json          # 清单：活跃区间映射 + 全部快照 + 分配水位
```

- **写入**：数据落成一个全新的物理块，旧区间在覆盖边界分裂，
  仅覆盖区被替换（跨块写入只改覆盖区，两侧原样保留）。
- **打洞**：把覆盖区间从映射中移除（中段打洞时两侧分裂保留，
  仍指向原物理块），洞内读为零；失去引用的块被回收。
- **快照**：复制当前区间映射。之后的写入/打洞只改活跃视图，
  快照引用的块因仍被引用而保留，旧快照不受后续打洞影响。
- **分裂/合并**：区间始终保持升序、不重叠；相邻且指向同一块
  连续偏移的区间自动合并。

## 提交协议与故障注入

每次修改按以下顺序提交（`volume.go` 的 `commitLocked`）：

1. （写入时）块数据写临时文件 → fsync → rename 为 `blk-<id>` → fsync 目录
2. 清单写 `manifest.json.tmp` → fsync
3. rename 为 `manifest.json`（原子替换）
4. fsync 目录
5. 回收失去引用的物理块

`FaultHook` 在三个注入点被回调（`fault.go`）：块已落盘清单未写、
清单临时文件已落盘未 rename、rename 完成目录未 fsync。
返回 error 表示操作中止（内存状态回滚到上一提交）；panic 模拟进程崩溃。

## 进程崩溃恢复

`Open` 时执行恢复：

- 丢弃未 rename 的 `manifest.json.tmp`——rename 的原子性保证
  `manifest.json` 要么是旧的完整版本，要么是新的，绝不撕裂；
- 回收不被清单引用的孤儿物理块（块已写盘但清单未提交）和
  残留的块临时文件。

因此崩溃后卷的状态恰好等于**最后一次成功提交**或**本次操作完整生效**，
二者之一，不会出现半个写、半个洞。

## 断电保证的边界

- **保证**：`Write` / `PunchHole` / `Snapshot` 返回 nil 时，该操作已
  持久化（块与清单均已 fsync，目录项已 fsync），断电后不丢失。
- **保证**：断电发生在操作中途时，卷回退到上一次已提交状态，
  且下次 `Open` 自动完成清理。
- **依赖**：文件系统需提供 rename 原子性与 fsync 语义
  （ext4/xfs/apfs 等日志文件系统均满足）；我们不防御
  物理块文件自身被断电撕裂后文件系统谎报 fsync 成功的硬件。
- **不保证**：操作返回前断电，该操作本身可能丢失（但绝不损坏卷）；
  快照/写/打洞之间没有多操作事务，批量一致性需调用方自行串行化。

## 运行样例

```
$ go run ./cmd/voldemo
两个块写入后:                      "AAAAAAAAAAAAAAAABBBBBBBBBBBBBBBB"
跨界写 [12,16) 后:               "AAAAAAAAAAAAxxxxBBBBBBBBBBBBBBBB"
打快照: id=0
打洞 [8,24) 后(洞读为0):           "AAAAAAAA\x00...\x00BBBBBBBB"
旧快照不受打洞影响:                 "AAAAAAAAAAAAxxxxBBBBBBBBBBBBBBBB"
重开后(崩溃恢复)状态:               "AAAAAAAA\x00...\x00BBBBBBBB"
```

## 测试

```
$ go test ./...
ok  	volmap
```

覆盖：基本读写与重开持久化、跨块写只改覆盖区、打洞中段两侧保留、
洞读零且回收物理块、快照免疫后续打洞、随机操作对模型校验区间不变式、
三个注入点的写/打洞崩溃恢复、孤儿块回收、注入错误时状态回滚。
