# thermosim

Go 控制模拟器：显式温度样本驱动的恒温开关 + 多控制器共享最大开启数的全局仲裁。

## 恒温控制器（`Controller`）

每个显式样本到来时判定一次：

- `temp >= Upper` → 关闭（上阈值优先检查，等阈值时落在关闭）
- `temp <= Lower` → 开启
- 两者之间 → 保持当前状态（及待请求状态）

约束：

- **最短驻留**：每次切换后须驻留 `MinDwell` 才能再次切换；样本要求切换而驻留未满时，决定延迟到下一个样本重新判定。
- **不插补样本**：模拟器完全由样本驱动，所有切换只发生在真实样本时间点上，绝不在样本之间插补切换。
- **迟到样本拒绝**：样本时间戳必须严格递增，重复或乱序样本返回 `ErrLateSample` 且不改变任何状态；后续正常样本到达即恢复处理。

## 全局仲裁器（`Arbiter`）

- 最多允许 `MaxOn` 个控制器同时开启。
- 仲裁器**从不强制关闭**任何控制器：容量只在控制器自身恒温逻辑关闭时释放，因此个体驻留时间不会被全局仲裁打断。
- 需求超出容量时，请求保持**待请求（pending）**；容量恢复后按 **优先级（小者优先）→ 等待序号（先申请者先）** 授予。
- 等待中的请求若温控不再要求开启（温度越过上阈值），自动取消，等待位置让给后续请求者。

## 虚拟时钟

测试用显式时间戳（`at(min)` 分钟偏移）充当虚拟时钟，逐步推进时间线并核对：

- 时间线状态表：保持 / 等阈值 / 驻留延迟 / 切换事件时间（`controller_test.go`）
- 迟到样本拒绝与恢复（`controller_test.go`）
- 全局容量上限、驻留不可抢占、优先级与等待序号、恢复后的等待顺序（`arbiter_test.go`）

## 运行

```sh
go test ./... -v
```
