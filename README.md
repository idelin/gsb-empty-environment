把复杂 SQL `WHERE` 谓词编译成复合 B-Tree 索引（如 `(k1 ASC, k2 DESC, k3 ASC)`，支持每列独立 `NULLS FIRST`/`NULLS LAST`！）上的一组互不相交、严格按物理索引序排列的扫描区间 `[start, end]` 是数据库执行引擎最容易出现边界漏行或重扫的模块之一：1）行值比较器（Row-Value Constructor）如 `(k1, k2) > (10, 20)` 在混合升降序 `(k1 ASC, k2 DESC)` 下**绝不是**一个单一连续物理区间，因为 `k1 > 10` 在物理键上往后延伸而 `k1 = 10 AND k2 > 20` 在 `k2 DESC` 物理序上反而排在 `(10, 20)` **之前**，必须精确拆解为两个互不重叠、按物理索引序重排的独立扫描区间！2）`IN (...)` 与 `OR` 叠加嵌套比较（如 `k1 IN (1, 3, 2) AND k2 BETWEEN 5 AND 10` 或两段部分重叠的析取区间）必须去重合并并按物理索引键序输出无重叠区间（防重复扫描同一行！）；3）对字符串列的 `LIKE pattern ESCAPE ch` 前缀提取必须先精确解析转义序列（区分字面 `\%`/`\_` / `\\` 与通配符 `%`/`_`，非法末尾孤立转义符立刻报错！），提取最长精确字面常量前缀 `P` 并计算物理紧邻上界 `nextPrefix(P)`（正确处理尾字节为 `0xFF` 的进位与全 `0xFF` 无上界情况，且在 `DESC` 列上反转开闭端点！）。为数据库索引访问层交付可导入的 Go 复合索引规范扫描区间编译与校验包。规则同时支持标量/行值比较、`BETWEEN`、`IN`、`IS [NOT] NULL`、`LIKE ... ESCAPE` 及 `AND`/`OR` 组合，输出规范化的有序互不重叠物理索引扫描区间列表与残余谓词，并内置 B-Tree 物理键排序对照扫描器，在含 `NULL`、混合 `ASC`/`DESC`、`0xFF` 字节串与重叠 `OR` 条件的测试集上校验编译区间扫描 + 残余过滤的结果与全表逐行过滤 100% 逐行一致且绝无重复扫描任何物理键。验收覆盖混合 `ASC/DESC` 行值比较拆分重排、`NULLS FIRST/LAST` 边界、`OR`/`IN` 区间合并去重、`LIKE` 转义与 `0xFF` 上界进位及与全表扫描逐行零差异校验。
