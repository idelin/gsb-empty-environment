联邦身份基础设施在按 OpenID Federation 1.0 解析叶实体至信任锚（Trust Anchor）的实体声明链（Entity Statements）并合并多层元数据策略（Metadata Policy）时，若解析器未拦截 `authority_hints` 循环、忽略 `constraints.max_path_length`/`naming_constraints`，或在合并 `value`/`add`/`default`/`one_of`/`subset_of`/`superset_of`/`essential` 策略算子时违反单调收紧原则，下级中间机构可放宽上游安全限制或劫持外部域命名空间。为 TypeScript 身份联邦宿主实现可导入、零外部联邦库依赖（仅用 `node:crypto`）的信任链构建、约束核验与策略求交引擎，严禁联网。组件支持真实 ES256 签名实体声明解析：从叶实体配置出发沿 `authority_hints` 与下级声明构建全部可达至指定 Trust Anchor 的有效链（自动检测并拒绝环路、过期声明、主体 `sub`/`iss` 错配与密钥缺失）；逐级核对 `constraints`——精确实施 `max_path_length` 剩余跳数递减、`naming_constraints`（`permitted`/`excluded` DNS 后缀子树，排除优先）及 `allowed_entity_types` 白名单。对元数据策略合并，严格按规范实现七大算子的逐级复合（上级策略优先且下级只能收紧不能放宽，如 `subset_of` 取交集、`superset_of` 取并集、`one_of` 取交集、`value` 冲突或与 `one_of`/`subset_of` 矛盾即报错、`essential=true` 不可被下级改为 `false`），并将最终策略应用到叶实体元数据验证其合规性（检出缺失必填项或违背值域）。附多路径分叉、策略冲突、命名约束越权与循环引用测试集验证零误判。
