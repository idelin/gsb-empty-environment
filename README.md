# treeedit — 有序标号树最小编辑代价工具

计算两棵**有序标号树**之间的最小编辑代价（插入 / 删除 / 改名），输出操作
序列与源↔目标节点映射，并对结果做双重独立验证。

## 操作语义

- **delete(node)**：删除单个节点，其孩子按顺序提升到它原来的位置。
  代价为 `Del(label)` 一次——**不会**按整棵子树计费。
- **insert(node, parent, index, adopt, label)**：`delete` 的精确逆操作。
  新节点成为 `parent`（0 表示森林顶层）的第 `index` 个孩子，并收养紧随
  其后的 `adopt` 个连续兄弟作为自己的孩子。代价为 `Ins(label)`。
- **rename(node, label)**：修改节点标号，代价 `Ren(old, new)`。

编辑过程中中间状态可以是有序森林（删除根会产生多棵树，插入可以在顶层
收养它们），最终必须恰好剩一棵等于目标树的树。

## 用法

```sh
go run . -src tree1.json -tgt tree2.json [-costs costs.json] \
    [-exhaustive-max-nodes 12] [-exhaustive-max-states 300000]
```

- 树：`{"label":"a","children":[...]}`（JSON，有序）。
- 代价表（全部为非负整数，均可选，默认为 1）：

```json
{
  "insert": 1, "delete": 1, "rename": 1,
  "insertLabel": {"a": 2},
  "deleteLabel": {"b": 0},
  "renamePair": {"a>b": 3}
}
```

- 输出（JSON）：`distance`、`mapping`（源/目标节点的后序编号 + 路径 +
  是否改名）、`operations`（操作序列）、`verification`（两项验证结果）。
  任一验证失败时进程以非零码退出。

## 正确性要点

- **DP**：Zhang-Shasha 算法，回溯时记录森林矩阵每个格子的选择以恢复
  映射；只有"双根"格子的 match 才直接产生映射对，整子树 match 递归
  处理，且跳过整棵子树（`l(x)-1`），保证映射一一对应且保序。
- **代价闭包**：代价表只需非负，不必满足三角不等式。若 `a→x→b` 比直接
  `a→b` 便宜，或"插入便宜标号再改名"比直接插入便宜，脚本可以利用它。
  因此先对改名代价做 Floyd-Warshall 最短路闭包，并相应归一化插入/删除
  的有效代价；DP 在有效代价上求值，脚本生成器把每条最短路还原成真实的
  操作序列，使应用器按原始代价表核算的总价等于 DP 距离。
- **操作序列生成**：由映射模拟生成——后序删除未映射源节点（孩子提升）、
  前序插入未映射目标节点（位置 = 其在目标兄弟中的下标，收养其"最上层
  已映射后代"构成的连续块）、按最短路链执行改名。生成器自检模拟结果
  等于目标树。
- **独立应用器**（`apply.go`）：不共享生成器代码，从头解释操作序列并按
  原始代价表计费；删除始终按单节点计费（孩子提升），杜绝把整棵子树的
  删除成本误算进来。
- **穷举复算**（`exhaustive.go`）：短树（默认 `n1+n2 ≤ 12`）上用 Dijkstra
  在森林状态空间上按原始代价重新搜索最短路。状态有限（节点数封顶、标号
  集合有限）且每个状态只结算一次，**零代价操作不会造成搜索循环**；超出
  状态预算时报告 `inconclusive` 而非误判。

```sh
go test ./...
```

包含：已知距离用例（含插入收养、根删除成森林、改名链、零代价表）、
