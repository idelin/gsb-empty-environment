现代链接器（LLD / Mold 风格）用 `--gc-sections` 裁剪未引用段，并用 `--icf=safe`（Safe Identical Code Folding）把指令字节与重定位完全同构的冗余模板函数折叠为同一份副本以大幅缩减二进制体积；但一旦忽略相互递归同构或 C/C++ 函数指针身份语义，就会错漏大量折叠或破坏 `fp1 == fp2` 比较！核心规则包括：1）**段级垃圾回收（`--gc-sections`）**：输入多目标文件段图（代码段、只读数据段、普通数据段、重定位边表——标注每条重定位是直接调用 `CALL` 还是取地址 `ADDR_TAKEN`！）、入口符号根集及 `SHF_KEEP` 强制保留段（如 `.init_array`/导出表），经有向可达性搜索精确回收所有不可达段并保留完整有效重定位；2）**基于 Moore 分区细化的相互递归同构折叠**：仅比较原始指令字节加目标符号名会漏掉自递归（`f` 调 `f`、`g` 调 `g`）和相互递归环（`f1<->f2` 与 `g1<->g2`）——必须先把所有候选只读/代码段按“(非重定位原始字节, 重定位偏移与类型序列)”做初始划分，随后每轮把重定位目标符号替换为目标段当前的等价类 ID 重新细化划分，迭代至不动点收敛，精准捕获自递归与任意长度互递归同构等价类！3）**`--icf=safe` 函数指针地址身份保护 vs `--icf=all`**：若两个代码段均存在来自存活段的 `ADDR_TAKEN` 重定位（意味着程序可能比较它们的函数指针是否相等！），`--icf=safe` **绝不可**把它们折叠到同一个地址！但允许把任意多个**未被取地址**的同构函数安全折叠到同一个已被取地址（或同未取地址）的代表函数上，且带全局可写数据或显式 `NO_ICF` 标记的段严禁折叠；4）折叠后重写全部指向被合并段的重定位到规范代表段，并内置 IR/段解释器校验折叠与裁剪前后所有函数调用返回值与函数指针相等性判断 100% 与原程序一致！为链接器工具链交付可导入的 Go `--gc-sections` 与 Moore 分区细化 Safe ICF 引擎。验收覆盖不可达段精准裁剪、`SHF_KEEP` 根保留、自递归与互递归环同构合并、`--icf=safe` 保护双 `ADDR_TAKEN` 指针不等 vs 允许未取地址并入已取地址，以及解释器结果与指针身份 100% 等价。
