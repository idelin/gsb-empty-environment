TLS 1.3 记录层把多种内容类型（Handshake、Alert、ApplicationData、ChangeCipherSpec）封装在长度不超过 16384 字节的明文片中，在 0-RTT 早期数据被拒绝、密钥纪元切换（Initial -> Handshake -> Application -> KeyUpdate）和跨记录分片并发出现时，极易违反 RFC 8446 的边界禁令产生安全漏洞。为协议栈交付可导入的 Go 记录层重组与校验包（密码加解密由调用方注入按纪元键控的 AEAD 回调，聚焦协议状态机与边界校验）。输入按任意字节块切分的输入流、当前解密纪元切换指令（由上层握手逻辑触发）及 0-RTT 拒收最大可跳过字节上限 `maxEarlyDataSkip`。严格执行 RFC 8446 规则：(1) 握手消息和告警消息严禁零长度分片，应用数据允许零长度分片；(2) 明文分片严格 ≤16384 字节、密文载荷 ≤16384+256 字节，超限立即报 `record_overflow`；(3) 同一条记录内禁止混拼不同内容类型，且任何导致密钥纪元变更的握手消息（如 `ServerHello`、`Finished`、`KeyUpdate`）之后必须对齐记录边界——若同一条记录尾部还夹带后续字节须立即报 `unexpected_message` 拒绝；(4) 0-RTT 被拒期间，连续解密失败的密文记录按 `maxEarlyDataSkip` 累加跳过，超额报错 `bad_record_mac`，一旦命中合法 Handshake 纪元记录则关闭跳过模式并正常交付；(5) `ChangeCipherSpec` 仅允许在握手未完成期间以单字节 `0x01` 出现并静默忽略，握手完成后出现须报错。验收用按单字节与随机分片喂入对比 RFC 8446 边界样例，覆盖跨三条记录的大握手消息重组、纪元切换消息尾部夹带越界数据拦截、0-RTT 跳过刚好达上限与超 1 字节报错、以及零长度握手/应用记录区分。
