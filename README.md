自治系统边界路由器在同时启用 RPKI ROA、ASPA（Autonomous System Provider Authorization）与 BGPsec 路径签名时，若验证器忽略多跳客户-提供商谷地约束或允许伪造 `pCount=0` 跳数压缩，恶意中间 AS 仍能制造路由泄漏或缩短路径劫持流量。为 Go 路由控制面宿主实现可导入的联合路径安全验证与对抗搜索包，严禁联网。系统维护带有效期的 ROA 前缀表（含 `prefix`、`maxLength` 与 `originASN`）、按客户 AS 索引的 ASPA 提供商集合（区分显式空集 `AS0` 与未发布记录）以及可信 BGPsec 路由器公钥表（真实 Ed25519/ECDSA-P256 验签）。验证入口接收本地视角角色（`customer`/`provider`/`peer`/`rs`/`rs-client`）、IPv4/IPv6 目标前缀、完整 `AS_PATH`（支持 `AS_SET` 拒绝与相邻重复去重）及逐跳 BGPsec `Secure_Path` 与 `Signature_Block`：先按 RFC 8205 反向链式核对每跳 `pCount`、目标 AS、前驱签名与前缀绑定（拒绝篡改前缀、截断尾部或非法 `pCount`），再按 ASPA 完整上坡/下坡（up-ramp/down-ramp）算法精确判定 `Valid`/`Invalid`/`Unknown`（严格区分客户侧收路须全上坡且无环、提供商/对等侧收路须上坡顶点与下坡顶点相邻或重叠，且任一环节出现非授权提供商即判 `Invalid`），同时联合 ROA 校验起源 AS 与 `maxLength` 合法性。另实现有界图对抗搜索器：给定不超过 12 个 AS 的拓扑、策略关系与部分腐化节点集合，搜索能绕过缺失 ROA 或弱单边校验的最短路由泄漏/路径缩短攻击链，并以小规模全路径枚举参考模型交叉验证无漏判。
