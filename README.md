# IMA签名属性评估

IMA 评估靠文件扩展属性里的签名决定能否执行，攻击者能写属性时会换成只带摘要的格式，或把属性长度写得超出实际，诱使解析越界。为Go完整性引擎写供执行与映射前调用的评估包：本题约定属性头为类型 1 字节、版本 1 字节（须为 2）、算法 1 字节、keyid 4 字节、签名长度 2 字节大端，策略要求签名的路径只接受签名类型且 keyid 在受信集合内；长度不符、未知算法、摘要类型用于要求签名的路径、属性不可读一律拒绝；签名长度为零或超出属性尾部拒绝；keyid 被撤销后即使签名有效也拒绝；同一 inode 的多个硬链接共享评估结果，但换路径不得绕过；写入、chmod 或 rename 后缓存立即作废并按新属性重评。用仅摘要属性、长度越界、受信外 keyid、撤销 keyid、硬链接别名、元数据变更和零长度签名验证。
