# 断点续传位点管理与崩溃安全恢复器

Go 标准库实现的数据消费进度安全检查点（Checkpoint）管理器。
消费端多线程并发处理变更事件，管理器追踪已被所有线程完整消费的
最小连续位点（Low Watermark）；崩溃重启后从该位点平滑续跑，
保证不漏掉任何未完成事件（at-least-once）。

## 设计

- `Manager.Begin(pos)`：工作线程领取位点；早于 Low Watermark 的位点返回 `false`（已消费，跳过）。
- `Manager.Commit(pos)`：确认消费完成；管理器越过连续完成前缀推进 Low Watermark，
  乱序完成的位点先缓存，等缺口补齐后一并越过。
- 崩溃安全持久化：每次状态变化以「写 `.tmp` 临时文件 → fsync → 原子 rename →
  fsync 父目录」落盘，崩溃后最多丢失最后一次未完成的写，绝不会得到半写文件。
- `LoadResumePoint(path)`：崩溃重启后的进度读取器，返回安全重放起始点。
  检查点文件损坏时返回错误，绝不静默回退导致位点错乱。

## 运行测试

```sh
go test -v ./...
```

## 运行样例

```sh
go run ./cmd/demo
```

样例复现验收场景：10 个工作线程并行消费位点 1000..2000，
线程 3 拿到块 `[1000,1100)` 并卡在 1050（已领取未提交）；模拟崩溃重启后，
进度读取器返回 1050 作为安全重放起始点，从 1050 续跑至 2000，
最终 Low Watermark 推进到 2001。
