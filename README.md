# set32

32 位无符号整数集合：按高 16 位分块，低 16 位在三种容器间切换。

## 容器与选择规则

| 容器   | 载荷字节数   | 内容                     |
|--------|--------------|--------------------------|
| array  | `2·n`        | 严格递增的 uint16 数组   |
| bitmap | `8192`       | 固定 1024 个 uint64      |
| runs   | `4·rc`       | 互不相邻闭区间 `[lo,hi]` |

每个块按**实际序列化字节数最小**选择容器；平局用固定优先级
`array > runs > bitmap`（`desiredKind`，container.go）。
更新后即时规范化（也允许延迟转换），因此同一逻辑集合的编码唯一。

## 编码格式（小端）

```
u32 magic("RSN1") | u32 blockCount
每块: u16 key | u8 kind | u8 reserved(0) | u32 count | payload
  array : count × u16
  bitmap: 1024 × u64
  runs  : u32 runCount, runCount × (u16 lo, u16 hi)
```

`Decode` 独立校验：块 key 严格递增、无空块、count 与载荷一致、
array 严格递增、runs 不重叠不相邻且 `lo<=hi`、bitmap popcount 匹配、
容器类型等于规范选择、无尾部字节。

## 操作

`Add`/`Remove`（run 数增量维护，快照写时复制）、`And`/`Or`/`Xor`
（按块归并 + runs 区间代数，不展开 32 位全域）、`Rank`(≤x 计数)、
`Select`（从 0 开始第 k 项，非法 k 返回 `ErrSelectRange`）、
`Snapshot`（快照后修改互不污染）。

## 实测编码尺寸（go test -v -run TestEncodingSizes）

| 场景                            | 字节数    | B/元素  |
|---------------------------------|-----------|---------|
| 1000 个随机值（全 32 位域）     | 9,960     | 10.0    |
| 全块 65536 个连续值             | 24        | 0.0004  |
| 1,000,000 个随机值              | 2,524,084 | 2.52    |
| 1000 段长度 100 的连续区间      | 15,876    | 0.16    |
| 单块 50000 个随机值（76% 密度） | 8,208     | 0.16    |

以上为实测值，不对更大规模数据的耗时做任何承诺。
