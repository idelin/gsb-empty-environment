认证网关与反向代理在校验和重写 `Set-Cookie` / `Cookie` 响应与请求头时，若未强制 `__Host-` 与 `__Secure-` 前缀的浏览器安全不变量、忽略控制字符/分号注入，或在 `SameSite=None` 缺失 `Secure` 时放行跨站请求携带会话 Cookie，攻击者可利用子域 Cookie 覆盖（Cookie Tossing）或 CSRF 劫持用户会话。为 TypeScript 网关宿主实现可导入的零外部依赖 RFC 6265bis Cookie 安全解析、前缀不变量强制与跨站发送裁决库，严禁联网。组件严格解析原始 `Set-Cookie` 字符串（拒绝控制字符、换行与非法属性），强制执行：（1）`__Secure-` 前缀必须经 HTTPS 下发且携带 `Secure` 属性；（2）`__Host-` 前缀除满足 `Secure` 外，严禁包含 `Domain` 属性且 `Path` 必须精确等于 `/`；（3）`SameSite=None` 必须同时具备 `Secure`；在出站/入站发送裁决器中结合请求 `Origin`、站点关系（`same-origin`/`same-site`/`cross-site`，基于有效顶级域 eTLD+1）、请求方法与顶层导航标志，精确判定 `Strict`/`Lax`/`None` 下允许附带的 Cookie 集合，拦截子域覆盖与跨站 CSRF 携带。附 Cookie Tossing、前缀违例与 SameSite 边界测试。
