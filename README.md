移动应用商店与安全网关在离线审计 Android DEX（Dalvik Executable）字节码及 APK 内嵌 `classes.dex` 时，若仅检查文件前 8 字节魔数 `dex\n035\0` 而未重算 Adler-32 校验和与 SHA-1 摘要、未校验 `header_item` 与 `map_list` 声明区段边界，或放过节区间重叠、越界 ULEB128 与尾部附带 ZIP 结构的 Janus（CVE-2017-13156）多义性文件，攻击者可绕过 APK v1 签名向受信任应用注入恶意 Dalvik 字节码。为 C++17 二进制安全宿主实现可嵌入、零外部依赖、`-Wall -Wextra -Wconversion -Werror` 编译通过的原始字节级 DEX 结构完整性与多义性审计库（内置 Adler-32 与 SHA-1）。库从 112 字节 `header_item` 起严格校验：（1）魔数版本（`035`–`040`）、`endian_tag == 0x12345678`、`header_size == 0x70`、`file_size` 精确等于输入实际字节长度（拦截尾部藏毒与 Janus 拼接）；按规范从偏移 12 起重算 Adler-32 与从偏移 32 起重算 SHA-1 并恒定时间比对；（2）完整解析 `string_ids`/`type_ids`/`proto_ids`/`field_ids`/`method_ids`/`class_defs` 与 `map_list`，硬拒绝任意区段偏移/长度整数回绕、越界或与头/其他元数据区段重叠，拒绝 `map_list` 与头声明计数/偏移冲突；（3）解码 `class_data_item` 中的 ULEB128 编码并硬拒绝超长 5 字节非规范 ULEB128、重复 `class_idx` 定义以及 `code_item` 指令数组越界。附手工构造的合法 DEX 样本与 Janus 尾部拼接、SHA-1/Adler-32 篡改、区段重叠及畸形 ULEB128 测试。
