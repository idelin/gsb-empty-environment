# rollsam — 可回滚的字节串后缀自动机

对末尾可追加（`Append`）、可撤销（`Undo`）的字节串维护后缀自动机，
支持查询模式串全部出现位置（`Positions`）与不同子串总数（`Distinct`）。

## 公开约定

- 位置均为 0 起始的字节下标。
- **空模式**：按“空串出现于一切位置”的约定，对长度 n 的文本返回
  `0..n`（共 n+1 个位置）；空文本上返回 `[0]`。
- `Distinct` 统计不同**非空**子串总数（不含空串）。
- `Undo` 以一次 `Append`（一个字节）为粒度；无可撤销操作时返回 `false`。

## 回滚原理

后缀自动机的每次扩展只在节点切片**尾部**新增节点（`cur` 与可选的克隆
节点），对既有节点的修改只有两类：新增/改向转移、改向后缀链接。因此
每次 `Append` 记录一条操作日志：

- `nodesBefore` / `lastBefore`：操作前的节点数与 `last`；
- `changes`：对旧节点的全部修改（转移旧值、链接旧值）；
- `delta`：不同子串数增量，即 `len[cur] - len[link[cur]]`
  （克隆节点的贡献与被改向节点 `q` 的贡献变化恰好抵消，不计入）。

`Undo` 逆序回放 `changes`、将节点切片清零后截断到 `nodesBefore`、恢复
`last` 并减去 `delta`。撤销后自动机与“从头构建同一文本”**逐节点一致**
（测试中以 `reflect.DeepEqual` 验证），不残留转移，计数不重复不遗漏。

## 复杂度

- `Append`：均摊 O(1)（map 操作）；`Undo`：O(当次操作的修改数)，均摊 O(1)。
- `Distinct`：O(1)。
- `Positions(p)`：O(|p| + 状态数 × 链接深度)。为保持回滚下的简洁与正确，
  endpos 集合按需沿后缀链接链归集，未做子树聚合；如需高频位置查询，
  可在链接树上维护可回滚的子树位置集。

## 持久内存占用

- **活自动机**：O(n)，n 为当前文本长度。状态数 ≤ 2n−1，转移数 ≤ 3n−4，
  每条转移为一个 map 项（数十字节）。
- **回滚日志**：与“尚未撤销的 Append 次数”成正比。由于全部扩展过程中
  转移写入总数是线性的，日志条目均摊 O(1)/次追加；总占用 O(已追加字节数)。
- **撤销即释放**：`Undo` 弹出日志时清空记录、把截断的新节点置零，转移
  map 与位置切片随即成为垃圾可被 GC 回收——内存回到撤销前的水平，
  仅切片容量（cap）保留供后续追加复用，不归还 OS。
- 本结构是**线性撤销栈**而非全持久（分支版本）结构：只支持按栈序回滚。
  若需任意版本切换，可改用不可变节点 + 持久映射的全持久后缀自动机，
  代价是每次操作多 O(log) 的复制与更高的常数。

## 测试

`go test ./...` 覆盖：

- 全部长度 ≤ 8 的二进制串，逐步与暴力枚举的全部子串对比；
- 重复字符（`aaaaaaaa`）与交替串（`abababab`、`abcabcabc`）；
- 撤销后改接另一后缀（`ababa` → 撤销 2 → 接 `bb` 得 `ababb`），
  并与从头构建做结构级 `DeepEqual`；
- 随机追加/撤销混合操作 400 步，每步校验计数、定期校验位置与结构。
