OSPF 多区域路由计算绝非在整张图上跑一次 Dijkstra：RFC 2328 强制规定路径类型严格按 `Intra-Area > Inter-Area > External Type-1 > External Type-2` 排序（哪怕区域内路径总开销 1000 也绝对优于开销 10 的区域间路径！），且连接到骨干区（Area 0）的 ABR 必须忽略从非骨干区学到的 Type-3 Summary LSA 以防区域间环路；而在 RFC 3101 NSSA（Not-So-Stubby Area）中，当多台 ABR 同时连接同一 NSSA 时，必须按 `Always` 角色或最高 Router ID 选举唯一翻译器将 `P-bit == 1` 且转发地址（Forwarding Address, FA）非零的 Type-7 LSA 翻译为 Type-5 注入骨干区，同时任意 Type-5/Type-7 外部路径在计算到其非零 FA 的最短路径时若发现 FA 不可达或需经非区域内路径绕行，则该外部路径必须被精确忽略！为路由协议控制面交付可导入的 Go OSPF 多区域 LSDB 路由表计算引擎。输入为完整的多区域 LSDB（每区域含 Type-1 Router LSA、Type-2 Network LSA、Type-3 Summary LSA、Type-4 ASBR Summary LSA、Type-7 NSSA External LSA 及全局 Type-5 AS External LSA，带 `age`/`MaxAge=3600`、P-bit、E1/E2 度量与 FA）及本机 Router ID 与所属区域集合。规则：1）对每个直连区域执行严格两阶段区域内 SPF（仅当双向邻接链接均相互引用时该边才有效！忽略 `MaxAge` LSA 与不可达 Stub/Transit 链），产出区域内前缀与等价多路径（ECMP）下一跳集；2）处理区域间 Type-3 LSA——仅在存在活跃 Area 0 邻接的 ABR 上只接受 Area 0 的 Type-3，丢弃回指自身或非骨干区环回通告；3）实现 RFC 3101 NSSA Type-7 转 Type-5 翻译器选举（仅翻译 `P-bit=1` 且 `FA != 0.0.0.0` 的非 MaxAge Type-7），并在存在同前缀多条 Type-5/Type-7 时按 RFC 3101 §2.5 精确决胜（`E1` 优于 `E2`；同等开销下 Type-5 优于 Type-7，除非配置兼容性开关）；4）针对非零 FA 按区域内/区域间路由表解析到 FA 的真实下一跳与开销（FA 不可达时立刻跳过该外部 LSA！）。验收覆盖单向断链忽略、路径类型压倒开销优先级、ABR 丢弃非骨干区 Type-3 防环、多 ABR 的 NSSA 翻译器选举、非零 FA 可达/不可达过滤及 E1/E2 与 ECMP 下一跳完整校验。
