# 内存映射撤权栅栏

隔离运行器撤销共享页访问时，不能只改策略而留下仍可读取的映射。为Go控制宿主实现撤权事务包，先阻止新映射，再让所有已登记映射完成失效确认，最后返回撤销成功；失败映射保持隔离状态不可复用。用模拟页驱动测试确认乱序、映射编号重用和撤权期间新租户申请。

## 事务协议

`netsec.Host` 通过三阶段屏障事务撤销模拟共享页（`Page`）访问：

1. `BeginRevocation()` 同步升起屏障：新租户的 `Map` 申请立即返回 `ErrBarrier`，
   所有已登记映射进入失效中状态，`Read` 即刻失败，不存在策略已改但映射仍可读的窗口。
2. 运行器逐条调用 `ConfirmInvalidation` 提交失效确认；`Revoke(ctx)` 等待
   `pending` 计数归零。确认可以乱序到达，事务在全部确认到齐前不会收尾。
3. 收尾回收确认成功的映射编号；确认失败（`success=false`）的映射进入永久隔离，
   编号进入 `quarantined` 集合、永不发放，`Revoke` 返回包装 `ErrInvalidationFailed` 的错误。

## 编号重用与代际

成功撤权后编号进入空闲表并可重新发放；每次重用都会递增代际（`Generation`）。
旧 `MappingRef` 的迟到确认或读取会被识别为 `ErrStaleMapping`，无法影响新映射。

## 取消语义

`Revoke` 支持并发等待者共享同一事务。某个等待者的 `ctx` 被取消只会让它提前返回
`context.Canceled`，屏障与事务继续推进；后续等待者仍能拿到同一事务的最终结果。

## 测试

`revoke_test.go` 用模拟页驱动以下场景：

- 乱序失效确认与屏障期间读取失败
- 映射编号重用与旧代际引用拒绝
- 撤权期间新租户（含并发）申请被拒、事务后恢复
- 失效失败映射永久隔离且编号不回收
- 等待者取消不中止事务
- 空宿主撤权与重复确认拒绝
