基于 UDP 的 DTLS 1.3（RFC 9147）安全传输宿主在重组跨多个数据报乱序到达的握手消息分片时，若重组缓存未严格检测重叠分片字节冲突、放过超过总长的碎片，或在记录层解密前未按 epoch 正确重构 48 位隐式序号及抗重放窗口，攻击者可向握手流注入冲突字节篡改转录哈希、制造内存耗尽或利用旧纪元密文重放。为 C++17 网络协议宿主实现可嵌入、零外部依赖、`-Wall -Wextra -Wconversion -Werror` 编译通过的 DTLS 1.3 记录层防重放与握手分片安全重组库（底层 AEAD 与序号掩码原语由抽象接口注入并提供确定性参考实现）。组件严格实现：（1）DTLS 1.3 统一头（Unified Header）解码与 8/16 位截断序号按当前接收窗口重构完整 48 位序列号（处理回绕边界，按每个 `epoch` 独立维护 64 位滑动防重放窗口，绝不跨 epoch 混用序号空间，且在 AEAD 认证通过前严禁推进重放窗口）；（2）安全握手分片重组器：维护按 `message_seq` 索引的区间合并表，精确处理乱序、相邻与部分重叠分片——当新到达分片与已缓存字节存在重叠时，必须逐字节比对，完全相同才允许去重合并，只要有任意 1 字节不一致或 `fragment_offset + fragment_length > total_length` 或同 `message_seq` 声明的 `total_length`/`msg_type` 变化，立即判定为分片注入攻击并丢弃/告警；同时强制单消息最大字节数与并发未完成消息槽位上限防内存耗尽；（3）无状态 Cookie DoS 防御与跨 epoch 丢弃旧明文记录保护。附确定性边界测试覆盖重叠字节篡改、序号回绕、未过 AEAD 不推进窗口与多 epoch 隔离。
