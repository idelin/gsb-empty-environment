# POP3 STLS后能力重取与降级拒绝

POP3 客户端靠 CAPA 判断服务器是否支持 STLS，攻击者在路径上可让服务器的 STLS 回 -ERR、在 +OK 之后夹带明文字节，或沿用握手前缓存的能力列表。给Go POP3 客户端写供连接建立流程调用的升级包，策略为必须加密：CAPA 多行应答以单独一行 . 结束，没有 STLS 就失败；STLS 得到 -ERR 就失败而不是继续明文登录；+OK 之后若读缓冲里还有任何尚未交给 TLS 的字节，视为注入并断开；握手完成后丢弃此前全部能力，重新发 CAPA，并只依据新的列表选择认证方式。用 -ERR 回退、+OK 后夹带字节、握手前能力里的 USER 被新列表去除、合法升级验证。
