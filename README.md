QUIC 将包号拆分为 Initial、Handshake、Application Data 三个独立空间，其丢包检测定时器与探测超时（PTO）在不同握手阶段和反放大限制下互相耦合：把 `max_ack_delay` 误用到 Initial/Handshake 空间、在地址未验证且触发 3 倍反放大上限时仍持续触发 PTO 死循环，或把纯 ACK 包计入在途字节，都会导致连接假死或带宽雪崩。为传输栈交付可导入的 Go RFC 9002 丢包检测与拥塞事件状态机。组件维护三空间的已发送包表、`largest_acked`、RTT 估算（`min_rtt`、`smoothed_rtt`、`rttvar`、`latest_rtt`，仅当最大确认包为新确认且至少包含一个 ack-eliciting 包时更新 RTT，且仅在 Application Data 空间握手确认后才减去受 `max_ack_delay` 限制且不超过 `latest_rtt - min_rtt` 的延迟）、包门限（`kPacketThreshold = 3`）与时间门限（`max(9/8 * max(latest_rtt, smoothed_rtt), kGranularity)`）双触发丢包判定。规则：实现 `GetLossTimeAndSpace` 与 `GetPtoTimeAndSpace` 驱动统一单一定时器；服务端在地址未验证且发出字节达收到字节 3 倍时必须停用 PTO 定时器并在收到新客户端包解除限制后重设；Initial/Handshake 空间丢弃密钥时同步清理对应空间在途字节与丢包计时器且重置 `pto_count`；收到 ECN-CE 计数增长时与丢包一致每个恢复周期（Recovery Epoch）最多触发一次拥塞窗口折半，并支持持久化拥塞（Persistent Congestion）窗口重置至最小窗口。验收覆盖跨三空间乱序 ACK、反放大锁死与解除、握手确认前后 `max_ack_delay` 差异、纯 ACK 不触发 PTO、空间密钥丢弃清理与持久化拥塞恢复。
