HTTP/3 用 QPACK 替代 HPACK 以消除队头阻塞，但动态表更新通过独立编码器流异步发送，请求头块可能早于动态表条目到达而被阻塞，编码端驱逐旧条目时若误删仍有未确认流引用的槽位会直接触发连接错误。为 HTTP/3 传输层交付可导入的 Go QPACK 动态表编解码与流同步包，按 RFC 9204 精确实现。支持配置最大动态表容量、当前生效容量、`MaxBlockedStreams`，提供编码端与解码端完整状态机：编码端支持插入字面量/静态引用/动态复制指令、按流编码头块（遵守 `KnownReceivedCount` 与 `MaxBlockedStreams` 限制：达到阻塞流上限时不得引用尚未被解码端确认的动态条目，且严禁驱逐 `min(未确认流引用最小绝对索引)` 以上的条目）、接收解码器流的 Section Acknowledgement / Stream Cancellation / Insert Count Increment 更新确认水位；解码端支持乱序到达的编码器指令流与多条请求流，正确解码 `RequiredInsertCount` 模编码与正负 `DeltaBase`、在 `InsertCount < RequiredInsertCount` 时挂起阻塞流并统计阻塞流数（超 `MaxBlockedStreams` 报错 `QPACK_DECOMPRESSION_FAILED`），待编码器流补齐后自动唤醒解出完整首部列表。验收用双端乱序通道仿真对照全部首部无损还原，覆盖 `RequiredInsertCount` 回绕解码、达到 `MaxBlockedStreams` 自动降级字面量编码、取消未确认流释放驱逐锁，以及乱序到达阻塞后唤醒。
