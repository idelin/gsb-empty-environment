关系数据库优化器利用部分索引（`CREATE INDEX ... WHERE P_idx`）或跳过无关分区（Range/List/Default Partition Pruning）前，必须先从数学上证明查询条件 `P_q` 在表级约束（`NOT NULL` 与 `CHECK` 约束）背景下严格蕴含索引谓词 `P_idx`（即对所有满足表约束且使 `P_q` 求值为 `TRUE` 的行，`P_idx` 必然求值为 `TRUE`！），否则就会静默漏行！SQL 三值逻辑在这里布满了反直觉陷阱：例如 `x > 5` 蕴含 `x IS NOT NULL`，但 `NOT (x = 5)` 对 `x = NULL` 求值为 `UNKNOWN`（因此也无法为 `TRUE`，在顶层 `WHERE` 中同样蕴含 `x IS NOT NULL`！），然而一旦外层套了析取 `NOT (x = 5) OR y = 1` 就不再蕴含 `x IS NOT NULL`；又如表上有 `CHECK (state IN ('draft', 'live', 'archived'))` 且列 `state` 可空，查询 `WHERE state != 'draft' AND state != 'archived'` 结合表约束蕴含 `state = 'live'`（因为 `!=` 拒绝了 `NULL`！），但若查询写成 `WHERE state IS DISTINCT FROM 'draft' AND state IS DISTINCT FROM 'archived'`，则 `state = NULL` 仍满足查询，因此**不**蕴含 `state = 'live'`！为查询优化器交付可导入的 Go 三值谓词蕴含证明、部分索引匹配与多分区裁剪引擎。输入为表模式（列类型、`NOT NULL` 标志、`CHECK` 约束列表）、候选部分索引列表、分区定义（Range 复合闭开区间 / List 枚举值集 / 可选 `DEFAULT` 分区）及查询 `WHERE` 谓词（支持 `AND`/`OR`/`NOT`、整数与字符串有序比较、`IN`/`NOT IN`、`BETWEEN`、`IS [NOT] NULL`、`IS [NOT] DISTINCT FROM`）。规则：1）基于有限区间/枚举域拆分与三值真值反例搜索实现可靠（Sound）且对区间+布尔+枚举组合完备的蕴含判定器（支持输出可验证的反例行证明“不蕴含”！）；2）筛选全部可安全使用的部分索引并标注是否需残余过滤（当 `P_idx` 已被 `P_q` 蕴含时需补残余，若双向等价则免残余！）；3）对 Range/List/Default 分区精准裁剪——特别处理 `DEFAULT` 分区（仅当全部满足 `P_q` 的可能值均落在显式非默认分区内时才可裁掉 `DEFAULT` 分区，否则必须保留 `DEFAULT` 防止漏行！）。验收覆盖 `!=` vs `IS DISTINCT FROM` 在可空列+`CHECK` 约束下的蕴含差异、三值 `NOT`/`OR` 边界、反例行自动构造校验以及含 `DEFAULT` 分区与 `NULL` 值的零假阴性分区裁剪。
