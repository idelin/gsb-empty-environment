在同时存在行级/语句级触发器（`BEFORE`/`AFTER EACH ROW`/`STATEMENT` + 过渡表 `OLD TABLE`/`NEW TABLE`）与多表外键约束（`ON DELETE/UPDATE CASCADE`/`SET NULL`/`SET DEFAULT`/`RESTRICT`/`NO ACTION`）的关系数据库中，执行顺序、跳过语义与延迟校验极易互相打架：1）`BEFORE EACH ROW` 触发器按名称字典序依次执行，任一触发器修改 `NEW` 行将传递给后续触发器与最终写入，任一触发器返回 `SKIP`（`NULL`）则立即取消对该行的写入以及所有后续 `BEFORE`/`AFTER` 行级触发器和外键级联（绝不进入过渡表！）；2）外键动作 `RESTRICT` 与 `NO ACTION` 绝非同义词——`RESTRICT` 要求在被引用行修改/删除的**当下立即检查**子表是否仍有引用（即使约束被标记为延迟或后续同语句级联会清掉子表，也必须立刻报错回滚！），而 `NO ACTION` 延迟到**整个语句结束（含全部 `CASCADE` 传播完成后）或事务提交（`DEFERRABLE`）**时才检查，因此当菱形外键 `A -> B (CASCADE)`、`B -> C (CASCADE)` 与 `A -> C (NO ACTION)` 并存时删除 `A` 必须合法成功，而若 `A -> C` 为 `RESTRICT` 且先于 `B -> C` 校验则必须失败！3）外键级联引发的子表 `DELETE`/`UPDATE` 必须同样递归触发子表自身的 `BEFORE`/`AFTER` 触发器并正确填充子表的过渡表，且对嵌套递归触发器严格设置最大深度上限防止无限自触发死循环；4）单条外层 DML 的语句级 `AFTER EACH STATEMENT` 过渡表（`OLD TABLE`/`NEW TABLE`）必须恰好包含该表在本次语句中实际生效（未被 `BEFORE` 跳过！）的全部旧/新行快照。为关系数据库执行层交付可导入的 Go 触发器与外键级联引擎。验收覆盖 `BEFORE` 修改传递与返回 `SKIP` 取消级联、`RESTRICT` vs `NO ACTION` 在菱形外键与延迟交换键上的本质差异、级联触发子表触发器与过渡表精确内容、以及递归触发器深度超限原子回滚。
