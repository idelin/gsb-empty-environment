# 多分区确定性事务状态机

基于本地确定性日志的多分区键值状态机（TypeScript，零依赖，Node.js 内置测试）。

## 特性

- **本地确定性日志**：仅追加日志（`DeterministicLog`），状态机的一切输入都来自日志回放。
- **两阶段事件回放**：`prepare`（声明读写集合）→ `commit` / `abort`，支持乱序到达（commit 可先于 prepare，自动缓冲配对）。
- **并发事务依赖拓扑排序**：批次边界 `seal()` 时对完整冲突图（ww / wr / rw）做拓扑排序，排序键 `(lamport, txnId)` 作确定性决胜；最终状态只是事件集合的函数，与网络到达顺序无关。
- **可审计决胜证据**：未决冲突产出 `tie-break` 证据（冲突键、双方排序键、胜者、规则），内容与到达顺序无关；拒绝、重复、孤儿事件均记入有界审计环形缓冲。
- **内存有界**：未决事务表上限超限拒绝新 `prepare`（含证据）；已决结果缓存 FIFO 逐出；提前到达的决策缓冲与审计日志均有容量上限。
- **崩溃恢复**：快照记录切片点（`consumedSeq`），恢复 = 加载快照 + 从切片点继续回放日志。

## 运行

需要 Node >= 22.6（推荐 >= 23.6，原生类型擦除直接运行 TypeScript）。

```sh
npm test        # node --test test/*.test.ts
npm run demo    # node demo/run.ts
npm run typecheck  # 需要本地安装 typescript（可选）
```

## 结构

- `src/types.ts` — 事件、排序键、审计记录类型
- `src/log.ts` — 确定性日志（追加 / 切片点 / 从任意位置回放）
- `src/stateMachine.ts` — 分区、冲突检测、拓扑排序定局、快照 / 恢复
- `test/stateMachine.test.ts` — 9 个 `node:test` 用例
- `demo/run.ts` — 乱序注入 + 决胜证据 + 快照恢复的运行样例

## 确定性模型

事件先进入未决缓冲，批次边界 `seal()` 时状态机拥有完整视图：已决事务中，
所有排序键更小的冲突前驱都已落定的方可应用；多候选就绪时取排序键最小者。
因此同一事件集合的任意到达顺序产生相同的应用顺序与最终键值状态。
