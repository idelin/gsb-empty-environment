大型微服务网格在某核心下游容量骤降时，若仅靠各服务各自独立限流，往往会因为多路径扇出放大（同一个底层存储被多个中台服务以不同放大倍数重复调用！）和盲目丢弃高优关键流量而诱发全局雪崩。为站点可靠性治理控制面交付可导入的 Go 强弱依赖图动态降级与优先级负载脱落（Adaptive Load Shedding）求解包。输入为微服务有向依赖图（每服务含当前健康容量上限 `cap_v`、各入口流量按四档优先级 `CRITICAL_PLUS > CRITICAL > SHEDDABLE_PLUS > SHEDDABLE` 划分的到达速率；每条调用边 `(u -> v)` 标注调用放大倍数 `fanout > 0` 与依赖类型 `HARD` 或可降级 `SOFT`——切断一条 `SOFT` 边会使边流量归零且不引起上游 `u` 请求失败，仅扣减可配置的轻量业务降级代价！）。规则：1）**多路径 DAG 流量精确守恒传播与环路检测**：检测调用图是否含环（有环报精确极小环阻断！）；对任意一组弱依赖开关与各入口各优先级放行比例，按拓扑序精确累加全部入口经多条共享路径汇入每个节点 `v` 的真实总负载 `load_v`（绝不可按树重复错算！）；2）**先弱依赖降级、再按严格优先级字典序保高优负载脱落**：当存在节点过载（`load_v > cap_v`）时，优先在满足全部节点 `load_v <= cap_v` 的前提下最小化被拒的高优流量——严格按字典序最大化保留 `CRITICAL_PLUS` 总量 -> `CRITICAL` 总量 -> `SHEDDABLE_PLUS` 总量 -> `SHEDDABLE` 总量，并在同优先级容量守恒的前提下优先用关闭低代价 `SOFT` 边替代丢弃用户请求（同一优先级内多个入口竞争同一瓶颈下游时按水填最大最小公平 `Max-Min Fairness` 分配放行率！）；3）**滞回防抖与容量恢复平滑回升**：维护每条 `SOFT` 边与脱落档位的冷却窗与恢复阈值（仅当瓶颈余量连续高于恢复水位且过冷却期才按步长逐步恢复，防止恢复瞬间流量回涌引发二次过载震荡！）。验收覆盖菱形多路径扇出总负载精确守恒、切断弱依赖保全关键流量、四档优先级字典序严格保护、同优先级多入口 Max-Min 公平分配、调用环拦截以及恢复滞回防震荡时间线验证。
