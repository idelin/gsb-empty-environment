推理调度器可以合并校验多个请求的草稿，但不能偷看尚未返回的接受长度。为它交付可导入的 Go 包：每个请求是一棵有限有根树，边是 token，叶是完成；全局模型场景表中每行给各请求的真实根到叶路径及正整数权重。一次加速卡调用为若干未完请求各选一个深度不超过三的连通前缀子树（以当前已确认前缀为根，至少一边）。同一次内，相同完整 token 前缀仅产生一个 KV 页；不同长度前缀不可合并，祖先页亦计，空根免费。一次最多 B 个不同页，其调用时间等于一份固定启动时间加子树最大深度乘不同页数。每请求沿真实路径连续接受，遇到第一条未选边即停；设备只报告走到的节点，不泄露缺失边。调用之间释放所有临时页。输入至多七项请求、十二种联合场景、每棵树十二个非根节点，各请求有从时刻零计的硬截止。返回对每种场景都按期的反馈策略，在这些策略中最小化场景权重乘完成全部请求时间之和，再最小化最坏场景耗时；无解返回最小基数的不可满足场景子集，同基数取排序后编号最小的。给出服务按真实设备回执驱动的调用例和独立模拟，不可按请求把联合场景拆成笛卡尔积。用小树枚举对照可行性、成本和无解核，覆盖观测一项后另一项无需再消歧、失败探测无 token 前进但排除一个场景、拆批比共享全部前缀快、最后一项恰好踩线。
