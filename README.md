# scandetect

基于序贯假设检验（SPRT，即 TRW：Threshold Random Walk）的逐源端口扫描检测组件，用于边界防火墙。

## 算法

对每个源地址维护一个对数似然比（LLR），在两个假设之间做序贯检验：

- `H0` 良性源：连接成功概率为 `theta0`（默认 0.8）
- `H1` 扫描源：连接成功概率为 `theta1`（默认 0.2，`theta1 < theta0`）

每观测到一条**到新目标**的连接结果，更新一次：

- 成功：`LLR += ln(theta1 / theta0)`（负向，偏向良性）
- 失败：`LLR += ln((1-theta1) / (1-theta0))`（正向，偏向扫描）

阈值由可接受的错误率直接给出（Wald 边界）：

- 上界 `ln((1-beta)/alpha)`：越过判为 `Scanner`
- 下界 `ln(beta/(1-alpha))`：越过判为 `Benign`
- 两者之间保持 `Pending`，继续观测

其中 `alpha` 为名义误报率（良性判成扫描），`beta` 为名义漏报率（扫描判成良性），默认均为 0.01。
默认参数下连续 4 次失败即判扫描、连续 4 次成功即判良性。

## 关键语义

- **同目标去重**：`(source, target)` 只在首次连接时更新 LLR，`target` 通常为 `ip:port`。
  对同一服务的重试、长连接复用不会累积证据；正常客户端访问大量不同服务时，每个成功连接都把 LLR 推向良性，因此不会被误封。
- **判定冻结**：一旦越过阈值，该源在其状态存活期内判定不再改变（防火墙可据此执行封禁/放行动作）。
- **内存上限**：
  - `MaxSources` 限制并发跟踪的源数量，超限按 LRU 淘汰最久未活动的源；被淘汰的源再次出现时从空状态重新计数。
  - `MaxTargetsPerSource` 限制单个源的去重目标集合大小，超限遗忘最老的目标。
  - 总内存上界为 `O(MaxSources × MaxTargetsPerSource)`。
- 所有方法带互斥锁，可并发调用。

## 文件结构

- `scandetect.go`：检测器核心（配置、LLR 更新、去重、LRU 淘汰、状态快照）
- `scandetect_test.go`：单元测试（阈值、去重、冻结、淘汰、内存上界、并发）
- `internal/sim/`：蒙特卡洛模拟与验证测试
- `cmd/scansim/`：模拟命令行工具

## 运行

```sh
go test -race ./...          # 单元测试 + 模拟验证
go run ./cmd/scansim         # 默认 5000 个扫描源 + 5000 个良性源
```

常用参数：`-alpha -beta -theta0 -theta1 -pool -horizon -trials -seed`。

默认配置的典型结果（随机种子 42）：

| 类别 | 判为扫描 | 判为良性 | 未决 | 判定所需唯一连接（均值 / p95） |
| --- | --- | --- | --- | --- |
| 扫描源 | 99.80% | 0.20% | 0% | 6.64 / 14 |
| 良性源 | 0.38%（误报，名义 alpha=1%） | 99.48% | 0.14% | 6.73 / 14 |

## 调参建议

- 缩小 `alpha/beta` 会降低误判率但增加判定所需连接数（如 0.001 时均值约 8）。
- 慢速扫描与正常流量差异越小（`theta0`、`theta1` 越接近），所需观测越多；
  例如 0.65 对 0.35 时扫描源平均约 27 个唯一连接才判定，这是 SPRT 在“早判定”和“低误判”之间的固有折中。
- `theta0/theta1` 应按实际网络的连接成功基线校准，而非直接套用默认值。
