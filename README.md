# 析构回调重入导致同一资源二次释放

扩展对象关闭时会先调用插件的OnClose再释放宿主资源，插件可重入Close或转移资源，诱发二次释放。给Go插件宿主实现可导入的关闭状态机：对象状态Open、Closing、Closed，持有至多4个资源句柄，每个句柄绑定对象代次；Close从Open原子转Closing，先冻结句柄列表并从对象上清空，再逐个调用宿主Release，全部Release尝试结束后先置Closed，再调用一次OnClosed只读通知；OnClosed中的Close幂等且不能Move或Call。插件回调仅允许在每次Release前由宿主模拟器触发，可请求再次Close、MoveTo(other)或Call(handle)；Closing对象上的这些请求全部拒绝，其他Open对象接收Move须验证句柄当前仍归源对象且尚未进入冻结列表。重复Close幂等返回原结果。Release回调失败时继续释放其余句柄，最终返回聚合错误但所有权仍终结；宿主记录每个句柄最多一次Release。实现一个待审的“先回调再清空”版本并搜索最短插件动作使同一句柄二次Release或在进入Closing后成功Call，返回完整重入栈。测试两个对象互相Move、某次Release失败、回调内重复Close及旧代次句柄，不得通过吞掉回调错误伪装成功。
