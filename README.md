在存在严重反压（Backpressure）的多上游流计算拓扑中，传统的 Chandy-Lamport 对齐检查点（Aligned Checkpoint）会因等待慢通道 Barrier 而阻塞快通道导致检查点超时；**Flink Unaligned Checkpoint（非对齐检查点）**允许 Barrier 立刻超越输入/输出队列中的在途记录，同时把被超越的在途缓冲区一并持久化以维持精确一次（Exactly-Once）语义，四处核心协议极易破坏顺序或丢失记录：1）**输入通道 Barrier 超越与在途快照触发**：当多输入算子从任意首条输入通道收到新检查点 `ckptID` 的 Barrier 时，**立刻**触发本算子快照并把 `ckptID` Barrier 插队注入全部输出通道队头（超越尚未发出的输出缓冲记录！）；此时算子状态快照同时包含三部分：(a) 当前本地算子状态；(b) 当前所有输出通道中被 Barrier 超越的在途缓冲记录；(c) 其余尚未收到 `ckptID` Barrier 的输入通道中已到达但在逻辑上位于该 Barrier 之前的记录（继续正常消费处理，但同步把后续在对应通道收到 `ckptID` Barrier 之前到达的所有记录追加写入该通道的 `in-flight input state`！）；2）**对齐退化超时切换（`alignedCheckpointTimeout`）**：支持混合模式——初始按对齐模式阻塞已到通道等待其他上游；若等待时间超过阈值 `alignedTimeout` 仍未收齐，立刻无缝切换为非对齐模式：解除阻塞、立刻发下游 Barrier 并把积压记录记为在途状态完成持久化；3）**故障恢复与重放顺序不变量**：从最新已完成检查点 `ckptID` 恢复时，每个算子必须**先恢复本地算子状态 -> 再按原通道 FIFO 顺序重放持久化的在途输入缓冲区（并在处理完通道在途缓冲前绝不可混入该通道的新网络记录！）-> 同时将持久化的在途输出缓冲区优先发往下游**，保证端到端恰好一次（无丢、无重、单通道内严格保序！）；4）**取消/中止过期检查点与多检查点并发隔离**：支持 `CancelCheckpointMarker` 中止已超时检查点并清理对应在途追踪状态，防止阻塞后续新 `ckptID`。为流计算运行时交付可导入的 Go Unaligned Checkpoint 算子网络仿真与故障注入恢复引擎。验收覆盖重度反压下非对齐检查点零阻塞完成、`alignedTimeout` 动态切换、任意时刻杀进程/断通道从快照恢复后与无故障全量运行输出集合（及单通道顺序）完全一致以及过期检查点取消清理。
