# 单机生产排程器（精确求解，n ≤ 18）

单机排序问题：换线时间序列相关且有方向（`setup[i][j] ≠ setup[j][i]`），
任务带释放时间、交期与单位迟交罚金。主目标最小化总迟交罚金
`Σ w_j · max(0, C_j − d_j)`，次目标最小化最终完工时刻。允许空闲，
输出逐段的等待与换线时间。

## 运行

无需安装依赖（Node ≥ 22.6 原生执行 TypeScript）：

```bash
node src/cli.ts example.json      # 从文件读入
cat example.json | node src/cli.ts # 或从标准输入
npm test                           # 自测：随机算例与全排列暴力对拍
```

## 输入格式

```json
{
  "jobs": [{ "id": "A", "processingTime": 4, "releaseTime": 0, "dueDate": 12, "weight": 3 }],
  "setup": [[0, 2], [4, 0]],
  "initialSetup": [1, 0]
}
```

- `setup[i][j]`：从任务 `i` 换到任务 `j` 的时间（有方向，可不对称）。
- `initialSetup[j]`（可选）：开机后首个任务 `j` 前的准备时间，默认全 0。
- 罚金：`weight × max(0, 完工时刻 − dueDate)`。

## 输出

逐段给出：序号、任务、换线时间、等待（空闲）时间、开工/完工时刻、
交期、迟交量、罚金，以及总罚金与最终完工时刻。

## 算法与正确性要点

- Held-Karp 子集 DP：状态为 `(已排集合, 末尾任务)`，复杂度 `O(n²·2ⁿ)`，
  n=18 时约 8 秒（默认堆内存即可）。
- 每个状态保留 `(累计罚金, 当前时刻)` 的**帕累托前沿**而非单一最优：
  罚金低但时刻晚的标签可能让后续任务付出更高罚金，二者不可互相替代。
  标签 `a` 支配 `b` 当且仅当 `a.cost ≤ b.cost 且 a.time ≤ b.time`。
- 关于主动空闲：总加权迟交与 makespan 均为正则目标（对完工时刻单调
  不减），故必存在最优调度，其空闲仅由释放时间强制产生；任何额外
  主动空闲都会生成被支配的标签，不可能导向更优解。求解器不依赖
  “可执行即开工”的启发式，最优性由穷举全部排列保证，等待段在输出中
  显式列出。
- 正确性由 `src/selftest.ts` 保证：随机小算例（n ≤ 8）上与全排列暴力
  枚举逐一比对主/次目标，并校验输出分段的时间轴自洽性。

## 文件

- `src/scheduler.ts`：求解器（类型定义 + `solve()`）。
- `src/cli.ts`：命令行入口，渲染分段表格。
- `src/selftest.ts`：暴力对拍自测。
- `example.json`：示例输入。
