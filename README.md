# 双人密钥导入仪式被同一操作者凑票

HSM导入根密钥要求两个独立管理员批准，攻击者若用别名账号或重放旧批准可单人完成仪式。给Go密钥宿主实现可导入的导入仪式状态机：管理员注册表把多个credentialID映射到唯一personID、公钥、角色和撤销代次；仪式绑定随机ceremonyID、目标HSM槽、算法、用途、密钥材料承诺SHA256、包装公钥摘要、开始/截止单调时刻和策略代次。批准为Ed25519签名，覆盖全部字段及decision=approve；只计当前未撤销且角色允许的不管理员条目含不可变personID且由HR根签名确认；同personID，同一personID多个credential最多一票，阈值至少2且策略可要求SecurityOfficer与KeyCustodian各一。密钥材料由参与者分别提交的随机32字节份额按personID顺序排列后逐字节异或得到，份额用一次性HSM导入公钥封装并绑定ceremonyID/personID；任何单方不能读取其他份额，宿主只把封装项交给HSM CombineAndImport回调。达到批准和份额要求后原子调用一次，回调返回keyHandle、属性摘要和HSM签名收据；收据、属性、承诺和槽全匹配才Completed。失败、超时、管理员撤销或策略变化终止且封装项销毁，响应丢失按ceremonyID回读原收据。用真实签名及HSM替身测试别名账号、批准重放、份额换仪式、角色缺失、并发完成和回执丢失。
