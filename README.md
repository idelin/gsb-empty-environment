RFC 9000 QUIC 把单条连接拆分为多条并发字节流，其接收与发送流控状态机存在四类极易在边界踩坑的硬规范：1）一旦对某条流收到带 `FIN` 的 `STREAM` 帧或 `RESET_STREAM` 帧，该流的 `final_size` 即永久锁死——此后任何结束偏移超出 `final_size` 的分片、带不同 `final_size` 的重复 `FIN`/`RESET_STREAM`、或 `RESET_STREAM` 给出的 `final_size` 小于此前已收到的最高字节偏移，都必须立刻抛出连接级 `FINAL_SIZE_ERROR`！2）连接级接收流控 `MAX_DATA` 统计的是**各流历史最高到达偏移之和**（而非按收到的报文载荷累加！），重传重叠分片绝不可重复扣减连接额度，且仅当单流或连接超出已通告上限时触发 `FLOW_CONTROL_ERROR`；3）流 ID 最低两位编码发起方（客户端偶数/服务端奇数）与单双向（bit 1），创建高编号流（如流 12）必须隐式打开并计入同类型全部更低编号流（0、4、8）以强制校验 `MAX_STREAMS` 并发上限（超限报 `STREAM_LIMIT_ERROR`）；4）双向流的发送半部与接收半部拥有完全独立的状态机，`RESET_STREAM` 只关闭发送侧而 `STOP_SENDING` 仅请求对端发 `RESET_STREAM` 并不关闭本端发送侧！为传输栈交付可导入的 Go RFC 9000 QUIC 流多路复用与双层流控包。组件同时实现 62 位变长整数（VarInt）严格编解码、双向/单向流生命周期状态机、基于区间树的乱序/重叠 `STREAM` 分片重组（检测重传分片与已收数据字节一致或按偏移切分去重并按序交付）、连接与单流双层 `MAX_DATA`/`MAX_STREAM_DATA` 窗口消费与自动放窗更新、`MAX_STREAMS` 隐式开流计数与关闭回收以及 `RESET_STREAM`/`STOP_SENDING` 交互。验收覆盖 `FINAL_SIZE_ERROR` 四类违规、重叠重传不重复扣 `MAX_DATA`、跳跃流 ID 触发隐式开流突破 `MAX_STREAMS`、单向流误发反向帧报 `STREAM_STATE_ERROR`、双向流半关闭独立推进以及乱序交错分片无缝重组。
