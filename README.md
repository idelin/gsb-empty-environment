HTTP/2 的头部块用 HPACK 压缩。给连接组件交付可导入的 Go 编解码包。实现 RFC 7541：带前缀的整数编码、带霍夫曼标志的字面量、61 项静态表、带容量上限的动态表及其插入、淘汰和容量更新；四种头部表示都要能解码，编码只要求产出可被本包解码的合法字节。动态表项大小为名称字节数加值字节数加 32，新项放最前，容量不足时从最旧开始淘汰。以下情形必须报错而不是静默接受：霍夫曼编码含结束符号或填充超过七位、动态表容量更新超过对端上限、索引为零、索引超出当前表长、新项自身超过容量上限、整数编码的字节数超出线格式允许的上限。验收用 RFC 7541 附录 C 的三组请求编码逐字节对照，随机表操作序列与朴素模型对照表内容，并用逐字节喂入与整块喂入结果一致来核对边界。
