# 屏障模拟器（Barrier Simulator）

TypeScript 实现的屏障同步模拟：每轮全员到齐后由最小编号参与者结算，
失败依次接任，轮次隔离，成功结果恰好广播一次。

## 运行

```sh
tsc -p tsconfig.json   # 编译到 dist/
node dist/simulate.js  # 运行模拟（含断言）
```

## 规则实现

- **到齐触发**：`Barrier.arrive()` 计数，到齐后启动该轮的结算链（每轮只启动一次）。
- **最小编号优先，失败依次接任**：结算链按编号升序逐个 `await` 尝试；
  失败（异常）或超时即移交下一位。
- **每人最多一次**：每轮用 `attempted` 集合记录已尝试者，绝不重复指派。
- **轮次隔离**：每轮状态（到达集合、尝试集合、已提交结果）独立存放在
  `Map<round, RoundState>` 中，跨轮互不影响。
- **恰好广播一次**：广播与提交绑定在唯一的裁决点 `tryCommit()` 中——
  只有第一个把结果写入 `committed` 的结算会触发广播，之后一律丢弃。

## 领导者超时但迟到成功：哪次结算有权成为该轮结果？

模拟第 1 轮：0 号（领导者）结算耗时 250ms，超过 100ms 超时；1 号接任后
20ms 内成功。时间线：

1. t≈0：0 号开始结算。
2. t≈105ms：0 号超时，1 号接任。
3. t≈126ms：1 号成功，`tryCommit` 写入结果并广播——**该轮结果归 1 号**。
4. t≈257ms：0 号迟到成功，再次进入 `tryCommit`，发现 `committed` 已存在，
   结果被丢弃，不重复广播。

**结论**：有权成为该轮结果的是“第一个通过 `tryCommit` 提交成功的结算”，
即接任者 1 号的结算。超时只是触发接任的本地判据，并不剥夺迟到结果的
提交资格；真正决定归属的是提交点的先到先得。由于每轮只有一个
`committed` 槽位且广播与其原子绑定，任何迟到成功都无法覆盖已提交的
结果，也不会造成第二次广播。

## 文件

- `src/barrier.ts` — 核心：`Barrier` 类与提交裁决点 `tryCommit`。
- `src/simulate.ts` — 四个场景：领导者迟到成功、正常结算、两次失败后接任、
  全员失败；结尾带断言验证恰好一次广播与结果归属。
