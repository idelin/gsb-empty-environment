# 改动交互测试规划器

在依赖约束与执行预算内选择合法改动组合，**先最大化二阶交互覆盖，再最小化总成本**
（字典序）。给出精确解（枚举 ≤ 2^18 个子集）并与贪心解对照差距，同时列出全部
未覆盖交互及其原因。

## 问题定义

- **改动**：`id`、`cost`（占用预算）、`requires`（依赖，可传递、容忍依赖环）、
  `conflicts`（互斥，自动对称化）。
- **合法组合**：依赖闭包封闭、无冲突对、总成本 ≤ `budget`。
- **二阶交互**：任意两个不同改动组成的无序对；两者同时被选中即被覆盖。
- **可达交互**：存在某个合法组合同时包含两者的改动对。
- **目标**：在所有合法组合中，先最大化覆盖的二阶交互数，再最小化总成本。

## 运行

环境自带 Bun（无需安装依赖，Bun 原生执行 TypeScript）：

```bash
bun run src/main.ts                          # 内置演示实例
bun run src/main.ts instances/example.json   # 从 JSON 文件加载
bun test                                     # 随机化对照测试
```

输入格式见 `instances/example.json`；改动数量上限 18（`src/model.ts` 中
`MAX_CHANGES`），超出即报错。

## 输出说明

- **精确解 / 贪心解**：选中的改动、总成本、覆盖的交互数。
- **差距**：覆盖差（个与百分比）与成本差（贪心 − 精确）。
- **未覆盖项**：每个未被精确解覆盖的交互对，附原因：
  - `不可达 — 依赖闭包内存在冲突`：两者依赖闭包的并集含互斥改动（给出见证对）；
  - `不可达 — 最小成本超过预算`：同时执行两者（含依赖）的最小成本超预算；
  - `可达但未覆盖 — 需牺牲 N 个`：覆盖该对的最优方案覆盖数低于全局最优；
  - `可达但未覆盖 — 同等覆盖成本更高`：覆盖数相同但成本更高，被成本目标淘汰。

## 实现要点

- `src/model.ts`：输入校验、依赖闭包（不动点迭代）、冲突对称化、位掩码合法性检查。
- `src/exact.ts`：枚举全部子集，子集成本按低位递推；逐对统计包含该对的合法方案
  的最优覆盖与最低成本，用于生成未覆盖原因。18 个改动时约 60ms。
- `src/greedy.ts`：每轮加入“新增覆盖最多、边际成本最低”的改动（自动带上依赖闭包）。
- `test/planner.test.ts`：40 个随机实例与独立实现的暴力枚举交叉验证
  （覆盖数、成本、可达对数完全一致），30 个实例验证精确解字典序不劣于贪心，
  另有输入校验与未覆盖原因分类的定向用例。
