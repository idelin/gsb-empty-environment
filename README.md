网格数据面在多优先级上游端点池之间分配流量时，需结合健康过载因子、恐慌阈值（Panic Threshold）以及新上线端点的慢启动斜坡曲线，任一环节算错都会把刚启动的冷节点打垮或在全区亚健康时把流量全送给极少数节点。为负载均衡器交付可导入的 Go 权重计算包。输入按优先级 P0..Pn 排列的端点组（每端点含原始权重、健康态 Healthy/Degraded/Unhealthy 与上线时刻）、当前时刻、过载因子（如 1.4）、恐慌阈值（如 50%）、慢启动窗口 W、激进指数 A 及最小权重占比地板 m。规则：先按 Envoy 优先级负载公式计算各优先级健康与降级可用率（乘过载因子并截断到 100%），从 P0 起依次吃满 100% 流量份额（先全健康，不足再依次由各优先级降级端点补齐）；若所有优先级有效健康+降级总和仍低于 100% 则按比例放大，若全部优先级健康比例均低于恐慌阈值则切换全局恐慌模式（忽略健康过滤，按各优先级端点总数比例分流）；在获得非零流量的组内，对处于慢启动窗口 `0≤age<W` 的端点按 `max(m, (age/W)^(1/A))` 缩放其有效权重。组件输出每个优先级分得流量比例、是否触发恐慌模式及每个端点的最终精确归一化概率。验收用 Envoy 规范样例与边界用例逐项核对，覆盖 P0 部分受损溢出到 P1、降级端点承接二级溢出、全组跌破恐慌阈值触发全局恐慌、以及慢启动端点受最小地板保护。

## 交付物

可导入包 `prioritylb`（模块 `prescreen.local/ps-cdd9f54284`），无第三方依赖。

- 入口：`prioritylb.Calculate(groups []PriorityGroup, cfg Config) (*Result, error)`
- 输出 `Result` 包含：`Panic`（是否触发全局恐慌）、`PriorityShares`（每优先级流量份额，和为 1）、`Endpoints`（每端点有效权重与最终概率，总和精确为 1.0）。

## 计算规则

1. 各优先级按原始端点计数得到健康/降级比例，乘 `OverprovisioningFactor` 后截断到 1.0。
2. 常规模式按 Envoy `calculatePerPriorityLoad` 语义，从 P0 起逐优先级先消费健康容量、再消费降级容量，剩余预算带入下一优先级；总有效容量不足 100% 时按可用率整体等比放大。
3. 当所有非空优先级的原始健康比例均严格小于 `PanicThreshold` 时进入全局恐慌：忽略健康过滤，按各优先级原始端点总数比例分流。
4. 拿到非零份额的组内，对 `0 ≤ age < W` 的端点按 `max(m, (age/W)^(1/A))` 缩放原始权重，`age ≥ W` 或慢启动关闭时系数为 1。
5. 端点概率 = 所属优先级份额 × 有效权重 / 组内有效权重和；向量经残差校正后求和精确等于 1.0。
