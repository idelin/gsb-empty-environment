# 无锁 MVCC 只读事务

面向高频读业务的 MVCC 读路径：只读事务不获取任何排他锁，无锁遍历不可变
版本节点；写事务高并发追加版本链时，读操作完全不被阻塞，且绝不读到
写事务提交到一半的"半脏"数据。

## 设计

- **不可变版本链**：每个键一条单向链表，节点（值 + 全局提交序列号）发布后
  永不修改，链头是 `atomic.Pointer`。
- **原子提交点**：写事务先发布本次所有版本节点，最后原子推进全局 commit
  序列号。只读事务只读一次 commit 序列号作为快照点。
- **快照过滤**：读者沿链取第一个 `seq <= 快照点` 的版本。未提交完的事务
  其 seq 大于快照点，天然不可见 —— 这就是零撕裂的来源。
- **写者串行、读者无锁**：写路径用一把仅写者可见的互斥锁串行化；
  读路径不接触任何锁。
- **安全 GC**：读者在槽位表登记快照点，GC 只裁剪所有活跃读者都不可见的
  旧版本尾部；极端竞争下读者检测到版本缺失会整表重试，绝不返回撕裂数据。

## 运行

```sh
go test -race -v ./...   # 单元测试 + 验收边界测试
go run ./cmd/demo        # 3 秒压测样例：1 写 5 读，校验和守恒验证
```

## 验收边界（TestZeroTornReads）

- 1 个写线程对 1000 个键持续执行两键"转账"事务（事务内总和守恒）；
- 5 个读线程并发执行全表扫描并核对校验和；
- 写操作无等待，每次读快照内部总和守恒，撕裂读为 0。
