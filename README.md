# 加密索引泄露的关键词共现

文档虽然加密，服务器仍能看到同一查询令牌命中了哪些匿名文档，关键词可能据共现频次被恢复。为Go隐私测试宿主实现可导入的泄漏分析包，攻击者知道同一语料的关键词集合但不知道文档匿名ID映射：输入至多18个关键词和若干明文文档的关键词集合，以及与关键词数量相等的匿名令牌各自的命中文档ID集合；文档重复作为不同文档计数，单文档内重复关键词只计一次。分别计算单词频数及两词共现矩阵，搜索保持这些统计的关键词—令牌双射，可附少量已知对应，重复关键词ID、重复令牌ID、已知对应不成单射或统计冲突直接报告。输出至少一个完整见证、在所有可行双射中始终固定的对应，以及最多20个完整映射，先按令牌ID字节序形成对应关键词ID序列，再按该序列字节序排序；必须穷尽才能称某对应确定，预算耗尽只返回已找到见证和未完成，不以首个解恢复全部关键词。用有对称词的语料、重复文档、零命中词和相同边频但不同原始文档组的例子验证：结论仅限单点及二阶泄漏，不能暗中加入未授权的更高阶统计。

## 使用

```go
result, err := netsec.AnalyzeInput(netsec.Input{
    Keywords: []string{"a", "b", "c"},
    Documents: [][]string{
        {"a", "b", "c"},
        {"a", "b"},
        {"a"},
    },
    Tokens: []netsec.Token{
        {ID: "t1", Documents: []string{"d1", "d2"}},
        {ID: "t2", Documents: []string{"d1"}},
        {ID: "t3", Documents: []string{"d1", "d2", "d3"}},
    },
})
```

也可以使用位置参数形式：

```go
result, err := netsec.Analyze(keywords, documents, tokens, known, options)
```

`KeywordStatistics` 和 `TokenStatistics` 可单独计算一阶频数与所有无序词对的共现数（包括零值边）。明文文档按切片元素分别计数；同一文档内重复关键词和同一令牌内重复文档ID均按集合去重。

## 结果语义

- `Witness` 是找到的一个完整映射，`Mappings` 是按“令牌ID字节序下的关键词ID序列”排序并至多保留20个的映射。
- `Fixed` 只在 `Exhaustive == true` 时填写；它是所有可行双射中都相同的对应。
- 预算耗尽时 `Exhaustive == false`、`Incomplete == true`、`BudgetExhausted == true`，`Fixed` 为空，绝不从首个见证推断其余关键词。
- `Solutions` 是已发现的完整解数量；未穷尽时它是下界。
- 非法输入、已知对应非单射、已知对应统计不符或所有一阶/二阶统计无可行双射时返回对应哨兵错误，可用 `errors.Is` 判断。

算法只使用单词频数和两词共现矩阵。匿名文档ID与明文文档ID之间没有、也不会建立映射，因此不会引入三阶或更高阶的文档分组信息。
