# rga — 有限副本集合的序列 CRDT

基于 RGA（Replicated Growable Array）的离线文本协同实现，仅依赖 Go 标准库。

## 模型

- **操作 ID** = （副本 ID, 递增计数），全序且全局唯一。
- **插入**引用前驱元素的永久 ID（根为哨兵零 ID）；**删除**引用目标元素 ID。
  数组下标只用于*生成*操作（`InsertAt`/`DeleteAt`），从不作为身份存储。
- **并发插入同前驱**：兄弟节点按操作 ID 降序（计数优先，副本 ID 决胜）排列，
  与到达顺序无关；可视序为深度优先遍历，同一插入的后继子树连续成块。
- **删除即墓碑**：被删元素不显示，但保留为后续插入的定位锚点。
- **因果缓冲**：依赖（前驱/目标）未到的操作进入待定集，每次成功应用后重试；
  重复投递幂等；同 ID 不同内容返回 `ErrConflict`。
- **Checkpoint**：包含全部元素（含锚点墓碑）、已应用删除、本地计数器与待定
  操作，纯值类型可 JSON/gob 序列化；`Restore` 后可继续合并。

## 墓碑回收（仅讨论，未实现）

墓碑仍被其子树引用为锚点，仅当 (a) 有限副本集中所有副本已确认收到该删除
（如版本向量覆盖删除操作 ID），且 (b) 待定操作与存活元素都不再引用该 ID 时
方可回收。回收只是优化，不要求收齐全部历史。

## 用法

```go
alice := rga.New("alice")
op, _ := alice.InsertAt(0, 'h')   // 生成并本地应用，op 用于广播
_ = bob.Apply(op)                 // 任意顺序、任意次数投递
d, _ := alice.DeleteAt(0)         // 按可视位置生成删除
cp := alice.Checkpoint()          // 持久化（含锚点与待定操作）
r, _ := rga.Restore(cp)           // 恢复后继续合并
```

## 测试

```
go test ./...
```

- `TestCausalPermutationsConverge`：枚举 7 个操作的全部 240 种满足因果关系
  的投递排列，验证最终文本与待定集合一致。
- 另覆盖：先删后插、同位置并发插入（子树连续）、锚点删除后继续在墓碑上插入、
  重复投递幂等、同 ID 冲突、可视位置操作、checkpoint 恢复后继续合并。
- `Example`：两个副本离线编辑后双向合并的可运行示例。
