SQL:2011 的多维聚合子句允许在同一条 `GROUP BY` 中任意嵌套和逗号串联 `ROLLUP`、`CUBE`、`GROUPING SETS` 与复合列元组，并同时叠加 `GROUP BY ALL | DISTINCT`、`GROUPING(c1, c2, ...)` 位图函数以及每个聚合函数独立的 `DISTINCT` 与 `FILTER (WHERE cond)` 修饰符，极易在展开顺序与空表边界上失真：1）**复合列组与笛卡尔积展开**：如 `GROUP BY ROLLUP(a, (b, c)), GROUPING SETS((d), ())` 中，`(b, c)` 是不可拆分的整体复合项——`ROLLUP(a, (b, c))` 展开为 `[(a, b, c), (a), ()]`（绝不是 4 组！），再与 `[(d), ()]` 做笛卡尔积得到 6 组（每组内部按规范列序去重重复列名！）；2）**`GROUP BY ALL` vs `GROUP BY DISTINCT`**：当展开后出现两个完全相同的分组列集合（如 `GROUP BY CUBE(a), ROLLUP(a)` 会产生两份 `(a)` 与两份 `()`！），`ALL`（默认）必须完整保留并输出重复分组行，而 `DISTINCT` 必须按列集合去重只输出一份！3）**`GROUPING(c1, ..., ck)` 精确区分真实 `NULL` 与上卷合成 `NULL`**：`GROUPING` 返回无符号整数位图，第 `i` 位（高位优先！）为 `1` 当且仅当列 `ci` 未出现在当前分组集中（被汇总折叠为合成 `NULL`），为 `0` 当且仅当 `ci` 参与当前分组（哪怕该组真实的键列值本身就是 `NULL`！）；4）**空输入表经典边界与独立 `FILTER`/`DISTINCT` 聚合**：当输入表为 0 行时，`GROUP BY ()`（全局空分组集）必须输出 **1 行**（`COUNT=0, SUM/AVG/MIN/MAX=NULL, GROUPING=全1`），而 `GROUP BY a` 必须输出 **0 行**——因此 `GROUP BY ROLLUP(a)` 在空表上恰好只输出 `()` 对应的那 1 行！同时支持单查询内多个聚合各自携带不同 `FILTER (WHERE ...)` 与 `COUNT(DISTINCT col)`（严格忽略 `NULL` 值！）。为分析型查询引擎交付可导入的 Go 嵌套多维分组与过滤聚合执行包。验收覆盖复合元组 `ROLLUP`/`CUBE` 笛卡尔展开、`ALL` vs `DISTINCT` 重复分组集、真实 `NULL` 键与合成 `NULL` 的 `GROUPING` 位图区分、空表 `ROLLUP`/`GROUPING SETS` 精确行数以及多 `FILTER`+`DISTINCT` 聚合对照独立逐组参考器逐行一致。
