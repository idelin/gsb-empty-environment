# auditjoin

采集 SDK 的 Go 消费者组装包：把跨分片到达的审计片段按“启动代次 + 事件序号”
聚合成完整事件并写入存储，带水位线推进、超时强制发布与迟到补正能力。

## 核心模型

- `EventKey{NodeID, Generation, Seq}` 是事件逻辑键。代次 `Generation` 在节点每次
  启动时重新生成，因此同名节点重启、序号从头计数也不会与历史事件混淆。
- `Fragment` 是分片投递的片段，同一事件的片段按 `FragmentID` 去重；重复投递幂等
  丢弃，同 ID 不同载荷返回 `ErrConflict`。
- 事件首次发布 `Version=1`；超时先发半成品（`Complete=false`），补正片段在补正窗口
  内到达时沿用原 `EventKey` 覆盖写并把 `Version` 递增，不产生新的逻辑事件。
- 序号回绕由 `Config.WrapModulus` 控制，内部用回绕周期 `Cycle` 给存储物理键消歧，
  业务事件身份仍是 `EventKey`。

## 组装与发布规则

- **完整发布**：声明了 `ExpectedFragments` 且收齐，或所有必需分片的水位线均越过该事件。
- **超时发布**：`PublishTimeout` 到期仍未收齐，强制发布半成品等待补正。
- **水位线**：`ObserveWatermark` 收集各分片已处理序号；配置 `RequiredShards` 后必须
  全部上报才推进，缺一个分片都不会提前发布。
- **封板**：超过 `CorrectionWindow` 的事件拒绝迟到片段（`ErrEventSealed`），
  窗口为 0 时无限期接受补正。
- **持久化**：`New` 传入状态文件路径后，组装状态每次变更原子落盘；重开同一文件即
  模拟消费者重启，未确认片段的重放不会制造重复事件。

## 存储替身

- `MemStore`：纯内存幂等存储，带调用计数与版本历史。
- `FileStore`：JSON 原子落盘（临时文件 + rename），重启后数据与统计完整恢复；
  落盘失败整体回滚，内存与磁盘保持一致。

`Store.Put` 的幂等契约：同版本同内容重放返回 `changed=false`；更高版本覆盖并递增；
同版本内容冲突返回 `ErrConflict`；旧版本拒绝写入。

## 验证

```sh
go test -race ./...
```

测试覆盖：重复片段去重、冲突检测、超时发布与迟到补正、水位线发布、封板拒绝、
消费者重启重放、同名节点代次隔离、序号回绕消歧、并发幂等写与落盘失败回滚。
