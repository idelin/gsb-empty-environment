流处理引擎执行双流时间区间连接 `A JOIN B ON A.key = B.key AND B.ts BETWEEN A.ts + lower AND A.ts + upper`（支持 `INNER`、`LEFT`、`RIGHT`、`FULL OUTER` 及正负任意上下界）时，面对左右流各自独立推进的水位（Watermark）和乱序迟到记录，最容易犯两类致命错误：一是在外连接里过早把尚未匹配到的左记录按 `(a, NULL)` 发出，随后合法时间窗内的右记录才迟到到达，造成既发了 `(a, NULL)` 又发了 `(a, b)` 的重复脏结果；二是状态清理水位算错正负号（左流记录 `a` 必须保留直至右流水位严格超过 `a.ts + upper + allowedLateness`，右流记录 `b` 必须保留直至左流水位严格超过 `b.ts - lower + allowedLateness`！），导致早删漏连或永不回收 OOM。为流处理运行时交付可导入的 Go 双流区间连接执行包。组件接收来自左流和右流的乱序事件 `(key, ts, payload)` 及独立水位推进事件 `AdvanceLeftWatermark(wm)` / `AdvanceRightWatermark(wm)`，支持配置连接类型、区间 `[lower, upper]` 与 `allowedLateness >= 0`。规则：1）记录到达时先判定是否已过期（超过对端已清理界限的极迟到数据路由至 `SideOutput`，绝不污染主连接状态！）；2）未过期记录存入己方按键与时间索引的状态缓存，并立即扫描对端状态缓存中落在匹配区间内的全部记录输出内连接结果（同时标记双方 `matched = true`）；3）仅当对端水位（含 `allowedLateness`）推进越过记录的最晚可能匹配界限时，才原子清理该记录，且仅在对应方向为外连接且 `matched == false` 时恰好发出一次补空记录 `(a, NULL)` 或 `(NULL, b)`；4）精确报告任意时刻左右状态表滞留记录数，验证水位推进后过期状态零泄露。验收用大量乱序双流与正负区间（如 `[-50, -10]`、`[-20, +30]`、`[0, 0]`）对照全量批处理区间外连接，覆盖边界精确闭区间命中、迟到匹配抑制错误补空、超允许迟到进侧输出、`FULL OUTER` 双方零重复补空以及状态表精确归零回收。
