# 版本撤回安全回退

更新服务撤回漏洞版本时，客户端不能随意回退到更早的另一漏洞版本。为Go更新宿主实现版本图选择包，节点带已签名安全级别、兼容条件与撤回状态，合法边由清单指定；从当前版本选择可达且级别不降的最低迁移成本版本。最多30节点，返回路径和拒绝原因，用穷举小图测试撤回中间节点与零成本环。

## 包结构

- `graph.go`：图模型（`Manifest` / `VersionNode` / `Edge`）、清单校验、拒绝码与拒绝原因。
- `sig.go`：`LevelVerifier` 接口与 Ed25519 实现，安全级别必须先验签才会被采信。
- `select.go` / `dijkstra.go`：选择入口 `Select` 与支持零成本边的标签定值搜索。
- `*_test.go`：定向用例与 1–4 节点全部有向图的穷举交叉验证。

## 选择规则

1. 仅允许遍历清单中显式列出的边，客户端不自行推断迁移路径。
2. 进入任一节点前必须同时满足：级别签名验签通过、节点未撤回、兼容条件满足。
3. 每条边的目标节点安全级别不得低于源节点，因此不可能回退到更脆弱的版本。
4. 在所有可达且合规的“其他版本”中，按 `总成本 → 跳数 → 路径字典序` 选最优；边成本非负，允许零成本边和零成本环。
5. 不存在合规迁移时，若当前版本仍合规则返回零长度零成本兜底路径；当前版本本身不合规则返回结构化 `RejectReason`。

节点上限为 `MaxNodes = 30`，超出即按 `invalid_manifest` 拒绝。

## 拒绝原因

`RejectReason.Code` 区分：`invalid_manifest`、`verifier_missing`、
`current_not_found`、`node_not_found`、`bad_signature`、`revoked`、
`incompatible`、`no_eligible_destination`；节点级原因带 `NodeID` 与可读消息。
`NodeEligibility` 可单独查询某个节点被拒的具体原因。

## 测试

```sh
go test ./... -count=1
go test -race -count=1 ./...
```

穷举测试枚举 1–4 个节点的全部有向图（`2^(n*n)` 种边集，含自环与零成本环），
节点属性由掩码确定性派生（撤回、不兼容、坏签名、级别顺序、零成本边），
并用独立的 DFS 简单路径参考实现与 `Select` 的输出逐一比对。
