认证服务在离线快照恢复时保留了每次挑战的签名回执，但旧格式只列出可能匹配的设备步号，没有记录最终消费的步号。给 Go 认证宿主写可导入的单次授权恢复包。每个回执绑定账户、设备代次、请求 ID 和一组候选步号区间；候选由可信验证回调产生，不计算口令，也不输出任何设备秘密。同一请求 ID 的重复回执必须解释为同一次消费，不同请求不可消费同一步。设备恢复或更换密钥后，旧区间的票据不得映成新代次。对于新的认证请求，需要判定是否有一个具体候选步号，在所有符合旧回执的完整历史中都确定未消费；不能因为每个历史中分别还有某个可用步号就放行。若查到已提交的相同请求，只能返回其原结果；历史无解、必须重新同步和安全新消费需区分。提交前必须原子比较历史版本。输入最多5000条回执，候选由至多两个闭区间组成，步号48位，不能枚举全部步号或全部历史匹配。返回可独立复核的安全步号或未决区间证书，小范围用所有一对一分配对照相交区间、同请求重传、全局约束排掉局部候选和旧快照缺少最后一条记录。
