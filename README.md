加密信箱第一次离线投递时只保存握手摘要，几个月后接收方可能已换设备、轮换身份钥或撤销一部分预密钥。请给Go消息宿主实现可导入的历史会话恢复验收包。输入是签过名的目录检查点、设备增删事件、各设备的一次性公钥承诺树，以及消息携带的发送时检查点和消费回执。永久账户与设备实例分别标识，重新注册同名设备不得继承旧钥。允许离线见证先收到回执再收到目录前缀；只有能证明同一公钥承诺在该会话发起时仍获授权且只被这一会话摘要消费，才可把恢复密钥交给宿主回调。目录含冲突后缀时，只接受对所有可成立的分支都相同的会话身份；缺少包含证明与确有双重消费要分开。输出可独立验证的最小必要记录子集，最小指去掉任何记录都会失去其中一项证明。用小目录全量回放检验跨设备同序号、并发换钥、延迟到达的撤销和两个分支后来各有不同消费回执。

## recov 包

`recov/` 给出零第三方依赖（仅 Go 标准库）的可导入实现与完整测试。

### 身份模型

- `AccountID`：永久账户，跨设备生命周期存在。
- `DeviceName`：账户内可复用的设备名；`InstanceID`：每次注册产生的唯一设备实例。
- 同名设备注销后重新注册得到全新 `InstanceID` 与全新身份钥/OPK 树，
  折叠事件前缀时任何复用旧实例或继承旧钥的操作都会返回 `ErrReRegistration`。

### 数据与信任锚

- 目录日志：`Event` 叶子（注册/注销/换钥/OPK 树挂载/OPK 撤销）由目录 ed25519
  私钥对 `Checkpoint` 签名覆盖。
- 回执日志：见证对每条 `Receipt` 的叶子哈希做检查点签名。
- OPK 承诺树：RFC 6962 风格 Merkle 树，叶子承诺由账户/实例/序号/公钥域分隔派生。
- 宿主只需预置两个信任公钥：目录验签钥与见证验签钥。

### 判定流水线（`Importer.Evaluate`）

1. 校验消息携带的发送时目录检查点签名。
2. 验证 OPK 承诺在该实例承诺树内的包含证明（失败归类为 `ErrMissingInclusion`）。
3. 重建发送时检查点上所有“可成立”的目录分支（冲突后缀产生多分支）。
4. 比较各分支会话身份：不一致返回 `ErrForkAmbiguity`；一致后再查授权状态，
   未授权返回 `ErrNotAuthorized`。
5. 在所有可成立回执分支上统计该承诺的消费者：
   - 找不到本会话回执 → `ErrMissingInclusion`；
   - 存在第二个不同会话摘要 → `ErrDoubleConsumption`（与缺少包含证明严格分开）；
   - 同一会话的重复回执不算双花。
6. 证据未到齐（如回执先到、目录前缀后到）返回 `ErrPending`，补齐后可重判。

全部通过后 `Importer.RecoverSession` / `RecoverFromPackage` 才用 P-256 ECDH +
HKDF + AES-GCM 解封恢复密钥，并交给 `HostCallback`；验收失败绝不触发回调。

### 验收包的最小性

`BuildAcceptancePackage` 输出的每条记录都承担不可替代的证明：会话信封、OPK 承诺树、
发送时检查点及其完整事件前缀、一个可重放回执检查点及其完整回执前缀。
`assertMinimal` 在构建时逐条删除并断言独立验证必然失败；清单由见证签名，
`VerifyAcceptancePackage` 不依赖任何历史状态即可重放。

### 测试

`go test ./...` 以小目录全量回放覆盖：跨设备同序号、并发换钥、延迟撤销、
同名重注册不继承、回执先到的乱序、缺少包含证明与双花分类、目录冲突后缀、
两个回执分支各有不同消费回执，以及验收包的最小性与篡改检测。
