# baselinepatch

基于「基线摘要 + 原子编辑」的差分编解码，纯 Go 标准库实现。

一个 `Patch` 只针对**唯一一份**基线文档：补丁头携带基线与目标的
SHA-256 规范化摘要，应用前先验基线、应用后再验目标；任何一步失败都不
改动调用方的文档（原子应用）。逆差分只依赖补丁内记录的旧值，不需要基线。

## 自行定义的序列化范围

支持的文档值仅限以下类型（明确拒绝其它一切，不做隐式转换）：

- `nil`（JSON null）
- `bool`
- `float64`（仅有限数；`NaN`、`±Inf` 拒绝，保证可移植）
- `string`
- `[]any`（数组）
- `map[string]any`（对象；编码时键按字典序规范化）

明确**不支持**：`int`/`int64`/`float32` 等数值类型、`json.Number`、
结构体、指针、函数、外键 map、`[]string` 等。文档根必须是对象。

## 语义约定

- **缺基线拒绝，不猜默认对象**：`Apply(nil, p)` 返回 `ErrMissingBaseline`，
  绝不会把缺失基线当成 `{}`。
- **同长度不同内容不通过**：摘要是内容哈希（SHA-256 over 规范化编码），
  与序列化长度无关；调换两个数组元素即使长度完全相同也会被拒绝。
- **删除 ≠ 设 null**：`OpDelete` 移除键（键变为不存在）；`OpSet` 写入
  `nil` 保留键且值为 null，二者摘要不同、逆操作也不同。
- **正反差分恢复原图身份约定**：`Apply(Apply(base, p), Inverse(p))`
  的规范化摘要等于原基线摘要。float 按位保留（`-0.0` ≠ `+0.0`），
  对象键序不影响身份，新增的 null 键的逆操作是「删除」而非「置 null」。
- **解码不执行宿主代码**：格式中没有类型注册表、接口、函数指针或插件；
  解码只产出上述六种普通值，不调用任何用户提供的代码。
- **先验证长度再分配**：所有长度前缀先过两道关——硬上限（字符串 64MiB、
  数组/对象成员约 4M、路径 4096 段、操作 1M）与剩余缓冲区字节数——
  通过后才 `make`；varint 拒绝 10 字节以上的溢出编码；对象重复键拒绝。

## 二进制格式 `BPDIFF01`

补丁：

```
"BPDIFF01"            8 字节魔数
version               1 字节（=1）
baseline digest       32 字节 SHA-256
target digest         32 字节 SHA-256
op count              uvarint
ops...
```

每个操作：`kind`（1 字节）、路径段数 uvarint + 各段长度前缀字符串，
然后是种类相关载荷：

- `OpSet(1)`：old-exists 标志 1 字节、新值（规范化编码）、
  若旧值存在则再跟旧值；
- `OpDelete(2)`：被删除的旧值；
- `OpSplice(3)`：`index` uvarint、`deleteCount` uvarint、插入元素数及
  各值、被删元素数（=deleteCount）及各值。

值标签：`0 null | 1 bool | 2 float64(BE) | 3 string | 4 array | 5 object`，
容器均以 uvarint 成员数开头，object 成员按键升序、键长前缀。

数组差异用 LCS 计算，多个变更区间各生成一个 splice，并按索引**降序**
发射，保证正向应用时前面的索引不随长度变化而失效；同一数组只允许一个
splice（结构校验拒绝多个）。

## 应用流程（原子）

1. 基线非空且根为对象；补丁结构合法；
2. 计算基线摘要，必须等于 `BaselineDigest`；
3. 深拷贝基线（同时再次验证全部值类型）；
4. 对拷贝做 preflight：逐操作检查路径、父容器类型、数组边界，并比对
   所有旧值/被删元素（补丁自校验）；
5. 全部通过后才执行编辑；
6. 计算结果摘要，必须等于 `TargetDigest`。

原基线全程只读；任何失败都返回错误且结果为 nil。
