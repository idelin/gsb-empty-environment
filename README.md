制品目录里有已登记漏洞的包，但发布方声明相关实现没有进入最终映像。给 Go 发布宿主写可导入的 VEX 证明验收包，仅处理已签名的符号摘要和链接清单，不运行任何二进制。每个对象由编译者、源摘要和编译配置共同标识，导出符号分为强、弱和同组选一的实现；仅符号名字相同不能证明来自已修复对象。宿主提供入口引用、按顺序扫描的归档组、可能的条件引用及有签名的候选配置。组内会重复提取能满足尚未解析引用的对象直到不再变化，已提取对象又可引入新引用；同组选一必须整组一致，不能在每个符号上各选较有利实现。只有所有被部署方允许且实际可链接的配置、所有合法弱绑定选择下，入口都不能到达被标记的对象身份，才可接受该制品的“不受影响”。存在合法配置但缺签名证据须返回未知，不能按不可达处理。返回可独立验收的证书，核对条件一致性、提取闭包、最终绑定和入口可达性，支持同一归档成员跨配置共享证据。用小归档逐配置逐绑定枚举对照同名弱符号被强实现替代、同组多个符号的关联选择、循环引用、存在依赖但入口不可达及实际链接才出现的间接调用。
