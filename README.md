# CRDT 列表模型（TypeScript）

一个收敛的列表模型（RGA 风格），配合全排列测试验证乱序/重复消息下的收敛性。

## 语义

- **插入**：消息携带全局唯一 `id` 与前驱 `pred`（`ROOT_ID = ''` 表示表头）。
- **同前驱排序**：共享同一前驱的元素按 `id` 字典序升序排列。
- **删除即墓碑**：删除只打标记，节点保留在树中，后续插入仍可以它为锚点。
- **删除可先于插入到达**：墓碑记录在 `deletedIds` 中，插入物化时回放。
- **未知前驱暂存而非丢弃**：`pending` 按缺失前驱分桶，前驱物化时级联回放。
- **乱序/重复收敛**：终态是消息集合的纯函数；重复插入/删除幂等（同 id 首达优先）。

## 诊断

`diagnostics()` 返回缺依赖信息，全部依赖到达后收敛为空：

- `pending`：因前驱未知而暂存的插入（按 id 排序）。
- `missingPredecessors`：被暂存插入引用但尚未物化的前驱 id。
- `deletesAwaitingInsert`：目标插入尚未应用的删除。

## 结构

- `src/list-model.ts` — 增量模型（`ListModel`）。
- `test/reference.ts` — 参照实现：从消息集合一次性计算终态（不动增量逻辑）。
- `test/convergence.test.ts` — 对每个场景的消息集合做**全排列**（5–6 条短消息，
  24–720 种顺序），每种顺序喂给全新副本，断言：
  1. 所有副本收敛到同一快照与诊断；
  2. 与参照实现逐一致；
  3. 显式期望（最终顺序、墓碑标记、缺依赖诊断）独立成立。
  另有 "healing" 场景：先到达 5/6 条消息时诊断非空且与参照一致，补最后一条后收敛。
- `tools/strip-types.mjs` / `tools/run-tests.mjs` — 离线环境没有 `tsc`，
  测试通过一个小型类型擦除器直接运行 TS 源码（仅支持源码用到的可擦除子集，
  约定见文件头注释）。

## 运行

```sh
npm test           # 离线可跑：node tools/run-tests.mjs
npm run typecheck  # 有 tsc 时的权威类型检查
npm run build      # 编译到 dist/
```
