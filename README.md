生产集群同时开启水平弹缩（HPA）与垂直弹缩（VPA）时，常在三个边界引发严重震荡或雪崩：一是 HPA 处理新启动未就绪（Unready）或缺失指标的 Pod 时，K8s 规范要求按“保守不误动作”原则分类处理（扩容方向计算时排除未就绪和刚启动初始化期内的 Pod，缩容方向却必须将未就绪 Pod 按 `0` 利用率计入分母、将缺失指标 Pod 按 `100%` 目标值计入，防止误缩掉正常副本！）；二是 VPA 基于指数衰减权重直方图推算内存与 CPU 推荐值时，必须叠加 OOM 事件触发的紧急峰冲（`max(lastOOM * (1 + bumpUpRatio), lastOOM + minBumpBytes)`）并受 `minAllowed`/`maxAllowed` 钳位；三是 HPA 与 VPA 若同时盯紧 CPU 指标，一方调副本另一方调单核配额会形成互搏震荡。为弹性伸缩控制器交付可导入的 Go HPA+VPA 协同决策引擎。规则：1）HPA 严格遵循 K8s 算法实现多指标（资源利用率、Pod 自定义指标）计算：`tolerance` 死区跳过、`unready`/`missing` 双向保守计数（算出缩容候选值与扩容候选值若方向反转则保持当前副本数！）、`scaleUp`/`scaleDown` 各自独立的稳定窗口历史极值（扩容取窗内最小还是最大？按规范稳定窗缩容取窗内最大值防抖、扩容取窗内最小值防过冲！）与每周期步长速率限制（`Pods`/`Percent` 取 `Max` 或 `Min` 策略）；2）VPA 实现带半衰期 `halfLife` 的指数衰减分桶直方图，计算 `lowerBound`/`target`/`uncappedTarget`/`upperBound` 分位推荐，处理 OOM 事件记录并按 `oomBumpUpRatio` 与 `oomMinBumpBytes` 抬升下界，再按容器 `minAllowed`/`maxAllowed` 与 `ControlledResources` 裁切；3）协同仲裁器检测 HPA 与 VPA 是否在同资源维度冲突（例如 HPA 追踪 CPU 而 VPA 未禁用 CPU 自动调整时自动将 VPA CPU 降级为 `Off`/仅建议模式并输出冲突告警，放行 VPA 独立调整内存！）。验收覆盖未就绪与缺指标 Pod 在扩/缩方向的不对称保守计算、死区与稳定窗防抖、VPA 指数衰减权重随时间漂移与 OOM 峰冲抬升，以及 HPA+VPA CPU 互搏自动降级协同。
