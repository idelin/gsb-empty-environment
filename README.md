文件系统崩溃一致性测试经常抓到异常磁盘镜像，但要区分它是底层驱动违背 Flush/FUA 持久性契约的真 Bug，还是易失写缓存允许的合法乱序落盘子集。给存储验证框架交付可导入的 Go 崩溃镜像判定包。输入初始磁盘扇区内容、主机 I/O 历史（若干普通写 `Write(id, sector, data)`、带强制落盘标志的 `WriteFUA(id, sector, data)` 与全局 `Flush(id)`，每条带整数提交时刻 `submit` 和可选完成时刻 `complete`；未完成操作 `complete=nil`）以及一幅崩溃后观测到的目标磁盘扇区镜像。块层持久性契约定义：任何普通写可在 `[submit, ∞)` 任意时刻落盘或丢弃，但若存在已完成的 Flush，则在该 Flush 的 `submit` 之前已完成的全部写（及所有已完成的 FUA 写）必然已在崩溃前持久，且同一扇区上落盘的写不能违背先后完成（`complete(a) < submit(b)`）的因果覆盖序；并发写同一扇区可按任一顺序生效。组件判定目标镜像是否合法可达：合法时返回一组满足全部约束的持久写子集与生效偏序，非法时指出违背契约的精确扇区与强制先于其落盘的缺失/被逆序覆盖写编号。验收在写操作不超过十二的小历史中用全合法子集枚举对照判定结果，覆盖未完成普通写部分落盘、Flush 屏障锁住前序完成写但不锁并发写、FUA 独立落盘绕过未 Flush 的旧普通写，以及同扇区因果逆序覆盖被判非法。
