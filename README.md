# read-repair 模拟器

单进程事件模拟器中的读修复（read-repair）实现，仅使用 Go 标准库。
通信延迟、丢包故障、时间流逝全部由模拟器（虚拟时钟 + 事件堆）控制，结果完全确定、可复现。

## 结构

- `sim.go` — 事件模拟器：虚拟时钟、事件堆、可取消定时器
- `net.go` — 模拟网络：随机延迟、`DropHook` 故障注入、消息计数
- `store.go` — 副本：版本化值，唯一写入点 `Apply` 执行 last-write-wins 守卫
- `repair.go` — 修复管理器：按键合并、全局并发上限、有界重试
- `coordinator.go` — 读写路径：读时增量检测落后副本并承诺修复；读可取消
- `main.go` — 六个演示场景
- `system_test.go` — 安全性与活性证据测试

## 关键性质

- **按键合并**：同一 `(key, replica)` 的重复承诺合并为一条，只保留最新版本；
  同键 100 次读只产生每个落后副本 1 条修复 RPC。
- **全局限并发**：在途修复 RPC 总数不超过 `maxInflight`，其余排队。
- **取消不丢承诺**：承诺进入 `RepairManager` 后即与读操作解耦，取消读不影响已承诺修复。
- **旧修复不覆盖新写**：副本侧 `Apply` 只接受严格更新的版本。
- **有界重试**：单目标最多 `maxAttempts` 次尝试，超时重排，耗尽则记录失败并终止。

## 运行

```sh
go run .        # 演示六个场景
go test -v ./... # 安全性 / 活性证据测试
```
