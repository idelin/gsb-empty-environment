# leasefed — 跨集群租约联邦与全局互斥控制器

主备跨数据中心（跨机房）全局活跃租约控制器。通过轻量级外部第三方
法官（Witness）维持跨机房全局单点写入租约；主机房整体掉电/失联时，
法官向备用机房颁发接管租约，彻底杜绝双机房双写。

## 架构

```
 机房1 (dc1)                机房2 (dc2)
 ┌──────────────┐          ┌──────────────┐
 │ Controller   │          │ Controller   │
 │  + Store(栅栏)│          │  + Store(栅栏)│
 └──────┬───────┘          └──────┬───────┘
        │  acquire/renew          │
        └──────────┬──────────────┘
                   ▼
          ┌─────────────────┐
          │ Witness (法官)   │  唯一租约权威：单条租约记录 + 单调递增 Epoch
          └─────────────────┘
```

- `witness/`：第三方法官。全局唯一租约（holder + 过期时间 + Epoch 栅栏令牌），
  HTTP API：`/lease/acquire`、`/lease/renew`、`/lease/status`。
  只有在前任租约**真正过期**后才把租约颁发给新机房，每次易主 Epoch +1。
- `controller/`：每个机房一个控制器。持有未过期租约 = 主（可写）；
  续约失败且本地租约到期 → 自动降级为只读备机；续约被法官拒绝
  （凭证失效/Epoch 已过期）→ 记录新栅栏令牌并降级为只读备机。
- `store/`：带栅栏令牌的 KV 存储。写入必须携带当前 Epoch，
  过期 Epoch 的写入被拒绝——即使"僵尸主"误以为自己仍持有租约也无法写入。
- `cmd/demo/`：完整运行样例（光纤挖断 → 接管 → 恢复降级）。

## 防双写的两层防线

1. **租约层**：法官在旧租约过期前绝不颁发新租约 → 任意时刻至多一个有效主。
2. **栅栏层**：Epoch 单调递增，存储拒绝携带旧 Epoch 的写 →
   即使主误判自己仍持有租约，其写入也会被存储层拒绝。

## 运行样例

```sh
go run ./cmd/demo
```

## 测试

```sh
go test ./...
```

验收场景见 `controller/federation_test.go`：
机房1 主、机房2 备 → 光纤挖断两机房失联 → 法官确认机房1 真正失联后
向机房2 颁发晋升租约 → 机房1 恢复后检测到法官凭证已失效，自动切换为只读备机。
