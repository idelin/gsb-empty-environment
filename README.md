制品签发要回答一个具体问题：给定根包的目标摘要，所有被允许的构建配置是否都只选到有来源证明的依赖？实现供 Go 签名宿主调用的闭包验收包。输入是有限候选包表，身份为名称、整数版本、源与内容摘要；每个依赖可有备选身份，并受最多 24 个共享布尔构建标志的条件控制。激活的每个包名全图只能选一个身份，引用环允许，闭包只计从根实际可达的包。来源证明绑定确切身份、构建标志条件和签发者策略代次；全局约束是二元布尔子句的合取。对每个允许配置分开判断：不存在合法解析为不可构建，有合法解析但某一种含未证明依赖为拒绝，所有合法解析均受证才为通过。输出把三类配置分别表示为按给定变量序约简的共享有序决策图，禁止逐配置生成树后再压缩，且禁止对同一个条件标志取反后把未受证传递依赖折叠进已证明分支。拒绝区须附能复现未受证依赖的具体选择和根引用链；检查器只用输入表复核证据。相互排斥分支不能合并成虚假冲突，同名不同源不能共用证明。用不超过六个开关的全枚举核对三个区域，在 24 个开关但仅两个影响结果的数据上检验节点预算，预算不足明确返回未定。
