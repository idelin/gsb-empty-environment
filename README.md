# lseq — LSEQ 协同序列（Go 标准库实现）

LSEQ（Logoot-Split）风格的协同编辑序列结构：为每个字符分配一个
**无界分数因果树**上的致密标识符（`Identifier = [(digit, site), ...]`），
标识符的全序即文档顺序，插入/删除操作满足交换律与幂等律，任意副本以
任意顺序合并同一操作集合后收敛到同一严格因果序。

## 自适应可变基数空间分配

- 每个位置是 `(digit uint32, site uint64)`，深度 `d` 处的分配窗口为
  `2^(4+d)`：**每深入一层，可用空间翻倍**，因此深度（即标识符位宽）
  随密集插入仅对数级平缓增长。
- 每一层随机选用 **boundary+**（靠左邻居分配，利于向右连续输入）或
  **boundary-**（靠右邻居分配，利于向左连续输入），任何固定插入模式
  都不会在每一层都撞上最坏情况（LSEQ 论文的核心思想）。
- 在任意两个紧邻标识符之间总能再分配出新标识符（缺失位置左界读 0、
  右界读 `MaxUint32`），空间致密且无界。

## 结构

- `identifier.go` — `Position` / `Identifier` / 全序比较 / `Allocator`
- `document.go` — `Document` 副本：本地 `Insert`/`Delete`，可交换、
  幂等的 `Merge`（墓碑删除 + 删除先行缓冲，删除与插入可乱序到达）
- `lseq_test.go` — 验收测试
- `cmd/lseqdemo` — 运行样例

## 运行

```sh
export GOCACHE=/tmp/gocache   # 如默认构建缓存不可写
go test ./... -v
go run ./cmd/lseqdemo
```

## 验收结果（本仓库实测）

- 开头/结尾 1000 次密集交替插入：`maxDepth=4`，直方图
  `depth1=502 depth2=4 depth3=7 depth4=487`，位宽增长平缓；
- 连续 2000 次尾部追加 / 头部前插：`maxDepth=3`；
- 3 节点操作集在 100 组随机全排列下合并，所有副本的标识符序列与
  文本逐位一致（严格因果序收敛）；删除先于插入到达时也能正确收敛。
