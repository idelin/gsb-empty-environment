# 数据同步校验和（Checksum）实时比对器

源库与目标库一致性在线巡检器。采用**分区滚动 XOR 校验和 + Merkle 树**机制：
在变更持续流动的同时，按分区持续增量计算两端的数据摘要并比对，
毫秒级发现丢数与数据篡改，并精确定位到主键 ID。

## 原理

```
            源库 TableStore                目标库 TableStore
            ┌──────────────┐              ┌──────────────┐
  变更流 ──▶│ 行数据 + 索引 │── 复制事件 ─▶│ 行数据 + 索引 │
            └──────┬───────┘              └──────┬───────┘
                   │ 增量维护                      │ 增量维护
                   ▼                              ▼
            ChecksumIndex                  ChecksumIndex
            P 个分区滚动 XOR                P 个分区滚动 XOR
                   │                              │
                   └────── Merkle 根哈希 ─────────┘
                              │ SyncInspector.patrol()
                              ▼
        L1 根哈希比对(O(1)) → L2 分区比对(O(P)) → L3 行级下钻定位主键
```

- **滚动 XOR 校验和**：每行哈希为 64 位值，分区校验和为区内行哈希的异或。
  插入 `^= hash(new)`，删除 `^= hash(old)`，更新 `^= hash(old) ^= hash(new)`，
  变更流动时 O(1) 增量维护，无需全表重算，且与应用顺序无关。
- **Merkle 树**：分区校验和为叶子，SHA-256 逐层聚合出根哈希，
  一致时一次比对即可放行整表。
- **三级下钻**：根失配 → 逐分区比对圈定失配分区 → 仅对失配分区做行级
  哈希 diff，输出主键、差异类型（`tampered` / `missing_in_target` /
  `missing_in_source`）与变更字段。

## 目录结构

- `src/hash.ts` — cyrb64 风格双通道 32 位行哈希（可替换为 SHA-256 截断）
- `src/checksum.ts` — 分区滚动 XOR 校验和索引 + Merkle 根
- `src/store.ts` — 内存表存储（模拟源库/目标库），写入即增量维护校验和
- `src/inspector.ts` — 巡检器：三级比对、失配定位、差异分类
- `src/cdc.ts` — 持续变更流模拟器（INSERT/UPDATE/DELETE、丢数/篡改注入）
- `src/demo.ts` — 验收场景运行样例
- `test/` — Node.js 内置测试（`node:test`）

## 运行

要求 Node.js ≥ 22.6（原生 TypeScript type-stripping），推荐 23.x。

```bash
npm run demo   # 运行样例
npm test       # 运行测试
```

## 测试结果

```

```

覆盖：哈希确定性、滚动 XOR 增量与全量重算等价、顺序无关性、Merkle 根
敏感性、篡改定位到主键与字段、丢数（missing_in_target）、幽灵行
（missing_in_source）、修复后恢复一致、30 万条变更流动中篡改单行当周期
捕获（延迟 < 1s 断言）、丢数与篡改并存同周期报出、无误报。
