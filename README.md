# 聚合签名协调方复用一次性nonce

多方签名协调方可能在收集nonce后更换消息，让同一个签名者对两个挑战使用同一nonce。为Go签名宿主实现本题自定义Schnorr会话组件，使用P-256：成员2至32人；所有哈希字段带大端8字节长度前缀且系数、nonce承诺、挑战使用不同固定域标签。成员公钥按压缩编码排序且不得重复，a_i为SHA256(域标签||完整名单||公钥)模群阶，零则带计数器重试，聚合公钥P=Σa_iP_i。每方先承诺SHA256(会话ID||自己的公钥||R_i)，全部承诺固定后才揭示R_i=r_iG；核对揭示后R=ΣR_i，挑战e绑定会话ID、完整名单、消息、P和R，部分签名z_i=r_i+e*a_i*x_i，协调方逐份验z_iG=R_i+e*a_iP_i再相加。签名者的nonce及消息绑定由宿主持久化接口保存，nonce在发出承诺前已绑定消息和名单；原子持久化已消费状态与部分签名结果，确认后才能交付部分签名；重试同一请求返回原结果，换消息、名单或R拒绝，中止后nonce永久废弃。定义可重放事件状态并实现两方真实签名测试，在每个持久化点注入失败，核对重启后不会再次计算已消费nonce的不同挑战；零聚合公钥或零聚合R终止会话。
