# 弱引用回调复活已撤销能力

宿主撤销脚本对象能力后，终结回调若把对象重新放回全局表，旧方法可能再次访问敏感资源。实现供Go运行时测试宿主调用的对象生命周期模型：对象有唯一逻辑ID、分配代次、状态{live,finalizing,dead}、能力代次及宿主资源ID；StrongAdd/StrongDrop维护强引用，降到0时进入finalizing并排队一次Finalize，WeakGet仅在live且强引用大于0时以原子方式加一并返回强引用。Finalize回调可由不可信脚本请求Resurrect到某全局槽，但只有宿主显式允许且能力仍未撤销时才恢复live；否则请求被记录但对象转dead并清除资源。Revoke先递增能力代次并清资源，所有方法票据绑定对象ID、分配代次和能力代次。Finalize完成后再次StrongDrop不得重复排队；dead地址可复用但代次递增，旧弱引用与票据失效。给定至多3线程事件搜索任何撤销后成功Call(resource)的最短交错，并提供正确实现及故意在回调后恢复旧资源的待审实现。覆盖回调内WeakGet、两次复活请求、撤销与Finalize并发、全局槽覆盖和地址复用；析构次数本身不是漏洞，必须出现真实资源调用。
