# 会议室安排工具 (roomsched)

对最多 16 场会议求精确最优安排: **主目标拒绝权重最小, 次目标拆合次数最少**,
并输出每个房间的状态时间线, 自动校验"两间被合并期间不能再分别分配"。

## 模型

- `numRooms` 个房间排成一排, 任意连续区间可合并为大房间; 会议需求 `rooms` 间,
  只能安排在容量 ≥ 需求的连续块内, 且会议中途不可换房。
- 合并操作耗时 `mergeTime`, 恰在会议开始前完成; 拆分(恢复)操作耗时 `splitTime`,
  把块恢复为独立单间。两者都计入"拆合操作数"。
- 时间轴从 0 开始, 准备操作不能落在负时间, 因此需要现场合并的会议最早于
  `mergeTime` 开始。
- 拆分/合并尽量晚做 (lazy): 不影响可行性, 且便于统计操作数。

## 用法

```sh
go run .                          # 运行内置示例
go run . -input examples/meetings.json
cat meetings.json | go run . -input -
go test ./...                     # 运行测试 (含合并排他性校验)
```

输入 JSON:

```json
{
  "numRooms": 4,
  "mergeTime": 1,
  "splitTime": 1,
  "meetings": [
    {"id": "A", "start": 1, "end": 6, "rooms": 2, "weight": 5}
  ]
}
```

输出: 拒绝权重与拒绝列表、拆合操作数、每场会议的分配区间、每个房间的
状态时间线 (空闲 / 合并准备 / 已合并 / 会议X / 拆分恢复), 末尾打印校验结论。

## 求解与校验

- `solver.go`: 按会议开始时间分支限界 DFS, 状态为当前房间划分及各块忙碌截止
  时间, 记忆化剪枝; 目标按 (拒绝权重, 操作数) 字典序比较。
- `timeline.go`: 按结果重放拆合与会议, 生成每房间状态段序列。
- `validate.go`: 独立校验——时间段不重叠、容量足够、准备时长符合配置、
  操作数一致; 并按时间切片扫描, **任意两间处于同一合并块的房间若被分别
  分配给不同会议 (或一方开会一方空闲) 即报违规**。
