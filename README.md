# 安全组规则回溯解释

云网络安全组包含引用其他组的规则，成员变更后解释不能只列最终放行条目。实现供Go网络宿主调用的增量判定包，组成员是地址集合，规则支持源组与目标端口匹配，规则之间取并；一次成员与规则事务原子发布。查询返回所有最小放行证据，撤销引用仅重算受影响关系。用全量重建核对循环组引用、空组和同地址多组，不提供管理后台。

## 模型

- 基础事实：组的成员是地址集合；`Rule` 以源组 + 目标组 + 目标端口表达单跳引用，组成员不沿规则做传递展开，因此循环引用合法且不会递归。
- 派生关系：`(源地址, 目标组, 端口)` 到最小证据集合；多条规则取并，每条匹配规则独立贡献一条 `Evidence{Rule, SourceAddress}`，证据只含基础事实、不嵌套其他证据。

## 用法

```go
eng := netsec.NewEngine()

// 成员与规则在一个事务里暂存，Apply 原子发布；校验失败整体不落地。
err := eng.Apply(netsec.NewTxn().
    AddMember("web", "10.0.0.1").
    PutRule(netsec.Rule{ID: "r1", TargetGroup: "db", SourceGroup: "web", DstPort: 5432}))

// 查询返回所有最小放行证据，而不只是布尔结果。
for _, ev := range eng.Explain("10.0.0.1", "db", 5432) {
    // ev.Rule.ID == "r1", ev.SourceAddress == "10.0.0.1"
}

// 全量重建核对：派生索引一致性 + 循环引用 / 空组 / 同地址多组审计。
report := eng.CheckRebuild()
_ = report.Consistent
```

## 设计要点

- 事务：`Txn` 暂存增删操作，`Apply` 先全量校验再持写锁发布；读路径持读锁，发布对查询原子可见，`Version` 仅在成功提交后递增。
- 增量：成员变更只重算引用该组的规则，规则增删只重算该规则；按规则对派生证据做 diff，撤销引用不会触发全量扫描。
- 核对：`CheckRebuild` 从基础事实独立重算全部派生关系并比对增量索引，同时报告规则引用图中的所有环（含自环）、空组与跨组共享地址。
- 边界：空源组不产生证据；同一地址可属于多个组并各自贡献证据；同事务支持“先删后增”替换同 ID 规则。
- 范围：仅判定库，不含任何管理后台或外部服务。
