# 加密附件分块可被跨文件拼接

聊天附件每块单独加密，若块标签不绑定文件身份和位置，攻击者可从另一附件拼入合法密文。给Go消息宿主实现可导入的附件封装包：每个附件随机fileID32字节、fileKey32字节、固定chunkSize和总明文长度；块号从0连续，块明文长度除最后一块外恰为chunkSize。每块nonce=HMAC-SHA256(fileKey,'nonce'||fileID||大端块号)前12字节，AEAD附加数据绑定协议版本、fileID、块号、总块数、总长度、该块明文长度和整体metadata摘要。清单含每块密文SHA256、Merkle根、chunkSize、总长度、metadata摘要及fileKey给每个收件设备的封装项；清单由发送设备Ed25519签名并绑定会话ID和消息ID。解密先验清单签名与设备封装身份，再按请求顺序验证块摘要、Merkle路径和AEAD；重复块号、缺块、非末块短块或总长度不符整体失败，不发布部分文件。支持流式读取时只向隔离临时对象写已验块，全部完成再原子发布。用两个fileKey相同但fileID不同的夹具测试跨文件块、交换块、截断、收件deviceID唯一，收件deviceID唯一，重复收件设备、metadata改写及最后块边界，失败时文件回调零调用。
