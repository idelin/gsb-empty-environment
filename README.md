# 实时信号队列租户隔离

受限进程向宿主代理发送信号时，排队载荷和权限不能只在发送端检查。给Go信号宿主实现投递包，标准信号同种类合并但实时信号逐条保留，队列按租户计费；目标身份代次在入队固定，投递时重新核验授权，取消与投递只释放一次额度。用阻塞接收器测试目标重启、合并规则及高频租户不能占尽保留槽位。

## 实现

包 `netsec`（`doc.go`、`types.go`、`errors.go`、`host.go`）提供信号宿主：

- **标准/实时信号**：信号 1..31 为标准信号，按 `(目标, 身份代次, 信号)` 合并，多次发送折叠为一个信封并累计 `Coalesced`；信号 32..64 为实时信号，逐条排队并携带不透明载荷，入队时复制载荷并校验大小。
- **按租户计费**：每个信封占用一个全局槽位并计入发送租户。准入依次检查租户配额、全局容量和保留槽位；`ReservedSlots` 把单租户上限锁定为 `Capacity-ReservedSlots`，高频租户无法占尽为其他租户保留的槽位。
- **身份代次与再授权**：`Send` 时把目标当前代次固定在信封上并做入队授权；每个目标有独立投递泵，弹出信封后在锁外按固定代次重新调用 `Authorizer`。授权未过则原地停放（仍计费、保持顺序），`RefreshAuth` 唤醒重检；`Restart` 提升代次并使旧代次信封失效。
- **一次性释放**：槽位释放集中在 `QueuedEnvelope.release`，由互斥量保证投递、取消、重启/关闭三条路径至多释放一次，计费不会变成负数。
- **阻塞接收器**：目标通道无缓冲，接收器不读取时投递泵阻塞，仅背压该目标；取消在途信封、重启或关闭都能通过 `recheck`/`stop` 通道打断阻塞点。

## 测试

`host_test.go` 使用阻塞接收器与确定性阶段授权器覆盖：

- 标准信号合并、不同种类不合并、实时信号逐条保留及载荷隔离；
- 目标重启后旧代次信封不投递且槽位归零，新代次使用新通道；
- 投递阶段重新核验授权，撤销后停放、重新授权后投递；
- 高频租户达到 `Capacity-ReservedSlots` 即被拒，其他租户仍可使用保留槽位；
- 取消、重启、关闭并发下槽位精确释放一次（`go test -race`）。
