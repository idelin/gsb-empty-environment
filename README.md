# 系统调用代理对象绑定

沙箱把文件打开请求交给受信代理时，进程退出和请求号复用可能导致代办给错进程。本包（`netsec`）实现供 Go 代理宿主调用的请求组件，保证句柄只进入提交请求的那个进程实例，且所有权只转移一次。

## 组件

- `system.go`：`System` 宿主接口（`Open` / `InjectHandle` / `SendResponse` / `Close`）、可选的 `Checkpointer` 检查点钩子，以及 `ProcessRef`（PID + 可信进程代次）、`RequestID`、`Handle` 类型。
- `request.go`：`Registry` 进程与请求注册表。代次由宿主进程监管者可信提供；重启（含 PID 复用）推进代次并把旧请求原子标记为失效。路径字节在提交时私有拷贝，调用方事后修改不影响实际打开的路径。
- `manager.go`：`Manager.Handle` 编排一次请求，强制执行两道有效性门并维护句柄所有权状态机。

## 安全不变量

1. **执行前门**：`Open` 之前校验进程实例与请求仍有效；重启落在该窗口内时不执行任何特权操作。
2. **交付前门**：`InjectHandle` 之前再次校验；`Open` 与注入之间发生重启时，已打开的代理句柄立即 `Close`，绝不注入替代进程。
3. **实例绑定**：`InjectHandle` 只接受与 `ProcessRef.Generation` 匹配的存活实例，代次不符直接失败。
4. **单次转移**：句柄注入成功即脱离代理；此后代理既不关闭也不二次注入。注入成功但 `SendResponse` 失败时返回 `ErrResponseFailed`，句柄留在目标进程，交由宿主带外回收。
5. **请求 ID 不复用**：同一存活实例内，已占用（活动或已转移）的请求 ID 拒绝重提；只有失败/失效槽位可替换。代次键控使跨重启的同 ID 请求天然隔离。

## 测试

`fake_system_test.go` 提供可暂停的 `System` 测试替身：四个检查点可分别 `arm`/`waitReached`/`releaseOnce`，把进程重启精确插入请求生命周期的任意窗口；替身自身也强制代次匹配与单次转移，违反规则会计入 `violations`。

场景见 `manager_test.go`：

- 正常路径与并发压力（每句柄恰好一次注入、零关闭、零违规）
- 执行前重启（无句柄产生，请求失效）
- 打开后、交付前重启（句柄立即关闭且不转移）
- 跨重启同请求 ID 复用（两个独立句柄、各自一次转移）
- 注入成功但响应失败（返回 `ErrResponseFailed`，不关闭、不重注）
- 注入与响应之间重启（句柄留在旧实例，新实例另开新句柄）
- 路径字节防御性拷贝、未知/过期进程拒绝、`Open`/`InjectHandle` 失败路径

go test -race -count=20 ./...
