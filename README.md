# 不可变段 + 删除位图索引

纯 Python 3.11 标准库实现（仅 `threading` / `unittest`），不使用任何搜索
服务或全文检索库。文档为本地合成 UTF-8 文本。

## 文件

- `tokenizer.py` — 分词器（规则见下）
- `index.py` — `Segment`（不可变段）、`Snapshot`（读快照）、`Index`（写入 + 后台合并）
- `demo.py` — 运行样例：`python3.11 demo.py`
- `test_index.py` — 测试：`python3.11 -m unittest -v`

## 分词规则

1. 输入为已解码的 UTF-8 字符串。
2. ASCII 字母/数字 `[A-Za-z0-9]` 的连续序列为一个词元，统一小写
   （`"Python3.11"` → `["python3", "11"]`）。
3. 每个 CJK 表意文字（U+4E00–U+9FFF、U+3400–U+4DBF、U+F900–U+FAFF）
   单独成词（`"水果"` → `["水", "果"]`）。
4. 其余字符（空白、标点、符号）均为分隔符。

查询用同一分词器；多词元按 AND 求交集。

## 核心机制

- **不可变段**：每次 `put`/`delete` 生成一个新段插入段列表头部；段创建后
  永不修改，因此读快照无需加锁。
- **版本遮蔽**：每个 docid 的写入分配单调递增版本号；快照内同一 docid
  只有最高版本可见，旧版本被遮蔽（查询时倒排命中必须来自可见版本所在段）。
- **删除位图（墓碑）**：`delete` 记录 `docid -> 删除时版本号`，
  版本号 ≤ 墓碑版本号的条目不可见；删除后重新 `put` 的更高版本不受影响。
- **读快照**：`snapshot()` 持有当前段列表引用，之后的写入、删除、合并
  都不影响旧读者。
- **后台合并**：合并线程在段数超阈值时合并最老的段。合并计算在锁外完成，
  只在交换段列表时加锁；合并期间的新写入落在更新的段里，不会被合并丢弃，
  交换时按对象身份校验目标段未被并发修改，冲突则放弃本次合并。
- **墓碑保留**：合并时被墓碑覆盖的条目直接丢弃；墓碑本身只有在所有未参与
  合并的段中都不存在被它覆盖的条目时才能丢弃，否则随合并结果保留。
- **统计**：`stats()` 只统计可见（未删除、未遮蔽）文档。

## 运行

```sh
python3.11 demo.py            # 运行样例
python3.11 -m unittest -v     # 20 个测试
```
