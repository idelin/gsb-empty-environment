PromQL 的 `rate()`、`increase()` 与 `irate()` 并非简单的首尾差值除以窗口长度：当区间内发生多次计数器重置、首尾样本距窗口边界有空隙、或者向窗口左边界外推时斜率会穿过零点，朴素线性外推就会把新启动进程的指标算偏甚至推导出负计数；同时 Prometheus 特有的陈旧标记 `StaleNaN`（特定位模式 `0x7ff0000000000002`）必须与普通数学 `NaN` 区分处理。为监控查询引擎交付可导入的 TypeScript PromQL 区间计数器求值包。输入为升序样本序列（毫秒时间戳 `t` 与 IEEE 754 `float64` 值，通过 `DataView`/`BigInt64Array` 精确识别 `StaleNaN`）、求值时间戳 `evalTs` 及窗口长度 `rangeMs`。严格遵循 Prometheus `extrapolatedRate` 规范：过滤掉全部 `StaleNaN` 样本（不把 `StaleNaN` 视作计数器重置，且若有效非陈旧样本少于 2 个则不输出该序列；普通 `NaN` 按 IEEE 语义传播）；累计相邻有效样本增量时，若 `v[i] < v[i-1]` 判定为计数器重置并累加 `v[i]` 而非差值；对 `rate`/`increase` 计算精确外推倍数：左右端距窗口边界的距离各受 `1.1 * avgInterval` 门限控制（超出门限时仅外推半个 `avgInterval` 防止稀疏采样过度放大！），且左端外推遇到计数器（`isCounter=true`）且 `v[0] >= 0` 时，若按平均斜率回推会在到达窗口左边界之前穿过零点，则左外推时长必须钳位至 `v[0] / (resultValue / sampledInterval)`；`increase` 乘以窗口秒数比例，`rate` 除以窗口秒数；`irate` 仅取窗口内最后两个非陈旧样本按重置规则计算瞬时速率且不做外推。验收覆盖多次计数器重置、新进程刚启动触发左边界零点钳位、稀疏采样触发 `1.1 * avgInterval` 半间隔截断、`StaleNaN` 与普通 `NaN` 精准区分以及 `irate` 末尾重置边界。
