加密信箱第一次离线投递时只保存握手摘要，几个月后接收方可能已换设备、轮换身份钥或撤销一部分预密钥。请给Go消息宿主实现可导入的历史会话恢复验收包。输入是签过名的目录检查点、设备增删事件、各设备的一次性公钥承诺树，以及消息携带的发送时检查点和消费回执。永久账户与设备实例分别标识，重新注册同名设备不得继承旧钥。允许离线见证先收到回执再收到目录前缀；只有能证明同一公钥承诺在该会话发起时仍获授权且只被这一会话摘要消费，才可把恢复密钥交给宿主回调。目录含冲突后缀时，只接受对所有可成立的分支都相同的会话身份；缺少包含证明与确有双重消费要分开。输出可独立验证的最小必要记录子集，最小指去掉任何记录都会失去其中一项证明。用小目录全量回放检验跨设备同序号、并发换钥、延迟到达的撤销和两个分支后来各有不同消费回执。

## 实现

代码位于 `recovery/`，仅依赖 Go 标准库（`crypto/ed25519`、`crypto/sha256`）。

- `types.go`：账户/设备实例标识、签名检查点、事件、预钥承诺树证明、
  回执与稀疏树证明、三态 `Decision` 与原因码。
- `merkle.go`：RFC 6962 风格日志树/预钥树的递归包含验证，以及 256 层
  稀疏默克尔树的包含、非包含证明。
- `acceptor.go`：乱序记录导入、签名检查点链与冲突分叉枚举、设备事件链
  完整性、发送时授权、回执单消费与宿主回调。
- `bundle.go`：`ExportBundle` 导出最小必要记录子集，`VerifyBundle`
  仅凭 Bundle 内信任锚独立验证，并逐条删除自检最小性。

## 信任与判定要点

- 永久账户 `AccountID` 与设备实例 `DeviceID` 分离；同名重注册产生新实例，
  检查点内的 `DeviceTail` 由目录签名，证明每个实例最后一条事件的全局位置。
- 记录可任意乱序导入。证明未到齐返回 `pending` 及专门原因码；证据足以
  否定时才返回 `rejected`，双花固定为 `double_spend`，与缺证明严格分开。
- 冲突后缀下枚举所有可成立分支；仅当每个分支在发送检查点处推导出的
  `SessionIdentity` 完全一致才放行。
- 恢复密钥材料只在 `accepted` 时经 `RecoveryCallback` 交付，解封由宿主负责。

## 测试

`go test ./...` 使用小目录全量回放，覆盖跨设备同序号、并发换钥、延迟
  到达的撤销、分叉后不同回执造成双花、回执先于目录前缀、同名重注册不
  继承旧钥，以及 Bundle 的独立验证与逐条最小性自检。
