容器调度器在集群资源耗尽时为高优先级 Pod 选择抢占目标节点，不仅要逐个模拟驱逐比待调度 Pod 优先级更低的现有 Pod，还必须同时兼顾多项相互牵制的约束：同一节点上可能有多个 PodDisruptionBudget（PDB）重叠匹配同一组低优先级 Pod（驱逐一个 Pod 可能同时扣减多个 PDB 预算并引发多重违例！）；节点上还可能存在已被先前调度轮次提名（`NominatedNodeName`）的高优先级等待 Pod，其预留资源绝不可被较低优先级的新抢占者挪用；更隐蔽的是，驱逐某个低优先级 Pod `X` 后，若节点上某个本不该被驱逐的高优先级留存 Pod `H` 依赖 `X` 满足硬性 `PodAffinity`（`requiredDuringSchedulingIgnoredDuringExecution`），则单驱逐 `X` 会使 `H` 陷入亲和违例！为调度器交付可导入的 Go 抢占评估与受害者最小化包。输入为集群节点集合（可用 CPU/内存/扩展资源与标签）、在跑 Pod 与已提名 Pod 列表（含优先级、`preemptionPolicy`、资源需求、标签、硬性 Pod 亲和/反亲和、启动时间）、全部 PDB 列表（选择器与当前剩余允许中断数 `disruptionsAllowed`）及待调度的抢占者 Pod。规则：1）若待调度 Pod 的 `preemptionPolicy == Never` 直接返回不可抢占；对每个候选节点，扣减所有优先级 `>=` 待调度者的已提名 Pod 占位资源，仅允许驱逐严格低优先级 Pod；2）对每个候选节点求解可行最小受害者集合——先按低优先级优先移除使资源与待调度者自身反亲和均满足，再贪心回填不破坏可行性的最高优先级受害者以最小化驱逐集，同时强制校验驱逐后所有留存 Pod 的硬性 Pod 亲和性均保持成立（若破坏了某个更低优先级留存 Pod 的亲和则一并驱逐；若破坏了更高优先级留存 Pod 的亲和则该驱逐组合非法！）；3）跨全部可行候选节点严格按标准决胜序选优：被违例的 PDB 数量最少（精确按多 PDB 重叠扣减后 `< 0` 的唯一 PDB 数计，而非按被驱逐 Pod 数计！） -> 受害者最高优先级最低 -> 受害者优先级总和最小 -> 受害者数量最少 -> 受害者中最新启动时间最晚优先 -> 节点名最小。验收覆盖多 PDB 重叠违例精确计数、高优先级已提名 Pod 占位保护、驱逐破坏高优先级留存 Pod 硬亲和拦截、回填精简受害者集与六级确定性决胜。
