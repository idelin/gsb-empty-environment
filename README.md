Btrfs / ZFS 等写时复制（CoW）文件系统通过只读快照增量 `send / receive` 完成异地容灾复制，其核心算法隐藏着三大极难写对的工程陷阱：1）**代际号（Generation-ID）共享子树剪枝**：每个 CoW B-Tree 节点记录物理块号与最后修改代际 `gen`；对比父快照 `S_parent` 与子快照 `S_child` 时，凡两棵树在相同路径指向**同一物理块号或节点 `gen <= parent_gen`** 的整棵子树必须直接跳过（验证增量遍历访问节点数仅与改动量成正比而非全树大小！）；2）**目录树重命名依赖环与路径占位破环（Orphan Rename）**：当子快照相对父快照把目录 `a/b` 与 `b/a` 互换位置、把原文件 `f` 删除并在同名路径 `f` 建目录、或者把父目录删掉前先把其中子目录移出到别处时，简单的“先建后删”或按 inode 顺序重命名必定撞路径冲突或 `ENOTEMPTY`！`send` 编码器必须对所有存在路径冲突、类型变更或重命名环的 inode 先发 `RENAME` 暂移至唯一临时孤儿名（如 `.orphan-<ino>`），待依赖父目录全部就绪、旧占位清除后再按拓扑序 `RENAME` 归位并清理已空旧目录！3）**物理块指纹级 `CLONE_EXTENT` 零拷贝传输与硬链接保持**：识别子快照文件区段若与父快照已有文件（或子快照内另一文件）共享同一底层物理 Extent（支持按偏移切片引用！），编码为紧凑 `CLONE_EXTENT` 指令而非重传完整字节，并精确维护硬链接（多路径共享同 inode）、文件截断（`TRUNCATE`）、权限与扩展属性（xattr）增量更新。为存储容灾引擎交付可导入的 Go CoW 快照树、代际裁剪增量 `send` 流编码器与 `receive` 重建包。验收覆盖共享大子树 `O(changed)` 节点访问计数断言、互换目录名与“文件变同名目录”冲突破环、跨快照 `CLONE_EXTENT` 零拷贝传输、硬链接/xattr 增量同步以及接收端重建后与源子快照逐 inode/路径/字节/硬链接/xattr 100% 同构。
