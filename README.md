分析型数据库执行引擎在严格内存页预算 `M`（每页最多存 `P` 行，任何时刻内存中驻留的哈希表页、分区写缓冲页与读缓冲页总数严格 `<= M`！）下执行大规模等值连接时，必须实现支持 `INNER`、`LEFT OUTER`、`RIGHT OUTER`、`FULL OUTER`、`LEFT SEMI` 与 `LEFT ANTI` 六种语义的混合 Grace 哈希连接（Hybrid Grace Hash Join），同时攻克数据倾斜与 `NULL` 语义陷阱：1）**混合驻留与动态分区溢出**：Build 阶段优先把分区 0 保留在内存哈希表，当内存页触及预算 `M` 时把其余分区刷出到受控磁盘页存储并随需增加溢出分区，Probe 阶段对命中驻留分区 0 的行直接即时连接、其余行按相同哈希函数路由写入对应 Probe 溢出分区（全程实时断言峰值内存页 `<= M` 并精确统计磁盘读写页数！）；2）**递归二次哈希与高倾斜（Skew）防死循环回退**：读取某对溢出分区 `(B_i, P_i)` 时，若 `B_i` 仍超过可用内存页，则换独立哈希种子对其递归二次分区；若连续递归达到深度上限或发现某单个高频热键（Skew Key）自身就超出内存页导致再分裂无效，必须自动切入**分块嵌套循环（Block-Nested Spill Loop）**逐批加载 `B_i` 块并与整段 `P_i` 流式配对，绝不可 OOM 或死循环！3）**六类连接语义与跨溢出分区的匹配标记保真**：在 `RIGHT OUTER`、`FULL OUTER` 或翻转 Build/Probe 侧的 `LEFT OUTER`/`LEFT ANTI` 中，同一条 Build 行可能在多批 Probe 块中被重复扫描——引擎必须为每条 Build 行持久记录 `matched` 位（仅当扫描完所有对应 Probe 块仍未匹配时才输出一次补空行！）；`LEFT SEMI` 每条左表行最多输出一次（绝不因右表多匹配而翻倍！）；4）**SQL `NULL` 连接键语义**：键列含 `NULL` 时永不与另一侧 `NULL` 匹配（`INNER`/`SEMI` 丢弃；`LEFT`/`RIGHT`/`FULL` 按各自方向补空输出；`LEFT ANTI` 保留带 `NULL` 键的左行——注意区分等值 `LEFT ANTI` 与 `NOT IN`！）。为分析型查询执行层交付可导入的 Go 混合 Grace 哈希连接包。验收在极小内存预算（如 `M=6` 页）、90% 单键极端倾斜、大量 `NULL` 与重复键数据集上，对照朴素内存全量参考器验证全部 6 种连接输出多重集 100% 一致、峰值内存严格 `<= M` 且高倾斜绝不死循环。
