密钥管理服务与证书导入网关受理用户上传的 PKCS#12（PFX / RFC 7292）密钥包时，若跳过 `MacData` 完整性验证、放任 `MacData.iterations` 设为 `1`（弱口令离线爆破）或 `10^8`（服务端 CPU 耗尽 DoS），或接受明文无加密私钥与弱加密套件（`pbeWithSHA1And40BitRC2-CBC` / `3DES` / `SHA-1`），攻击者可篡改受信任根证书包（在无口令下向 `SafeContents` 注入恶意 CA 证书）或发动解析 CPU 拒绝服务。为 Go 密码安全宿主实现可导入的原始 ASN.1 DER 级 PKCS#12（PFX）结构完整性与安全策略验证包，严禁联网（仅用标准库 `encoding/asn1`/`crypto/hmac`/`crypto/sha256`/`crypto/sha512`/`crypto/aes`/`crypto/cipher`）。组件严格实现：（1）严格 DER 解析 `PFX`（`version == 3`、`authSafe` `ContentInfo` 及强制存在的 `MacData`），硬拒绝缺失 `MacData`、尾随垃圾字节与非规范 BER 长度；（2）`MacData` 安全门禁与恒定时间验真：仅允许白名单 MAC 算法（`SHA-256`/`SHA-384`/`SHA-512` 或 `PBMAC1` PBKDF2-HMAC-SHA256，硬拒绝 `MD5`/`SHA-1` 降级）、校验盐值长度 ≥16 字节且迭代次数落入 `[minIter, maxIter]`（如 `[10000, 500000]`，既防弱迭代又防 DoS），按 RFC 7292 Appendix B 精确实现 `PKCS12KDF`（ID=3 MAC 键派生，含 BMPString UTF-16BE + 双零终止符编码）并恒定时间校验 `authSafe.content` 原始字节 HMAC；（3）解析 `AuthenticatedSafe` 与 `SafeBag`（`pkcs8ShroudedKeyBag`/`certBag`）：硬拒绝未加密的裸 `keyBag` 与 RC2/RC4/DES/3DES 弱 PBE OID，仅放行 PBES2 + AES-256-CBC/GCM。附缺失 `MacData`、篡改 `SafeContents` 注入 CA、`iterations=10^8` DoS、RC2/SHA-1 降级拦截与合法 PKCS#12 向量测试。
