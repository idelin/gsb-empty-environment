# stabber — 最小成本刺点求解器

给定闭整数区间集合和带非负成本的候选点，选出候选点的子集，使每个区间
至少被一个选中的点**刺中**(stabbing / hitting)。候选点可以共享覆盖多
个区间——求解器全局优化,绝不逐区间独立选最便宜点。

目标按字典序依次优化:

1. **总成本最小**(选中点成本之和)
2. **点数最少**
3. **字典序最小**(选中坐标升序列表的字典序)

## 构建与运行

```sh
go build -o stabber .
./stabber -input examples/feasible.json
cat examples/feasible.json | ./stabber          # 或从 stdin 读
```

## 输入格式 (JSON)

```json
{
  "intervals": [[1, 4], [2, 6]],
  "candidates": [{"x": 3, "cost": 4}, {"x": 5, "cost": 1}],
  "maxNodes": 0,
  "timeoutMs": 0,
  "verify": true,
  "verifyMax": 20
}
```

- `intervals`:闭区间 `[l, r]`,要求 `l <= r`。
- `candidates`:`x` 为整数坐标,`cost` 必填且非负;同一坐标重复时只保留最小成本。
- `maxNodes` / `timeoutMs`:搜索节点数 / 毫秒上限,`0` 表示不限(可被
  命令行 `-max-nodes` / `-timeout-ms` 覆盖)。
- `verify`:是否启用有限候选子集枚举核对(默认开);`verifyMax` 为参与
  枚举的候选点上限(默认 20,硬上限 26,另有 512MB 内存预算保护)。

## 输出格式 (JSON)

- `status`: `optimal` | `interrupted` | `infeasible` | `error`。
- `cost` / `count` / `points`:最优解(或中断时的现任可行解)。
- `proof`:逐区间被刺中的证明——每个区间(按输入顺序)给出一个选中的、
  落在该区间内的点。
- `infeasibleEvidence`:不可行证据——每个不含任何候选点的区间,附最近
  的左右候选点。
- `bounds`:成本下界 / 上界。`optimal` 时两者相等;`interrupted` 时
  下界取自中断瞬间 DFS 栈上各节点下界的最小值(有效全局下界),上界为
  现任可行解成本。
- `verification`:枚举核对结果——枚举子集数、可行子集数、枚举最优解及
  其与求解器结果是否一致(`matchesSolver`)。
- `stats`:区间数、候选点数、去重数、搜索节点数、耗时。

## 算法

- **主求解器**:分支定界。每步选取未被覆盖且右端点最小的区间,对落在
  其中的候选点(按成本升序)分支。下界 = 当前成本 + max(最少还需点数
  k × 全局最低成本, 未覆盖区间各自区间内最便宜候选成本的最大值),其中
  k 由"最右可用点"贪心精确求得。仅当下界严格劣于现任最优的
  (成本, 点数) 对时才剪枝,保证字典序最优不被剪掉。先用带冗余消除的
  贪心构造现任可行解。
- **枚举核对**:对全部 2^n 个子集用 lowbit 递推维护区间覆盖位集,独立
  求出同一目标序下的最优解并与主求解器比对。
