递归 DNS 解析器在验证 DNSSEC 否定应答（NXDOMAIN、NODATA、无签名委派与通配符扩展）时，NSEC3（RFC 5155）引入了加盐迭代 SHA-1 哈希、环形哈希区间覆盖、最近包围者（Closest Encloser）三元组证明以及 Opt-Out 标志；一旦哈希链环形回绕区间判断、空非终端（Empty Non-Terminal）判定或 Opt-Out 适用范围写错，攻击者就能伪造域名不存在或把已签名子域降级为无签名。为 DNSSEC 验证器交付可导入的 Go NSEC3 证明核验包。组件实现标准域名小写线格式编码、加盐迭代 SHA-1 计算（`H_0 = SHA1(wire_name || salt)`，`H_k = SHA1(H_{k-1} || salt)` 执行 `iterations` 次附加迭代）及 Base32hex（RFC 4648 扩展十六进制）编解码；实现环形覆盖判断（区分单记录全覆盖 `owner == next`、普通区间 `owner < x < next` 及跨零回绕 `owner > next && (x > owner || x < next)`）与 RFC 4034 窗口块型类型位图解析。支持四类否定证明核验：1）NXDOMAIN（必须找到精确匹配的 Closest Encloser、覆盖 Next Closer 的 NSEC3 以及覆盖 `*.<closest_encloser>` 的 NSEC3）；2）NODATA（精确匹配目标哈希且位图不含请求类型、不含 CNAME，若是 DS 查询还需排除 SOA；或精确匹配空非终端，或 Opt-Out 覆盖的未签名委派）；3）无签名委派（Next Closer 覆盖记录必须置位 Opt-Out 标志且 Closest Encloser 自身非委派点）；4）通配符应答（核验 Next Closer 被覆盖以防屏蔽更具体子域）。须拒绝迭代次数超上限、未知哈希算法、跨区哈希不匹配以及在未置位 Opt-Out 时试图用覆盖记录充当无签名委派。验收覆盖 RFC 5155 附录 A 标准哈希向量、环形回绕边界、空非终端 NODATA、Opt-Out 合法与非法伪造拦截以及通配符 Next Closer 证明。
