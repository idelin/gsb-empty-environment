递归解析器与权威安全网关在离线校验 DNSSEC（RFC 4035 / RFC 5155）的 `NXDOMAIN` 与 `NODATA` 否定应答时，若仅检查 NSEC3 记录签名有效而未按规范验证最近封闭者（Closest Encloser）匹配、下一更接近名（Next Closer）与源通配符（`*.<ce>`）的哈希区间覆盖，或放任攻击者利用高迭代次数触发 CPU 耗尽以及滥用 `Opt-Out` 标志伪造已签名委托域的 NXDOMAIN，中间人可对关键域名实施静默降级或拒绝服务。为 Go DNS 安全宿主实现可导入的 DNSSEC NSEC3 否定存在证明与通配符扩展验证包，严禁联网（仅用标准库 `crypto/sha1` 等）。组件接收规范化的查询名（QNAME）、查询类型（QTYPE）、应答码（NXDOMAIN/NOERROR）与已验签的 NSEC3 记录集合：严格实现 RFC 5155 迭代哈希计算（含规范小写线格式编码、盐值拼接，并对超过策略上限如 50 次的迭代参数直接按降级/DoS 拒绝）；完整判定三类证明：（1）`NXDOMAIN` 必须同时证明存在精确匹配的 Closest Encloser、Next Closer 哈希严格落入某条 NSEC3 覆盖开区间（正确处理环形回绕与单记录全环），且 `*.<ce>` 亦被覆盖；（2）`NODATA` 精确区分普通无类型、空非终端（ENT）及未签名委托（仅允许在 `Opt-Out=1` 且覆盖 Next Closer、不匹配 NS/DS 时接受，严禁把 `Opt-Out` 用于已签委托或 NXDOMAIN 跳过通配符）；（3）通配符应答扩展时核对 Next Closer 被 NSEC3 覆盖以防具体记录被遮蔽。附环形回绕、ENT、Opt-Out 滥用与高迭代 DoS 测试集。
