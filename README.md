Kubernetes StatefulSet 控制器在同时启用 `OrderedReady`/`Parallel` 管理策略、`RollingUpdate` 分区灰度（`partition` + `maxUnavailable`）、`minReadySeconds` 就绪稳定期以及 `persistentVolumeClaimRetentionPolicy`（`whenDeleted` / `whenScaled`）时，每一步调谐都存在极易违背顺序或误删数据的边界：1）`OrderedReady` 模式下扩容严格按序号 `0 -> N-1` 推进，前一个序号 Pod 尚未达到 `Running && Ready`（且满足 `minReadySeconds`）前绝不可创建下一个序号；缩容严格按 `N-1 -> 0` 逆序逐个删除，且在删除最高序号前若发现任意更低序号 Pod 处于不健康/未就绪态，按标准必须先阻断缩容等待修复，避免雪崩丢副本！2）`RollingUpdate` 严格从最高序号向 `partition` 逆序滚动重建（所有序号 `< partition` 的 Pod 保持旧版本绝不触发更新！），在 `maxUnavailable >= 1`（支持百分比向上/向下取整与最小保底 1）约束下，统计当前不可用副本数必须把**全集合**中未 `Ready`、处于 `Terminating` 或未满 `minReadySeconds` 的新旧 Pod 全部算入，绝不可在不可用数已满时继续删除下一个旧 Pod！3）支持 `startOrdinal` 非零起始序号（合法序号区间 `[startOrdinal, startOrdinal + replicas - 1]`）；4）PVC 留存策略必须严格区分“缩容移除单序号”与“整个 StatefulSet 被删除”：仅当 `whenScaled == Delete` 时，对缩容超出 `[startOrdinal, startOrdinal + replicas - 1]` 范围的序号 PVC 写入指向 StatefulSet 的 OwnerReference（若该序号稍后被重新扩容回来且 PVC 尚未消失，则必须立刻剥离该 OwnerReference 恢复留存！）；仅当 `whenDeleted == Delete` 时在 StatefulSet 自身带 DeletionTimestamp 时向所有现存 PVC 挂 OwnerReference。为集群控制面交付可导入的 Go StatefulSet 调谐控制器包。验收覆盖 `OrderedReady` 遇不健康低序号阻断缩容、逆序 `partition` 灰度与全量 `maxUnavailable` 含 `minReadySeconds` 核算、非零 `startOrdinal` 边界以及缩容挂 OwnerReference 后重新扩容即时剥离的 PVC 留存验证。
