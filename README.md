# 连接迁移模拟器（TypeScript）

模拟 QUIC 风格的连接迁移：迁移点附近新旧两条链路短暂并存，逻辑消息在两条链路上
使用**同一组连续序号**。实现迁移点、确认合并（ACK merge）、双向重传，并验证接收方
业务交付**恰好一次**且内存**有界**。

## 运行

需要 Node ≥ 22.6（利用原生类型擦除直接运行 `.ts`，无需编译）：

```sh
node src/main.ts        # 或 npm run sim
```

## 模型

- `src/sim.ts`：虚拟时间离散事件模拟器（二叉堆）。
- `src/link.ts`：单向链路，固定时延 + 均匀抖动（产生乱序）+ 随机丢包；
  `up=false` 表示迁移排空期结束、链路关闭，已在途的包仍会送达。
- `src/endpoint.ts`：端点同时是发送方与接收方（双向流，两边都会重传）。
- `src/scenario.ts`：A、B 各发 N 条消息，先后迁移，旧链路经排空期后关闭。
- `src/migration-test.ts`：定向测试，精确构造迟到 ACK 验证合并规则。

## 迁移点与确认合并

发送方记录每条路径上实际发送过的序号集合 `sentOnPath[p]` 及其最大值
`maxSeqSentOnPath[p]`。核心规则（`Endpoint.onAck`）：

> 从路径 p 到达的 ACK，其累计确认被钳制到 `maxSeqSentOnPath[p]`。

由此得到题目要求的语义：

- **旧链路迟到确认可推进已发送前缀**：迁移后旧链路上到达的 ACK 仍被接受，
  推进 `ackedPrefix`、释放发送缓冲（统计 `lateAcksAfterMigration` /
  `oldPathAckAdvanced`）。
- **不能确认新链路未发数据**：旧链路 ACK 声称的序号超出旧路径已发前沿时被钳制，
  只在新链路上发过的数据不会因此被确认；任何超过已发送序号的 ACK 同样被钳制
  （统计 `clampedAcks`），并有不变量 `ackedPrefix < nextSeq` 兜底。

## 重传

- RTO 定时器（SRTT 估计 + Karn 算法：重传包不采样），超时在**当前活跃路径**上
  批量重传最老的未确认消息——迁移后旧数据自动改走新链路。
- 快重传：3 个重复 ACK 立即重传最老未确认消息。

## 恰好一次与有界内存

- 接收方只交付连续前缀，乱序包进入容量为 `maxRecvWindow` 的缓存，重复包与窗口外
  的包直接丢弃；`delivered` 序列必须严格等于 `0..N-1`。
- 发送缓冲以 `maxSendBuffer` 反压；`sentOnPath` 元数据随 `ackedPrefix` 裁剪。
  每次变更后自检越界即抛错，并记录高水位（`highWaterSend/Recv`）作为有界性证据。

## 验证项（`src/main.ts`）

1. 定向测试：钳制、前缀推进、越界 ACK 拒绝，逐断言通过。
2. 6 个随机场景（不同丢包/抖动/迁移时刻/排空期，含新链路更差、大消息流）：
   全部收敛、双向交付恰好一次、内存高水位不超界、双方均有重传、
   旧链路迟到 ACK 确实到达并推进过已发送前缀。
