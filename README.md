全球负载均衡（GSLB）结合 EDNS Client Subnet（ECS）为不同地域与运营商客户端分配最近数据中心，但返回的 Scope 掩码若比实际参与决策的规则前缀更宽，会导致公共递归缓存把结果错发给相邻子网；且主中心过载向备中心溢出时若规则成环会陷入死循环。为 GSLB 权威决策层交付可嵌入的 TypeScript 路由组件。输入数据中心池（每中心含静态 IP 列表、最大容量、当前已占流量、健康探测比例与最低健康门槛、以及溢出目标备中心列表）、有序网段映射表（含 IPv4 CIDR 集合与默认兜底，指定首选中心权重分布）及客户端查询（含客户端 ECS IP 与源前缀长度 `srcPrefix`）。规则：先在网段表中按最长前缀匹配客户端 ECS，并计算精确 `scopePrefix`（不大于 `srcPrefix`，且必须至少覆盖所有与当前查询有更细子前缀冲突的最小区分前缀长度，确保缓存绝不会误命中更细规则！）；对选中的首选中心，若健康比例低于门槛或剩余容量不足，按确定性溢出链逐跳向存活且有余量的备中心迁移所需流量，遇到溢出环立即终止当前分支并按剩余可用中心重归一化（全网不可用时进入降级兜底返回最低负载中心并标记 `degraded=true`）。组件返回最终选中中心及 IP 列表、精确 `scopePrefix`、溢出路径与是否降级。验收用子网全分割测试对照无缓存串流不变量（任何落在返回 `scopePrefix` 内的 IP 必命中同一网段规则），覆盖更细子网存在迫使 `scopePrefix` 收缩、主中心不健康触发二级溢出、溢出环检测断环，以及全网过载触发降级。
