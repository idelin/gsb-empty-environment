# posetmatch

Go 分析库：输入多个案例的事件偏序（每事件带标签），判断给定标签模式能否作为**某个拓扑序（线性扩展）的连续子串**出现。判定只基于偏序本身，绝不按时间戳排序下结论。

## 问题与判定算法

模式 `p[0..m)` 能匹配，当且仅当存在事件的单射指派 `e1..em`（标签与模式逐位相同、事件互不相同），满足：

1. **链一致性**：在偏序上追加链边 `e1<...<em` 后仍无环；
2. **段内无外来者**：不存在段外事件 `x` 使 `e1≺x≺em`（否则 `x` 被强制夹在段中间，连续性必然被破坏）。

满足两条件时，把链收缩成超节点，收缩后偏序的任一线性扩展展开即为**完整见证拓扑序**。匹配器按此枚举指派并增量剪枝；≤12 事件时开销可忽略。重复标签由单射指派天然处理，并发事件由线性扩展空间天然覆盖。

## 核对（全枚举 / 全排列筛选）

- `BruteForceFind`：独立实现，枚举全部线性扩展逐一扫描，用于交叉核对（`CrossCheck`）。
- `PermutationFind`：全排列筛选——遍历 `n!` 排列、滤出合法拓扑序再扫描，专门核对重复标签与并发事件（建议 n≤8）。
- 匹配失败时返回 `ExhaustionReport`（已闭合搜索范围）：尝试过的指派数、枚举过的拓扑序总数、FNV 摘要、样例序列表，以及枚举是否完整闭合（超过 `MaxExtensions` 上限时标记截断）。
- 测试含 200 组随机偏序（2–8 事件、3 字母表强制重复标签）与 12 事件大空间案例（665280 个拓扑序完整闭合），均与全枚举核对一致。

## 版本化、增量失效与原子拒绝

每个 `Case` 维护版本号与不可变证据日志（`Evidence`）：

- `Match` 结果按模式缓存，跨版本复用，直到被增量失效；
- `AddEvent`：正证据存活（孤立新事件总可附在旧见证末尾），负证据保守失效；
- `RetractEvent`：正证据仅当被撤事件属于匹配段时失效（否则见证剔除该事件后仍成立），负证据保守失效；
- `AddPrecedence`：正证据仅当见证违反新关系时失效，负证据必然存活（加边只会缩小拓扑序空间）；
- 失效记录**保留在日志中**，带 `InvalidatedAt` 版本与原因，作为旧版本证据；
- `AddPrecedence` / `AddPrecedences` 若成环则**原子拒绝**：不加任何边、版本不前进、证据不受扰动，返回带成环路径的 `CycleError`；批量版本要么全部应用（一次版本递增）要么全部回滚。

## API 速览

```go
c := posetmatch.NewCase("case-1")
c.AddEvent("e1", "a", 1700000001)
c.AddEvent("e2", "b", 1700000002)
c.AddPrecedence("e1", "e2")          // 成环则返回 *CycleError，原子拒绝

ev := c.Match([]posetmatch.Label{"a", "b"})
if ev.Found {
    // ev.Witness 完整见证拓扑序；ev.Segment() 实现模式的事件段
} else {
    // ev.Report 已闭合搜索范围：拓扑序总数、摘要、样例、是否截断
}

c.RetractEvent("e2")                 // 增量失效受影响证据，旧记录保留
for _, e := range c.Evidence() { /* 全部历史证据 */ }

a := posetmatch.NewAnalyzer()        // 多案例
a.Add(c)
results := a.AnalyzeAll(pattern)     // map[案例名]*Evidence
```

`Poset.TimeOrderCheck` 是刻意保留的反例基线（按时间排序再扫描），测试证明它在两个方向上都不可靠：并发事件可重排时会漏报，时间序违反先后关系时会误报。
