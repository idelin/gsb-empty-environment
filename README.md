# filelock — 本地文件锁管理库（C++17）

以规范化资源 ID 为锁对象的进程内锁管理库，支持共享锁、独占锁与共享→独占升级。

## 构建与测试

```sh
cmake -S . -B build && cmake --build build
cd build && ctest --output-on-failure
```

或直接编译：

```sh
clang++ -std=c++17 -Iinclude -Itests -pthread \
  src/lock_core.cpp src/lock_manager.cpp tests/*.cpp -o filelock_tests
./filelock_tests
```

## 架构

- `filelock::LockCore`（`include/filelock/lock_core.hpp`）：确定性、单线程、可复制的
  锁表状态机。全部锁语义（授予/排队/升级/取消/关闭）都在这里，不阻塞、不拥有线程。
- `filelock::LockManager`（`include/filelock/lock_manager.hpp`）：在 `LockCore` 上加
  互斥锁与条件变量，提供阻塞式 API 与 RAII 句柄 `LockManager::Handle`。
- 测试直接对 `LockCore` 做穷举交错探索（`tests/model_tests.cpp`），并用真实线程
  对 `LockManager` 做屏障对齐的交错穷举（`tests/interleaving_tests.cpp`）。

## 资源 ID 规范化

`CanonicalizeResourceId`：折叠重复 `/`，按词法解析 `.` 与 `..`，去除末尾 `/`。
空结果或越出根（如前导 `..`）为非法，返回 `kInvalidResource`。同一规范 ID 的不
同写法（如 `a//b/./c` 与 `a/b/c`）共享同一把锁。

## 固定语义

**锁模式与兼容性**：共享锁彼此兼容；独占锁与任何锁互斥。同一（句柄, 资源）对同
时最多持有一把锁；重复获取返回 `kAlreadyHeld`。

**排队次序**：每资源一条 FIFO 等待队列。
- 队列非空时，新的共享请求必须排队，不得插队到已排队的写者/升级者之前
  （写者不会被读者流饿死）。
- 升级者在成为该资源**唯一持有者**的即刻转换为独占锁，优先于队列中等待的
  新锁请求。此插队有界（每资源至多一个待定升级者，且队列非空时新读者无法
  入场），因此排队写者至多被超越一次，不会饿死。

**升级与死锁规避**：同一资源同一时间至多一个待定升级。第二个并发升级请求
**立即**返回 `kUpgradeConflict`（不阻塞），因此两个读者同时升级永远不会互相
永久等待：先到者成为待定升级者，等待其余共享持有者释放；后到者立即失败，
仍持有共享锁，可自行释放并重试。

**取消语义**（固定）：
- 取消待定**升级**：请求从队列移除，调用者**保留原共享锁**。
- 取消待定**获取**（共享/独占）：不持有任何锁。
- 取消是尽力而为：若请求在取消到达前已被授予，则返回 `kOk`。

**关闭句柄**：`Close()`（或句柄析构）释放该句柄持有的全部锁，并取消其全部
待定请求；被关闭句柄上阻塞中的调用以 `kClosed` 返回。

**重复释放**：对未持有的锁调用 `Release` 返回 `kNotHeld`，状态不变（幂等安全，
不会误放他人之锁）。

## 验证

`tests/` 共 32 个用例、9000+ 断言：

- **单元测试**（`tests/unit_tests.cpp`）：规范化、兼容矩阵、FIFO 次序、升级
  转换/冲突/优先级、取消保留共享锁、关闭释放全部、重复释放拒绝、写者不饿死。
- **屏障穷举短交错**（`tests/interleaving_tests.cpp`）：两个真实线程各执行
  4 步程序（取共享锁→升级→释放→关闭），指挥者用计数门闩强制遍历全部
  C(8,4)=70 种交错，每步后检查不变量；线程日志用**独立持锁模型**回放校验
  （含"取消/冲突后共享锁保留""重复释放被拒"）。另有屏障对齐压力测试：
  两读者同时升级 300 轮，断言恰好一人成功、无人永久等待；取消与升级竞态
  300 轮。
- **模型穷举**（`tests/model_tests.cpp`）：对确定性 `LockCore` 做 BFS，穷举
  三个句柄程序（两个可取消升级者 + 一个写者）的全部交错与取消分支，对每个
  可达状态用独立检查器验证：互斥（独占者唯一）、至多一个待定升级且升级者
  持有共享锁、队首共享请求必被独占持有者阻塞、无死局（任何非终止状态必有
  可行动作——即两读者升级不会互相永久等待）、终止状态锁表完全清空。
