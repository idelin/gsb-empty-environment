数据库代理与 WAF 在拦截 SQL 注入时，若仅用正则或单一标准词法分析器扫描查询，攻击者可利用方言特有的词法边界差异——如 PostgreSQL 嵌套块注释与美元符号定界串 `$tag$...$tag$`、MySQL 版本条件注释 `/*!50000 UNION SELECT*/` 与反引号/反斜杠转义差异、以及多语句堆叠与注释拼接——让前端解析器误判为安全字符串字面量而后端数据库当作可执行 SQL 运行。为 Go 数据库安全代理宿主构建可导入的多方言（PostgreSQL/MySQL/SQLite）SQL 词法规范化与结构化注入检测包，严禁依赖外部 SQL 解析库。组件内置严格状态机词法分析器与子集语句结构解析器，按目标方言准确区分标识符、字符串字面量、占位符（`$1`/`?`）、注释与操作符：对 PostgreSQL 精确处理 `E'...'` 逃逸串、嵌套 `/* /* ... */ */` 注释与任意标签 `$tag$...$tag$`；对 MySQL 精确展开条件执行注释 `/*!...*/`（按目标版本号决定是否展开为活跃 token）并区分 `NO_BACKSLASH_ESCAPES` 模式下的反斜杠行为。安全策略校验要求：（1）将运行时查询与预注册的参数化模板（AST 骨架）做逐 token 结构同构比对，只允许模板占位符位置替换为单值字面量且严禁任何字面量逃逸改变语法树拓扑、新增子查询/UNION/布尔恒真分支或堆叠第二条语句；（2）识别未声明方言下的跨方言解析分歧（同一段 SQL 在 PG 与 MySQL 下产生不同可执行语义即判为词法走私告警）。用涵盖美元定界逃逸、嵌套注释闭合差、MySQL 条件注释注入、反斜杠吞引号与合法复杂参数化查询的测试矩阵实测零漏报零误报。
