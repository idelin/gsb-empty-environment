# LS/SPF 路由计算引擎

类似 OSPF 的链路状态路由计算引擎（TypeScript 实现，零依赖）：
收集全网 LSA 链路状态通告，在断纤或权值变更时运行**增量 Dijkstra**
重算最短路径转发表，并输出路由震荡避免日志。

## 运行环境

- Node.js ≥ 22.6（利用原生 TypeScript 类型擦除直接运行 `.ts`，无需编译）
- 开发验证版本：v23.9.0（见 `.nvmrc`）

```bash
npm run demo   # 运行 8 节点多环拓扑演示
npm test       # 运行 Node.js 内置测试（node:test）
```

## 系统结构

| 文件 | 职责 |
| --- | --- |
| `src/types.ts` | LSA、路由表项、拓扑等公共类型 |
| `src/lsdb.ts` | 链路状态数据库：序列号去重、双向校验、拓扑快照差异 |
| `src/spf.ts` | 全量 Dijkstra + 增量 Dijkstra + 首跳提取 |
| `src/dampening.ts` | 路由震荡抑制（RFC 2439 风格惩罚/衰减/解除） |
| `src/router.ts` | 路由器：接口状态、LSA 发起/接收、SPF 触发与退避 |
| `src/network.ts` | 离散 tick 仿真器：泛洪、收敛判定、环路/黑洞校验 |
| `src/topology.ts` | 8 节点多环拓扑构建 |
| `src/demo.ts` | 演示：断纤 → 权值变更 → 抖动抑制 → 自动恢复 |

## 关键设计

**离散 tick 模型**：每个 tick 依次执行 ① 震荡惩罚衰减 → ② 状态变化的
路由器发起新 LSA → ③ LSA 沿可用链路逐跳泛洪直至静默 → ④ LSDB 有变化的
路由器运行 SPF。建模假设泛洪远快于 tick 粒度，因此所有路由器基于同一份
LSDB 计算，转发表天然一致，从机制上避免瞬时黑洞与环路；
`Network.verifyForwarding()` 在每个 tick 边界对所有可达节点对做逐跳
转发模拟，实证无环路、无黑洞。

**增量 Dijkstra**：仅对“旧最短路径树上经过变化边”的目的地子集重算，
未受影响节点的距离作为已知边界直接复用。该优化对劣化型变化
（链路 Down / 权值上升）严格正确；改善型变化（链路 Up / 权值下降）
可能让任意节点获得新短路径，自动回退全量计算。日志示例：

```
[tick 2] R1: SPF 重算(mode=incremental, 重算目的地 2/8) 触发: R3-R5:down
```

**路由震荡避免**：

- *链路抖动抑制*：每次 Up/Down 翻转累加惩罚值（默认 1000），按 tick 指数
  衰减（半衰期 2 tick）；惩罚 ≥ 2000 时抑制该链路的 Up 通告（按 Down
  处理），衰减至 750 以下自动解除，避免全网反复 SPF 震荡。
- *SPF 退避*：`Router.spfMinIntervalTicks` 可配置两次 SPF 的最小间隔，
  过频触发时延迟重算并输出退避日志。

```
[tick 7] R3: 震荡抑制: 链路 R3-R5 惩罚值 2686 >= 阈值 2000, 抑制其 Up 通告(按 Down 处理)
[tick 14] R3: 解除抑制: 链路 R3-R5 惩罚值衰减至 539 < 750, 恢复正常通告
```

## 验收拓扑

```
    环A                       环B
  R1 ---- R2                R5 ---- R6
  |       |                 |       |
  |       |                 |       |
  R4 ---- R3 == R3-R5(2)== R5       |
  |       |                 |       |
  |       +== R4-R8(3) ==== R8 ---- R7
```

环A / 环B 各 4 节点（cost=1），核心主干 R3-R5（cost=2），
备用主干 R4-R8（cost=3），构成多环冗余。

## 运行样例（`npm run demo`，节选）

```
=== 阶段 1: 初始收敛（8 节点多环拓扑） ===
  [tick 1] R3: 发起 LSA seq=1 [R2:1 R4:1 R5:2]
  [tick 1] R2: 接收 R3 的 LSA seq=1 (来自 R3)
  ...
  [tick 1] R1: SPF 重算(mode=full, 重算目的地 8/8) 触发: 首次计算
  初始收敛耗时 1 tick
  R1 转发表:
    R1 -> R6  下一跳=R2  代价=5        # 走核心主干 R1-R2-R3-R5-R6
  [校验] 初始收敛后转发一致性: 无环路、无黑洞 ✔

=== 阶段 2: 切断核心主干链路 R3-R5（断纤） ===
  [tick 1] 网络: 链路 R3-R5 断开(断纤)
  [tick 2] R3: 发起 LSA seq=2 [R2:1 R4:1 R5(down):2]
  [tick 2] R1: 接收 R3 的 LSA seq=2 (来自 R2)
  [tick 2] R1: SPF 重算(mode=incremental, 重算目的地 2/8) 触发: R3-R5:down
  断纤后重收敛耗时 1 tick
  R1 转发表:
    R1 -> R6  下一跳=R4  代价=6        # 绕行备用主干 R1-R4-R8-R5-R6
  [校验] 断纤后 tick 2: 无环路、无黑洞 ✔

=== 阶段 3: 权值变更（R4-R8 备用主干 3 -> 1，流量回切） ===
  [tick 3] R1: SPF 重算(mode=full, 重算目的地 8/8) 触发: R4-R8:cost-down
    R1 -> R6  下一跳=R4  代价=4

=== 阶段 4: 链路反复抖动，触发路由震荡抑制 ===
  [tick 7] R3: 震荡抑制: 链路 R3-R5 惩罚值 2686 >= 阈值 2000, 抑制其 Up 通告(按 Down 处理)
  R3-R5 当前是否被 R3 抑制: true

=== 阶段 5: 惩罚衰减后自动解除抑制，全网恢复 ===
  [tick 14] R3: 解除抑制: 链路 R3-R5 惩罚值衰减至 539 < 750, 恢复正常通告
  恢复收敛耗时 4 tick, R3-R5 抑制状态: false
    R1 -> R6  下一跳=R2  代价=5        # 恢复走核心主干
  [校验] 最终转发一致性: 无环路、无黑洞 ✔
```

## 测试结果（`npm test`）

Node.js 内置 `node:test` 运行器，13 个用例全部通过：

```
✔ 8 节点多环拓扑：初始收敛，无环路无黑洞，路由最优
✔ 切断核心主干 R3-R5：分布式 LSA 更新 + 增量 SPF，若干 tick 内收敛且无瞬时黑洞环路
✔ 权值变更触发重收敛，路由保持最优
✔ 断纤后恢复：改善型变化回退全量 SPF 并恢复最优路径
✔ 链路反复抖动：触发路由震荡抑制日志，衰减后自动解除
✔ 分区场景：不可达目的地不产生路由（合法不可达，非黑洞）
✔ 全量 Dijkstra: 距离与首跳正确
✔ 增量 SPF: 断链后与全量结果一致，且只重算受影响目的地
✔ 增量 SPF: 权值上升与全量结果一致
✔ 增量 SPF: 改善型变化（链路 Up / 权值下降）回退全量
✔ 增量 SPF: 未受影响时零重算
✔ LSDB: 拒绝过期序列号的 LSA
✔ LSDB: 双向校验——单边通告的链路不参与计算
ℹ tests 13  pass 13  fail 0
```

验收边界覆盖：8 节点多环拓扑 → 切断核心主干 R3-R5 → 各节点分布式
泛洪 LSA 并触发增量 SPF → 1 tick 内重收敛（上限断言 3 tick）→
每个 tick 边界逐跳校验无瞬时黑洞、无环路 → 收敛后路由与全量
Dijkstra 最优解逐项一致。
