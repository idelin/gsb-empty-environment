虚拟化宿主机通过 IOMMU（DMAR/SMMU）隔离直通 PCIe 设备的 DMA 访问时，若回收客户页后仅修改内存页表而未按序完成 IOTLB 与设备侧 ATS（Address Translation Services）ATC 失效屏障，或忽略同桥下 PCIe-to-PCI 设备的 BDF 别名共享同一域，恶意设备可利用残留翻译向已重新分配给内核的物理页发起 DMA 覆写。为 C++17 虚拟化安全宿主机实现可嵌入的 IOMMU 隔离与 ATS 失效序验证库（零外部依赖，`-Wall -Wextra -Wconversion -Werror` 编译通过）。库精确建模多 PCIe BDF 设备、别名组（Alias Group）、PASID 域表与 4 级页表（支持 4KB/2MB/1GB 大页、R/W/Exec 权限与页表物理地址有效位），维护两层缓存（IOMMU IOTLB 与每设备 ATS Device-TLB）及异步失效等待队列（`InvalidateIOTLB` -> `InvalidateDeviceATC` -> `InvalidationWait` 屏障）。安全不变量要求：设备发起任意 `(BDF, PASID, IOVA, len, R/W)` DMA 访问时，既检查当前页表也检查可能命中的陈旧 IOTLB/ATC 条目；仅当某物理页在页表中已解除映射且已完成对应域的 IOTLB 失效、全部关联设备/别名设备的 ATC 失效及等待屏障后，才允许释放回宿主空闲页池并分配给其他安全域。除在线事件拦截器外，实现深度至多 8 步的有界并发交错搜索器：自动寻找在“取消映射、下发失效、释放重分配、设备并发 DMA”交错下引发跨租户或内核页 DMA 越权的最短操作序列，并附小地址空间参考模型全枚举核对。
