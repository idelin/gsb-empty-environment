# netsim — 有容量边队列的存储转发网络仿真器

Go 实现的 tick 制包交换网络仿真器，含死锁检测与小网络状态穷举验证。

## 模型

- **节点**：有限缓冲（`BufferCap`），存放待转发包；源节点待注入包排在 pending 队列。
- **边**：有向、带容量队列（`Cap`），每 tick 每条边最多交付队首一个包（带宽 1 包/tick）。
- **路由**：静态给定 `NextHop[at][dst]`，配置加载时校验无环、无缺失边。
- **发送阻塞不丢包**：边队列满时发送阻塞，包留在节点缓冲下 tick 重试，绝不丢弃。

## Tick 语义（与节点遍历顺序无关）

1. **inject**：到期包进入源节点缓冲（按 Born、ID 排序，缓冲满则等待）。
2. **receive**：每条边向目的节点交付队首包；目的缓冲满则包留在边上（阻塞）。
3. **commit**：先收集全网所有发送意图（本节点包 → 出边），再按**包 ID 全局排序**统一提交；
   边容量不足的发送阻塞。因为意图先收集、后统一提交，节点遍历顺序不影响结果。

## 死锁证据

`Run` 检测到不动点（整 tick 无任何推进且无未来注入）即判定死锁，输出：

- **wait-for 环**：节点 A 持包等待节点 B 的资源（边队列满 / 节点缓冲满），成环即死锁证据；
- **冻结状态**：各节点缓冲、各边队列、已交付集合的完整快照。

## 状态穷举验证

`Enumerator` 对同一 tick 语义做 BFS 穷举，但把确定性仿真器中任意固定的调度选择
（receive 的边顺序、commit 的意图顺序）全部展开为非确定性分支，从而证明：

- **不变式**在任意遍历顺序下成立：包守恒（不丢不重）、容量不越界；
- 找出**所有**可达终态：全部交付（成功）或死锁（附 witness 轨迹 + wait-for 环）。

限制：穷举要求所有包 `Born == 0`，包数 ≤ 64，状态数上限 2,000,000。

## 运行

```sh
go run .                  # 全部演示：链式网延迟、环网死锁、穷举验证
go run . -scenario chain  # 仅确定性仿真 + 延迟报告
go run . -scenario ring   # 仅死锁演示 + 证据
go run . -scenario enum   # 仅穷举验证
go test ./...             # 单元测试（含仿真器与穷举结果一致性）
```
