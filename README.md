# async-channel-pipeline

异步通道库：用容量受限的通道把三个处理阶段（以及生产者、消费者）串成一条链，
带背压、阶段失败传播和基于所有权移交的清理保证。TypeScript 实现，无第三方依赖。

## 运行

需要 Node >= 22.6（`--experimental-strip-types`）或 >= 23.6（直接运行 `.ts`）：

```sh
node --test test/pipeline.test.ts
```

## 结构

- `src/channel.ts` — 有界异步通道。`send` 在缓冲满时阻塞，因此下游暂停会逐级
  阻止上游拉取（背压）。`close` 优雅关闭；`fail` 使挂起/后续的收发立即抛错，
  缓冲中的元素保留给接收方 `drain()`。
- `src/tracked.ts` — 带编号的 `TrackedItem` 与 `Tracker`：记录每次移交
  （`handoff`）和每次释放（`release`），重复释放立即抛错，`assertNoLeaks`
  校验所有已生产元素恰好被释放一次。
- `src/pipeline.ts` — N 个阶段、N+1 条通道的链路，以及生产者/消费者辅助函数。

## 所有权规则

1. `send` 成功完成时，元素所有权移交给接收方；`send` 被拒绝时仍归发送方。
2. 阶段失败时：释放自己当前持有的元素；`drain` 输入通道，释放其中已移交给自己
   （接收阶段）的元素；随后 `fail` 输入与输出通道，使上游阻塞的 `send` 弹错、
   下游的 `recv` 抛错，失败沿链双向逐级传播。
3. 消费者提前退出调用 `pipeline.abort()`，同样由每一级接收方清理自己通道中的
   残留元素。

## 验证（test/pipeline.test.ts）

- 正常流转：20 个编号元素全部流经 3 个阶段，每个元素的 8 次移交链路完整，
  全部由消费者释放，无泄漏、无重复释放。
- 背压：消费者暂停时，4 条通道填满、3 个阶段阻塞在 `send`、生产者阻塞，
  上游拉取数稳定在 8 不再增长；恢复后全部排空。
- 中段失败：s2 在处理 #7 时失败。确定性断言释放者归属：#1–#6 消费者，
  #7–#9 由 s2（#8、#9 是已移交进 ch1 的元素，由接收阶段释放），#10、#11
  由 s1，#12 由生产者；`assertNoLeaks` 通过。
- 消费者提前退出：消费 5 个后 `abort`，失败级联到生产者，拉取停止
  （生产数 <= 13），所有已生产元素恰好释放一次。
