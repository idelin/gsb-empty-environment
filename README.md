API 网关与资源服务器采用 OAuth 2.0 DPoP（RFC 9449）将访问令牌绑定到客户端非对称私钥时，若未严格规范化 `htu`（忽略 query/fragment 剥离或大小写）、允许 DPoP 头携带私钥分量（`d`）或对称算法（`HS256`/`none`）、漏检访问令牌 `cnf.jkt` 与证明公钥的 RFC 7638 拇指印匹配，或接受降级为普通 `Bearer` 认证，攻击者窃取令牌后仍可跨接口重放或替换证明密钥。为 Go 认证网关宿主实现可导入的 RFC 9449 DPoP 证明校验与防重放中间件组件，严禁联网（使用标准库 `crypto/ecdsa`/`crypto/ed25519`/`crypto/sha256`）。组件对每个受保护请求执行完整校验：（1）解析 `Authorization: DPoP <token>` 与 `DPoP: <jwt>`，当令牌带 `cnf.jkt` 时硬拒绝 `Bearer` 降级与多头走私；（2）校验 DPoP JWT 头必须为 `typ="dpop+jwt"`、仅允许白名单非对称 `alg`（`ES256`/`EdDSA`）、嵌入 `jwk` 不得含私钥字段且其规范 RFC 7638 SHA-256 拇指印与访问令牌 `cnf.jkt` 恒定时间一致；（3）严格校验载荷 `htm` 与 HTTP 方法一致、`htu` 与去除 query/fragment 后的规范目标 URL 一致、`ath` 等于访问令牌的 Base64URL(SHA-256)、`iat` 在允许时钟偏斜窗内，且 `jti` 在有界窗口内严禁重复；（4）实现可轮换服务端 `DPoP-Nonce` 签发与校验（支持当前与上一周期无缝切换、超时/错签返回 `use_dpop_nonce` 挑战）。附含私钥 JWK 注入、URL 混淆、Bearer 降级、跨端点重放与 Nonce 轮换测试。
