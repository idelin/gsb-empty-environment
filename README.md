现代浏览器安全网关与服务端防御中间件在协同部署 `Cross-Origin-Opener-Policy`（COOP）、`Cross-Origin-Embedder-Policy`（COEP）、`Cross-Origin-Resource-Policy`（CORP）以及 CORS 与 `Sec-Fetch-*` 元数据时，若错误配置允许携带凭证的通配 CORS、在 `COEP=require-corp` 页面下放行无 CORP 头的跨源子资源，或忽略重定向链中 `Origin` 退化为 `null` 的沙箱 iframe 绕过，攻击者可发起 Spectre 侧信道读取或跨站信息泄漏（XS-Leak）。为 TypeScript Web 安全网关宿主实现可导入的跨域隔离与 XS-Leak 策略裁决及对抗分析包，严禁联网。组件完整实现：（1）浏览器级 `crossOriginIsolated` 判定与浏览上下文组（Browsing Context Group）切换状态机：按 HTML 规范校验顶层文档与子 iframe 的 COOP（`unsafe-none`/`same-origin-allow-popups`/`same-origin`）与 COEP（`unsafe-none`/`require-corp`/`credentialless`）组合，精确判定导航切换、弹窗 `window.opener` 切断以及跨源子资源加载是否因缺失匹配的 `CORP`（`same-origin`/`same-site`/`cross-origin`）或匿名 CORS 响应头而被拦截；（2）服务端 Fetch Metadata 与 CORS 防御门禁：依据 `Sec-Fetch-Site`/`Sec-Fetch-Mode`/`Sec-Fetch-Dest`/`Sec-Fetch-User` 精确放行合法顶层导航与同源请求，拦截跨站 CSRF、跨站子资源探测与 `Origin: null` 提权，强制拒绝 `Access-Control-Allow-Origin: *` 与 `Access-Control-Allow-Credentials: true` 共存及未做规范化比对的反射 Origin；（3）有界 XS-Leak/隔离破坏搜索器：在给定多源端点配置下搜索可窃取跨源响应状态或维持非法 `window.opener` 引用的最小导航/嵌入序列，并附完整规范场景矩阵核验。
