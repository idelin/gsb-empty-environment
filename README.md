# 目录引荐跟随范围与凭据携带限制

目录客户端遇到服务端返回的引荐（referral）时，会自动用同一份绑定凭据去连引荐里的地址，攻击者控制或污染一个目录服务，返回指向自己机器的 ldap 地址，就能拿到用户的明文口令。Go目录访问库需要可导入的引荐跟随判定包，输入原请求的地址与是否已用加密传输、引荐地址列表、调用方的可信目录主机白名单和已绑定的身份：只跟随 ldaps，或原连接已用 StartTLS 且引荐也要求 StartTLS，从加密降到明文的引荐一律不跟随；引荐主机须在白名单内，按小写比较，ldaps 缺省端口取 636；引荐地址里的 DN 必须在调用方给的搜索根之下，含 .. 或百分号编码的 DN 解码后再比较；绑定凭据只用于白名单主机，且只在跟随时重新绑定一次，不得沿引荐链继续转交；引荐深度不超过 3，出现环（同一主机、端口与 DN 重复）即停止；原连接为匿名绑定时，引荐也只能匿名。用降级到明文、主机不在白名单、引荐环、DN 越界和凭据转交验证。
