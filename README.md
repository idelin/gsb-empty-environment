# 冷热对象迁移模拟器

模拟热层（本地）对象迁移到冷层（目标存储）的全过程。核心问题：**上传成功后，何时才能安全删除本地副本？**

## 安全规则

1. **上传成功 / 收到回执 ≠ 可删除**。回执只是触发验证的提示，不是安全依据。
2. **回读验证**：从目标重新读出对象，重算摘要，且版本必须与当前本地副本一致。
3. **决议先行**：`RECLAIM_LOCAL` 迁移决议必须先持久化到日志（journal），落盘失败则不回收。
4. **回收前最终校验**（全部原子满足才删除本地副本）：
   - 决议仍在日志中，且版本/摘要与当前本地副本一致（之后没有发生过更新）；
   - 目标此刻仍健康（重读校验摘要+版本）；
   - 本地读句柄计数为 0（有读者持句柄则延迟回收，轮询等待）。

## 状态机

```
IDLE → UPLOADING → AWAITING_RECEIPT → VERIFYING → RELEASING → RECLAIMED
                       │  │              │            │
                       │  │              │            └─ 句柄未排空 → 轮询等待
                       │  │              └─ 摘要/版本不符、决议落盘失败 → ABORTED（保留本地）
                       │  └─ 回执丢失超时 → 直接回读验证（只影响进度，不影响安全）
                       └─ 旧回执（版本不符）→ 拒绝，ABORTED
```

ABORTED 后由模拟器按退避重试新一轮（重新上传最新版本）。

## 关键不变量

每个事件之后校验：**任意时刻，最新版本的对象至少存在一份有效副本**（本地有效或远端有效）。
若本地副本已删除，则必须存在对应版本+摘要的已持久化决议，且远端副本有效；句柄打开期间本地副本不得消失。

## 故障注入

- **回执丢失**（`loseReceiptProb`）：走超时回读路径，仍能完成迁移；
- **更新竞争 + 旧回执重放**（`replayOldReceipts`）：旧回执/旧决议不能确认新版本，本轮中止；
- **目标损坏**（`corruptAfterUploadProb` / `corruptAfterDecisionProb`）：上传后损坏被回读校验拦截；决议后损坏被回收前最终校验拦截；
- **决议落盘失败**（`journalFlushFailProb`）：未持久化决议则不回收。

## 运行

```bash
bun run src/main.ts   # 8 个场景：clean / 回执丢失 / 更新竞争 / 目标损坏×2 / 句柄延迟 / 决议失败 / 混沌
bun test              # 9 个状态机单元测试
```

## 结构

- `src/migrator.ts` — 迁移状态机（安全规则全部在此强制执行）
- `src/store.ts` — 热层（含读句柄跟踪）与冷层（含 bit-rot 损坏注入）
- `src/journal.ts` — 迁移决议的持久化日志
- `src/world.ts` — 离散事件模拟器、故障注入、不变量校验
- `src/main.ts` — 场景定义与报告
- `test/migrator.test.ts` — 状态机单元测试
