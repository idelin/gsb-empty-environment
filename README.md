macOS 终端准入网关在离线核验 64 位 Mach-O 可执行文件与动态库的 `LC_CODE_SIGNATURE` 完整性时，若仅检查存在签名 Load Command 而未从原始字节逐页重算 `CodeDirectory`（`CSMAGIC_CODEDIRECTORY`）SHA-256 页哈希、漏检 `codeLimit` 未覆盖完整 `__TEXT` 段或尾部藏毒、未核对特殊槽位（Special Slots）与实际 `Requirements`/`Entitlements` Blob 的摘要一致，攻击者可篡改未覆盖代码页或注入 `com.apple.security.cs.disable-library-validation` 权限绕过硬运行时保护。为 C++17 二进制安全宿主实现可嵌入、零外部依赖、`-Wall -Wextra -Wconversion -Werror` 编译通过的原始字节级 Mach-O 64 位代码签名与权限审计库（内置 SHA-256）。库严格解析 `mach_header_64`、全部 Load Commands（`LC_SEGMENT_64`/`LC_CODE_SIGNATURE`）与大端序 `CS_SuperBlob`（`0xfade0cc0`）：（1）硬拒绝越界偏移、整数溢出、重叠段以及 `LC_CODE_SIGNATURE` 未位于 `__LINKEDIT` 合法末尾的畸形样本；（2）解析 `CS_CodeDirectory`（`0xfade0c02`），逐页重算 `[0, codeLimit)` 范围内全部 `2^pageSize` 页的 SHA-256 并与 `nCodeSlots` 槽位恒定时间比对，同时校验 `codeLimit` 必须严格覆盖至 `LC_CODE_SIGNATURE` 起始偏移且完整覆盖所有可执行段；（3）核对特殊槽位 `-2`（Requirements）、`-5`（XML Entitlements）与 `-7`（DER Entitlements）哈希与对应子 Blob 原始字节严格一致，检查必须开启 `CS_RUNTIME`（`0x10000`）与 `CS_KILL` 标志，并拦截含 `get-task-allow`、`allow-unsigned-executable-memory`、`disable-library-validation` 的高危权限。附手工构造的合法 Mach-O 样本与页篡改、特殊槽位错配、缺失 Hardened Runtime 及高危权限注入测试。
