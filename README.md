# 积分兑换规划器 (Points Redemption Planner)

在有限时段内规划积分兑换，使总兑换价值最高。

## 模型

- **时段**：时间划分为 `1..N` 个时段，按批次处理。
- **积分批次**：每批积分有来源、数量、到期时段（最后可用时段）和使用限制
  （`categories` 为空表示通用，否则只能兑换指定类别的奖励）。
- **奖励**：每个奖励有类别、积分成本、兑换价值、返还积分（cashback）和
  每时段库存。
- **返还积分**：在当时段结束时计入返还池（`REBATE`），**只能从下一时段起
  使用**——因此同一时段内无法循环兑换返还。返还池不限类别，在最后一个时段
  结束后到期，未用完的部分计为到期损失。
- **目标**：最大化总兑换价值。价值相同的情况下，优先消耗更多积分
  （即让到期浪费更少）。

## 用法

```sh
go run ./cmd/planner examples/sample.json        # 文本输出
go run ./cmd/planner -json examples/sample.json  # JSON 输出
cat input.json | go run ./cmd/planner            # 从 stdin 读取
go test ./planner/                               # 运行测试
```

输入格式见 `examples/sample.json`。

## 输出

每个时段输出：

- `redeem`：兑换的奖励、数量、成本、价值、返还；
- `deduct`：各批次（含 `REBATE` 返还池）的积分扣减；
- `expire`：在该时段开始时到期损失的积分（最后一批次还包含
  规划期结束时剩余的所有积分）；
- `cashback earned`：当时段获得、下一时段起可用的返还积分。

末尾输出总计：总价值、总消耗、总返还、总到期损失。

## 算法

记忆化动态规划，状态为 `(时段, 奖励槽位, 各类别积分持有量, 当时段待返还积分)`：

- 每个奖励的每单位库存是一个"槽位"，决策为跳过或从某个可用且
  类别允许的批次中扣减兑换；
- 时段结束时把待返还积分计入返还池，并清零已过期的批次（计为损失）；
- 目标按 `(总价值, 总消耗)` 字典序比较。

状态数受 `maxStates`（默认 4,000,000）限制，超出时返回
`ErrStateOverflow`。适用于中小规模规划（时段、批次、库存均为数十以内）。
