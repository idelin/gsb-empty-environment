# crcseg — CRC-32 分段计算与按长度合成

纯标准库实现的反射型 CRC-32（与 IEEE/zlib CRC-32 同族），支持：

- 定义**多项式、寄存器初值、末轮异或**三个外参（`Params`，内置 `IEEE`、`Castagnoli`）；
- 字节输入**任意分块**喂入（`Hasher` 实现标准库 `hash.Hash32`）；
- 段摘要 = `{长度, CRC}`，可只凭摘要**按长度合成**，无需原始字节；
- **任意切分合成 == 一次计算**（GF(2) 线性算子 + 二进求幂，见 `crc.go`）；
- **空段是恒等元**；
- **相同摘要、不同长度不能混用**（段替换强制等长）；**长度溢出报错**；
- 子段替换后只重算被替换段，再做摘要合成完成**整体验证，不重新扫描未变数据**；
- 线路帧解析区分**缺数据**（`ErrMissingData`）与**坏数据**（`ErrBadData`）；
- **长度额度在分配/吸收之前检查**（`ErrQuota`）。

## 目录结构

- `crcseg/` — 库代码
  - `crc.go`：参数、CRC 表、GF(2) 矩阵与按长度合成
  - `segment.go`：段摘要与 `Combine`
  - `hasher.go`：流式 `hash.Hash32`
  - `collector.go`：帧解析、缺/坏区分、配额检查
  - `chain.go`：段链、等长替换、整体验证
  - `errors.go`：哨兵错误
  - `crcseg_test.go`：测试（`go test`）
- `cmd/demo/` — 运行样例

## 合成原理简述

反射型 CRC 中，“吸收一个零字节” `v -> (v>>8) ^ t[v&0xff]` 是 GF(2) 上的
线性变换，且**只依赖多项式、与数据内容无关**。把它表示为 32×32 比特矩阵 `Z`，
则吸收 `n` 个任意字节 `B` 满足：

```
raw(A||B) = Z^n(raw(A)) ^ shift(B)
shift(B)  = raw(B) ^ Z^n(init)
```

其中 `raw` 为去掉末轮异或的寄存器状态。于是只需 A、B 两段各自的摘要与 B 的
长度，就能得到拼接摘要——这就是分段计算/子段替换无需重扫数据的原因。
`Z^n` 用矩阵平方 + 二进求幂得到，复杂度 O(log n) 次 32×32 矩阵乘法。
