IKEv2 的 EAP-only 认证让服务器不出示证书，攻击者在路径上可伪装成服务器，借强度不足或降级协商的 EAP 方法拿走凭据。给Go IKEv2 发起方写供 IKE_AUTH 应答处理调用的认证策略包，按 RFC 5998：仅当请求里带了 EAP_ONLY_AUTHENTICATION 通知（类型 16417 且载荷长度与协议号符合规范）且应答也带该通知时才接受不含 AUTH 载荷的服务器认证；同时校验该通知未被伪造为带额外 SPI 或错误协议标识，且当收到 AUTH 载荷时不允许与 EAP-only 通知混用绕过证书链校验。EAP 方法必须在调用方允许列表内（至少含 EAP-TLS 13，EAP-AKA 50，不得含 MSCHAPv2 26 与 GTC 6），且对服务端中途发来的 EAP-Request 方法切换与降级提案必须重新过白名单；服务器未回该通知却缺 AUTH 载荷，或回了通知但方法不在列表内，都以认证失败结束并禁止退回只验用户名口令。用服务器缺 AUTH、畸形通知、方法降级切换、MSCHAPv2 和合法 EAP-TLS 验证。
