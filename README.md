# 权限规则排序器

只交换相邻规则，求满足全部允许/拒绝样例的**最少交换次数**。规则按顺序评估、
**首次匹配**生效；规则数最多 15 条。样例不可修改、不可丢弃：要么全部满足，
要么报告一组互相冲突的样例。

## 运行

需要 Node.js ≥ 22.6（`--experimental-strip-types`）或 ≥ 23.6（原生运行 TypeScript）：

```bash
node src/cli.ts input.json      # 从文件读取
node src/cli.ts < input.json    # 从标准输入读取
node test/verify.ts             # 对拍测试（DP vs 全排列暴力枚举）
```

退出码：`0` 有解；`1` 无解（输出冲突样例子集）；`2` 输入错误。

## 输入格式

```json
{
  "rules": [
    { "id": "r1", "action": "allow", "when": { "user": "alice" } },
    { "id": "r2", "action": "deny",  "when": { "role": "*" } }
  ],
  "samples": [
    { "id": "s1", "expect": "deny", "attrs": { "user": "bob", "role": "guest" } }
  ]
}
```

- `when` 中每个键要求样例属性等值匹配；值为 `"*"` 表示通配；`when` 为空对象匹配一切。
- 样例缺少某属性时，只有该键为 `"*"` 的规则能匹配。
- `action` / `expect` 取值为 `"allow"` 或 `"deny"`。

## 输出

- **有解**：最少相邻交换次数、新的规则顺序、每个样例命中的规则及动作。
- **无解**：一个**包含极小**的冲突样例子集（去掉其中任意一个样例即可有解），
  并列出每个冲突样例匹配到的规则。冲突只能靠调整规则本身解决，不能通过
  修改或忽略样例绕过。

## 算法

- 设样例 `s` 匹配的规则集为 `M`，其中动作符合期望的规则集为 `C`。首次匹配
  语义下，样例被正确分类 ⟺ `M` 中在新顺序里排最前的规则属于 `C`。
- 最少相邻交换次数 = 新顺序相对原顺序的逆序对数。
- 子集 DP：`dp[mask]` 表示把 `mask` 中的规则排在前 `popcount(mask)` 位且不
  违反任何已确定约束的最小逆序对数。放置规则 `r` 时，若 `r` 是某样例匹配集
  `M` 中第一个被放置的（`mask & M == 0`）且 `r ∉ C`，则剪枝。
  复杂度 `O(2^n · n · s)`，`n ≤ 15` 时约 50 万次状态转移。
- 无解时用删除式极小化（greedy deletion）在 `O(s)` 次可行性检查内找出一个
  包含极小的冲突样例子集。

正确性由 `test/verify.ts` 保证：300 个随机小规模用例（n ≤ 7）与全排列暴力
枚举逐一比对交换次数与可行性，并校验冲突子集的极小性。

## 文件

- `src/sorter.ts` — 核心求解器（纯函数，可复用）
- `src/cli.ts` — 命令行入口
- `test/verify.ts` — 随机对拍测试
