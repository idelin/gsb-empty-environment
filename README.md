# reorder-check：指令重排检查器

验证一个直线指令序列是否为另一序列的**合法重排**。

## 方法

判定分两层，**依赖分析是权威结论，穷举核对只是辅助**：

1. **依赖分析（权威）**：在原始序列上计算全部依赖边——
   真依赖（RAW）、反依赖（WAR）、输出依赖（WAW）与屏障顺序边。
   候选序列是合法重排，当且仅当：
   - 它是原始序列的一个排列（相同指令多重集）；
   - 每条依赖边的两端在候选中保持原有先后关系。

   非法时输出**最早冲突依赖边**（原始序列中源指令最靠前的被违反边）。

2. **有限初始状态穷举（辅助核对）**：在给定取值域（默认 `{0,1}`）上枚举
   初始寄存器/内存状态，分别执行两个序列并比较最终状态。
   发现发散即给出具体见证（初始状态 + 分歧单元）。
   **注意：碰巧结果相同不能证明无依赖**——例如两条都把 `r1` 置 0 的
   指令交换后结果恒等，但 WAW 依赖依然存在，仍判非法；屏障越序在
   单线程语义下也观察不到差异，同样仍判非法。

## 指令格式

每行一条指令，`#` 后为注释。读写对象为命名寄存器或半开内存区间：

```
barrier                  # 屏障：两侧指令不得越序
r1 = li 42               # 立即数（支持 0x 十六进制）
r1 = mov r2              # 寄存器传送
r1 = add r2, r3          # 算术：add/sub/xor/and/or
r1 = load [100, 104)     # 从半开区间 [100,104) 加载（小端序，最多 8 字节）
r2 = load [100]          # 单字节简写，等价 [100, 101)
[100, 104) = store r1    # 存储到半开区间
```

内存区间**可以重叠**，别名判断按半开区间精确求交：
`[0,4)` 与 `[4,8)` 不相交，`[0,5)` 与 `[4,8)` 相交。

## 用法

```
go build -o reorder-check ./cmd/reorder-check
./reorder-check -orig examples/original.txt -cand examples/legal.txt
```

选项：

- `-orig` / `-cand`：原始序列与候选序列文件（必需）
- `-domain 0,1`：穷举取值域
- `-max-states 1048576`：穷举状态数上限；`domain^单元数` 超限则退化为
  确定性模式 + 固定种子伪随机采样（输出中会标注"非穷举"）
- `-v`：打印全部依赖边与被违反的边

退出码：`0` 合法；`1` 非法重排；`2` 用法/解析错误。

## 设计要点

- **精确别名**：`Location.Overlaps` 对寄存器按名字、对内存按半开区间
  相交判断，部分重叠（如 `[0,4)` 与 `[2,6)`）也算冲突。
- **屏障**：屏障与所有先于/后于它的指令之间都有顺序边，跨屏障顺序由
  传递性保证。
- **指令匹配**：候选与原始按规范文本做多重集匹配，相同文本按出现次序
  配对。
- **穷举的从属地位**：穷举只在有界域上进行，且只观察最终状态；
  它能为非法重排提供具体反例，但"没找到反例"绝不推翻依赖分析的结论。
