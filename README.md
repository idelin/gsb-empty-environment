物联网与边缘认证服务在校验基于 CBOR 的 `COSE_Sign1`（RFC 9052）和 CWT（RFC 8392）访问凭据时，若使用宽松 CBOR 解码器放行非最短整数编码、重复 map 键或尾随字节，或在验签前信任 `unprotected` 头里的 `alg`/`kid` 与未受保护的 `crit` 扩展头，攻击者可构造多义性 CWT 声明（验签器看到普通用户而业务层读到重复键后的管理员）或实施算法混淆攻击。为 TypeScript 认证宿主实现可导入的零外部依赖确定性 CBOR（RFC 8949 Section 4.2）解码器与 `COSE_Sign1`/CWT 验证组件（签名校验通过注入的验签回调或内置 Web Crypto/Node `crypto` 接口完成）。组件从原始 `Uint8Array` 字节流起严格执行：（1）确定性 CBOR 解码硬拒绝一切非最短整数/长度编码、不定长数组/映射/字节串、重复 map 键、非按规范字节序排列的键、超深嵌套及尾随未消费字节；（2）解析 `COSE_Sign1` 四元组（带或不带 Tag 18），按规范重新构造确定性编码的 `Sig_structure = ["Signature1", body_protected, external_aad, payload]` 进行验签；强制要求 `alg` 必须位于 `protected` 头且与验签密钥绑定算法一致（严禁仅出现在 `unprotected` 或双头冲突）；（3）严格校验 `crit`（label 2）关键头列表：禁止空数组、禁止引用未出现在 `protected` 头或宿主不支持的关键标签；并校验 CWT 的 `iss`/`sub`/`aud`/`exp`/`nbf`/`cti` 时间窗与防重放。附重复键多义性 CWT、非最短编码绕过、`unprotected` 算法混淆与未知 `crit` 标签对抗测试。
