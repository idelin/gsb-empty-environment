关系库在写前日志恢复中途再次崩溃时，若重复撤销已写过补偿日志（CLR）的更新或错选脏页表重做起点，会直接损坏磁盘页内容。为存储恢复内核交付可导入的 Go ARIES 恢复包。输入日志序列（含普通 UPDATE 日志、已持久化 CLR 日志带 UndoNextLSN、COMMIT/ABORT/END 记录与成对 BEGIN_CHECKPOINT/END_CHECKPOINT 模糊检查点快照，含检查点时的事务表和脏页表 DPT）以及崩溃时刻各磁盘页的初始字节数组与 PageLSN。严格执行三阶段：分析阶段从最近完整检查点正向扫描重构精确活跃事务表与最小 RecLSN 脏页表（注意未配对的不完整检查点须忽略，回退上一完整检查点）；重做阶段从最小 RecLSN 起对所有未跳过更新和 CLR 幂等重做（仅当页在 DPT 中、LSN≥RecLSN 且页当前 PageLSN<LSN 时应用并更新 PageLSN）；撤销阶段按所有未提交事务的 NextLSN 最大堆逆序推进，遇到普通更新则逆向应用并追加写一条指向其 PrevLSN 的 CLR，遇到已有 CLR 则直接跳至 UndoNextLSN 绝不二次撤销。验收用中途任意 LSN 二次崩溃重跑恢复对照最终各页状态与干净单次恢复完全一致，覆盖不完整检查点回退、已写部分 CLR 后再次崩溃、重做阶段因 PageLSN 已新而跳过，以及多事务交错撤销写 END 记录。
