S3 兼容对象存储网关同时支持桶版本控制（Versioning）、乱序分段上传（Multipart Upload）、从已有对象版本零拷贝截取区间创建分片（`UploadPartCopy`）以及按任意字节区间读取（`Range GET`），底层元数据与内容块引用计数（Chunk RefCount）极易在并发覆写与删除下发生孤儿块泄漏或误删存活数据：1）同一 `UploadID` 允许客户端按任意乱序上传或多次覆写同一 `PartNumber`（覆写必须立刻释放旧分片对底层 Chunk 的引用！），`CompleteMultipartUpload` 时允许客户端只提交部分已上传 `PartNumber`（须严格按 `PartNumber` 升序校验 ETag 匹配，且除末片外其余每片不得小于最小分片阈值 `MinPartSize`！），未入选的残留分片必须随完成一同回收，而完成后的多段 ETag 必须严格按 S3 规范计算为 `hex(MD5(concat(raw_md5(part_i)))) + "-" + partCount`；2）`UploadPartCopy` 按 `[copyStart, copyEnd]` 引用源对象（指定 `VersionId` 或当前最新版本，若源版本是 `DeleteMarker` 须报 405/404！）的底层 Chunk 切片而不复制物理数据，源对象随后被永久删除时，只要目标分段或合并后的新对象仍存活，共享 Chunk 引用计数必须保持 `> 0` 绝不可回收！3）版本化桶中不带 `VersionId` 的 `DELETE` 仅追加新 `DeleteMarker`（普通 `GET` 返回 404，按历史 `VersionId` 仍可读），只有按 `VersionId` 永久删除全部指向某 Chunk 的对象版本与未完成/已中止分段后，该 Chunk 才归零进入 GC 回收集；4）支持跨越任意变长分段与零拷贝切片边界的 `Range: bytes=A-B` / `bytes=A-` / `bytes=-N`（精确处理越界返回 416、尾部截断至 `size-1`）。为对象存储元数据层交付可导入的 Go 多版本分段存储、零拷贝切片与 Chunk 引用计数 GC 包。验收覆盖分片覆写与未入选分片清理、S3 多段 ETag 规范校验、`UploadPartCopy` 后删除源版本不误删共享块、`DeleteMarker` 语义、跨多变长切片 `Range GET`（含 416/后缀范围）以及全量 Chunk 引用计数精确守恒校验。
