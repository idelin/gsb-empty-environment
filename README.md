机密计算平台在审计 Intel SGX Enclave 的内存布局（ELRANGE / EPCM 页缓存映射）与 ECALL/OCALL 边界接口时，若 Enclave 函数未校验外部传入指针及长度区间完全位于 Enclave 地址范围（`[elrange_base, elrange_base + elrange_size)`）之外（`sgx_is_outside_enclave`），或未将外部缓冲深拷贝入 Enclave 内部后再校验与解引用，恶意宿主机 OS 可传入指向 Enclave 内部堆/栈的伪造指针诱使 Enclave 覆写自身机密内存（Confused Deputy），或利用 OCALL 返回指针触发双取（TOCTOU）与未初始化 EPCM 页访问。为 C++17 机密计算审计宿主实现可嵌入、零外部依赖、`-Wall -Wextra -Wconversion -Werror` 编译通过的 SGX EPCM 与 ECALL/OCALL 边界隔离符号验证库。库建模 64 位地址空间、Enclave 范围 `ELRANGE`、EPCM 页表项（`VALID`、`PT_REG`/`PT_TCS`/`PT_SECS`、R/W/X 权限、`PENDING`/`MODIFIED` 动态页状态）以及 ECALL/OCALL 内存操作序列：（1）提供无 64 位整数回绕的 `is_within_enclave` 与 `is_outside_enclave` 精确区间判定，拦截任意一级或嵌套二级外部指针与 `ELRANGE` 相交、或 `ptr + len` 绕回 0 地址跨入 Enclave；（2）验证 EPCM 页权限与状态机：禁止同时可写可执行（`W=1 & X=1`）页、拒绝访问 `PENDING=1` 未 `EACCEPT` 的动态页以及非法的 `TCS` 入口跳转；（3）追踪 ECALL/OCALL 外部指针读操作，检出任意外部不可信字节在未完整拷贝进 Enclave 私有内存前被二次读取的 TOCTOU 漏洞，以及 OCALL 返回指针未重新校验边界直接解引用的 Confused Deputy 缺陷。附指针回绕、EPCM `PENDING` 越权、内部指针注入与双取 TOCTOU 测试。
