# canon — 规范序列化（含循环/共享引用有根图）

`canon` 用 Go 标准库实现一个确定性的二进制规范序列化，输出可直接作为
摘要/签名方案的稳定输入（本库**不**实现任何签名算法，仅提供
`Digest` 计算规范编码的 SHA-256）。

## 支持的序列化范围（自定义数据模型）

| 类型 | 说明 |
|---|---|
| `Null` | 空值 |
| `Bool` | 布尔 |
| `Int` | int64 |
| `Float` | float64，**仅有限值**；NaN/±Inf 编码时明确报错；`-0.0` 归一化为 `+0.0` |
| `String` | 必须是合法 UTF-8，否则拒绝 |
| `Array` | 保序，元素顺序有意义 |
| `Object` | 字符串键；编码按键字节序排序；重复键拒绝 |
| `Graph` | 有根、带标签、有向图；邻接表**有序**；支持共享引用与循环 |

范围之外的类型（big.Int、time.Time、嵌套在图节点标签里的图等）不受支持，
编码时明确报错。

## 编码格式

长度一律使用无符号 varint：

```
'N'                          Null
'B' 0x00|0x01                Bool
'I' 8 字节大端               Int
'F' 8 字节大端 IEEE754       Float（仅有限值）
'S' uvarint 长度 + 字节      String
'A' uvarint 个数 + 元素      Array（保序）
'O' uvarint 个数 + 条目      Object，条目按键字节序排列：
                              uvarint 键长 + 键 + 值
'G' uvarint n + uvarint 根下标 + n 个节点   Graph，节点按规范序：
                              标签值 + uvarint 出度 + 出度个目标下标
```

## 规范性保证

- 对象键插入顺序不同 → 编码相同（`Object`/`ObjectFromMap` 等价）。
- 类型即编码：`Int(1)`、`Float(1)`、`String("1")` 两两不同。
- 数组保序：`[1,2] ≠ [2,1]`；图的边序同样有意义。
- 图编码只依赖于**有根标签图同构类**（标签 + 有序邻接 + 根），
  与节点指针身份、创建顺序、遍历/发现顺序无关——内部不使用发现序号。

## 图规范化算法

`graph.go` 实现经典的颜色细化 + 个体化-细化（IR）搜索：

1. **初始着色**：按标签规范编码排序赋秩（颜色本身即规范，与输入顺序无关）。
2. **分区细化**：每轮用有序签名 `(自身颜色, 各后继颜色…)` 重新着色，
   按排序后的签名重新赋秩，直到划分稳定。
3. **有界个体化搜索**：若划分非离散，取最小非单点单元，对其中**每个**
   节点分支个体化（赋予新颜色）后细化并递归；叶子（离散着色）产生候选
   编码，取字典序最小者。因为分支集合是完整的单元，最小值与输入顺序无关。
4. **预算**：细化轮数与搜索节点共用一个预算（`Options.SearchBudget`，
   默认 65536）。预算耗尽时返回 `ErrBudgetExhausted`——**明确报告未完成**，
   绝不输出可能非规范的结果。

该规范形是 nauty 式规范标记：同构图必然得到相同编码；它不是"全排列
字典序最小"（后者无法多项式级计算），但每个叶子编码都对应某种顶点序的
合法渲染，测试对此做了全置换核验。

## 解码安全性

- 只构造数据，**不执行任何宿主代码**。
- 所有长度/个数前缀先与剩余输入比较，**验证通过后才分配**。
- 嵌套深度限制 512 层；图的下标越界、零节点图、非法 UTF-8、
  线上的非有限浮点、重复键、尾随字节一律拒绝。
- 解码接受任何良构编码；重新编码即得规范形（`Decode∘Encode` 是不动点）。

## 使用

```go
v := canon.Object(
    canon.Pair{Key: "msg", Value: canon.String("hello")},
    canon.Pair{Key: "n", Value: canon.Int(1)},
)
enc, _ := canon.Encode(v)        // 规范编码
sum, _ := canon.Digest(v)        // 规范编码的 SHA-256（签名输入）
dec, _ := canon.Decode(enc)      // 安全解码

// 有根图：共享引用 + 循环
a := &canon.Node{Label: canon.String("a")}
b := &canon.Node{Label: canon.String("b")}
a.Edges = []*canon.Node{b}
b.Edges = []*canon.Node{a}       // 循环
genc, _ := canon.Encode(canon.GraphValue(a))
```

## 测试结果

```
$ go test ./...
ok  	canon	0.383s
```

全部 22 个测试通过，覆盖：

- 键插入顺序不变性、`1` vs `"1"`、非有限浮点拒绝、`-0.0` 归一化
- 数组保序、重复键/非法 UTF-8 拒绝
- **小图全置换参考核验**：对每个 ≤6 顶点的图，所有 n! 个同构重标记
  编码完全相同，且规范编码等于某种顶点序的合法渲染
- 共享引用 vs 不同身份不被错误合并、边序有意义、循环图创建顺序不变性
- 预算耗尽明确返回 `ErrBudgetExhausted`（64 节点同标签环）
- 截断/超长声明/深度超限/越界下标等恶意输入拒绝、编解码往返一致
