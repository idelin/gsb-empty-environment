HTTP/3（RFC 9204）网关在无序 QUIC 流上运行 QPACK 头压缩编码器与解码器时，若解码器未严格限制并发阻塞流数（`SETTINGS_QPACK_BLOCKED_STREAMS`）、未校验 `Required Insert Count` 编码回绕与动态表驱逐引用计数，或未拦截非法增量/静态索引越界，恶意客户端可通过故意延迟编码器流指令或构造悬空引用制造永久阻塞流耗尽内存或引发跨流头域错乱。为 Go 边缘网关宿主实现可导入的原始字节级 RFC 9204 QPACK 编解码安全状态机与反 DoS 验证包，严禁联网与严禁依赖外部 QPACK 库。组件完整实现 QPACK 静态表、FIFO 动态表（带精确 32 字节条目开销计算、绝对索引与相对/基后索引换算）、前缀整数与 Huffman 编解码、编码器流指令（Set Dynamic Table Capacity / Insert With Name Reference / Insert With Literal Name / Duplicate）与解码器流指令（Section Acknowledgment / Stream Cancellation / Insert Count Increment）：强制安全不变量包括：（1）解码头块时精确还原 `Required Insert Count` 与 `Delta Base`，若超出当前 `Insert Count` 则将流挂起为阻塞态，当阻塞流总数超过 `SETTINGS_QPACK_BLOCKED_STREAMS` 立即返回 `QPACK_DECOMPRESSION_FAILED` 断开连接；（2）编码器严格维护每条动态表项的活跃流引用计数，严禁驱逐仍被未确认流引用的条目（防引用失效错乱）；（3）拒绝无对应未确认流的伪造 `Section Acknowledgment`、零值或超界 `Insert Count Increment` 及超容量 `Set Capacity`。附乱序流阻塞超限、悬空驱逐拦截、非规范 `Required Insert Count` 编码与正常并发流回环验证测试。
