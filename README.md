# cleaner

两阶段、抗竞态的文件清理器。

## 工作流程

1. **冻结计划**：`Planner.BuildPlan(roots...)` 遍历目标，快照每个文件/目录的
   身份（ID）、版本（Version）和大小（Size），生成不可变的 `Plan`。
   `Plan.Preview()` 输出人类可读的预览。计划内子项始终排在父目录之前。
2. **校验执行**：`Executor.Execute(plan)` 逐项重新 `Stat`，与快照比对后才删除：
   - 文件：身份、版本、大小任一变化 → 跳过并报告 `changed`；
     路径已不存在 → 报告 `gone`。绝不会按旧路径误删新文件。
   - 目录：仅在所有计划子项处理完之后处理，且当前确实为空才删除，
     否则报告 `not-empty`（计划外新文件、被跳过或删除失败的子项都会阻止删除）。
   - 删除本身失败（如 I/O 错误）→ 记入 `Report.Failed`，其余项继续执行。

## 文件系统抽象

- `FS` 接口（`Stat` / `ReadDir` / `Remove` / `Join`）解耦清理逻辑与存储。
- `OSFS`：真实文件系统，身份 = dev+inode，版本 = mtime。
- `MemFS`：内存虚拟文件系统，提供 `WriteFile` / `Rename` / `FailRemove`
  等辅助方法，用于在测试中编排"计划后替换、移动、部分失败"等竞态场景。

## 测试

```sh
go test ./...
```

覆盖：预览冻结、原样执行、预览后替换、移动后旧路径出现新文件、
移走文件报告 gone、部分删除失败、计划外新文件保护，以及真实文件系统回归。
