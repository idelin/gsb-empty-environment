边缘存储与取证安全网关在挂载或恢复外部提交的 SQLite 3 Write-Ahead Log（`-wal`）文件前，若直接交由数据库引擎自动回放，攻击者可构造畸形 WAL 帧（如伪造 `db_size` 截断或越界扩张主库、利用未更新 `Salt-1`/`Salt-2` 的旧检查点残留帧重放历史已撤销权限、破坏链式累加 32 位校验和绕过完整性验证，或构造非法的页号 `pgno == 0` / 超大页号触发堆越界写）。为 C++17 存储安全宿主实现可嵌入、零外部依赖、`-Wall -Wextra -Wconversion -Werror` 编译通过的原始字节级 SQLite 3 WAL 文件安全审计库。库从 32 字节 WAL 头起严格解析：（1）校验魔数（`0x377f0682` 小端累加校验和或 `0x377f0683` 大端累加校验和）、格式版本 `3007000`、页大小（512–65536 且为 2 的幂）、检查点序列号、以及用前 24 字节按对应端序精确重算的 64 位双字累加校验和（`s0`/`s1`）；（2）逐帧顺序解析 `24 + pageSize` 字节帧（硬拒绝尾随残缺字节）：严格按 SQLite WAL 规范将上一帧的 `(s0, s1)` 链接输入本帧头前 8 字节与完整页载荷重算校验和并恒定时间比对；强制校验每条有效帧的 `salt1`/`salt2` 与 WAL 头完全一致（精确识别并截断旧检查点残留无效帧，硬拦截将旧 `salt` 帧混入有效事务或篡改中间帧校验和的伪造日志）；（3）审计全部有效提交事务（`db_size > 0` 标记提交边界）：硬拒绝 `pgno == 0`、`pgno > maxAllowedPages`、单事务内页号超出该事务声明的 `db_size`，以及尾部存在未提交半截事务却被误判为已提交的异常。附手工构造的合法大小端 WAL 样本与链式校验和篡改、旧 `salt` 重放、`pgno=0` 越界及未提交尾帧截断测试。
