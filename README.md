# ts-build-cache

TypeScript 增量构建库:以「源码 + 直接依赖导出签名」为键缓存模块编译产物(JS + `.d.ts`)。

## 核心设计

- **缓存键**:`hash(编译器版本, 组内全部源码, 直接依赖的导出签名)`。
  导出签名 = 该模块 emitted `.d.ts` 的 SHA-256。`.d.ts` 完整刻画模块的公开类型面,
  因此内部实现变化不改变签名,调用方键不变、直接命中缓存;导出变化改变签名,
  使直接依赖方键失效,并沿签名链传递失效(直到签名不再变化处停止)。
- **循环依赖**:对模块图做 Tarjan 强连通分量分解,同一 SCC 作为整体编译,
  键覆盖组内所有成员源码 + 组外直接依赖签名;SCC 缩点后按拓扑序(依赖在前)构建。
- **失败产物不入缓存**:编译组内任一文件存在 error 级诊断即判定失败,
  不写入缓存;依赖失败模块的下游组同样标记失败且跳过编译。
- **编译方式**:对全部源码创建 `ts.Program`(跨模块类型解析自当前源码),
  仅对目标组做诊断检查与 emit,保证增量与全量产物逐字节一致。

## 结构

- `src/builder.js` — 增量构建编排(发现模块、构图、SCC、查/写缓存、统计编译次数)
- `src/compiler.js` — 单组编译:诊断检查 + JS/`.d.ts` emit + 签名计算
- `src/graph.js` — import 解析(AST)、Tarjan SCC、缩点拓扑排序
- `src/cache.js` — 文件型内容寻址缓存(仅接收成功产物)
- `src/load-typescript.js` — 定位 TypeScript 编译器(`require('typescript')`,
  或环境变量 `TYPESCRIPT_PATH` 指向 `typescript.js`)

## 验证

```sh
npm test   # node test/run.js
```

`test/run.js` 构造 7 模块工程(含 util→service→api 链与 cycleA↔cycleB 环),
每个变更场景同时跑增量构建与全新空缓存的全量重编,断言:

| 场景 | 期望编译数 |
| --- | --- |
| S1 冷构建 | 7(全部) |
| S2 无变更 | 0(全命中) |
| S3 依赖内部实现变化 | 1(仅该模块,调用方不重编) |
| S4 依赖导出签名变化 | 3(传递失效至 api) |
| S5 编译失败 | 0(失败产物不入缓存,缓存条目前后一致) |
| S6 环内实现变化 | 2(整个 SCC,环外 consumer 不重编) |
| S7 环内导出变化 | 3(SCC + 下游 consumer) |

并逐模块对比增量产物与全量重编产物(`js` + `d.ts` 完全一致)。
