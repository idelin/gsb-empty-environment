# routemigrate — 路由更新规划器

给定旧、新两张下一跳表，计算一个**逐条生效且全程无转发环、无黑洞**的更新方案：

1. 优先寻找**逐节点安全更新顺序**（每步只更新一个节点）；
2. 若不存在安全单节点顺序，则求**最小同步更新方案**——最小化最大同步组规模（主目标），
   其次最小化组数；
3. 对每一步输出各目的地的**可达性与环检测证据**。

支持最多 18 个节点。

## 模型

- `old[i][d]` / `new[i][d]`：节点 `i` 去往目的地 `d` 的下一跳；`-1` 表示无路由（黑洞），
  对角线忽略。
- 更新一个节点 = 该节点整行切换（对所有目的地同时生效）；同一组内的节点**同步**切换。
- 状态用 bitmask 表示「哪些节点已切换」。一个状态是安全的，当且仅当对每个目的地 `d`，
  每个源节点沿下一跳都能到达 `d`（无环、无黑洞）。

## 算法

- 安全性检查：对每个 (目的, 源) 对沿下一跳链追踪，访问标记检测环，`-1` 检测黑洞；
  搜索内部使用无分配的快速版本（`checkFast`）。
- 单节点顺序：DFS + 死状态记忆（状态空间 ≤ 2^18）。
- 同步组：对组规模上限 s = 2,3,… 逐个做 BFS（每步应用任意 ≤ s 个剩余更新的安全子集，
  大子集优先），第一个可行的 s 即最小同步代价；BFS 层序保证该 s 下组数最少。
  若新配置本身安全，方案必然存在（最坏情况：全部节点一组同步）。

## 用法

```sh
go build -o routemigrate .
./routemigrate -input examples/conflict.json      # 摘要证据
./routemigrate -input examples/order.json -v      # 完整逐源路径证据
cat plan.json | ./routemigrate -input -
```

输入 JSON：

```json
{
  "nodes": 4,
  "old": [[0,1,1,3],[0,1,2,0],[0,1,2,3],[0,1,2,3]],
  "new": [[0,1,2,1],[0,1,0,3],[0,1,2,3],[0,1,2,3]]
}
```

## 示例

- `examples/order.json`：存在逐节点安全顺序（链路新增后的改路）。
- `examples/conflict.json`：经典双目的地冲突——先更新 n0 则去往 n3 的流量
  形成 `n0↔n1` 环，先更新 n1 则去往 n2 的流量成环；必须同步更新 `{n0,n1}`。
  规划器会输出每个首步更新的阻塞环证据。
- `examples/stress18.json`：18 节点、16 个节点待更新的规模验证。
