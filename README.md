# 路由更新规划器 (route-update-planner)

给定旧、新两张下一跳路由表, 规划把网络从旧路由切换到新路由的更新顺序,
要求**每一步中间状态都无转发环且全可达**:

1. 优先寻找**单节点逐一更新**的安全顺序 (每步只切换一个节点);
2. 若不存在安全的单节点顺序, 求**最小同步更新组** —— 即最小的 k,
   使得存在每步至多同步更新 k 个节点的安全方案, 并输出该方案。

节点数上限 18。对每一步输出可达性与环检测证据 (每个目的节点下每个源节点的完整转发路径)。

## 构建与运行

```sh
go build -o rup .
./rup examples/chain.json        # 从文件读取
./rup - < examples/sync-pair.json # 或从标准输入读取
go test ./...                    # 运行测试
```

## 输入格式 (JSON)

```json
{
  "nodes": ["A", "B", "C", "T"],   // 可省略, 省略时从路由表推导
  "destinations": ["T"],           // 可省略, 省略时取路由表中出现过的所有目的
  "old": {"A": {"T": "B"}, ...},   // 旧下一跳表: 节点 -> 目的 -> 下一跳
  "new": {"A": {"T": "T"}, ...}    // 新下一跳表
}
```

每个非目的节点对每个目的都必须给出旧、新下一跳。旧/新完全一致的节点自动视为无需更新。

## 算法

- 状态 = 已切换到新路由的节点集合 (位掩码, 18 节点 => 至多 2^18 个状态)。
- 安全性检查: 对每个目的节点, 从每个源节点沿混合 (旧/新) 下一跳游走,
  命中已访问节点即转发环, 缺少下一跳即黑洞; 同时记录完整路径作为证据。
- 搜索: 在状态图上做带记忆化的深度优先搜索, 每步枚举剩余节点中大小
  1..k 的子集 (小组优先), 仅走入安全状态。k 从 1 起递增, 第一个可行的
  k 即最小同步更新组大小 (k = 待更新节点数时一步全量切换必然可行, 故必终止)。
- 单节点顺序不存在时, 输出从初始状态出发逐一更新每个节点的直接后果
  (具体的转发环或黑洞) 作为不可能性证据, 并报告穷举的状态数。

## 示例

- `examples/chain.json` —— 链式反转, 存在单节点安全顺序 (必须按 A,B,C 次序)。
- `examples/sync-pair.json` —— 更新 A 或 B 任一个都会成环 A->B->A,
  最小同步更新组 k=2, 一步同步更新 {A, B}。
- `examples/chain18.json` —— 18 节点链式反转 (上限规模)。
