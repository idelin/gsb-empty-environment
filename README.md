# JSON大整数精度丢失导致的对象标识错位

网关用 JSON.parse 解析请求后做对象授权检查，后端却用 64 位整数处理同一个标识；超出 2 的 53 次方的整数在 JavaScript 里会被舍入，攻击者提交 9007199254740993，网关检查的是 9007199254740992，也就是自己拥有的对象。为TypeScript网关写可导入的请求体解析包，输入原始 JSON 文本和字段声明表（字段名到 id64、safeInt、string、number）：解析时保留数字的原始文本；声明为 id64 的字段必须是十进制 JSON 字符串（无前导零，不超出 64 位有符号范围），或绝对值不超过 2 的 53 次方减 1 的整数，其他整数形式一律拒绝，包括 1e3 这类指数写法；safeInt 字段超出安全整数范围拒绝；number 字段允许小数与指数形式，但解析后为 -0 或 Infinity 时拒绝；声明表外且数值超出安全范围的字段拒绝；对象键重复拒绝；授权检查拿到的是规范化后的十进制字符串，而不是浮点数。用 9007199254740993、1e3 写法、-0、重复键和合法的字符串标识验证。
