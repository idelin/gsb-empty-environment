分布式追踪的尾部采样器必须等整条 Trace 的 Span 凑齐后再决定保留还是丢弃，但网络乱序会让部分 Span 在决策窗过期后才到达，内存上限还会迫使系统提前对最老活跃 Trace 做裁决。为链路采集器交付可导入的 Go 尾部采样状态机包。输入配置：决策等待时长 D、最大并发活跃追踪数 `MaxTraces`、每秒最大允许采样条数限速 `MaxTracesPerSec`、决策缓存保留时长 C，以及多条采样策略（支持错误状态匹配、整链总耗时阈值、属性匹配、确定性 TraceID 哈希概率采样，且每条策略标明为 `Sample` 允许或 `InvertDrop` 强制丢弃）。处理按毫秒递增的 Span 到达与时钟推进事件。规则：新 Trace 到达时记录首次见到的时间 `firstSeen`；若活跃数超 `MaxTraces`，立即强制提前对 `firstSeen` 最早的活跃 Trace 执行策略裁决并迁入决策缓存；任何 Trace 到达 `firstSeen + D` 同样触发裁决；策略合取原则为：命中任一 `InvertDrop` 强制丢弃，否则命中任一 `Sample` 且当前 1 秒滑动/整秒窗口尚有 `MaxTracesPerSec` 余额则采样保留并扣 1 配额，配额耗尽则降级丢弃；裁决后 C 毫秒内到达的同一 Trace 迟到 Span 必须严格沿用决策缓存（已采样则补收，已丢弃则继续丢弃），超出 C 毫秒视为全新 Trace。验收用事件序列对照精确逐条决策日志与配额计数，覆盖 `InvertDrop` 覆盖错误采样、活跃表满提前裁决最老 Trace、限速耗尽降级丢弃，以及决策窗后迟到 Span 沿用缓存一致放行/丢弃。
