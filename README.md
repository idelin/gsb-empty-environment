SQL:1999/2023 标准 `WITH RECURSIVE` 支持 `UNION` / `UNION ALL` 以及 `SEARCH DEPTH|BREADTH FIRST BY ... SET seq` 和 `CYCLE c1, c2 SET is_cycle TO mark DEFAULT nomark USING path` 子句，执行引擎极易在两处犯错：第一，`CYCLE` 判定的是**当前推导祖先链（path）中是否已出现相同周期列元组**，绝非全局已访问集合——在菱形 DAG（`A->B->D` 与 `A->C->D`）中，节点 `D` 经两条不同路径抵达时两条路径都必须被当作非环（`nomark`）正常继续展开；一旦真正成环（`A->B->A`），则必须**输出**这条首次闭合环的边界行（带上 `is_cycle = mark` 且 `path` 包含闭合元组！）然后立刻停止沿该分支继续展开！第二，`UNION` 去重必须跨越全部历史轮次且遵循 SQL `IS NOT DISTINCT FROM` 语义（两个 `NULL` 视为相等去重！），而 `SEARCH DEPTH FIRST BY k1 DESC NULLS FIRST, k2 ASC` 生成的全局排序列 `seq` 必须严格反映按父路径前缀递归排序后的真实深度优先序（而非简单的数值递增计数器，因为同一父节点下不同子分支的字面键序决定了完整子树先后！）。为关系执行引擎交付可导入的 Go `WITH RECURSIVE`（含 `SEARCH` 与 `CYCLE`）求值包。输入为非递归初始查询结果、递归步连接/投影/过滤算子（支持多列与 `NULL` 值）、`UNION`/`UNION ALL` 模式、可选 `SEARCH` 规范与可选 `CYCLE` 规范。规则：1）严格执行标准工作表（Working Table）半朴素迭代，校验 `UNION` 跨全历史去重（`NULL` 相等）与 `UNION ALL` 保留重复路径；2）精准实现路径级 `CYCLE` 环检测（含多列周期键中存在 `NULL` 时的 `IS NOT DISTINCT FROM` 元组比对）、闭合行输出并截断该分支、构造有序路径数组 `path`；3）精确构造 `SEARCH DEPTH FIRST` 与 `SEARCH BREADTH FIRST` 的可比较排序键 `seq`，验证按 `seq` 排序后的完整输出与规范树展开顺序逐行一致；4）支持静态拦截非法递归引用（如递归项出现在 `LEFT JOIN` 右侧、聚合或 `NOT IN` 子查询内，返回明确语法语义错误！）。验收覆盖菱形 DAG 非环双路径展开、多列含 `NULL` 的环检测与首闭行输出截断、`UNION` 跨轮 `NULL` 去重、`DEPTH`/`BREADTH` 多列升降序+`NULLS FIRST/LAST` 精确排序以及非法递归位置拦截。
