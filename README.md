Prometheus Alertmanager 的通知管线由**路由树分发、分组聚合计时器、静默（Silence）与抑制（Inhibition）**四个紧密耦合的组件构成，任何一条边界失真都会导致线上故障漏报或告警风暴：1）路由树深度优先匹配子路由（支持 `=`/`!=`/`=~`/`!~` 四种匹配器），默认命中首个子路由即终止，仅当子路由声明 `continue: true` 时才在匹配该子树后继续尝试后续兄弟路由（可能把同一告警投递到多个不同接收组！）；子路由未显式配置的 `group_by`/`group_wait`/`group_interval`/`repeat_interval` 继承自父路由，且特殊配置 `group_by: ['...']` 表示彻底禁用分组（每条告警独享独立组！）；2）每个告警分组独立维护状态机：首次收到活跃告警后等待 `group_wait` 发出首批通知；后续分组内告警集合发生变化（新增告警或已有告警恢复）时至少间隔 `group_interval` 推送变更；若集合不变则每满 `repeat_interval` 重复提醒；全组告警均已 `resolved` 后按接收器 `send_resolved` 决定是否发出恢复通知并清理空组；3）抑制规则（`source_matchers`/`target_matchers`/`equal`）仅在源告警当前处于 `firing`（绝不可用已 `resolved` 告警抑制！）且目标告警与源告警不是同一指纹、且双方在 `equal` 列表中的每个标签值相等（注意：按 Alertmanager 规范，若源与目标**同时缺失**某个 `equal` 标签也视为相等匹配！）时生效；4）当且仅当某分组内**全部**活跃告警都被静默或抑制时才阻断该次通知，只要仍有 1 条未被静默/抑制的活跃告警，就必须仅携带未受阻的告警发出通知！为可观测告警中心交付可导入的 Go Alertmanager 路由、分组计时、静默与抑制引擎。验收覆盖 `continue: true` 多路分发与属性继承、`group_by: ['...']`、`equal` 标签双缺匹配抑制、`resolved` 源告警解除抑制、静默/抑制部分遮蔽与全遮蔽阻断以及 `group_wait`/`group_interval`/`repeat_interval` 虚拟时钟精确推送时间线校验。
