# Latch Crabbing / Coupling（螃蟹脚并发加锁协议）— TypeScript 版

在一棵 B+ 树上实现数据库系统经典的 **Latch Crabbing** 并发控制协议，
并用 Node.js 内置测试框架（`node:test`）验证：10 个读线程 + 5 个写线程
并发执行时无死锁，读操作在未分裂的高层节点上无阻塞高速穿越。

## 协议要点

- **查找（读耦合）**：先持有父节点读闩，再获取子节点读闩，随后立即释放
  父节点。任意时刻最多持有 2 个闩，高层节点被即刻放行。
- **插入（悲观写耦合）**：以写闩自顶向下。每闩住一个子节点即检查其是否
  **安全**（`keys.length < maxKeys`，本次插入不会引发分裂）；若安全，
  立即释放所有祖先写闩——分裂不可能向上传播越过安全节点。
- **根指针**：由树级 `rootLatch` 保护（对应 bustub 的 `root_page_id` 闩）。
  读/写线程只在"抓根指针 + 闩住根"的瞬间持有其读闩；仅当根已满时，
  写线程才升级为写闩并**预防性分裂根**（树高 +1），保证分裂传播永远
  终止于已持有写闩的祖先链内。
- **无死锁**：所有任务严格按 `rootLatch -> 父 -> 子` 的同一偏序获取闩，
  等待图不可能成环。等待 `rootLatch` 写闩时不持有任何节点闩。
- **闩的实现**：公平 FIFO 读写闩（`src/latch.ts`），写者排队后读者不得
  插队（no barging），避免写者饿死。

## 目录结构

- `src/latch.ts` — 公平 FIFO 读写闩（Promise 模拟阻塞/唤醒）
- `src/bplustree.ts` — B+ 树 + 螃蟹脚协议（查找 / 插入 / 分裂传播 / 校验）
- `src/workload.ts` — 并发工作负载（测试与演示共用，确定性种子）
- `test/latch.test.ts` — 读写闩单元测试（互斥 / 共享 / FIFO 公平）
- `test/crabbing.test.ts` — 协议验收测试（并发、无死锁、提前释放）
- `demo.ts` — 运行样例：10 读线程 + 5 写线程

## 运行环境

需要 Node.js **>= 23.6**（原生类型擦除，直接运行 `.ts`），
或 Node 22.6+ 加 `--experimental-strip-types` 标志。无需任何 npm 依赖。

```bash
nvm use 23        # 或任何 >= 23.6 的 Node
npm test          # 等价于 node --test
npm run demo      # 等价于 node demo.ts
```

## 运行样例（`npm run demo`）

```
== 预填 1000 个 key，让树长到 3 层以上 ==
预填完成，当前规模: 1000

== 启动 10 个读线程 + 5 个写线程 ==
并发阶段耗时: 200.3 ms
写线程插入:   1500 个 key
读线程查找:   3014 次 (命中 886, 未命中 2128)

== 螃蟹脚协议行为指标 ==
读操作同时持闩峰值:   2 (读耦合应 <= 2)
读操作到达叶子时持闩: 1 (应恒为 1)
写操作同时持闩峰值:   5
写操作到达叶子最少持闩: 1 (安全路径应 = 1)

== 各层闩统计（immediate = 未阻塞直接获得, wait = 排队后被唤醒）==
level  nodes  readImmediate  readWait  writeImmediate  writeWait
----------------------------------------------------------------
L0(根)   1      22             2652      8               1324
L1      3      1545           1469      840             1443
L2      14     2897           117       2284            175
L3      77     3001           13        2482            12
L4      461    3014           0         2502            0
rootLatch(树级): read 5518 immediate / 4 wait, write 3 immediate / 5 wait
根预防性分裂(树高增长)次数: 4

== 最终校验 ==
结构不变量校验通过；写线程插入的 1500 个 key 全部可查 (1500/1500)
最终规模: 2500，无死锁、无丢 key。
```

读阻塞随层深递减：叶子层（L4）3014 次读闩全部立即获得；根层的排队是
悲观螃蟹脚的固有特征（每次插入都需短暂写闩根节点），真实系统亦然，
这正是"乐观闩"等后续优化要解决的问题。

## 测试结果（`npm test`）

```
✔ 顺序插入/查找正确性 + 结构不变量
✔ 读耦合：任意时刻最多持有 2 个闩，到达叶子时只持有 1 个
✔ 提前释放：叶子安全时，插入到达叶子只持有叶子自身的闩
✔ 无写者时读者零阻塞：高层节点读闩全部立即获得
✔ 验收：10 读线程 + 5 写线程并发，无死锁且结果正确
✔ 压力：多写线程下分裂传播正确，无丢 key
✔ 写闩互斥：任意时刻最多一个写者
✔ 读闩共享：多个读者可同时持有
✔ FIFO 公平：写者排队后，后来的读者不得插队
✔ 读写互斥：写者持闩期间读者必须等待
ℹ tests 10  ℹ pass 10  ℹ fail 0
```

验收边界覆盖：

- **10 读 + 5 写并发**：`runConcurrentWorkload` 以确定性种子驱动，
  测试带 30s 看门狗超时——能跑完即证明无死锁；跑完后 1500 个新 key
  全部可查、树结构不变量（key 有序、子树键域、叶子同深）校验通过。
- **无死锁**：闩获取遵循固定偏序；压力测试（8 写线程随机交错）多轮通过。
- **读高速穿越**：纯读并发场景下所有层 `readWait == 0`；混合负载下
  读阻塞集中在根层，越深越接近零阻塞（见上方分层统计）。
