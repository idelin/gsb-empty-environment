# 组织边界层层收窄

云账号的有效授权同时受组织树多层边界限制，单层允许不能越过祖先拒绝。给Go授权宿主实现策略求值包，动作集合有限，资源条件为给定区间集合，祖先边界逐层求交，资源策略和身份策略按指定并集后再套边界。返回每层贡献及最早拒绝证据，用组织迁移和空允许层测试旧查询快照不受影响。

## 模型

- 动作集合在 `NewEngine` 时固定，未知动作直接报错而不是静默拒绝。
- 资源条件是闭区间整数集合 `IntervalSet`，内部始终归一化（排序、去重重叠、合并相邻）。
- 求值顺序：
  1. 身份策略与资源策略的 `allow` 语句按动作取并集，并与资源全集求交；
  2. 两条策略中的 `deny` 语句先生效（身份策略先于资源策略，语句按输入顺序）；
  3. 沿组织树根到账号的路径逐层处理：`allow` 层与当前授权求交，`deny` 层从当前授权中扣除；
  4. 单层 `allow` 边界为空集时，该层及所有后代的授权立即变为空集。
- 显式拒绝优先于“无允许”，只返回最早一次拒绝证据 `DenyEvidence`（策略拒绝、边界拒绝、无匹配允许三类原因）。

## 主要类型

- `Interval` / `IntervalSet`：闭区间与归一化区间集合，提供 `Union`、`Intersect`、`Subtract`、`Contains`。
- `Policy` / `Statement`：身份或资源策略，效果只有 `allow` / `deny`。
- `Layer`：组织路径上的一层边界，按根到账号顺序传入。
- `Engine.Evaluate`：返回 `Decision`，含策略并集、逐层 `LayerContribution`、最终有效授权与 `EarliestDeny`。
- `Engine.Check`：只返回允许/拒绝的点查询便捷接口。
- `Snapshot`：查询输入与决策的持久化封装，求值是纯函数，旧快照在组织迁移后重放仍得到同一结论。

## 测试

```sh
go test ./...
# 仅在确认升级快照 schema 时重新生成基线：
GSB_REGEN_GOLDEN=1 go test ./...
```

`testdata/snapshot_golden.json` 锁定序列化形状与历史裁决。迁移测试先重放旧快照验证结论不变，再用迁移后的组织树证明新查询会被新的祖先拒绝拦截；空允许层用例单独锁定“空 allow 即全拒”。
