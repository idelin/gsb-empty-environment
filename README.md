传统 B+Tree 在并发插入分裂时必须采用自顶向下的悲观锁蟹行（Latch Coupling），锁住整条从根到叶的路径，严重制约多核吞吐；**Lehman-Yao B-link Tree** 在每个节点引入 **`highKey`（当前节点键上界）** 与 **`rightLink`（右兄弟页指针）**，使得读操作全程只需持有**单个页锁（绝不锁蟹行！）**且写操作仅按自底向上加锁，四处不变量必须严丝合缝：1）**`highKey` + `rightLink` 右链追赶（`move-right`）协议**：除每层最右节点外，所有节点都维护精确的 `highKey`（等于分裂送往父节点的分隔键！）和指向右兄弟的 `rightLink`；任何查找或插入线程在下降到某层节点 `P` 时，若目标键 `K > P.highKey`（说明并发写线程刚刚把 `P` 向右分裂了！），只需释放 `P` 的锁并沿 `P.rightLink` 向右追赶直至找到满足 `K <= Q.highKey`（或最右节点）的目标页——绝不因并发分裂而迷路或返回假阴性！2）**原子两步分裂（Half-Split Safe State）**：节点 `P` 满时，先创建右兄弟 `Q`，把右半数据、`P` 原来的 `rightLink` 和 `highKey` 迁入 `Q`，再把 `P.highKey` 更新为分隔键并将 `P.rightLink` 指向 `Q`（此时即使父节点尚未插入新指针，整棵树已处于完全合法的并发可读状态！）；随后释放 `P` 锁再向上获取父节点写锁插入 `(sepKey, Q)`——若父节点在期间也已分裂，同样在父层执行 `move-right` 找到正确父页后再插入！3）**根节点分裂与高度并发增长**：根分裂时新建两子页或新根并原子切换全局 `rootPageID`；正在读旧根的线程通过 `move-right` 仍能安全抵达目标叶页而不触发死锁（因为所有锁获取严格遵循**自底向上 + 自左向右**的无环偏序！）；4）**无锁/单页锁范围扫描与并发删除下溢处理**：支持精确范围扫描 `[start, end]`（单页锁顺序沿叶层 `rightLink` 推进，在并发分裂下绝不重复或漏扫键！）以及删除与懒惰空页回收。为高并发索引层交付可导入的 Go Lehman-Yao B-link Tree 页式并发索引引擎。验收覆盖高并发多 goroutine 混合读写分裂下零死锁（开启 `-race` 验证！）与零假阴性、刻意注入“半分裂延迟（父指针尚未更新）”时 `move-right` 正确命中、根多层并发分裂以及并发插入期间范围扫描无漏键无重键校验。
