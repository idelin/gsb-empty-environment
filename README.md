在多租户日志路由与 WAF/指标匹配引擎中，回溯型正则引擎遇到 `(a+)+b` 等病态模式会瞬间 CPU 打满瘫痪节点；必须采用线性时间有限自动机（Thompson NFA / PikeVM + 惰性构造 DFA），同时又不能为了防回溯而丢失 Perl 最左优先（Leftmost-First）与非贪婪量词（`*?`/`+?`/`??`）的精确子匹配捕获组边界！最难处理的四处陷阱是：1）分支优先级与去重——执行 PikeVM 线程同步推进时，必须严格按 NFA 指令分支顺序保留线程队列，同一输入位置遇到已访问状态时**只保留优先级更高的先到线程**并剪除低优重复线程（否则 `a|ab` 或 `(a*?)(a*)` 的捕获边界会错乱或指数膨胀！）；2）可空子表达式的重复匹配——例如 `(a|b?)*` 或 `(()|a)*`，每次空匹配循环必须通过记录本字节位置已访问的空转移状态精确防死循环，且规范要求空匹配在最后一次迭代的捕获槽语义与主流引擎一致；3）零宽断言 `^`/`$`（含多行模式 `(?m)`）、`\b`/`\B`（ASCII/UTF-8 词边界）与多字节 UTF-8 字符类（`.` 匹配完整 UTF-8 码点而非单字节！）；4）惰性按需构造 DFA 加速纯布尔判定，为状态缓存设置硬上限（如最大 256 状态，超限自动清空缓存重建或无损回退 PikeVM！），保证任意对抗正则与输入均在严格 `O(N * M)` 线性步数内完成。为基础设施规则引擎交付可导入的 Go 正则编译、惰性 DFA 缓存判定与 PikeVM 捕获组匹配包。验收覆盖病态指数正则 `(a+)+b` 线性步数上限断言、`a|ab` 与 `(a*?)(a*)` 贪婪/非贪婪捕获组精确下标、可空循环 `(a|b?)*` 零死循环、UTF-8 多字节字符类与多行 `^`/`$`/`\b` 边界，以及超缓存预算触发 DFA 驱逐/回退与标准参考结果逐字节一致。
