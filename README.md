# logrec — 基于持久确认位置的日志前缀回收（单进程事件模拟）

标准库实现，无第三方依赖。通信、故障与虚拟时间全部由单进程离散事件
模拟器（`sim.go`）控制。

## 模型

- 每个副本向 leader 汇报**已持久**（durable）位置；内存中已接收
  （`Received`）但未持久的位置**不参与确认**。
- `Confirmed`：被成员法定人数（quorum）持久过的最高日志索引，单调不减。
- 可回收前缀 `min(Confirmed, min(成员 Persisted))`：任何未移出副本尚未
  持久的条目都必须保留，因此**慢副本未移出时会阻止回收**。
- 离线副本可**显式移出**（`RemoveReplica`，在线副本拒绝移出），移出时
  在 `Removals` 中记录**快照重入要求**；重入（`Rejoin`）时安装
  `>= Confirmed` 的快照，**绝不要求已删除的日志条目**。从未移出的副本
  重连时，其缺失条目必然仍在（前缀从未超过其持久位置）。

## 证据

- **安全性**：模拟器在每个事件后校验三条不变量（见 `Sim.check`）——
  确认索引单调、回收前缀单调、回收前缀 ≤ 每个未移出副本的持久位置；
  运行期间任何违反都会记入 `Sim.Violations`。随机化测试
  （`TestRandomizedSafetyAndMonotonicity`，固定种子，500 步追加/崩溃/
  恢复/移出/重入混合）验证零违反。
- **活性**：`TestLivenessEventuallyRecycles` —— 当所有成员持久到末尾，
  回收前缀最终推进到最高索引。

## 运行

```sh
go test ./... -v   # 测试
go run ./cmd/demo  # 样例：正常复制 → 慢副本阻塞 → 移出 → 快照重入 → 恢复回收
```
