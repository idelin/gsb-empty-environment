对象存储在修复条带时按机架结算流量。给修复调度器写一个可导入的 Go 包：每个可读分片都是同一组原始字节向量在 GF(256) 上的已知线性组合，模多项式为 0x11d。调用方给出至多十二个源维度、二十四个可读分片、每片的系数行与读取价格、每机架首次读取费用，以及多个需要重建的目标系数行。一次读取可服务所有目标。返回总费用最低的读取集合和每个目标对该集合的解码系数；费用相同时先取分片少者，再取升序编号列表字典序较小者。价格为非负整数，费用用 64 位整数，输入保证总和可表示。即便原始条带无法完整解码，也要尝试恢复所需目标。恢复不了时返回某个目标和一个列向量，使所有可读行与它的内积均为零，而所指目标的内积为一。交付独立证书检查接口；用随机字节条带实际重建，另用小规模子集穷举核对最优解。覆盖两个目标共用一个昂贵机架后反而更便宜、重复行有不同价格、异或以外的非平凡系数、全零目标无需读取这几种情况。

## repair 包

可导入包位于 `repair/`（导入路径 `prescreen.local/ps-8303db8549/repair`）。

- `repair.Schedule(dim, shards, rackFee, targets)` 返回 `*repair.Result`：可行时
  `Plan` 给出升序分片编号、总费用（读取价 + 涉及机架的首次读取费）和每个目标对
  所选分片的 GF(256) 解码系数；不可行时 `Certificate` 给出一个目标和对偶列向量，
  所有可读行与其内积为 0、所指目标与其内积为 1。
- `repair.CheckCertificate(...)` 是独立证书检查接口，只依赖域运算与调用方输入。
- 费用相同时依次按分片数更少、升序编号列表字典序更小决胜；全零目标不需要读取。

测试：

- `go test ./...` 包含随机字节条带实际重建（独立 GF(256) 参考实现）、小规模
  子集独立穷举核对最优解与决胜规则、四个指定场景、证书篡改拒绝和参数校验。
- `go test ./... -bench .` 给出满规模（12 维、24 分片）与零价极端场景的基准。
