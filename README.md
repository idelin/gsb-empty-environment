# 区间资源分配器

为半开区间 `[start, end)` 分配资源(非负整数编号),保留固定绑定,
并使不同资源的总数最少。

## 语义约定

- **半开区间**:`[0, 2)` 与 `[2, 4)` 不重叠,可以共用资源。
- **零长区间**:`start == end` 视为空集,不与任何区间冲突(包括其他
  零长区间),可挂在任意资源上;`end < start` 视为非法输入,直接抛错。
- **固定绑定**:`resource` 字段指定的编号必须保留。同一资源上的固定
  区间若互相重叠,属于冲突 —— 直接返回全部冲突对(`ok: false`),
  不再尝试分配。
- **编号空洞**:固定绑定可以使用稀疏编号(如 3 和 7)。新分配优先
  复用已用编号,其次填充空洞(0、1、2…),再向外扩展;`resourceCount`
  统计的是实际使用的不同资源数。

## 为什么不能只看最大重叠数

无固定绑定时,区间图是完美图,最少资源数等于最大重叠数,按起点
贪心即最优。但带固定绑定后,问题变成区间图上的**预着色扩展**
(precoloring extension),是 NP-hard 的:最大重叠为 2 的实例也可能
被迫使用 3 个资源。例如:

```
v1=[0,2)->资源0   v2=[1,3)   v3=[2,4)   v4=[3,5)->资源0
```

任一时刻最多 2 个区间重叠,但 v2、v3 都不能用资源 0 且互相重叠,
必须再引入 2 个新编号,总数为 3。因此可扩展性不能由最大重叠数
推断,必须真正求解。

## 算法

- **短实例(未绑定区间数 ≤ `exactThreshold`,默认 24):精确求解。**
  下界 = max(最大重叠数, 固定色数);上界 = 贪心解的色数。K 从下界
  递增,对每个 K 用「固定编号 + 最小空洞编号」的调色板做
  MRV 选点 + 前向检查的回溯搜索,第一个可行的 K 即最优。
- **长实例:按起点排序的贪心着色**(每个区间取未被重叠邻居占用的
  最小编号),结果合法但不保证最优,`exact` 字段为 `false`。

## 用法

```ts
import { allocateResources } from './src/allocator.ts';

const result = allocateResources([
  { id: 'a', start: 0, end: 5, resource: 3 }, // 固定绑定
  { id: 'b', start: 5, end: 10, resource: 7 },
  { id: 'c', start: 0, end: 10 },             // 待分配
  { id: 'd', start: 2, end: 8 },
]);
// result.assignments: { a: 3, b: 7, c: 0, d: 1 }
// result.schedule:    逐资源时间表(按资源编号、区间内按起点排序)
// result.resourceCount: 4, result.exact: true
```

返回结构:

| 字段 | 含义 |
| --- | --- |
| `ok` | 是否成功分配(固定绑定冲突时为 `false`) |
| `conflicts` | 固定绑定冲突对 `{ resource, a, b }` 列表 |
| `assignments` | 区间 id → 资源编号 |
| `schedule` | 逐资源时间表 `[{ resource, intervals: [...] }]` |
| `resourceCount` | 实际使用的不同资源总数 |
| `exact` | 是否为可证明的最优解 |
