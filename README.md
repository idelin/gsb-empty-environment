微服务网关在同时支持 JWS（RFC 7515）与 JWE（RFC 7516）嵌套令牌校验时，若直接信任令牌头中的 `alg`/`jku`/`x5u`/`kid` 参数、未校验 `crit` 关键扩展头，或对 `zip=DEF` 压缩载荷不设解压上限，攻击者可发动 `alg=none`/RS256-to-HS256 密钥混淆、路径穿越 `kid` 注入或几百字节压缩炸弹打垮网关内存。为 TypeScript 网关宿主实现可导入、零第三方 JOSE 依赖（仅用 `node:crypto` 与 `node:zlib`）的严格 JWS/JWE 安全解封与策略校验库，严禁联网。组件从紧凑序列化字符串完整解析 JWS 与 JWE（支持 `dir`/`A256KW`/`RSA-OAEP-256` 密钥管理与 `A256GCM` 内容加密，以及 `ES256`/`EdDSA`/`RS256`/`HS256` 签名），强制策略如下：（1）调用方显式指定允许算法集合与密钥用途（`use=sig`/`enc`），严格拒绝 `alg=none`、禁止将非对称公钥误作对称 HMAC 密钥、强制拦截含 `jku`/`x5u`/`jwk` 外联或内嵌未知公钥的不可信头；（2）严格解析 `crit` 数组：禁止 `crit` 为空、含标准保留头名或包含本引擎未声明支持的扩展名，且 `crit` 中每项必须在受保护头中实际出现；（3）`kid` 仅允许匹配精确密钥表键，拒绝路径遍历字符与通配；（4）对 JWE 要求受保护头作为完整 AAD 参与 GCM 认证，且处理 `zip=DEF` 时采用流式硬字节上限解压（超出 `maxDecompressedBytes` 立即中止并报错，禁止先完整解压再查长度），嵌套深度严格限制不超过 `maxNestingDepth` 且外层必须声明 `cty=JWT`。用真实密钥实测算法混淆、未知 `crit`、AAD 篡改与压缩炸弹全部拦截。
