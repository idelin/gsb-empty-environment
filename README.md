# bqueue — Go 广播队列

一份载荷共享给所有订阅者，按**接收集合**（receive-set）记账：每条消息记录
发布时刻的全部订阅者为待收者，只有集合清空后槽位才被回收。

## 语义

- `New(capacity)`：定长环形队列，容量即最多可容纳的未回收消息数。
- `Subscribe()`：新订阅者从发布前沿开始，**不追认**任何旧消息。
- `Publish(ctx, v) (seq, err)`：提交即分配序号并快照当前订阅者为待收集合；
  队列满时阻塞等待回收。**取消发布若已提交，仍返回序号**；未提交才返回
  `ctx.Err()`。
- `Receive(ctx) (seq, v, err)`：收到即确认，将其从该消息的待收集合中移除。
- `Subscription.Close()`：**退出视为确认其全部未读项**，可能立即释放容量；
  幂等。
- 回收按队头推进：只有最老槽位的待收集合清空才释放，慢消费者会钉住容量，
  直到它接收或退出。

## 验证

`bqueue/bqueue_test.go` 用独立的接收集合账本（model）对实现做逐步对账：

- 慢消费者钉住容量、退出释放容量、退出重入跳过旧消息、取消发布的提交/未提交两路；
- `TestInterleavings`：20 组固定种子 × 400 步随机交错（订阅/发布/接收/退出），
  每步核对每条消息的待收集合、已提交序列与容量不变量。

运行：

```sh
go test ./...        # 或加 -race
```
