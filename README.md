SQLite 的预写日志（WAL）允许单写多读无阻塞并发，但其磁盘格式与检查点协议有四处极易产生静默读脏或崩溃吞事务的硬规范：1）**双 Salt 与累计链式校验和**：WAL 头保存 `salt1`（每次重置 WAL 重头复写时递增）与 `salt2`（随机数），每一帧头不仅重复写入当前 `(salt1, salt2)`，还携带自第 1 帧起**逐帧串行累加**的 64 位校验和 `(s0, s1)`（覆盖前帧校验和 + 当前帧头与完整页数据！）；崩溃恢复扫描 WAL 时，一旦遇到任一帧 `salt` 与 WAL 头不匹配或链式校验和断裂，必须立刻截断停止——这样就能精准区分当前轮次有效帧与旧轮次回绕覆盖后残留在文件尾部的旧帧！2）**提交边界（Commit Frame）与未提交尾部隔离**：只有当帧头 `dbSize > 0` 时该帧才标志一个完整事务的提交边界，其之前的全部连续未提交帧随之一同生效；若 WAL 末尾存在若干 `dbSize == 0` 的未提交残帧，恢复与全部读事务必须精确退回至最后一个有效提交帧，绝不可暴露半提交事务的页！3）**多读快照 `mxFrame` 版本查找**：每个读事务在开启瞬间登记当前最新提交帧号作为其 `readMark = mxFrame`，此后读任意页号 `pgno` 必须定位 WAL 中所有 `frame <= mxFrame` 里 `pgno` 的**最大帧号**（超过 `mxFrame` 的后续新写事务帧对该读事务完全不可见；若 `<= mxFrame` 无该页记录则回退读主数据库文件！）；4）**四模式检查点推进（`PASSIVE`/`FULL`/`RESTART`/`TRUNCATE`）**：检查点把 WAL 有效页按 `pgno` 最新提交版本写回主库文件，但**绝不可覆写任何活跃读事务仍在依赖的主库旧页**——最大安全回写帧上限严格受限于 `min(所有 readMark < latestCommit 的活跃读事务的 readMark)`（`PASSIVE` 仅推到当前安全上限立即返回不阻塞；`FULL`/`RESTART`/`TRUNCATE` 报告受阻读事务并按模式推进至全部回写后递增 `salt1` 重置/截断 WAL！）。为嵌入式存储层交付可导入的 Go 类 SQLite WAL 帧索引、多读快照与四模式检查点包。验收覆盖旧回绕尾帧经 `salt1` 与链式校验精确截断、未提交尾帧隔离、多并发读事务在不同 `mxFrame` 下读到各自精确历史页版本、活跃旧读事务阻断 `PASSIVE` 检查点防破坏主库快照以及全回写后递增 `salt1` 复用 WAL 验证。
