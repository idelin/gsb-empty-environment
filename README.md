# Topics观察者过滤与纪元隔离

Topics API 向调用方返回用户的兴趣话题，追踪方想借新嵌入的第三方脚本读到它从未观察过的话题，或靠反复调用剥离随机噪声。为TypeScript浏览器宿主写供 document.browsingTopics() 调用的话题返回包：每周纪元保存（话题, 观察过该话题的调用方集合）；调用方只能得到它在该纪元里对该话题观察过的结果；最近 3 个纪元各取一个话题，最多返回 3 个；每个（顶层站点, 调用方, 纪元）的随机话题与取舍由宿主种子确定，同一组合重复调用结果相同；纪元之间使用独立种子，同一调用方不得借此把不同纪元的随机结果关联起来；调用来自跨源 iframe 且无 browsing-topics 权限策略时返回空数组。用从未观察、重复调用、跨纪元、无权限 iframe 验证。

## 实现

`index.ts` 导出 `TopicsHost`，是 `document.browsingTopics()` 的宿主侧逻辑：

- `startEpoch(seed?)`：开启每周纪元，每纪元持有独立 32 字节随机种子（可注入固定种子做确定性测试）。
- `observe(topic, caller)`：在当前纪元记录 `(话题 -> 观察过该话题的调用方集合)`。
- `browsingTopics(context)`：按下面规则返回 `BrowsingTopic[]`，形状对齐浏览器 API；另有 `browsingTopicsWithEpoch()` 带纪元标注，便于宿主内部与测试核验。

隐私与确定性规则：

- 只取最近 3 个纪元，每个纪元最多贡献 1 个话题，因此结果最多 3 个，按纪元由旧到新排列。
- 调用方在某纪元没有观察过任何话题时，该纪元不贡献话题——新嵌入的第三方读不到未观察话题。
- 每个 `(顶层站点, 调用方, 纪元)` 的过滤取舍与话题选择，由该纪元种子对组合标签做 HMAC-SHA256 后确定性派生；同一组合重复调用结果逐字节相同，反复调用无法剥离噪声。
- 每纪元独立种子即独立 HMAC 密钥，不同纪元的伪随机输出之间不存在可关联关系。
- `filterRate`（默认 0）对应规范的每纪元过滤噪声概率，阈值比较同样由种子决定、重复调用稳定。
- 跨源 iframe 且未授予 `browsing-topics` 权限策略时直接返回 `[]`；顶层文档、同源 iframe 与已授权跨源 iframe 不受影响。

## 验证

`topics.test.ts` 覆盖从未观察、重复调用、跨纪元（含独立种子不可关联、最多 3 个）、无权限 iframe 四类场景，并用固定 HMAC 锁定向量防止派生算法被悄悄改坏。
