Prometheus PromQL 的求值引擎在时间对齐、缺口陈旧标记（`StaleNaN`）、计数器重置外推（`rate`/`increase`）与嵌套子查询（`expr[range:step] offset D @ T`）的交互上藏着大量精确语义边界，任何简化都会导致告警漏报或毛刺误报：1）**Lookback Delta 与 `StaleNaN` 显式截断**：瞬时向量选择器在求值时刻 `t` 向回查找 `(t - lookbackDelta, t]`（默认 `5m`）内最新样本；若最新样本为标准 `StaleNaN`（IEEE-754 特定载荷 NaN，必须与普通计算产生的 `NaN` 严格区分！），立刻判定该序列在 `t` 时刻**已下线不输出**（绝不可越过 `StaleNaN` 继续往前捡更老的旧值！）；2）**`rate` / `increase` 的 Counter Reset 检测与半步长外推（Extrapolation）**：在范围窗口 `(t - range, t]` 内收集非 `StaleNaN` 样本（少于 2 个样本时跳过该序列！）；遍历相邻样本，凡出现 `v_i < v_{i-1}` 即判定发生一次 Counter Reset 并累加 `v_i` 而非负差值；接着按 Prometheus 规范计算两端外推：分别检查首样本距窗口左边界与尾样本距窗口右边界的距离，若超出 `1.1 * avgSampleInterval` 则将对应端外推时长钳位到 `0.5 * avgSampleInterval`，且对单调计数器左端外推结果绝不可越过 0 点（若线性反推到零点早于目标外推时间，则截断到零点时刻！）；3）**子查询 `[range:step]` 的步长网格对齐**：对 `subexpr[range:step]` 在时刻 `t` 求值时，子查询采样网格绝非从 `t` 倒推——而是先计算不大于 `t` 且为 `step` 整数倍的最大对齐点（考虑 `offset` 与 `@ modifier` 覆盖！），再以 `step` 为步长覆盖 `(t - range, t]` 内全部对齐网格点（含右端、不含恰好等于 `t - range` 的左端点！），并对每个网格点递归执行内层表达式求值组装成 Matrix；4）**`@` 修饰符与 `offset`（含负 `offset`！）叠加语义**：支持 `metric offset -5m` 与 `metric @ 1700000000 offset 2m`（`@` 锁定基准时间戳后仍叠加 `offset` 偏移，且允许外层子查询与内层选择器各自独立携带 `@` 与 `offset`！）。为监控观测引擎交付可导入的 Go PromQL 时间对齐、Counter 外推与嵌套子查询求值包。验收覆盖 `StaleNaN` 截断 vs 普通 `NaN` 区分、多次 Counter Reset 与 1.1x/0.5x 外推及零点截断精准对照、子查询步长整倍网格对齐（含左开右闭边界）以及多层嵌套 `@` + 负 `offset` 组合求值。
