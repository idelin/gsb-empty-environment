邮件投递服务切换 MX 授权和证书目录时，两套配置各自合法却可能在不同服务器先后生效。写供 Go 投递宿主调用的可导入准入包。每个连接收据承诺实际 MX、公钥、认证路径摘要、DNS 策略代次和消息所属域。恢复连接须证明这些值在同一份已签配置中共同获准，不能取旧配置的 MX 和新配置的公钥。宿主提供两端观察到的部分更新顺序和签名生效区间，时间精确到整数刻度；对给定一批投递判断哪些可以确定使用原连接、哪些需要重新握手、哪些必须等待。重新握手仅补充当次看到的证书路径，不能补齐缺失的 DNS 授权。求能使所有必投消息确定安全的最少新增认证收据，若无解则指出未核实的签名义务。对小配置枚举相容顺序，覆盖同名换钥、共享交叉证书、签名区间端点、原连接过期后晚到成功以及只影响其他域的目录变更。
