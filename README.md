# 资金分配求解器 (fundsolver)

在**限定用途、有效期、配捐规则**约束下，求**总项目收益最大**的资金分配方案；
次目标为**过期闲置金额最少**；最多资助 **15 个项目**（可配置）。
输出每笔资金流向及其触发依据。

## 问题模型

- **资金来源 (sources)**：`amount` 金额、`purpose` 限定用途（空或 `"*"` 表示不限）、
  `expires` 有效期（空表示永不过期）。已过基准日到期的来源不可用，全额计入过期闲置。
- **项目 (projects)**：`target` 目标额、`benefit` 收益。**只有累计到账
  （直接拨款 + 配捐）整笔达到 target 才计收益**，不允许超额拨付。
- **配捐规则 (match_rules)**：当来源 `source_id`（空=任意）向用途 `purpose`
  （空=任意）的项目拨款 x 时，出资方 `funder` 按 `ratio` 追加配捐，
  单规则总配捐不超过 `cap`，规则本身也有 `expires`。
  **配捐资金来自出资方预算，本身不会再次触发配捐**（结构上保证，非连锁）。
- **目标函数**（字典序）：
  1. 已达标项目的收益之和最大；
  2. 过期闲置金额最小 = 有有效期的来源余额与配捐额度剩余之和最小。
- **约束**：资助项目数 ≤ `max_projects`（缺省 15）。

## 用法

```bash
go run . -input examples/input.json          # 人类可读报告
go run . -input examples/input.json -json    # JSON 报告
cat examples/input.json | go run .           # 标准输入
go run . -input in.json -max-projects 10     # 覆盖项目上限
go test ./solver/                            # 运行测试
```

输入/输出中的金额单位为元（支持两位小数，内部以“分”整数计算，避免浮点误差）。

## 算法

1. **搜索**：对项目按收益密度排序做分支定界（包含/不包含），
   以收益后缀和为上界剪枝；先用贪心可行解做 incumbent。
   叶子按（收益, 动用临期资金）字典序比较，保证主目标最优、次目标最优。
2. **单项目拼凑**：为项目凑整 target 时，按“配捐杠杆高 → 临期优先 → 余额大”
   的顺序选来源；每笔来源出资沿适用规则（按比例降序）逐段触发配捐，
   二分控制不超目标额，规则额度用尽后用本金补足。
3. **复杂度**：分支定界对项目数指数级，适合中小规模（数十个项目）实例；
   收益剪枝 + 贪心 incumbent 使典型实例很快。

## 输出说明

- `flows`：每笔资金流向，`kind=direct`（来源→项目）或 `kind=match`
  （出资方→项目），`reason` 记录触发依据（用途匹配、有效期、触发的规则与比例）。
- `idle`：未动用资金明细，`expired=true` 的计入 `expired_idle`（次目标）。
