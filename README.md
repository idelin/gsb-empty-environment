# fslog

入侵者改写审计日志后，单靠哈希链发现不了最后几条被截掉。给Go审计SDK实现前向安全日志写入器：每个时段的MAC密钥由上一时段单向派生，用后立即擦除旧密钥，记录与时段结束标记链式绑定；验证方从初始密钥重算，指出被篡改、删除、重排或截断的位置。在写入中途模拟崩溃，按写入协议区分未写完的撕裂尾和恶意截断。

## 设计

- **前向安全密钥**：`K_{e+1} = SHA-256("fslog/evolve" || K_e)`，派生后立即将旧密钥清零（`CloseEpoch`/`Close`）。攻击者在时段 e 攻陷写入方，也无法伪造 e 之前的记录。
- **链式 MAC**：`mac_j = HMAC(K_e, "fslog/rec" || epoch || seq || chain_{j-1} || data)`，`chain_j = mac_j`。删除或重排记录会在下一条记录处断链。
- **时段结束标记**：绑定本时段记录数与最终链值；下一时段的初始链吸收上一时段的结束标记，跨时段整体锚定。
- **写入协议**：每帧 `magic || len || payload || len`（尾部长度作为提交标记），单帧一次 `Write` 原子落盘（可选每帧 `Sync`）。

## 崩溃 vs 攻击

- **撕裂尾（torn tail）**：文件末尾是不完整帧 → 写入中途崩溃，已验证前缀完整可信，属良性。
- **恶意截断（truncated）**：文件结束于干净帧边界、但最后时段无结束标记 → 按写入协议只可能是尾部被删除。

已知限制：若攻击者恰好截断到某个时段结束标记处，该前缀自身是密码学自洽的——在没有外部锚点（可信时间戳/在线计数器）的情况下无法检测，这是前向安全日志的固有边界。

## 用法

```go
w, _ := fslog.NewWriter(f, initialKey, fslog.WithSync(true))
w.Append([]byte("user login"))
w.CloseEpoch()          // 结束当前时段，派生并擦除密钥
w.Append([]byte("..."))
w.Close()               // 写入结束标记并擦除最终密钥

rep, _ := fslog.Verify(f2, initialKey)
fmt.Println(rep)        // OK，或逐条列出 tampered / chain-break / truncated / torn-tail 及位置
```

验证方只需初始密钥，即可独立重算全部时段密钥与链值，定位问题到具体帧偏移、时段与序号。

## 测试

`go test ./...` 覆盖：正常往返、篡改、删除、重排、恶意截断、崩溃撕裂尾（`crashWriter` 模拟写一半断电）、密钥擦除、错误初始密钥、前向安全性。
