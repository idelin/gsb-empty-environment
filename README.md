# batchrun

可重启的 Go 批处理库：以“批次”为单位处理虚拟目录中的文件，保证输入版本一致、结果可核对、故障可恢复。

## 核心保证

- **冻结清单**：批次开始时扫描源目录，冻结文件清单与每个文件的内容摘要（SHA-256），清单此后不再增长。
- **重启核对**：恢复时逐项核对未处理项的当前摘要；被删除或内容变化的项连同其传递后继一起被隔离，独立项继续处理。
- **新文件不自动纳入**：冻结后出现的文件仅列入 `Ignored`，只有显式调用 `NewBatch()` 才会进入下一批次的清单。
- **结果绑定原摘要**：已确认结果记录其计算所用的输入摘要与依赖摘要；源文件事后被篡改不影响已确认结果。
- **批次间不复用**：`NewBatch()` 后所有项重新计算，绝不复用其他批次的结果。
- **单批次不混用版本**：每项在处理前即刻重校摘要，运行中途的源变化同样触发隔离。

## 依赖

清单携带显式文件间依赖（`Options.Deps`）。依赖图在冻结时校验（必须指向清单内文件、无环），处理按拓扑序进行：某项仅在其全部同批依赖结果确认后才执行，并收到各依赖的输出与原始摘要。

## 检查点

`state/checkpoint.json` 原子持久化（tmp + rename），每项记录：状态、输入摘要、输出摘要（输出确认）、依赖摘要。重启时：

1. 确认已完成项的输出文件摘要仍匹配，否则回退为待处理并级联回退其依赖者；
2. 核对待处理项的源摘要，不匹配则隔离。

## 测试

`batch/runner_test.go` 基于内存虚拟目录（`MemFS`）覆盖：删除、替换、重启、显式新批次、依赖顺序与结果传递、输出篡改后的重算、全量重算一致性，以及通过 `AfterPersist` 钩子在每个检查点切点注入崩溃后恢复的一致性。`batch/osfs_test.go` 验证真实目录行为。
