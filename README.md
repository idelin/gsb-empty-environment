# Git notes签名与分层路径冲突

Git notes 把评审意见挂在提交上，目录按提交 ID 十六进制分层，攻击者构造同一提交的两种路径写法，或在未签名的 notes 提交里追加批准记录。为Go发布门禁写可导入的 notes 校验包：输入 notes 分支提交链（每个提交的签名者及是否通过验签）、最新树的路径列表与各 blob 内容；路径去掉全部 / 后须是 40 位小写十六进制，同一目标提交出现两条路径（如 ab/cdef… 与 abc/def…）视为冲突，该目标的 notes 全部作废；只有当前 blob 内容首次出现在该路径的那个提交由调用方授权签名者签名，该路径才被采信，后来被授权提交原样保留的内容仍不采信；blob 首行须为 Approved-by: 邮箱。用分层冲突、未授权提交写入后被保留、授权提交新增和大写十六进制路径验证。
