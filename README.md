# IMA签名属性评估

IMA 评估靠文件扩展属性里的签名决定能否执行，攻击者能写属性时会换成只带摘要的格式，或把属性长度写得超出实际，诱使解析越界。为Go完整性引擎写供执行与映射前调用的评估包：本题约定属性头为类型 1 字节、版本 1 字节（须为 2）、算法 1 字节、keyid 4 字节、签名长度 2 字节大端，策略要求签名的路径只接受签名类型且 keyid 在受信集合内；长度不符、未知算法、摘要类型用于要求签名的路径一律拒绝；文件被写入后缓存的评估结果立即作废。用仅摘要属性、长度越界、受信外 keyid、写后重执行和硬链接另一路径验证。

## 使用

```go
policy := netsec.RequireSignatures(0x12345678)
engine := netsec.NewEvaluator(policy)

// 在执行或 mmap 前调用；成功返回 nil，其余情况返回具体拒绝原因。
if err := engine.BeforeExec("/usr/local/bin/tool"); err != nil {
	return err
}
```

`ParseAttribute` 严格按 9 字节头解析，且要求声明的载荷长度与
`len(raw)-9` 完全一致，不会按攻击者声明的长度分配或读取内存。评估缓存以
设备号 + inode 为键，因此硬链接共享同一份结果；每次评估都比较文件的
大小、mtime、ctime 和属性摘要，文件被写入或属性被替换后旧结果立即失效。

测试覆盖：仅摘要属性、声明长度越界、受信外 keyid、写后重执行、硬链接
另一路径。
