Apache Iceberg v2 数据湖引擎在扫描表快照时，同一快照下的数据文件可能诞生于不同的历史分区规范（Partition Evolution——例如旧文件按 `day(ts)` 分区、新文件按 `hour(ts)` 或 `bucket[16](id)` 分区！），同时还挂载了按 `data_sequence_number` 生效的 Position Delete 与 Equality Delete 文件。查询裁剪器若直接用最新分区规范去套旧文件、把负整数 `truncate[W]` 错写成向零截断、或忽略列统计里的 `nan_value_counts` 与 `null_value_counts`，就会产生致命的假阴性漏数据！为数据湖查询规划层交付可导入的 Go Apache Iceberg v2 分区演进裁剪与删除文件关联包。输入为表模式、历史分区规范表（每个 `spec_id` 含 `identity`/`bucket[N]`（标准 Murmur3_x86_32 哈希且 `hash & 0x7FFFFFFF % N`）/`truncate[W]`（负整数采用欧氏向下取整 `v - ((v % W) + W) % W`，字符串按 Unicode 码点截断！）/`year`/`month`/`day`/`hour` 跨 1970 纪元含负偏移变换）、数据文件清单（各带 `spec_id`、分区元组、`data_sequence_number`、列级 `lower_bounds`/`upper_bounds`/`value_counts`/`null_value_counts`/`nan_value_counts`）以及 Position/Equality Delete 文件清单与查询过滤表达式（含 `AND`/`OR`/`NOT`、比较、`IN`、`IS [NOT] NULL`、`IS [NOT] NAN`）。规则：1）把查询谓词转成否定范式（NNF），对每个数据文件按其自身的 `spec_id` 执行 Inclusive 分区投影裁剪（注意：`bucket[N]` 仅对等值/`IN` 可裁剪，范围谓词绝不可裁剪！`truncate` 范围投影须保留端点闭区间！）；2）执行列级指标裁剪——正确处理全 `NULL` 列、含 `NaN` 浮点列（当 `nan_value_counts > 0` 时对 `x > c` 或 `IS NAN` 的保守判定！）、缺失统计列保守保留，确保零假阴性；3）为每个存活的数据文件精确匹配必须应用的删除文件集合：Position Delete 仅匹配同分区且 `delete.data_sequence_number >= data.data_sequence_number` 且（若带文件级引用统计）路径边界涵盖该数据文件者；Equality Delete 仅匹配同分区（按对应分区规范兼容！）且严格满足 `delete.data_sequence_number > data.data_sequence_number`（同序列号绝不删除同事务写入的数据文件！）且待删列与数据文件统计区间有交集者！验收覆盖跨分区演进 `day -> hour -> bucket` 同快照混扫、负数 `truncate` 与 UTF-8 码点截断、Murmur3 `bucket` 精确对齐、含 `NaN`/`NULL` 统计零假阴性，以及 Position(`>=`) vs Equality(`>`) 删除文件序列号精确关联。
