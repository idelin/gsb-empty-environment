# 引导测量顺序证明

远程证明服务要核对设备的测量日志是否真能得到签名寄存器值。写供Go验证宿主调用的重放包，哈希扩展绑定事件类型与长度，多个寄存器独立演进，重置只在授权启动事件出现时允许。输出首个不一致前缀和最终值，用标准库摘要测试跨寄存器挪用、事件删改及截断不能被误判通过。

## 用法

`netsec.Replay` 逐条重放事件日志，返回 `Result`：

- `Prefix`：首个不一致位置；所有 `[0, Prefix)` 的条目都与声称的寄存器状态一致。
- `Final`：完整重放后每个寄存器的摘要，即使中途发现不一致也会算到日志末尾。
- `Mismatch`：首个分歧的条目/寄存器、期望值与实际值；`nil` 表示验证通过。

每次扩展的哈希输入为
`H(prev || index(8B) || event_type(2B) || data_len(8B) || data)`，
寄存器下标、事件类型和数据长度均参与摘要，因此跨寄存器挪用、改类型、
长度混淆都会产生不同摘要。寄存器只有在 `Config.StartupTypes` 中的
授权启动事件出现时才允许归零，启动事件本身仍被测量。

```go
result, err := netsec.Replay(log, netsec.Config{Quote: signedQuote})
if err != nil {
	// 结构性错误：寄存器越界、未知事件类型、摘要尺寸不符等
}
if !result.OK() {
	// result.Prefix 给出首个不一致前缀，result.Mismatch 给出分歧细节
}
```

## 测试

仅依赖标准库（`crypto/sha256`、`crypto/sha512`、`encoding/binary`）：

```sh
go test ./... -race -cover
```

测试用独立实现的参考重放器交叉校验，并覆盖跨寄存器挪用（带逐条状态与
仅签名 quote 两种情形）、事件删除/改数据/改类型、日志截断、未授权重置、
长度与类型绑定以及畸形输入，确保任何篡改都不会被误判通过。
