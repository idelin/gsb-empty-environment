SQL:2011 双时态表（Bitemporal Table）同时追踪业务有效时间 `VALID_TIME [vs, ve)` 与系统事务时间 `SYSTEM_TIME [ss, se)`（当前有效行 `se = +∞`），在区间局部更新、历史追溯与时态外键约束上存在三项极易写错的二维几何语义：1）**区间局部 `UPDATE`/`DELETE FOR PORTION OF VALID_TIME FROM [t1, t2)`**：若当前系统有效行（`se == +∞`）的有效区间 `[vs, ve)` 与 `[t1, t2)` 存在真交集（注意左闭右开 `[a, b)` 相邻不重叠！），绝不可原地覆盖该行——必须把原行的 `se` 封闭为本次事务提交时刻 `txNow`（永久留作历史审计版本！），并生成所有存活残片（若 `vs < t1` 生成左残片 `[vs, t1)` 保留旧值；若 `ve > t2` 生成右残片 `[t2, ve)` 保留旧值；对于 `UPDATE` 再生成交集段 `[max(vs, t1), min(ve, t2))` 写入新值，所有新行统一带 `[txNow, +∞)`！），且支持相邻同值有效区间按配置规范化合并；2）**二维双时态主键排他与时间旅行查询**：任意主键在任意 `(validTime, systemTime)` 二维点至多对应 1 条记录；查询支持 `AS OF SYSTEM TIME T_sys`、`BETWEEN SYSTEM TIME` 与 `VALID_TIME` 交集/包含过滤，确保任何后续更新/删除绝不改变过去任意 `T_sys` 时刻的历史查询结果！3）**无空洞拼接时态外键（Temporal Foreign Key）**：子表某当前有效行 `(fk, [c_s, c_e))` 的合法性**不要求**被父表单条记录覆盖——只要父表中同键的若干当前有效记录之有效区间并集无缝覆盖 `[c_s, c_e)`（例如父表 `[1, 5)` 与 `[5, 10)` 拼接覆盖子表 `[2, 8)`！），即合法；一旦父表局部删除 `[4, 6)` 在子表跨度内撕出任何 1 单位空洞，就必须精确拦截拒绝或按级联策略拆分同步！为时态数据库存储层交付可导入的 Go SQL:2011 双时态表与无空洞外键引擎。验收覆盖局部更新 1 裂 3 与历史封闭不变性、左闭右开相邻边界、二维重叠主键拦截、多段父记录无缝拼接满足时态外键与父表打洞撕裂精确拦截。
