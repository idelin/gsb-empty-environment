骨干网路由器用 RPKI 验证 BGP 路由源（ROV）时，同一宣布前缀可能同时被多条来自不同信任锚（TA）且带不同 `MaxLength` 和 `OriginASN`（含特殊禁止声明 `AS 0`）的 ROA（VRP）覆盖；当某个信任锚因证书过期批量撤回一批 VRP 时，路由器必须准确算出所有状态在 `Valid`、`Invalid`、`NotFound` 之间发生跃迁的路由前缀，避免误把本应回落为 `NotFound` 的路由留在 `Invalid` 或反之。为控制面安全模块交付可嵌入的 TypeScript RPKI ROV 引擎。支持 IPv4 与 IPv6 前缀的 VRP 集合管理（每条 VRP 含 `taId`、`prefix`、`prefixLen`、`maxLen`、`originASN`）及路由表 `(prefix, prefixLen, originASN)` 判定。严格遵循 RFC 6811 与 RFC 9319：(1) 对给定路由，查找所有覆盖它的 VRP（即 `vrp.prefixLen <= route.prefixLen` 且高位匹配）；若无任何覆盖 VRP 判 `NotFound`；若存在至少一条覆盖 VRP 满足 `route.prefixLen <= vrp.maxLen` 且 `vrp.originASN == route.originASN` 且 `vrp.originASN != 0` 判 `Valid`；否则（存在覆盖 VRP 但均因 ASN 不符、长度超 `maxLen` 或仅由 `AS 0` 覆盖）判 `Invalid`（特别注意：若同时存在一条匹配 Valid 的 VRP 与一条 `AS 0` VRP，RFC 6811 规定 Valid 优先于 Invalid！）；(2) 支持按 `taId` 原子批量新增/撤销/替换 VRP，精确增量返回所有验证状态发生变化的路由及其 `(oldState -> newState)` 与决定性 VRP 证据。验收用暴力全表重算逐路由对照全部单条查询与批量 TA 撤回增量差异，覆盖长度超 `maxLen` 判 `Invalid`、同时存在 `AS 0` 与合法 ASN 判 `Valid`、撤销唯一合法 VRP 后有更宽父 VRP 覆盖导致从 `Valid` 跌为 `Invalid`（而非 `NotFound`！），以及 IPv6 `/128` 与 `/0` 边界。
