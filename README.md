# 索引重建工具（indexrebuild）

旧索引继续对外服务，新索引从一致性快照构建后追赶增量，满足切换条件后原子接管。

## 核心机制

- **版本化事件流**：`EventLog` 为每条变更分配全局连续版本号（`event.go`）。
- **每键版本消重**：`Index.Apply` 只接受版本严格更大的事件；删除留墓碑，迟到的旧 PUT 无法复活已删键；重发事件按版本全局去重（`index.go`）。
- **连续水位**：`watermark` 是已应用版本的最大连续前缀，乱序事件先落袋、缺口补齐后水位跳升；`MissingUpto` 给出未确认版本清单。
- **切换条件**（`Coordinator.TrySwitch`，`rebuild.go`）：
  1. 新索引水位追到冻结版本，且冻结前所有未确认变更已处理（无缺口）；
  2. 新索引与源库全量扫描参考数据完全一致（缺键/多键/值不符/版本落后均拒绝）。
  任一条件不满足则拒绝切换，旧索引继续服务。

## 运行

```sh
go run .        # 5 个场景演示，输出新旧索引水位证据
go test ./...   # 单元测试：消重、墓碑、水位缺口、删除/补录、切换成功与失败
```

场景覆盖：正常切换（乱序+重发）、构建中删除、补录、事件丢失导致切换失败、参考校验不一致导致切换失败。
