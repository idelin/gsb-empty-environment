# lockplan — 锁文件更新规划器

新增依赖时精确求解锁文件更新：**第一优先级尽量保留原版本，第二优先级减少下载字节**。
输出每个被迫变化的原因路径，并删除已无根依赖的包（垃圾回收）。

## 模型

- `registry.json`：包注册表。每个版本有若干下载来源（镜像），来源有字节数与可用性；
  同一 `(name, version)` 可出现多次（同版本不同来源），加载时自动合并。
- `lock.json`：根需求 + 已固定条目 `(name, version, source)`。
- 代价（字典序）：`变更包数`（版本与锁不同或新增的包；仅切源不计入）→ `下载字节`
  （版本未变且锁定来源可用则为 0，否则为所选来源的字节数）。

## 用法

```sh
go run ./cmd/lockplan -registry examples/registry.json -lock examples/lock.json \
    -add 'auth@^1.0.0' -verify
```

- `-add name@constraint`：新增根依赖（可重复）。约束支持 `*`、`= != > >= < <=`、`^`、`~` 及组合（`>=1.0 <2.0`）。
- `-verify`：用独立实现的穷举法核验本次求解的最优性（仅适合小规模）。
- `-json`：以 JSON 输出计划。

## 精确求解

`internal/plan/solver.go`：分支限界。状态为「每包一个版本」的部分赋值，
从根需求出发按需扩展必需包集合（天然支持依赖环，不会递归发散）；
MRV 选包、锁定版本优先排序，下界剪枝（未赋值的新包/原版本已不可行的包至少各计 1 次变更）。
来源选择在版本确定后相互独立，直接取最优（锁定来源可用则 0 字节，否则最小可用来源），
因此搜索空间只需覆盖版本。完备且终止，故结果为全局最优。

## 原因路径

`internal/plan/plan.go`：对每个变更给出从根出发的引入路径与被迫原因——

- 旧版本违反新解中某条入边约束 → 指出约束与路径；
- 旧版本已被注册表移除 / 所有来源下线；
- 探测求解（固定旧版本）无解 → 指出与解冲突的传递依赖；
- 探测可行但代价更高 → 列出保留旧版本将额外被迫变化的包；
- 移除：在旧锁图中定位从根到它的路径断点（父包改版后不再依赖，或父包本身被移除）。

## 核验

- `internal/plan/brute.go`：独立实现的朴素穷举器，枚举全部可行解取最优代价。
- `internal/plan/fuzz_test.go`：随机生成小规模实例（含依赖环、同版本多来源、
  来源下线、版本下架），逐实例断言 `Solve` 与穷举的最优代价一致、解合法
  （根满足、全部依赖约束满足、解恰为根可达闭包）、结果确定。
- `internal/plan/solver_test.go` / `plan_test.go`：环、多来源、级联更新、
  孤儿移除、字节决胜、全局最优击败贪心等定向用例。
