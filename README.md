# 缓存执行计划越过已撤销权限

数据库连接池复用已编译计划时，计划若只绑定SQL文本，不绑定主体与策略版本，撤权后的会话仍可能读取旧表。给Go数据库宿主实现可导入的安全计划缓存模型：编译输入含规范查询AST摘要及参数类型列表摘要及参数类型列表、调用主体ID、角色闭包摘要、每个引用对象的objectID与schemaVersion、所需操作、行级策略摘要及全局policyEpoch；输出计划包含相同依赖清单和不可变执行算子。参数值不进入计划身份但执行时仍走结构化绑定；参数值不进入计划身份但执行时仍走结构化绑定；缓存键须覆盖全部输入，命中后执行前再核对主体仍活跃、角色闭包和policyEpoch未变、每个对象ID/版本与权限仍满足，任一变化视为未命中并重新编译，不能沿用旧允许决定。事务固定一个权限快照，但显式REVOKE带immediate标记时使正在等待执行的计划失败；无immediate的撤权只影响下一事务。连接切换主体必须清空会话局部计划句柄，GLOBAL缓存项仍可由新主体按自身键使用。实现待审cacheKey回调的有限差分搜索，从主体、角色、对象版本、RLS摘要和epoch各两个值中找弱键相同而正确授权结果不同的最短例。用可观察执行回调测试撤权、DROP后同名重建、RLS收紧、连接池换用户和事务边界，未通过复核的计划零算子执行。
