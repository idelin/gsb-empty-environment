集群水平弹性伸缩器（HPA）同时消费 CPU 利用率、自定义每 Pod 指标和外部指标，若在扩容启动期把尚未就绪 Pod 的零负载算进均值，会立刻触发误缩容震荡。为弹性控制器交付可导入的 Go 决策包。输入最小/最大副本数、容忍死区 tolerance、初始化就绪延迟、各指标目标规格、扩容/缩容稳定窗长度及多条步进速率策略（百分比与绝对值双限制，选最大或最小变更策略），以及按秒推进的快照事件（当前副本数、各 Pod 就绪状态/启动时刻/各指标采样或缺失）。规则：对资源指标按 Kubernetes 语义区分扩容与缩容处理未就绪及缺样本 Pod（避免误扩与误缩，并检查忽略这些 Pod 后方向是否反转则保持现状）；比率落入 `[1-tol, 1+tol]` 死区维持原副本数；多指标取最大期望副本数；再分别在扩/缩容稳定窗内按滑动极值（缩容取窗内历史建议最大值、扩容取最小值）过滤，最后叠加周期速率上限与 [min,max] 截断。组件每步输出精确目标副本数、被采用的主导指标与限速原因。验收用时序事件流对照规范逐式计算，覆盖未就绪 Pod 方向反转保平、容忍死区边界、缩容稳定窗锁存防抖，以及百分比与绝对值策略取大/取小交互。
