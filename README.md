# fdtool — 函数依赖规范化工具

计算函数依赖（FD）集的**正则覆盖**（canonical / minimal cover），并为每一次删除给出推导证据；同时提供属性闭包与 FD 集等价核验。

## 构建与测试

```sh
go build ./cmd/fdtool
go test ./...
```

## 用法

```sh
fdtool canonical [-f file]      # 正则覆盖 + 完整规范化日志（含推导证据）
fdtool closure   [-f file] A,B  # 属性闭包 + 推导轨迹
fdtool equiv     fileA fileB    # 两个 FD 集是否等价（互相覆盖）
```

输入每行（或 `;` 分隔）一条依赖：`AB -> C`、`A,B -> CD`、`{} -> A`（空左侧，也接受 `∅`/`-> A`）。无分隔符时每个字符视为一个属性。

## 规范化流程（固定消除顺序，输出稳定）

1. **拆分右侧**：所有 RHS 拆成单属性，去重后按 (LHS 长度, LHS 字典序, RHS) 排序，固定后续处理顺序。
2. **去除多余左属性**：按固定顺序检查每个 FD 的每个左属性 `a`；若 `RHS ∈ (LHS\{a})⁺`（在当前 FD 集下），则 `a` 多余，删除并记录闭包推导轨迹作为证据。左约简可能产生完全相同的依赖，先去重再进入下一步，避免冗余证据"自证"。
3. **去除冗余依赖**：按固定顺序，若 `RHS ∈ LHS⁺`（在**其余** FD 下），则该 FD 冗余，删除并记录推导证据。

证据语义：删除 `f` 的轨迹展示当前 FD 集推导出被约简/被删依赖的完整过程（每步标注所应用的 FD 与闭包变化），即 `F ⊢ f'`；反向由增广律/分解律显然成立，故替换保持等价。

## 边界情形

- **空左侧**：`{} -> A` 表示 `A` 恒成立；闭包、左约简（LHS 可约简为空）、冗余判定均支持。
- **循环依赖**：`A->B, B->A` 互为支撑，二者都保留；环上的冗余边（如同时存在 `A->C, B->C`）会被识别并删除其一。

## 等价核验

`F ≡ G` 当且仅当互相覆盖：对 G 中每条依赖在 F 下求闭包（反之亦然）。每条被验证的依赖都附推导轨迹；不等价时列出两个方向上不可推导的依赖。
