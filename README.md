# Forensics Acceptance Planner（取证规划器）

按布尔表达式检查验收条目，在证据成本、有效期与互斥执行条件的约束下，
求覆盖**全部**验收条目的最低成本取证计划（默认最多 25 项证据）。

## 构建与运行

```sh
go build -o forensics .
./forensics -spec examples/case.json            # 文本报告
./forensics -spec examples/case.json -json      # 机器可读 JSON
./forensics -spec examples/case.json -asof 2026-12-01
go test ./...
```

无可行计划时进程以退出码 1 结束，并逐条给出未满足原因。

## 输入规格（JSON）

```json
{
  "asOf": "2026-10-04",          // 计划日期；过期/未生效证据一律不计入
  "maxEvidence": 25,             // 证据数量上限，缺省 25
  "evidence": [
    {
      "id": "E1",
      "cost": 120,
      "validFrom": "2026-01-01",  // 可缺省
      "validUntil": "2027-03-31", // 可缺省（缺省=永不过期）
      "mutexWith": ["E2"],        // 两两互斥（自动对称）
      "group": "disk-image"       // 同组证据至多选一项
    }
  ],
  "criteria": [
    {"id": "AC1", "expr": "(E1 AND E3) OR (E4 AND NOT E5)"}
  ]
}
```

表达式支持 `AND / OR / NOT`（大小写不敏感）、`&& || !` 与括号，
优先级 `NOT > AND > OR`。

## 输出

- 可行：总成本、待采集证据清单（含成本与有效期）、每条验收的
  **满足路径**（选中的合取项 + 整棵表达式树的 ✓/✗ 追踪）。
- 不可行：每条验收的未满足原因，区分——
  - 表达式自相矛盾（如 `E1 AND NOT E1`）；
  - 所有路径都依赖已过期/未生效证据；
  - 所有路径内部互斥（需要同时采集互斥证据）；
  - 单独可满足，但与其他条目的需求冲突（互斥 / NOT / 数量上限）。

## 正确性要点

- **任一 ≠ 全部**：`AND` 要求每个子表达式满足，`OR` 只要求至少一个；
  求值器保留完整追踪树，报告不会把“任一满足”误报为“全部满足”。
- **过期不计入**：`asOf` 不在 `[validFrom, validUntil]` 内的证据从解空间中
  整体剔除，绝不进入计划，也不会出现在满足路径里。
- **互斥**：`mutexWith` 与 `group` 统一归并为两两互斥约束，在同一表达式
  路径内部与跨验收条目之间同时生效。
- **NOT 约束**：`NOT E` 表示计划中不得采集 `E`，与其他条目的需求冲突时
  判定为不可行。

## 算法

1. 表达式解析为 AST，经 De Morgan 下推否定（NNF）后展开为 DNF，
   每个合取项即一条候选满足路径（含必采集 `Require` 与禁止集 `Forbid`）。
2. 剔除依赖过期证据或内部互斥的路径，按成本升序排列。
3. 在“每条验收选一条路径”的组合空间上做分支限界搜索：共享证据只计一次
   成本，实时检查互斥、NOT 冲突与 25 项上限，找到全局最低成本计划。
