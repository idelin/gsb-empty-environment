# blockgc — 共享内容块存储的标记-清扫回收器

针对"根清单可更新、读者仍持有旧根"的共享内容寻址块存储，实现安全的标记-清扫垃圾回收。

## 组件

- `store.go` — 内容寻址块存储。块不可变；删除前先进入**隔离区**（quarantine），
  隔离期间仍可读、可恢复，确认后才物理删除。`Delete` 只删仍处于隔离态的块，
  过期删除列表不会误杀已复活的块。
- `manifest.go` — 可更新的根清单。`Publish`/`Revoke` 管理命名根；读者用
  `Pin`/`Unpin` 持有旧视图。**活动根 = 未撤销的根 ∪ 所有 pin 快照**，
  版本计数器用于检测扫描期间的变更。
- `collector.go` — 回收器。阶段：快照 → 标记 → 屏障（重读清单直到根集稳定，
  吸收扫描期间发布的新根与新建块）→ 清扫入隔离区 → 独立校验 → 写**确认记录** →
  物理删除。存储侧写屏障：回收期间新分配的块视为临时根；引用到隔离块时将其
  **传递性复活**。
- `journal.go` — 崩溃恢复日志（内存 / 文件两种实现，文件原子 rename 写入）。
  未确认的隔离在恢复时回滚（复活）；已确认的删除在恢复时继续完成。
- `verify.go` — 独立校验器：删除确认前，从**当前所有活动根**重新遍历，
  任何可达块落在隔离区中即中止并整体恢复。

## 安全性要点

- 扫描期间发布新根：屏障循环重读清单 + 版本号，新根被补充标记。
- 扫描后新增引用：写屏障复活 + 隔离区宽限 + 校验中止，三重保护。
- 崩溃恢复：隔离列表先落日志再执行；确认记录先于物理删除。任意时刻
  崩溃后 `Resume()` 都能收敛到一致状态。
- 环状/坏引用：遍历用 visited 集合，悬空引用被容忍。

## 测试

```sh
go test ./... -count=1 -race
```

覆盖：共享块、环状与悬空引用、根撤销与读者 pin、扫描中发布新根、
扫描后新增引用（中止并恢复）、确认前/后崩溃恢复、文件日志恢复、
并发发布与回收的竞争不变量。
