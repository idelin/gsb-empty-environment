# rootslot — 双槽原子根指针发布

通过**两个带序号和校验和的元数据槽**原子发布根指针。读时校验每个槽，
选择序号最大的完整槽；任何损坏槽一律视为无效，**绝不猜测其内容**。
仅使用 Go 标准库。

## 槽格式（每槽固定 512 字节）

```
[0,8)     magic "RTSLT001"
[8,16)    seq        uint64 大端，单调递增，从 1 开始；全零槽 = 从未写入
[16,20)   payloadLen uint32 大端
[20,32)   reserved（必须全零）
[32,480)  payload（根描述符，对存储层 opaque，最长 448 字节）
[480,512) sha256 校验和，覆盖前 480 字节
```

## 发布与恢复协议

- **提交**：验证器先独立检查新根的可达闭包（根页及所有可达页完整可读），
  失败则不发布；然后序号 +1，把新槽**一次性**写入备用槽并 `Sync`。
- **打开**：两槽都损坏 → 拒绝打开（`ErrBothSlotsCorrupt`）；
  一槽有效 → 用有效槽；两槽都有效 → 取序号大者；
  序号相同内容不同 → 报冲突（`ErrSlotConflict`）；
  序号相同内容相同 → 幂等发布，合法。
- **序号环绕策略**：序号耗尽（达到 2^64-1）即拒绝提交
  （`ErrSequenceExhausted`），**绝不回绕**到 0。
- **旧槽重放检测**：提交前读目标槽，若已持有 ≥ 本次序号的有效记录，
  判定重放并拒绝（`ErrReplayDetected`）。
- **序号空洞诊断**：两槽序号差 ≠ 1 说明中间有提交丢失，记入
  `Diagnostics()`（不拒绝打开）。

## 依赖的原子写与同步假设

1. 单次 `WriteAt` 落盘的内容可以是任意前缀（撕裂），但不会出现
   字节级“新旧混杂”以外的伪造数据——完整性由 sha256 校验和保证，
   因此**不依赖硬件原子写**；校验和失败的槽一律丢弃。
2. `Sync` 返回后，之前所有已写字节持久（fsync 语义）；`Sync` 返回前
   崩溃，恢复结果只能是**旧根或新根**，不会是中间态。
3. 已同步字节不会被后续故障重排或篡改（位腐烂不在本模型内，
   但会被校验和检出并判为槽损坏）。

## 进程崩溃 vs 断电的保证边界

模拟器（`SimBackend`）明确区分三种字节状态：

| 状态 | 含义 | 进程崩溃后 | 断电后 |
|---|---|---|---|
| 已写 (written) | `WriteAt` 生效，进程可读 | 保留（OS 页缓存） | 丢失 |
| 已同步 (synced) | `Sync` 刷入 durable | 保留 | 保留 |
| 可恢复 (recoverable) | 崩溃后重开可见的字节 | 已写 ∪ 已同步 | 仅已同步 |

- **进程崩溃**：已写未同步的字节仍可见，可能恢复到更新的根。
- **断电**：只有 `Sync` 成功前的提交保证可恢复；保证恢复出
  旧根或新根二者之一的**完整**版本。

## 故障注入

`SimBackend` 支持按写/同步序号注入：撕裂（`TornAt`）、丢失
（`DropAt`）、重排到下次 Sync 之后（`DelayAt`）、同步丢失
（`SyncNoopAt`）。测试枚举了槽写全部 513 个字节边界的撕裂，
以及 1..5 次连续提交 × 5 类故障 × 每个注入点的组合。

## 文件位置

真实后端在调用方指定目录下创建 `root.slots`（2×512 字节）：
`rootslot.Open(dir, validator)`。

## 运行样例

```
$ go run ./cmd/demo
== 真实目录 /tmp/rootslot-demo 提交并崩溃重开 ==
committed root page 2 (seq=1)
committed root page 3 (seq=2)
committed root page 1 (seq=3)
reopened: seq=3, verify closure: <nil>
== 注入故障：新槽撕裂写，断电后恢复旧根 ==
recovered root: "root-old" (diagnostics: [slot 1 is corrupt; ignored (never guessed)])
== 两槽都损坏：拒绝打开 ==
open with both slots corrupt: rootslot: both metadata slots are corrupt
```

枚举、进程崩溃与断电边界。
