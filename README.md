带认证加密的固定帧调度器准备增加持久恢复：掉线时可能不知道最后一帧是否已经发送。请为 Go 隔离执行宿主写可导入的恢复策略包。公开观察包含线路、时隙、帧长、重连请求及关闭结果；恢复选择只能依赖共同公开历史，不得由秘密任务的完成与否决定。每次实际密封绑定密钥代次、公开计划、槽号和事务摘要，结果不明时只能取回同一已密封帧，不得以同一 nonce 密封另一内容。宿主提供不完整持久回执和多个可能线路后继。判定是否存在在所有相容发送历史中均可完成的公开恢复策略，若有则最小化最坏额外帧数，并提供独立证书。小模型枚举丢确认、同槽换线、查到旧密文、秘密任务提前结束与两个隐藏状态分别有策略却没有共同首步的情况。

## 包说明

`recovery` 包(`prescreen.local/ddd-9705-v3/recovery`)提供:

- `Observation`:公开观察(线路、时隙、帧长、重连请求、关闭结果);策略是信念(公开历史等价类)到动作的映射,结构上无法依赖秘密任务状态。
- `Solve` / `Verify`:在信念空间上求解最小-最大可达博弈,判定公开恢复策略是否存在、最小化最坏额外帧数,并产出可独立校验的证书(可行时为取值函数+策略,不可行时为对抗陷阱)。
- `FrameStore` / `SealRequest` / `NewGCMBinder`:密封纪律——绑定密钥代次、公开计划、槽号、事务摘要;结果不明时幂等取回同一已密封帧,同一 nonce 密封另一内容返回 `ErrNonceReuse`。
- `Scenarios` / `HostModel`:枚举丢确认、同槽换线、查到旧密文、秘密任务提前结束、无共同首步五个小模型,以及不完整回执+多线路后继的组合宿主模型。
