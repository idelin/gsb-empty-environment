# 依赖哈希算法迁移

包仓库从旧摘要升级到新摘要时，同一旧摘要对应的冲突对象不能被合并。写供Go存储宿主调用的双摘要迁移组件，旧索引映射到候选集合，只有重读内容并核对两种摘要后才能建立新身份；迁移和读取并发，旧摘要歧义必须显式返回。用注入碰撞函数与逐点故障测试迁移恢复及引用计数守恒。

## 组件

- `migrator.go`：`Migrator` 双摘要迁移核心。
  - `Store` 是存储宿主接口：`Candidates` 返回旧摘要下的候选集合，`LookupNew`/`PutNew` 管理新身份，`RangeOld` 遍历旧索引。
  - `Resolve(oldDigest)` 重读每个候选内容，先核对旧摘要再计算新摘要；同一新身份的引用计数聚合后一次性落库，旧索引与新索引引用总数守恒。
  - 旧摘要对应多个不同对象时返回 `*AmbiguityError`（携带全部候选新身份），宿主必须向读取方显式报错，禁止猜测或合并。
  - 内容与旧摘要不符、或新摘要碰撞到不同内容时返回 `*IntegrityError`，不建立任何身份。
  - 每个旧摘要一把门闩锁：同键的迁移与读取串行化，不同键可并行；首次解析即迁移，重复调用幂等。
  - `MigrateAll` 遍历全量旧索引，逐键收集歧义与故障（`errors.Join`），不中断其余键的迁移。
- `store_memory.go`：`MemoryStore` 内存参考实现，含逐键锁、防别名拷贝、引用计数快照（`SnapshotRefs`）供宿主审计与测试。

## 故障模型与恢复

- 迁移进度以新索引是否落库为准，不依赖内存标记；`Candidates`/`LookupNew`/`PutNew` 任一点失败后，下一次 `Resolve` 干净重试，失败的迁移不产生部分身份。
- `migrator_test.go` 中的 `FaultStore` 可按方法与调用序号注入故障，`collisionHash` 可注入旧摘要碰撞。
- 测试覆盖：单键幂等迁移、碰撞歧义显式返回、重复候选引用聚合、逐点故障恢复、旧摘要篡改与新摘要碰撞的完整性错误、16 worker 并发迁移/读取（`-race`）、同键竞争只落库一次、全量迁移与引用计数守恒（语句覆盖率 98.8%）。

## 运行

```sh
go test -race -count=1 ./...
go vet ./...
```
