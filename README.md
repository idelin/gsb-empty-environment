# 协议部分有序轨迹等价

两个安全实现只改变独立消息的处理次序，差分测试不应误报。实现供Go验证宿主调用的轨迹比较包，事件有主体、读写对象与发送接收因果边，仅无冲突且无因果关系事件可交换；判断两条有限轨迹是否等价并输出交换证书，失败定位必要顺序差异。用短轨迹全排列验证，秘密状态写入也计冲突。

## 模型

- `Event`：主体（`Subject`）执行的一步，携带对若干对象的 `Read`/`Write` 访问；`Access.Secret` 标记秘密状态。
- `Edge`：发送/接收因果边 `From -> To`。
- `Trace`：有限事件序列（执行次序）加因果边集合。

两个事件**可交换（独立）**当且仅当同时满足：

1. 主体不同（同一主体的程序序不可重排）；
2. 无对象冲突：不存在同一对象被双方访问且至少一方写入——秘密状态写入与普通写入同样计冲突，纯读不冲突；
3. 无因果关系：由同主体程序序和发送/接收边求传递闭包得到的 happens-before 两个方向都不成立。

两条轨迹**等价**当且仅当事件集合、主体、访问与因果边结构一致，并且所有冲突对与 happens-before 对的相对次序一致（Mazurkiewicz 轨迹等价）。

## API

- `Compare(a, b Trace) (*Report, error)`：返回 `Equivalent`；等价时附带交换证书，不等价时在 `Violations` 中定位必要顺序差异，因果类差异附带 happens-before 见证链。
- `Independent(t Trace, a, b EventID) (IndependenceCheck, error)`：单次独立性判定，给出冲突与双向 happens-before 依据。
- `Verify(t Trace, cert *Certificate) error`：逐步回放证书，校验每次相邻交换确实独立。

证书 `Certificate.Swaps` 记录每一步相邻交换的位置、两个事件及 `IndependenceCheck` 证据；回放后应到达目标次序。

## 验证

`go test ./...` 使用短轨迹全排列交叉验证：

- 5 事件稠密规格（120 个排列）与 6 事件稀疏规格（720 个排列）分别枚举；
- 用相邻独立交换做 BFS 独立计算 Mazurkiewicz 可达类，与 `Compare` 的判定逐一核对，并校验自反、对称、传递性；
- 等价排列的证书逐交换回放并核对最终次序，稀疏规格覆盖最长 4 步交换；
- 针对秘密写/写、秘密读/写冲突、纯读可交换、因果反转与传递见证链、同主体不可交换、结构差异及非法输入均有专项用例。
