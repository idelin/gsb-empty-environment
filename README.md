实现 RFC 9113 HTTP/2 帧协议状态机时，最容易导致互操作故障或安全漏洞的四类规范细节都集中在跨流与连接级耦合状态上：`HEADERS`/`PUSH_PROMISE` 若未置 `END_HEADERS`，在收到完整 `CONTINUATION` 序列之前连接上出现任意其他帧（哪怕是 `PING`、`SETTINGS` 或其他流的 `RST_STREAM`！）都必须立刻抛出连接级 `PROTOCOL_ERROR`；对端更新 `SETTINGS_INITIAL_WINDOW_SIZE` 时，必须对所有处于 `open` 或 `half-closed (remote)` 的既有流按差值调整发送窗口——窗口可以合法变为负数（此时暂停发送 `DATA`），但绝不可超过 `2^31 - 1`（溢出必须报 `FLOW_CONTROL_ERROR`），且连接级发送窗口不受该设置影响！同时，流 ID 必须按客户端奇数/服务端偶数严格递增，在已关闭流或空闲流上收到帧的错误级别（流错误 vs 连接错误）因帧类型而异。为反向代理与传输网关交付可导入的 Go RFC 9113 HTTP/2 连接与流状态机核（不含明文 HPACK 解压，输入为结构化帧头与字段块片段）。规则：1）完整实现 7 种流状态（`idle`/`reserved(local)`/`reserved(remote)`/`open`/`half-closed(local)`/`half-closed(remote)`/`closed`）的合法迁移与奇偶流 ID 单调递增校验（新建流隐式关闭所有更小编号的同方向 `idle` 流！）；2）强制 `HEADERS`/`CONTINUATION` 原子头块序列校验，并校验 `END_STREAM` 后禁止再收 `DATA`/`HEADERS`（保留对刚发送 `RST_STREAM` 后的在途窗口容忍语义区分）；3）维护连接级与每流独立双向流控窗口，支持 `WINDOW_UPDATE` 零增量 `PROTOCOL_ERROR`、超过 `2^31-1` 的 `FLOW_CONTROL_ERROR` 及 `SETTINGS_INITIAL_WINDOW_SIZE` 差值同步调窗（含合法负窗口冻结与后续 `WINDOW_UPDATE` 恢复发送！）；4）完整实现 `GOAWAY(lastStreamID)` 优雅排空——后续 `GOAWAY` 的 `lastStreamID` 只允许递减（增大报 `PROTOCOL_ERROR`），拒绝所有 `id > lastStreamID` 的新流同时允许 `id <= lastStreamID` 的在途流正常完成至关闭。验收覆盖 `CONTINUATION` 中间插入 `PING` 触发连接错误、`SETTINGS_INITIAL_WINDOW_SIZE` 调小产生负窗口再由 `WINDOW_UPDATE` 恢复、窗口溢出 `2^31-1`、隐式关闭更小 `idle` 流、流级与连接级错误精确分级以及多轮 `GOAWAY` 截断排空。
