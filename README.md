# logtrunc

分段日志的安全截断规划与执行工具（Go，仅标准库）。

## 截断判定

一个段可删除，当且仅当：

1. **所有已注册消费者的连续确认前缀都覆盖整个段。** 消费者逐条确认记录，
   水位线只在无缺口前缀上推进——确认到最大序号 5 但缺 3，水位仍是 3，
   缺口不会被最大序号掩盖。水位回退（ack rollback）会被拒绝。
2. **没有任何存活快照钉住该段。** 旧快照可能依赖历史段，过期移除后才解除阻塞。

消费者退出即注销，其确认不再构成约束；没有任何消费者时，消费侧无依赖，
仅快照能保留段。

`Planner.Plan()` 返回可删段列表，以及每个保留段的**最小阻挡证据**（恰好一个
确定性的阻塞原因：ID 最小的钉住快照，或水位最低的消费者）。`AllBlockers`
返回完整阻塞集合用于诊断。

## 执行与恢复

`Executor` 先把截断请求写入 `Store` 的追加式 JSON 日志（fsync 持久化），再尝试
删除；删除失败请求保持 pending，`ProcessPending` 可反复重试。崩溃后重新
`OpenStore` 即重放日志恢复全部未完成请求，不会丢失。`Deleter` 必须幂等。

## 正确性校验

`Reference` 是逐条记录的依赖集合模型：每条记录的依赖集 = 未覆盖它的消费者
∪ 钉住它所在段的快照，依赖集为空才可删。`property_test.go` 用随机操作序列
（追加段、逐条/批量确认、回退尝试、消费者加入/退出、快照增删、执行截断）
逐步比对规划器与参考模型的可删集合、水位线及阻挡证据。
