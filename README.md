# 边缘缓存屏障模拟器

模拟边缘缓存的一致性语义：配置更新后，节点**允许继续读旧值**，直到指定**屏障（barrier）**发布；此后只能读新版本，否则**等待**数据到达。失效消息可以先于数据到达，消息也可能乱序。

## 架构

```
OriginStore ──publish──> MessageBus ──deliver/replay──> CacheNode
     │                                                    │
     └────────────── fetch(key, minVersion) <─────────────┘
```

- `src/origin.ts` — 配置源站。`update` 先提交并广播失效消息，`replicate` 之后数据才对节点可见（因此失效先于数据）。`fetch(key, minVersion)` 在可见版本不足时挂起等待。
- `src/bus.ts` — 消息总线。保留完整消息日志（全局序号）；支持暂停/乱序投递（`deliverNext`）、断线重连按序号重放、新节点加入时补发全部历史（快照同步）。
- `src/node.ts` — 缓存节点，每个 key 一台状态机。

## 状态机（每个 key）

| 状态 | 含义 | 读行为 |
| --- | --- | --- |
| `EMPTY` | 无缓存、无屏障 | 加载任意版本 |
| `CLEAN` | 缓存版本 ≥ 屏障，无更新失效 | 缓存直接返回 |
| `STALE_ALLOWED` | 收到失效但屏障未覆盖旧值 | 继续返回旧值 |
| `BARRIER_WAIT` | 缓存缺失或版本 < 屏障 | 只能读 ≥ 屏障的新版本，否则等待 |

关键不变式：

- `barrier` 与 `invalidatedTo` **单调递增** —— 迟到/乱序的旧消息不会使状态回退（连续两次更新、旧屏障迟到都不会绕过屏障）。
- 加载完成时若结果版本 < 当前屏障（**迟到的旧加载**），直接丢弃并按最新屏障重试，绝不写入缓存或返回给调用方。

## 运行测试

需要 Node ≥ 22.6（依赖原生 TypeScript 类型擦除；Node 23.6+ 默认开启）：

```sh
node --test
```

本机默认 Node 为 16，可使用：

```sh
~/.nvm/versions/node/v23.9.0/bin/node --test
```

## 测试覆盖（`tests/simulator.test.ts`）

- 屏障发布前允许继续读旧值；
- 屏障发布后只能读新版本或等待（失效先于数据到达）；
- **旧加载迟到**：在途加载带着旧值返回时被丢弃，不写入缓存、不返回；
- **节点重连**：断线期间的失效与屏障按序号重放，重连后不得读旧值；新加入节点同样受屏障约束；
- **连续两次更新**：迟到的旧屏障不回退状态，满足旧屏障的 v1 不可返回；屏障先于失效乱序到达仍正确等待 v3。
