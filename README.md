# 链路状态同步模拟器

TypeScript 实现的链路状态路由协议同步过程模拟，覆盖：

- **跳过过期更新**：版本为 `(代次 generation, 序号 sequence)` 字典序；仅接受严格更新的同源 LSA，被新版本覆盖的旧更新直接跳过（`Node.handleUpdate`，src/node.ts）。
- **删除后重建用新代次**：撤销（withdraw）在同代次内序号 +1；删除后重新通告时代次 +1、序号归零（`Node.originate`），避免与网络中残留的旧代次副本混淆。
- **摘要交换 + 缺失补齐**：邻居间交换逐来源版本向量（`summary`），对方向量中更新/本地缺失的来源精确发起 `request`，同时把本地更新的 LSA 主动 `update` 给对方（`Node.handleSummary`）。
- **逐来源进度**：摘要和补齐都按 origin 的版本向量计算，不使用全局最大版本代表各来源进度（见单元测试 T4）。
- **分区重连一致性**：模拟器支持链路 up/down、开销变更、节点撤销/重建；重连后通过泛洪 + 周期性摘要交换收敛，最终逐节点核对 LSDB 与拓扑完全一致。

## 运行

```sh
npm run run      # 编译并运行（等价于 tsc -p tsconfig.json && node dist/main.js）
```

## 场景

6 个节点、两个三角形集群（A/B/C 与 D/E/F）加桥接链路 C-D：

1. 初始收敛，核对 6 节点 LSDB 一致；
2. 断开 C-D 形成分区，两侧 LSDB 出现分歧；
3. 分区内变更：A-B 开销改为 5；向 B 注入被覆盖的旧版 A LSA（须被跳过）；D 撤销后重建（须出现新代次 D@1.0）；
4. 恢复 C-D，触发摘要交换与缺失补齐（日志可见按来源精确请求，如 `D -> C 请求 [A, B]`）；
5. 核对所有节点 LSDB、拓扑一致，并与期望拓扑（含新开销、D 新代次）比对。

## 结构

- `src/types.ts` — 版本、LSA、消息类型与版本比较
- `src/node.ts` — 节点：LSDB、生成/撤销、泛洪、摘要/请求/更新处理
- `src/simulator.ts` — 网络：链路状态、消息投递、分区/重连、收敛循环
- `src/topology.ts` — LSDB 规范化与拓扑推导
- `src/main.ts` — 单元测试（T1–T4）+ 分区重连场景与一致性核对
