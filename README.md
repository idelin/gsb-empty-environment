# memsched — 协程内存配额与垃圾回收协作调度器

纯 Go 标准库实现（兼容 Go 1.11+），无第三方依赖。

## 组件

- **`Monitor`（内存监控器，`monitor.go`）**
  统计每个 Fiber 执行过程中申请的临时对象大小（`perFiber` 记账），
  维护全局容量、80% 高水位 / 60% 低水位，内存变化时回调调度器。
  记账绝不超发：`used` 永不超过 `capacity`，超额申请会阻塞等待释放。

- **`Fiber`（协程抽象，`fiber.go`）**
  `Alloc`/`Release` 按协程记账；`GC()` 回收该协程全部临时内存。
  准入时调度器按 `Task.MemDemand` 为 Fiber 预留额度（credit），
  Fiber 实际申请时先抵扣预留，保证准入控制不被记账滞后绕过。

- **`Scheduler`（调度器，`scheduler.go`）**
  - 正常使用量 < 80%：FIFO 准入，预留内存后运行。
  - 使用量 ≥ 80%（反压）：**拦截新协程创建**（排队不丢弃），
    只优先调度具有 GC 回收能力的协程。
  - 使用量回落 ≤ 60%：通过令牌桶**平滑恢复接单**，
    令牌按时间补充、桶容量指数爬坡，避免恢复瞬间流量洪峰。

## 运行样例

```sh
go run ./cmd/demo
```

注入 100 个批处理任务（80 个普通任务各申请 40 单位内存，20 个 GC 任务），
实时打印内存水位与 BACKPRESSURE 状态，最后输出统计。

## 测试

```sh
go test -v ./...
go test -race ./...
```

验收测试 `TestBackpressureAcceptance` 注入 100 个批处理任务并断言：

- 达到 80% 阈值时反压触发（`PressureEpisodes > 0`、`BlockedEvents > 0`）；
- 反压期间没有任何非 GC 协程被准入（`Violations == 0`）；
- GC 协程在反压期间被优先调度；
- 存量协程释放内存后准入平滑恢复，100 个任务全部完成；
- 峰值内存不超过容量，结束后无内存泄漏（`Used() == 0`）。
