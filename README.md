# Cap'n Proto远指针遍历守卫

Cap'n Proto消息的远指针可把结构指向其他段，攻击者构造双重远指针、越界段号或让多个指针反复指向同一块来放大遍历。给C++写供消息读取线程调用的指针遍历守卫：落脚区须在目标段内，双重远指针的第二个须是结构指针，段号越界拒绝，遍历预算按已读字数累计，零大小结构和Void列表也计费。用越界段号、自环和重复引用验证。

## 设计

`netsec::MessagePointerGuard` 在读取一条消息期间做 DFS 指针遍历，段表本身只读可跨线程共享，
但预算与祖先栈是每线程私有状态——每个读取线程持有自己的 guard，互不加锁。

守卫规则（对应需求）：

- 落脚区校验：结构/列表/远指针落脚 pad 都用 `segmentInBounds` 校验完全落在目标段内，
  越界返回 `kLandingOutOfBounds`。
- 段号越界：远指针（含双重远指针内层远指针）命名的段号超出段表即 `kSegmentIdOutOfBounds`。
- 双重远指针：第一个落脚词必须仍是远指针，第二个必须是结构指针，否则 `kDoubleFarNotStruct`；
  内层远指针先递归解析，使其段号越界能被优先报告。
- 遍历预算：`charge` 按已读 64 位字数累计，溢出安全；任何对象/落脚至少计费 1 个字，
  因此零大小结构与 Void 列表（`ElementSize::kEmpty`）也无法免费放大遍历。
- 环检测：用祖先区间栈判断落脚区是否与仍在遍历的对象重叠，自环/互环返回 `kCycleDetected`；
  已离开的共享 DAG 节点允许再次到达，但每次重新计费。
- 深度上限：嵌套指针与远指针跳转共用 `maxNestingDepth`，远指针自环由该上限截断。
- 能力（interface）指针不可跟随，返回 `kCapabilityUnsupported`。

## 验证

`test_guard.cpp` 用原生 `uint64_t` 段手工构造线格式消息，覆盖题目指定场景及附加规则：

- 越界段号（单远指针、双重远指针内层）
- 自环（结构指针回指自身、远指针指向自己）
- 重复引用（两指针指向同一结构，验证逐次计费与预算拦截、DAG 共享节点）
- 零大小结构与 Void 列表最小计费
- 双重远指针标签非结构、合法双重远指针计费
- 复合列表标签谎报元素数导致越界、能力指针拒绝
