# 恶意文件多别名隔离

终端防护发现恶意文件后，只移动一个名字会留下其他硬链接入口。写供Go文件宿主调用的隔离事务包，输入完整目录引用图及目标对象代次，先安装按对象拒绝执行的门禁，再把该代所有名字移入隔离映射；门禁失败不得移动，移动部分失败保留门禁并给出恢复清单。用模型文件系统测试新链接、重命名与对象号复用，确认无入口在隔离期间继续可执行。

## 包结构（`package netsec`）

- `quarantine.go`：隔离事务核心与宿主接口 `HostFS`。
- `modelfs.go`：并发安全的内存模型文件系统，建模对象号、硬链接、代次、
  隔离映射与对象号确定性复用，并提供故障注入。
- `quarantine_test.go`：覆盖新链接、重命名、对象号复用、门禁失败、
  部分失败恢复清单与并发搅动的测试。

## 事务语义

1. `Quarantine(host, graph, target)` 先对目标对象代次 `ObjectRef{ID, Generation}`
   安装拒绝执行门禁；安装失败立即返回，不移动任何名字。
2. 门禁成功后，按引用图把该代次的全部目录项（硬链接名字）逐个原子移入
   隔离映射；移动时宿主校验名字仍指向预期代次，名字已消失或被重定向则跳过。
3. 每轮结束重新获取完整引用图，覆盖事务期间新建的硬链接和重命名；
   仍有残留时返回带 `Remaining` 恢复清单的 `ErrQuarantineIncomplete`，门禁保留。
4. `QuarantineReport.Retry` 凭清单继续隔离（必要时补装门禁）；
   `Rollback` 恢复全部名字后才撤销门禁，任一恢复失败则保留门禁与清单。
5. 门禁按“对象号 + 代次”精确生效，对象号复用后的新代次不受旧门禁影响。
