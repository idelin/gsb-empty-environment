# treereplay — 合成文件树操作日志重放工具

在合成文件树上重放 `create` / `rename` / `unlink` 操作日志。节点以稳定 ID
标识身份，路径只表示节点当前位置，不承载身份。

## 构建与运行

```sh
go build -o treereplay .
./treereplay [-v] <logfile>     # -v 每步打印完整 path->id 映射
go test ./...
```

## 日志格式（JSON Lines）

```json
{"seq":1,"op":"create","path":"/a","id":10,"dir":true}
{"seq":2,"op":"create","path":"/a/f.txt","id":11}
{"seq":3,"op":"rename","old":"/a/f.txt","new":"/b/f.txt"}
{"seq":4,"op":"unlink","path":"/b/f.txt"}
```

`id` 仅在 `create` 时出现，是节点的稳定身份；`rename`/`unlink` 通过当前
路径定位节点。

## 语义

- **目录搬移**：`rename` 目录时整棵子树随之移动，所有后代节点 ID 不变，
  仅路径变化。
- **目标替换**：遵循 POSIX rename 规则——文件可覆盖文件；目录可覆盖空
  目录；文件不可覆盖目录，目录不可覆盖文件，非空目录不可被覆盖。被替
  换节点的身份随之注销。
- **父环禁止**：目录不得搬入自身或自身后代，校验失败则整个操作拒绝。
- **事务原子**：每个操作先完整校验生成执行计划，再无失败点地提交；失
  败的操作不留下任何半个改名（`tree.go` 中 `planRename`/`commit` 分离）。

## 输出

每一步输出：序号、操作、成败、受影响路径及其身份（含被替换者）、异常
备注；结尾输出最终 `路径 -> 稳定ID` 身份映射。

## 异常检测（重放器）

- **日志重复**：同一 `seq` 出现两次。
- **序号缺口**：`seq` 跳号，报告缺失区间。
- **先删后重建同路径**：路径上的旧身份被 `unlink`（或被 rename 替换）
  后，同一路径出现新身份。

## 独立核对

`verify.go` 的 `FlatModel` 是与指针树完全独立第二种实现：用扁平的
`路径 -> (id, 是否目录)` 表加纯字符串操作重放同一日志，最后与树模型的
身份映射逐路径比对，不一致即报错。树模型负责"正确执行"，扁平模型负责
"独立复核"。

## 退出码

- `0`：全部事务成功、无异常备注、双模型一致。
- `1`：存在失败事务（树保持一致）、异常备注或模型不一致。
- `2`：用法或日志解析错误。
