# rematch

员工—岗位重新匹配库。原有岗位匹配中部分边失效后，在当前的可用边集合上重新求解匹配。

## 目标（字典序，优先级从高到低）

1. **匹配人数最大**：最大化获得岗位的员工数。
2. **岗位变更最少**：原本有岗位、新岗位与原来不同（包括变为未分配）的员工数最少。
   原本未分配的员工获得岗位**不算**岗位变更。
3. **岗位向量决胜**：按 `Employees` 顺序取每个员工的岗位下标组成向量
   （未分配视为比任何下标都大），字典序最小者胜。

## 用法

```go
p := rematch.Problem{
    Employees: []string{"a", "b"},
    Positions: []string{"p", "q"},
    CanWork: map[string]map[string]bool{ // 当前有效边
        "a": {"q": true},                 // a->p 已失效
        "b": {"p": true, "q": true},
    },
    Original: map[string]string{"a": "p", "b": "q"}, // 原分配（可含失效边、可部分）
}
sol, err := rematch.Solve(p)
// sol.Assignment: a->q, b->p   sol.Matched: 2   sol.Changes: 2
// sol.Chains: [[{a p q} {b q p}]]（调整链：a 让出 p 换 q，b 让出 q 换 p）
```

## 输出

- `Assignment`：新分配（员工 → 岗位）。
- `Unmatched`：未分到岗位的员工（按员工顺序）。
- `Displaced`：失配人员——原本有岗位、现在未分配的员工（按员工顺序）。
- `Chains`：调整链。原分配与新分配的对称差分解为若干条交错链/环，
  每条链按交替顺序给出每个员工的 `From`/`To`（空串表示未分配）。
  岗位未变的员工不出现在任何链中。
- `Matched` / `Changes`：两级目标的取值。

## 实现

1. 二分图最大匹配（Kuhn）求目标 1。
2. 最小费用流（每员工一条单位流，费用为变更 0/1，未分配走虚拟汇点）
   在匹配数固定为最大值的前提下求目标 2。
3. 按员工顺序逐位固定向量：每位从小到大尝试岗位（未分配最后），
   用同一最小费用流做可行性检查，保证三级目标字典序最优。

## 测试

`go test ./...` 包含：

- 小规模全匹配暴力枚举基准，与库输出在 3000 组随机实例上逐一比对
  （含随机失效边、随机部分原分配）；
- 链的一致性校验（链作用于原分配必须得到新分配，相邻步骤共享岗位）；
- 失效边换岗、未分配不计变更、字典序决胜、失配输出、输入校验等定向用例。
