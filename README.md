SQL 的多列 `NOT IN` 和 `<> ALL` 子查询在存在 `NULL` 时极易被错误优化成普通反半连接（Anti-Join）：当子查询为空集时即使外表列全为 `NULL` 也返回 `TRUE`，而子查询哪怕只含一行带 `NULL` 的部分匹配也可能把结果变成 `UNKNOWN` 从而整行滤除。为查询重写器交付可导入的 Go 去关联与执行验证包。输入外表与内表模式（含列是否非空标记）、关联条件（可选，支持相关子查询与非相关子查询）、多列元组比较 `(a1,..,ak) NOT IN (SELECT b1,..,bk ...)`（含 `NOT` 外层取反或放在 `OR` 析取分支中，必须完整保留 TRUE / FALSE / UNKNOWN 三值而非仅二值过滤！）。组件将查询重写为单次分组聚合与标记连接（Single-Pass Mark-Join / Null-Aware Anti-Join）物理计划并内置该计划求值器，正确区分内表空集、内表存在完全非空匹配行、内表无完全匹配但存在按三值逻辑与外表行比较结果为 `UNKNOWN` 的行（例如 `(1, NULL)` 对比 `(1, 2)` 为 `UNKNOWN`，但对比 `(3, 2)` 仍为 `FALSE` 不会污染结果！）。验收在含大量 `NULL` 组合的小表上对比逐行按 SQL:2016 三值语义直接求值的朴素参考实现，覆盖多列部分空 `(1,NULL)` vs `(1,2)` 与 `(3,2)` 区分、内表为空集外表全空返回 TRUE、相关子查询不同外键对应有的组空有的组含空，以及 `NOT (... NOT IN ...)` 外层取反三值传播。
