# Sub-cluster Gossip — 动态分片广播海量规模降噪器

万级节点规模下的分层拓扑 Gossip 协议（TypeScript 实现）+ 离散事件模拟器。
将扁平全网划分为虚拟局部集群（Cluster Cell），Cell 内高频 Gossip、
跨 Cell 低频汇聚广播，在保证局部故障感知 SLO 的前提下，把单节点网络
包量降低两个数量级。

零依赖：仅使用 Node.js 内置模块与内置测试运行器（`node:test`），
TypeScript 源码由 Node 原生类型擦除直接执行。

## 架构

```
┌──────────────────────── 全网 N 节点 ────────────────────────┐
│  Rendezvous(HRW) 哈希分片：numCells ≈ √N 个 Cluster Cell     │
│                                                              │
│  ┌── Cell ──┐   ┌── Cell ──┐        ┌── Cell ──┐            │
│  │ 高频Gossip│   │ 高频Gossip│        │ 高频Gossip│            │
│  │ 25ms/轮  │   │ 25ms/轮  │        │ 25ms/轮  │            │
│  │ fanout=3 │   │ fanout=3 │        │ fanout=3 │            │
│  │    ◆─────┼───┼────◆     │  ……    │     ◆    │            │
│  └────│─────┘   └────│─────┘        └────│─────┘            │
│       └──────────────┴── 低频汇聚广播 ────┘                  │
│              delegate ↔ delegate（1s/轮）                    │
└──────────────────────────────────────────────────────────────┘
   ◆ = delegate（Cell 内 id 最小的 2 个存活节点，免选举）
```

- **Cell 内（高频）**：每 25ms 向 3 个同 Cell 随机对等体推送心跳摘要，
  心跳以流行病速度在 Cell 内扩散；心跳停滞 150ms 判定疑似故障。
- **跨 Cell（低频汇聚）**：每个 Cell 的 delegate 每 1s 把本 Cell 的
  聚合心跳摘要发给其他每个 Cell 的 delegate 候选；跨 Cell 心跳以
  有界增量（每摘要 ≤16 条，轮转挑选）借 Cell 内 Gossip 再扩散，避免泛洪。
- **动态分片**：Rendezvous（HRW）哈希决定节点归属，Cell 数按 `√N`
  随规模伸缩；重分片时理论迁移率仅 ~1/(k+1)（实测 2.6%）。
- **单节点包量**：`O(fanout)` + 摊销 `O(cells²/cellSize)` ≈ 248 包/秒，
  与 N 无关；扁平广播为 `O(N)` = 79,920 包/秒（N=1000，同心跳周期）。

## 运行

需要 Node.js ≥ 22.6（≥ 23.6 原生运行 TypeScript，无需编译；仓库 `.nvmrc`
已固定 v23.9.0）。

```bash
nvm use            # 或任何 >= 22.6 的 Node
npm test           # node --test test/*.test.ts
npm run sim        # node src/sim/run.ts（1000 节点对比样例）
```

## 验收边界对照

| 指标 | 目标 | 实测 |
| --- | --- | --- |
| 单节点每秒出入包数降噪比 | ≥ 95% | **99.69%**（79,920 → 248 包/秒） |
| Cell 内崩溃局部感知延迟 | < 300ms | **max 234ms**（多种子复测 180–235ms） |
| 跨 Cell 广播可达性 | 全网可达 | 100% 覆盖，99% 耗时 ≤ 525ms |

基线口径：扁平全网广播要与分层方案达成相同的局部感知 SLO，就必须以相同
心跳周期（25ms）向全部 N−1 个对等体广播，故单节点包量为 `2×(N−1)/周期`；
这正是"扁平全网"在万级规模下不可持续、需要分层降噪的原因。

## 代码结构

- `src/sim.ts` — 离散事件模拟器（虚拟时钟 + 二叉堆）与虚拟网络
  （按 5ms 时间窗聚合投递事件；按节点统计出/入包数）
- `src/membership.ts` — Rendezvous（HRW）哈希动态分片
- `src/hierarchical.ts` — 分层 Gossip 节点（Cell 内高频 + 跨 Cell 汇聚）
- `src/flat.ts` — 扁平全网广播基线
- `src/protocol.ts` — 线协议消息类型（心跳用并行数组，减少小对象分配）
- `src/metrics.ts` — 包量/延迟指标
- `src/scenario.ts` — 1000 节点场景构建器（确定性种子）
- `src/sim/run.ts` — 对比样例
- `test/gossip.test.ts` — 验收测试（node:test）

## 设计说明与取舍

- 故障检测只作用于本 Cell（局部 300ms SLO）；跨 Cell 健康度由汇聚摘要
  的时效性体现，超时尺度为秒级，不参与局部 SLO。
- 心跳摘要携带全 Cell 心跳 + 有界跨 Cell 增量；生产实现可进一步用
  Bloom filter / 增量序列号压缩载荷（本模拟只计量包数，不计量字节）。
- delegate 采用"id 最小的 2 个存活节点"的确定性选择，零选举开销；
  delegate 崩溃时由次小 id 节点自动补位。
- 模拟器使用虚拟时间，结果由种子完全确定，可复现。
