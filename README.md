虚拟 NVMe 迁移时主机封存了实际 zone 盘像和几个完成队列，但部分 Zone Append 的返回 LBA 没有留下。设备后台要恢复客户的完成环，不能按到达先后猜 LBA。给块设备宿主写可导入的 Go 恢复包：从空区开始，输入每个提交队列上有序的请求和跨队列屏障（前驱完成才可执行），每个请求最多执行一次。Append 把给定块串原子写在该区当前写指针并返回起始绝对 LBA；Reset 擦净整个区并归零指针；Read 返回指定范围当时的块串，未写处为独立的空标记。某次执行若会越过区容量则该顺序不合法，不自动换区。断点可能留下一些未执行尾项。观测包含断点时每区写指针及若干已采样地址的块值、若干带请求号的成功回执（附返回内容或 LBA），其余既可能未完成也可能仅丢回执；每次请求都有固定编号，不把内容相同的追加归并。先判定全部观测能否由同一合法前缀解释，再给每个缺失回执列出精确的可能结果：未执行、或按实际结果去重后的已执行回执。只有唯一已执行结果才允许向客户发布；不唯一要给能独立重放的两条前缀。再实现一次批量询问：宿主指定几个请求的假定回执，回答它们能否同时成立并构造同一条前缀，不能把逐项合法误当联合合法。至多四个队列、三十个请求、三个区；区容量可到 2^48 块，初始及追加内容用值和重复次数描述（次数可跨 32 位），Read 回执与盘像必须按真实字节内容而非哈希相等验证。禁止展开长盘面或枚举全部拓扑排列；共享状态必须区分已返回但已被 Reset 抹去的效果。短区独立逐块全序前缀对照所有可能回执和联合询问；覆盖两个相同追加交换 LBA、末盘完全一致但旧读区分解释、排在另一个队列的 Reset 被屏障挡住，以及长重复块串只在最后一块不同。
