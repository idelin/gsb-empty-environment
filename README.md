# 带权 Max-CSP 分支定界求解器

软约束优化求解器：当所有约束无法同时满足时，为每个软约束赋予破坏惩罚权重，
使用**分支定界（Branch and Bound）**在硬约束绝对成立的前提下，
寻找**加权违反代价最小**的全局最优赋值方案。

纯 TypeScript 实现，零第三方依赖；使用 Node.js 内置 `node:test` 测试框架
（Node ≥ 22.6 原生支持运行 TypeScript，无需编译步骤）。

## 目录结构

- `src/maxcsp.ts` —— 通用带权 Max-CSP 分支定界求解器
- `src/scheduling.ts` —— 任务排期场景（3 条硬约束 + 5 条软约束）
- `src/demo.ts` —— 可运行演示样例
- `test/maxcsp.test.ts` —— 求解器单元测试（含随机实例 vs 暴力枚举交叉验证）
- `test/scheduling.test.ts` —— 排期场景验收测试

## 算法要点

- **下界**：当前部分赋值下已确定被违反的软约束权重之和（未判定的按 0 计，
  可采纳 / admissible）。
- **剪枝**：下界 ≥ 当前最优代价时剪掉整棵子树；硬约束不一致的分支立即剪除。
- **值排序**：按「立即新增惩罚」升序尝试取值，尽早获得优质 incumbent 以强化剪枝。

## 任务排期场景

5 个任务（T1 需求评审 / T2 原型设计 / T3 版本上线 / T4 宣传物料 / T5 备份演练）
排进周一至周五 5 个时段：

| 类型 | 约束 | 说明 |
| --- | --- | --- |
| 硬 | H1 资源独占 | 同一时段最多一个任务 |
| 硬 | H2 硬性截止 | 需求评审 ≤ 周三 |
| 硬 | H3 合规前置 | 宣传物料早于版本上线 |
| 软 | S1 权重 10 | 需求评审 = 周一 |
| 软 | S2 权重 8 | 原型设计 = 周二 |
| 软 | S3 权重 2（次要） | 版本上线 = 周三 |
| 软 | S4 权重 4 | 宣传物料 = 周四 |
| 软 | S5 权重 1（次要） | 备份演练 = 上线后第 2 天 |

S1+S2+S3+S4 与 H3 无法同时成立，必须有所取舍。

┌────────┬────────────────┐
│ 时段   │ 任务           │
├────────┼────────────────┤
│ 周一   │ T1 需求评审    │
│ 周二   │ T2 原型设计    │
│ 周三   │ T5 备份演练    │
│ 周四   │ T4 宣传物料    │
│ 周五   │ T3 版本上线    │
└────────┴────────────────┘

总惩罚（被违反软约束权重之和）: 3
违反软约束 2 条：
  ✗ S3（权重 2）版本上线排在周三（次要：发布日偏好）

即：在保证 3 条硬约束绝对成立的前提下，最优解恰好违反 2 条权重最低的
次要软约束（S3、S5），总惩罚 3 为全局最小；搜索仅展开 16 个节点、
访问 2 个叶子，其余空间被下界与硬约束剪枝消除。
