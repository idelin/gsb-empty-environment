# ECDSA高S变体绕过签名身份去重

交易接入层用签名字节作为请求ID，却同时接受ECDSA的(s)与(n-s)两种有效形式，攻击者可重放同一授权得到两个ID。给Go接入宿主实现P-256严格签名包：签名是ASN.1 DER SEQUENCE中恰好两个INTEGER r、s，DER须最短长度、正整数、无不必要前导零、无尾随数据，且1≤r,s<n；验签前要求s≤n/2。请求ID取SHA256(固定域标签||规范压缩公钥||大端消息长度||消息)，不含签名字节；同一请求ID原子登记一次，验签失败不占用，合法重复返回原结果。提供真实签名测试，生成任一有效(r,s)，计算另一个s2=n-s，将其中大于n/2者编码为高S并把另一个编码为低S，构造s'=n-s并确认两者在宽松标准库验签下都有效；严格入口只接受低S形式且两份映射同一请求ID。覆盖负INTEGER编码、冗余零、r或s为0、尾随DER、并发双提交和不同公钥签同消息，撤销索引绑定公钥与消息ID而非签名字节。
