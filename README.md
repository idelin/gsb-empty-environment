驱动升级会把共享队列逐个迁给不同虚拟机，旧中断可能沿另一条路由到达。为 Go 虚拟化控制宿主提供可导入的切换计划包。输入是至多 14 个路由表改写、队列封口和确认动作，各有先后依赖；另给每个设备、向量、投递域及可复用的代次编号。封口前已发中断可以停在路径任一段，之后每跳按该跳当时的表前进，只有末端租约和设备身份、投递域、完整路径代次均匹配才可交付。冲刷动作可任选输入列出的链路集合，确保该集合上已发事件全数投递或丢弃，代价由调用方给定。未封口且所有者未变的队列不能丢失合法中断；旧租户中断不得投递给新租户。为给定初末表求最低总冲刷代价的切换次序，次级目标为冲刷次数再按动作编号排序。同一代次值在不同路由组合下可重复出现，不可只记录向量与当前代次。返回可独立回读的切换证书，预算不足返回未知。用小拓扑展开全部中断位置和动作交错，检验两条队列共享末跳、有限代次回绕、不同端口确认乱序及不加屏障也安全的更新。
