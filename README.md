# logex — 日志提取器匹配库

支持字面字符、连接、或（`|`）、星号（`*`）与捕获括号（`()`）的正则匹配库，
面向从日志行中提取字段的场景。TypeScript 实现，零依赖。

## 匹配语义

1. **最左起点**：从位置 0 起扫描，第一个存在匹配（含空匹配）的起点获胜。
2. **最长整体匹配**：同一起点下，整体匹配最长者胜（POSIX 风格，而非回溯顺序）。
3. **按捕获组顺序选最长**：整体长度并列时，从组 1 起依次比较各组长度，长者胜。
4. **未参与 ≠ 空串**：未参与的组记为 `undefined`，参与但匹配空串记为 `''`；
   比较时未参与视为 -1，即“参与但为空”优于“未参与”。
5. **平局裁决**：以上全部并列时，按组序比较捕获区间，起点靠后者胜，
   其次终点靠后者胜（与“星号后迭代覆盖先迭代”一致），保证结果唯一确定。

星号迭代的捕获以后一次迭代为准；空迭代同样会写入捕获（例如 `(a*)*` 作用于
`"b"` 得到 `['', '']` 而非 `undefined`）。

## 用法

```ts
import { compile, extractFirst } from './src';

const re = compile('user=(a|b|c)* ');
const r = re.exec('INFO user=abba id=7');
// r = { index: 5, match: 'user=abba ', groups: ['a'] }
// groups[0] 是组 1 的最后一次迭代捕获

extractFirst('(a|b)*', 'xxab'); // { index: 2, match: 'ab', groups: ['b'] }
```

解析失败（未闭合括号、孤立的 `*` 等）抛出 `SyntaxError`。

## 终止性与性能

输入长度按 ≤ 20 设计。匹配器穷举每个 `(节点, 位置)` 的所有 `(终点, 捕获表)`
结果并记忆化；星号用工作表法求不动点——状态集合有限且单调增长，
因此 `(a*)*`、`((a*)|(b*))*` 之类的空匹配循环必然终止。

## 验证

测试采用双实现差分：

- `src/matcher.ts`：记忆化 + 不动点穷举。
- `test/oracle.ts`：独立实现，显式枚举**解析树**（星号展开为具体迭代序列，
  按状态 `(位置, 捕获表)` 剪枝），逐树求值后用独立选取规则得出答案。

`test/unit.ts` 覆盖语义边界用例（含长度 20 的终止性用例）；
`test/differential.ts` 用可复现的随机模式/输入做差分（默认 3000 例，
可用 `SEED` / `CASES` 环境变量调整，已验证 4 万+ 例一致）。

```sh
npm test                      # 构建并运行全部测试
SEED=7 CASES=20000 npm test   # 指定种子与用例数
```
