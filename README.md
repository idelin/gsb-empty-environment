# 邮件放行规则允许引用可信接入节点的认证结果，外部同名声明不得参与求值

邮件放行规则允许引用可信接入节点的认证结果，外部同名声明不得参与求值。写供Go邮件宿主调用的证据逻辑包，每个原子事实绑定消息摘要、接入节点签名和认证方法；仅配置受信节点且签名有效的事实可取真或假，其余为未知。规则采用强Kleene逻辑，只有真可放行，返回使放行成立的最少已认证事实集合。最多18事实，用真实签名、跨邮件拼接及全部子集枚举验证，不能通过把未知改成假满足否定规则。

## 实现

证据逻辑包位于 `evidence/`，仅依赖 Go 标准库：

- `evidence/evidence.go`：原子事实、ed25519 签名与校验、强 Kleene 三值、引擎与最小集枚举。
- `evidence/rule.go`：规则 AST 与程序化构造器（`AtomOf`/`NotOf`/`AndOf`/`OrOf`）。
- `evidence/parser.go`：规则文本解析，优先级 `not` > `and` > `or`，支持括号。

### 证据绑定

每个 `Fact` 绑定名称、接入节点 id、认证方法、消息原文与布尔断言。
`NewFact` 对长度前缀的规范载荷计算 ed25519 签名，载荷覆盖名称、节点 id、
方法、消息 SHA-256 摘要与断言，篡改任一字段都会使校验失败。

`Engine` 仅在以下条件全部满足时把事实取为真或假：

1. 节点 id 存在于配置的 `TrustedNodes` 且公钥长度合法；
2. ed25519 签名通过校验；
3. 事实绑定的消息摘要等于当前被评估消息的摘要。

不可信节点的同名声明、无效签名、畸形事实以及从其他邮件拼接来的事实一律为
`Unknown`，不参与求值，也不能覆盖受信绑定。

### 求值与最小集

规则使用强 Kleene 逻辑：`not Unknown = Unknown`，因此缺失证据不能被当作假来
满足否定规则。只有规则值为 `True` 时 `Decision.Release` 为真。放行时按基数
递增枚举子集（上限 18 个已认证事实，即最多 2^18 次求值），返回全部最小基数的
已认证事实集合；结果按名称确定性排序。

### 验证

`evidence/*_test.go` 使用真实 ed25519 密钥覆盖：

- 真实签名、六类字段篡改与错误公钥；
- 跨邮件拼接隔离与外部同名声明隔离；
- 强 Kleene 真值表与“未知不能当假”反例；
- 10 个事实的全部 2^10 子集暴力交叉验证与单调性；
- 18 事实上限、最小集基数与解析器错误。

运行：

```sh
go test ./... -count=1 -race -cover
```
