# rematch

员工-岗位重新匹配库。原匹配中部分边失效后，在当前可用边上重新匹配，依次优化三级目标：

1. **人数最多**：匹配上的员工数最大；
2. **变更最少**：岗位变更次数最小。原本已分配的员工最终岗位不同（含失去岗位）记一次变更；
   **原本未分配的员工获得岗位不算变更**；
3. **向量决胜**：按员工顺序的岗位向量字典序最小（未匹配分量取哨兵值 `numPositions`，
   即越靠前的员工越优先获得小编号的真实岗位）。

## 用法

```go
res := rematch.Reassign(numEmployees, numPositions, edges, original)
```

- `edges`：`[][2]int`，当前可用的（员工, 岗位）边（已剔除失效边）；
- `original`：`[]int`，`original[e]` 为员工 `e` 的原岗位，`rematch.Unassigned`(-1) 表示原本未分配；
- 返回 `rematch.Result`：
  - `Assignment[e]`：员工 `e` 的新岗位（-1 表示未匹配）；
  - `Moves`：失配人员列表（岗位发生变化的员工，含 From/To）；
  - `Chains`：调整链——新旧匹配对称差分解出的交替路径/环，
    链中相邻员工满足 `前者.To == 后者.From`（顶岗方向），`Cyclic` 表示成环。

## 实现

- 前两级目标建模为最小费用流：每人一个虚拟“未分配”岗位，费用 = `w0*未匹配人数 + 变更次数`
  （`w0 = n+1` 保证人数优先），用势 + Dijkstra 的连续最短路求解；
- 第三级目标在最优费用约束下按员工顺序逐人贪心固定字典序最小可行岗位，逐步重解费用流验证；
- 正确性由测试中与全匹配暴力枚举（小规模随机用例）逐一核对保证，见 `rematch_test.go`
  与 `stress_test.go`。
