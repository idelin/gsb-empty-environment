# tsbuild-cache

TypeScript 模块的增量构建缓存库（零依赖，Node.js ≥ 14）。

## 缓存键设计

每个缓存条目以一个**强连通分量（SCC）**为作用域，键为：

```
H( 排序后的 [H(模块id + 源码) | 组内每个模块]
 + 排序后的 [依赖id : 依赖导出签名哈希 | 每个组外直接依赖] )
```

由此得到三条核心性质：

- **内部实现变化不重编调用方**：依赖只改函数体、不改导出签名时，其签名哈希不变，
  调用方的键不变，直接命中缓存。
- **导出变化传递失效**：依赖导出签名变化会改变直接调用方的键；若调用方自身导出
  签名也因此变化，失效沿依赖链继续向下传递。
- **失败产物不入缓存**：编译器抛 `CompileError` 时，整个 SCC 的产物不会写入缓存
  （先全部编译成功才提交），已有有效条目不被污染。

## 循环依赖

`src/graph.js` 用 Tarjan 算法求 SCC，并对缩点图做拓扑排序（依赖在前）。
同一 SCC 内的模块互为循环依赖，无法单独确定键，因此**整组作为一个编译与缓存单元**：
任一成员源码变化即整组重编；组外模块只依赖该组对外导出签名的哈希。

## 模块组成

- `src/hash.js` — sha256 内容哈希
- `src/compiler.js` — 迷你 TS 编译器：导出签名提取（函数/类/常量/接口/类型/re-export，
  不含实现体）+ 类型擦除"编译"；括号不配对抛 `CompileError`
- `src/graph.js` — import 解析、Tarjan SCC、SCC 拓扑排序
- `src/cache.js` — 条目缓存，支持 `save`/`load` 持久化到磁盘
- `src/builder.js` — 增量构建器，返回产物与 `{ compiled, reused, compileCount }` 统计

## 验证

```
npm test
```

测试用两种方式验证正确性：

1. **全量重编对比**：每个增量构建场景的产物都与同源码的全新全量构建
   （空缓存）逐模块 `deepStrictEqual`。
2. **编译次数断言**：精确断言每个场景下哪些模块被编译、哪些命中缓存，
   覆盖：无变化全命中、内部变化只编自身、导出变化逐级传递、菱形依赖、
   循环组整体重编、编译失败不入缓存且重试会重新编译、缓存磁盘持久化。
