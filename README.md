终端准入与代码签名网关在离线校验 Windows 64 位 PE32+ 二进制文件的 Authenticode 完整性时，若仅按节区哈希而未精确排除规范规定的三大可变字段（`OptionalHeader.CheckSum`、`Certificate Table` 数据目录项以及文件尾部 `WIN_CERTIFICATE` 属性证书表），或放过证书表后追加的未签名 Overlay 载荷、重叠节区与缺失控制流防护（CFG）标志，攻击者可在不破坏数字签名的前提下向证书表尾部塞入恶意配置或伪造节偏移。为 C++17 二进制安全宿主实现可嵌入、零外部依赖、`-Wall -Wextra -Wconversion -Werror` 编译通过的原始字节级 PE32+ 结构与 Authenticode 摘要计算及准入验证库（内置 SHA-256 并通过抽象回调验证签名摘要）。库从 DOS 头（`MZ`/`e_lfanew`）与 PE 头（`PE\0\0`、`0x020B` PE32+ 魔数）起严格解析全部节表与数据目录：硬拒绝节文件偏移越界、节间文件区间重叠、同时可写可执行节（`IMAGE_SCN_MEM_WRITE | IMAGE_SCN_MEM_EXECUTE`）以及整数加法回绕；严格按微软 Authenticode 规范分三段流式计算文件真实 Authenticode SHA-256（精确跳过 4 字节 `CheckSum`、8 字节 `IMAGE_DIRECTORY_ENTRY_SECURITY` 目录项及 8 字节对齐后的完整证书表区间，并把全部合法已覆盖的尾部非证书字节纳入哈希）；强制校验 `WIN_CERTIFICATE` 位于文件精确末尾且其内部 `dwLength` 与目录声明严格一致（拦截证书表后藏毒与长度填充绕过），同时核查 `DllCharacteristics` 必须开启 `DYNAMIC_BASE`、`NX_COMPAT`、`HIGH_ENTROPY_VA` 与 `GUARD_CF`。附手工构造的合法 PE32+ 样本与尾部藏毒、重叠节、修改非排除字段篡改测试。
