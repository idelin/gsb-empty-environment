# 弱稳定匹配求解器(带并列与容量)

求解 **Hospitals/Residents with Ties (HRT)** 问题:双方偏好均允许并列,
岗位(医院)带容量,求**最大规模弱稳定匹配**。

## 稳定性定义

采用**弱稳定性**:对 (申请者 a, 岗位 h) 构成阻挡对,当且仅当

1. a 与 h 互可接受且未匹配在一起;
2. a **严格**偏好 h 胜于现状(或 a 未匹配且 h 可接受);
3. h 有空位,或 h **严格**偏好 a 胜于其最差在院者。

任一侧仅为**并列**即不构成阻挡对。

## 为什么不打破并列

MAX-HRT(最大基数弱稳定匹配)在一般情形是 NP-hard,且不同的并列打破
方式会产生规模不同的稳定匹配。本求解器**不做任何并列打破**,而是对全部
匹配做精确分支定界枚举,直接按原始并列偏好判定弱稳定性,因此报告的最大
规模是精确最优值。搜索上界为 10 名申请者(`MaxApplicants`)。

剪枝的安全性依据(沿任一搜索分支):

- 申请者按固定顺序决策,已决策者的指派不再改变;
- 岗位的在院者集合只增不减,满员后不再变化;
- 故"岗位已满"的阻挡对一旦出现便永久存在,可安全剪枝;
- 若岗位空位对剩余未决策申请者均不可接受,该空位永久存在,相关阻挡对亦可剪枝;
- 已匹配数 + 剩余未决策人数严格小于当前最优时,分支不可能更优或持平。

每个叶子(完整匹配)还会用独立验证器复查弱稳定性作为安全网。

## 输入格式

JSON,偏好按从强到弱分档列出,同一内层数组内为并列:

```json
{
  "applicants": [
    {"name": "a1", "prefs": [["h1"], ["h2", "h3"]]}
  ],
  "hospitals": [
    {"name": "h1", "capacity": 2, "prefs": [["a1", "a2"], ["a3"]]}
  ]
}
```

未出现在对方列表中即互不可接受;列表可截断。

## 运行

```sh
go run . -i examples/tie_tradeoff.json   # 从文件读取
cat instance.json | go run .             # 从标准输入读取
go run . -v -i instance.json             # 列出全部互可接受对的检查证据
```

输出三部分:

1. **匹配结果**:最大规模弱稳定匹配及未匹配者;
2. **阻挡对检查证据**:对每个"申请者一侧严格偏好"的关键对给出非阻挡的
   具体理由(岗位已满且不严格偏好 / 并列等),`-v` 列出全部对;
3. **最优性证据**:精确枚举的搜索统计与最优规模匹配的总数。

## 示例

`examples/tie_tradeoff.json` 展示任意打破并列为何不可靠:h1 对 a1/a2
并列,若按 h1: a1≻a2 打破并列再求稳定匹配,只得规模 1 的 {a1—h1};
而真正的最大规模弱稳定匹配是规模 2 的 {a1—h2, a2—h1}(a1 虽更想去 h1,
但 h1 对 a1/a2 并列,不构成阻挡对)。
