查询引擎的 JIT 有两个固定入口，旧查询可能在两次热切换之间暂停。代码缓存由有限的双代中继槽组成；只校验切换前后都能到达目标不足以保证暂停的查询正确恢复。交付查询执行引擎可导入的 Go 链接包，提供读取当前缓存、生成写计划和逐步应用的接口；每步应用前核对实际旧指令，不匹配则拒绝该步。每个源和槽各有不可移动的地址、指令宽度和可编码的有符号位移闭区间；槽另有实际可写的候选后继列表。源的原子动作可切换到某个允许后继，同时把新进入该源的逻辑版本从旧改新（已是新版本的源无需切换，其余源只能切换一次）；每个槽的一步更新只改这个槽的后继。版本只随源进入时确定，不在运行中改变。已进入线程可在任一槽取指之前暂停任意多个安装动作，随后按当时实际指令继续。任何线程均须最终到其进入时规定的版本目标，且在安装停止时从每个可能暂停位置出发不得陷入环或到空槽；不能要求线程报告位置、等待读者退出或全局停机。规划器知初末配置、每写一槽的正成本，以及哪些是可临时借用的空槽；最终必须精确恢复给定新配置（含空槽）。用所有合法线程移动的闭包评价安装序列，找总写成本最低者（源切换也有给定费用），同费最少安装步数；如果不存在，区分于零步成功。最多八槽、每槽有至多三个候选地址及清空动作。提供能逐步落到稀疏代码缓存的补丁、终端跳转模拟器与独立交错测试。覆盖暂停线程尚可读取旧槽而新线程已在同槽下游进入、先写临时中继才能安全通达、静态合法新旧图间没有安全过渡，以及相邻指令的位移边界。
