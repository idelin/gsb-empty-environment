POSIX 与 NFSv4 文件锁允许客户端对 64 位偏移区间申请共享读锁、独占写锁或解锁，且约定长度 `len == 0` 表示一直锁到文件末尾（`UINT64_MAX`）；同一属主在已有锁内部执行部分升级、部分降级或中间打洞解锁时，锁表必须把单条区间原子拆成多段并把相邻同类型锁重新合并，否则会产生锁碎片泄露或跨属主冲突漏报。为分布式文件服务器锁服务交付可导入的 Go 字节区间锁管理器。每条请求含文件句柄、`ownerId`、操作（`LOCK_RD`、`LOCK_WR`、`UNLOCK`、`TEST`）、`uint64` 起点 `offset` 与长度 `length`（`0` 表示至 `UINT64_MAX` 闭区间末尾；若 `length > 0` 且 `offset + length - 1` 溢出 `uint64`，须按 RFC 7530 规范拒绝或返回 `NFS4ERR_INVAL` 而非回绕！）。规则：同一 `ownerId` 内部永不自冲突，其新锁直接覆盖重叠区并原子拆分/收缩原有锁，相邻且类型相同的区间自动合并为单条规范区间；不同 `ownerId` 间写锁与任意锁互斥、读锁彼此兼容，冲突时不得修改锁表并精确返回偏移最小的冲突区间与属主；`UNLOCK` 仅裁剪调用者自身持有的锁（对未锁区域或全文件解锁均幂等成功，包括在已有大锁正中打洞拆成左右两段）；支持按 `ownerId` 一键释放租约过期属主的全部锁，并校验高边界 `offset = UINT64_MAX, length = 1` 与 `length = 0` 的单字节端点无溢出。验收覆盖同一锁内三段拆分升级/降级、相邻同型自动合并、跨属主读写冲突返回最小偏移冲突、打洞解锁、租约失效回收及 `UINT64_MAX` 边界无回绕。
