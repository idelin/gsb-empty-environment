# alias-resolver

对象别名解析库（TypeScript，零依赖）。别名可指向具体对象版本或另一别名，
解析时限制最大跳数并返回完整路径；批次更新原子生效；缓存按依赖（含负依赖）
细粒度失效。

## 运行测试

需要 Node.js >= 22.6（利用原生 type-stripping 直接运行 `.ts`，无需编译）：

```sh
node --test test/*.test.ts   # 或 npm test
```

## 核心概念

- `AliasStore`（`src/store.ts`）：保存版本化对象与别名表。每次变更产生一个
  递增的 `epoch` 并记录变更的依赖键集合（`alias:<name>` /
  `object:<name>@<version>`）。`commitAliasBatch` 先整体校验再一次性应用，
  任一操作非法则整批拒绝、状态与 epoch 不变（原子性）。`snapshot()` 返回某
  epoch 的不可变一致视图，旧快照永远解析旧结果。
- `AliasResolver`（`src/resolver.ts`）：带缓存的解析器。遍历过程中把每一次
  查询都记入依赖集——**包括未命中的查询（负依赖）**。缓存条目对目标 epoch
  有效的充要条件：条目 epoch 不晚于目标 epoch，且两者之间的所有提交均未触
  及其依赖。因此补上缺失目标（此前是负依赖）会使缓存的 dangling 结果失效，
  而未受波及的条目（如共享目标之外的别名）继续命中。
- `referenceResolve`（`src/reference.ts`）：独立的无缓存遍历参考实现，与
  缓存解析器不共享代码，用于差分核对。

## 解析结果

`resolve(name, { maxHops?, snapshot? })` 返回带完整路径的判别联合：

- `ok`：到达具体对象版本，`path` 为逐跳记录；
- `cycle`：检测到环，`cycle` 列出构成环的别名序列；
- `dangling`：目标缺失（`missing` 区分缺失的别名与缺失的对象版本）；
- `max-hops-exceeded`：超过跳数上限，返回已遍历的部分路径；
- `missing-alias`：起始别名本身不存在。

环与悬空在写入时不禁止（允许多个别名共享目标、允许批次内成环），统一在
解析时分别报告。

## 测试要点（`test/resolver.test.ts`）

- 批次原子性：重复别名 / 非法目标导致整批拒绝；
- 批量造环（含自环）与悬空目标分别报告；
- 负依赖：补上缺失别名、缺失对象版本后缓存失效；
- 细粒度失效：无关提交不影响已有缓存条目；
- 删除后重建同名别名指向不同目标，不读旧缓存；
- 旧快照按自身 epoch 解析，不被新缓存污染；
- 随机历史差分测试：400 步随机批次/对象增删 + 随机快照与跳数上限，
  缓存解析器结果与无缓存参考实现逐一深比较。
