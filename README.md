# 维修规划器（备件齐套 / 拆旧回收）

在预算约束下，对最多 **18 台** 设备逐台决策 **修复 / 拆解 / 闲置**（三者互斥），
使 **恢复总价值 − 拆解残值损失** 最大，并输出备件从来源到用途的流水。

## 问题建模

- **齐套才能修**：设备修复需要一份备件清单，库存 + 回收不足以齐套则不能修。
- **拆旧回收**：拆解旧设备可回收备件，但损失该设备的残值（从目标中扣除）。
- **回收有损耗**：有效回收量 = `floor(标称量 × 回收率)`，回收率支持全局或按备件覆盖。
- **不能循环产料**：修复与拆解互斥，回收一次性发生，不存在“修了再拆、拆了再修”的循环。
- **预算**：只计修复费用，`Σ 修复费用 ≤ 预算`。
- **目标**：`max Σ修复价值 − Σ拆解残值损失`。

## 运行

需要 Node.js ≥ 22.6（利用 `--experimental-strip-types` 直接运行 TypeScript）；
或自行 `npm i -D typescript` 后用 `tsc` 编译运行。

```bash
npm start                 # 求解内置样例（14 台设备）
npm start -- case.json    # 求解指定输入文件
npm test                  # 300 个随机实例与 3^n 暴力枚举对拍 + 守恒性检查
```

## 输入格式（JSON）

```json
{
  "budget": 60,
  "recoveryYield": 0.8,
  "partYield": { "密封件": 0.9 },
  "stock": { "液压泵": 1, "密封件": 4 },
  "devices": [
    {
      "id": "D01",
      "repairCost": 18,
      "repairValue": 60,
      "residualValue": 12,
      "repairParts": { "液压泵": 1, "密封件": 2 },
      "salvageParts": { "轴承": 2 }
    }
  ]
}
```

`partYield` 可省略（缺省用 `recoveryYield`）；设备数 ≤ 18，超限报错。

## 输出

- **方案**：修复 / 拆解 / 闲置设备清单，目标值、恢复价值、残值损失、预算使用。
- **备件平衡**：每类备件的 库存 / 回收 / 损耗 / 消耗 / 剩余。
- **备件流水**：逐条 `备件: 来源(库存|某拆解设备) -> 用途(某修复设备) ×数量`，
  分配规则为先耗库存、再按设备顺序耗回收件（确定性）。

## 算法

精确分支定界（`src/solver.ts`），对每台设备枚举三种互斥决策：

- **上界**：忽略备件约束，对剩余设备按 价值/费用 密度做分数背包（前缀和 + 二分，
  单次 O(log n)）；拆解收益非正，按 0 计入上界。
- **可行性剪枝**：任一备件 已承诺需求 > 库存 + 已承诺回收 + 未决设备全部潜在回收 时剪枝。
- **预判**：修复永远不可能齐套的设备直接剪掉修复分支；回收件无人需要且残值非负的
  设备剪掉拆解分支。
- 支持 `timeLimitMs` / `maxNodes`，超限返回当前最优并标记 `terminated`。

正确性由 `test/solver.test.ts` 保证：300 个随机小规模实例与独立实现的 3^n 暴力
枚举逐一比对目标值，另含 18 台设备限时用例与边界用例。

## 文件结构

- `src/types.ts` — 输入模型与决策类型
- `src/solver.ts` — 分支定界求解器
- `src/flow.ts` — 备件流水与平衡表生成
- `src/cli.ts` — 命令行入口（读 JSON 或内置样例）
- `src/sample.ts` — 内置样例（14 台设备、4 类备件）
- `test/solver.test.ts` — 暴力对拍与守恒性测试
