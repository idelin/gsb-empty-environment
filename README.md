文档渲染与浏览器安全网关在加载用户上传的 TrueType/OpenType（`sfnt`）字体文件前，若未做原始字节级结构审计，攻击者可利用 `sfnt` 表目录偏移/长度整数溢出、不同表数据区相互重叠、`head`/`maxp`/`loca`/`glyf` 间计数矛盾（如 `loca` 偏移非单调递增或越出 `glyf` 表末尾）、以及复合字形（Composite Glyph）循环引用触发渲染引擎栈溢出或堆越界写。为 C++17 媒体安全宿主实现可嵌入、零外部依赖、`-Wall -Wextra -Wconversion -Werror` 编译通过的原始字节级 OpenType/TrueType `sfnt` 安全审计库。库从大端序 `OffsetTable` 起严格校验：（1）魔数（`0x00010000` TrueType 或 `OTTO` CFF）、`numTables` 与表目录记录边界及每张表的 32 位大端加法校验和（含 `head.checkSumAdjustment` 特殊清零规则），硬拒绝重复表标签、未按标签字典序排列、偏移未 4 字节对齐、64 位 `offset + length` 回绕以及任意两表区间重叠；（2）联合校验核心表一致性：解析 `head`（`indexToLocFormat` 仅限 0/1、`unitsPerEm` 合法范围）、`maxp`（`numGlyphs` 上限）与 `loca` 表（校验表长精确为 `(numGlyphs + 1) * (2 或 4)` 且全部偏移单调不减并严格 `<= glyf.length`）；（3）遍历 `glyf` 全部字形头：对简单字形校验 `numberOfContours >= 0` 且轮廓终点数组严格递增不越界；对复合字形（`numberOfContours < 0`）递归校验子字形索引 `< numGlyphs` 并用有向图访问集硬拦截循环引用与超过上限（如 16 层）的嵌套。附合法微型 TTF 样本与表区间重叠、校验和篡改、`loca` 非单调越界及复合字形循环引用测试。
