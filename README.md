# 淘汰赛签位求解器

按种子档把选手安排进淘汰赛签位（部分位置可锁定），使同队选手的总罚分最低，
并输出每对同队选手的最早相遇轮次。签表规模最大 16 人。

## 模型

- 签表大小为 2 的幂（2..16），`size: 0` 表示取不小于人数的最小 2 的幂；人数不足时剩余位置为轮空（bye）。
- **种子档**：可选 `slotTiers` 给每个签位一个档位标签，选手只能进入与自己 `tier` 相同的签位；各档位数必须与各档人数一致。省略则无档位限制。
- **锁定**：`locked` 把指定选手固定到指定签位。
- **罚分**：同队两人在第 `r` 轮最早相遇（假设一路获胜）的罚分为 `2^(R-r)`，`R` 为总轮数——越早相遇罚分越高，决赛相遇罚 1。
- **目标**：最小化所有同队配对的罚分总和；并列时按签位 0..N-1 的选手编号序列取字典序最小者（轮空记为 0）。

## 用法

```sh
go run . -i examples/sample.json          # 从文件读入
cat input.json | go run .                 # 从标准输入读入
go run . -i in.json -brute=always         # 强制穷举对照（auto|always|never，默认 auto）
go test ./...                             # 含 300 组随机小规模“求解器 vs 穷举”对照
```

默认 `-brute=auto`：当合法签表数不超过 `-brute-limit`（默认 200 万）时自动做全枚举对照，
核对分支定界求解器的最优罚分与并列决胜结果是否一致。

## 输入格式

```json
{
  "size": 8,
  "players": [{"id": 1, "team": "A", "tier": 1}, ...],
  "slotTiers": [1, 2, 1, 2, 1, 2, 1, 2],
  "locked": {"0": 1}
}
```

## 实现

- `solver.go`：`NewProblem` 校验输入并预计算相遇轮次表（两签位最早相遇轮 = 编号异或的最高位 +1）；
  `Solve` 按签位顺序做分支定界（下界：未落位的同队配对每对至少罚 1），并列时维护字典序最小序列；
  `BruteForce` 不剪枝全枚举，用于小规模对照。
- `main.go`：CLI，打印完整签表、总罚分、每对同队选手的最早相遇轮次，以及穷举对照结论。
