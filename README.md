# exact-compositing

8 位透明度合成库：内部使用精确有理数（bigint 分数），支持预乘（premultiplied）
与非预乘（straight）两种输入格式，零透明度单独处理；并比较"一次性合成"与
"分组后量化"两种管线的输出差异，穷举输出最小反例。

## 规则约定

- **颜色空间**：按题内线性规则——直接在通道值上做线性插值（Porter-Duff `over`），
  不做 sRGB/gamma 转换，不调用任何图形库的默认混合。
- **内部表示**：通道与 alpha 均为 0..255 尺度上的精确有理数（`Fraction`，bigint 约分）。
- **合成算子**（预乘形式，`top over bottom`）：
  `out.c = top.c + bottom.c * (255 - top.a) / 255`，alpha 同理。
- **量化**：四舍五入（round-half-up，精确判定），中间分组结果量化为 8 位预乘像素。
- **零透明度**：straight 输入 alpha 为 0 时视为透明黑（RGB 无意义，置 0）；
  输出 un-premultiply 时 alpha 为 0 直接输出 `(0,0,0,0)`，避免 0/0。
- **管线语义**：
  - 一次性（one-shot）：整叠图层精确合成，末尾量化一次。
  - 分组（grouped）：每组精确合成后量化到 8 位预乘缓冲，再继续参与合成，
    末尾再量化一次输出。单个组（如 `[3]`）即一次性合成，不做多余量化。

## 最小反例

在"图层字节最大值最小、其次字节和最小、再次字典序"的度量下穷举（灰度即可，
因为 RGB 通道在 `over` 下相互独立，灰度最小性蕴含 RGBA 最小性）：

- 2 层不可能产生差异（`[2]` 即一次性合成；`[1,1]` 对 8 位输入量化是恒等），
  故 3 层为最小深度，非平凡分组只有 `[1,2]` 与 `[2,1]`。
- **最小反例**（所有输出格式一起比较）：最大字节值 = 1
  - 层（自下而上，预乘灰度）：`L1=(0,0,0,0)`，`L2=(1,1,1,1)`，`L3=(0,0,0,1)`，分组 `[1,2]`
  - 一次性：精确值 `(254/255, a=509/255)` → straight `(127,127,127,2)`
  - 分组：顶层组量化为 `(1,1,1,2)` → straight `(128,128,128,2)`
  - 差异出现在 un-premultiply 后的 straight 通道：127 vs 128
- 若只比较预乘输出（不做 un-premultiply），首次分歧出现在最大字节值 = 7
  （如 `(0,0,0,6),(0,0,0,7),(0,0,0,7)`，alpha 19 vs 20）。

## 运行

需要能直接运行 TypeScript 的 Node（>= 23，或 22.6+ 加 `--experimental-strip-types`），
或用 `tsc` 自行编译：

```sh
npm start     # 打印最小反例报告
npm test      # node:test 单元测试（含穷举一致性校验）
```

## 结构

- `src/fraction.ts` — 精确有理数（bigint，自动约分）
- `src/color.ts` — 颜色类型、格式转换、`over`、量化、零透明度处理
- `src/compose.ts` — 一次性 / 分组合成管线
- `src/search.ts` — 精确整数谓词 + 按上界穷举的最小反例搜索
- `src/main.ts` — 报告输出
- `test/library.test.ts` — 单元测试（含整数谓词与精确管线的随机一致性对拍）
