双栈云边界网关实现有状态 NAT64（RFC 6146）与无状态头部翻译（RFC 7915）时，必须同时维护地址无关绑定表（BIB）、五元组会话表（Session Table）、TCP 6 态转换机及嵌套 ICMP 报文重写：1）**EIM（Endpoint-Independent Mapping）与端口奇偶/范围保持**：同一 IPv6 客户端 `(src6, sport)` 访问多个不同 IPv4 目标时必须复用同一条 BIB 映射 `(poolIPv4, port4)`；新分配端口须保留源端口区间（`0..1023` 系统端口 vs `1024..65535` 用户端口）及尽可能保持奇偶性，且支持多 IPv4 池地址下的 `(poolIPv4, port4, dst4, dport)` 会话复用而不碰撞；2）**RFC 6146 TCP 6 态机与 `V4_INIT` 6 秒延迟**：当 IPv4 侧向一个已存在 BIB 映射但尚无对应 Session 的 `(poolIPv4, port4)` 发来 `SYN` 时（可能是 TCP 同时打开或外部扫描！），不可立即转发也不可立即发错，必须进入 `V4_INIT` 态并缓存该 `SYN` 恰好 6 秒——若 6 秒内收到 IPv6 侧发往同目标的 `SYN` 则无缝配对进入 `ESTABLISHED` 并放行双向流量；若 6 秒超时未配对，则删除临时态并回发 `ICMPv4 Destination Unreachable (Code 13)`！3）**ICMPv6 <-> ICMPv4 嵌套内层翻译**：收到 `ICMPv6 Packet Too Big (Type 2)` 或 `Time Exceeded (Type 3)` 时，除按 RFC 7915 映射外层 Type/Code 与 MTU（IPv6 -> IPv4 须 `MTU - 20`，反向 `MTU + 20` 且钳位 `>= 1280`！）外，还必须按 BIB/Session 反向查表将嵌套在 ICMP 载荷里的原始触发包头（IPv6 <-> IPv4 及内层 TCP/UDP 端口）精准重写并重算传输层与 ICMP 校验和！4）支持不同协议与状态超时回收（`UDP >= 5m`、`TCP_EST >= 2h`、`TCP_TRANS = 4m`、`ICMP = 60s`）及引用归零自动清理 BIB。为双栈网络边界网关交付可导入的 Go RFC 6146 NAT64 状态机与报文翻译包。验收覆盖 EIM 跨目标端口复用、IPv4 侧 unsolicited SYN 进入 `V4_INIT` 6 秒配对成功 vs 超时发 ICMPv4、`ICMPv6 PTB` 嵌套内层五元组翻译与 MTU 减 20、以及会话超时与 BIB 级联回收。
