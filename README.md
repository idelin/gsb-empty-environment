# jobshop — 单机换型排程库 (Go)

单台设备处理最多 12 个订单。每个订单有类型、加工时长和截止时间；相邻两个
不同类型的订单之间需要换型时间，由（可非对称的）矩阵给出，设备初始类型给定。

## 目标（字典序）

1. 最小化最大迟交量 `max(C_j - d_j)`（可为负，表示全部提前）；
2. 在前者最优的所有排程中，最小化总换型时间；
3. 仍并列时取订单下标字典序最小的序列，保证结果确定。

## 算法

子集 DP（`2^n × n` 状态）：

- 第一阶段：`dp[mask][last]` 保存 `(完工时间, 最大迟交量)` 的 Pareto 前沿
  （换型使完工时间与顺序相关，单一最优对会丢解），求得最优 L*；
- 第二阶段：在所有前缀迟交量 ≤ L* 的状态中，最小化 `(总换型时间, 序列)`。
  可行性在于：固定 `(mask, last)` 时，换型时间最小的可行前缀完工时间也最小
  （完工时间 = 时长之和 + 换型时间之和），因此它若把下一单推过 L*，其他前缀更不行。

12 个订单求解约 0.7s（`BenchmarkSolve12`）。

## 用法

```go
sol, err := sched.Solve(sched.Problem{
    Orders:      []sched.Order{{ID: "A", Type: 0, Duration: 4, Deadline: 12}, ...},
    Setup:       [][]int{{0, 2, 5}, {3, 0, 4}, {1, 6, 0}}, // 可非对称
    InitialType: 0,
})
fmt.Print(sol.String()) // 时间表：每单的换型/开始/完工/迟交
```

运行示例：`go run ./cmd/sched`

## 验证

`sched.SolveBruteForce` 枚举全排列（n ≤ 10），使用完全相同的目标比较器。
测试覆盖：

- 300 组随机小规模实例（非对称换型矩阵、松紧混合的截止时间）与全排列逐一比对
  （最大迟交量、总换型时间、序列三者一致）；
- 手工构造的非对称用例：方向不同换型时间不同，验证不假设对称性；
- 并列用例：完全对称的实例必须返回下标字典序最小的序列；
- 时间表自洽性与输入校验。

`go test ./sched/`
