# certcache

基于证书的图查询验证缓存（Go)。缓存为可达性和最短路径查询保存路径证书
及其依赖边的版本，图变更时按证书类型做定向失效，并支持用全量重新验证
核对缓存的正确性。

## 证书类型（分开管理）

- **可达性证书 `ReachCert`**：一条从源到目标的路径 + 路径上每条边的版本。
  删边或改权只失效依赖该边的证书；新增边不影响（可达性对加边单调）。
- **最短性证书 `SPCert`**：最短距离 + 最短路径 + 依赖边版本 + 缓存时的加边
  计数器。依赖集是 Dijkstra 在目标出栈前松弛过的所有边（非负权重下，集合
  之外的边不可能影响该距离）。任何新增边都会使其失效。

## 失效规则

| 图操作   | 可达性证书         | 最短性证书         |
|----------|--------------------|--------------------|
| 删边     | 仅失效依赖该边的   | 仅失效依赖该边的   |
| 改权     | 仅失效依赖该边的   | 仅失效依赖该边的   |
| 加边     | 不失效             | 全部失效           |
| 版本回绕 | 全部失效（代际拒绝）| 全部失效（代际拒绝）|

## 版本与回绕拒绝

每条边的版本为 `{Value uint8, Gen uint64}`，每次变更 `Value` 自增；边删除后
保留版本墓碑，重新加边时延续序列而不复用旧版本。`Value` 越过 255 回绕时，
全图代际 `Gen` 自增并清空缓存——旧证书记录的版本即使数值再次重合，也会因
代际不匹配而被拒绝。

## 全量重新验证

`Cache.VerifyAll(g)` 对缓存中每个存活的证书做从零重算（路径逐边走查 +
Dijkstra 复算距离），用于核对定向失效没有留下过期证书。

## 运行

```sh
go test ./...
```

## 文件

- `graph.go` — 带版本的图与变更事件
- `cert.go` — 两类证书定义
- `cache.go` — 分类型证书存储、定向失效、全量核对
- `engine.go` — 查询引擎（BFS / Dijkstra）与证书构造
- `verify.go` — 证书的全量重新验证
- `certcache_test.go` — 定向失效、类型分治、回绕拒绝与随机化交叉核对测试
