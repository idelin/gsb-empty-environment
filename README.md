# bootjournal

给双镜像设备的Go更新库实现可恢复提交日志。镜像校验完成后才允许改变启动槽，首次启动需确认，连续两次未确认回退；防回滚计数只能在确认之后推进。用内存闪存模拟只能由1写0、整页擦除以及逐字掉电，枚举写入前缀验证重启时至少有一个可验证镜像。

## 设计

- `flash.go`：内存 NOR 闪存模型。位只能 1→0（`Program`），按整页擦除（`ErasePage`），掉电边界为 4 字节字；`ArmFault` 可在任意一次字编程/页擦除后注入一次性掉电。
- `journal.go`：只追加的提交日志。每条 64 字节记录采用两阶段提交（先写 torn 标记、再清 commit 标记，均为 1→0 且位于 CRC 覆盖区之外）；日志写满时在记录 0 处折叠为 snapshot 并擦除其余页，保证任意时刻重放都能还原状态。
- `device.go`：双槽状态机。
  - 更新只写非活动槽，活动槽永不被擦除；镜像先整体写入并通过 SHA-256 校验，头部就绪标记最后才 1→0 提交，之后日志才允许改变启动槽。
  - 新镜像在下次 `Boot` 时激活；激活本身不计未确认次数，之后连续两次未确认启动即回退到另一槽（该槽必须仍可验证）。
  - `Confirm` 是唯一推进防回滚下限（`MinVersion`）并清零失败计数的事件；低于下限的更新在任何闪存写入之前即被拒绝。

## 崩溃一致性验证

`powerloss_test.go` 先无故障跑一遍完整生命周期并统计突变操作总数，再对每个操作前缀注入一次掉电、重开设备并断言：

- 至少有一个槽持有可验证镜像，且活动槽自身可验证；
- 防回滚下限永不倒退；
- 重试基于“目标状态谓词”收敛，所有前缀的最终设备状态与无故障参考运行完全一致。
