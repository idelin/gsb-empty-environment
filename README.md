# 重协商双向密钥切换

安全通道两端分别完成密钥切换，接收新钥不代表发送也可以立即换钥。写供Go会话宿主调用的双向状态机，方向各有旧、新密钥及序号，只有本方向的切换标记认证通过才提交；控制消息与排队应用消息保留边界顺序，失败方向不得回到已废弃密钥。加解密由测试接口提供。用同时协商、控制帧部分写入和旧代迟到消息验证每条记录只用一个确定版本。

## 设计要点

- 发送方向与接收方向各自维护独立的代次（generation）、密钥与序号，互不影响。
- 接收侧仅在切换控制帧用预置新钥认证通过后才提交；发送侧在标记帧完整写入后提交。
- 每条记录在入队时冻结其代次、密钥与序号，短写只续传同一份已封帧字节，绝不二次加封。
- 旧代次在提交后仅作为“已废弃”密钥保留有限的迟到消息窗口，不能重新成为活动密钥。
- 控制标记与应用消息共用同一有序字节流，应用消息边界通过长度前缀帧保留。

## 宿主接入

1. 实现 `Cipher` 接口（`Seal`/`Open`/`Overhead`），每个代次、每个方向各给一个实例。
2. 用 `NewSession(transport, sendKey, recvKey)` 建立会话。
3. 换钥时分别调用 `InstallSendRekey`/`InstallReceiveRekey` 预置新钥，再用 `SwitchSend` 发出标记。
4. 持续调用 `ReceiveMessage`；切换标记在内部消费，仅返回应用消息。

## 验证场景

`go test ./...` 覆盖：同时双向协商、控制帧分片部分写入、旧代迟到消息窗口、
标记认证失败不回退密钥，以及重放拒绝。
