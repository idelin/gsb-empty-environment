电信信令与高可靠传输网关在实现 SCTP（RFC 9260）四次握手与多宿主（Multihoming）关联管理时，若 `INIT-ACK` 签发的 State Cookie 未用服务端轮换密钥做 HMAC-SHA256 认证并绑定双端 Verification Tag、初始 TSN 与地址列表，或未验证 `INIT`/`ASCONF` 携带的对端补充 IP 地址归属（路径验证 `HEARTBEAT`），盲攻击者可发动关联劫持、将流量重定向至第三方受害 IP 实施反射放大，或利用旧 Cookie 重放重置合法关联。为 Go 传输安全宿主实现可导入的 SCTP 四次握手 Cookie 认证与多宿主路径验证状态机包，严禁联网（仅用标准库 `crypto/hmac`/`crypto/sha256`）。组件严格实现：（1）服务端无状态 `INIT` → `INIT-ACK` State Cookie 签发与 `COOKIE-ECHO` 验真：Cookie 封装 `(init_tag, my_tag, init_tsn, my_tsn, peer_addrs, creation_time, lifespan, nonce)` 及双代轮换密钥 HMAC-SHA256，硬拒绝篡改、过期、跨源地址重放、Verification Tag 为 0 或非法 `Initiate Tag` 的伪造包；（2）所有已建立关联的数据/控制块强制校验包头 `Verification Tag` 精确匹配，且 `DATA` 块 TSN 必须落入严格滑动接收窗口（拒绝离径盲注与重放）；（3）多宿主防重定向门禁：对端在 `INIT` 宣告的次级 IP 或后续 `ASCONF` 新增 IP 在完成独立随机 Nonce 的 `HEARTBEAT` → `HEARTBEAT-ACK` 路径确认前，一律标为 `UNCONFIRMED`，严禁向未确认地址发送业务数据（彻底阻断第三方 IP 反射放大）。附伪造 Cookie、过期重放、未确认次级 IP 反射阻断与 TSN 窗口外盲注拒收测试。
