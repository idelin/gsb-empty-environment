# 自适应心跳健康度探测器（φ-Accrual Failure Detector）

基于**失联概率评估**的自适应心跳系统，仿 Apache Cassandra 的 φ-Accrual Failure Detector。
不采用固定超时阈值，而是根据历史心跳到达间隔的分布动态计算节点崩溃的**怀疑度 φ**，
当 φ 超过阈值时触发租约回收。

## 核心原理

对每次心跳记录到达间隔，维护滑动窗口估计间隔分布 N(μ, σ²)。当前等待时长为 `t` 时：

```
P_later(t) = 1 - F(t)        // 等待 t 之后心跳才到达的概率（F 为正态 CDF）
φ(t)       = -log10(P_later(t))
```

φ 每 +1，误判概率下降一个数量级：φ=1 → ~10%，φ=8 → ~10⁻⁸。常用阈值 8 / 12 / 16。

- **抖动容忍**：偶发延迟尖峰若处于历史方差范围内，φ 仍远低于阈值，不误警；
- **果断失效**：真正断网时 φ 随等待时间指数级增长，迅速越过阈值；
- **自适应衰减**：发送端采用类 AIMD 策略——网络稳定时心跳间隔按衰减因子
  乘性上调（降低开销），观测到异常偏离时快速收缩（加快取证）。

## 目录结构

```
src/
  phiAccrualDetector.ts   # φ 怀疑度计算（滑动窗口 + 正态 CDF）
  heartbeatWindow.ts      # 心跳间隔滑动窗口（增量均值/方差）
  adaptiveHeartbeat.ts    # 发送端自适应间隔控制器（衰减/收缩）
  leaseManager.ts         # 租约生命周期：held → reclaimed
  statistics.ts           # erf / 正态 CDF
  simulatedNetwork.ts     # 确定性模拟网络（抖动/尖峰/分区）+ 固定超时对照组
test/                     # Node.js 内置测试（node:test）
examples/demo.ts          # 运行样例：φ 探测器 vs 固定超时
```

## 运行

要求 Node.js ≥ 22.6（利用 `--experimental-strip-types` 直接运行 TypeScript，
零依赖、无需编译）。Node ≥ 23.6 可去掉该 flag。

```bash
npm test        # 运行全部测试
npm run demo    # 运行对照样例
npm run typecheck   # 可选：需自行安装 typescript（npm i -D typescript）
```

## 验收场景（测试与样例共用）

场景：心跳基线 1000ms，常态抖动 σ=150ms，每 25 拍叠加 +600ms 尖峰，第 150 拍后断网。

| 指标 | 固定超时（1400ms） | φ 探测器（阈值 8） |
| --- | --- | --- |
| 抖动期误判 | 6 次（引发重选风暴） | 0 次（最大 φ=5.84） |
| 断网检测 | 1400ms 后 | ~2200ms 后，φ=9.82 果断回收租约 |

## 关键测试

- `预热期不判定失效`：样本不足时 φ 恒为 0，避免冷启动误判；
- `φ 随等待时间单调增长`：怀疑度语义正确；
- `常态抖动+偶发尖峰不触发误警`：验收边界——短时抖动不误判；
- `真正断网时 φ 果断越过阈值`：验收边界——失效检测果断且延迟有限；
- `minStdDeviation 防零方差爆炸`：完全等间隔心跳下 φ 仍有限；
- `自适应衰减/收缩/escalate`：间隔控制器行为；
- `租约回收幂等`：回调恰好触发一次。
