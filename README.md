# 原子操作内存序反例

`netsec` 是供 Go 模型宿主调用的弱内存序执行枚举包，用于回答一个具体的并发
安全问题：**弱内存序是否允许消费者读到尚未发布的秘密缓冲区？**

## 能力边界

- 最多 `MaxThreads`(3) 个线程，每线程最多 `MaxEventsPerThread`(4) 个读写或
  屏障事件；每个内存位置带一个固定在最前的初始写。
- 输入：程序、读自边（`ReadFrom`，缺省读初始写）、允许重排的相邻事件对
  （`Pair`，缺省按内存序推断），以及断言失败谓词。
- 输出：满足全部约束的连贯全序执行，或断言失败的最短见证 `Witness`。

## 枚举模型

1. 构建先行发生（happens-before）偏序：
   - 线程内程序序，显式允许重排的相邻弱序事件对除外；
   - 每条读自边强制写先于读；
   - 发布/获取同步边，含发布写-获取读与发布屏障-获取屏障（C11 风格围栏）。
2. Warshall 求传递闭包，闭包成环即判定读自边/重排关系自相矛盾。
3. 对偏序做拓扑线性序枚举，并在放置每个读时强制**每位置写序（连贯性）**：
   读只能观察到该位置当前最近一次写。
4. `ShortestWitness` 用分支限界搜索断言失败的最短前缀，再补全为完整执行。

## 参考实现

`ReferenceEnumerate` 不做剪枝：对全部事件做全排列，再逐条检查程序序、先行
发生闭包与读连贯性。事件数超过 `MaxReferenceEvents`(9) 时返回
`ErrLimitExceeded`。测试对每个读自边组合差分比较两个实现，结果必须一致。

## 发布/获取与普通读写的差异

对消息传递范式 `T0: W(data)=secret; W(flag)=1` 与 `T1: R(flag); R(data)`：

- 当 flag 为发布写/获取读时，`R(data)` 读到新秘密而 `R(flag)` 仍读到旧标记
  的读自边组合被先行发生关系排除（`ErrInfeasible`），秘密不会提前泄露。
- 当全部为普通读写时，两个读允许重排，存在 `R(data)` 先观察到秘密的合法
  执行，`ShortestWitness` 给出最短失败见证（前缀长度 2）。
- 用发布屏障 + 获取屏障替代原子语义可重新建立先行发生关系，阻止同样的泄漏。

运行 `go test ./...` 可复现上述对照与穷举差分验证；`Example` 演示完整调用。
