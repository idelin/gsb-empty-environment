# 存储转发中的部分地址别名

处理秘密的代码先向私有地址store，再从公开地址load，错误的部分地址匹配可能把秘密值推测转发给后续probe。实现供Go安全实验宿主调用的有限流水线模型：地址12位、值8位，store缓冲至多4项，每项含完整地址、值和是否提交；load的架构值来自内存或最近的同完整地址store，预测器却从最近的低6位地址相同store转发，若完整地址不同则在最多4步后发现误配并回滚寄存器，但probe(reg)以寄存器低4位作为观察组产生的16组观察不回滚。指令为store、load、xor常量、probe与barrier，最多16条；barrier先解析全部未决load再继续。攻击者控制最多2个公开地址低6位和公开内存，秘密只进入指定store值，所有地址的高6位由宿主固定且公开。搜索公开输入相同、秘密不同、架构probe轨迹相同但推测probe轨迹不同的输入对，输出每个load选择的store、解析时刻和回滚前后寄存器。架构执行若已泄密要单列原有漏洞；预算耗尽为未知。用无别名、真同址转发、最近store优先、barrier修复和两个未决load验证，逐周期参考不能把最终架构状态相同误写成无泄漏。
