支持双向 TLS（mTLS）按路径阶梯鉴权的边缘网关在实现 TLS 1.3 握手后客户端认证（Post-Handshake Authentication，RFC 8446 Section 4.6.2）时，若向未声明 `post_handshake_auth`（扩展 49）或在 HTTP/2（RFC 8740 / RFC 9113）多路复用连接上的客户端发起 PHA、未强制要求 `CertificateRequest` 携带唯一非空 `certificate_request_context` 并与客户端 `Certificate`/`CertificateVerify`/`Finished` 精确绑定，或忽略 `CertificateVerify` 与 `Finished` 必须覆盖包含原始握手转录的完整转录哈希，攻击者可重放旧客户端证书证明或跨请求混淆认证身份。为 Go 传输安全宿主实现可导入的 TLS 1.3 PHA 状态机与转录绑定验证包，严禁联网（仅用标准库 `crypto/ecdsa`/`crypto/hmac`/`crypto/sha256`）。组件严格实现：（1）准入前置硬门禁：仅当初始 `ClientHello` 显式携带空载荷 `post_handshake_auth` 扩展且协商 ALPN 非 `h2`（RFC 8740 硬禁止 HTTP/2 上使用 PHA）时才允许服务端发送 `CertificateRequest`；（2）上下文与防重放绑定：每次 PHA 必须生成唯一非空 `certificate_request_context`（拒绝空上下文与同连接内重复上下文），强制客户端响应的 `Certificate` 精确回显对应待决上下文，并支持按策略拒绝未请求的 `Certificate` 注入与并发未决上限控制；（3）完整转录与密码学验证：精确按 RFC 8446 Section 4.4.3/4.4.4 计算 `Transcript-Hash(Handshake Context || CertificateRequest || Certificate)` 校验客户端 `CertificateVerify`（含 64 字节 `0x20` + `"TLS 1.3, client CertificateVerify"` + `0x00` 前缀）及后续 `Finished` HMAC（使用 `client_application_traffic_secret` 派生的 `finished_key`），仅在三者全部通过后原子升级连接认证主体。附 HTTP/2 PHA 拦截、空/重复上下文拒绝、跨连接 `CertificateVerify` 重放与完整转录向量测试。
