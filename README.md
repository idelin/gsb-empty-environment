加密卷升级会同时留下两套元数据，校验和正确也可能引用正在重写的密钥槽。写一个可导入的 Go 恢复包给卷宿主调用。输入是只读块镜像及选定的当前信任根；两个头各自包含代次、父头摘要、槽区间、加密段区间和已签名的槽到段授权。每个槽由多个独立写入单元组成，单元带版本和内容承诺；范围可以相交但不可将同一物理单元的新内容解释成旧槽。只有全部引用经核对且没有混合代次的头可用于解锁，冲突的同代有效头报分叉。另给目标头、可用备用单元、有限写入及冲刷动作，单次冲刷之前的写在崩溃时可持久化任意子集，跨冲刷有序；至多 16 个动作。规划最少冲刷次数，使每个崩溃镜像都至少有一套完整受信授权，可使用旧头或新头，但任何已不可撤回的撤销都不能被旧头恢复，且禁止在未冲刷备用槽单元前就更新根头指针。将撤销承诺作为单独可靠单调寄存器，写该寄存器也算动作。无安全计划须给可核验原因，状态预算不足须返回未知。用内存块设备穷举小例的持久化子集，对照重叠槽、同代分叉、两次写同单元和撤销提交早于备用头的情况，不依赖真实设备。

## `volrecover` 包

导入路径：`prescreen.local/ps-3e4b4cd13e/volrecover`

- `Analyze(view, root)`：只读校验签名、单元版本/承诺、父头链，识别同代分叉（`ReasonFork`）与混合代次（`ReasonMixedGeneration`），并按镜像内的单调撤销寄存器过滤旧头。
- `BuildPlan(PlanRequest{...})`：返回 `*Plan`、`*UnsafePlan`（可核验原因）或 `*UnknownPlan`（动作/枚举预算不足）。计划最少冲刷，保证每个崩溃子集都保留一套完整受信授权。
- `ExhaustCrashes(view, actions, limit)`：在 `MemDevice`/`MemView` 上枚举单冲刷内任意持久化子集、跨冲刷有序前缀，无需真实设备。
- `ValidateOrdering(actions, durable...)`：独立校验“先冲刷备用单元/新头，再写根指针；撤销寄存器写入不得早于新头冲刷”。

动作总数（含撤销寄存器写与冲刷）受 `MaxActions = 16` 限制；超出返回 `ReasonBudgetExceeded` 的 `UnknownPlan`，崩溃状态枚举超出限制返回 `ReasonEnumerationLimit`，均为未知而非判定不安全。
