# 插件加载器（计划器 + 生命周期模拟）

TypeScript 实现的插件加载器，覆盖前置插件（硬依赖）、可选依赖、冲突范围、
失败级联卸载与最小冲突解释。

## 结构

- `src/semver.ts` — 轻量版本范围匹配（`^` `~` `>=` `<=` `>` `<` `=` `*` `||` 与组合区间）。
- `src/planner.ts` — 计划器：把请求解析成可执行的 `Plan`。
- `src/loader.ts` — 生命周期模拟：初始化、动态请求、失败级联、选择性卸载。
- `src/types.ts` — 插件清单 / 上下文 / 注册表类型。

## 计划器行为

- 每个插件名从注册表选择满足全部约束的最高版本；逐请求提交，某个请求失败
  （缺前置、版本不可满足、冲突）只拒绝该请求，**保留其余可独立工作的插件**。
- 可选依赖能装则装；缺失、版本不符或引入冲突时记入 `plan.optionalSkipped`，
  绝不拖垮宿主。
- 冲突解释（`ConflictExplanation`）只保留最小边集：从请求根到冲突双方的最短
  依赖链 + 冲突边，再经贪心删边验证（删除任一边后冲突双方不再同时可达即保留）。

## 生命周期行为

- 按拓扑序初始化；`init` 抛错时该插件标记 `failed`，仅卸载**已加载且硬依赖
  它**的部分（反向拓扑序调用 `dispose`），可选依赖者与无关插件保持 `active`。
- 尚未初始化且硬依赖失败插件的插件直接标记 `failed`，其 `init` 不会被调用。
- `ctx.require(name)` 支持初始化回调内动态请求：已 `active` 的直接返回现有实例
  （绝不重复初始化，`initCounts` 恒为 1）；`planned` 的按需初始化一次；不在计划
  中但注册表可解析的，先扩展计划再初始化；循环动态请求会被检测并使双方失败。

## 运行测试

需要 Node >= 22.6（利用原生 type-stripping 直接运行 `.ts`）：

```sh
node --test test/planner.test.ts test/loader.test.ts
```
