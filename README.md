日志结构文件系统（LFS/F2FS）采用追加段写与后台段清理（Segment Cleaning）：选择回收段若仅按利用率最低排序，会反复搬运刚写入马上又要被覆盖的热段导致严重写放大，而采用经典收益-年龄公式 `score = ((1 - u) * age) / (1 + u)`（`u` 为存活块占比、`age` 为段内最年轻块距今时长）并按冷热分离写回不同目标段才可收敛；同时崩溃恢复必须校验双检查点槽（CP0/CP1）的头尾双 CRC 与递增版本号，再沿 fsync 节点链做前滚恢复（Roll-Forward），期间绝不能把未 fsync 的孤儿块或已被覆盖的旧块复活。为文件系统存储层交付可导入的 Go 段清理与双检查点恢复包。组件维护段数组（每段固定 `B` 块及 Segment Summary 反向指针 `(ino, blkIdx, ver)`）、节点地址表（NAT）、热/冷双当前追加段以及支持显式快照钉住历史块版本的快照表。规则：1）精确判断某物理块存活——仅当 NAT 当前映射仍指向该物理块 **或** 存在活跃快照仍引用该物理块时为存活（快照删除后原本仅靠快照保活的块自动转为可回收垃圾！）；2）段清理按 `((1 - u) * age) / (1 + u)` 选出最高分候选非活跃段（当 `u == 1.0` 得分为 0 跳过；空段 `u == 0` 无需搬移直接立即可回收！），将存活块按热度阈值分流写入新热段或新冷段并原子更新 NAT/快照指针，若搬移过程中空闲段触及紧急水位须保底不死锁；3）检查点写入采用 CP0/CP1 交替双槽（含首尾版本号与 CRC，模拟半写撕裂时自动回退到另一有效旧槽），崩溃前滚从最新完整检查点之后顺次重放带完整 `fsync` 标记与有效校验和的连续节点块链，遇到校验错、版本号断层或非 fsync 尾块即精确停止。验收覆盖冷热双峰负载下收益-年龄选段、快照钉住与释放后回收、CP 槽撕裂回退旧槽、fsync 链前滚恢复丢弃未落盘尾写以及全块守恒校验。
