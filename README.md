# hyperprover — 超图推导求解器

给定一组超边（全部前置就绪后产生目标，同一目标可由多条超边产生）和部分初始事实，
求解：

1. **可推出集合**：从初始事实出发经超边前向链式触发所能推出的全部节点；
2. **每点最小成本证明**：每个可推出节点的最小成本证明 DAG —— 证明成本为其中
   各超边成本之和，**共享证明节点只收费一次**（同一条超边在证明中至多出现一次）。

## 为什么不是逐点最短路

共享子证明只计一次费，使"分别对每个节点求最短路再相加"会重复计费；而把共享
考虑在内后，问题等价于在超图上求最小成本推导 DAG（AND-OR 图上的最小证明，
一般情形是 NP 难的）。因此本求解器采用：

- **有限精确搜索**：在"已证节点集合"（位掩码）状态空间上跑 Dijkstra。状态只增
  不减、成本非负，因此每个节点第一次被弹出时的成本即其最小证明成本；父指针
  回溯即得证明 DAG。状态数由 `-max-states` 限制（默认 200000），超出即截断，
  已记录的节点仍是精确的。
- **上下界**（始终计算，截断后仍有效）：
  - 下界 `LB(v) = min_e (cost(e) + max_p LB(p))`：经 e 证明 v 必然包含每个前置的
    完整子证明，故总成本至少是最贵的那个前置的最小成本；
  - 上界 `UB(v) = min_e (cost(e) + Σ_p UB(p))`：树形展开（共享子树按次计费）的
    最小成本，最优 DAG 证明展开后即为某个树形证明，故不会低估。
  - 两者都是超图上的单调递推最小不动点，用广义 Dijkstra（标号设定）精确求解。
- **循环自证**：前向闭包语义天然拒绝纯循环自证（"A 需 B、B 需 A"而无基础事实
  时两者皆不可推出）；有事实锚定的环不受影响。

## 枚举核对

`enumerate.go` 对小规模超图（≤24 条边）枚举全部超边子集：子集能证明目标当且仅当
目标落在其前向闭包中（闭包构造自动保证无环），成本为子集中各边成本之和（共享前提
自然只计一次）。`random_test.go` 用 300 个随机小超图将精确搜索与枚举对拍，并校验
每个返回证明的点火顺序合法、成本一致、`LB ≤ cost ≤ UB`。

## 用法

```sh
go build -o hyperprover .
./hyperprover -f example.json
./hyperprover -max-states 50000 -f example.json   # 限制精确搜索预算
./hyperprover -bounds-only -f example.json        # 只算上下界
cat example.json | ./hyperprover                  # 从 stdin 读
```

输入 JSON：

```json
{
  "facts": [{"name": "ore", "cost": 0}],
  "edges": [{"id": "smelt", "from": ["ore", "energy"], "to": "metal", "cost": 3}]
}
```

- 初始事实视为零前置超边，其成本仅在实际被使用时计一次（默认 0）；
- 边成本必须非负；`id` 可省略（自动命名 `e0, e1, ...`）；
- 前置永不可产的边为死边，求解前自动剔除。

输出：可推出集合、每节点成本（精确值或 `[下界, 上界]`）、以及每个精确节点的
最小成本证明（按点火顺序列出，标注共享前提）。

## 复杂度

- 精确搜索：O(2^n · m)，n 为可产节点数（≤62），m 为边数；适合小中超图或配合
  状态预算截断；
- 上下界：O((n + m) log n)，任意规模可用；
- 枚举核对：O(2^m · m)，仅用于小规模验证。

## 测试

```sh
go test ./...
```

覆盖：共享前提只计一次、纯循环自证被拒绝、事实锚定的环、同目标多边取最小、
事实成本按使用计费、状态预算截断后界限仍有效、随机小超图与枚举对拍。
