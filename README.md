安全启动代码面临双故障注入（电压毛刺跳过指令叠加寄存器翻转或条件反转）时，单点保护指令本身可能与主校验一并被击穿，给 Go 安全回归宿主写可导入的双故障分析与修补组件。自定义程序至多 32 条指令，含 6 个布尔寄存器与 1 个有界 4 位计数器寄存器（支持 `inc`/`dec`/`jz`），新增 `emit(tag)` 可观察事件指令；指令仍覆盖读公开位、读验签结果位、`and`/`not`、条件跳转、`unlock` 与 `halt`（至多 8 个公开输入位，循环上限 64 步）。故障预算提升为最多 `K = 2` 次故障（每次可选跳过非 `halt` 指令、翻转布尔寄存器或反转一次条件跳转方向）；攻击者不能改验签位。输入给定至多 8 个带代价权重的候选插入点及若干禁止修改的只读 ROM 区间，在排除无故障原漏洞与只读禁区后，求总代价最小的保护插入方案，要求修补后不仅阻止所有 `K <= 2` 故障轨迹到达 `unlock`，还必须保证所有正常有效验签输入下的 `unlock` 次数及完整 `emit(tag)` 事件序列与原程序完全一致。用独立全枚举执行对照双跳击穿单守卫、寄存器翻转与 `emit` 序列一致性约束。
