# rga-list-crdt

面向协同编辑场景的列表复制库（RGA 风格 CRDT），TypeScript 实现。
支持两名（或更多）编辑者离线并发编辑，之后在任意投递顺序下合并收敛。

## 设计

### 稳定标识

每个元素获得不可变且全局唯一的 `Id = { counter, replica }`：

- `counter`：副本内的 Lamport 式计数器，单调递增；应用远端操作时会推进到
  已见最大值，保证本地新 id 永远新鲜且唯一。
- `replica`：副本唯一标识，用于打破计数器并列。

id 一旦发出生效即不变，删除、乱序投递、重复投递都不影响元素身份。

### 确定性排序

插入操作携带锚点 `parent`（其前驱元素 id，`null` 表示表头）。共享同一锚点
的兄弟节点按全序比较器 `(counter 降序, replica 降序)` 排列。可见序列是对
该树结构的前序遍历。排序只依赖操作集合本身，与投递顺序无关，因此所有
副本得到完全一致的序列。

### 墓碑删除

删除只给节点打标记，节点保留在树中：

- 被删除的元素仍可被新插入引用为锚点（离线期间另一副本可能正挂在它后面）；
- 已有元素的相对顺序不因删除而改变——幸存者在最终序列中保持原有先后
  （有测试以子序列性质验证）。

### 乱序到达与缺失前驱缓冲

- 插入的锚点尚未到达时，操作进入因果缓冲区；每应用一个新插入后反复冲刷
  缓冲区，直到没有可推进的操作为止（支持任意长度的缺失链）。
- 删除直接记录进墓碑集合，与插入可交换：无论删除先于还是后于目标插入
  到达，结果一致。
- 所有操作幂等，重复投递安全。

### 收敛性论证

终态完全由操作集合决定：父子链接不可变、兄弟顺序是确定性全序、墓碑由
集合成员关系决定。投递顺序只影响缓冲等待时间，不影响最终结构。测试通过
对同一操作集的大量随机洗牌投递，验证所有副本的完整结构转储（含墓碑）
逐字节一致。

## 使用

```ts
import { RgaList } from "./src/rga-list";

const a = new RgaList("alice");
const op1 = a.insertAt(0, "hello");      // 本地编辑，返回可分发的操作
const op2 = a.insertAt(1, "world");
const op3 = a.deleteAt(0);               // 墓碑删除

const b = new RgaList("bob");
b.apply(op2);                            // 乱序投递：自动缓冲等待
b.apply(op3);
b.apply(op1);                            // 前驱到达，缓冲冲刷
b.toArray();                             // ["world"]
```

```sh
npm run build     # tsc -> dist/
npm test          # 编译并运行全部测试
```

测试覆盖：同位置并发插入的确定性收敛、墓碑锚点插入、缺失前驱缓冲与
整链冲刷、删除先于插入到达、重复投递幂等、随机操作集在 20 种子 × 25
种投递顺序下收敛、删除锚点后幸存者相对顺序保持。
