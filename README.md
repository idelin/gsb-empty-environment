# 稀疏文件敏感空洞

备份恢复器将稀疏空洞映射到复用块时可能泄漏旧数据。给Go恢复宿主实现区间写入包，输入已认证的数据区间和空洞区间，要求覆盖整个逻辑长度且互不重叠；空洞读取恒为零，不能依赖新分配块的原内容。以带脏页的内存块设备测试对齐边界、部分末块和中途失败，发布前逐段核对覆盖证明。

## 包 `netsec`

- `Range` 描述镜像的一个半开区间，`Data` 区间携带已认证载荷，`Hole` 区间载荷必须为 nil。
- `validateRanges` 要求区间从偏移 0 开始、有序、互不重叠、无缺口，并恰好结束于逻辑长度。
- `RestoreWriter.Restore` 逐块在零初始化缓冲区中装配整盘内容：数据字节来自认证载荷，空洞字节显式清零，然后整块写入；从不读取或合并目标块的旧内容，因此复用块里的陈旧数据无法存活。
- 每次成功写入一块后记录覆盖账本（`Segment`）。`Verify` 逐段核对账本连续覆盖 `[0, size)`，`Publish` 在其基础上回读每个空洞段，证明设备读出恒为零后才允许发布。
- 写失败时账本只包含已成功落盘的块，`Verify`/`Publish` 返回 `ErrIncomplete`；修复设备后可重新调用 `Restore` 完整重试。

## 验证

`go vet ./...` 与 `go test -race ./...` 必须通过。测试使用预填非零脏页（`0xDB`）的内存块设备，覆盖对齐边界、块内未对齐切换、部分末块、全空洞镜像、中途注入故障及重试、空洞回读防篡改、空镜像与全部非法分区形态。
