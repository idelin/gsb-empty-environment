多授权服务器（AS）架构的 API 网关在落地 OAuth 2.1、PAR、JAR 与 DPoP（RFC 9449）时，若令牌绑定校验忽略 `htu` 规范化、允许跨 AS 混用 `iss`/受众，或在令牌交换（RFC 8693）委托链中丢失主体绑定，攻击者窃取 Bearer 或 DPoP 证明即可重放请求或冒充上游身份。为 TypeScript 认证网关实现可导入的零外部加密依赖（仅用 Node 内置 `node:crypto`）OAuth 2.1 + DPoP 全链路校验与防混用引擎，严禁联网。引擎提供授权请求（PAR/JAR）、令牌签发/交换与资源访问三个核心核验入口：对 DPoP Proof JWT 严格校验 `typ=dpop+jwt`、非对称允许算法白名单（拒绝 `none` 与对称算法）、头内嵌入公钥不含私钥字段（`d`/`p`/`q`）、RFC 7638 规范 JWK 指纹 `jkt` 与访问令牌 `cnf.jkt` 精确匹配、`htm` 方法全等、`htu` 去除 query/fragment 后的严格方案-主机-端口-路径匹配、`ath` 等于访问令牌 SHA-256 base64url 摘要，以及 `iat` 时钟偏斜窗口与单次 `jti` 防重放账本（要求在内存上限触发驱逐时，通过提升最小可接受时间戳前沿确保绝不因缓存淘汰重新放行旧 `jti`）。对授权回调与委托交换强制校验 `iss` 绑定（防 Mix-Up 攻击）、PKCE `S256`、多跳 `act` 委托链深度上限与权限单调衰减（子令牌 `scope` 须为父令牌严格子集）。使用真实 ES256/EdDSA 密钥实测跨 AS 混用、重放前沿驱逐边界、URL 路径变体、`ath` 篡改与委托提权全部拒收。
