# OpenPGP信任签名深度与域范围

OpenPGP 的信任签名可把验证权委托给介绍人，并用正则限制可认证的邮箱域，攻击者作为介绍人可越出域范围认证，或重复签名凑够信任量。给TypeScript密钥环库写供用户标识有效性计算调用的信任包，密码学验签由调用方注入：信任签名携带级别与数量（数量 120 为完全信任，60 为边缘），在此基础上，本题规定：用户标识有效当且仅当存在从自有根密钥出发、每段级别递减的路径，且累计数量不低于 120；信任签名的正则只允许 <[^>]+[@.]域名>$ 形式，其他形式整条无效，用户标识的邮箱须匹配；同一签发者对同一用户标识只计最新一份，已撤销或过期的不计；深度超过根给定上限的不计。用越域认证、重复签名、撤销与深度验证。

## 用法

`trust.ts` 导出 `isUserIdValid(targetKeyId, userId, signatures, root, verify)`：

- `signatures`：密钥环上收集到的信任签名（`TrustSignature`），携带 `level`、`amount`、可选 `regex`、`createdAt`、可选 `expiresAt` / `revoked`。
- `root`：自有根密钥 `keyId`、深度上限 `maxDepth`，可选根级别 `level`（默认 255）、所需累计数量 `requiredAmount`（默认 120）与当前时间 `now`。
- `verify`：调用方注入的密码学验签回调，返回 `false` 的签名整条不计。

判定规则：从根出发的每条路径上级别严格递减、深度不超过 `maxDepth`；边上的正则（只允许 `<[^>]+[@.]域名>$` 形式，否则整条签名无效）约束其下游所有用户标识的邮箱；同一签发者对同一用户标识只计最新一份未撤销、未过期且验签通过的签名；路径累计数量（每条上限 120）达到 120 时用户标识有效。

运行测试：`node --experimental-strip-types --test`（需要支持类型擦除的 Node 版本）。
