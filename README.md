# MessagePort转移后旧文档仍能发送

页面把MessagePort转给隔离iframe后，若原端点没有原子失效，旧文档可复制能力继续发送特权消息。给TypeScript浏览器宿主实现可导入的端口能力模型：channel有唯一channelID和代次、两个endpoint，每端点绑定ownerDocumentGeneration、storagePartition、capabilitySet、状态Owned/Transferring/Transferred/Closed及有序消息序号。postMessage先核对Owned和调用文档，消息结构化克隆只允许原始值、数组、自有可枚举数据属性组成的无原型记录，读取时不得调用getter、ArrayBuffer和待转移端口；getter、函数、symbol和循环对象拒绝。转移是事务：冻结源端点，验证目标文档/分区和能力衰减策略，克隆消息成功后原子把端点owner换成目标、代次递增并使所有旧包装失效，再将消息入队；任一步失败恢复源Owned且零消息。ArrayBuffer转移同时使所有源视图detached，不能复制后再转。端口不可在同一转移图出现两次、不可转移自身对端形成环；关闭撤销排队未投递的特权请求。导航使该文档Owned端点关闭，Transferred端点不受旧文档导航影响。用两个文档与延迟投递调度器搜索待审实现中旧代包装在成功转移后post特权消息的最短轨迹，覆盖批量端口、克隆失败、重复引用和导航竞态。
