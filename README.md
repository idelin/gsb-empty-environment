多集群零信任网格通过 SPIFFE X.509-SVID 与 JWT-SVID 实施跨信任域联邦认证时，若校验器未严格限定 `spiffe://<trust-domain>/<path>` 唯一 URI SAN、未隔离各信任域的独立 Trust Bundle，或放过工作负载选择器（selector）通配符冒充，某个被攻陷的外部联邦域 CA 可签发目标本地信任域的伪造 SVID 接管核心服务。为 Go 零信任代理宿主构建可导入的 SPIFFE 联邦身份校验与工作负载证明策略包，严禁联网。组件严格按 SPIFFE 规范校验 URI 格式（ASCII 小写字母/数字/连字符/点/下划线组成的信任域，路径禁止 `.`/`..`/空段/百分比编码/查询与片段）：对 X.509-SVID 强制验证证书恰好仅含一个 URI SAN 且为合法 SPIFFE ID、不含 `cA=true`、具备合法 `KeyUsage`/`ExtKeyUsage`、使用该 SPIFFE ID 所属信任域对应且仅对应的 Trust Bundle 验签（严格禁止用联邦域 A 的根证书验证宣称属于域 B 的 SVID，防跨信任域越权签发），并校验目标服务白名单是否显式配置了 `federates_with` 该外部域。对 JWT-SVID 强制核验 `sub` 为合法 SPIFFE ID、`aud` 精确命中本地预期受众、`exp` 有效且不得超长、按 `sub` 所属信任域查找对应 JWKS 公钥验签并拒绝跨域 `kid` 碰撞。另实现工作负载证明注册匹配引擎：确保节点与进程选择器集合须全量精确匹配且拒绝高权限父进程伪造跨命名空间选择器。使用真实 ECDSA 密钥实测跨信任域伪造签发、多 URI SAN、路径规范化绕过与受众错配全部拒收。
