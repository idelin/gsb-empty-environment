权威 DNS 节点上线新视图前要回答一个问题：哪些可能的名称在两个视图里实际得到不同应答？名称的每个标签取自调用方有序字典（可有数千个），深度至多 40，不准枚举所有名字或只检验已缓存的名字。给区发布器实现可导入的 Go 规划包。两边各是一棵区树：某个名称可以有本区的 A、TXT、通配子节点或对子区的委派；委派携带具名服务端，视图内若该子区已装载则继续在那里查询，否则返回带服务端的转介。委派以下被父区记录遮住的名字不能偷偷使父区的空非终结点存在。本区内精确名称及空非终结点优先，未命中只尝试最近存在祖先的直接通配子节点；星号作为规则而非可查询标签。区顶点总存在，查 A/TXT 得到记录集、NODATA、NXDOMAIN 或转介；应答比较按类别和实际值集，忽略记录归属及内部路径。按深度优先级（浅者先），同深按从区顶点向叶的标签序，再按 A、TXT 排序，对不同答复的查询精确计数、反选第 k 个和求给定查询的名次；每次反选都能由两侧真实查询器重放。内存与构建时间可以随区文件、字典大小和深度上限增长，但不能与名字总数增长。测试用短字典独立穷举对照，另覆盖父区残留数据与子区同名、同答复但委派路径改变、精确空节点压制通配、根视图无差异但仅一个很深分支触发转介，以及计数超过 64 位。
