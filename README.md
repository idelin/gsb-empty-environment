高安全 TLS 网关与代码签名服务在核验 X.509 证书吊销状态（RFC 5280 CRL 与 RFC 6960 OCSP）时，若未校验 OCSP 委托响应者证书的 `id-kp-OCSPSigning` EKU 且由同一签发 CA 签发、未比对请求与响应中的 OCSP `Nonce` 扩展（OID `1.3.6.1.5.5.7.48.1.2`）或放任缺失 `nextUpdate` 的旧响应被永久重放（冻结攻击），抑或在处理 CRL 时忽略 `IssuingDistributionPoint` 范围限制与 `Delta CRL` 基础号（`BaseCRLNumber`）连续性，攻击者可重放吊销前的旧 OCSP/CRL 响应继续使用已泄露私钥的吊销证书。为 Go 密码安全宿主实现可导入的 RFC 5280 CRL 与 RFC 6960 OCSP 吊销状态深度验证包，严禁联网（仅用标准库 `crypto/x509`/`encoding/asn1`/`crypto/sha256`）。组件严格实现：（1）OCSP 响应验证：解析 `BasicOCSPResponse` 并验签，严格区分签发 CA 直签与授权委托响应者（委托证书必须由同一签发 CA 签发、有效期内、含 `id-kp-OCSPSigning` EKU，且若不带 `id-pkix-ocsp-nocheck` 则必须可验证自身未吊销）；校验 `CertID`（`issuerNameHash`/`issuerKeyHash`/`serialNumber`）精确匹配目标证书；校验 `thisUpdate <= now < nextUpdate` 且响应跨度不超过策略上限（硬拒绝缺失 `nextUpdate` 或超龄响应防冻结重放），并当请求带 `Nonce` 时强制响应 `Nonce` 恒定时间一致；（2）CRL 与 Delta CRL 联合验证：校验 CRL 签名与签发者 `cRLSign` KeyUsage、时间窗、`CRLNumber` 单调递增（阻断回滚旧 CRL）、`IssuingDistributionPoint` 覆盖范围匹配目标证书（防间接/分区 CRL 漏报），并正确合并 `Base CRL + Delta CRL`（校验 `BaseCRLNumber <= Base.CRLNumber` 及 `removeFromCRL` 语义）。附 OCSP 冻结重放、缺失 `OCSPSigning` EKU 伪造委托者、`Nonce` 错配、CRL 回滚与不完整分区 CRL 绕过测试。
