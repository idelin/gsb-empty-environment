PostgreSQL 堆页采用 32 位无符号事务号（`XID`）与多事务锁组（`MultiXactId`）记录元组生命周期，一旦忽略 32 位环形回绕或 `MultiXact` 语义，`VACUUM FREEZE` 就会灾难性地把刚提交的新数据当成历史死数据删掉，或者漏冻结导致整库回绕停服！核心规则包括：1）`0=InvalidXid`、`1=BootstrapXid`、`2=FrozenXid` 为三个特殊常量（不参与模 `2^32` 环形运算，`FrozenXid` 对所有快照恒可见！），普通事务号在 `[3, 2^32-1]` 内按有符号 32 位差值 `int32(a - b) < 0` 比较前后顺序（跳过 `0..2`）；2）元组的 `xmax` 字段在置有 `IS_MULTI` 标志时指向一个 `MultiXact` 成员数组——其中可能同时包含多个共享行锁（`KEY_SHARE`/`SHARE`）和**至多一个**真正的修改/删除事务（`UPDATE`/`DELETE`）；仅包含锁成员（或修改成员已中止）的 `MultiXact` 绝不能把元组判为已删除！3）给定全局活跃快照下界 `OldestXmin` 与冻结阈值 `FreezeLimit`（及 `MultiXactCutoff`），`VACUUM FREEZE` 扫描堆页时：物理清除所有确认对全部快照已死（`xmin` 中止，或 `xmax` 真实删除事务已提交且 `precedes(xmax, OldestXmin)`）的元组；对存活元组，若 `xmin` 已提交且 `precedes(xmin, FreezeLimit)` 则将其 `xmin` 原地冻结为 `FrozenXid`，对已过时或仅含已结束锁成员的 `xmax`/`MultiXact` 清除或重打包（仅保留仍活跃的锁成员！）；4）精确维护可见性映射位（Visibility Map）：仅当清理后页内**不存在任何死元组且全部存活元组对任意新老快照均可见**（`xmin` 已提交且 `< OldestXmin`，且无未决删除 `xmax`）时才置 `ALL_VISIBLE`；且只有当页内全部存活元组均已冻结且无任何残留 `MultiXact`/活跃 `xmax` 时才置 `ALL_FROZEN`！为数据库存储层交付可导入的 Go 32 位回绕 MVCC 可见性判定与 `VACUUM FREEZE` 页清理引擎。验收覆盖跨 `0xFFFFFFFF -> 3` 回绕边界的 XID 比较与冻结、含混合锁+中止/提交更新的 `MultiXact` 可见性与清理、活跃快照保护防误删以及 `ALL_VISIBLE` vs `ALL_FROZEN` 精确判定。
