HTTP/3 宿主要把数据报通道从旧连接迁到新连接，同时保留同一业务请求的授权。为 Go 分发器交付可导入的租约管理包。连接 ID、QUIC 请求流号、业务授权 ID 各有自己的命名空间，整数值相同不表示同一对象；每次建立或迁移都由宿主签发租约，绑定三者、租户和代次。对端可乱序送达数据报，网络确认与业务收件回执分开。请求允许有限的双路重叠期，数据报序号是 24 位环形数，发起时给出锚点和最多跨度，落在半圈分界的序号无法唯一展开必须拒绝。重复的同一逻辑序号、同一负载只能交付一次，双路收到同序号不同内容时冻结该请求并保留两份来源；不能通过比较到达时间选胜者。旧路径的确认不能释放新代的暂存区，接收端持久化状态与业务交付通过可重试的确认协议连接。明确提供 committed、pending、unknown 三态：崩溃在交付与回执之间时，只有宿主幂等收件箱给出确定结果才能标记完成。用可暂停收件箱穷举每个持久写点，测试流号重用、半圈歧义、迁移完成后迟到旧包、重复控制回执与两租户相同业务编号。
