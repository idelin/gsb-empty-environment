RFC 8955 BGP FlowSpec 允许通过 BGP 控制面向全网路由器动态下发细粒度 DDoS 清洗过滤规则，但其规则全序优先级、复合逻辑操作数与防劫持源验证（Validation Procedure §6）极易写错：1）**RFC 8955 §5.1 规范规则全序比较**：同一地址族下多条 FlowSpec 规则的优先级绝非按到达先后——必须逐组件类型按编号 `1 -> 12` 比较：对 Type 1（Destination Prefix）与 Type 2（Source Prefix），先取两前缀的公共最小长度比较前缀位（字节序更小者优先！），若公共部分完全相等则**掩码更长者优先**（更具体前缀优先！）；仅含一方有某组件类型时，组件类型编号更小者优先；对 Type 3..12（IP Protocol、Port、DestPort、SrcPort、ICMP Type/Code、TCP Flags、Packet Length、DSCP、Fragment），按规范化编码字节序字典比较！2）**RFC 8955 §6 防劫持验证（Validation Procedure）**：一条目标前缀为 `D` 的 FlowSpec 规则绝不可盲目下发——必须核对本地单播 RIB：条件 (a) 单播 RIB 中必须存在匹配 `D` 的最佳路由，且该最佳路由的接收相邻 AS（`neighborAS`）与本 FlowSpec 规则的通告邻居 AS 完全一致；条件 (b) 单播 RIB 中**所有比 `D` 更具体的子前缀路由**的最佳路径也必须同样来自该同一相邻 AS（防止非授权邻居借聚合大前缀恶意拦截他人子网流量！）；不满足任一条件即标为 `INVALID_FLOWSPEC` 禁止生效！3）**复合逻辑操作数求值与扩展团体动作合并**：支持 RFC 8955 数值操作数（`LT`/`GT`/`EQ` 任意位组合 + `AND`/`OR` 短路链）与位掩码操作数（`match`/`not` 精确匹配 TCP Flags 与 Fragment 位），按全序命中全部匹配规则并按 RFC 8955 动作语义合并（如 `traffic-rate 0` 丢弃优先、限速速率、VRF 重定向与 DSCP 重写，且支持 `terminal` 标志控制是否继续求值后续低优规则！）。为边缘网络清洗控制面交付可导入的 Go RFC 8955 FlowSpec 验证、全序排序与报文匹配引擎。验收覆盖 Type 1/2 公共前缀字节序与长掩码优先、跨组件编号优先级、§6 更具体子前缀异源 AS 拦截防劫持、复合 `AND`/`OR` 数值与位掩码求值以及 `terminal`/非 `terminal` 多规则动作合并。
