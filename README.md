面向对象虚拟机与静态编译器（HotSpot / GraalVM / Swift SIL 风格）依赖类层次分析（CHA）与快速类型分析（RTA）把昂贵的虚方法/接口动态分派消除为静态直接调用，但在同时存在单类继承、多接口默认方法（Default Methods）与私有/静态遮蔽时极易解析错目标方法：1）**类与多接口默认方法精确分派解析**：给定类型图（类单继承 + 任意多接口继承，含抽象方法、具体方法与接口默认方法），对任意具体类 `C` 解析方法签名 `m` 必须严格遵循标准三原则：(a) 沿类继承链向上找到的具体类实现永远压倒任何接口默认方法；(b) 若仅接口提供默认方法，则最具体子接口实现压倒父接口实现；(c) 若存在两个及以上互不为子接口的接口同时提供默认方法且未被类覆写，必须在编译期精确报告 `AMBIGUOUS_DEFAULT_METHOD` 错误！2）**CHA vs RTA 精确不动点收敛**：CHA 把接收者静态类型的全部子类型（含接口全部实现类）的解析目标并集作为候选集；RTA 则从入口函数集合出发联合维护“可达方法集 `ReachableMethods`”与“已实例化具体类集 `InstantiatedClasses`”——每发现 `new T` 把 `T` 加入 `InstantiatedClasses` 并重新唤醒所有先前被挂起的对 `T` 超类/接口的虚调用点，每发现新可达目标方法就扫描其函数体继续迭代直至不动点收敛，精准剪除从未被构造的死子类实现！3）**去虚化代码变换与投机 PIC 守护**：候选目标为 0 个标为不可达陷阱；恰好 1 个直接改写为静态直调 `direct_call`；恰好 2 个（配置开启投机多态内联缓存）生成精确类标识守卫分派 `if exactType == T1 -> direct(m1) else if exactType == T2 -> direct(m2) else virtual_fallback`！为编译器中端交付可导入的 Go CHA/RTA 去虚化分析与多态执行验证包。验收覆盖类覆写压倒默认方法、菱形子接口压倒父接口、平级双接口冲突报错、RTA 剪除未实例化死子类使 CHA 的 2 目标降为 1 目标直调、以及在运行期执行器上校验 CHA/RTA 改写前后全部调用路径与返回值 100% 一致。
