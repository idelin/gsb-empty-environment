分布式串行化事务存储（CockroachDB 风格）无需为只读操作加悲观读锁，而是借助内存 **Timestamp Cache（区间读高水位缓存）**、**WriteTooOld 推高**、**Read-Refresh 校验** 与 **不确定读窗口（Uncertainty Interval）** 共同保证严格串行化，四处交互一旦错位就会破坏线性一致性或导致活锁：1）**区间时间戳缓存与低水位（Low Water）推进**：记录每个已执行读操作的键区间 `[startKey, endKey)` 及其读时间戳与事务 ID（支持排除本事务自身读记录！）；当节点内存页上限触发驱逐时，只能将最旧页的最大时间戳整体提升为全局 `lowWater`，任何新查询返回 `max(区间重叠最高读时间戳, lowWater)`——绝不可静默丢弃读记录导致迟到写落入已读历史！2）**写入遇读高水位推高（`WriteTooOld`）**：当事务 `T_w` 试图在时间戳 `ts_w` 写入键 `K` 时，查询 Timestamp Cache 中覆盖 `K` 且 `txnID != T_w` 的最高读时间戳 `ts_r`；若 `ts_w <= ts_r`，必须将写入（以及 `T_w` 的提交时间戳）强制推高至 `next(ts_r)`（同时记录 `writeTooOld` 标志！）；3）**Read-Refresh 原位刷新免重启**：当事务 `T` 因 `WriteTooOld` 或提交前冲突导致其提交时间戳从 `origTS` 被推高到 `newTS` 时，不必盲目中止重试——调度器对其记录的全部 `ReadSpan` 集合发起 `Refresh(origTS -> newTS)` 扫描底层 MVCC 版本链：若在 `(origTS, newTS]` 区间内**没有任何其他已提交事务修改过 `T` 读过的任一键/区间**（含范围扫描防幻读！），则刷新成功允许 `T` 直接以 `newTS` 原位提交；只要发现任意版本变更，刷新失败强制 `T` 在 `newTS` 重启；4）**时钟偏斜不确定窗口（`ReadWithinUncertaintyInterval`）**：给定集群最大时钟偏移 `maxOffset`，若事务 `T` 在 `readTS` 读键 `K` 时遇到另一节点写入的已提交版本满足 `readTS < writeTS <= readTS + maxOffset`（且该节点不在 `T` 已观测安全集合中！），必须触发不确定读重启并把 `T` 的 `readTS` 推高至 `writeTS`（同时更新该节点的 `maxTimestamp` 防止二次循环重启！）。为分布式存储层交付可导入的 Go 时间戳缓存、MVCC Read-Refresh 与不确定窗口事务调度包。验收覆盖区间重叠高水位与驱逐 `lowWater` 保底、`WriteTooOld` 推高、`Read-Refresh` 无冲突原位提交 vs 范围幻读冲突强制重启以及不确定窗口精确推高且零死循环。
