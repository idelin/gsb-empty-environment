分布式告警调度中心（Prometheus Alertmanager 架构）需要把高并发告警流经由声明式路由树聚合、抑制、静默并精准触发通知，四类规范细节极易在边界场景漏发告警或制造告警风暴：1）**嵌套路由树 `continue` 分发与继承覆盖**：自顶向下递归匹配 `Route` 节点，每个子节点继承父节点的 `receiver`、`group_by`、`group_wait`、`group_interval`、`repeat_interval` 并允许局部覆盖；当某子节点匹配成功且 `continue: false`（默认）时停止探索后续同级兄弟路由；当 `continue: true` 时继续尝试后续同级兄弟路由（一条告警可同时进入多个接收组！），若某节点所有子节点均不匹配则回落由当前节点自身承接；支持 `group_by: ['...']` 全标签不聚合模式；2）**聚合组三计时器状态机（`group_wait`/`group_interval`/`repeat_interval`）**：新建聚合组首次进入告警时等待 `group_wait` 后触发首轮通知；此后每间隔 `group_interval` 评估该组：仅当组内告警指纹集合发生变化（新增 Firing 或已有告警转 Resolved，且考虑 `send_resolved` 开关！）时才发送增量通知，若集合无变化则等到距上次通知满 `repeat_interval` 才重发；当组内全部告警均 Resolved 且已通知（或 `send_resolved=false`）后安全回收聚合组；3）**Inhibition（抑制规则）精确语义与自抑制豁免**：每条抑制规则包含 `source_matchers`、`target_matchers` 与 `equal` 标签名列表；某条 Firing 源告警抑制某条目标告警的充要条件是：源告警处于活跃未过期 Firing 状态且命中 `source_matchers`、目标告警命中 `target_matchers`、二者不是同一条告警（绝不可自抑制！）、且对于 `equal` 中的**每一个**标签名，源告警与目标告警的值完全相等（特别注意 Alertmanager 规范：**若双方都缺失该标签，也视为相等并触发抑制**；一方缺失另一方存在则不相等！）；4）**Silence 时间窗与多规则合并**：结合生效中的 Silence 列表（正则/反正则/等值/不等值匹配器），在聚合组触发通知瞬间动态过滤被 Inhibited 或 Silenced 的告警——若过滤后组内无待发告警则跳过本次发送而不更新 `lastNotifiedAt`（确保 Silence 过期解封后能立即补发，而不是苦等整个 `repeat_interval`！）。为可观测告警平台交付可导入的 TypeScript Alertmanager 路由、聚合计时与抑制/静默引擎。验收覆盖 `continue: true/false` 多路分发与回落、三计时器状态机与静默解封立即补发、Inhibition 双缺失标签相等与自抑制豁免以及全生命周期通知审计日志。
