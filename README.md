分布式连接遇到数据倾斜时，单个热键足以撑爆 Reduce 节点内存，把左表热键按盐值拆成 k 份能摊薄内存，但右表同键数据必须同步复制 k 份产生额外网络流量。为执行计划器交付可导入的 Go 求解包。输入若干连接键（各自给出左表字节数、右表字节数及是否允许拆分）、Reduce 槽位数 R、单槽总内存上限 M 及每槽最大可承载分片数 P。若某键拆为 k 份（1≤k≤R），左表按向上取整均分到 k 个不同槽位，右表每个目标槽位均须接收该键完整右表字节数，总网络代价为左表全量加右表乘 k；每槽收到的全部左、右表字节总和不得超 M，且分配给该槽的分片条数不得超 P。在键数不超过八、槽位数不超过六时，组件求可行方案中总网络代价最小者，并列按最大单槽负载最小，再按各键拆分度与槽位分配向量字典序最小；无解返回不可行。验收用小规模穷举对照最优代价与并列决胜，覆盖单键不拆必超内存、拆为 2 份仍因槽位分片数 P 受限须调整装箱、多热键竞争同一空闲槽，以及所有方案均超限返回无解。
