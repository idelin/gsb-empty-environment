# 资源迁移规划器（resource-migration-planner）

处理层级重组带来的继承权限与相对引用变化，求满足目标分组的迁移方案：

- **主目标**：移动节点数最少；
- **次目标**：权限例外（grant/deny 补偿条目）最少；再次平手时让迁移后断裂的引用更少；
- **约束**：部分节点固定不可移动；总节点数 ≤ 15；只移动、不复制节点（身份不虚增）；
- **输出**：迁移前后每一条引用的解析结果。

## 模型

每个节点（`src/types.ts` 的 `NodeSpec`）：

| 字段 | 含义 |
| --- | --- |
| `id` | 节点标识（同时作为引用路径段） |
| `parent` | 当前父节点，`null` 表示根（恰一个根，根必须固定） |
| `fixed` | 固定节点，不可移动 |
| `grants` | 本节点本地授予的权限，沿子树继承 |
| `refs` | 相对/绝对引用路径（POSIX 文件语义：相对路径从父节点解析，`/` 开头从根解析） |
| `targetParent` | 目标分组（期望的父节点）；缺省表示不关心 |

有效权限 = 自身及全部祖先的 `grants` 并集。迁移后为保持每个节点有效权限不变，
自上而下在尽量高的节点放置例外条目：丢失的继承权限补授（`grant`），
新获得的继承权限回收（`deny`），例外随子树继承，条目数由最终树唯一确定。

## 算法（`src/solver.ts`）

1. **强制赋值**：有 `targetParent` 的节点指向目标，其余保持原父节点。
2. **环检测**：赋值构成函数图（每点出度为 1），环两两不相交。
   环中若所有节点都是固定或带目标的，则不可行。
3. **最小移动数** = 强制移动数 + 环数：
   - 目标与现父节点不同的节点必须移动（下界）；
   - 每个环必须额外移动一个环内非固定、无目标的节点来破环（环不相交，下界可达，
     例如把破环节点挂到根下必然合法）。
4. **次目标优化**：在最小移动数的解空间中，枚举每个环的（破环节点 × 目的地）
   组合（整树合法性校验兜底），取权限例外数最少者；平手时依次比较断裂引用数、
   字典序保证确定性。枚举量超过上限（默认 1e6）时退化为坐标下降贪心。
5. **身份校验**：迁移前后节点 id 集合必须完全一致——只移动、不复制。

## 使用

```bash
npm run build          # 需要任意 TypeScript >= 4.5 的 tsc
node dist/main.js                       # 运行内置演示场景
node dist/main.js examples/scenario.json        # 从 JSON 文件加载场景
node dist/main.js examples/scenario.json --json # JSON 格式输出
npm test               # 编译后运行 src/selftest.ts 自测
```

场景 JSON 格式见 `examples/scenario.json`。不可行时退出码为 1 并列出原因
（固定节点目标冲突、不可破环等）。

## 输出内容

- 移动清单（来源 -> 目标，标注「目标分组」或「破环」）；
- 权限例外清单（节点、±权限、补授/回收）；
- 每条引用的迁移前 -> 迁移后解析结果（绝对路径 + 节点 id，或 BROKEN），
  状态分为：不变 / 重定向 / 断裂 / 修复 / 前后均断裂；
- 身份校验结论。
