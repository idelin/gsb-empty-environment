# driftdet — 可回溯纠正的漂移检测

Python 3.11+，仅标准库，零依赖。

## 问题

异常段如果事后才被标记，滚动基线已经被污染：极端值抬高了均值、放大了方差，
后续样本的判定随之漂移（真实漂移被掩盖成正常，或正常被误判）。本组件支持
**补录 / 撤回异常标记**，并让变化沿真实依赖传播，为每个受影响结果生成
**修订链**，且可随时用全量重放验证增量修订的正确性。

## 模型

- 样本：`(source, seq, event_time, value)`，按到达顺序处理；基线按 source 独立维护。
- 基线：同一 source 最近 `window` 个**合格**（未被活跃异常段覆盖）样本的
  均值与总体方差；合格数不足 `min_baseline` 时返回 `UNDECIDABLE`。
- 判据（公开的 Shewhart 型规则）：`|x − μ| > k·σ` 判 `DRIFT`，否则 `OK`。
- 被异常段覆盖的样本判定为 `EXCLUDED`：不进任何基线，自身也不参与判定。

## 精确性

所有数值经 `to_exact()` 转为 `fractions.Fraction`：字符串/Decimal 保持十进制
语义（`"0.1"` 就是 1/10），float 经十进制字符串转换。比较采用平方形式
`(x−μ)² > k²·var`，不引入开方与浮点，临界值判定不受偶然舍入影响
（见 `ExactArithmeticTest`：恰在边界上不判漂移，超出 1/10000 即判漂移）。

## 增量传播

标记变化只影响该 source 的结果。从被覆盖的最早样本起向前重算；同时维护
新/旧两套资格下的滑动窗口状态，一旦两者收敛即停止（窗口转移对资格是确定
性的，故后续结果必然不变）。注意：单个结果不变**不能**作为停转条件——
EXCLUDED 结果不携带窗口，覆盖样本看似没变时下游窗口可能仍在移动。

每个被改变的结果追加一条 `Revision`（版本号、判定、窗口依赖键、精确均值/
方差、原因、触发事件 id），历史版本永不覆盖。

## 验证

`verify_against_replay()` 将当前增量状态与 `replay()`（从样本日志+当前标记
全量重算）逐键比较。测试对每一步操作（摄入、补录、重叠段、撤回）后都做此
比较；另有一组对照实验：先纳入极端值再补录标记，其后续基线与"从未纳入"
的检测器逐字段相等。

运行：

```
python3 -m unittest discover -s tests -v
python3 demo.py        # 展示前后判定差异、原因与修订链
```

## 支持修订所需的证据

要让每次修订可审计、可重放，需保留：

1. **样本日志**（不可变）：source、seq、事件时间、精确十进制数值——重放的输入。
2. **标记事件日志**：每次 mark/retract 的事件 id、段 id、source、区间、原因；
   重复标记幂等（不产生新事件），撤回不删除历史。
3. **依赖清单**：每条修订记录其基线窗口的样本键及精确均值/方差——判定可由
   这些键独立重算核对。
4. **修订链**：每个结果的全部版本，含修订原因与触发事件 id——可回答
   "这条判定为什么变了、由哪次标记引起"。
5. **判据配置**：window、k、min_baseline——同一配置下全量重放必须复现
   任何历史状态。

有了 1+2+5 即可重放任意时刻的全部判定；3+4 让单条判定的修订可独立验证。
