发布控制器先发指令，再收到节点就绪事件，不能按它希望的次序挑回调。请实现供控制器导入的 Go 滚动升级策略包。每个服务给旧副本的初始节点、新副本的目标节点、占用资源、最少就绪数与最少就绪机房数，跨版本合并计数。每拍先由控制器选择启动一个未建新副本、删除一个旧副本、或等待；启动立即占节点资源，删除立即永久释放。随后环境在所有尚未就绪的新副本中选择任意子集变就绪（可含刚启动者），但每个新副本必须在启动拍及之后的 D−1 拍内就绪。控制器到下一拍才知道该子集。每个半拍都检查资源与服务约束；目标是旧副本全删、新副本全就绪。资源、节点、机房和时限均由输入给出，不得假定回调独立同分布。要求返回对所有合法回调次序都能完成的策略；先最小化最坏完成拍数，再在该时限内最小化任一合法执行中同时驻留的新旧副本总数峰值。输出可查询的共享策略图：给定当前可观察状态和剩余拍数，能取控制动作并用真实回调驱动至下一状态，而非给一条幸运路径。无解返回可回放的环境反策略：对每个合法动作给出可以阻止完成的后继，循环必须能持续满足回调时限。最多 5 个旧、5 个新副本、4 节点、D≤3；各容量是非负整数。用另一套小型显式博弈树核对是否必胜和两级代价，覆盖多个同拍到期、就绪数够但机房覆盖不足、只按一种回调顺序可达目标却不能据此证明必胜的发布。
