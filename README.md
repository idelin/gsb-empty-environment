# dedup

按事件 ID 去重的内存 Go 库, 语义如下:

- **首次载荷获胜**: 同一 ID 首次出现时保存其载荷; 之后同 ID 事件
  (含跨来源、含不同事件时间的冲突)一律判 `Duplicate`, 首次载荷不被覆盖,
  回收基准也只用首次事件时间。
- **显式来源进度**: 调用方通过 `Advance(source, t)` 承诺该来源不再发出
  事件时间 `<= t` 的事件; 进度单调不减, 去重器从不隐式推进。
- **水位回收**: 全局水位 = 已上报来源进度的最小值, 且单调不减(新来源以
  低进度首次上报不会拉低水位)。仅当水位严格超过 `事件时间+保留期` 时,
  记录才被回收。
- **重放判旧**: 记录被回收后, 同 ID 的重放不会当作新事件——若事件时间
  `<=` 其来源已上报进度, 或 `事件时间+保留期` 严格小于当前水位, 判
  `Stale` 且不留下任何记录。

## 用法

```go
d := dedup.NewDeduper(retention)
v, payload := d.Observe(dedup.Event{Source: "s1", ID: "id-1", Time: ts, Payload: p})
d.Advance("s1", ts) // 显式上报来源进度, 驱动水位与回收
```

## 测试

- `dedup_test.go`: 确定性单元测试(回收边界、单调水位、多来源最小值、
  同 id 冲突不延长保留期、新来源不拉低水位等)。
- `model_test.go`: 全历史参考模型——永久保留全部首次记录与来源进度,
  逐步推导期望判定; 随机生成 观察/推进 混合序列(200 种子 x 3000 步),
  逐条核对判定、载荷、水位与存活数, 覆盖水位推进、不同来源隔离、
  同 id 冲突与已回收 id 重放。
