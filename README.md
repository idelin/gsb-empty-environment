WireGuard 隧道状态机（Noise_IKpsk2）的核心鲁棒性建立在极其精巧的三槽密钥轮转（`Current` / `Previous` / `Next`）、响应方延迟晋升与抗 DoS Cookie 切换机制之上：1）当响应方校验完启动方的 `Handshake Initiation` 并回复 `Handshake Response` 后，它必须把刚派生的新会话密钥放进 `Next` 槽，**绝不可立刻晋升为 `Current` 用来加密发包**（因为启动方可能尚未收到 Response！）——只有当响应方收到启动方用该新会话索引加密的首条有效传输报文（哪怕是 0 字节空载荷 Keepalive！）后，才原子执行轮转 `Previous = Current; Current = Next; Next = nil`；而启动方收到合法 Response 即可直接晋升 `Current` 并立发首包确认！2）每个会话严格受四条硬界限约束：发出超过 `REKEY_AFTER_MESSAGES` 或寿命超过 `REKEY_AFTER_TIME`（120s）触发主动新握手但不中断旧键；超过 `REJECT_AFTER_MESSAGES` 或 `REJECT_AFTER_TIME`（180s）则**彻底销毁**该会话密钥拒绝一切收发（绝不可继续用过期密钥解密！）；3）每个发起方携带 12 字节 TAI64N 严格单调时间戳防握手重放（小于等于该对端历史最大时间戳的 Initiation 立刻丢弃！），且接收端在处于高负载标记 `underLoad = true` 时，对缺少有效 `MAC2` 的握手包不执行昂贵 DH 验签，而是校验 `MAC1` 后直接回发加密 `Cookie Reply`（每 120s 轮换本地 Cookie 秘密键！），启动方据此填充 `MAC2` 重试后方放行；4）每个会话维护独立的 64 位发送计数器与 2048 位防重放接收位图窗口。为虚拟专网数据面交付可导入的 Go WireGuard 会话生命周期、三槽轮转与 Cookie 限载状态机包（加密原语采用标准 X25519/BLAKE2s/ChaCha20-Poly1305 或可插拔标准密码套件接口）。验收覆盖响应方未收确认首包前绝不晋升 `Next`、收到确认首包原子轮转三槽、TAI64N 重放拦截、高负载 `MAC1`/`Cookie Reply`/`MAC2` 两步握手切换、`120s` 重密钥与 `180s` 硬销毁以及旧 `Previous` 槽平滑接收在途乱序包。
