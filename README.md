# 剪贴板异步许可绑定

浏览器宿主在弹出剪贴板许可后，页面可能导航或切换焦点。本组件把每次剪贴板
动作与“文档代 + 焦点代 + 用户瞬态激活”三项绑定，许可回调到达时先全量复核，
全部通过才接触系统剪贴板；授权按请求独立发放、单次消费，一个请求失败不会
消费或作废另一个请求的许可。

## 模块

- `src/types.ts`：请求快照、激活令牌、授权、审计条目等接口。
- `src/environment.ts`：多标签页宿主模型，导航递增文档代，焦点切换递增全局焦点代。
- `src/activation.ts`：用户手势产生的瞬态激活，按 TTL 过期，按标签页绑定。
- `src/permissioner.ts`：`PausablePermissioner`，可暂停、逐条批准/拒绝、批量
  flush，并支持注入异步门精确控制回调到达时机。
- `src/clipboard.ts`：`RecordingSystemClipboard`，记录每次读写的授权上下文。
- `src/guard.ts`：`ClipboardGuard`，对外提供 `copy(tabId, text, signal?)` 与
  `paste(tabId, signal?)`，内含回调复核、授权消费/作废与审计日志。
- `src/errors.ts`：各类失配错误（文档代、焦点代、激活过期、拒绝、取消等）。

## 复核规则

许可回调到达后、任何剪贴板 I/O 之前，守卫依次复核：

1. 标签页仍然存在（未关闭）；
2. 文档代与请求快照一致（期间没有导航）；
3. 全局焦点代与请求快照一致（期间没有焦点切换）；
4. 激活令牌仍在 TTL 内，且仍是该标签页最近一次手势；
5. 授权未被消费或作废。

任一失败即抛错并把该授权登记为作废（`invalidateGrant`），其他请求的授权
不受影响；只有复核全部通过才 `markConsumed` 并执行一次剪贴板读写。

## 测试

使用 Node 内置测试运行器（无需安装依赖，Node >= 22 支持 strip-types）：

```bash
npm test
```

覆盖场景（共 21 个用例）：

- 多标签页焦点切换导致焦点代失配，失败请求不触碰另一标签页的授权；
- 回调到达前导航（文档代失配）、标签页被关闭；
- 瞬态激活 TTL 过期，且同页新手势的请求仍可成功；
- 复制动作在等待期取消、授权到达后取消，两种路径均零剪贴板调用；
- 宿主拒绝许可、无激活手势直接发起、底层剪贴板抛错；
- 全量零越权不变量：每条剪贴板调用都能对上当次已消费授权，且授权要么
  消费、要么作废，从不同时出现。
