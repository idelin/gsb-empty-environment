# 网络隔离修复步骤安全性

演练平台修改网络连边以隔离受感染节点时，中间步骤不能短暂开放原本禁止的路径。写供Go控制宿主调用的更新规划包，输入至多十二条可变边、初始与目标开关状态及禁止到达对；每步只能翻转一条边，求每个中间图都满足约束的最短步骤，等长按边ID排序。给出无法安全迁移时的已遍历状态证据，用全状态BFS核对，动作只作用于内存网络模型。

## 包 `example.org/netsec/q0120`（package `netsec`）

纯内存、无 I/O、无包级可变状态，可被 Go 控制宿主直接调用。

- `Plan(req *Request) (*Result, error)`：在开关状态超立方体上做全状态 BFS，
  只扩展满足全部禁止到达对的状态。每条边按 `EdgeID` 升序翻转，因此首次到达
  目标即为最短路径，多条等长路径中取边 ID 序列字典序最小者。
- `Verify(req, result)`：用并查集独立重建每个状态的安全性，再跑一次参考 BFS，
  核对可行性、步数、字典序、最短性以及证据集合，便于宿主交叉验证。
- 输入上限 `MaxEdges = 12`，状态空间至多 `2^12 = 4096`，使用 `uint16` 位掩码。
- 校验失败返回包装了 `ErrInvalidRequest` 或 `ErrInvalidState` 的错误；请求合法
  但无法安全迁移时不返回错误，而是 `Result.Feasible == false`，并在 `Evidence`
  中给出已访问的安全状态（含深度、父状态、翻转边）与被拦截的不安全状态。

约束语义：边为无向；某禁止对的两端在当前启用边构成的图中连通即判定该状态不安全，
初始状态与每个中间状态都必须安全。所有判定都在请求的内存副本上完成，
`Plan` 不会修改入参，也不触碰真实网络。

## 验证

```sh
go vet ./...
go test ./... -count=1
go test -race ./...
```

测试覆盖最短性与字典序决胜、零步、目标/初始不安全的不可行证据、入参校验、
12 条边上界、请求不可变，以及 400 组随机小网络对照独立 BFS 预言机的全状态核对。
