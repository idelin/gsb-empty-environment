标准 BGP 对同一前缀只通告一条最优路径，开启 ADD-PATH（RFC 7911）后通过 `(Prefix, PathID)` 键并发通告多条路径；但当发送端采用 Send-N 策略动态裁剪候选集或隐式替换旧 PathID 时，若混用未撤销的 PathID 或对隐式/显式撤销处理有误，会造成对等体残留幽灵路由。为 BGP 路由引擎交付可导入的 Go ADD-PATH 状态机包。支持接收端 Adj-RIB-In 与发送端 Adj-RIB-Out（配 `SendBestN` 或 `SendOnePerNextHop` 模式与上限 K）：接收端处理带 32 位 PathID 的 Update/Withdraw（同 `(Prefix, PathID)` 隐式覆盖，不同 PathID 并存，收到未记录 PathID 的 Withdraw 幂等忽略，会话重置清空该邻居全部 PathID），实时维护各前缀按 BGP 选路序排好的全部有效候选路径及最优路径；发送端每当 Loc-RIB 候选路径集变化时，计算须向对等体发出的最小增量 Update/Withdraw 列表——已通告且仍在发送集中的路径保持原 PathID 不抖动，移出发送集的路径发显式 Withdraw（或当需立刻替换为新入选路径且启用复用时明确用新路径复写同一 PathID 并标注隐式替换），绝不为不同活跃路径分配重复 PathID。验收用多邻居抖动事件流对照对等体最终镜像与本地应发集合完全一致且零冗余通告，覆盖同前缀多 PathID 独立撤销、不同下一跳去重发最优、PathID 复用隐式替换 vs 显式撤销，以及对等体重启全清空。
