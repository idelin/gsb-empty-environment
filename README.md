LLM 推理服务同时启用 RadixAttention 前缀共享缓存与 Chunked Prefill（分块预填充与解码混批）时，两个模块深度耦合：新请求的提示词在前缀树某条边的中间分叉时必须原子劈分边节点并保留原共享块引用计数；当物理 KV 块预算紧张时，只能按 LRU 驱逐引用计数为 `0` 的**叶子**节点（父节点仅在所有子节点均被驱逐且自身无人引用时才进入可驱逐叶集合！），若仍不足则须抢占低优先级运行中请求释放其独占 KV 块，绝不能发生全员互相卡死或驱逐正在解码的共享祖先前缀。为推理调度引擎交付可导入的 Go RadixAttention KV 缓存与混批调度包。物理 KV 池总容量为 `totalBlocks`（每块存 `blockSize` 个 token）。组件实现：1）基数树（Radix Tree）块级前缀匹配、节点中途劈分（精确切分 token 序列与物理块切片、继承父子关系与 `refCount`）、请求锁定/解锁路径上所有祖先节点的引用计数；2）按最后访问时间戳维护可驱逐叶节点最小堆（驱逐叶节点回收其独占物理块，若父节点因此变为叶且 `refCount == 0` 立即入堆！）；3）单步迭代调度器在 `maxTokensPerStep` 与 `totalBlocks` 双约束下，优先保障在途解码（Decode）请求每人 1 token，剩余算力按预算切分装入预填充请求（支持单条长 Prompt 跨多步分块推进，命中前缀树缓存的块直接跳过预填充计算！）；当在途解码请求申请新 KV 块且可驱逐缓存耗尽时，按规则抢占最近到达的运行中请求（将其退回等待队列并释放独占块，保持前缀树其余节点引用计数守恒）确保至少最老解码请求向前推进绝不死锁。验收覆盖中途劈分共享前缀后双请求并发解码、父节点仅在全子叶驱逐后才可回收、跨步分块预填充命中前缀跳过计算、紧 KV 预算触发抢占无死锁，以及每步物理块严格守恒（树内块 + 空闲块 + 未挂树运行块 == `totalBlocks`）。
