七层边缘网关严格按 RFC 9110 执行服务端驱动内容协商（`Accept`、`Accept-Encoding`、`Accept-Language`）与范围请求（`Range` + `If-Range`）时，五类边界极易与规范偏离：1）`Accept` 媒体类型匹配特异性严格按 `type/subtype;param=v`（参数个数多更优先！） > `type/subtype` > `type/*` > `*/*` 匹配最具体的一条客户端条目并取其 `q` 值——当客户端发送 `Accept: text/html;q=0, */*;q=0.8` 时，`text/html` 命中更具体的 `q=0` 必须被**彻底排除**，绝不可回退匹配 `*/*;q=0.8`！2）`Accept-Encoding` 未显式列举 `identity` 时默认隐式允许 `identity`（除非显式声明 `identity;q=0` 或 `*;q=0`！），而多维度协商综合得分按主权重与确定性候选顺序决胜，全不可接受必须返回 `406 Not Acceptable`；3）`Accept-Language` 同时支持 RFC 4647 Basic 与 Extended 过滤（如 `zh-*-CN` 匹配 `zh-Hans-CN`）；4）多区间 `Range: bytes=0-9, 5-15, 20-9999, -4` 解析必须截断越界上界至 `total-1`、展开后缀 `-N` 为 `[max(0, total-N), total-1]`（`total==0` 或 `-0` 为不可满足！）、检测语法非法直接退回完整 `200`，若所有区间均不可满足（如 `bytes=500-600` 而总长 100）必须返回 `416` 并附 `Content-Range: bytes */100`，且提供抗 DoS 重叠区间合并上限（超过最大碎片/重叠阈值拒绝拆分直接退回 `200`！）；5）`If-Range` 携带弱 ETag（`W/'...'`）时 RFC 9110 §13.1.5 强制要求强比对失败，必须忽略 `Range` 返回完整 `200 OK` 而非 `206`！为 HTTP 网关交付可导入的 TypeScript RFC 9110 内容协商与范围响应编译库。验收覆盖 `q=0` 压制 `*/*`、带参数媒体类型特异性、`identity;q=0` 触发 `406`、BCP 47 扩展匹配、多区间重叠/后缀/越界 `206` vs `416` 以及弱 ETag `If-Range` 强制回退 `200`。
