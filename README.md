大型 SRE 平台的 SLO 错误预算核算引擎同时面对**请求比（Request-Based）与时间片（Window-Based）双口径、跨边界计划维护窗口扣减、日历月/滚动窗口切换与多窗口燃烧率滞回（Hysteresis）**四重复杂性：1）遇到已批准的计划维护窗口 `[mStart, mEnd)` 时，维护期内的请求与故障必须从好事件与总事件中**同步剔除**（绝不可把维护期故障计为成功从而虚增分母稀释真实错误率！）；若一个聚合时间桶（如 5 分钟桶）与维护窗口部分重叠，则窗口型指标按精确非重叠时长比例切分，请求型指标按事件时间戳或重叠区间精确过滤；2）日历月 SLO 须按指定 IANA 时区处理 28/29/30/31 天与跨夏令时 23h/25h 天，而滚动窗口（如 28 天或 30 天）须随查询时刻 `t` 精确滑出过期桶并扣减维护窗后的真实有效分母计算剩余预算比例（全维护或零流量导致有效总量为 0 时不得产生 `NaN`/`Inf` 误判违约！）；3）多窗口燃烧率告警策略（支持配置多条分级规则，每条含 `(longWindow, shortWindow, burnRateThreshold, clearThreshold)`）必须同时满足长短两窗口燃烧率 `>= burnRateThreshold` 才从 `OK` 跃迁至 `FIRING`，且为了防止临界抖动，一旦进入 `FIRING` 必须等到长短两窗口均回落到 `<= clearThreshold`（滞回下阈）才恢复 `OK`；4）支持多服务依赖的复合 SLO 预算上限聚合与精确可追溯审计明细（输出扣减前/后分母、排除的维护时长及每条规则跃迁时刻）。为可靠性治理平台交付可导入的 Go SLO 错误预算核算与多窗滞回告警引擎。验收覆盖维护窗同步扣分子分母防稀释、跨维护窗部分重叠桶切分、零流量/全维护无 `NaN`、闰年与夏令时日历月窗口边界以及双窗口同时触发与滞回回落恢复状态机。
