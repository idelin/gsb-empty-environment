# 数据库文件锁不能成为跨租户读取密文解包缓存的许可

数据库文件锁不能成为跨租户读取密文解包缓存的许可。写供Go存储宿主调用的句柄能力包，可信打开操作授予对象ID、版本、租户及读写权限，锁只控制冲突不增加权限；复制句柄只能收窄权限，跨租户移交必须提供双方签名的目标绑定票据。锁升级、对象替换及移交并发时每次读取重新核对同一能力代次。用小对象模型、真实签名和伪造锁持有者测试零越权读取，并验证失败移交不泄漏解包数据。

## 实现结构（包 `taskpkg`）

- `capability.go`：能力句柄，非导出字段绑定对象 ID、版本、租户、能力代次与
  读写权限；`Duplicate(Narrow)` 只能撤销权限，对象绑定与代次原样继承。
- `lock.go`：按对象分片的共享/排他锁管理器（条件变量阻塞、支持锁升级），
  完全不感知租户与权限，锁只做冲突控制。
- `ticket.go`：跨租户移交票据，源、目标租户对同一份确定性规范字节流分别做
  真实 Ed25519 签名，目标租户签名即目标绑定。
- `host.go`：存储宿主。`Open` 可信签发能力；`Read` 每次重新核对租户与同一
  能力代次后才允许触达解包缓存；`Replace`/`Transfer` 要求排他锁并推进代次、
  清空该对象所有解包缓存；移交仅在全部票据校验通过后才在宿主内部重封装。
- `crypto.go`：每租户独立数据密钥，AES-256-GCM 加解密，随机 nonce。

## 关键不变量

- 持锁不授权：持排他锁的伪造锁持有者跨租户读取仍返回 `ErrWrongTenant`，
  且不会产生任何攻击者租户的解包缓存条目。
- 代次失效：对象替换或移交都推进 `generation`，旧句柄随后每次 `Read` 都
  返回 `ErrStaleCapability`，旧代次缓存同步清除。
- 失败移交零泄漏：签名缺失/伪造、目标被替换、票据过期、重放、版本代次
  陈旧、缺锁、调用方不符等失败路径都不触碰解包缓存、不返回明文。

## 测试

```sh
go test -race -count=1 ./...
```

测试使用 1~32 字节小对象、真实 Ed25519 密钥与伪造锁持有者，覆盖越权读取、
锁升级冲突、替换/移交并发代次核对以及失败移交的解包数据泄漏矩阵。
