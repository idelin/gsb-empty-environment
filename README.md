云原生内核安全引擎在准入审计用户提交的 eBPF 程序组合（主程序 + `BPF_MAP_TYPE_PROG_ARRAY` 尾调用子程序图 + BTF 类型元数据）时，若仅独立检查单个 eBPF 程序而未全局验证 `bpf_tail_call` 调用链的最大嵌套深度（内核硬上限 `MAX_TAIL_CALL_CNT=33`）与栈总消耗（子函数调用 + 尾调用组合栈深超 512 字节限制）、忽略 Map 句柄类型与辅助函数参数类型匹配（如把 `ARRAY` Map 当 `PROG_ARRAY` 或 `RINGBUF` 传入导致类型混淆），或放过 BTF 结构体字段偏移越界与循环类型定义，恶意 eBPF 组合可导致内核栈溢出或信息泄漏。为 C++17 系统安全宿主实现可嵌入、零外部依赖、`-Wall -Wextra -Wconversion -Werror` 编译通过的 eBPF 尾调用图、Map 类型安全与 BTF 结构完整性静态验证库。库输入为 eBPF 程序集合（含字节码指令、栈帧大小、调用的 `bpf_func_id` 与 Map ID）、Map 描述符表（类型、key/value 大小、最大项数、`PROG_ARRAY` 槽位映射）以及 BTF 类型表。验证库精确执行：（1）构建全量 `bpf_tail_call` 与 BPF-to-BPF 子函数调用有向图：检出任意环路或超过 33 次尾调用的逃逸/不可达路径，并按内核组合栈规则精确计算每条路径最大累计栈深（拦截单帧或组合栈超 512 字节）；（2）校验每条 `BPF_CALL` 辅助函数（`map_lookup_elem`/`map_update_elem`/`tail_call`/`ringbuf_reserve`）的 Map 类型、指针偏移与访问字节长度严格落入该 Map 的 `value_size` 边界内；（3）审计 BTF 类型表：硬拒绝类型引用循环、结构体字段 `offset + size > struct_size`、对齐非法及指向未定义类型 ID。附 34 层尾调用链、子函数+尾调用栈溢出、Map 类型混淆与 BTF 环路/越界字段测试。
