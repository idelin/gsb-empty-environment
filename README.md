# archmerge

多源归档合并工具：把若干来源归档合并成一份清单（manifest），逐项记录来源，
**只读原归档，不做任何修改**。

## 用法

```sh
archmerge -o manifest.json SRC [SRC...]
```

每个 `SRC` 可以是：

- **JSON 清单**：`{"name": "s1", "entries": [{"path": "a/b.txt", "type": "file", "version": 2, "digest": "sha256:..."}]}`
- **目录**：就地扫描，文件摘要取内容 sha256、版本取 mtime；目录（含空目录）显式记录。

退出码：`0` 无冲突，`1` 有冲突（清单仍完整输出），`2` 用法/读取错误。

## 合并规则

1. **同路径，新版本优先**。版本相同则必须类型一致；同为文件还必须摘要一致，
   否则报 `digest-mismatch`；类型不一致报 `type-mismatch`。
2. **目录与文件不隐式互换**。同版本类型变更视为冲突；不同版本属正常版本更替。
   父路径类型约束整棵子树：文件下面不允许存在任何存活条目（`prefix-conflict`）。
3. **墓碑（tombstone）删除整棵子树**：路径下所有版本 ≤ 墓碑版本的条目被移除；
   若子树下有更新的条目存活，报 `tombstone-conflict`。
4. **空目录保留**：显式 dir 条目即使没有子条目也会出现在清单中。
5. **顺序无关**：合并结果只取决于来源集合，与输入顺序无关。

冲突类型：`type-mismatch`、`digest-mismatch`、`prefix-conflict`、`tombstone-conflict`。

## 测试

```sh
go test ./...
```

除单元测试外，测试在路径空间 `{a, a/b}` 上枚举全部小型来源
（每路径：缺失 / 文件×版本×摘要 / 目录×版本 / 墓碑×版本），
穷举所有有序对（交换律）与所有三元组（旋转不变性），并对每个结果校验：
确定性、排序、版本最大性、来源记录精确性，以及无冲突时
“文件无子代、墓碑无子代”的结构不变量；另验证枚举确实覆盖
前缀冲突、空目录与墓碑场景。
