RFC 9260 SCTP 通过把传输序号 `TSN`（连接级可靠传输与确认）和流序号 `SSN`（每条逻辑流独立定序）彻底解耦来消除多流队头阻塞，但在实现带 `B`/`E`/`U` 三标志位的分片重组与 `SACK` 间隙块生成时存在四类极易出错的边界：1）一条消息被拆分为多片（首片 `B=1,E=0`、中间 `B=0,E=0`、尾片 `B=0,E=1`；单片 `B=1,E=1`）时，其全部分片必须拥有**严格连续的 32 位回绕 `TSN`**、相同的 `StreamID` 与相同的 `U-bit`（有序消息全部分片还必须拥有相同 `SSN`！若某片缺失或 `StreamID`/`SSN` 不一致则绝不可拼出残缺消息）；2）流 `S` 上若 `SSN=k` 尚未收齐，同流 `SSN=k+1` 必须暂存排队，但**同流的无序消息（`U=1`，忽略 `SSN`！）**以及**其他流的就绪消息**必须立即按交付序向上层吐出，绝不能被流 `S` 的缺包阻塞！3）`SACK` 构造必须精确推进 `Cumulative TSN Ack`（按 RFC 1982 模 `2^32` 序列号空间处理 `0xFFFFFFFF -> 0x00000000` 回绕！），把高于累积确认点的所有不连续已收区间合并为有序无重叠的 `Gap Ack Blocks`（相对 `Cumulative TSN Ack` 的 16 位无符号偏移起止对），并把所有落在累积点及之前或已收集合内的重复分片登记为 `Duplicate TSNs`；4）发送端解析对端 `SACK` 时必须按 RFC 9260 §7.2.4 维护每个在途 `TSN` 的缺失报告计数（仅当更高 `TSN` 被 `SACK` 确认且该 `TSN` 落在间隙内才累加，达到 3 次立刻触发快速重传，且收到 `Cumulative TSN Ack` 回退的乱序旧 `SACK` 必须静默忽略！）。为传输协议栈交付可导入的 Go RFC 9260 SCTP 收发重组与 SACK 状态机包。验收覆盖跨 `0xFFFFFFFF` 回绕的 `Cumulative TSN` 与 `Gap Ack Blocks`、多片 `B`/`E` 乱序重组、单流缺 `SSN` 时他流与本流 `U=1` 无头阻塞即时交付、重复 TSN 记录、乱序旧 SACK 忽略及 3 次缺失报告快速重传。
