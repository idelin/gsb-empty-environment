# incbuild — 增量构建计划器

区分**内容依赖**与**顺序依赖**的增量构建计划器，支持动态依赖发现与最短原因链输出。

## 模型

- **内容依赖**（`Task.Inputs`）：输入内容哈希变化沿此边传播失效，级联重建下游。
- **顺序依赖**（`Task.OrderOnly`）：只约束调度顺序，内容变化**不**传播失效。
- **动态发现**：任务运行中通过 `RunContext.Discover` 上报新发现的内容依赖（如编译器生成 depfile）。新边会触发额外调度轮次补排任务；任何基于过期内容算出的结果都会被作废并重跑，绝不使用。
- **restat**：任务重跑后若输出内容未变，下游不重建。

## 算法

每轮（pass）按拓扑序（内容边 + 顺序边）评估任务：未运行过、命令变化、输出缺失/被外部修改、内容输入哈希与记录不符 → 判脏并重跑。轮末做收敛校验：所有任务记录的内容输入必须与磁盘一致，否则作废该结果并重排，直至收敛或超过 `MaxPasses`（防止任务自改输入导致震荡）。

运行中源文件改变通过运行前后输入哈希快照比对检测；发现过晚的依赖由轮末校验兜底。

## 原因链

`BuildResult.Reasons` 为每个重建节点保留最短原因链（并列时取字典序最小保证确定性），`BuildResult.Report()` 渲染，例如：

```
task "gen-d" rebuilt (1 run(s)); shortest reason chain:
  file "a.txt" changed on disk (hash 3b5d... -> 9f21...)
  -> task "gen-b" rebuilt: input "a.txt" changed
  -> file "b.txt" regenerated by task "gen-b"
  -> task "gen-d" rebuilt: input "b.txt" changed
```

## 验证

```
go test ./...          # 菱形依赖 / 顺序依赖不传播 / 生成文件 restat / 运行中源文件改变 / 动态发现补排
go run ./cmd/incbuild-demo
```
