# 密钥轮换后台重加密

卷密钥轮换期间，新写入和后台重加密会竞争同一块。给Go卷宿主实现重加密事务包，每块版本绑定密钥代次与内容摘要，迁移只能在读到的版本仍是当前版时提交，否则重读；旧钥在所有旧代块与活跃读者消失后才销毁。用暂停加密器和逐点重启验证迁移不会覆盖新写入。

## 设计概览

包名 `netsec`，实现一个事务化块宿主，让前台写入与后台重加密在同一块上安全并发。

- `BlockVersion`（`types.go`）：每块的不可变版本戳，绑定密钥代次 `Gen`、块内单调序号 `Seq` 与明文 SHA-256 摘要 `Sum`。
- `Store`（`store.go`）：按块的事务存储，核心原语是 `CompareAndSwap`——仅当读到的版本仍是当前版本时才原子替换，否则返回 `ErrConflict` 与最新记录。提供内存版 `MemoryStore` 与原子落盘的 JSON 版 `FileStore`（临时文件 + rename，崩溃只留旧态或新态）。
- `KeyRing`（`keyring.go`）：跟踪每个密钥代次的两类引用——仍用该代加密的块数 `blocks` 与解密期间钉住的活跃读者数 `readers`。代次被轮换后标记 `retired`，只有 `blocks==0 && readers==0` 才销毁并通过 `OnDestroy` 钩子清零密钥材料。
- `Volume`（`volume.go`）：协调存储、密钥环与加密器。

## 事务不变量

1. **版本绑定**：写入时计算明文摘要，版本同时携带代次与摘要；读取与迁移都重新计算摘要并比对，密文被篡改即失败。
2. **乐观迁移**（`MigrateBlock`）：读当前版本 → 用旧钥打开并校验摘要 → 用当前代重新封装同一份明文 → 仅当磁盘版本仍等于步骤一读到的版本时 CAS 提交；任何冲突都丢弃本次工作并重新读取，绝不覆盖更新的写入。迁移保持明文与摘要不变，只改代次、密文与序号。
3. **旧钥延迟销毁**：读取和迁移在需要旧钥期间 `PinReader` 钉住对应代次，结束后 `ReleaseReader`。块引用迁移走用 `MoveBlock`。旧代次在块引用与读者引用都归零前不会被销毁。
4. **重启对账**：`NewVolume` 调 `KeyRing.Reconcile` 从磁盘现有块重建块引用，读者钉住本就不跨进程存活；`FileStore` 重新打开即模拟一次进程重启。

## 验证手段

- `PausingEncryptor`（`pausing.go`）：包装真实加密器，可按代次暂停 `Encrypt`（`Pause` 持久、`PauseOnce` 单次），`Decrypt` 永不阻塞。`TestPausingEncryptorMigrationDoesNotOverwriteNewWrite` 在迁移的封装步骤将其冻住，让前台写入先提交新版本，再放行迁移，断言迁移 CAS 失败后重读、最终内容与版本都属于新写入。
- 逐点重启（`restart_test.go`）：在“读完之后 / 提交之前”两个检查点中止迁移并重建宿主，断言未提交事务不改磁盘，恢复后迁移收敛且内容不丢；多块场景每提交一块就重启一次，逐点推进；并验证重启前的新代写入不会被回滚或覆盖。
