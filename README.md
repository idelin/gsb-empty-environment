# 候补递补引擎（Waitlist Promotion Engine）

一人可报名多个互斥场次的候补/递补系统，TypeScript 实现。

## 规则

1. **互斥报名**：一人可报名多个互斥场次（`preferences` 按偏好从高到低），同一时刻最多持有一个名额。
2. **排队次序**：每个场次的候补队列按「优先级降序、报名序号升序」排序；报名序号在报名时分配一次，终身不变。
3. **级联递补**：`settle()` 迭代执行递补直到稳定——某人升入更偏好的场次会释放原场次名额，可能继续触发下一人递补。
4. **只升不降防循环**：递补只接受「比当前持有场次严格更偏好」的场次，每人偏好序单调前进，从机制上杜绝循环；撤销过的场次记入 `declined`，不会再补给本人。
5. **撤销恢复**：`revoke()` 撤销确认后，按原优先级与原报名序号把候补条目插回有序队列（恢复原位），而非重新排尾；释放的名额自动触发新一轮递补至稳定。
6. **完整递补链**：所有递补/撤销事件追加到全局链（`getChain()`），`formatChain()` 输出可读文本，包含来源、去向与释放的名额。

## 运行

需要 Node.js ≥ 23.6（原生运行 TypeScript；或 ≥ 22.6 加 `--experimental-strip-types`）。

```bash
node src/demo.ts                 # 演示：级联递补链 + 撤销恢复原位
node --test test/*.test.ts       # 运行测试
```

## 接口

- `addSession(id, capacity)`：定义场次与容量。
- `register({ id, priority, preferences })`：报名，为每个志愿场次建立候补条目。
- `settle()`：递补至稳定，返回本次产生的递补事件。
- `revoke(personId)`：撤销确认，恢复原候补资格并递补至稳定，返回撤销及级联事件。
- `getChain()` / `formatChain()`：完整递补链（结构化 / 可读文本）。
- `assignmentOf` / `waitlistOf` / `occupantsOf`：状态查询。

## 正确性要点

- **终止性**：每次递补都使该人的偏好下标严格减小，每人每场结算最多前进 `|preferences|` 次，循环有界。
- **稳定性**：`settle()` 的不动点性质——退出时所有空余名额都没有可接受的候补者。
- **原位恢复**：队列始终按 `(priority, seq)` 有序，撤销后用原 `(priority, seq)` 二分插回，自然回到原位置。
