# rcpsp — 小规模资源约束项目调度求解器

最多 12 项作业、整数时长、前置关系、多资源需求，在离散时域 `0..horizon-1`
内不可抢占调度。求解器输出**最短完工期（makespan）**；同优时取**开始时间向量
字典序最小**（按作业输入顺序）。零时长作业不占时槽、不耗资源，但前置关系
仍然生效（`s_succ >= s_pred + d_pred`，含 `d_pred = 0`）。

## 语义约定

- 时长为 `d` 的作业从 `s` 开始占用时槽 `s .. s+d-1`，完工时间为 `s+d`，
  所有作业须满足 `s+d <= horizon`。
- 前置 `i -> j`：`s_j >= s_i + d_i`。
- 资源为可再生资源：每个时槽上所有运行作业的需求之和不得超过容量。
- 零时长作业不得声明资源需求（输入错误）；前置环一律判不可行。

## 用法

```sh
go run . -f examples/multi_resource.json          # 求解并打印逐时资源证据
go run . -f examples/multi_resource.json -verify  # 同时用全枚举核对
cat inst.json | go run .                          # 从 stdin 读入
go test ./...                                     # 单元测试 + 3000 例随机全枚举核对
```

输入为 JSON：`horizon`、`resources`（名称+容量）、`jobs`
（id、duration、preds、demand）。输出包括最优 makespan、各作业开始时间，
以及**逐时资源证据**：每个时槽运行的作业与每种资源的 用量/容量，
可直接核验可行性。不可行时给出原因（前置环 / 需求超容量 / 下界超时域 /
时域内无解），退出码为 1。

## 实现与核对

- `solver.go`：从关键路径/资源工作量下界起迭代 makespan 上界，对每个上界
  按作业下标顺序、开始时间升序做 DFS（CPM 的 EST/LST 剪枝 + 资源剖面
  增量维护），首个可行解即为字典序最小开始向量。
- `brute.go`：独立的全枚举器，枚举时域内全部开始向量，逐对检查前置、
  逐槽检查资源，取 (makespan, 开始向量) 字典序最小者，用于小规模核对
  不可行判定与多资源冲突。
- `solver_test.go`：固定用例（零时长前置、多资源冲突、字典序同优、
  三类不可行）+ 3000 个随机小实例（n<=6, horizon<=8, 1-3 种资源，
  含零时长、超容量需求、随机前置）与全枚举器逐一比对。
