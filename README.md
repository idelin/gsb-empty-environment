递归 DNS 解析器（Unbound / BIND 风格）在缓存上游权威应答与追逐多级委托/`CNAME` 链时，四类安全与一致性规范决定了解析器能否免疫缓存投毒与死循环：1）**Bailiwick 区域边界校验（RFC 5452）**：当解析器向负责委托区 `Z` 的权威服务器查询时，该服务器应答中只有落在 `Z` 子树（`name == Z` 或 `name` 以 `.Z` 结尾）内的权威段（NS/SOA）与附加段胶水记录（A/AAAA）才属于 `In-Bailiwick` 允许入缓存，任何越界指向外部域（如 `Z = example.com` 却附带 `bank.org A 1.2.3.4`！）的记录必须彻底丢弃绝不入缓存！2）**RFC 2181 信任秩（Trust Ranking）**：不同来源的 RRset 拥有严格优先级（权威应答段 AA=1 > 权威段 NS > 非权威应答 > 附加胶水），且同一 RRset 必须原子替换（不可合并新旧残片！）；缓存中尚未过期的**高信任秩 RRset 绝不可被低信任秩新应答覆写**（即使新应答 TTL 更长！）；3）**RFC 2308 负缓存精确计算**：`NXDOMAIN` 与 `NODATA` 的负缓存 TTL 严格等于权威段 SOA 记录自身 TTL 与 SOA `MINIMUM` 字段的**较小值**（缺 SOA 时禁止负缓存！）；更微妙的是，若响应同时包含一条 `CNAME` 链 `a.com -> b.com` 且最终对 `b.com` 返回 `NXDOMAIN`，必须把 `a.com CNAME b.com` 正常缓存、而只对链尾 `b.com` 写入 `NXDOMAIN` 负缓存（绝不可把 `a.com` 标为 `NXDOMAIN`！）；4）递归追逐器完整防御 `CNAME` 自环/互环、超最大跳数、以及需要跳过无胶水 NS（Out-of-Bailiwick NS）单独发起子查询解析其 A/AAAA 时的相互依赖环（如 `ns1.a.com` 与 `ns1.b.com` 互为对方权威！）。为递归解析服务交付可导入的 Go DNS 缓存与迭代追逐引擎包。验收覆盖越界胶水投毒拦截、RFC 2181 高信任秩防低秩覆写、`CNAME + NXDOMAIN` 分离缓存、`MIN(SOA.TTL, SOA.MINIMUM)` 负缓存计算以及 `CNAME` 环与互依赖 NS 死循环拦截。
