# fs-verity描述符与哈希树

文件被度量后仍可能被改动或在末尾追加，攻击者也可换盐或哈希算法伪造相同的度量字段。为Go文件完整性组件写供读取路径调用的 Merkle 树校验包，沿用 fs-verity 的 4096 字节块、末块补零和逐层打包思路，本题描述符固定为 256 字节：版本、算法、块大小对数、盐长、数据长度 8 字节小端、根哈希、盐，其余置零，度量值是描述符的哈希；盐以哈希分组大小补齐后作为每次哈希的前缀。读取任一块都要校验到根；数据长度与实际不符、盐或算法与已签名的度量不一致都拒绝。用单块、非块整数倍文件、末尾追加、改盐和改单个中间块验证。

## 实现说明

描述符采用 fs-verity 的 256 字节布局：

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 1 | 版本，固定为 1 |
| 1 | 1 | 算法，1=SHA-256，2=SHA-512 |
| 2 | 1 | 块大小对数，固定为 12（4096 字节） |
| 3 | 1 | 盐长 |
| 4 | 4 | 保留，必须为 0 |
| 8 | 8 | 数据长度，小端 |
| 16 | 64 | 根哈希，SHA-256 只用前 32 字节 |
| 80 | 32 | 盐 |
| 112 | 144 | 保留，必须为 0 |

度量值是描述符 256 字节的哈希，使用描述符中声明的算法。盐先补零到哈希压缩函数的输入块大小（SHA-256 为 64 字节，SHA-512 为 128 字节），再作为每个数据块和哈希树块的哈希前缀。数据末块补零到 4096 字节；每层摘要按顺序打包进 4096 字节块，末块补零，直到只剩一个摘要。单块非空文件的根哈希就是该数据块的哈希，空文件根哈希全零。

## 用法

```go
d, measurement, err := netsec.Measure(data, salt, netsec.AlgorithmSHA256)
v, err := netsec.NewVerifier(file, d, measurement) // measurement 来自可信的签名元数据
block, err := v.ReadBlock(3)                        // 每次读取都校验块哈希和到根的路径
err = v.Verify()                                    // 重新读取并校验整棵 Merkle 树和实际长度
```

`NewVerifier` 会校验度量值、`DataSize` 与实际长度、根哈希；每次 `ReadBlock`/`ReadAt` 都会重新检查文件长度并在块级重新计算哈希。`Verify` 和 `ReadAll` 会重新构建整棵树，因此也能发现度量后对其他块的修改。
