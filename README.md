# 改动交互测试规划器

在依赖约束与执行预算内选择合法的改动组合，**先最大化二阶（两两）交互覆盖，再最小化总成本**。支持最多 18 个改动，输出未覆盖的交互对及原因，并用精确解对照贪心解的成本差距。

## 问题定义

- 每个改动有 `cost`（执行成本）与 `deps`（依赖的其他改动）。
- 一个**组合**是一起部署测试的一组改动。组合合法当且仅当：
  1. 依赖闭包完整：组合内每个改动的传递依赖都在组合中；
  2. 组合总成本不超过执行预算 `budget`。
- 组合覆盖其中全部 `C(k,2)` 个二阶交互对。
- 交互对 `(i, j)` **可达**当且仅当 `i`、`j` 的联合依赖闭包成本不超过预算。
- 目标（字典序）：先覆盖全部可达交互对（最大覆盖），再使所选组合的总成本最小（最少成本）。

## 运行

需要 Node.js ≥ 22.6（直接运行 TypeScript，无需编译）。

```bash
node src/cli.ts --demo          # 运行内置示例
node src/cli.ts spec.json       # 运行自定义输入
node src/cli.ts spec.json --json  # JSON 格式输出
npm test                        # 运行测试
```

## 输入格式

```json
{
  "budget": 12,
  "changes": [
    { "id": "auth", "cost": 4, "deps": ["db"] },
    { "id": "db", "cost": 3 }
  ]
}
```

约束：`changes` 1–18 个，`id` 唯一，`cost` 为正整数，`deps` 引用已存在的 id（支持传递与环形依赖）。

## 输出内容

- 概览：改动数、预算、合法组合数、可达交互对数；
- 精确解：最优组合列表（成员、成本、覆盖对数）与总成本；
- 贪心解：对照组合列表与总成本；
- 差距：贪心成本 − 精确成本（绝对值与百分比）；
- 未覆盖项：每个不可达交互对及原因（自身闭包超预算 / 联合闭包超预算）。

## 算法

- **枚举**：`n ≤ 18`，枚举 `2^n` 个子集，筛出依赖闭包完整且不超预算的合法组合（BigInt 位掩码表示）。
- **可达性**：交互对 `(i,j)` 可达 ⟺ `cost(closure(i) ∪ closure(j)) ≤ budget`。
- **精确解**：最小成本集合覆盖。先做支配剪枝（组合 A 覆盖对超集且成本 ≤ B 则 B 被支配），再用分支限界 + 记忆化搜索：选择上界候选最少的未覆盖对分支，下界取未覆盖对的最小覆盖成本最大值；初始上界来自贪心解。
- **贪心解**：每步选择「新增覆盖对数 / 成本」比值最大的组合，平局时取新增对数更多、成本更低者。
- 最大覆盖恒等于全部可达对（每个可达对都有见证组合），因此字典序目标等价于「覆盖全部可达对的最小成本」。

## 复杂度

- 枚举 `O(2^n · n²)`，`n = 18` 时约 26 万子集，秒级完成。
- 精确集合覆盖为 NP-hard；剪枝与记忆化后，18 个改动的典型实例在秒级内求解（见测试用例「十八个改动可在合理时间内求解」）。
