# 硬链接删除配额保留

隔离文件系统按可见路径扣配额，会漏算删除后仍打开的敏感文件。写供Go存储宿主调用的对象计费包，目录项与打开引用分别计数，物理字节直到最后引用关闭才归还；创建链接不能跨租户。重命名覆盖与写入扩容作为事务处理，用故障注入验证失败不增发配额、并发关闭不重复回收。

## quota 包

对象计费实现在 `quota/` 子包，存储宿主通过 `quota.Manager` 调用。

### 计费模型

- 每个对象由创建它的租户永久持有，字节数只向属主租户计一次费。
- 引用分两类分别计数：目录项（硬链接 `links`）与打开句柄（`handles`）。
  两者都为零时对象才被回收，物理字节在最后一个引用消失的瞬间归还配额。
- 因此 `Unlink` 删除唯一目录项后，只要还有打开句柄，字节仍计入属主租户
  （`TestUnlinkedOpenHandleKeepsBytesCharged` 覆盖该场景）。
- `Link` 不增发配额；源对象属主与目标租户不一致时直接返回
  `ErrCrossTenant`，任何命名空间和配额都不改动。

### 事务与故障注入

- `Create`、`Unlink`、`Grow`/`SetSize` 扩容、`Rename` 覆盖均以 undo 日志
  实现事务：每步状态变更登记逆操作，任一步失败按 LIFO 全部回滚。
- `Manager.SetFault(quota.Fault)` 注入故障，按 `(Op, Phase)` 在预留、提交、
  摘除、挂接等阶段触发；注入错误统一包装为 `ErrInjected`。
- 测试断言失败后配额、对象表、目录项、链接计数完全复原，重试只生效一次，
  即“失败不增发配额”。
- 重命名覆盖的受害者若仍被句柄打开，其字节保留到句柄关闭才归还。

### 并发

- 所有状态变更在单个互斥锁下完成，`Handle.Close` 另用 per-handle 锁保证
  并发关闭时恰好一次释放，其余调用返回 `ErrClosed`，回收不会重复。
- `go test -race` 下包含 64 个独立句柄并发关闭与 32 goroutine 共享单句柄
  并发关闭两组测试。

### 运行

```sh
go vet ./...
go test -race -count=1 ./...
```
