多租户裸金属与虚拟化宿主机通过 PCIe SR-IOV 将同一物理网卡/GPU 的多个虚拟功能（VF）直通给不同租户虚拟机时，若 PCIe 交换芯片/根端口未在整条拓扑路径上完整启用 ACS（Access Control Services：`Source Validation`、`Translation Blocking`、`P2P Request Redirect`、`P2P Completion Redirect`、`Upstream Forwarding`），或某设备配置空间的 MMIO BAR 区间相互重叠/越入宿主机 MMIO 敏感区，抑或对不可信 VF 误开启 ATS（Address Translation Services）允许其发送预翻译（Translated）DMA 绕过 IOMMU，恶意租户 VF 可直接发起 P2P DMA 读写同交换机下另一租户 VF 内存或绕过地址翻译。为 C++17 虚拟化安全审计宿主实现可嵌入、零外部依赖、`-Wall -Wextra -Wconversion -Werror` 编译通过的 PCIe 拓扑 SR-IOV / ACS / ATS / BAR 隔离验证库。输入为 PCIe 拓扑树（Root Port、Switch Upstream/Downstream Port、PF、VF）、各节点配置空间能力寄存器（BAR0–BAR5、SR-IOV Capability、ACS Capability/Control、ATS Capability/Control）以及租户 VF 归属与宿主机受保护 MMIO 区间表。验证库精确执行：（1）校验全拓扑全部 PF/VF 的 32/64 位 BAR 与 SR-IOV VF BAR（按 `NumVFs * VF_BAR_Size` 展开）对齐合法、无 64 位回绕、彼此不重叠且不与宿主机受保护 MMIO 重叠；（2）针对任意一对属于不同租户的直通设备 `(A, B)`，沿拓扑树计算其最近公共祖先并逐跳校验上行路径上的全部交换端口与多功能设备均开启所需 ACS 控制位（含 `SV`/`TB`/`RR`/`CR`/`UF`，且禁止跨租户启用 `Direct Translated P2P`）；（3）审计全部非白名单租户 VF 严禁启用 `ATS Enable`，对检出的每项 P2P 逃逸、BAR 重叠或 ATS 绕过输出具体拓扑路径、设备 BDF 与缺失控制位。附跨租户缺失 `ACS RR/UF` P2P 逃逸、SR-IOV VF BAR 重叠与非授权 VF 开启 ATS 测试。
