VLIW 与 AI/DSP 加速器编译器通过软件流水线（Iterative Modulo Scheduling, IMS）重叠执行多轮循环迭代以逼近硬件峰值吞吐，核心算法在依赖环下界、模资源冲突弹射与首尾边界展开上极易出错：1）**精确计算最小启动间隔 `MII = max(ResMII, RecMII)`**：给定循环体 DDG（指令节点含操作类型与所需功能单元类别、依赖边含延迟 `latency >= 0` 与循环携带距离 `distance >= 0`）和硬件各类功能单元数 `units[kind]`，`ResMII = max_kind ceil(count(kind) / units[kind])`，而 `RecMII = max_{有向环 C} ceil(sum_{e in C} latency(e) / sum_{e in C} distance(e))`（若存在 `sum(distance) == 0` 的零距数据环，直接报非法依赖环错误！）；2）**模资源预留表（MRT）与带预算的弹射重排调度**：从 `II = MII` 起按优先高度排序逐一尝试调度每条指令——指令 `u` 放在时刻 `t` 必须满足全部已调前驱 `t >= sched(p) + L - D*II`、全部已调后继 `t <= sched(s) - L + D*II` 且 `t mod II` 时刻对应功能单元尚有余槽；若无空闲槽则弹射（Eject）与之冲突的已调度指令并把它们压回队列（配固定重试预算防无限震荡，超预算则递增 `II` 重试直到产出合法模调度！）；3）**Prologue / Kernel / Epilogue 展开与边界精确处理**：根据最终核调度的跨度 `stageCount = max(sched(u)/II) + 1`，针对任意实际循环行程次数 `N >= 0`（特别覆盖 `N < stageCount` 的短循环防越界多执行迭代！）生成可执行的序幕、稳态核循环与尾声指令序列，并校验每条跨迭代传递的寄存器生命周期自动分配旋转/重命名槽避免新迭代提前覆写旧迭代仍需读取的值；4）内置周期精确功能单元模拟器，验证每个时钟周期绝不超硬件功能单元数、每条跨迭代依赖严格满足延迟，且对 `N = 0, 1, 2, stageCount-1, stageCount, 20` 各类行程产出与原始顺序循环逐元素 100% 相同的计算结果！为加速器编译器后端交付可导入的 Go 迭代模调度与周期精确仿真验证包。验收覆盖多跳循环携带环 `RecMII` 精确计算、零距环报错、MRT 冲突弹射与递增 `II` 收敛、短循环 `N < stageCount` 边界以及跨迭代累加全行程周期仿真等价。
