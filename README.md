通信宿主有几种可选的公开事件编码，需要既保留运维规定必须区分的结果，又保证秘密不会比指定的公开发布点更早暴露。给 Go 协议注册服务写可导入的投影合成组件。协议以有限状态、有理数概率和可见标签描述，只有经宿主签名的发布事件才允许公开相应的秘密类别。在同一发布历史下，准入必须证明本轮之前的全部普通事件及后续未获准字段在不同秘密初态下具有相同分布；提前终止也是观察量。配置只给出允许合并的标签对和不得合并的业务标签对，不可信的合并提示可能不是传递闭包。选择保留类别数最多的安全投影，同时不打破业务约束；并列按规范编码决胜。输出独立可复核的安全与最优性证书，不输出针对实际用户的识别手段。公开原标签至多12种，概率必须精确计算，不能只校验单轮边缘分布或依靠采样。用小表枚举所有允许投影对照先泄露后发布、同分布单次但两轮相关性不同以及两个分别安全的合并放在一起不满足业务区分的情形。
