# 有限请求-响应协议完成性检查器

Python 3.11,仅标准库,测试用 unittest。

## 规则

- **验证对象**: 仅限给定的有限状态模型(`ProtocolModel`),状态、迁移、终态均显式声明。
- **终态声明**: `terminals` 集合显式给出;取消(`CANCELLED`)也是合法声明终态。
- **可能完成(may_complete)**: 从当前状态存在一条到达终态的路径。存在成功路径不代表保证完成。
- **公平必完成(must_complete)**: 所有公平路径都到达终态。要求无可达死锁状态、无可达公平活锁环。
- **公平性**: 弱公平,仅作用于模型声明的 `fair_groups`(如调度器、worker、网络);
  客户端动作(如 `cancel`)不在公平组内,不假设其终将发生。
- **阻塞状态**: `dead` 表示从该状态无法到达任何终态;`livelock` 表示该状态处于
  可无限公平循环却不到达终态的强连通分量中。
- **未决(pending)**: 搜索被 `max_states` 截断、状态空间未搜索完时,判定保持未决,
  不给出反例。
- **反例可重放**: 反例为套索轨迹(前缀 + 环),`replay()` 逐步校验每条迁移在模型中
  真实存在,并校验环闭合与环的公平性(环内覆盖了所有持续可用的公平组)。
- **重复请求 ID 状态独立**: 每次 `accept` 创建独立实例,键为 `(request_id, 序号)`;
  相同 ID 重复接受时各实例状态互不影响。

## 判定逻辑

| 条件 | 判定 |
| --- | --- |
| 搜索未完整 | `pending` |
| 初态不可达任何终态 | `blocked` |
| 可达死锁状态或公平活锁环 | `may_complete`(不保证) |
| 其余 | `must_complete` |

## 文件

- `model.py` — 有限状态模型与请求实例管理器
- `checker.py` — 完成性分析、阻塞状态识别、反例生成与重放
- `samples.py` — 三个演示模型(无限重试 / 有界重试 / 依赖阻塞)
- `run_sample.py` — 运行样例
- `test_checker.py` — unittest 测试

## 运行

```sh
python3.11 run_sample.py
python3.11 -m unittest -v
```
