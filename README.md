隔离端点时，同一文件映射可能同时由多个进程、后台请求及已发送但尚未领取的消息句柄持有。用Go写供端点防护宿主调用的撤回协调库。输入是抽象内核提供的带代次对象事件和各通道单调水位，水位之前的事件已完整。复制、转发、映射切片与派生都产生新的有来源的持有权，关闭源句柄不撤回已发送的接收权。请求隔离某进程最初持有的指定映射范围，并保留同对象上无关授权。对水位不齐的快照只能将有证据的片段判为已撤回，必须给出未知范围、潜在在途派生通道和缺少哪个通道的进展；允许晚到但不跨水位的事件，重复与不同代次重用按身份判别，跨进程派生后的子区间缩小不得掩盖父区间残留写权限。协调器支持中断恢复，同一外部撤回请求带幂等ID，成功回执绑定实际范围与所有参与通道的水位向量。用小型完整事件图解释器核验跨进程转交、待接收消息、部分字节切片授权、中断恢复幂等和水位错开时看似为空的扫描。

## revco 撤回协调库

实现位于 `revco/`，仅依赖标准库。

- `types.go`：代次身份（`HoldKey = Generation + HoldID`）、事件、持有权、区间类型。
- `ranges.go`：半开字节区间的交、差、并运算。
- `graph.go`：小型事件图解释器。按各通道单调水位提交事件，水位之上的事件只缓冲不作为证据；缺失来源的事件进入定点重试；重复投递幂等，同序号不同负载报 `EventConflict`；`receive` 物化新的接收持有权，撤回后才领取的消息“出生即死”。
- `coordinator.go`：来源 BFS 追踪 `issue/copy/slice/derive/send/receive` 全部派生，仅撤回请求根持有权的后代，同对象无来源关系的授权保留；输出已证实撤回片段、未知片段、受阻通道（含当前水位与所需序号）和所有参与通道的水位向量。
- `store.go`：`MemoryStore` 与原子落盘的 `FileStore`，用于中断恢复。

### 语义保证

- 关闭源句柄不影响已发送的接收权；在途消息本身可被撤回，但在接收通道推进前其字节只能判为未知。
- 子区间缩小不会掩盖父区间残留权利：父子持有权同时进入撤回集合。
- 水位不齐时只把有完整证据的片段计入 `Revoked`，其余进入 `Unknown` 并在 `Blocked` 中指名缺失进展的通道。
- 同一幂等 ID 的请求重放返回已绑定的回执；主机失败只重试未落日志的持有权，成功回执绑定实际范围与水位向量。

### 核验

`go test ./...` 运行事件图解释器核验，覆盖跨进程转交、待接收消息、部分字节切片、中断恢复幂等、水位错开的“空”扫描、代次重用与晚到事件不跨水位。
