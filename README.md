# reclaimsim — 复制日志回收模拟器

模拟复制日志的前缀回收（log truncation / GC），核心规则：

1. **全员越水位才可回收**：可回收前缀 = 所有成员已复制水位（`Matched`）的最小值；
   水位等于最小值的成员即**阻挡节点**。
2. **剔除需确认**：`RemoveMember` 只将成员置为 `PendingRemoval`，确认前仍参与水位
   计算、继续阻挡回收；`ConfirmRemoval` 后才退出。
3. **重加入走新代次**：`Rejoin` 要求代次严格递增，水位重置到已回收前缀处
   （更早数据已回收，需从新代次快照恢复）；旧代次心跳一律拒绝。
4. **水位只增不减**：乱序 / 重复 / 越界心跳被拒绝，不会提升水位。

## API 一览

| 方法 | 语义 |
| --- | --- |
| `Append(n)` | 追加日志，返回最高绝对下标 |
| `Heartbeat(id, gen, matched)` | 推进成员水位；代次不符或 matched 回退则报错 |
| `AddMember(id)` / `RemoveMember(id)` / `ConfirmRemoval(id)` | 成员变更（剔除两段式） |
| `Rejoin(id, newGen)` | 以新代次重加入，水位回落到已回收前缀 |
| `Reclaimable()` | 返回可回收前缀与阻挡节点列表 |
| `Reclaim()` | 执行回收，截断到可回收前缀 |

## 运行测试

```sh
go test ./... -v
```

覆盖：全员推进与阻挡节点判定、乱序/重复/越界心跳、旧代次心跳拒绝、
剔除确认前后的阻挡行为、乱序心跳与成员变更交错、回收不回退。
