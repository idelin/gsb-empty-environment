在 Ceph 风格的分布式对象存储中，集群拓扑（OSDMap Epoch）频繁变动并伴随节点反复上下线与网络分区时，Placement Group（PG）必须在恢复任何写服务之前完成严格正确的 **Peering（对等协商）**，否则会丢失已向客户端确认的写操作或读到旧版本，四处核心算法缺一不可：1）**`past_intervals` 与 `maybe_went_rw` 权威历史回溯**：给定一系列 OSDMap 纪元历史（包含每个纪元的 `up` 集合、`acting` 集合与 `min_size`），构建 `past_intervals`——每个历史区间若当时处于 `active` 且成员数 `>= min_size` 则标记 `maybe_went_rw = true`；在当前纪元发起 Peering 时，主 OSD 必须从所有已查询到的历史 `maybe_went_rw` 区间中，确认每个此类区间**至少有一个成员**参与了本次日志探测（否则存在可能已确认写入但全员失联的风险，必须立刻停在 `Incomplete/Down` 阻塞状态，绝不可私自 `Active`！）；2）**主日志选择与分叉日志（Divergent Log）回滚**：比较各参与 OSD 的 `(last_update, last_complete, log_tail)`，挑选最新合法 `auth_log`（注意：不能盲选 `last_update` 最高的 OSD——若某旧主在分区中被孤立并写入了未达 `min_size` 的孤立日志，其条目相对于已确认的 `last_epoch_started` 属于分叉日志，必须被识别为 `divergent_priors` 并截断回滚！）；3）**`up` vs `acting` 临时集合与 `missing` 集合推导**：当新 `up` 成员数据落后（`backfill` 场景）时，主 OSD 自动构造临时 `pg_temp` 使 `acting` 集合沿用已有完整副本的旧 OSD 提前恢复 `active+degraded` 服务，同时为每个成员精确计算 `missing` 对象版本集合与全局 `missing_locations`；4）**`unfound` 对象检测与 `min_size` 写门禁**：对于权威日志声明存在最新版本号但当前全部在线存活 OSD 均未持有该版本的对象，精确标记为 `unfound` 并禁止该对象读写；仅当可用副本数 `>= min_size` 且无阻断性历史缺口时才转入 `Active` 允许写入。为分布式存储控制面交付可导入的 Go PG Peering 协商、权威日志合并与恢复状态机包。验收覆盖历史 `maybe_went_rw` 全员失联阻断 `Incomplete`、分区孤立旧主分叉日志精准截断回滚、`up != acting` 生成 `pg_temp` 与精确 `missing` 计算以及 `unfound` 对象定位。
