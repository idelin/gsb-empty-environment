多租户 API 网关的层级配额树（集群 -> 租户 -> 服务 -> 接口）既要对每个节点执行速率与突发上限，又允许突发流量向父节点与空闲兄弟借用富余容量，同时必须死守每个兄弟节点的最低保底额度（`minGuaranteed`）不被贪婪租户掏空；当一条大代价请求（`cost > 1`）在叶子层通过但在祖先层超限时，若未做原子回滚就会永久扣丢叶层令牌，而使用 `float64` 累计微秒级令牌又会在长时间运行后产生精度漂移。为网关限流控制面交付可导入的 Go 分层借用令牌桶准入账本（内部全程采用 64 位整数定点运算无浮点误差！）。树中每节点配置 `(ratePerSec, burst, minGuaranteedRate, maxBorrowBurst, priority, shadowOnly)`，父节点容量大于等于直接子节点 `minGuaranteedRate` 之和。规则：1）任意请求 `(nodeId, cost, nowMicros)` 在从叶到根整条路径上按两阶段试算+提交原子执行——先按微秒时间差补充各节点自有令牌（封顶 `burst`）与保底保留池，校验自有令牌不足时在 `maxBorrowBurst` 上限内向祖先富余池（严格扣除其余活跃兄弟尚未消费的保底预留量！）借用差额；若任一非 `shadowOnly` 祖先无法满足则整条路径零扣减并精确返回导致拒绝的瓶颈节点与建议重试等待微秒数 `retryAfterMicros`；2）`shadowOnly=true` 的节点仅参与试算并记录 `shadowRejected` 审计信号，绝不阻断真实请求、也不因其自身被拒而回滚正常节点扣减；3）支持运行时动态调配某节点 `rate`/`burst`/`minGuaranteed` 而不丢失已合法积攒的未超新上限令牌，且校验配置变更绝不破坏子保底之和不超过父容量不变式。验收覆盖大代价请求高层拒绝零泄露回滚、贪婪租户借满 `maxBorrowBurst` 仍无法侵占兄弟 `minGuaranteed`、影子节点审计不误拦、`retryAfterMicros` 精确到微秒（推进该时长后重试必通过！）以及长时定点无漂移校验。
