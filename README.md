# lockmgr — 本地文件锁管理库（C++17）

以**规范资源 ID** 为锁对象的进程内锁管理器，支持共享 / 独占 / 升级，
可取消，句柄关闭即释放全部持有。

## 构建与测试

```sh
cmake -S . -B build && cmake --build build -j
cd build && ctest --output-on-failure
```

- `interleaving_test`：屏障穷举短交错（284 个交错序列）
- `model_test`：独立持锁模型的随机并发验证 + 饥饿条件验证

## 固定语义

### 资源 ID 规范化
`LockManager::canonicalize` 对路径做 `lexically_normal` 并折叠多余分隔符：
`"/a/./b/../c"`、`"/a/c"` 映射到同一把锁。所有会话操作在入口规范化，
调用方可传任意等价写法。

### 锁模式与重入
- `lock_shared` / `lock_exclusive`：阻塞获取。
- 同级重入为无操作；持有共享时 `lock_exclusive` 等价于不可取消的隐式
  升级（冲突时抛 `std::runtime_error`）；持有独占时任何获取均为无操作。
- `try_lock_*`：不阻塞；已持有共享时 `try_lock_exclusive` 返回 false
  （try 不做隐式升级）。

### 排队次序（防饥饿）
每个资源一条**严格 FIFO** 队列，只有队首请求可被授予；队首为共享请求
时连续的共享请求一并授予。写者 / 升级者之前的读者照常进入，之后的
读者排队等待 —— 写者与升级者不会被读者流饿死（由
`test_writer_starvation` / `test_upgrade_starvation` 在有界时间内验证）。

### 升级（两个读者同时升级不会互相永久等待）
- 升级只允许注册在**空队列**上：已有升级在排队、或队列中已有其它
  等待者（如写者）时，`upgrade` 立即返回 `Conflict`。
- 若允许升级排在写者之后等待，写者又在等升级者释放共享锁，双方会
  互相永久等待；空队列约束从结构上排除了这一等待环。
- 升级等待期间只阻塞于“其它共享持有者释放”，可授予时原子地由共享
  转换为独占，中间不释放共享锁。

### 可取消行为与取消后的共享锁（固定：保留）
- `upgrade(rid, token)` 可被 `CancelToken::cancel()` 取消（可跨线程、
  可在注册前取消），返回 `Cancelled`。
- **取消后原共享锁保留**；`Conflict`、`NotHeld` 同样不影响已持有的锁。
- 普通 `lock_*` 不可取消；会话被关闭时其排队中的请求按取消处理。

### 句柄关闭
`Session::close()` / 析构释放该会话持有的**全部**锁并取消其排队中的
请求；幂等。已关闭会话上的获取操作抛 `std::logic_error`。

### 重复释放
`unlock` 未持有的资源（含重复释放、已关闭会话）返回 `false`，
不改变任何状态；绝不影响其它持有者。

### 调用方责任
库保证单资源层面无永久等待；跨资源的 hold-and-wait（持 A 等 B）属于
调用方责任，库不做死锁检测。需要多把锁时请按固定顺序获取或先释放再获取。

## 测试方法

### 屏障穷举短交错（tests/interleaving_test.cpp）
- 每个场景 = 若干线程 × 短操作脚本；每个交错序列使用全新管理器。
- 控制器按回合释放一个线程执行一步，并等待其**完成本步**或**在管理器
  内部阻塞**（`set_park_hook` 在请求入队且不可立即授予时触发）才进入
  下一回合；对所有多重集排列穷举。
- 若线程仍阻塞在更早的步（解除依赖后续回合），控制器不等待其进展，
  避免控制器与线程互相等待。
- 末尾看门狗检测永久等待；持锁期间用自省接口与临界区计数器验证互斥。
- 覆盖：S/X 两两组合、双读者升级、升级取消、升级阻塞新读者（FIFO
  公平）、重复释放、关闭释放全部、规范 ID 等价性。

### 独立持锁模型（tests/model_test.cpp）
- 测试侧维护独立于实现的模型：线程本地 `held` 表 + 全局原子临界区
  计数器（**获取返回后递增、unlock/close 调用前递减**，使计数严格覆盖
  实际持有区间，违规必为真实重叠）。
- 6 线程 × 300 随机操作（加锁/try/升级/取消/释放/重复释放/关闭重开），
  校验互斥、unlock 返回值与模型一致、升级失败后共享锁保留、结束时
  管理器与模型均为空。
- 饥饿：读者持续涌入时写者与升级者必须在有界时间内被授予。
- 调用方侧约束：阻塞操作前释放其它资源（单资源持有不变式），避免
  测试自身构造出库职责之外的跨资源等待环。
