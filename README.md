# logalloc

Go 日志分配器：先预留批次序号再写数据，配合显式跳过记录与持久化切点实现可恢复的发布流。

## 核心机制

- **预留优先**：`Reserve(n)` 先把序号区间持久化到 WAL 再返回，崩溃后同一序号绝不重复分配。
- **预留-决定分离**：每个序号有三种状态——`pending`（已预留未决定）、`committed`（数据已写入）、`skipped`（显式跳过）。预留与提交之间崩溃会留下 pending 空洞。
- **切点推进**：`AdvanceCut()` 只在连续已决定的序号上推进持久化切点；pending 空洞会阻塞发布，必须用 `Skip()` 写入显式跳过记录封闭空洞后才能继续前进。
- **恢复**：重启重放 WAL 后，`Pending()` 列出所有已预留未决定的序号（跳过记录不会误报为 pending），恢复流程据此逐个补数据（`Commit`）或补跳过（`Skip`）。
- **消费核对**：消费者以持久化切点为界，`Read(after, limit)` 只返回 `(after, Cut()]` 内已提交的记录；切点保证其下每个序号都有且仅有一个决定，从而消费连续且不重复。
