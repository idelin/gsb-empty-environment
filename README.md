SQL 标准 `MERGE INTO target USING source ON join_pred` 融合了条件 `UPDATE`、`DELETE`、`INSERT` 与 `DO NOTHING`，其执行语义有四条极易被简化成普通 UPSERT 而写错的硬约束：1）每对匹配的 `(targetRow, sourceRow)` 严格自上而下测试各 `WHEN MATCHED [AND cond]` 分支，只执行**第一条**条件求值为 `TRUE` 的分支后立即短路（绝不落入后续分支！），未匹配源行同理测试 `WHEN NOT MATCHED [BY TARGET]`，未匹配目标行则测试 `WHEN NOT MATCHED BY SOURCE`；2）**单行基数冲突（Cardinality Violation）**——若源表多行同时匹配同一目标行，只要该目标行已被先前的匹配动作实际执行了 `UPDATE` 或 `DELETE`，后续匹配再次尝试对该目标行执行 `UPDATE` 或 `DELETE` 必须立刻抛出 `CARDINALITY_VIOLATION` 错误并原子回滚整条 `MERGE`（注意：若先前的匹配命中了 `DO NOTHING` 或条件全假未执行动作，则不视为已修改，允许后续匹配动作生效！）；3）**快照可见性边界**——本条 `MERGE` 中由 `WHEN NOT MATCHED` 新插入的目标行，绝不可在同一条 `MERGE` 语句执行期间再被后续源行匹配到！4）**立即 vs 语句末延迟唯一约束（`IMMEDIATE` vs `DEFERRED`）**——当唯一索引设为 `DEFERRED` 时，允许单条 `MERGE` 原子互换两行唯一键（如 `row1.code='A'->'B'` 且 `row2.code='B'->'A'`）而只在语句结束时校验最终无重复；而设为 `IMMEDIATE` 时中途冲突即刻回滚，同时支持标准 `NULLS DISTINCT`（多行 `NULL` 不冲突）与 `NULLS NOT DISTINCT`（多个 `NULL` 视为重复冲突！）两种唯一索引模式。为关系数据库执行层交付可导入的 TypeScript `SQL MERGE` 执行与约束校验库。验收覆盖多分支条件短路、双源行命中同目标行触发 `CARDINALITY_VIOLATION` 回滚、`DO NOTHING` 不触发冲突、新插行本语句不可见、`DEFERRED` 唯一键原子互换以及 `NULLS DISTINCT` vs `NULLS NOT DISTINCT` 差异。
