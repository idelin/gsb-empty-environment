堡垒机与 SSH 认证宿主在校验 OpenSSH 用户/主机证书（`ssh-ed25519-cert-v01@openssh.com`）与二进制密钥吊销列表（KRL `SSHKRL` 格式）时，若解析器放过未知关键选项（`critical options`）、错误忽略证书序列号区间吊销或未按字典序校验 KRL 子段，已被吊销或越权指定 `source-address` 的凭证仍可登录生产主机。为 Go 认证宿主实现可导入的原生二进制 OpenSSH 证书与 KRL 吊销验证包，严禁依赖 `golang.org/x/crypto/ssh` 证书与 KRL 解析（仅用标准库 `crypto/ed25519`、`crypto/sha256`）。组件从原始线格式字节完整解码 SSH 证书各字段（`nonce`、公钥、`serial`、`type`、`key id`、`valid principals`、`valid after/before`、`critical options`、`extensions`、`signature key`、`signature`），用真实 Ed25519 验签并严格执行：拒绝未知关键选项、校验 `valid_after <= now < valid_before`、验证请求主体命中 `valid_principals`（禁止空列表通配通融除非宿主显式开启）、校验 `source-address` CIDR 列表覆盖连接源 IP 且当 `force-command` 存在时强制回传不可覆盖命令。对 `SSHKRL` 二进制文件完整解析魔数、版本与全部段类型（`CERTIFICATES` 段内按 CA 公钥分组的 `SERIAL_LIST`/`SERIAL_RANGE`/`SERIAL_BITMAP`/`KEY_ID`，以及 `EXPLICIT_KEY`/`FINGERPRINT_SHA256` 段），严格拒绝越界长度、乱序位图及截断记录，确保任意命中显式公钥、SHA-256 指纹、序列号（含 0 序列号特例）、位图偏移或 `key_id` 的证书一律判为已吊销拒收。附手工构造的二进制证书与多段 KRL 攻击向量全覆盖测试。
