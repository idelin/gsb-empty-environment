# isect — 带检查证据的多列表交集工具

每个排序 ID 列表存放在独立的块（block）中，块摘要包含 `Min` / `Max` /
`Count` / `Hash`（SHA-256，对规范化后的 ID 序列承诺）。求交集时：

- 任何公共 ID `x` 必满足 `lower <= x <= upper`（`lower` = 各列表最小值的最大值，
  `upper` = 各列表最大值的最小值）。
- 完全落在窗口之外的块被跳过，且证明中记录具体依据
  （如 `block max 3 < lower bound 5`）。
- 与窗口重叠的块一律被读取并逐元素求交——**范围重叠不能推断实际命中**。

验证器（`Verify`）读取证明涉及的每个块：重算哈希确认摘要未被篡改，
检查每条跳过依据成立、没有块被藏匿，并用读取到的块重算交集，
确认结果不漏项、不多项。篡改摘要、结果或证据都会失败。

## 结构

- `intersect/block.go` — 块、摘要、规范化（排序 + 去重）
- `intersect/intersect.go` — 交集计算与证明生成
- `intersect/verify.go` — 证明验证器
- `cmd/isect` — 命令行工具

## 使用

```sh
go test ./...
go run ./cmd/isect -block 4 list1.txt list2.txt list3.txt
```

输入文件每行一个十进制 ID（自动排序去重）。工具打印交集、逐块证据
（含跳过依据）并自验证明。

## 测试覆盖

- 空列表 / 空块：交集为空，所有块带依据跳过
- 重复 ID 规范化：摘要去重、结果不重复
- 恰好相等的边界：`max == lower` / `min == upper` 的块必须被读取而非跳过
- 篡改检测：证据摘要、块存储摘要、结果被篡改均验证失败
- 随机列表与朴素交集对照（200 组）
