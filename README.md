# expr-repair

表达式语法修复器：处理整数、函数调用、数组字面量和四则运算。语法错误时，
允许**插入**或**删除** token（单位代价均为 1），返回**代价最小、修复序列
字典序最小**的合法修复，并保留原 token 的位置信息。

## 文法

```
expr     -> term (('+'|'-') term)*
term     -> factor (('*'|'/') factor)*
factor   -> int | ident '(' args ')' | '[' elems ']' | '(' expr ')'
args     -> (expr (',' expr)*)?
elems    -> (expr (',' expr)*)?
```

（实现中写成无左递归、无 epsilon 环的形式，见 `src/grammar.ts`。）

## 算法

把文法模拟为下推自动机，配置为 `(输入位置, 符号栈)`：

- **零代价移动**：展开非终结符；匹配当前输入 token。
- **代价 1 移动**：删除当前输入 token；插入自动机当前期望的终结符。
  只插入"被期望"的终结符是完备的——自动机恰好遍历所有
  (修复后串, 语法分析) 对，代价 = 插入/删除编辑距离。

在此图上：

1. **求最小代价**：A\*（可采纳启发式 `h = max(0, 栈最小产出 − 剩余输入)`，
   标签修正式实现，允许重松弛，保证最优）。`maxCost` 剪枝同时保证
   零代价闭包有限。
2. **字典序最小修复序列**：在最小代价 `C` 下逐步贪心——每一步枚举当前
   可达配置集合的所有候选编辑，按规范序（删除 < 插入，再按原位置、
   token 种类，见 `src/edits.ts` 的 `editKey`）取最小且**仍可在 `C` 内
   完成**的编辑；可行性由带备忘的精确"到接受距离"预言机判定。

## 搜索预算与上下界

`repair(tokens, { budget, maxCost })`：

- `budget`：第一阶段最大扩展状态数（默认不限）。
- `maxCost`：代价截断（默认 `n+1`——删光再插一个整数必然可行）。

预算或截断超限时**不返回修复结果**，只返回当前上下界：

- 下界 = 搜索前沿的最小优先级（代价 + 可采纳启发式）；
- 上界 = 已松弛到的最小接受代价（初始为 `n+1`）。

## 验证（`test/verify.ts`）

- **短 token 串穷举核对**：小字母表上长度 ≤ 4 的全部串（738 条）+
  全终结符随机串，与暴力预言机 `src/bruteforce.ts` 对比。暴力枚举器按
  代价升层、收集该层**所有**可解析修复序列再取字典序最小——绝不把
  首个可解析方案当作最优；可解析性由独立的递归下降解析器
  （`src/parser.ts`）判定，与主修复器的 PDA 实现互为交叉验证。
- 针对性用例覆盖字典序平局（删除 vs 插入、删前 vs 删后等）。
- 预算/截断时的上下界包含性、位置保留、确定性。

共 6662 项检查。

## 运行

需要 Node ≥ 23.6（原生类型擦除；或 Node 22.6+ 加
`--experimental-strip-types`）：

```sh
node src/main.ts 'f(1+2,]'        # 演示：输出最小编辑序列与修复结果
node src/main.ts '1+*(' 5         # 第二个参数为搜索预算：超限只报上下界
node test/verify.ts               # 验证套件
```
