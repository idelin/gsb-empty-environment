多租户数据库网关复用预处理语句时，服务端语句编号只在单条连接内有效，错配会执行另一租户的SQL。写供Go查询宿主调用的执行组件，句柄绑定物理连接代次、数据库身份、模板摘要和参数类型，参数始终通过结构化绑定传递，禁止失败后退回文本拼接；执行、关闭与重准备并发时，旧回调不能覆盖新句柄，最后一个在途执行结束后才关闭服务端语句。用两条故意返回相同编号的模拟连接测试连接重建、模式变化、取消及参数数量错误，核对实际执行的模板和参数归属。

## 实现

- `gateway`：查询宿主调用的执行组件。
  - `Gateway` 持有当前物理连接与连接代次，`Rebuild` 递增代次并作废旧语句。
  - `Entry` 为预处理句柄，绑定数据库身份、模板摘要（SHA256）、参数类型与连接代次。
  - 参数只通过 `gateway.NamedArg` 结构化绑定交给驱动；任何校验/执行失败只返回错误，无 SQL 文本拼接回退。
  - 重准备采用 RCU：新执行切换到新服务端语句，旧语句在最后一个在途执行结束后才调用驱动 `CloseStmt`。
  - 异步完成回调按“语句指针 + 句柄当前指针”判旧，迟到/旧代回调只回收计数，结果丢弃。
- `mock`：模拟物理连接与服务端。两条连接的服务端语句编号都从 1 开始（故意相同），
  支持在途阻塞、prepare/exec 门控、失效/模式变化错误注入与完整调用审计。

## 测试

`go test -race ./...` 覆盖：两条连接相同编号、连接重建、模式变化重准备重试、
取消与迟到回调丢弃、参数数量/类型/序号错误、并发执行-重准备-关闭的排空不变量、
准备期间重建的竞态对账，以及身份/模板绑定与实际模板和参数归属核对。
