# 门店补货规划器（混合整箱配送）

在混合整箱配送约束下，决策**各箱型采购箱数**与**门店分配方案**，使
**采购成本 + 运输成本 + 欠供罚金** 最小。需求允许少量欠供，但需按件支付罚金。

## 模型

- 最多 **8 种箱型**、**5 家门店**（输入校验强制）。
- 每种箱型 `i`：容量 `cap_i`（件/箱）、采购成本 `cost_i`（元/箱）。
- 每家门店 `j`：需求 `D_j`、欠供罚金 `p_j`（元/件），可选门店级每箱运输成本。
- 决策变量 `x_ij`：分配给门店 `j` 的箱型 `i` 的箱数（非负整数）。

目标：

```
min  Σ_j [ Σ_i (cost_i + trans_ij) · x_ij  +  p_j · max(0, D_j − Σ_i cap_i · x_ij) ]
```

**约束与假设**

- 整箱配送：箱不可拆分，每箱完整归属唯一门店；门店的配送可由多种箱型混合组成。
- 禁止拆箱后跨门店无成本流转：模型中不存在门店间转运边，剩余库存留在原门店。
- 门店间无共享库存/预算耦合，因此问题按门店精确分解，各店独立最优即全局最优。

**求解方法**：对每家门店做完全背包 DP——`g(v)` 为恰好配送 `v` 件的最小
（采购+运输）成本，`v ∈ [0, D + maxCap − 1]`；再枚举 `v` 加上欠供罚金取最小，
回溯得到各箱型箱数。复杂度 `O(箱型数 × 需求上界)`，为精确最优解。

## 使用

```bash
# 编译（需要 TypeScript，如 npx tsc）
tsc -p tsconfig.json

# 运行
node dist/src/index.js examples/sample.json

# 校验（2000 个随机小实例与暴力枚举对比 + 端到端守衡检查）
node dist/test/verify.js
```

## 输入格式（JSON）

```json
{
  "transportCostPerBox": 2,
  "boxTypes": [{ "id": "M", "capacity": 12, "unitCost": 18 }],
  "stores": [
    { "id": "A", "demand": 45, "shortagePenalty": 3, "transportCostPerBox": 4 }
  ]
}
```

- `transportCostPerBox`：全局每箱运输成本（可选，默认 0）；门店内同名字段可覆盖。
- 所有数值须为整数；容量为正，成本/罚金/需求非负。

## 输出

- 各箱型采购总箱数；
- 每门店：箱型分配、配送件数、欠供件数与罚金、**剩余库存**、成本明细；
- 汇总：采购/运输/欠供罚金/总成本，剩余库存与欠供合计。
