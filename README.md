# 撤销表代次复用让旧能力复活

对象能力通过表槽间接引用资源，撤销后槽位复用若代次回绕，旧能力可能重新命中新对象。给Go宿主实现可导入的间接能力表：能力票据含tableID、slot、32位generation、权限、对象类型和MAC；MAC由宿主HMAC覆盖全部字段，表ID固定且不从请求选择。Allocate从空槽取当前generation并写对象，Issue只能由已分配对象生成权限子集票据；Use先验MAC，再常量时间比较代次、类型和权限。Revoke清对象并把generation加1，达到2^32-1后该槽永久burned，不回绕；ClearTable创建新tableID并烧毁旧表全部票据。批量Revoke/Allocate事务先验证后原子发布，失败不部分复用。实现一个待审的16位代次表，并在最多3槽的模型中用压缩循环证明旧票据在回绕后访问不同对象，证明记录初始票据、每次撤销/分配摘要及最终Use；正确模型须拒绝同样票据。覆盖MAC换权限、slot越界、类型相同但对象不同、表ID重建及Use先线性化读取表项后核对能力，Revoke线性化后旧Use不得成功；覆盖并发Use/Revoke的线性化顺序。
