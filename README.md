# 候补递补引擎（互斥场次）

TypeScript 实现的候补递补库：一人可报名多个互斥场次，按优先级与报名序号排队，
递补级联直到稳定，撤销确认按原候补资格恢复。

## 核心语义

- **互斥组**：同一 `mutexGroup` 内的场次互斥，一人至多持有一个确认名额。
- **排队规则**：候补队列按「优先级降序 → 报名序号升序」排序；序号全局递增、终身不变。
- **递补（stabilize）**：每次操作后自动运行至稳定。场次有空位时，按队列顺序
  找到第一个可接受的候选人递补；若该人已在同组较不偏好的场次确认，则放弃原场次、
  释放的名额进入级联，直到没有可发生的递补为止。
- **防循环**：每人只接受比当前确认场次**严格更偏好**的场次。每次递补都使被递补者
  的偏好严格改进（或从无到有），偏好档位有限，故必然收敛；另有步数上限兜底。
- **完整递补链**：所有事件（报名/递补/释放/撤销/取消/恢复）按序记录，
  `causedBy` 字段链接因果（谁释放的名额触发了本次递补），可输出完整链条。
- **撤销确认（revokeConfirmation）**：按原 `(priority, seq)` 回到候补队列**原位**，
  绝不重新排尾；同时标记 `declinedOffer`，避免刚撤销又被同一空位立即递补回去。
  通过 `reinstate` 可恢复该场次的递补资格。
- **对比**：`cancel` 是彻底退出，日后再报名会拿到新序号、重新排尾。

## 运行

```bash
npm install -D typescript   # 或任何可用的 tsc
npm run build               # 编译到 dist/
npm test                    # 运行测试
npm run demo                # 运行演示，打印完整递补链
```

## 文件

- `src/waitlist.ts` — 引擎核心（`WaitlistEngine`）
- `src/demo.ts` — 演示：多人互斥报名 → 级联递补 → 撤销恢复
- `test/waitlist.test.ts` — 10 个语义测试
