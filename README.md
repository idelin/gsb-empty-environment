# diskbtree

纯标准库实现的磁盘 B 树(Go),支持插入、重复键覆盖、点查、范围扫描、
快照,以及可恢复的节点分裂。所有文件放在调用方指定的目录下:

- `data.db` — 页数据(定长页,追加分配,已提交的页永不原地修改)
- `meta` — superblock,两个 64 字节槽位交替写入

## 设计

**写时复制(COW)+ 双槽 superblock。** 每次 `Put` 是一个独立事务:

1. 从叶到根复制整条路径上的节点,写入 `data.db` 中从未使用过的新页;
   分裂产生的新页同样只写新位置。旧版本页一个字节都不动。
2. `fsync(data.db)` —— 新页全部落盘。
3. 把 `{txid+1, 新根页号, numPages}` 写入 `meta` 的另一个槽位(带 CRC32)。
4. `fsync(meta)` —— 提交完成,新状态对外可见。

**逻辑叶链。** 叶子记录后继叶子的首键(`nextKey`)而不是页号。COW 会
改变页号,页号链必须级联修改前驱才能维护,与 COW 冲突;而分裂时左半页
保留原首键,前驱的 `nextKey` 永远有效,旧快照的链也不受新写入影响。
跨叶扫描时按 `nextKey` 从快照根重新下钻,叶子不可变保证无重复、无遗漏。

## 崩溃恢复

`Open` 即恢复:读取两个 superblock 槽位,取 CRC 校验通过且 `txid` 最大
者。提交协议保证任意崩溃时刻,恢复结果只能是**旧的完整状态**或**新的
完整状态**之一:

| 崩溃时机 | 恢复结果 |
|---|---|
| 新页写入中 / fsync 数据前 | 旧状态。新页未被 superblock 引用,成为不可达垃圾 |
| 数据已 fsync、superblock 未写(叶已写好但父未发布) | 旧状态。新根不可达,旧根完整 |
| superblock 已写未 fsync | 旧或新状态,取决于 OS 是否已落盘;两者都完整 |
| superblock 已 fsync | 新状态 |

未提交事务分配的页号随旧 superblock 的 `numPages` 一起被丢弃,空间泄漏
但不影响正确性(本实现不做空闲页回收)。

**根分裂后旧快照仍有定义**:快照只持有旧根页号,而旧页永不被覆盖,
因此旧快照可以完整遍历旧状态。

## 断电保证的边界

保证成立的前提:

- `fsync` 语义可信:数据落盘顺序为"数据文件 → superblock",依赖
  存储设备不谎报 fsync 完成(企业级/断电保护盘;消费级盘在掉电时
  可能丢失已确认刷新的数据,此时任何软件都无法保证)。
- superblock 单槽写入(64 字节)允许被断电**撕裂**:CRC32 校验会识别
  撕裂的槽位并回退到另一槽,因此不要求单扇区原子写。
- 数据页的撕裂写无害:未被 superblock 引用的页永远不可达。

不保证:

- meta 两个槽位同时损坏(如整文件被覆写)时无法恢复,`Open` 报错。
- 崩溃泄漏的页空间不回收,长期崩溃-重启循环会让 `data.db` 增长。
- 无并发写事务:同一时刻只允许一个 `Put`(由互斥锁保护)。

## 故障注入

`Options.CrashHook func(FaultPoint) bool` 在提交协议的三个注入点
(`FaultBeforeDataSync` / `FaultAfterDataSync` / `FaultAfterMetaWrite`)
回调,返回 `true` 即 panic `ErrSimulatedCrash` 模拟崩溃;丢弃句柄后
重新 `Open` 同一目录即模拟重启恢复。见 `TestCrashRecovery`。
