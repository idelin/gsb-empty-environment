# reorder-check

指令重排检查器：给定一条直线指令序列（原始调度）与另一条序列
（候选重排），验证候选是否为合法重排。

## 指令格式

每行一条指令，`#` 之后为注释。读写对象为命名寄存器或明确的
半开内存区间 `[lo, hi)`（宽度 1–8 字节）：

```
r1 = const 42          # 写寄存器 r1
r1 = add r2, r3        # ALU：add/sub/mul/xor/and/or，读 r2,r3 写 r1
r1 = load [0, 8)       # 读内存区间，写 r1
store [0, 8), r1       # 读 r1，写内存区间
fence                  # 屏障
```

## 合法性判定（依赖分析，权威结论）

候选序列必须是原始序列的一个排列（相同的多重指令集合），并且保持
原始序列中的全部依赖边：

- **RAW**（真依赖）：先写后读同一位置；
- **WAR**（反依赖）：先读后写同一位置；
- **WAW**（输出依赖）：两次写同一位置；
- **BAR**（屏障）：`fence` 之前的指令不得移到之后，反之亦然。

别名判断是精确的：寄存器仅与同名寄存器别名；内存区间按字节级
重叠判定（`[0,8)` 与 `[8,16)` 不相交，与 `[7,15)` 相交于字节 7）。
寄存器与内存永不别名。

判定为非法时，输出**最早**被违反的依赖边（按原始程序序中源指令
位置排序），例如：

```
ILLEGAL: earliest violated dependence: RAW on r1: #2 "r1 = add r1, r2" must stay before #3 "store [16, 24), r1"
```

退出码：`0` 合法，`1` 非法，`2` 用法/解析错误。

## 有限初始状态穷举（辅助核对）

检查器还会把两条序列在有限初始状态集上分别执行并比较最终状态：

- 涉及单元 ≤ 12 时以 `{0, 1, 0xFF}` 穷举，≤ 20 时以 `{0, 1}` 穷举；
- 否则以固定种子随机采样 2^20 个状态；
- 单元数超过 65536 时跳过模拟。

发现发散即构成非法的具体反例（报告初始状态与首个不同单元）；
但**结果一致不证明无依赖**——碰巧在所有采样状态上结果相同
（例如 `r1 = xor r2, r2` 与 `r1 = const 0` 交换）时，依赖分析
依然判定非法，模拟结果永远不会推翻依赖分析。

## 使用

```
go build -o reorder-check .
./reorder-check original.seq candidate.seq
go test ./...
```
