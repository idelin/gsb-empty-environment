# 资金分配求解器 (fundsolver)

在来源资金的**限定用途**、**有效期**与**配捐规则**约束下，把资金分配给项目：
项目**整笔达标才计收益**，求**总项目收益最大**的分配方案；次目标为**过期闲置金额最少**；
入选项目数**不超过 15 个**（可配置）。输出每笔资金流向及其触发依据。

## 构建与运行

```sh
go build -o fundsolver .
./fundsolver examples/sample.json        # 人类可读报告
./fundsolver -json examples/sample.json  # JSON 报告
cat input.json | ./fundsolver            # 从标准输入读取
./fundsolver -max-projects 10 input.json # 覆盖项目数上限
go test .                                # 运行测试
```

## 输入模型

```json
{
  "max_projects": 15,
  "sources": [
    {"id": "S1", "name": "教育专项", "amount": 100000,
     "categories": ["教育"], "expires": "2026-12-31"},
    {"id": "M1", "name": "配捐池", "amount": 60000,
     "categories": ["教育", "医疗"],
     "match": {"ratio": 1.0, "per_project_cap": 30000}}
  ],
  "projects": [
    {"id": "P1", "name": "乡村图书馆", "category": "教育",
     "goal": 90000, "benefit": 800, "deadline": "2026-11-30"}
  ]
}
```

- **来源 `sources`**
  - `categories`：限定用途，空表示不限；只能投向同类别的项目。
  - `expires`：有效期（`YYYY-MM-DD`），空表示长期有效。来源只能投向截止日不晚于其有效期的项目；到期未投出的部分计入**过期闲置**。
  - `match`：存在则该来源为**配捐池**，不直接拨付。每当某项目获得 1 单位**非配捐来源**的基础资金，配捐池按 `ratio` 跟投，单项目不超过 `per_project_cap`（0 为不限），全池合计不超过池总额。
- **项目 `projects`**
  - `goal`：整笔目标金额；只有足额到账才计 `benefit` 收益，未入选项目不拨付任何资金。
  - `benefit`：达标收益（非负）。

## 规则与假设

1. **配捐不递归**：配捐池只被非配捐来源的基础资金触发；配捐资金本身不会再触发任何配捐。多个配捐池可以同时对同一项目的基础资金配捐。
2. **字典序目标**：先最大化总收益；在所有收益最优的方案中，选择过期闲置金额最小的（即优先花掉临期资金）。
3. **整笔达标**：项目要么足额入选，要么完全不资助；不会把资金投进无法达标的项目。
4. 无截止日的项目视为可即时接收资金，不受来源有效期限制。

## 求解方法

- **项目选择**：按收益降序做分支定界。收益上界（剩余名额取收益最高项目之和）用于主目标剪枝；
  平局时用“过期闲置下界”（临期总额 − 剩余需求可吸收的临期资金上界）做次目标剪枝。
  可行性随项目增加单调变差，不可行集合的所有超集直接剪掉。
- **可行性 / 资金流**：对固定项目集合构造线性规划，用两阶段单纯形法（`lp.go`）求解：
  - 可行性：最大化总拨付额，约束为来源额度、配捐池额度、配捐触发约束
    `y_{m,p} ≤ ratio_m · Σ_s x_{s,p}`（基础资金只含非配捐来源）、单项目配捐上限、项目目标上限；
    最优值达到目标总额即可行。
  - 次目标：固定各项目足额（等式约束），最大化临期来源的使用量，即最小化过期闲置。
- LP 最优解的每个正变量即一笔资金流向，配捐流的触发依据（基础资金金额与来源、比例、上限）由解直接生成。

## 输出

- `funded_projects` / `unfunded_projects`：达标与未达标项目清单；
- `flows`：每笔资金流向，`type` 为 `direct`（直接拨付）或 `match`（配捐），`basis` 为触发依据；
- `idle_funds`：各来源剩余金额，`expired=true` 的计入过期闲置；
- `total_benefit` / `expired_idle`：两个目标值。

## 测试

- `lp_test.go`：单纯形法单元测试（含等式约束、不可行判定）；
- `solver_test.go`：规则测试（整笔达标、配捐不递归、比例与上限、有效期、用途限定、
  15 个项目上限、主/次目标优先级）以及随机小规模与暴力枚举的对拍和方案合法性校验。
