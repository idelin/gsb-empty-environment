Kubernetes 风格准入链按顺序执行多个 Mutating Webhook，靠后的插件修改对象后可能破坏前面插件注入的字段，因此支持 `reinvocationPolicy: IfNeeded` 触发第二轮甚至多轮重入，但两个插件互相改写同一字段会陷入震荡死循环。为 API 准入内核交付可嵌入的 TypeScript 管线编排组件。输入初始 JSON 资源对象、有序 Webhook 列表（含名称、命名空间/对象标签选择器、`reinvocationPolicy` 为 `Never` 或 `IfNeeded`、失败策略 `Fail`/`Ignore`，以及由调用方注入的确定性处理器函数——接收当前对象返回允许/拒绝及可选 RFC 6902 JSON Patch 数组）和最大重入轮次上限。规则：每轮按注册顺序仅调用选择器命中当前对象且本轮需执行的 Webhook（首轮全部命中均调用；后续重入轮次仅当上一轮存在位于其后的插件对对象产生了实质语义变更时，才重调声明 `IfNeeded` 的插件，并允许新变更使原本未命中的选择器变为命中）；每个插件返回的 Patch 必须原子应用，任一步失败则该插件结果整批回滚并按 `Fail`/`Ignore` 决策；若对象进入已出现过的完整规范状态（状态环）或超出轮次上限则报震荡冲突并指出参与改写的插件序列与冲突 JSON Pointer 路径。验收用多插件交互夹具核对最终对象与精确调用轨迹，覆盖后置插件修改触发前置 `IfNeeded` 重入而 `Never` 不重入、中间插件把标签改出选择器导致后续跳过、Patch 第 2 步失败整体回滚且 `Ignore` 继续，以及双插件来回翻转同一键触发精确环路检测。
