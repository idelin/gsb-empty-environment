# 混合密钥封装的单分量替换

握手把两个KEM共享秘密拼接，但若派生没有绑定两份密文，攻击者可替换一个分量或把失败分量当空串。为Go握手宿主实现可导入的混合解封装包：两个KEM适配器由宿主按固定suiteID注册，各自对固定长度密文解封并返回32字节共享秘密或失败；密文长度来自宿主注册的suite配置共享秘密和valid布尔值；适配器对任何规范长度密文都必须返回秘密，失败使用其隐式拒绝秘密。输入严格包含suiteID、两个长度前缀密文、客户端与服务端规范公钥摘要及握手上下文摘要；长度或suite错误在调用适配器前拒绝。无论valid真假，都计算PRK=HMAC-SHA256(全零32字节, ss1||ss2)，最终密钥=HMAC-SHA256(PRK, 固定标签||suiteID||ct1长度及字节||ct2长度及字节||两公钥摘要||上下文摘要)；valid1 AND valid2为真才把密钥交给上层，否则以相同长度的通用失败返回且不暴露哪一分量失败，内部诊断仅记位掩码。测试适配器记录调用次数，交换密文顺序、替换任一分量、同秘密不同密文、单侧失败和双侧失败都须产生不同内部派生值或统一外部失败；禁止降级为只使用有效分量，且包不宣称适配器本身的密码实现已验证。
