# shardplan

测试分片规划器：按预计运行时间把测试分配到固定数量的执行器。

## 目标（按优先级）

1. **最少迁移**：在每台执行器负载不超过给定容量上限的前提下，最小化
   相对上一份计划更换了执行器的测试数量；
2. **最小最大负载**：在所有迁移数最少的方案中，取最大负载最小者。

## 特性

- 最多 24 个测试（`MaxTests`）；
- `group` 非空的测试强制分配到同一台执行器；
- `previous` 为上一份计划中的执行器编号，`-1` 表示新测试（不计迁移）；
- 容量内无可行方案时，`Result.Feasible` 为 false，`Result.LowerBound`
  给出所需容量的下界（即可达到的最小最大负载），`Assignments` 为达到
  该下界的建议方案。

## 算法

同组测试先合并为必须同机的"项"，然后在项上做分支限界搜索（项数 ≤
24）。容量模式下按（迁移数, 最大负载）字典序搜索最优解，剪枝包括：
每项最低可行迁移成本下界、执行器容量挤占下界（分数背包松弛）、平均
负载与"最小负载 + 最大剩余项"的最大负载下界。不可行时再以最小化最大
负载为目标搜索一次，得到容量下界。

## 使用

```go
res, err := shardplan.Plan(tests, executors, capacity)
```

或命令行（JSON 进，JSON 出）：

```sh
echo '{"tests":[{"name":"a","duration":2,"previous":0},
               {"name":"b","duration":3,"previous":1}],
       "executors":2,"capacity":4}' | go run ./cmd/shardplan
```

```sh
go test ./...
```
