# threeway-merge — 三方文本合并工具

输入共同基线与两份修改稿，输出合并结果。纯 Go 实现，无第三方依赖。

## 用法

```
go run . <基线文件> <修改稿A> <修改稿B>   # 合并结果输出到 stdout
go test ./...                            # 运行测试（含短序列枚举对照）
```

退出码：`0` 合并干净；`1` 存在冲突（冲突数打印到 stderr）；`2` 参数或读取错误。

## 合并规则

- **按序列位置匹配**：diff 基于 LCS 动态规划，重复出现的相同行各自占据
  不同下标，按位置对齐，不会因内容相同而错位匹配。
- **相同修改只保留一次**：两侧对同一区域做出完全相同的修改时，输出一份。
- **独立修改自动合并**：仅一侧修改、或两侧修改互不重叠的区域，直接合并。
  相邻行的非空修改互不重叠，可自动合并；插入点落在另一侧修改区间的
  边界或内部时视为同一区域，避免静默叠加出重复内容。
- **冲突块最小且互不重叠**：两侧都触及的区域先削去公共前后缀（公共部分
  作为干净输出）；若削去后某一侧与基线一致，则直接取另一侧，不产生冲突。
  剩余的差异核心才构成冲突块，冲突块之间天然互不重叠。
- **不偏向任何一侧**：算法对左右完全对称，交换两份修改稿只会交换冲突块
  中的左右内容，不会改变合并结果。测试通过短序列枚举所有
  (base, left, right) 组合验证这一点（`TestNoSideBias`）。

## 冲突格式

```
<<<<<<< LEFT a.txt:4-4 | BASE base.txt:3-3 | RIGHT b.txt:4-4
修改稿A的内容
||||||| BASE base.txt:3-3
基线内容
=======
修改稿B的内容
>>>>>>> RIGHT b.txt:4-4
```

每个冲突块都标注三方来源区间。区间记法为 1 基闭区间 `start-end`；
当 `start > end` 时表示空区间（即位于第 `start` 行之前的插入点）。

## 实现说明

- `merge.go`：`diff`（LCS 求最小编辑序列）、`Merge`（hunk 聚簇 + 三方比较）。
- `main.go`：命令行入口，负责读文件、打印合并结果与冲突标记。
- `merge_test.go`：单元测试 + 短序列枚举对照测试（对称性、不变量、
  冲突块单调不重叠）。
