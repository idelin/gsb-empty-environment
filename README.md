# 流式有限模式匹配器（A →[W, 无 C]→ B）

监控日志按**到达顺序**消费，告警按**事件时间**计算。模式：事件 A 之后在窗口
`W` 内出现事件 B，且 `[A.time, B.time]` 区间内没有事件 C。

## 语义

- **窗口两端均包含**：`0 <= B.time - A.time <= W`；`C.time ∈ [A.time, B.time]`
  即否决（C 与任一端点同时间同样使匹配无效）。
- **确定序**：时间相同的事件按事件 ID 排序（匹配语义本身只依赖时间区间，
  该顺序保证处理与输出的确定性）。
- **修订**：事件有稳定 ID 与修订号。更高 rev 可改类型、改时间或撤销
  （tombstone）；同 rev 同内容幂等（无状态变化）；同 rev 不同内容为冲突，
  拒绝并计数；更低 rev 作为过期修订忽略。
- **水位线**：单调递增（回落的水位线被忽略）。满足
  `time < watermark - allowedLateness` 的修订被拒绝且不改变状态；
  边界 `time == watermark - allowedLateness` 仍被接受。
- **封闭即最终**：修订目标事件的当前时间若已超出允许迟到范围
  （`existing.time < watermark - L`）同样拒绝——它旧位置的影响面
  `[t-W, t]` 已部分封闭，接受它会篡改已归档告警。这条规则保证封闭线
  `horizon = watermark - L - W` 之前的状态不可变，因而可以安全裁剪，
  也是流式与一次性参考实现逐比特一致的前提。
- **告警**：每个 `(AID, BID)` 对有稳定告警 ID（`A:<aid>|B:<bid>`）。
  匹配建立/恢复时发 `upsert`，失效（迟到的 C、撤销或改型 A/B）时发
  `retract`。`A.time < horizon` 的告警封闭并归档，仍保留在有效集合中。

## 结构

- `src/types.ts` — 输入记录（upsert/retract/watermark）与输出变更类型。
- `src/time-index.ts` — 按 `(time, id)` 排序的事件索引（二分 + 有序数组）。
- `src/engine.ts` — 流式实现 `PatternEngine`：增量维护开放告警，
  水位线推进时归档封闭告警并裁剪热索引；`snapshot()`/`restore()` 支持
  checkpoint 恢复。
- `src/reference.ts` — 一次性参考计算：同一接收判定后，把存活事件按
  `(time, id)` 排序单趟算出全部匹配对，用于对拍。
- `src/view.ts` — 变更流物化视图：以稳定告警 ID 为键应用 upsert/retract，
  重复消费幂等、不重复计数。
- `test/` — Node 内置测试（`node:test`）：模式语义、修订、水位线边界、
  分批/乱序/同 tick 冲突、checkpoint 恢复、变更流重放、多种子随机对拍。

## 运行

需要 Node ≥ 23.6（内置类型擦除，直接运行 TypeScript，无需编译）：

```sh
node --test test/*.test.ts
```

## 内存界限

设水位线为 `wm`，允许迟到 `L`，窗口 `W`，封闭线 `horizon = wm - L - W`：

- **热匹配状态有界于开放窗口**：三个时间索引只保留 `time >= horizon`
  的事件，大小为 O(落在 `[wm-L-W, ∞)` 内的事件数)；开放告警数
  O(窗口内 A 数 × 窗口内 B 数)。水位线推进时，封闭线之前的事件被逐出
  索引——它们不再影响任何开放窗口（新可接受事件的 `time >= wm - L`，
  只能落入 `A.time >= horizon` 的窗口）。
- **修订注册表** O(出现过的不同事件 ID 数)，每条 O(1)（rev/kind/time），
  用于修订单调性、幂等、冲突与封闭拒绝判定；不随水位线裁剪，生产环境
  可外置为 KV 存储（如 RocksDB）。
- **归档告警**随已封闭告警总数增长，只增不改，可直接外置冷存储；
  有效集合 = 开放告警 ∪ 归档告警。

因此随"开放窗口"增长的部分只有热索引与开放告警，界限为
O(窗口 `W + L` 内的事件数 + 其产生的开放告警数)；其余部分只随
不同事件 ID 数（注册表）或累计告警数（可外置的归档）增长。
