# 霍夫曼编码流损坏单点定位与错误扩散隔离器

面向不可靠信道的霍夫曼容错解码器（TypeScript，零依赖，Node.js 内置测试）。

## 问题

霍夫曼编码是**变长前缀码**：解码器必须精确知道每个码字的起始比特位置（相位）。
一旦位流中发生单比特反转或丢位，后续所有码字的边界全部错位——
普通解码器从损坏点开始输出乱码，且永远无法自行恢复（错误无限扩散）。

## 方案

在编码端把霍夫曼比特流切分为固定 100 字节的**分段**，每段开头插入具有自同步特性的
**同步字（Sync Word）**，并携带该段的符号数、精确载荷比特数与校验和：

```
[文件头]（可选，可预先约定码表而省略）
  magic       u32  'HFR1'
  totalSyms   u32  符号总数
  codebook    变长 码表序列化
[分段] × N（每段恰好 100 字节）
  sync        u32  0x1ACFFC1D   ← 同步字
  symCount    u16  本段符号数
  payloadBits u32  本段载荷精确比特数
  checksum    u16  符号字节和 (mod 2^16)
  payload     变长 霍夫曼编码比特，0 填充到字节边界
```

解码端的三重错误检测 + 重同步机制：

1. **单点定位**：逐段解码并验证 —— 非法码字（码树空分支）、`payloadBits` 消耗不符、
   `checksum` 不符，三者任一命中即判定该段损坏；
2. **错误隔离**：损坏段被整体丢弃，错误不会扩散到相邻分段；
3. **相位重锁**：从损坏点**逐比特**扫描下一个同步字（丢位会破坏字节对齐，
   必须比特级扫描），在同步字处重新锁定相位，后续分段照常解码。

## 目录结构

- `src/bitstream.ts` — 位级读写器（任意比特寻址，支持逐比特扫描）
- `src/huffman.ts` — 霍夫曼码表构建 / 编解码 / 码表序列化
- `src/resilient.ts` — 容错分段协议（同步字、三重校验、重同步）与普通流对照实现
- `src/channel.ts` — 不可靠信道模拟（丢位、比特反转）
- `test/resilient.test.ts` — Node.js 内置测试（`node:test`）
- `examples/demo.ts` — 端到端运行样例

## 运行

需要 Node.js ≥ 22.6（原生 TypeScript 类型擦除，无需编译、无第三方依赖）：

```bash
npm test     # node --test test/*.test.ts
npm run demo # node examples/demo.ts
```

## 运行样例（`npm run demo`）

场景：4000 字符文本 → 霍夫曼编码 → 第 50 字节处被信道**抹去 3 个比特**。

```
=== 3. 普通解码器：损坏点后全部乱码 ===
解码输出 4000 符号，损坏点后可恢复比例: 0.00%
损坏点附近输出: "jugs. homecxingly quick daft zebras jump. sphinx of black quartz, ..."
原文对应位置  : "jugs. how vexingly quick daft zebras jump. sphinx of black quartz, ..."

=== 4. 容错解码器：同步字重锁，错误被隔离 ===
重新锁定：在受损流比特 797 处捕获同步字（即原始流第 100 字节处的同步字，因抹去 3bit 前移）
分段统计: 25 段完好, 1 段被隔离
挽救内容: 3850/4000 符号 = 96.25%
```

## 测试结果（`npm test`，5/5 通过）

```
✔ BitWriter/BitReader 位级往返一致
✔ Huffman 普通流往返一致且有压缩效果
✔ 干净信道：含文件头的容错流完整往返
✔ 单比特反转：仅损失所在分段，错误不扩散
✔ 验收：中间抹去3bit，容错解码器在第100字节的同步字重锁并挽救>=90%内容
ℹ 普通解码器损坏点后可恢复比例: 0.00%
ℹ 容错解码器挽救内容比例: 96.25%
ℹ pass 5 / fail 0
```

验收用例（`test/resilient.test.ts`）严格对应验收边界：

- 无文件头模式（双方预先约定码表，类比 DEFLATE 固定码表）下，同步字恰好位于第 0、100、200… 字节；
- 在第 50 字节处（第 0 段载荷中部）抹去 3 bit；
- 普通解码器损坏点后内容可恢复比例为 0%（全部乱码）；
- 容错解码器仅隔离第 0 段，在比特 797 处（即原第 100 字节同步字抹去 3 bit 后的位置）
  重新锁定，挽救 96.25% ≥ 90% 的有效内容，且恢复内容与原位逐符号对齐。

## 说明与权衡

- 同步字 `0x1ACFFC1D` 为 32 比特标记，载荷中随机撞车概率约 2^-32；
  即使误锁，三重校验也会立即识破并继续扫描。
- 校验和为 16 比特简单累加和，演示足够；生产环境可替换为 CRC-16/CRC-32。
- 每段 12 字节头开销（12%），换取任意单点损坏的有界隔离（最多损失 1 段）；
  段长可通过 `SEGMENT_SIZE_BYTES` 调整，在开销与隔离粒度间权衡。
