# logtrunc — 日志段截断工具

Go 实现的日志截断库：在多个消费者与历史快照共存的情况下，安全地计算并执行日志段删除。

## 设计

- **连续前缀确认**（`consumer.go`）：消费者可以乱序确认单条序号，但其有效水位
  （horizon）永远是**无缺口连续前缀**。确认 `{1,2,4}` 时水位停在 2——缺口不会
  被最大已确认序号掩盖。`ConfirmPrefix` 回退水位会被拒绝（`ErrRollback`）。
- **快照依赖**（`snapshot.go`）：快照钉住历史区间 `[From,To]`，与之重叠的段
  必须保留，直到快照释放。
- **截断规划**（`planner.go`）：`Planner.Plan(target)` 对每个候选段
  （`End <= target`）判定可删/保留。段可删 ⟺ 所有活跃消费者的连续前缀都覆盖
  整段 **且** 无快照重叠。保留段附带**最小阻挡证据**：恰好是那些状态必须改变
  才能放行删除的实体集合——落后的消费者（含水位与段内第一个缺口序号）加上
  重叠的快照。
- **可重试、可恢复的删除**（`truncator.go`）：请求先写日志（fsync）再执行；
  每删一个段记一条审计记录。删除失败时请求保持 pending，`RetryPending` 重试；
  崩溃后重开 `OpenTruncator` 会重放日志恢复所有未完成请求，已删段通过
  `ErrSegmentNotFound` 幂等跳过。
- **参考实现**（`reference.go`）：逐条目的依赖集合模型——每个条目维护显式
  依赖者集合（消费者/快照），依赖集合为空才可删。语义显然正确但昂贵，用于
  交叉验证规划器。

## 测试

```sh
go test ./...                 # 单元测试 + 随机对比测试
SEED=42 go test -run TestPlannerMatchesReference ./...
```

- `logtrunc_test.go`：缺口不被最大序号掩盖、确认回退拒绝、消费者退出解除
  阻塞、旧快照钉住历史段、最小阻挡证据随解除而收缩、删除失败重试、崩溃恢复
  不丢请求、崩溃后幂等跳过已删段。
- `property_test.go`：随机操作序列（注册/退出/乱序确认/回退尝试/快照钉放）
  下，逐步对比规划器与逐条依赖集合参考实现的可删判定，并校验每条阻挡证据
  与参考的依赖集合精确一致。
