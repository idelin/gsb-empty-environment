# 字节码栈高验证器

一个小型栈式虚拟机字节码的 TypeScript 验证器：对每条**可达**指令验证入口栈高唯一、
任何路径不发生栈下溢、`RET` 时栈高恰为 1，跳转目标必须落在指令边界上。
拒绝时输出带路径的证据；不可达（死）代码中的"坏指令"不会产生误报。

## 指令集（`src/isa.ts`）

变长编码，因此"跳转必须落在指令边界"是有意义的检查：

| 指令 | 字节 | 栈效应 |
| --- | --- | --- |
| `PUSH n` | `01 nn` | +1 |
| `POP` | `02` | -1（需 ≥1） |
| `DUP` | `03` | +1（需 ≥1） |
| `ADD` | `04` | -1（需 ≥2） |
| `JMP t` | `05 tt` | 0 |
| `JZ t` | `06 tt` | -1（需 ≥1），栈顶为 0 则跳转 |
| `RET` | `07` | 要求高度 == 1 |

## 验证算法（`src/verifier.ts`）

1. **结构检查（全程序）**：可解码性、跳转目标必须是指令边界。
2. **抽象解释（仅可达代码）**：抽象状态 = 精确栈高，从 `(0, 高度0)` 开始做
   不动点传播（BFS）。`JZ` 两个分支都探索（值无关，与 JVM verifier 相同的过近似）。
   - 同一偏移量被不同栈高到达 → `height-conflict`，报告两条见证路径；
   - 高度不足指令所需 → `underflow`；
   - `RET` 时高度 ≠ 1 → `ret-height`。
   不可达指令永远不会获得状态，因此死代码里的下溢/冲突/坏返回**不会被报告**。
3. **证据**：每条路径错误都携带偏移量路径，`replayPath` 按结构后继关系与栈效应
   逐步回放校验，`formatErrors` 渲染为带栈高变化的可读轨迹（见 `npm run demo`）。

终止性：每个偏移量的栈高首次到达即固定，冲突只记错误不合并，状态总数有限。

## 状态探索交叉验证（`src/explore.ts`）

`exploreConcrete` 对具体 `(pc, 栈)` 配置做 BFS（有界），作为独立 oracle：
- 具体探索发现违规 ⇒ 验证器必须拒绝（无漏报）；
- 验证器接受 ⇒ 具体探索无违规（无误报，涵盖"不可达坏码"）；
- 验证器拒绝 ⇒ 证据路径必须能结构回放且高度吻合。

注意验证器是值无关的：`JZ` 两条边都走，可能拒绝"具体执行不可达"的路径，
这是有意为之的标准设计（结构可达性），不属于误报范畴。

`test/differential.test.ts` 穷举全部 ≤3 指令程序（14424 个）+ 2 万个随机程序做差分，
并专门测试"在 `RET` 后拼接坏代码后缀不改变接受判定"。

## 运行

需要 Node ≥ 22.6（原生 TypeScript 类型擦除；开发用的是 v23.9）。

```sh
npm test     # node --test，单元 + 差分测试
npm run demo # 打印若干程序的验证结果与冲突路径证据
```
