# DMA完成环代次归属

设备完成环复用槽位时，旧完成项可能释放新租户正在使用的缓冲。写供Go驱动宿主调用的环管理包，队列槽位绑定提交代次、缓冲租约与租户，硬件只回传截短代次；按最多半圈在途范围恢复完整代次，歧义必须隔离队列，不能猜最近请求。提交序号耗尽时先排空再换纪元。用小位宽环穷举乱序完成、重复项、设备复位和迟到完成，验证只释放对应租约一次。

## 设计

- `Submit` 把环槽位绑定到 `(完整提交序号 seq, 租户, 缓冲租约)`；硬件完成项只回传 `(slot, tag)`，`tag` 为 `seq` 的低 `TruncBits` 位。
- 安全契约：tag 空间 ≥ 2×环大小，且 `Submit` 强制在途代次跨度 < 半圈 tag 空间（否则返回 `ErrQueueFull` 背压，等待最老请求完成）。因此恢复窗口 `(subSeq-半圈, subSeq]` 内每个 tag 至多对应一个完整代次。
- `Complete` 的判定：tag 在窗口内无候选 → 陈旧/迟到/复位残留，忽略；候选落在已完成请求上 → 重复项，忽略；候选指向其他在途请求、槽位不一致、tag 或槽位越界 → 歧义，**隔离队列**（`ErrQueueIsolated`），绝不猜最近请求。
- 租约只在 `inflight→free` 跃迁时释放（合法完成或 `Reset` 退役），每条租约恰好释放一次。
- 序号耗尽：`Submit` 返回 `ErrSeqExhausted`；`SwitchEpoch` 要求在途为 0（先排空），换纪元后序号重新开始。

## 残余风险（截断的固有限制）

- 延迟超过一整圈环周期的重复完成可能与新占用者产生 tag 混叠，无法区分；配置契约（tag 空间 ≥ 2×环大小）保证一圈内的迟到完成一定被识别为陈旧。
- 复位/换纪元后，设备必须保证旧纪元的完成项已静默（先排空再恢复提交）；否则与新占用者 tag 完全相同的迟到完成无法识别。

## 测试

- `ring_test.go`：定向场景——乱序完成全排列、重复完成、槽位复用后的迟到完成、设备复位、歧义隔离、序号耗尽与换纪元。
- `model_test.go`：以全序号模型为规约，在小位宽环（4 槽 / 3 位 tag / 4 位序号）上穷举所有操作交织（含故障注入），并用随机长序列模糊验证；每一步断言环与模型一致、每条租约至多释放一次、最终全部恰好释放一次。
