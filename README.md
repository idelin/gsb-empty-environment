# 秘密租户迁移权限同步

机密租户迁到新存储池时，内容复制完成不代表新池已经执行最新撤销。给Go存储宿主写迁移组件，内容版本与授权版本各有独立单调序号，目标块须带目标池密钥代和策略摘要；读路由切换前，目标同时追到内容屏障及撤销屏障，任何缺项保持源路由。撤销不得被后到的旧复制清单覆盖。用可暂停双池模拟先撤权后复制、换钥失败和切换后旧池凭据请求，证明新旧池都不重新开放已撤权数据。

## 设计

- `auth.go` — `AuthLog` 授权日志：撤销产生独立的单调授权序号（authorization seq），与内容序号互不影响。
- `pool.go` — `Pool`/`Block`：每个块封装目标池密钥代（`KeyGen`）与策略摘要（`PolicyDigest`），并记录内容版本与封装时的授权版本；读请求校验凭据归属、池退役状态、撤销表、密钥代与策略摘要。`ApplyAuth` 的水位只前进不后退，旧清单无法回滚已应用的撤销。
- `migrator.go` — `Migrator` 分阶段（`Snapshot` → `Copy` → `SyncAuth` → `Switchover`），阶段间可暂停以注入撤销、写入或换钥失败。`Ready` 同时检查内容屏障（源内容水位）与撤销屏障（授权日志头）以及目标块封装是否为新代；任一缺项 `Switchover` 拒绝并保持源路由。切换成功后源池退役，拒绝一切读请求（含旧凭据）。

## 模拟测试

`migrator_test.go` 的可暂停双池模拟覆盖：

- 先撤权后复制：撤销随清单到达目标，切换后两池均不开放已撤权数据。
- 复制与切换之间暂停时发生撤销：撤销屏障未满足，路由保持源池，源池已应用撤销。
- 快照后源池有新写入：内容屏障未满足，需重新复制后才可切换。
- 旧复制清单晚到：目标撤销水位不回退，撤销不被覆盖。
- 目标换钥失败：块停留在旧密钥代不可读，切换被拒，路由保持源池；重封成功后方可切换。
- 切换后旧池凭据请求：源池已退役拒绝服务，新池拒绝异池凭据，已撤权对象保持关闭。
