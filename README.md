HTTP/2 反向代理在解析客户端头部块时，常因 HPACK 动态表 32 字节条目开销计算、多条连续表大小更新指令的顺序校验或 Huffman 末尾填充位检查不严而遭头部走私或状态去同步。为代理网关交付可导入的 Go RFC 7541 HPACK 编解码包。实现完整的 61 项静态表、FIFO 动态表（每项大小 `len(name) + len(value) + 32` 字节，插入超过当前上限的条目须先清空动态表且不报错、也不保留该条目）以及 RFC 7541 附录 B 全部 257 符号（含 EOS=256）规范 Huffman 编解码器。严格执行协议边界：变长前缀整数（4/5/6/7 位前缀）须拒绝溢出 `uint64`/超过合理上限的恶意续字节；动态表大小更新（`001xxxxx`）只允许出现在头部块最开头（可连续多条，必须追踪中间最小上限并按该最小值执行淘汰，不得超过协商的 `SETTINGS_HEADER_TABLE_SIZE`，一旦在任意头部字段之后出现必须报错 `COMPRESSION_ERROR`）；Huffman 解码遇到末尾填充超过 7 位、填充位不全为 `1`、或码流中显式出现 EOS 符号 256 必须报错；支持区分 Indexed、Literal with Incremental Indexing、Literal without Indexing、Literal Never Indexed 四类表示（并正确保留 Never Indexed 标记供代理透传）。验收用 RFC 7541 附录 C 全部官方示例向量对照，并补充动态表先缩后扩中间淘汰、头部之后夹带大小更新拒收、超大条目清空动态表以及非法 Huffman 填充/显式 EOS 拦截测试。
