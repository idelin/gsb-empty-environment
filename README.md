# rollback

格斗类联机对战的回滚网络（rollback netcode）同步组件。服务端与客户端
共用同一套纯帧驱动、确定性的模拟与同步逻辑，不依赖 goroutine 或系统时钟，
因此可以完全确定性地测试与复现。

## 同步机制

- 本地输入立即执行：`AddLocalInput` 后下一帧立刻推进，无网络等待。
- 远端输入预测：缺失时沿用“严格早于当前帧的最近确认输入”，首帧前为零输入。
- 确认与回滚：确认输入到达且与已模拟帧的预测不同时，恢复到该帧上一帧边界
  的快照，从该帧起逐帧重算到当前进度。
- 环形快照窗口：输入与状态快照按帧存入固定容量环形缓冲；回滚目标的边界
  快照已淘汰时进入暂停，请求对端权威状态快照后用完整输入历史重放恢复。
- 哈希不同步检测：两端按固定周期交换状态 SHA-256；仅在该帧输入已确认、
  不会再回滚时才判定不同步，回滚纠正后自动撤销过期事件。
- 累积重发：每个消息包全量携带窗口内输入，单包丢失由后续包补齐，无需 ACK。

## 包结构

- `sim`：确定性格斗模拟（定点整数、固定结算顺序、内置确定性 PRNG）与状态哈希。
- `ring`：按帧号索引、随窗口滑动且无槽位别名的泛型环形缓冲。
- `netcode`：回滚端点状态机，含预测、回滚重算、暂停/快照恢复、哈希交换。
- `netem`：可播种的随机延迟/丢包链路模拟器与帧驱动中继（极简服务端）。
- `scenario`：双端端到端验证台，跑满固定帧后比对两端状态与无网络 oracle。

## 运行

```sh
go run .          # 随机延迟 + 15% 丢包下的端到端演示
go test ./...     # 全部单元与端到端测试
```

演示会打印两端的模拟步数、回滚次数、预测次数、暂停次数与丢包统计，
并校验两端最终哈希一致且与确定性 oracle 完全相同。

## 验证覆盖

- 模拟确定性、`Step` 无副作用、哈希覆盖全部状态字段。
- 环形缓冲滑动、窗口内重写不错位、跨容量无别名。
- 预测基线、回滚收敛、越窗暂停与快照恢复、真实不同步检测。
- 经真实中继的双端通信、随机延迟/丢包下多种子收敛、链路中断恢复。
