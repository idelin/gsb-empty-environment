# streamjoin — 带否定事件的流式时序 Join

双流时序 Join 组件（Go，仅标准库）。左流事件 `L` 到达后等待匹配窗口（默认 5s）内的右流事件 `R`：

- 窗口内 `R` 到达 → 立即输出 `MATCHED`；
- 窗口超时无匹配 → 输出 `LEFT-ONLY`（孤立结果）；
- 超时前收到该 key 的取消事件 → 放弃等待，**不输出任何结果**；
- `LEFT-ONLY` 已输出后迟到的 `R`（在 lateness 界限内）→ 输出 `LATE-MATCHED` 补偿结果；
- 乱序容忍：早到的 `R` 会被缓冲等待 `L`（自身窗口过期则输出 `RIGHT-ONLY`）；早到的取消事件会留下短暂墓碑，压制迟到的 `L`。

## 结构

- `joiner.go` — `Joiner` 核心：四张状态表（等待中的 L、缓冲的 R、孤立墓碑、取消墓碑），全部带定时过期，保证状态零泄漏。
- `clock.go` — `Clock` 抽象：`RealClock`（墙钟）与 `FakeClock`（手动推进，测试/演示用）。
- `joiner_test.go` — `go test` 验收测试。
- `cmd/demo` — 运行样例，用假时钟确定性回放验收场景。

## 运行

```sh
go test ./... -v     # 测试
go run ./cmd/demo    # 样例
```

## 设计要点

- 时间通过 `Clock` 接口注入，5 秒超时的验收场景可确定性测试，无需真实等待。
- 取消事件命中等待中的 `L` 时停掉其定时器并静默丢弃；若 `L` 尚未到达（乱序），记录取消墓碑，迟到的 `L` 被压制。
- `LEFT-ONLY` 输出后保留孤立墓碑（lateness 时长），迟到的 `R` 触发 `LATE-MATCHED` 补偿。
- 所有状态条目都由定时器回收；`StateSize()` 归零即证明无泄漏（乱序测试断言）。
