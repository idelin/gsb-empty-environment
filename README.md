编译器中端的循环不变代码外提（LICM）与标量演化（Scalar Evolution, SCEV）若忽略不可约控制流、异常陷阱或内存别名，就会把原本安全的代码优化出运行时除零崩溃或死循环：1）**自然循环识别与不可约图拦截**：先计算支配树（Dominator Tree），识别所有回边 `u -> h`（`h` 支配 `u`），合并共享同一循环头 `h` 的回边构造自然循环嵌套树（支持多层嵌套循环与自动插入/识别唯一循环前置头 `Preheader`！），同时通过强连通分量精准识别**不可约循环（Irreducible Loop，存在两个及以上非支配入口）**并标记跳过绝不误作自然循环优化！2）**双重安全门禁 LICM**：循环体内某指令操作数全部定义在循环外或已是循环不变量时，仅当满足以下二选一才可安全外提至 `Preheader`——(a) 指令绝对无副作用且绝不触发陷阱（如普通加减位运算），**或** (b) 指令所在基本块**支配循环的全部出口块**（保证只要进入循环至少执行一次，且循环必能到达该块！注意：对于在条件分支里的除法 `x / y`，若外提它会在分支本不执行且 `y == 0` 时引入幽灵除零崩溃，必须拦截！）；对于内存 `load(addr)`，只有当 `addr` 为循环不变量且整个循环体（含全部嵌套内循环！）中不存在任何可能与 `addr` 别名的 `store` 或有副作用 `call` 时才可外提！3）**SCEV 加法递推与精确行程计数（Trip Count）**：把循环归纳变量归一化为 `{start, +, step}<L>` 递推表达式，在固定 32/64 位有符号/无符号算术下精确推导边界比较的迭代次数——正确处理首轮即退出（0 次）、非整除步长向上取整以及步长跨越 `MAX_INT` 回绕导致无限循环或不可确定行程的场景（绝不可对回绕情况给出错误有限次数！）。为编译器中端交付可导入的 Go 循环分析、SCEV 与 LICM 优化核，并内置 SSA 解释器验证。验收覆盖多层嵌套循环外提、不可约多入口循环安全识别、条件除零陷阱禁外提 vs 支配全部出口可外提、别名 `store` 拦截 `load` 外提、SCEV 零次/非整除/溢出回绕行程判定及解释器全路径语义等价。
