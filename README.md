声明式集群控制面引入 Server-Side Apply（SSA）后，多个控制器与运维客户端同时以各自 `fieldManager` 局部提交同一对象配置；一旦结构化合并在关联列表（`listType=map`，含复合主键如 `(containerPort, protocol)`）、集合列表（`listType=set`）、原子对象（`atomic`）及多管理者共享字段删除语义上出错，控制器间就会出现静默覆写风暴或幽灵字段永远删不掉。为控制面 API 服务器交付可导入的 Go Server-Side Apply 结构化合并与 `managedFields` 追踪包。输入为资源 Schema（标注每个路径的合并策略：`granular` 映射、`atomic` 整体覆盖、`listType=atomic`/`set`/`map` 及单键或复合 `listMapKeys`）、当前线上对象及其按 `fieldManager` 维护的 `FieldsV1` 所有权集合、以及新提交的 `(manager, appliedPatch, force)` 请求。规则：1）支持递归结构化合并——`map` 列表按主键对齐合并元素内部字段并拒绝补丁内出现重复主键或缺失主键字段，`set` 列表按值集合合并，`atomic` 字段整体替换并由最后写入者独占所有权；2）冲突检测——当新补丁将某叶字段或原子字段改为与现值不同的新值且该字段当前由其他 `fieldManager` 拥有时，若 `force=false` 必须整体拒绝并返回全部冲突路径与原属管理者，若 `force=true` 则强制接管所有权并从原管理者所有权树中剥离；3）共享所有权与声明式裁剪——若新补丁写入了与现值相同的值，则与原管理者共同拥有该字段；当某管理者在后续提交中移除了其先前拥有的字段，仅当没有任何其他管理者仍共享拥有该字段时才从最终对象删除该字段（若原管理者仍显式写入 `null` 且与他人冲突同样受 `force` 约束！）；4）完整维护并输出更新后的对象与精简规范的 `managedFields` 集合。验收覆盖复合主键 `(port, protocol)` 关联列表跨两控制器并行改不同字段、共享所有权字段单方撤出保留至全员撤出才删除、`force=false` 冲突拒绝与 `force=true` 夺权、以及 `atomic` 列表与 `set` 列表嵌套合并语义。
