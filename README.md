# 域名委派密钥已撤销后，旧查询的有效签名仍可能重新污染缓存

域名委派密钥已撤销后，旧查询的有效签名仍可能重新污染缓存。为Go解析宿主写信任代次组件，每个查询固定权威区与信任锚版本，回答验签结果还须在缓存发布时确认该版本未被撤销；旧答案可保留诊断但不可授权新查询。信任更新声明允许保留的密钥指纹，不能仅比较版本大小。用真实签名和可暂停发布器测试旧钥迟到、同版本异钥与双区域并发，缓存中每项都附当前有效信任路径。

## 组件

- `TrustStore`（`trust.go`）：按权威区保存完整代次声明，每代显式枚举保留的密钥指纹；版本号只用于代次排序与锚定，授权判断只看指纹是否在当前声明的保留集合中。
- `Query` / `Resolver`（`query.go`）：查询在生命周期内固定 `TrustAnchor{Zone, Version}`；回答先校验权威区、锚版本、问题匹配，再用锚定版本声明中的公钥做真实 Ed25519 验签，得到 `VerifiedAnswer`（此时只代表锚代次下有效，尚不可授权）。
- `TrustPath`（`trust_path.go`）：从锚定版本到当前版本的逐代保留记录；缓存每一项都附带发布时刻的当前有效信任路径。
- `Cache`（`cache.go`）：授权项与诊断项分库存放，`Lookup` 只返回授权项；被撤销签名的回答仅保留在诊断区，永远无法授权新查询。
- `PausablePublisher`（`publisher.go`）：单 worker 串行发布，支持暂停/恢复；暂停期间回答只排队不落缓存，恢复发布时按“当前代次”重新确认签名指纹仍被保留，旧钥迟到的回答降级为诊断项。

## 设计要点

- 撤销判定发生在缓存发布时刻而非验签时刻：查询可继续锚定旧版本完成历史验签，但发布时 `BuildTrustPath` + 当前声明决定其是授权还是诊断。
- 指纹优先：跨代次仍被保留的指纹即使锚定旧版本也保持授权；同版本号下未保留的异钥一律拒绝，同版本重复声明被 `ErrVersionOutOfOrder` 拒绝。
- 信任路径可审计：每个缓存项记录锚定版本、当前版本与逐代 `Hop{Version, Retained}`，无需比较版本大小即可判断可信度。

## 测试

全部使用真实 Ed25519 密钥与签名，配合可暂停发布器：

- `TestOldKeyLateAnswerBecomesDiagnostic`：暂停排队期间轮换密钥，旧钥迟到回答不进授权缓存，仅作诊断且附完整信任路径。
- `TestRetainedFingerprintSurvivesRotation`：被保留指纹跨代次仍授权，被移除指纹同版本也不授权。
- `TestSameVersionDifferentKeyRejected`：同版本异钥拒绝、同版本重声明拒绝、篡改签名拒绝。
- `TestZoneAndAnchorPinning`：跨区、跨锚版本、错问回答一律拒绝。
- `TestDualZoneConcurrency`：双区域各 50 条并发，暂停中双区轮换（一区留钥、一区换钥），恢复后授权/诊断分区正确、信任路径不串区。
