# 事件时间去抖器（可暂停 / 可恢复）

纯标准库实现（`debouncer.py`），输入抖动状态，下游只收到
"稳定满门限时长"的确认变化。时间完全由调用方以事件时间驱动，
无后台线程、无真实时钟依赖。

## API

| 操作 | 说明 |
| --- | --- |
| `Debouncer(threshold)` | 创建去抖器，门限为事件时间单位 |
| `ingest(source, value, ts)` | 摄入事件；`value=None` 表示未知值 |
| `advance_to(ts)` | 推进事件时钟，确认到期候选 |
| `drain()` | 取出并清空已确认未消费的变化（`Change` 列表） |
| `save(path)` / `Debouncer.restore(path)` | JSON 快照暂停 / 恢复 |

## 语义要点

- 候选稳定满 `threshold` 才确认，确认时间 = `candidate_since + threshold`（边界取等）。
- 未知值（`None`）中断候选计时，不影响已确认值。
- 重复事件不延长稳定计时；回退到已确认值会取消挂起的候选。
- 来源之间状态完全隔离。
- 同一时刻多事件：先结算该时刻到期的确认，再按 ingest 调用顺序应用，
  同来源后到覆盖先到（last write wins）。时钟只前进，`ts < now` 抛 `ValueError`。

## 持久化内容（save 快照）

- `threshold` 与当前事件时钟 `now`；
- 每个来源：已确认值、候选值、候选起始时间；
- outbox 中已确认但未消费的变化（含确认时间）。

恢复后：未消费确认不丢失、不重复投递；未满足时长的候选继续累计；
已确认值保留用于去重，旧事件重放不会再次发送。状态值须可 JSON 序列化。

## 旧事件的释放

- 原始事件从不留存，只保留按来源聚合的派生状态，内存 O(来源数)；
- 候选状态在确认、被替换、被未知值中断、或回退到已确认值时释放；
- outbox 条目在 `drain()` 后释放，之后的快照不再包含；
- 已确认值按来源长期保留（抑制重复投递）。

## 测试

```sh
python3 -m unittest test_debouncer -v
```

全部时间推进由测试显式驱动，无真实 sleep。覆盖：门限边界、未知值中断、
重复事件、来源隔离、同时刻顺序、迟到事件，以及把 checkpoint 分别放在
候选刚开始 / 即将确认 / 确认已生成但尚未消费三个位置的恢复等价性回放。
