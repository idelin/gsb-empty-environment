多方托管密钥系统执行 `(t, n)` 门限 Schnorr/FROST 分布式密钥生成（DKG）与两轮协同签名时，若协调器跳过知识证明（Proof-of-Possession）校验、未核对秘密份额与多项式承诺一致性，或在第二轮签名聚合时复用单次 nonce 承诺，作恶成员可发动 Rogue-Key 密钥抵消攻击或迫使诚实节点泄露私钥。为 Go 密钥托管宿主实现可导入的门限 DKG 追责与两轮防重用签名状态机包（群运算由抽象 `Group` 接口注入并提供真实 P-256 完整测试实现）。DKG 阶段执行严格两轮协议：第一轮每方提交次数 `t-1` 的 Feldman 承诺向量及带域分离标签 `(context, participantID, C_0)` 的 Schnorr 知识证明（防 Rogue-Key 攻击）；第二轮每方向其余成员发送点对点份额，接收方按 `g^{s_{i,j}} == prod_k C_{i,k}^{j^k}` 验证并可提交可独立验真的投诉证据，协调器据此将作恶节点永久拉黑并从合格集合剔除，仅当合格人数 `>= t` 时冻结联合公钥与各节点公钥份额。签名阶段完整实现 FROST 绑定因子 `rho_i = H_1(i, msg, B)`（绑定全部参与者的 `(D_j, E_j)` 承诺列表，防 Wagner 并发生日攻击）：强制每个预生成 `(D_i, E_i)` 承诺单次消费并在进入第二轮前原子销毁本地私钥 nonce，聚合器逐份验签并输出可识别作恶者 ID 的精准追责报告而非仅返回验签失败。用真实 P-256 群测试诚实门限签发、Rogue-Key 拦截、坏份额投诉剔除、并发重放 nonce 阻断与坏部分签名精准定罪。
