# 哈希环碰撞与分布均匀度方差分析器

一致性哈希算法质量检验诊断内核（TypeScript / 零依赖）。输入任意哈希函数与节点序列，
对数百万随机/结构化样本在一致性哈希环上映射打点，输出节点负载标准差、最大最小比值、
弧长加权卡方拟合优度、方差收敛曲线、位宽扫描与雪崩效应诊断报告。

内置对比 **MD5-32 / MurmurHash3-32 / FNV-1a-32** 三种哈希在一致性环上的分布表现，
并可精准定位 FNV-1a 的雪崩不足缺陷。

## 环境要求

- Node.js ≥ 22.6（推荐 ≥ 23.6，原生支持 TypeScript 类型擦除运行）
- 无任何 npm 依赖，无需 `npm install`

## 快速开始

```bash
npm run analyze              # 完整诊断报告（默认 8 节点 × 160 虚拟节点 × 300 万样本）
npm run analyze -- --samples=1000000 --nodes=12 --vnodes=256   # 自定义规模
npm test                     # Node.js 内置测试运行器（node:test），20 个用例
```

## 架构

| 文件 | 职责 |
| --- | --- |
| `src/hashes.ts` | MD5-32 / MurmurHash3 x86_32 / FNV-1a-32 实现与位宽截断器 |
| `src/ring.ts` | 一致性哈希环：虚拟节点、二分查找、碰撞统计、弧长占比 |
| `src/stats.ts` | 统计内核：Lanczos logGamma、不完全伽马、卡方 p 值 |
| `src/analyzer.ts` | 诊断内核：负载分析、方差曲线、位宽扫描、雪崩测试 |

| `test/` | node:test 单元测试（20 个用例） |

## 诊断方法

- **弧长加权卡方**：一致性哈希环的节点负载天生不均匀（虚拟节点弧长随机，相对偏差 ≈ 1/√vnodes）。
  直接用均匀卡方会把环结构噪声误判为哈希缺陷。本工具先计算各节点的弧长占比作为期望分布，
  再对键映射做卡方拟合优度检验，从而把"哈希映射质量"与"环结构不平衡"分离。
- **结构 CV**：虚拟节点弧长占比的变异系数，刻画哈希连 vnode 键都散布不均的结构性缺陷。
- **方差曲线**：实测 CV 随样本量增长应收敛到结构 CV（比值 → 1）。
- **位宽扫描**：将哈希输出截断到 8~32 位（分别取低位/高位）后重建环并打点，
  定位雪崩不足开始暴露的位宽区间；同时统计低位宽下虚拟节点的落点碰撞。
- **雪崩测试**：逐位翻转输入，统计每个输出位的翻转概率，理想值为 0.5，偏差 > 0.1 记为缺陷位。

## 诊断结论

- **MD5 / Murmur3**：随机键与顺序键下 CV 比值均 ≈ 1.00，弧长加权卡方通过，
  各位宽（取低/取高）p 值健康，雪崩最大偏差 0.0285（统计噪声水平）。
- **FNV-1a**：
  - 结构 CV 高达 **28.85%**（MD5/Murmur 约 5%）——连 `node-i#j` 这类虚拟节点键都无法均匀散布，
    环本身即失衡（Max/Min = 2.72）；
  - 顺序键下弧长加权卡方 χ²=176.63，**p=1e-34，FAIL**；
  - 位宽扫描在 **8~32 全部位宽**（无论取低位还是高位）均 FAIL，最低 p=1.5e-57，
    精准暴露其雪崩不足并非个别位宽问题，而是全程性缺陷；
  - 雪崩测试最大偏差 **0.5000**（理论最差值），32 个输出位全部缺陷——
    乘法传播只向高位进位，输入变化无法充分扩散到全部输出位。
