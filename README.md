# 登录会话固定攻击防护

匿名会话升级为已登录时，原会话标识必须失效，不能被另一客户端继续使用。为Go服务实现会话轮换事务包，复制的只允许白名单匿名状态，认证结果与新标识原子绑定，旧标识仅能读取明确的失效结果；并发请求不得把旧状态覆盖新登录。用双客户端及提交失败测试唯一身份归属。

## 设计要点

`Store.Rotate` 在单把存储锁内完成完整事务，保证会话固定攻击无法跨标识复用：

- 新标识：`crypto/rand` 生成 256 位随机 ID，轮换必然换发，不复用旧标识。
- 白名单复制：只复制显式列出的匿名状态键，未列出的键（含内部敏感数据）一律丢弃，缺失键不物化空值。
- 原子绑定：`Committer.Commit` 在任何状态变更之前、锁内调用；提交成功后才一次性写入新会话、把旧标识置为墓碑并登记身份归属，提交失败则整体回滚、可安全重试。
- 旧标识墓碑：旧 ID 保留为不可读写的墓碑，`Get`/`PutState`/再次 `Rotate` 只返回 `InvalidationError`（`errors.Is(..., ErrSessionInvalidated)` 成立），并指明继任的新标识。
- 唯一身份归属：`owners` 索引保证同一 `UserID` 同时只绑定一个有效会话，第二个客户端绑定同一身份返回 `ErrIdentityBoundElsewhere`。
- 并发安全：所有读写经同一互斥锁串行化，旧标识上的滞后写入在轮换后全部被墓碑拒绝，无法覆盖新登录会话。

## 测试

```sh
go test -race -count=1 ./...
```

- `TestRotate_DoubleClient_SessionFixation`：双客户端（登录方/持旧标识的攻击方）验证旧标识失效、白名单复制与身份归属。
- `TestRotate_CommitFailure_Rollback`：提交失败后存储无中间态、可重试成功，并验证身份不能被第二个会话重复绑定。
- `TestRotate_Concurrent_UniqueOwnership`：32 个客户端并发轮换同一匿名标识，恰好一个成功，且轮换后的滞后写入全部被拒绝。
