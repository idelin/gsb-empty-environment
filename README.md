# 安全证明缓存依赖失效

程序分析服务缓存某函数安全证明后，依赖函数契约变化必须使证明失效。写供Go分析宿主调用的证明缓存包，证明绑定输入IR摘要、依赖摘要及验证规则版本，循环依赖形成同批固定点证书；只在整批依赖闭包核对通过后发布。用互递归、局部改动和并发旧证明到达验证不能以新标签复用旧证明。

## `proofcache` 包

实现在 `proofcache/`，仅依赖 Go 标准库，供分析宿主直接 import。

### 绑定与失效

- 每条证明绑定一个 `Fingerprint`：输入 IR 摘要、每个依赖的契约摘要（`DepClaim`）和精确的 `RuleVersion`；依赖声明按标签排序去重，保证同一逻辑指纹的摘要稳定。
- `Cache.Lookup` 命中要求指纹逐字节匹配，并重算整条传递依赖闭包：被调方契约变更会使所有依赖方证明失效，规则版本变更会使旧规则下的证明失效。
- 条目带 `bindingDigest`（覆盖标签、指纹、契约、证明字节、批次、事件序号），存储被篡改或重贴标签都无法通过校验。

### 循环依赖与固定点证书

- 互递归函数没有无环发布顺序，通过 `Cache.BeginBatch(members)` 组成同批固定点证书。
- 每个成员用 `Batch.Put` 提交草稿；批内边按草稿契约核对，批外边按已发布条目核对。
- `Batch.Commit` 仅在成员齐全、世代未推进、闭包全部核对通过、绑定重算一致时原子发布；任何失败都整体不发布。提交前草稿对 `Lookup` 不可见。

### 并发与旧证明防护

- 每个标签维护单调的 fencing generation：`Invalidate` 或替换该标签的提交只推进该标签的世代，栅栏该标签在途批次与迟到草稿，同时不影响无关标签上的并发批次。
- 草稿携带的世代若旧于批次捕获值会被拒绝（`ErrStale`）；失效会关闭相关在途批次并释放标签。
- 证明按「标签 + 指纹」双键索引，且绑定摘要含标签与证明字节，旧证明无法以新标签复用。

### 运行测试

```sh
go test -race -count=1 ./...
```

`proofcache/example_test.go` 给出宿主完整调用流程示例。
