# LLDP邻居表准入

接入端口上的攻击者伪造LLDP帧，想塞满邻居表，或用TTL为0抹掉真实邻居。给Go交换机软件写供帧接收线程调用的邻居表准入包：目的MAC须为01:80:C2:00:00:0E，前三个TLV依次为机箱ID、端口ID、TTL，类型0的结束TLV后不得有数据；每端口邻居数有上限；TTL为0的撤销只对同一机箱ID、端口ID且同源MAC的现有条目生效。用乱序TLV、洪泛和他人撤销验证。

## 实现

代码在 `lldp.go`，入口为 `Table.Admit(port, frame)`，供各端口的帧接收线程直接调用；内部用 `sync.Mutex` 保护，可并发调用。

准入规则：

- 目的 MAC 必须是 `01:80:C2:00:00:0E`，EtherType 必须是 `0x88CC`，否则丢弃。
- 前三个 TLV 必须依次为机箱 ID（类型 1）、端口 ID（类型 2）、TTL（类型 3）；乱序、缺失或重复的必需 TLV 一律拒绝。
- 结束 TLV（类型 0）长度必须为 0，其后再出现任何字节即判为畸形帧。
- 每个端口独立计数，新邻居数达到 `NewTable(maxPerPort)` 设定的上限后返回 `ErrTableFull`，防止洪泛塞满表；已有条目的刷新不占新名额。
- TTL=0 为撤销：仅当端口上存在相同机箱 ID、相同端口 ID 且创建该条目的源 MAC 与本帧源 MAC 一致时才删除，否则返回 `ErrSourceMismatch`。
- 同源校验同样适用于 TTL>0 的刷新，防止攻击者用相同机箱/端口 ID 覆盖真实邻居。
- `Sweep()` 按 TTL 老化过期条目；`Stats()` 给出接受/刷新/撤销/老化及三类拒绝计数，可用于攻击告警。

## 验证

`lldp_test.go` 覆盖三类攻击面及正常路径，运行：

```sh
go test -race -v ./...
```

- 乱序/重复 TLV、结束 TLV 后带数据、非零长度结束 TLV、截断帧均被拒绝。
- 洪泛：每端口超过上限的新邻居被 `ErrTableFull` 拒绝，端口间容量互不影响。
- 他人撤销：异源 MAC 的 TTL=0 帧（含对不存在邻居的撤销）无法删除真实条目，属主自身撤销正常生效。
- 并发：多端口多线程混合学习/超限时无数据竞争，条目数不超过上限。
