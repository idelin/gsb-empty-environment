发送端常把一封邮件加密后投递给多个收件人，但每个收件人可能有多把已认证设备密钥，地址别名与转交授权也会变化。给 Go 邮件宿主写可导入的加密投递规划包。设备能力声明由宿主验签，绑定稳定邮箱身份、设备代次、允许算法和有效期；别名只能通过有期限的签名边归到同一身份，合并后的地址显示名不能充当证据。投递请求给出各收件人必须覆盖的设备组、禁止同一信封共存的保密身份对和全局算法偏好。每份信封只能用一个算法，包含的每一把公钥都须在同一发布时间拥有对该算法的授权；两个设备组可共用同一把密钥仅当它确属同一主体。选信封数最少的方案，其次使最弱信封的算法等级尽可能高，再按稳定编号决胜。至多18个设备组。输出完整授权证书供独立投递端校验；提交前如证书吊销或收件组变更，只能重新规划，不能私自兜底降级。用小规模穷举对照需要拆封、贪心选最强算法导致多一份信封、证书区间仅在端点相接、同名异身份及盲抄送身份不能共同披露。
