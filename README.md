# gcrt — 广义同余系统求解库

求解设备计数器给出的同余系统 `x ≡ r_i (mod m_i)`，模数**不必互素**。
全程使用 `math/big`，支持负余数与任意大的整数。

## 求解语义

- 合并规则：`x ≡ a (mod m)` 与 `x ≡ b (mod n)` 相容当且仅当
  `a ≡ b (mod gcd(m, n))`，解定义在 `lcm(m, n)` 上（扩展欧几里得合并）。
- `Solution` 给出最小非负代表 `Res ∈ [0, Period)` 与周期 `Period`（所有模数的最小公倍数）。
- 空约束系统返回 `x ≡ 0 (mod 1)`，即**所有整数**。
- 系统不可行时，`Solution.Conflict` 给出**最早矛盾的原约束对**
  （按插入顺序：最小的 j，再取最小的 i < j）。同余系统可行当且仅当
  两两可行，故该对必然存在且可直接定位。

## 事务、快照与删除

- `Store.Begin()` 开启事务，`Add`/`Remove` 缓冲变更，`Commit` 发布新的
  不可变版本，`Rollback` 撤销（撤销后由全量合并核对状态）。
- 任意历史版本可通过 `Store.Solution(v)` / `Store.Constraints(v)` 查询。
- 求解状态始终保留**全部原约束**（ID、模数、余数），而非只保留合并余数：
  合并结果不可逆，删除任一原约束后必须依靠幸存约束重建真实解集
  （`System.Remove` 触发全量广义合并）。

## 检查点

- `Store.SaveCheckpoint(path)` 以 JSON 持久化每个版本的原约束身份与
  增量求解状态（缓存的合并解）。
- `LoadCheckpoint(path)` 恢复时逐版本审计：持久化的增量状态必须等于
  对原约束重新执行的**全量广义合并**，否则拒绝加载（防篡改/防损坏）。

## 验证

测试以有限周期枚举（在一个 lcm 周期内逐点核对）交叉验证：

- 随机系统与随机约束对的合并结果（含负余数）；
- 大整数（>100 位二进制）可行与不可行系统；
- 事务增删、回滚与历史快照在每一步都与全量合并及枚举一致；
- 检查点往返恢复、篡改拒绝、冲突对身份保持。
