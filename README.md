# facilitycover

Go 求解库：树形设施候选上的覆盖收益最大化。

设施组成森林：开启子设施必须同时开启其全部祖先（开启集是祖先闭包）。
每个需求点被任意已开设施覆盖即计一次收益，重叠覆盖不重复计分。

## 问题一：确定性覆盖（`SolveDeterministic`）

- 至多 20 个设施，整数预算。
- 目标：最大化覆盖总收益；并列时最小化总开启费用（再按字典序保证确定性）。
- 输出：开启闭包（排序后的设施 ID）、收益、费用。
- 算法：按父先子后的顺序递归枚举闭包，预算剪枝，覆盖用位集增量累计，
  每个需求点天然只计一次。
- 核对：`VerifyDeterministic` 独立重算——
  1. 开启集确为祖先闭包且不超预算；
  2. 逐需求点重算收益（存在覆盖即计一次），验证重叠不重复计分；
  3. 穷举全部 2^n 子集确认收益与费用均最优。

## 问题二：两阶段鲁棒覆盖（`SolveRobust`）

- 至多 12 个设施、5 个情景。
- 第一阶段：开启决策在观测前固定（祖先闭包）。
- 第二阶段：观测情景后，仅能在祖先已全部一阶段开启的设施中启用至多
  `EmergencyLimit` 个应急设施；同一观测组内的情景必须采取相同应急动作。
- 目标：最大化最坏情景覆盖收益；并列时最小化期望费用
  （一阶段费用 + 情景概率加权的应急费用）。
- 约束：每个情景都满足 一阶段费用 + 应急费用 ≤ 预算。
- 算法：枚举一阶段闭包；对每个观测组枚举应急子集，组内最坏收益最大、
  费用最小。整体最坏值是各组最小值的最小、期望费用按组可分，因此逐组
  最优即全局最优。
- 输出：策略树（`PolicyTree`）+ 每情景收益/费用。
- 核对：`VerifyRobust` 逐情景检查预算、同组动作一致、应急设施祖先已开、
  收益重算不重复计分、最坏收益与期望费用一致。

## CLI

```sh
go run ./cmd/facilitycover [-mode auto|det|robust] instance.json
```

输入 JSON 见 `examples/`。含 `scenarios` 时求解鲁棒问题，否则求解确定性
问题。输出前先运行对应校验器，校验失败以非零码退出。

```sh
go run ./cmd/facilitycover examples/deterministic.json
go run ./cmd/facilitycover examples/robust.json
```

## 测试

```sh
go test ./...
```

包含手算算例（重叠覆盖、闭包强制、同组同动作）与随机实例对拍：
求解器结果与独立的子集穷举暴力解在最坏收益与期望费用上逐一比对。
