列存引擎在扫描分区时把不同索引返回的候选行做布尔组合。内存不够时只能把某些页降级成整页候选，旧执行器却把候选位取反当作精确的 NOT，漏掉了本该返回的行。写可嵌入查询执行器的 Go 包：分区元数据给定每页实际存在的槽号区间，槽号可有洞；每个谓词索引对页分别给出肯定真集合 L 和可能真集合 U，必须验证 L 包含于 U 且二者均不越过活槽。底层谓词只有真假两值，但不同叶可相关，同一个叶名在表达式 DAG 中永远表示同一布尔量。给定最多十二个不同叶的 AND、OR、NOT DAG，输出每页不必回表就能判真的槽、判假的槽，以及剩余槽的重查表达式；按每槽所有与已知真值一致的赋值定义精确分类，不能把 p OR NOT p 判成待查。查询某个待查槽时，按给定列读取成本，以最小的最坏剩余读取代价决定下一次求值的叶，代价相同按叶名排序，返回值应能沿同一查询继续直到得到结论。已知的叶和曾经求过的列不再收费，同列不同叶一次读取会一起得到真值；允许不同分区成本表不同。扫描输出使用半开连续区间，页号、槽号可到 2^40，总输入区间端点二十万个，不逐槽枚举。交付可调用的位图组合器、逐步重查接口和测试；小页用独立的真值枚举与决策树穷举对照，覆盖同一谓词被正反复用、活槽成孤岛、两叶共列导致单独最便宜的叶不是最优首读，以及页降级后无假阴性的情形。
