# logstore — 追加日志恢复工具

追加式记录日志 + 旁路索引，打开时自动恢复。索引可能落后于数据，也可能
含有未持久化的尾部；恢复工具找出最后一个有效索引项，再增量补索引。

## 磁盘格式

数据文件 `data.log`，记录顺序追加：

```
| magic uint32 | payloadLen uint32 | payload ... | crc32 uint32 |
```

crc32 覆盖 8 字节头部 + payload。

索引文件 `index.log`，定长 20 字节项，与记录一一对应：

```
| offset uint64 | payloadLen uint32 | digest uint32 | entryCRC uint32 |
```

- `digest`：整条记录在磁盘字节的 crc32 —— 索引绑定偏移、长度与记录摘要，
  可独立于索引自身校验数据。
- `entryCRC`：索引项前 16 字节的 crc32 —— 识别撕裂/损坏的索引项。

## 故障点枚举（数据与索引交替写入）

`Append` 顺序：写数据 → fsync(数据) → 写索引 → fsync(索引)。崩溃可能落在
任意两个动作之间：

| #  | 故障点                                   | 表现               | 恢复策略                     |
|----|------------------------------------------|--------------------|------------------------------|
| F1 | 数据已持久化，索引项未写                 | 索引落后于数据     | 增量扫描数据尾部，补索引     |
| F2 | 索引项写了一半（撕裂写）                 | 索引尾部垃圾       | entryCRC 校验，截断索引尾    |
| F3 | 数据记录写了一半（撕裂写）               | 数据尾部垃圾       | 截断数据尾                   |
| F4 | 索引已持久化，数据记录丢失               | 索引领先于数据     | digest 校验失败，回滚索引项  |
| F5 | 完整记录被破坏（位衰减、错位写）         | 记录完整但 CRC 错  | **必须报告**，跳过并继续扫描 |

## 恢复流程（Open）

1. 顺序扫描索引，保留前缀连续有效项（entryCRC 校验），丢弃撕裂尾（F2）。
2. 逐项用 digest 对照数据验证：无法定位/度量的记录 → 丢弃该项及其后所有
   项（F4）；记录完整但摘要不符 → 仅丢弃该项（F5），留待空洞扫描报告。
3. 扫描索引未覆盖的所有数据区域（被丢弃项留下的空洞 + 索引覆盖终点之后
   的尾部）：合法记录补索引（F1）；数据末尾的撕裂记录截断（F3）；**完整但
   CRC 错的记录报告为损坏并跳过，绝不当作普通尾截断**（F5）。
4. 持久化：先写索引并 fsync（中间有删改时先截断为 0 再整体重写），再截断
   数据尾并 fsync。任意时刻崩溃，下次 Open 都会收敛到同一结果——重开
   不漏不重。

## 使用

```
go run ./cmd/logrecover <dir>
```

输出修复范围：数据截断点、索引截断/重写情况、补索引的数据偏移区间
`[RebuildStart, RebuildEnd)`，以及每条损坏记录的偏移、长度与原因。

```go
store, report, err := logstore.Open(dir) // 打开即恢复
off, err := store.Append(payload)
payload, err := store.Read(i)            // 读取时再次校验 digest
```

## 测试

```
go test ./...
```

测试覆盖 F1–F5 各故障点及组合场景，并断言恢复后再次打开报告干净、
记录集合不多不少。
