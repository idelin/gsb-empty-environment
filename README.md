# 实例身份更换隔离

虚拟机被回收后同一网络地址交给新实例，延迟到达的身份文件不能激活新实例。给Go启动宿主实现引导凭据状态机，绑定可信实例ID、启动随机数及一次性部署代次，凭据只在匹配引导窗口安装；新实例产生即废弃旧窗口。用乱序文件投递、地址重用与安装失败测试旧凭据不进入运行环境。

## 设计

状态机位于 `netsec` 包，围绕“引导窗口”（bootstrap window）组织：

- `Supervisor.BootInstance` 在实例启动时打开窗口，窗口绑定三个可信值：
  - 实例 ID（实例监控器提供），
  - 启动随机数 `BootNonce`（`NewBootNonce` 生成 128 bit 随机值），
  - 一次性部署代次 `Generation`（按网络地址严格递增，禁止复用或回退）。
- 同一地址出现新实例时，先 `Purge` 运行环境，再立即吊销旧窗口并移入
  `retired` 集合；旧窗口此后只用于识别并拒绝迟到文件。
- `Supervisor.HandleCredential` 仅当实例 ID、启动随机数、代次全部命中当前
  打开的窗口时才安装；过期、重放、无窗口的凭据在进入 `CredentialSink`
  之前就被拒绝，因此旧凭据永远不会触达运行环境。
- 安装遵循 Stage/Commit/Abort 契约：`Commit` 失败时 `Abort` 必须清除包括
  部分写入在内的全部痕迹，窗口保持打开以便重试；`Purge` 失败则拒绝启动，
  保留旧窗口，避免新旧身份混入半清理状态的环境。
- 状态机在整个校验—暂存—提交区间持锁，杜绝“校验后、提交前地址被重用”
  的 TOCTOU 窗口。

`delivery.go` 把身份文件建模为自描述 JSON 信封（`CredentialEnvelope`），
`DeliverCredentialDir` 以随机顺序消费目录中的文件，模拟乱序与至少一次
投递；重投由窗口内的已安装集合保证幂等。

## 关键不变量

- 仅匹配网络地址不足以安装，三个绑定字段必须同时命中当前打开窗口。
- 代次按地址单调递增，退役代次再次使用返回 `ErrGenerationReused`，
  回退返回 `ErrGenerationReverted`，失败的启动不消耗代次。
- 安装失败后运行环境中不存在该凭据（含部分写入）。
- 窗口吊销后，旧实例的任何迟到文件都返回 `DecisionStaleGeneration` 等
  拒绝决策，且不会调用底层 sink。

## 测试

```sh
go test -race -count=1 ./...
```

测试覆盖三类要求场景：

- 乱序文件投递：随机文件名与随机消费顺序、重复投递幂等。
- 地址重用：旧实例凭据在新实例启动后被拒绝，运行环境先 Purge，
  伪造随机数/实例 ID、未来代次、未知地址均被拒绝。
- 安装失败：Stage/Commit/Purge 故障注入，验证回滚后运行环境无残留，
  故障消除后可重试。

另有代次单调性、并发投递与重启竞争、畸形文件、随机数唯一性等测试。
