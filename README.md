# 符号绑定预审查

本模块提供 `binding` Go 包，为加载审查宿主计算自定义符号绑定结果和插件插入攻击方案；它不模拟或声称实现任何平台链接器。

## 模型

- `Module`：唯一 ID、信任位、有序依赖、按 `(名称, 版本)` 唯一的导出表。
- `Export`：包含 `weak`/`strong` 两类强度；`AliasOf` 可表示别名重导出或可信中继。
- `Relocation`：发起模块、符号名、精确版本、是否允许外部抢占、是否要求可信目标。
- 一次装入最多 16 个模块；缺依赖、重复模块 ID、同模块内重名同版本导出均返回输入错误。
- 依赖允许成环；广度优先遍历按依赖顺序入队，并以首次出现去重。

## 查找规则

- 允许抢占：发起模块 → 宿主全局列表中的其余模块 → 发起模块依赖的 BFS 序列。
- 禁止抢占：发起模块 → 发起模块依赖的 BFS 序列 → 全局列表中的其余模块。
- 所有序列合并时保留首次出现的模块；符号版本必须精确一致。
- 完整序列中优先选择第一个强定义；没有强定义时才选择第一个弱定义。
- 别名始终解析到实际定义模块，信任位也以实际定义模块为准。
- `Bind` 返回完整 `SearchOrder`、每个模块的匹配事件、强弱候选和最终胜出理由。

## 攻击搜索

`FindAttackPlans` 从 0 个插件开始枚举，最多选择 3 个给定插件并插入基础全局列表的任意 0 基位置，同时保持原模块相对次序：

- 返回使“要求可信”的重定位最终绑定不可信实际定义方的最少插件方案。
- 默认最多输出 20 个等长方案，按插件 ID、再按插入位置排序；超过上限时设置 `Truncated`。
- 超过模块上限、依赖未装入或别名目标未装入的排列不会作为可行方案。
- `AttackOptions.SearchBudget` 控制枚举预算；预算耗尽且不能证明最小值时返回 `unknown`。

## 示例

```go
result, err := binding.Bind(modules, globalOrder, relocation)

report, err := binding.FindAttackPlans(
    baseModules,
    baseGlobalOrder,
    candidatePlugins,
    relocation,
    binding.AttackOptions{},
)
```

测试覆盖弱定义被强定义抢占、依赖环、版本不命中、禁止抢占时本地强定义、可信中继暴露不可信定义、输出截断和预算耗尽。
