多租户身份提供商（IdP）开放 OpenID Connect Dynamic Client Registration 1.0（RFC 7591）端点供外部应用自助注册客户端时，若未严格校验元数据中的 `jwks_uri`/`sector_identifier_uri`/`logo_uri`/`request_uris` 指向目标、未核对 `sector_identifier_uri` 返回的 JSON 重定向列表包含全部 `redirect_uris`，或允许客户端在注册/更新时同时提交 `jwks` 与 `jwks_uri`、将 `subject_type="pairwise"` 篡改为 `"public"` 关联用户跨站身份，抑或通过 `grant_types`/`response_types` 组合绕过授权类型白名单，攻击者可发起内网 SSRF、窃取跨站用户关联标识或注册高危隐式流客户端。为 TypeScript 认证宿主实现可导入的零外部依赖 OIDC 动态客户端注册安全审查与 Pairwise `sub` 计算组件（外部 `sector_identifier_uri` 内容通过注入的确定性抓取回调获取，密码原语用 Node `crypto`）。组件严格执行：（1）URI 与防 SSRF 硬校验：全部元数据 URI 必须为规范 HTTPS（禁止回环/私网/链路本地/元数据 IP、IPv4-mapped IPv6、userinfo、fragment 及相对点段穿越），硬拒绝同时提供 `jwks` 与 `jwks_uri`，拒绝含私钥分量（`d`/`p`/`q`）的公钥集；（2）`grant_types` 与 `response_types` 强一致校验：按 OIDC Core 规范校验二者双向对应关系（如 `response_types` 含 `code` 时 `grant_types` 必含 `authorization_code`），策略禁止 `implicit`（`token`）与 `password` 遗留不安全流；（3）Pairwise `sub` 扇区隔离防越权：当 `subject_type="pairwise"` 且存在多个不同主机的 `redirect_uris` 时，强制要求配置有效 `sector_identifier_uri` 且其返回数组精确包含客户端全部 `redirect_uris`；客户端更新阶段硬禁止将已注册的 `pairwise` 降级为 `public` 或更改扇区标识，并用 `HMAC-SHA256(sector_secret, sector_id || local_user_id)` 确定性派生跨扇区不可关联的 `sub`。附内网 `jwks_uri` SSRF、多主机缺 `sector_identifier_uri` 绕过、`pairwise -> public` 降级拦截与私钥 JWK 拒绝测试。
