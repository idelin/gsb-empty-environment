边缘网关准备替换已上线的有状态过滤策略。给 TypeScript 控制面写可导入的变更检查包：两份策略分别由若干带优先级的条件和动作组成，条件可检查地址前缀、端口区间、方向、连接标签的三位掩码，或这些条件的与、或、非；最高优先级先匹配，同优先级按声明顺序。动作除允许或拒绝外还可设置标签，拒绝不改变标签。连接按五元组及其反向识别，首次标签为零。检查旧策略允许的已建立连接在热切换后能否出现权限扩大：切换前按旧策略处理任意前缀，切换后同时从同一旧标签分别继续执行新旧策略，计算各抽象类别中可达的标签对，核对每一对标签上的授权包含关系；只报告通过、拒绝及违反的规则编号。通过时给出可独立验证的不扩大证明。证书须覆盖所有前缀、端口和标签等价类，不能仅抽样；无需枚举 IPv6 地址。限定每份策略至多40条规则，只考虑一条连接的双向报文，变更期间端点、端口及传输协议不变。用缩小地址域的全枚举检查证书，并验证只有经过多步标签迁移才出现的差别、反向报文、前缀边界和两份写法不同但授权相同的策略。
