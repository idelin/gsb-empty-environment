连续批处理推理引擎用分页显存管理 KV Cache，多请求共享系统提示前缀块可省显存，但解码步显存不足触发抢占时，若误算共享块引用计数会造成显存泄漏或破坏其他运行中请求。给推理运行时交付可导入的 Go 块表调度包。显存总计 B 个物理块，每块容 S 个 token；每个请求含优先级、到达序、前缀内容哈希块链、待预填长度和最大生成步数。每迭代步先为运行中请求分配新步所需物理块：若待分配块的前缀哈希已在驻留共享表中则直接复用并递增引用计数，否则从空闲池或可驱逐零引用缓存块（按 LRU）分配；若物理块不足，按优先级最低（并列取最新到达）抢占运行中请求，释放其独享块并仅对共享块递减引用计数（减至 0 后移入可驱逐前缀缓存而非丢失哈希），直至满足剩余请求需求或无法满足报错；随后按优先级接纳等待队列请求（须一次够放其预填所需非共享块，不得反过来抢占已运行高优请求）。验收用单步跟踪对照物理块守恒不变量（已用+缓存+空闲恒等于 B，引用计数与所有存活页表一致），覆盖共享前缀跨请求复用、抢占不破坏同前缀存活请求、零引用前缀块按 LRU 淘汰后再命中重建，以及显存紧临界下多步抢占回滚与重新入队。
