堆表存储引擎引入 HOT（Heap-Only Tuple）优化后，未修改索引列的行更新在同一数据页内形成 `t_ctid` 更新链，外部索引仍仅指向链首的根行指针（Root Line Pointer）；执行页内剪枝（Page-Level Pruning）时，若直接释放仍有索引引用的根行指针、或把被中止事务打断的链段误当成死链合并，就会造成索引悬空指针或活行丢失。为数据库存储层交付可导入的 Go HOT 页剪枝与空间紧缩包。单页包含固定行指针数组（状态分 `LP_UNUSED`、`LP_NORMAL`、`LP_REDIRECT`、`LP_DEAD`）与变长元组区（每元组含 `xmin`、`xmax`、是否已提交/已中止标志、`HEAP_HOT_UPDATED`、`HEAP_ONLY_TUPLE` 及 `ctid` 下一偏移）。给定全局可见水位 `oldestXmin` 与活跃事务集合：剪枝器遍历所有根行指针沿 HOT 链识别死元组、近期死亡元组（仍对某活跃快照可见）和活元组；若根元组已彻底死亡且沿链可达某个活或近期死亡的后继，必须将根行指针改写为指向该后继的 `LP_REDIRECT` 并把中间已死 `HEAP_ONLY_TUPLE` 行指针回收为 `LP_UNUSED`；若整条链全部彻底死亡，根行指针须标记为 `LP_DEAD`（等待索引清理，绝不可直接标 `LP_UNUSED` 供新插入复用！），其余中间 `HEAP_ONLY_TUPLE` 标 `LP_UNUSED`；若链中途遇到已中止的 `xmax` 或非 HOT 更新（跨页 `ctid`），须正确终止链遍历。最后执行页内物理紧缩重排剩余元组偏移、更新全部 `LP_NORMAL` 偏移指针并保持所有 `LP_REDIRECT` 目标索引与自由空间边界一致。验收覆盖根死后继活转 `LP_REDIRECT`、整链全死根留 `LP_DEAD`、中止更新断链、跨页非 HOT 终止、二次剪枝穿透已有 `LP_REDIRECT` 以及紧缩后逐快照扫描结果与剪枝前完全等价。
