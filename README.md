SSH 网关在实现传输层协议（RFC 4253）及扩展协商（RFC 8308）时，若未强制落实严格密钥交换（`kex-strict-c-v00@openssh.com` / `kex-strict-s-v00@openssh.com`），中间人可在 `ChaCha20-Poly1305` 或 `EtM` 模式下于 `NEWKEYS` 前注入 `SSH_MSG_IGNORE` 递增序列号并丢弃加密后的首条 `SSH_MSG_EXT_INFO`（Terrapin / CVE-2023-48795），从而静默降级 `server-sig-algs` 认证算法并绕过敲击防护。为 Go 网络安全宿主实现可导入的 SSH 传输层握手与 `kex-strict` 完整防截断状态机包，严禁联网与严禁调用外部 SSH 协议库。组件精确管理收发 32 位二进制包序列号、版本交换、初始 `KEXINIT` 伪算法协商、`NEWKEYS` 密钥激活及重协商（Rekey）全流程：（1）正确识别对端 `KEXINIT` 中的 `kex-strict` 标记并在双方均支持时立即启用严格模式（同时提供策略开关硬拒绝不支持 `kex-strict` 且协商到易受攻击套件的对端）；（2）严格模式下在初始 `KEXINIT` 前及至首次 `NEWKEYS` 期间，硬拒绝任意 `SSH_MSG_IGNORE`、`SSH_MSG_DEBUG`、`SSH_MSG_UNIMPLEMENTED` 或乱序报文，并验证首条 `KEXINIT` 序列号严格为 0；（3）在收发 `SSH_MSG_NEWKEYS` 生效点强制将对应方向序列号重置为 0，并校验随后若协商了 `ext-info-c`/`ext-info-s` 则首条加密报文须按规范处理 `SSH_MSG_EXT_INFO`（拒绝重复或迟到的 `EXT_INFO` 注入），且在后续 Rekey 中保持非零初始序列号语义不被错误清零。附模拟 Terrapin 前缀注入、乱序忽略包、EXT_INFO 剥离与合法 Rekey 互操作测试。
