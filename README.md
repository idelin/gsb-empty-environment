多协议共享通配符证书的边缘网关同时承载 HTTPS、SMTP、IMAP、FTP 等 TLS 服务时，若未强制落实 RFC 7301 ALPN 严格协商与 RFC 6066 SNI 一致性校验，攻击者可将浏览器发往 HTTPS 站点的 TLS 流量重定向至同证书的 SMTP/FTP 端口（ALPACA 跨协议攻击），利用协议容错把 HTTP 请求体当作命令执行或窃取 Cookie。为 Go 传输安全宿主实现可导入的 TLS 握手 `ClientHello`（SNI/ALPN 扩展）与证书绑定防 ALPACA 混淆验证包，严禁联网（仅用标准库 `crypto/x509`）。组件严格实现：（1）原始字节级解析 `ClientHello` 中的 `server_name`（0x0000）与 `application_layer_protocol_negotiation`（0x0010）扩展，硬拒绝重复扩展、空协议名、越界长度、非法的 IP 字面量 SNI 及尾随垃圾字节；（2）执行严格的 ALPACA 准入策略：每个服务端口声明允许的 ALPN 协议集合与绑定主机名列表，当客户端缺少 ALPN 或双方 ALPN 交集为空时强制返回 `no_application_protocol`（Alert 120）阻断握手（严禁静默回退默认协议）；当 SNI 缺失或不匹配目标服务主机名时返回 `unrecognized_name`（Alert 112）；（3）校验服务证书 SAN（区分 DNS 与 IP SAN，禁止单通配符跨非授权子域或跨协议服务复用）以及应用层首行/Host 头与 TLS SNI 精确一致（拦截领域前端 Domain Fronting 与 HTTP/1.1 Host-SNI 错配）。附 ALPACA 跨端口重定向、无 ALPN 降级、重复扩展畸形包与 Host-SNI 错配对抗测试。
