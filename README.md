# 工作区设置可执行路径与受限模式

编辑器打开别人给的仓库时会读取工作区设置文件，攻击者在里面把解释器路径、终端 shell 或格式化程序指向仓库内的可执行文件，打开即运行。为TypeScript编辑器宿主写可导入的设置合并包，输入用户设置、工作区设置、文件夹设置（后者覆盖前者）、工作区是否受信任，以及调用方给的受限键清单（键名，或以 .* 结尾的前缀；这些键的值被当作可执行路径或命令）：不受信任时，工作区与文件夹层里的受限键整项忽略，保留低一层的值，并产出一条被忽略的记录；受信任时按常规覆盖；带 .* 的前缀按键名前缀匹配，匹配区分大小写；值为对象且内部任意层出现 path 或 args 子键时，该键视同受限；用户层的值永远生效；信任状态在合并之后变化时必须重新计算，不能沿用旧结果。用不受信任的解释器路径、含 path 子键的终端配置、前缀匹配、信任切换后重算验证。
