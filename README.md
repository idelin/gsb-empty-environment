RFC 9002 QUIC 丢包检测与恢复状态机把三个独立包号空间（`Initial`、`Handshake`、`ApplicationData`）的 RTT 估算、包门限/时间门限判丢、PTO 探测退避与地址未验证 3 倍防放大限制耦合在一起，五处细节是协议栈最常见的丢包误判或死锁根源：1）**三独立编号空间与防误算 `ack_delay`**：每个编号空间各自维护 `largest_acked_packet`、`loss_time`、`time_of_last_ack_eliciting_packet` 与在途包表；仅当收到新确认更大包号且本次 ACK 覆盖了至少一个 `ack-eliciting` 包时才更新 `latest_rtt` 与 `min_rtt`；且**仅在 `ApplicationData` 空间且握手已确认后**才从 `latest_rtt` 扣除 `min(ack_delay, max_ack_delay)`（绝不可让调整后的 RTT 小于 `min_rtt`！），Initial 与 Handshake 空间严禁扣除 `ack_delay`！2）**包门限与时间门限双重判丢**：对小于 `largest_acked` 的未确认在途包，满足 `largest_acked - pn >= 3`（`kPacketThreshold`）或 `now - time_sent >= max(9/8 * max(smoothed_rtt, latest_rtt), kGranularity)` 即立刻判为丢失；尚未超时的最早包决定该空间的 `loss_time` 定时器；3）**跨空间最早定时器选择与 PTO 指数退避**：若任意空间存在 `loss_time`，优先调度最早的 `loss_time`；否则仅在存在 `ack-eliciting` 在途包（或客户端尚未完成握手且未收到服务端验证前为防死锁！）时，按 `PTO = (smoothed_rtt + max(4*rttvar, kGranularity) + (AppData ? max_ack_delay : 0)) * 2^pto_count` 在非空空间中选取最早 PTO 到期空间；且**在握手确认（Handshake Confirmed）前绝不为 `ApplicationData` 空间设置 PTO**！每次 PTO 触发递增 `pto_count`，收到任意有效 ACK（且非过时包）归零；4）**丢弃密钥空间与防放大死锁防护**：当 `Initial` 或 `Handshake` 空间被上层通知丢弃时，必须立刻清除该空间全部在途包、归零其 `bytes_in_flight` 贡献并重算全局定时器；在服务端尚未验证客户端地址前，已发送总字节数受 `3 * bytes_received` 硬限制，此时若被防放大阻塞则停止设置服务端 PTO 定时器（避免无效空转！）。为传输层交付可导入的 Go RFC 9002 QUIC 丢包检测与恢复引擎。验收覆盖三空间隔离与 `max_ack_delay` 仅限 AppData 扣除、包门限 vs 时间门限精确判丢、握手未确认禁 AppData PTO、密钥空间丢弃清在途字节及服务端 3 倍防放大阻塞暂停 PTO。
