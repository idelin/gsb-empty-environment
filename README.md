大模型推理采用 Prefill-Decode（PD）物理分离架构后，每条请求先在 P 节点完成提示词预填充生成 KV 缓存块，再经由 RDMA 链路把 KV 块迁移至 D 节点执行逐令牌解码；实际调度中存在两类极易导致全集群锁死的陷阱：一是**跨节点 KV 预留死锁**——P 节点占着已算完的 KV 块等待满载的 D 节点腾出空间，或 D 节点把全部空闲块都预留给了尚未迁完的新请求，导致自身正在解码的老请求拿不到下一个 token 的 KV 块从而永远无法结束释放空间；二是高负载下盲目接纳长上下文请求不仅击穿首字延迟（TTFT）与单字间隔（TPOT）双 SLO，还打爆跨节点 RDMA 带宽。为分离式推理集群交付可导入的 Go PD 分离调度与防死锁迁移规划包。输入为异构 P 节点集合与 D 节点集合（各含算力速率、总 KV 块容量 `totalBlocks` 及点对点 RDMA 链路带宽）、动态到达的推理请求流（含提示词长度、预期生成长度、`ttftSlo`、`tpotSlo` 与优先级）。规则：1）为每条请求联合决策目标 `(P, D)` 节点对、Prefill 开始时间、RDMA 迁移窗口与 Decode 接纳计划；2）实施严格防死锁显存准入不变量——D 节点必须为正在解码的在途请求预留足够推进至完结的增量安全水位或实施可抢占回滚（把最低优先级刚预留但尚未开始解码的迁入预留安全撤销并重路由，绝不允许 D 节点出现“在途解码无块可涨、迁入预留互相等死”！），P 节点在 KV 迁移确认落盘到 D 节点后立刻释放源 KV 块；3）严格遵守各 P/D 节点算力批处理约束及点对点 RDMA 带宽容量上限（支持多条迁入共享链路按权重分摊带宽），在超载无法满足双 SLO 时按优先级拒绝低优请求而非拖死全部高优请求；4）精确输出每条请求的调度轨迹、实际 TTFT/TPOT、SLO 达标率及任意时间点所有 P/D 节点 KV 块占用不越界且无死锁证明。验收覆盖 D 节点满载临界压力下防死锁安全推进、RDMA 链路拥塞导致 P 节点背压与重路由、超载优先保障高优请求双 SLO，以及每时间步全节点物理 KV 块零超限零泄露。
