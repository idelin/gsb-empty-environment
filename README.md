# DKIM签名头绑定与密钥记录严格解析

攻击者可控制某子域的签名，或在邮件里再塞一个 From 头，让验签通过却显示另一个发件人。给Go验签包写可导入的两个判定函数，签名运算与 DNS 查询由调用方注入。其一是密钥记录判定：同名多条 TXT 时先拼接各条内的多个字符串（不加分隔），多于一条以 v=DKIM1 开头的记录视为无效；tag-list 按 ';' 分隔，标签名区分大小写，重复标签无效，未知标签忽略，p 中空白先去除；v 缺省或为 DKIM1；k 缺省 rsa，仅接受 rsa 与 ed25519；p 为空表示密钥已撤销；rsa 的 p 经调用方注入的解析器得到位数，小于 1024 无效、1024 至 2047 标记为弱；ed25519 的 p 解码后须恰为 32 字节原始公钥；h 列表不含签名所用哈希时拒绝；s 若存在须含 * 或 email；t 为冒号分隔标志，含 s 时签名 i= 域必须等于 d=，否则 i= 须等于或属于 d=，含 y 的结果只标记为测试。其二是 From 绑定判定：输入邮件头行列表与签名的 h= 列表，邮件含多个 From 头一律失败；h= 未覆盖 From 失败；调用方可要求超签，即 h= 中 From 出现次数须为邮件中出现次数加 1。选择器名与 d= 按小写规范化，选择器各标签须是合法 DNS 标签。用重复标签、撤销、弱 RSA、ed25519 长度错误、s=email 之外的服务类型、子域越权、多 From 头与超签验证。
