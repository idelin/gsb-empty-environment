边缘计算与插件沙箱在加载不可信 WebAssembly（Wasm 1.0）二进制模块前，若仅依赖运行时粗粒度异常捕获而未在字节码准入阶段核查内存上限、操作数栈类型安全与 `call_indirect` 间接表索引类型一致性，恶意模块可通过超限 `memory.grow` 申请、32 位无符号地址偏移回绕、畸形 LEB128 编码、非法导入未授权宿主函数或精心构造的块控制流栈不平衡触发沙箱逃逸与资源耗尽。为 C++17 沙箱宿主实现可嵌入、零外部依赖、`-Wall -Wextra -Wconversion -Werror` 编译通过的原始字节级 Wasm 1.0 二进制模块安全验证库。库从魔数与版本起严格顺序解析 Type、Import、Function、Table、Memory、Global、Export、Element、Code、Data 段：硬拒绝超长/非规范 LEB128、段序乱序、重复段与截断字节；实施宿主安全策略（仅允许白名单导入模块/函数签名、强制线性内存声明最大值且不超过配额、禁止导出未受限可变全局或内部表）；并在函数体字节码上执行完整类型与控制流栈抽象验证（覆盖 `block`/`loop`/`if`/`else`/`br`/`br_if`/`br_table`/`return`/`call`/`call_indirect` 以及多态栈 unreachable 语义），同时核查全部内存访存指令的对齐合法性（`align <= natural_alignment`）与静态 `memarg.offset` 防 32 位回绕越界，以及每条 `call_indirect` 引用合法类型索引且元素段初始化函数均符合对应签名边界。附手工构造的合法 Wasm 模块与栈类型不平衡、非授权导入、非法对齐、恶意 `call_indirect` 及畸形 LEB128 测试。
