# pkttrace

离散事件包追踪 + 因果 DAG 分析（纯 Go 标准库，整数 tick，无真实网络流量）。

## 模型

```
source -> queue Q1 -> lossy link L1 -> relay (duplicate)
         -> link L2A ->\
                        -> merge (first copy wins) -> deliver
         -> link L2B ->/
```

- 所有包、队列、链路在离散事件模型中运行，时间为整数 tick。
- 串行化时延 = ceil(bytes/rate) tick；传播时延为链路固定 tick。
- L1 按确定性规则丢包（每 k 次传输丢 1 次），触发 RTO 超时重传。
- 丢包不计入成功时延统计；超过 MaxAttempts 的包记为丢失。

## 分析

- 每包时延分项：排队 / 串行化 / 传播 / 重传等待，沿因果链归属，
  重叠阶段（多路径副本）按因果路径取而非盲相加，分项和 == 投递-入队差。
- 因果 DAG 两个指标：端到端墙钟关键路径（最长因果链）与累计工作量
  （所有因果边时长求和，并行分支全额计入）。
- 缺事件给上下界（开区间），不补零；矛盾时间（子事件早于父事件）
  报告原始边两端事件 ID 与 tick 作为证据，计算时钳为 0。
- 支持增量补事件后重新分析，下界随之修订为精确值。
- 小 DAG 穷举所有源-汇路径作为参考实现，验证 DP 关键路径不双加。
- 每个分项保留来源事件 ID（Evidence），每包给出因果链（Chain）。

## 运行

```sh
go run .      # 运行样例场景并打印报告
go test ./... # 运行全部测试
```
