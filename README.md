# 可暂停恢复的事件时间去抖器

仅依赖 Python 标准库。输入状态抖动时，下游只接收"稳定满门限"的确认变化。

## API

| 操作 | 说明 |
| --- | --- |
| `Debouncer(threshold)` | 创建去抖器，门限为事件时间长度 |
| `ingest(source, value, ts)` | 摄入事件；`value=None` 表示未知值，中断候选计时 |
| `advance(now)` | 推进事件时间，确认稳定满门限的候选 |
| `drain()` | 消费所有已确认未消费的变化（唯一出口） |
| `save()` / `Debouncer.restore(s)` | 导出 / 恢复 checkpoint（纯 dict，可 JSON 序列化） |
| `drop_source(source)` | 显式释放某来源的全部状态 |

## 语义要点

- 候选稳定时长按 `now - candidate_since >= threshold` 判定，满门限即确认。
- 重复事件不延长稳定计时；回到已确认值会清除候选。
- 同一时刻多事件按 `ingest` 调用顺序生效；时间戳非递减，迟到事件抛错。
- 来源之间状态完全隔离；一次 `advance` 内多源确认按来源首现顺序入队。

## 持久化与资源释放

- 持久化：门限、当前事件时间、每源的已确认值 / 候选及其起始时间 /
  最近事件时间、未消费的确认队列。**不保存事件日志**。
- 释放时机：事件在 `ingest` 时即折叠进 O(1) 状态（旧事件立即释放）；
  确认结果在 `drain()` 时释放；来源状态用 `drop_source()` 显式释放。
- 恢复保证：已消费的确认不会重发，未满时长的候选连同起始时间保留。
