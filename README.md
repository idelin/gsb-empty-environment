# orset — 离线集合复制库（OR-Set CRDT）

Go 实现的 Observed-Remove Set，支持离线副本、并发合并与安全的历史压缩。

## 语义

- **唯一标签**：每次 `Add` 分配全局唯一标签 `(replicaID, seq)`，同一元素可携带多个标签。
- **Observed-Remove**：`Remove` 只移除本副本已观察到的标签；分区副本上的并发重加使用新标签，合并后必然存活（add-wins）。
- **Merge**：对存活标签与墓碑（tombstone）取并集，幂等、交换、结合。
- **安全压缩**：`Compact` 仅当**所有已知副本**的版本时钟都覆盖某个删除事件时才丢弃对应墓碑（因果稳定性）。离线副本未确认前，删除记录一律保留，杜绝已删标签"复活"。
- **成员假设**：压缩安全性依赖成员列表——通过 `NewSet(id, peers...)` 声明全部副本；合并中发现的副本也会自动纳入跟踪。从不调用 `Compact` 时无此要求。

## 结构

- `orset.go` — 核心库：`Add` / `Remove` / `Contains` / `Merge` / `Compact` / `Clone`
- `orset_test.go` — 单元测试（并发重加、merge 性质、压缩安全性、防复活）
- `cmd/verify` — 三副本分区验证脚本
- `verify.sh` — 一键运行验证

## 运行

```sh
./verify.sh        # 三副本分区验证脚本
go test ./...      # 单元测试
```

验证脚本内容：A、B、C 三副本；A 添加 `x` 并全网同步；C 被分区；A 删除 `x`，A/B 同步并尝试压缩（必须保留墓碑）；C 在分区后并发重加 `x`；分区恢复后合并——断言 `x` 在所有副本存活且恰好只有一个存活标签（C 的新标签），旧标签不复活；确认传播后压缩生效。另有一组对照实验：不安全地提前丢弃墓碑会导致已删标签复活（2 个存活标签），证明安全压缩的必要性。
