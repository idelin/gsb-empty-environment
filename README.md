# 压缩首部接收器可能被恶意引用尚未存在的动态表项拖住全部请求

压缩首部接收器可能被恶意引用尚未存在的动态表项拖住全部请求。为Go协议宿主实现首部准入组件，题内每个区段声明所需插入计数并列出绝对表项号，表项归属连接代次；等待区段数、累计编码字节及最大等待时间分别封顶，取消后旧区段不能释放其他区段引用。解码前逐项核对已插入且未逐出，非法引用终止该连接并零交付。用小表与可控时钟构造远未来索引、取消风暴及合法共享引用，核对资源上限与正常区段能继续完成。

## 实现

- `table.go`：有界 FIFO 动态表 `DynamicTable`，表项携带连接代次（`Gen`），逐出跳过被等待区段钉住（pin）的表项；`Reissue` 开启新代次并清空旧表项。
- `admission.go`：连接级准入控制器 `Conn`。`Admit` 校验区段代次、引用号小于声明的所需插入计数，按 `Limits` 分别封顶等待区段数、累计编码字节与最大等待时间；等待区段仅钉住自己的引用，`Cancel` 幂等且只释放本区段的钉；`Decode` 前逐项核对已插入、未逐出且代次一致，非法引用终止连接并零交付。
- `admission_test.go`：小表 + 可控时钟构造远未来索引超时、取消风暴、合法共享引用、三类资源上限、逐出后非法引用、代次重发等场景。
