Raft 集群进行多节点同时增删时必须经过联合共识配置 `C_old,new` 过渡，但在真实故障交错中极易触发四类致命裂脑缺陷：未提交的 `C_old,new` 尚未生效就被发起第二次变更、在 `C_old` 与 `C_new` 完全不相交时误把两集合合并数多数派、更高任期日志截断未提交配置条目后节点仍残留旧内存配置、以及不在 `C_new` 中的旧 Leader 提交 `C_new` 后未立即退位或仍把自己计入 `C_new` 法定人数。为共识存储交付可导入的 Go 联合共识状态机（驱动多节点确定性消息网络模拟）。节点完整实现任期、投票、日志复制、联合配置条目（`JointConfig(C_old, C_new)`）与最终配置条目（`SingleConfig(C_new)`）。核心不变式：节点在日志追加配置条目瞬间即启用该最新配置（而非等提交）；处于 `C_old,new` 期间，选举获胜与日志提交均必须同时获得 `C_old` 多数派与 `C_new` 多数派；当日志中已有未提交配置条目时 Leader 拒绝新配置变更；一旦 `C_old,new` 被提交，Leader 自动追加 `C_new`；若 Follower 收到冲突 `AppendEntries` 截断了未提交配置条目，必须立即将生效配置回退到日志中剩余的最后一条配置；Leader 提交 `C_new` 时若自身不在 `C_new` 中，提交确认后立刻降级为 Follower 且计算 `C_new` 多数派时不把自身算作投票成员。验收用确定性分区/丢包/重启模拟器覆盖 3 节点完全替换为 3 个全新无交集节点、未提交 `C_old,new` 被分区新主截断回滚、不在 `C_new` 的 Leader 推进并退位，以及任意步均满足单任期单主和已提交日志全节点前缀一致。
