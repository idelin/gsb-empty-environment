分片托管服务换了一批保管人，需要在不知道整把密钥的前提下确认刷新后的份额仍属于同一秘密。实现供 Go 密钥宿主调用的份额刷新验收包，群运算与成员认证由调用方注入，域为已给定的素数域。每个发送者对一个常数项为零的次数小于 k 的多项式发布逐项承诺，给接收者的增量必须与该接收者坐标上的承诺求值一致；仅签名通过不算份额正确。投诉是有签名、绑定轮次及双方身份的记录，同一发送者可给不同收件人发送不同转录。收到的证据可能缺失或相互冲突。包须区分“已证明可计入”“已证明不能计入”和“待证”，只有各收件人引用同一个发送者集合与同一份公共转录摘要，且旧新承诺的常数项相同才允许原子发布新轮。掉电恢复不准把旧轮份额和新增量相加两次。支持参与者 ID 别名映到同一公钥，先消别名再验各证明和门槛；真实保管人的标量值不能出现在审计信息。另给公开证据的合并与验证入口，尚缺材料须准确列到发送者和收件人对，不能为使集合一致而忽略某一收件人的有效投诉。用小有限群的透明参考和可暂停存储验证同一投诉重放、跨轮搬运、两者各自正确但转录不同、少于门槛和提交前后重启。

## refresh 包

包路径：`prescreen.local/ddd-9449-20261122-v2/refresh`。所有协议原语均由宿主注入，
包本身不持有任何私钥或域参数。

### 注入面

- `refresh.Field`：由调用方给定素数 `p` 构造（`NewField` 拒绝合数），承载标量运算。
- `refresh.Group` / `refresh.Point`：承诺所在群，只需 `g*s`、点加、标量乘、逆元与编解码。
- `refresh.Authenticator`：成员认证。`Canonical` 把任意参与者 ID（含别名）映到同一公钥的
  规范 ID；`Sign` / `Verify` 完成签名校验。别名在任何证明与门槛判断之前消解。
- `refresh.Store`：持久化契约；测试用 `PausableStore` 带故障注入与快照恢复。

### 协议入口

1. `TranscriptDigest` 对轮次、有序发送者集合与逐项承诺求确定性摘要。
2. `SignIncrement` / `SignComplaint` 生成绑定轮次、双方身份与转录摘要的签名记录，
   三类消息使用不同域分隔前缀，不可互相重放。
3. `Engine.MergeEvidence` 合并公开 `EvidenceBundle`：先消别名，再去重；同投诉重放进审计
   `Excluded` 而不二次计入，跨轮记录（投诉或增量）整体排除并留痕。
4. `Engine.Triage` 对每个有向 `(sender, recipient)` 对给出三态裁决：
   - `ACCEPTED`：签名有效且 `g*delta == Eval(承诺, 接收者坐标)`；
   - `REJECTED`：签名坏、增量与承诺求值不符、同对冲突增量、有效投诉成立或跨收件人转录
     不一致（equivocation）；仅签名通过永远不够；
   - `PENDING`：材料缺失或暂不可证，缺失项精确列到发送者/收件人对及材料类型。
5. `Engine.PublishGate` 做原子发布闸门，任一条件不满足即整体拒绝：
   - 各收件人引用同一发送者集合与同一转录摘要；
   - 被计入门内的对全部为 `ACCEPTED`，有效投诉或失格发送者不得被悄悄忽略；
   - 完整通过的收件人数达到门槛 `k`；
   - 刷新承诺逐项和的常数项为单位元，且旧主承诺常数项加零仍等于宿主持久化的
     `ExpectedConstant`，即旧新承诺常数项相同、秘密未被替换。
6. `VerifyPublicEvidence` 是一站式公开入口，返回合并结果、三态报告、闸门决策与无标量
   审计投影 `AuditReport`（结构上不含任何 `math/big` 字段，有反射测试守护）。
7. `Engine.StageAndCommit` / `Recover` 用两阶段持久化折叠增量：先落 `StagedState`
   （含旧份额、预计算新份额与增量摘要），再替换当前份额并清标记。重启后按标记恢复，
   绝不把同一增量加第二次；非相邻轮次与旧份额不匹配都会拒绝。

### 透明参考与测试矩阵

- 加法参考群 `Z_101`（`refgroups_test.go`），每个运算都是可手算的模整数。
- 乘法参考群：`F_107^*` 中阶为 53 的子群 `<4>`，标量域为同阶素数域 `F_53`。
- 内存 Ed25519 认证器支持别名映射。

覆盖场景：健康轮发布、同投诉重放去重、跨轮增量/投诉搬运、各自正确但转录不同的
equivocation、签名有效但增量代数错误、缺失材料逐对列出、有效投诉不可被忽略、
少于门槛、转录摘要不一致、常数项不一致、别名先消解、审计无标量、失格发送者全局剔除、
多 bundle 合并、提交前/后重启与快照恢复、非相邻轮拒绝、多轮刷新后任意 `k` 个份额
重构出原秘密。
