网络接入服务器（NAS）与认证代理在运行基于 UDP 的 RADIUS（RFC 2865）协议时，若响应报文（`Access-Accept`/`Access-Reject`/`Access-Challenge`）未强制要求携带 `Message-Authenticator`（属性 80，HMAC-MD5）并将其置于属性列表首位、允许将 `Access-Reject` 经 MD5 前缀碰撞伪造为带特权属性的 `Access-Accept`（Blast-RADIUS / CVE-2024-3596），或未正确校验 `Proxy-State`（属性 33）顺序与 `Response Authenticator`，中间人无需共享密钥即可任意冒充管理员通过认证。为 Go 认证宿主实现可导入的原始字节级 RADIUS 报文解析与 Blast-RADIUS 完整防御验证包，严禁联网（仅用标准库 `crypto/md5`/`crypto/hmac`）。组件严格实现：（1）解析原始 RADIUS 报文头（Code、Identifier、Length、16 字节 Authenticator）与全部 TLV 属性，硬拒绝 `Length < 20`、`Length > len(pkt)`、尾随截断/冗余字节及 `attr.Len < 2` 死循环；（2）严格执行 Blast-RADIUS 缓解规范：客户端与代理对所有 `Access-Accept`/`Access-Reject`/`Access-Challenge` 强制要求存在且仅存在 1 个 18 字节 `Message-Authenticator` 属性（长度字段 18，16 字节值），策略开启严格模式时强制要求其必须为首个属性（防代理拼接前缀碰撞）；先将 `Message-Authenticator` 值置 16 字节零并用对应请求 `Request Authenticator` 替换包头 Authenticator 后重算 HMAC-MD5 恒定时间验真，同时校验标准 MD5 `Response Authenticator`；（3）完整核对代理链 `Proxy-State` 列表与原请求逐项按序一致（拦截删改/注入 `Proxy-State`），并拒绝 `Access-Request` 复用近期已见 `Request Authenticator` 重放。附 Blast-RADIUS 缺失/后置 `Message-Authenticator` 拦截、属性篡改、`Proxy-State` 乱序与重放测试。
