Raft 集群在成员变更中途发生切主时，未提交的旧配置条目可能被新主覆盖，导致每个索引生效的成员集合随日志前缀动态变化。为共识核心交付可导入的 Go 提交水位计算包。输入新主当前任期号、主节点完整日志条目（每条含索引、任期，及可选配置变更：进入联合配置 C_old,new 或切至新配置 C_new，节点集合含投票者与非投票学习者）、各节点已复制匹配的最高索引 matchIndex 及各节点持久任期。按 Raft 规则，日志条目一旦写入即对后续索引生效，但仅当某索引 k 的条目任期等于当前主任期、且从上一已提交水位到 k 之间所经历的每一生效配置（单配置须过半投票者，联合配置须同时在 C_old 与 C_new 各自过半投票者）均确认已复制到 k 及以上时，才可安全推进 commitIndex 至 k。组件返回精确最大安全 commitIndex 以及每个未通过推进门槛的瓶颈配置。验收用状态机枚举合法故障切换场景对照不变量，覆盖主节点自身不在新配置中、学习者不计入多数、旧任期日志被当前任期配置变更间接提交、以及连续两条配置日志尚未提交时双多数同时受阻。
