高性能加密隧道在定期密钥轮换（Rekey）期间需要同时维持上一代、当前代与待确认下一代三个会话槽，且每个会话独立用固定字数位图拦截重放包；若大跳步序号把位图清理错位或未等首个合法加密包就过早淘汰旧会话，会造成切换抖动或重放漏洞。为隧道数据面交付可导入的 Go 会话与防重放接收包。每个会话含 32 位接收索引、64 位单调计数器上限 `RejectAfterMessages`、过期时长 `RejectAfterTime` 及长度为 W 位（64 的整数倍，如 2048）的环形防重放位图（按 RFC 6479 精确分字清理）。规则：发起方创建 Next 会话后仍保留 Current 与 Previous，直到收到属于 Next 会话的首个通过认证与防重放校验的合法包时，原子把 Next 晋升为 Current、旧 Current 降为 Previous、丢弃更老的 Previous；超过 `RejectAfterMessages` 或时间超 `RejectAfterTime` 的会话一律拒收；防重放窗口接收低于 `maxCounter - W + 1` 或位图已置位的序号必须判重放拒绝，接收高于 `maxCounter` 的新序号时推进窗口并精确清零跨过的全部位图字（跳步 ≥W 时整表清零仅置新位）。验收用大跨度乱序/重放/跨代切换事件流对照朴素已见集合参考模型，覆盖跳步恰好等于 W-1/W/W+65 的位图边界、Next 首包触发原子三代晋升、迟到 Previous 包在过期前仍放行而过期后拒收，以及伪造 Next 包绝不触发晋升。
