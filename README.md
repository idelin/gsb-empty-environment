# sshchannel

跳板机允许登录却不应允许任意端口转发。给Go会话宿主实现每个通道独立授权的多路复用包，异步拨号时固定目标与策略代次，成功接入前复核撤销；通道号可复用，旧回调不得接管新通道。用可暂停拨号器验证半关闭、拨号失败与回收次序。

## 设计

`Mux` 在一条可靠、有序的会话字节流（如 SSH channel）上承载多条逻辑通道。

- **每通道独立授权**：每个 `Open` 帧都先经过 `Policy.Authorize`，返回一张与该通道绑定的 `Grant`；拒绝时直接回 `Fail`，不会触发任何拨号。
- **目标与代次固定**：`Grant` 在拨号前固化目标（`Host/Port`）与策略代次（`Generation`）及唯一流水号（`Serial`）。异步拨号只使用这个固化目标，后续策略变更无法改道。
- **接入前复核撤销**：拨号在独立 goroutine 中进行；拨号返回后、通道被真正接入（发送 `OK`）前，再次调用 `Policy.Revoked`。代次推进（`SetRules`/`RevokeAll`）或单通道撤销（`Grant.Revoke`）都会让连接被关闭并回 `Fail`。
- **通道号复用与防陈旧回调**：通道以“编号 + 代次（epoch）”标识。编号被回收后，旧拨号回调返回时通过指针与 epoch 双重校验识别为陈旧，关闭其连接且绝不触碰新通道。
- **回收次序**：回收严格按“先摘注册表（编号立即可复用）→ 取消拨号上下文/关闭上游连接 → 等待 relay 退出”的顺序进行。
- **半关闭**：客户端 `CloseWrite` 传播为对上游目标的写侧关闭；目标 EOF 经 relay 转成 `Half` 帧送达客户端，读侧得到 `io.EOF` 而不会拆除整条会话。

## 帧协议

帧格式：`1 字节类型 | 4 字节大端载荷长度 | 载荷`，单帧载荷上限 1 MiB。

| 类型 | 含义 |
| --- | --- |
| `Open` | 请求打开通道，载荷为 `通道号 + host:port` |
| `Data` | 通道数据，载荷为 `通道号 + 数据` |
| `Close` | 全关闭通道 |
| `Half` | 写侧半关闭 |
| `OK` | 宿主接入成功 |
| `Fail` | 授权/拨号/复核失败 |

## 主要类型

- `Mux`：会话宿主，`NewMux(Config)` + `Serve()`，`Close()` 取消在途拨号并回收全部通道。
- `Client`：拨号侧，`NewClient`、`Open(host, port)` 返回支持 `CloseWrite` 的 `Channel`。
- `RulePolicy`：基于白名单的代次策略，支持单 grant 撤销与整体代次失效。
- `NetDialer`：标准库 `net.Dialer` 适配器。
- `PausableDialer`：可暂停拨号器，拨号阻塞到 `DialCall.Release`，用于确定性地制造异步竞态。

## 测试

`go test -race ./...`

测试用可暂停拨号器与支持真实半关闭语义的内存管道，覆盖：同步拒绝、拨号失败后编号回收、双向中继与双向半关闭、接入前撤销（单 grant 与代次推进）、陈旧拨号回调无法接管复用编号、`Mux.Close` 取消在途拨号、多通道独立授权与回收次序。
