# 证书压缩字典隔离

TLS 服务端为减小握手而缓存压缩后的证书链，攻击者若能让不同租户共用同一个压缩字典或缓存条目，或声明一个巨大的解压长度，就能探测他人的证书内容或耗尽内存。为Go TLS 服务端写供握手路径调用的证书压缩包（RFC 8879）：只使用客户端 compress_certificate 扩展里列出的算法；缓存键为（算法, 字典 ID, 证书链字节的 SHA-256），字典只能由同一租户的 SNI 选取，来自别的租户的字典 ID 一律拒绝（字典为本题约定的扩展）；CompressedCertificate 中的 uncompressed_length 不得大于 2^24−1，解压结果长度必须恰等于该值，否则按 bad_certificate 处理；同一连接只允许发送一次压缩证书；压缩后不比原文小时改发未压缩证书。用算法未列出、跨租户字典、长度声明偏大和偏小、压缩反而变大验证。
