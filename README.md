# 多来源采集表的数值格式与计量单位不一致，单列样本可能同时符合两种解释

多来源采集表的数值格式与计量单位不一致，单列样本可能同时符合两种解释。写供Go入仓宿主调用的联合类型推断包，至多12列，每列给最多4种小数符、分组规则及有理单位倍率候选，整列必须使用同一候选；输入另给按业务键关联的最多18条行级线性校验关系，缺失值不作零，只有相关值齐备才约束。解析为精确有理数，返回全部满足关系的格式组合与每单元规范值；零解返回按条数最少、ID字典序决胜的冲突关系集，并给删除其中任一关系后的可行解释。预算耗尽返回未完成，不以首个可行解宣称唯一。用小表全组合枚举核对千分位歧义、不同单位、重复业务键冲突及不可判定的缺失列。

## 包 `taskpkg`

入口为 `Solve(*Input) (*Report, error)`，仅依赖标准库（`math/big` 做精确有理数运算）。

### 输入要点

- `Candidates`：至多 12 列，每列至多 4 个 `Candidate`，由 `Decimal`（`.`/`,`）、
  `Grouping`（`GroupNone/Comma/Dot/Space`）与有理 `UnitScale` 组成；整列在一次
  解释中只能选同一个候选。
- `Relations`：至多 18 条，两种形态：
  - `KeyCol < 0` 行内线性方程，`Coeffs` 为列系数，`RHS` 为常量，`RHSCol` 为可选
    右端取值列；不需要右端列时必须显式传 `NoRHSColumn`（-1），零值 0 表示第 0 列。
  - `KeyCol >= 0` 业务键等值，对同键多行要求参与列的非缺失取值彼此相等。
- 缺失单元为空串，永不按零处理；关系涉及的列任有缺失，该行/分组就跳过约束。
- `Budget <= 0` 不限预算；否则每评估一个格式组合、每做一次冲突子集可满足性检查计 1。

### 返回语义

- `StatusOK`：预算内枚举完毕，`Feasible` 给出全部满足关系的组合及每单元 `*big.Rat`
  规范值；`Classes` 按规范值矩阵归并等价类，`Undecidable` 列出存在多候选的列并区分
  是否真正改变取值。
- `StatusInfeasible`：零可行解。`Conflicts[0]` 是按“条数最少、ID 字典序”决胜的
  MUS，其 `Witnesses` 对冲突集内每条关系给出删除后的可行解释；若不存在满足全部
  其余关系的全局松弛，则 `ConflictOnly=true` 并给出仅满足冲突集其余关系的解释。
  若某列所有候选都无法解析，改由 `UnparseableColumns` 报告，不产生 MUS。
- `StatusIncomplete`：预算耗尽，已收集结果仅为部分结果，不能据此宣称唯一解释。

### 测试

`go test ./...` 以小表全组合枚举交叉核对千分位/欧陆小数歧义、单位倍率、重复业务键
冲突、全缺失不可判定列、MUS 字典序决胜、ConflictOnly 回退与预算中断。
