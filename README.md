# checksumdiff — 数据同步校验和实时比对器

源库与目标库一致性在线巡检器。采用**滚动 XOR 分桶校验和**（类 Merkle 树：
1024 个分桶为叶子，根签名由全部桶签名再哈希得到），在变更持续流动的同时
按主键分区持续增量维护两端数据摘要并比对，毫秒级发现丢数与数据篡改，
并精确定位到主键 ID。仅使用 Go 标准库。

## 原理

```
            Root 签名 (FNV-1a over 全部桶签名)
           /                                \
   Bucket 0 .. Bucket 1023          每个桶: { XOR(行哈希), Count(行数) }
           |
   Row.Hash() = FNV-1a(ID, Name, Balance, UpdatedAt, Version)
```

- **增量维护**：每次行变更只需 `XOR 旧哈希 ^ XOR 新哈希`，O(1) 更新桶签名，
  无需全量重算；Count 捕捉"增删哈希抵消"场景。
- **三级下钻**：先比根签名（O(1)）→ 失配则比 1024 个桶签名 → 仅对失配桶
  做行级 diff（O(桶内行数)），输出 `MISSING_IN_TARGET`（丢数）/
  `EXTRA_IN_TARGET`（多行）/ `MODIFIED`（篡改）及主键。
- **抗复制延迟**：单周期差异可能是复制中的瞬时状态，连续两个周期仍存在的
  差异才判定为真实不一致并告警。

## 运行样例

```sh
go run ./cmd/demo
```

模拟：20 万行初始全量同步 → 约 10 万条/秒变更流持续复制 → 运行中人为
篡改目标库某行单个字段 → 巡检器（50ms 周期）捕捉分桶 Checksum 失配并
定位主键。实测输出：


## 测试

```sh
go test -v ./...
```

覆盖：行哈希单字段敏感性、滚动 XOR 交换律/增删归零/更新计数、
两库一致判定、单字段篡改定位、丢数检测、多行检测，以及验收场景
`TestDetectTamperUnderContinuousFlow`（10 万行、变更持续流动中篡改
目标库单行单字段，要求 500ms 内定位主键，实测约 20ms）。

## 代码结构

- `row.go` — 行模型与行级哈希
- `index.go` — 滚动 XOR 分桶索引（Merkle 叶子层 + 根签名）
- `store.go` — 线程安全行存储，按桶组织，写入即增量更新校验和
- `inspector.go` — 巡检器：根比对 → 桶比对 → 行级定位
- `cmd/demo/main.go` — 端到端运行样例
