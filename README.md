# rulecache — 带缓存失效传播的规则结果计算器

高频查询场景下的规则结果缓存与失效控制器，仅使用 Go 标准库。

## 设计

- **规则求值与依赖追踪**：规则通过 `ReadTx.Get(table, key, field)` 读取外部
  维度表，求值期间的所有读取被自动记录为该缓存项的依赖。
- **精确反向索引**：引擎维护 `维度键 -> 缓存项集合` 的反向索引
  （`index`）以及 `缓存项 -> 维度键列表` 的正排依赖（`deps`）。
- **精准定向失效**：`SetDimension` 更新维度数据时，只剔除反向索引中
  依赖该维度键的缓存项，并同步清理正排/反向索引；其余缓存零失效。
- **缓存键**：规则 ID + 排序后的参数，同一 (规则, 租户, 用户, 月份)
  稳定映射到唯一缓存项。
- **并发安全**：读写锁保护，求值双检避免并发重复计算，`go test -race` 通过。

## 文件

- `engine.go` — 引擎：缓存、反向索引、失效控制器
- `rules.go` — 规则"VIP生日送积分"（`vip_birthday_points`）
- `engine_test.go` — 验收与单元测试
- `cmd/demo/main.go` — 运行样例（1 万用户预热，单用户等级变更）

## 运行

```sh
go test -race -v ./...
go run ./cmd/demo
```

## 验收边界

规则"VIP生日送积分"缓存了用户 U 的结果；当 U 的会员等级变更时，
系统仅令 U 的积分规则缓存失效，同一租户下其他成千上万用户的缓存
保持热态。见 `TestAcceptance_PreciseInvalidation`：预热 10000 个用户
缓存，变更 U1 等级后恰好剔除 1 项，其余 9999 项全部保持热态，
U1 重新计算得到新等级结果，全局未命中数仅 +1。
