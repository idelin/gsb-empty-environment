# objstore

一个带并发三色垃圾回收的持久化 Go 对象库：对象可被多个命名根引用，
事务原子地修改任意多个根与对象，回收器与事务并发执行。

## 设计

- **事务（store.go）**：`Begin`/`Put`/`SetRoot`/`DeleteRoot`/`Commit`。
  一次 Commit 先把整条记录追加到 WAL 并 fsync，再在 `Store.mu` 临界区内
  应用，因此 WAL 顺序与内存可见顺序一致，崩溃重放收敛到同一状态。
  Commit 前做引用完整性校验：任何指向不存在对象的边（根或对象引用）
  都会以 `ErrNotFound` 拒绝——否则事务可能把根挂到刚被清扫器回收的
  对象上，任何屏障都无法复活它。
- **三色 GC（gc.go）**：`RunGC` 与事务并发。标记期从所有根出发做
  灰栈遍历；清扫期逐个删除白色对象，每次删除先写 WAL 再在持锁状态下
  复核颜色后生效。
- **插入写屏障（Dijkstra）**：GC 活跃期间，Commit 创建的每条新边
  （根→对象、对象→对象）都会把目标染灰：标记期入灰栈被追踪，清扫期
  染灰即免于删除。周期内新建的对象不在颜色表中，视为隐式黑色（保留）。
  锁序恒为 `Store.mu` → `gc.mu`，标记循环不同时持有两者，无死锁。
- **崩溃恢复**：每条事务记录与每次 GC 删除都先落盘（fsync）后生效。
  清扫中途崩溃时，已记录的删除重放后仍然生效，未扫到的垃圾留待下一
  周期；重放遇到尾部撕裂写即停止，视为未提交。

## 测试

`go test -race ./...` 覆盖：多根原子事务、标记期/清扫期新增根与对象
引用的屏障交错、标记期移动根（浮动垃圾下一周期回收）、多 goroutine
事务与多轮 GC 并发压力（每轮校验根闭包完整）、崩溃重启重放、清扫中途
崩溃、悬空引用拒绝。
