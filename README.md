# replsim

单机日志复制模拟器：节点接收来自不同任期的追加请求，匹配前驱后截断
冲突后缀，并在状态持久化之后才确认追加。

## 规则

- 前驱匹配：`PrevIndex`/`PrevTerm` 必须命中本地日志，否则拒绝
  （`missing-predecessor` / `prev-term-mismatch`）。
- 冲突截断：同索引不同任期的条目触发截断，删除该索引起的未提交后缀
  后追加新条目。
- 已提交前缀不可截断：冲突落在 `commitIndex` 之内时拒绝
  （`committed-conflict`）。
- 旧任期拒绝：`Term < currentTerm` 的请求拒绝（`stale-term`）；更高任
  期先持久化再处理。
- 损坏检测：同索引同任期但内容不同，报告 `corruption`，日志不变。
- 先持久化后确认：`Store` 成功前绝不返回成功确认。
- 提交推进：`commitIndex = min(LeaderCommit, lastIndex)`，只前进不后退。

## 验证

- `node_test.go`：上述每条规则的单元测试，含重复投递幂等性与
  持久化失败不确认。
- `crash_test.go`：事件重放 + 崩溃切点。对混合脚本（重复消息、缺失
  前驱、冲突截断、提交推进、损坏与旧任期请求）枚举每一个持久化切点
  注入崩溃，从持久态恢复并重投在途请求，校验不变量：确认即已持久化、
  已提交前缀稳定、提交索引单调、崩溃不丢已确认的已提交条目。
