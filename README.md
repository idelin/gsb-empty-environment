调度一个同时挂载多个持久化卷声明（PVC）的 Pod 时，容器调度器的 `VolumeBinding` 插件必须把存储拓扑约束与节点 CSI 卷挂接配额作为一个整体联合求解：有的 PVC 已经绑定到特定可用区的静态 PV（直接锁死 Pod 可去的拓扑范围！），有的 PVC 属于 `WaitForFirstConsumer` 延迟绑定（需在候选节点所属拓扑内挑选合适的未绑定静态 PV，若无匹配静态 PV 则评估 StorageClass 的 `allowedTopologies` 是否允许在该节点拓扑动态供应！）；同时，每台节点上的 `CSINode` 对每种 CSI 驱动都有独立的**最大可挂接卷上限（`Allocatable.Count`）**——统计节点剩余挂接槽位时，若某块 PV 已经被该节点上另一个运行中的 Pod 挂接（如 `ReadOnlyMany` 或同节点 `ReadWriteOnce` 共享），再次被新 Pod 引用**不额外消耗**挂接槽位，而同 Pod 引用多个不同延迟绑定 PVC 时绝不可把同一块未绑定静态 PV 重复分配给两个 PVC！为集群调度器交付可导入的 Go 多卷 PVC 拓扑绑定与 CSI 配额校验包。输入为集群节点（含拓扑标签与各 CSI 驱动已挂接 PV 集合及 `Allocatable.Count`）、全部 PV（容量、访问模式、`storageClassName`、状态、CSI 驱动名、节点亲和拓扑 `nodeAffinity`）、StorageClass（绑定模式 `Immediate`/`WaitForFirstConsumer`、驱动名与 `allowedTopologies`）及待调度 Pod 的多 PVC 列表。规则：1）校验已绑定 PVC 的 PV 节点亲和是否全部兼容候选节点（任一不兼容即淘汰节点）；2）对同一 Pod 的全部未绑定 `WaitForFirstConsumer` PVC，在候选节点上执行无冲突静/动态联合绑定：优先为每个 PVC 匹配容量 `>= request`、访问模式超集、StorageClass 相同且拓扑兼容的最小容量可用静态 PV（当多 PVC 竞争同一有限静态 PV 集合时必须做精确二分图匹配而非贪心分配，避免错配导致本可静态绑定的卷被迫失败或动态创建！），无静态 PV 可配时回退校验 StorageClass `allowedTopologies` 决定动态供应；3）精确核算每种 CSI 驱动在候选节点上的新增唯一 PV 挂接数（排除该节点已挂接的同一 PV，计入新增静态与动态卷），超 `Allocatable.Count` 则淘汰节点；4）在全部可行节点上按静态匹配优先、最小容量浪费与节点名字典序确定性产出最终绑定方案。验收覆盖已绑定 PV 锁死可用区、多 PVC 竞争有限静态 PV 的二分图精确匹配、同节点共享已挂接 PV 不重复扣减 CSI 槽位、超 CSI 上限拦截以及静态回退动态供应拓扑校验。
