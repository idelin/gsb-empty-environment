# 覆盖语料事务合并

多个安全测试进程会同时提交具有相同覆盖的新样本。给Go模糊测试宿主写可导入的语料存储包，覆盖为边ID集合，目标是保留覆盖并优先较短样本，长度相同按内容摘要排序；每次变更原子发布一份不可变索引，崩溃恢复后索引不能引用缺失文件。用逐次写盘失败、重复摘要和并发压缩测试覆盖守恒；不要求求最小集合，但任何被删样本的边必须仍被覆盖。

## corpus 包

`corpus` 实现了上述语料存储：

```go
s, _ := corpus.Open(dir)          // 打开/恢复；多进程可同时打开同一目录（flock 串行化）
s.Add(sample, edges)              // 提交样本及其覆盖边集合；相同摘要自动合并边
s.Compact()                       // 贪心压缩：短样本优先，等长按摘要排序，覆盖严格守恒
s.Coverage()                      // 当前覆盖的边集合并集
s.Validate()                      // 校验索引不引用缺失文件
```

每次变更先落盘样本与元数据（fsync），再以 rename 原子发布一份不可变索引
（`index/<seq>.json` + `current` 指针）；压缩时先发布新索引再删除文件，
因此崩溃恢复后索引绝不会引用缺失文件。测试见 `corpus/corpus_test.go`，
覆盖逐次写盘失败、重复摘要与并发压缩下的覆盖守恒。
