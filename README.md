# gifcompose

缩略图服务要从动图中取任意一帧，但image/gif只返回原始帧块。给Go缩略图服务实现供取帧接口调用的动图帧合成包：按逻辑屏幕尺寸合成，正确处理处置方式1、2、3，越界帧裁剪，局部调色板和透明色只影响本帧，背景恢复为透明；随机访问第N帧时从最近可复用的完整画面开始重算并缓存。逐帧对比顺序合成与随机访问的结果。

## 用法

随机访问第 N 帧（缩略图取帧接口的推荐入口，带关键帧缓存）：

```go
g, err := gif.DecodeAll(reader)
// ...
comp, err := gifcompose.NewCompositor(g)
frame, err := comp.Frame(n) // *image.NRGBA，尺寸为逻辑屏幕大小
```

顺序流式合成（内存恒定，适合整图导出）：

```go
seq, _ := gifcompose.NewSequencer(g)
for {
    frame, err := seq.Next()
    if err == io.EOF {
        break
    }
}
```

一次性合成全部帧可使用 `gifcompose.CompositeAll(g)`。

## 语义

- 画布按 `gif.GIF.Config` 的逻辑屏幕尺寸创建，初始为全透明；零值配置时按首帧边界推导。
- 帧矩形与逻辑屏幕求交：部分越界裁剪、完全越界跳过，负偏移同样正确对齐。
- 处置方式：`0/1` 保留画面；`2` 把帧区域恢复为透明（背景索引无确定显示色）；`3` 恢复到该帧渲染前的完整画面；保留值 4–7 按浏览器惯例视为不处置。
- 每帧的局部调色板与透明索引只参与本帧像素的混合，不修改共享调色板，也不影响其他帧。
- `Compositor.Frame(n)` 从编号不大于 n 的最近可复用完整画面（处置 0/1 的帧快照，或透明初始画布）重放到第 n 帧，并把途经的可复用画面缓存起来；`ClearCache` 可清空缓存，`SnapshotStats` 可观察命中与重算次数。
- 所有返回的画面都是独立副本，可安全保留或修改；`Compositor` 内部带互斥，可并发调用。
