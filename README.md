# 802.11 分片安全重组（netsec）

针对分片聚合攻击（攻击者把不同密钥或明文的分片混入同一帧序号，诱导接收端
拼出伪造帧）的 C++17 重组包，可直接作为静态库链入 Wi-Fi 驱动。

## 安全策略

重组器按 802.11 序号把分片分组，对每组强制执行：

- 同一序号的加密分片必须使用同一密钥索引（`keyId`），不同密钥即整组丢弃；
- 加密分片的 PN 必须逐片恰好 `+1`，跳变、回退、相等都整组丢弃；
- 明文分片与加密分片不允许混合，出现即整组丢弃；
- 分片号必须从 0 开始连续；没有首片的“孤儿”续片直接拒绝；
- 首片重传会丢弃旧组后重建，避免新旧 PN/密钥状态混淆；
- 密钥重装（PTK/GTK/IGTK）或站点重新关联时调用 `clear()` 清空全部缓存；
- 缓存分片总数不超过 16（可配置），超限时淘汰最旧的整组（同组分片一起失效）。

纯明文多片帧不做 PN/密钥约束，但仍要求受保护属性一致、分片连续。
单片（非分片）帧直通，不占用缓存。

## 接口

- `netsec::FragmentReassembler`：核心类，`process(FragmentInput)` 喂入解密后的分片；
- `ReassemblyResult`：`completed` 时 `frame` 为完整帧，`rejected` 时 `reason` 给出原因；
- `clear()`：密钥重装/重新关联时清空缓存；
- `stats()`：返回接受分片、完成帧、丢弃/淘汰/清空组数等计数。

类本身不加锁，驱动应在 RX 串行化上下文中使用或自行加锁。

## 构建与测试

```sh
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

测试覆盖：PN 跳变/相等、明文与加密双向混合、换密钥后续片、密钥重装清空、
孤儿分片、分片号断号、16 分片上限淘汰，以及正常多片重组与单片直通。
