# cdc-masking

CDC 变更流的一致脱敏引擎。纯 Python 3.11 标准库实现，变更来自本地 JSON
夹具（事务 ID、表、主键、前后值、提交序号），不依赖任何消息平台。

## 设计

- `cdc_masking/policy.py` — 字段策略（`pseudonym` / `redact` / `passthrough`）、
  schema 注册表（字段敏感性、演进）、按提交序号排列的策略版本时间线、
  显式映射注册表（raw→token，按版本隔离）。热更新先把新版本的全量映射
  构建好再一次性安装，任何失败都不会改动旧版本：主外键及前后值映射
  原子迁移。
- `cdc_masking/engine.py` — 按事件的 `commit_seq` 解析"当时"的策略版本
  （删除事件只含旧键时也用事件时策略，绝不用当前密钥猜）。外键字段与
  被引用主键共享假名域，因此主外键映射稳定、可连接；同一值前后像映射
  相同（确定性 HMAC-SHA256）。所有错误（含意外异常）都被清洗为只含
  表/字段/事务/序号的 `MaskingError`，错误日志不落原值。
- `cdc_masking/replay.py` — 合成引用图回放：跨版本校验每个外键 token
  解析出的原值在被引表主键集合中存在；不可见（redact）字段不参与节点
  身份与边，带/不带不可见字段两次回放结果必须一致。校验失败时
  `VersionedOutput` 保留旧输出版本。
- 严格模式：schema 演进引入的敏感字段若无策略，热更新拒绝（保持旧版本），
  运行期事件同样被拒绝；非严格模式则降级为 redact。

## 运行

```sh
python3.11 run_sample.py                  # 运行样例（夹具驱动的完整场景）
python3.11 -m unittest discover -s tests  # 运行测试
```

样例场景：v1 脱敏 → schema 演进新增敏感字段 `phone` → 无策略的 v2 热更新
被拒 → 严格模式拒绝含 `phone` 的事件（错误路径无原值泄漏）→ v3 热更新
原子迁移映射 → 迟到的删除事件按事件时 v1 策略解析 → 跨版本回放校验 →
篡改事件校验失败、输出版本保持 v3。

## 目录

- `fixtures/` — schema、三个策略版本、变更事件流（本地 JSON）
- `tests/` — 19 个 unittest 用例（引擎一致性、严格模式、原子迁移、回放）
