多租户边缘计算宿主装载第三方 WebAssembly 模块时，若字节码验证器忽略不可达代码后的多态操作数栈、未校验 `memory` 偏移加法 33 位溢出或放过 `call_indirect` 签名索引失配，恶意模块可突破线性内存沙箱或触发间接调用类型混淆。为 Go 沙箱宿主实现可导入、直接解析原始 Wasm 二进制切片（MVP + 多表 + `bulk-memory` 子集）的静态安全校验与资源配额验证包，严禁依赖第三方 Wasm 解析库。组件从魔数与版本头起完整解码 LEB128 编码（严格拒绝超长非规范 LEB128 与越界段长度），按规范校验段顺序（Type/Import/Function/Table/Memory/Global/Export/Start/Element/Code/Data）及索引空间界限；核心指令类型与控制流检查器完整维护控制帧栈（`block`/`loop`/`if`/`else`/`end`）与多态操作数栈（`unreachable`/`br`/`br_table`/`return` 后的栈多态规则必须精确，防止伪造栈下溢或未消费残留值逃逸）。安全沙箱约束包括：强制线性内存最大页数不超过宿主上限（拒绝缺失 `max` 声明或超过 65536 页的内存）、检查所有 `load`/`store` 的对齐提示不得大于访问位宽的自然对数且静态 `offset + width` 在 32 位地址空间中须由运行时边界检查标记覆盖、校验所有 `call_indirect` 的表索引与函数签名索引存在且表元素类型为 `funcref`、禁止导入未在宿主白名单中的敏感能力函数并检验 `data`/`elem` 主动段初始化偏移不越界。用手工构造的合法模块与多态栈伪造、非规范 LEB128、非法对齐、`call_indirect` 签名错位、超限内存段恶意二进制样本实测拦截。
