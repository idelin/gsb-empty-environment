# treecolor — 树路径不同颜色数（带单点改色）

Go 库：树上单点改色 + 查询两点路径上的不同颜色数，颜色值可在任意修改中
全新出现（在线新增）。查询严格按操作序列中该时刻的颜色状态回答，
绝不使用最终颜色。

## 算法与复杂度

采用**离线带修改莫队算法**：

1. 欧拉序展开（每点入栈/出栈各出现一次，长度 `m = 2n`），配合
   `tin/tout` 区间 + 奇偶出现计数，把路径查询化为区间不同颜色数；
   LCA 用倍增预处理，非祖先情形单独补计 LCA 节点。
2. 莫队指针在 `(左端, 右端, 时间)` 三维上移动，块长取 `m^(2/3)`；
   时间维通过应用/撤销第 k 次改色实现，因此每个查询看到的就是
   它之前的修改序列，与最终颜色无关。

复杂度（n 个点，q 个查询，u 次修改，m = 2n）：

- 预处理：`O(n log n)`（倍增 LCA）+ `O(n)`（欧拉序）；
- 总计：`O((m + q) · m^(2/3))`，当 `q, u = O(n)` 时为 `O(n^(5/3))`，
  即每次操作均摊 `O(n^(2/3))`；
- 空间：`O(n log n + q + C)`，C 为出现过的颜色种数（坐标压缩）。

正确性性质：

- **根无关**：路径是无根树的固有属性，欧拉序只是表示方式；
  测试用多个不同根求解并断言答案一致。
- **同点路径**：`u == v` 时答案恒为 1。
- **颜色反复改回**：时间维撤销恢复被覆盖的颜色，改回旧色后
  查询结果与历史时刻一致。
- **确定性**：答案按查询输入顺序输出，排序比较器全序且无随机性，
  重复运行结果逐位相同。

## 用法

```go
answers := treecolor.Solve(n, edges, initColors, ops, 0) // 与 naive 对照: SolveNaive
```

命令行演示：

```
go run ./cmd/treecolor <<'IN'
3
0 1
1 2
1 2 3
4
Q 0 2
C 1 1
Q 0 2
Q 1 1
IN
# 输出: 3 2 1
```

```
go test ./treecolor/
```
