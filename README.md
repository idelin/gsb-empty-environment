构建机从多个代理拿到同一 Go 模块，go.sum 相同却不能证明各机房依赖的是一致的校验日志。实现给 Go 构建宿主导入的模块准入包。输入为模块身份与版本、内容摘要、已验签的检查点、Merkle 包含与一致性证明、见证者签名，哈希用 SHA-256，叶与内节点分别加 0 和 1 前缀，非满树按小于长度的最大二次幂分割。根和大小一起标识检查点，且所有见证者签名必须绑定来源域标签、树大小和根摘要以防跨树重放。客户端保存上次接受的检查点集合，可能互不可比；不得凭树更大就覆盖旧根。新模块发布需有从每个已承诺检查点到同一目标的有效一致性证据链，以及该目标上的模块叶包含证明；每条证据边由不同管理域达到给定门槛，别名见证者按实际域去重。允许尚缺中间边的乱序到达，缺证时报未知；同大小异根返回已观察分叉。由宿主给若干候选补证请求，每项带可覆盖的边、费用及提供者，同一提供者在一次计划中有获取次数上限。对仍有可能准入的目标返回最小费用的补证计划，不能假定尚未取得的签名已经有效。小规模用全子集核对费用，另测一条共享证明边同时连接多个根、缩短证明、非满树、同一域重复签名和磁盘提交失败前的旧信任状态。
