LSM 引擎支持 `DeleteRange(start, end)` 后，一个大范围墓碑可能在压实中被拆成多段并跨越多个 SST 文件边界；当同时存在多个活跃读快照与新旧点写交替出现时，压实器若把仍在旧快照之前的范围墓碑过早丢弃，或错把比范围墓碑更新的点写误删，就会造成历史读视图损坏或数据复活。为存储引擎压实层交付可导入的 Go 合并与裁剪包。输入为待压实的多层有序点记录流（`Key`、`Seq`、`Kind`: Put/PointDelete、`Value`）、重叠范围墓碑集合（左闭右开 `[Start, End)` 及 `Seq`）、当前升序活跃快照序号列表 `snapshots`，以及布尔标志 `isBottommost`（是否最底层压实且下层无键重叠）。规则：将所有活跃快照切分为若干可见条带（`(-inf, s0]`, `(s0, s1]`, ..., `(sk, +inf)`）；对每个点记录，若同条带内存在覆盖其键且序号严格更大的范围墓碑或点记录，则该点记录可丢弃；若某点写序号大于覆盖它的范围墓碑，该点写不受该墓碑影响；合并输出的范围墓碑须按端点切分为互不重叠的碎片并仅保留各条带内覆盖该区间的最大序号墓碑，消除冗余低序号范围覆盖；仅当 `isBottommost` 为真且记录或碎片序号不高于最老快照（或无快照）时，才可彻底清除点墓碑与范围墓碑，否则必须保留以遮蔽更低层旧数据。验收覆盖同一键在跨快照条带中被“旧 Put -> RangeDelete -> 新 Put -> 新 RangeDelete”交错覆盖、重叠范围墓碑碎片化拆分、最底层与非最底层压实墓碑留存差异，以及压实前后对任意活跃快照点查与范围扫描结果逐键一致。
