API 网关与 CDN 边缘节点在动态生成 CORS（Fetch Standard）响应头时，若直接反射请求 `Origin` 或用宽松子串/前缀匹配（如 `origin.startsWith("https://trusted.com")` 放过 `https://trusted.com.evil.com`）、允许 `Origin: null` 配合 `Access-Control-Allow-Credentials: true`（被沙箱 `<iframe sandbox>` 利用窃取用户敏感数据），或返回动态 `Access-Control-Allow-Origin` 却遗漏 `Vary: Origin` 导致共享 CDN 缓存把 A 站点的授权响应投毒给 B 站点，攻击者可跨站窃取全量已登录接口数据。为 TypeScript 网关安全宿主实现可导入的零外部依赖 CORS 预检/实际请求策略决策与响应头安全审计组件。组件严格实现：（1）请求 `Origin` 规范化与精确白名单匹配：拒绝多值/重复 `Origin` 头、硬拒绝 `null` 源（尤其携带凭证模式）、按精确 `(scheme, host, port)` 三元组比对预注册白名单（彻底阻断前缀/后缀/正则点号未转义绕过及 `http:` 降级）；（2）预检（`OPTIONS`）严格门禁：校验 `Access-Control-Request-Method` 与 `Access-Control-Request-Headers`（大小写不敏感逐项校验）均严格落入白名单、拒绝在 `Allow-Credentials: true` 时输出任意通配符 `*`（含 `Allow-Origin`/`Allow-Methods`/`Allow-Headers`/`Expose-Headers`），并限制 `Access-Control-Max-Age` 上限；（3）响应头与缓存防投毒审计：凡非静态 `*` 的动态 `Access-Control-Allow-Origin` 响应，强制要求 `Vary` 头包含 `Origin`（合并已有 `Vary` 值不覆盖），并提供审计入口扫描现网响应头检出凭证+通配、`null` 源放行、子域后缀绕过与缺失 `Vary: Origin` 缓存投毒缺陷。附 `trusted.com.evil.com` 绕过、`null`+凭证拒绝、缺失 `Vary: Origin` 检出与合法预检测试。
