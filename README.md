Kubernetes 控制器高可用领导者选举（`client-go/leaderelection` Lease 协议）在节点时钟不同步、网络分区与进程卡顿（GC STW）交错时，极易发生双主脑裂：1）**严禁信任对端墙上时钟（Clock Skew Immunity）**：候选节点绝不能用“本机当前时间减去租约里的 `RenewTime`”来判断租约是否过期（因为两台主机墙上时钟可能相差数分钟！）——规范要求每个节点必须用**本地单调时钟（Monotonic Clock）**记录自己首次观察到当前 `(HolderIdentity, AcquireTime, RenewTime, LeaseTransitions)` 完整快照的本地时刻 `observedTime`；仅当本地单调时钟已流逝 `>= LeaseDuration` 且期间上述字段均未发生变化（或租约被原主显式清空释放！）时，才判定租约已过期允许发起 CAS（基于 `ResourceVersion`）抢占并递增 `LeaseTransitions`！2）**现任 Leader 的 `RenewDeadline` 自杀退位与 Fencing Token**：现任 Leader 每隔 `RetryPeriod` 尝试 CAS 续约；若因网络分区或 API 延迟导致自上次成功续约起本地单调时钟流逝超过 `RenewDeadline`（`RetryPeriod < RenewDeadline < LeaseDuration`！），或者在续约时发现 `HolderIdentity` 已被他人抢占，Leader 必须立刻触发 `OnStoppedLeading` 停止对外写操作！同时为下游受保护存储提供单调递增的 Fencing Token（取自 `(LeaseTransitions, AcquireSeq)`），拦截任何迟到旧主携带过期 Fencing Token 的写入请求；3）**优雅交接（`ReleaseOnCancel`）**：当现任 Leader 收到优雅退出信号时，先停止业务再以 CAS 清空 `HolderIdentity` 并将 `LeaseDurationSeconds` 置为 0，使其他候选者在下一次 `RetryPeriod` 立刻接管而无需苦等完整 `LeaseDuration`！为高可用控制面交付可导入的 Go 单调时钟 Lease 选举、网络分区/时钟偏斜仿真与 Fencing 防脑裂验证包。验收覆盖跨节点 +/-60 秒墙上时钟偏移下绝不误抢占、单调时钟满 `LeaseDuration` 精准抢占、分区超时 `RenewDeadline` 自动退位、迟到旧主写入被 Fencing Token 拦截以及 `ReleaseOnCancel` 零等待秒级切换。
