# undocrdt — 可逆编辑撤销树（Undo/Redo CRDT Graph）

协同编辑场景下的分布式撤销树（Go，仅标准库）。每个用户可以单独撤销/重做
自己的操作，而不会破坏其他并发协作者的输入；撤销与重做通过向操作图追加
**反向补偿节点**（Delete/Restore）实现，历史永不被改写，拓扑有效性始终成立。

## 设计

- **序列 CRDT（RGA 风格）**：每个字符是带有全局唯一 ID `(site, seq)` 和
  左源指针 `After` 的图节点。并发插入按 `(seq, site)` 确定性排序，任意
  投递顺序下各副本渲染结果一致。
- **墓碑删除**：删除只是把字符标记为不可见，节点仍留在图中，后续并发
  插入到其后的字符不受影响。
- **撤销树**：Undo/Redo 生成新的补偿操作节点，携带 `Undoes` 边指向被
  逆转的节点，形成只增不减的撤销树；补偿节点本身就是普通 CRDT 操作，
  与其他协作者的并发编辑可交换。
- **每站点撤销栈**：每个副本只追踪本站点的用户操作，因此 A 的 Undo 只
  逆转 A 自己的编辑。
- **因果缓冲**：乱序到达的操作（如补偿先于被撤销的插入）会被缓冲，待
  依赖到齐后自动应用。

## 验收场景

用户 A 输入 `hello`，用户 B 插入 `!`；A 执行 Undo 撤回 `hello`，文档保留
B 的 `!`；A 再次 Redo 后无缝恢复为 `hello!`。见 `TestAcceptance`。

## 运行

```sh
go test ./... -v     # 测试（含验收边界）
go run ./cmd/demo    # 运行样例，打印每一步双副本状态与撤销树
```

## 文件

- `op.go` — 操作节点类型（Insert/Delete/Restore）与撤销树边
- `doc.go` — 副本：CRDT 应用、Undo/Redo、收敛渲染、因果缓冲
- `doc_test.go` — 验收与并发收敛测试
- `cmd/demo/main.go` — 可运行样例
