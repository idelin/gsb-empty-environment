多租户集群在单个命名空间内同时配置多条带作用域（`Terminating`、`NotTerminating`、`BestEffort`、`NotBestEffort`、`PriorityClass` 集合）的资源配额（ResourceQuota），同一 Pod 可能同时命中多条配额；当高优 Pod 申请通过抢占驱逐同空间低优 Pod 来腾出配额时，若没有原子净增量核算，抢占前会因超额被拒、抢占后又可能因多作用域交叉配额依然不足而白白杀掉低优 Pod。为多租户准入控制器交付可导入的 Go 配额账本包。输入命名空间内全部 ResourceQuota（每条含作用域合取条件与 CPU/Mem Request/Limit、Pod 数硬上限）、现有 Pod 集合（含 QoS 类别、是否带 `activeDeadlineSeconds`、PriorityClass 与资源向量）及准入请求（新建 Pod、原地调整资源、终止释放、或带候选牺牲集合的原子抢占准入）。规则：按 Kubernetes 语义严格判定每个 Pod 命中的全部配额集合（`BestEffort` 仅当所有容器均未设 Request 与 Limit；`Terminating` 仅当设了 `activeDeadlineSeconds >= 0`）；普通准入须满足全部命中配额；带牺牲候选的抢占准入须先验证只驱逐严格低优先级 Pod 的最小牺牲子集能否使全部配额（含受新 Pod 命中和原牺牲 Pod 释放后跨作用域变化影响的每条配额）同时满足，满足才原子提交，否则一个低优 Pod 都不杀并指出卡死的具体配额与资源项。验收用全子集对照验证不超额且无白杀，覆盖高优 Pod 与低优 Pod 落在不同 `PriorityClass` 作用域导致杀低优也腾不出高优配额、BestEffort 与 NotBestEffort 互斥作用域，以及单条配额多资源同时临界。
