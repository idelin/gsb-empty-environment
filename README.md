# bridge — 跨协议版本离线桥接器

仅用 Go 标准库实现的 v1/v2 协议离线桥接器。输入为声明字段 ID、类型、
必需性与迁移规则的 schema，编译出双向转换计划，按 epoch 热更新，支持
任意分块的字节输入。

## 结构

- `wire.go` — 帧编码（1 字节版本 + 4 字节长度 + 字段序列）、流式 `Parser`。
  解析严格区分 `ErrNeedMoreData`（合法前缀，缺数据）与 `ErrBadData`
  （坏数据）；所有长度在分配前先对照 `Limits` 额度检查。
- `schema.go` — `Schema`/`FieldDef`：字段 ID、类型（varint/bytes/string）、
  必需性、扩展载体字段、默认值迁移规则。
- `plan.go` — `Compile` 编译单向计划，字段分为三类：无损（`ActCopy`，
  改名不改 ID 仍属此类）、需保留扩展（`ActExtend`）、不可表示（`ActDrop`）。
  目标端新增的必需字段若源端无法提供且无默认值规则，编译直接失败，
  协商随之拒绝。计划与计划集均有 SHA-256 摘要。
- `convert.go` — 原子转换：先完整构建目标帧，出错返回 nil，绝不发布
  半转换帧；未知字段原始字节经扩展载体逐字节保留，回到认识它的版本时
  原样恢复；扩展条目与真实字段冲突时真实字段优先并记入报告；
  `Diff`/`FormatDiff` 生成双向往返差异报告。
- `bridge.go` — `Bridge` 持有当前计划集与 epoch；`HotReload` 只影响新
  epoch，帧的第一个字节到达时绑定（epoch, 计划集），进行中的分块帧在
  新 schema 发布后完成仍按旧计划转换；`Negotiate` 校验对端计划摘要。
- `demo.go` + `cmd/demo` — 可重放样例，输出确定性日志。

## 运行

```sh
go test ./...     # 全部测试
go run ./cmd/demo # 可重放样例（输出恒定）
```

## 测试结果

```
ok  	bridge	0.430s
?   	bridge/cmd/demo	[no test files]
```

14 个测试全部通过，覆盖：计划三分类、改名不改 ID 的无损性、v2 新增
必需字段拒绝协商、摘要绑定、未知字段往返不丢、扩展字段冲突、资源超限
（帧长/字段长/字段数均在分配前拒绝）、缺数据与坏数据区分、逐字节分块、
热更新 epoch 绑定（旧 epoch 分块帧按旧规则完成）、失败不发布半转换帧、
迁移环收敛、双向往返差异报告、样例可重放性。
