Kubernetes Gateway API（`Gateway` + `HTTPRoute` + `ReferenceGrant`）相比旧版 Ingress 引入了严格的多租户跨命名空间安全边界与确定性冲突裁决，四类规范条款缺一不可：1）**Listener 与 HTTPRoute 主机名交集计算**：Listener 与 Route 均可声明多个精确主机名（`api.example.com`）或单层左通配泛域名（`*.example.com`，注意按规范 `*.example.com` 匹配 `a.b.example.com` 但**绝不**匹配裸域 `example.com`！）；二者成功绑定（Attached）的前提是 Listener 的 `allowedRoutes.namespaces`（`Same`/`All`/`Selector`）允许该 Route 所在命名空间、且双方主机名列表存在非空交集（若一方未填 hostname 则视为全匹配，交集取更具体一方！）；2）**跨命名空间后端引用与 `ReferenceGrant` 单向授权**：当 `HTTPRoute` 的 `backendRef` 指向其他命名空间的 `Service` 时，目标命名空间内**必须**存在至少一条 `ReferenceGrant` 其 `from` 匹配 `(group, kind, routeNamespace)` 且 `to` 匹配 `(group, kind, serviceName 或空名通配全部)`；缺少授权时绝不可静默丢弃整条路由，必须将未授权 `backendRef` 标记为 `RefNotPermitted` 并在路由命该权重分片时返回确定性 `500` 状态码（其余已授权分片按原权重继续生效！）；3）**确定性路由优先级与冲突裁决**：匹配顺序严格遵循：精确主机名优先于泛域名（多泛域名按后缀长度降序！）-> 路径匹配 `Exact` > 最长前缀 `PathPrefix`（按路径段边界匹配，`/v1` 不匹配 `/v10`！）> `RegularExpression` -> 最多精确 Header 匹配数 -> 最多精确 QueryParam 匹配数 -> 显式 Method 匹配；若两条规则以上维度全部打平，严格按**最早 `creationTimestamp` 胜出，时间相同再按 `namespace/name` 字典序升序胜出**！4）**权重流量切分与无效后端合并**：对同规则多 `backendRef` 按非负整数权重归一化（权重为 0 的后端不分配流量；全部权重之和为 0 时直接返回 500），支持基于请求键的确定性分流与精确状态报告（`Accepted`/`ResolvedRefs` Condition 与 `attachedRoutes` 计数）。为服务网格控制面交付可导入的 TypeScript Gateway API 编译与路由裁决引擎。验收覆盖泛域名交集（含裸域排除）、`allowedRoutes` 三模式、`ReferenceGrant` 缺失局部 500 隔离、七级匹配优先级含 `/v1` vs `/v10` 路径段边界以及 `creationTimestamp` + `namespace/name` 冲突裁决。
