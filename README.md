多租户大模型推理服务在单张 GPU 上并发服务数十个 LoRA 适配器，显存仅能同时驻留 K 个适配器槽位，且单步融合核最多支持 A ≤ K 个不同活跃适配器；正在解码的请求会 Pin 住其适配器槽位直到生成结束，若准入调度随意拉入冷门适配器占满槽位，不仅频繁触发昂贵的 PCIe 换入换出，甚至会把高优请求堵死在显存外。为多 LoRA 推理调度器交付可导入的 Go 槽位与组批调度包。输入显存适配器总槽位 K、单步最大批请求数 B、单步最大活跃适配器数 A、当前驻留槽位列表（含最后使用步号）以及按迭代步到达的请求队列（每请求含所需适配器 ID、优先级、需执行步数，支持同一请求用基础模型 `adapter=''` 不占槽位）。每迭代步规则：(1) 所有已开始且未完成的运行中请求必须继续保留在批内并 Pin 住其适配器（不可抢占已跑请求，确保槽位不泄漏）；(2) 在剩余批容量与剩余活跃适配器预算内，优先挑选可与当前已驻留适配器直接复用（零换入代价）的最高优等待请求，其次才在存在未 Pin 可驱逐空闲槽位时按 LRU 驱逐并加载新适配器，绝不驱逐 Pin 计数 > 0 的槽位；(3) 请求在最后一步完成后立即递减其适配器 Pin 计数（减至 0 仍留驻显存缓存供后续步复用，直至被 LRU 驱逐）。验收用多租户交错请求序列核对全部不变量（每步活跃适配器 ≤A、驻留槽位 ≤K、每适配器 Pin 数与存活请求数严格相等、总换入次数与确定性策略一致），覆盖满 Pin 阻塞冷适配器准入但放行同适配器热请求与基础模型请求、释放 Pin 后次步 LRU 精准驱逐最久未用槽位，以及单步同时多个新请求共享同一未加载适配器只计一次加载。
