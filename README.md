# corputrim — 语料裁剪器

从一组带**覆盖边**、**执行成本**和**失败类别**的输入中选出保留集，要求：

1. 保留集覆盖所有输入观察到的全部覆盖边；
2. 保留集覆盖所有输入观察到的全部失败类别（每类至少保留一个）；
3. 在此前提下，先使**保留样本数最少**，再使**总执行成本最小**（字典序）。

输入最多 30 个，程序给出**精确解**以及独立的**下界**作为最优性证书。
内容重复的输入先按内容合并：覆盖边与失败类别取并集（不丢失各自观察到的覆盖），成本取最小值。

## 构建与使用

```sh
go build -o corputrim .
./corputrim -f input.json          # 或 cat input.json | ./corputrim
```

参数：`-f` 输入文件（默认 stdin）、`-o` 输出文件（默认 stdout）、`-compact` 输出紧凑 JSON。

## 输入格式

JSON 数组，或含 `inputs` 数组的对象。每个输入：

```json
{
  "id": "fuzz-01",            // 可选，缺省自动生成
  "content": "AAAA",          // 输入内容，重复判定依据
  "cost": 12,                 // 非负整数执行成本
  "edges": ["e1", "e2"],      // 观察到的覆盖边
  "failure": "heap-overflow"  // 可选失败类别；也可用 "failures": [...] 
}
```

## 输出格式

```json
{
  "selected": [
    {"id": "fuzz-03", "merged_ids": ["fuzz-04"], "cost": 4,
     "edges": ["e3", "e4", "e5"], "failures": ["heap-overflow"]}
  ],
  "num_selected": 3,          // 保留样本数（第一目标）
  "total_cost": 17,           // 总成本（第二目标）
  "lower_bound": {"min_inputs": 3, "min_cost": 10},
  "optimal": true,            // 解经分支定界证明最优
  "duplicates_merged": [{"kept": "fuzz-03", "merged": "fuzz-04"}],
  "num_requirements": 7,      // 需求总数 = 覆盖边数 + 失败类别数
  "search_nodes": 3
}
```

`lower_bound.min_inputs` 不超过最优保留数，`lower_bound.min_cost` 不超过最优成本；
当 `min_inputs == num_selected` 时下界即构成最优性的完整证书。

## 算法

- **合并**：按 `content` 分组，覆盖边/失败类别取并集，成本取最小值。
- **需求全集**：所有覆盖边 ∪ 所有失败类别，编码为位集。
- **归约**：必选输入（某需求仅它能覆盖）反复提取；被支配输入（覆盖子集且成本不更低）删除，迭代至不动点。
- **分支定界**：按"覆盖候选最少的需求"分支，候选按边际覆盖降序、成本升序展开；搜索中同样做必选提取。
- **下界剪枝**：
  - packing 界：贪心构造两两不能被同一候选覆盖的需求集合，其大小即下界；
  - 覆盖界：⌈未覆盖需求数 / 单候选最大覆盖数⌉；
  - 成本界：还需 k 个输入时，额外成本 ≥ 剩余候选中最便宜的 k 个之和。
- **报告下界**：在合并后的完整实例上独立计算，与精确解一同输出。

30 个输入在普通实例上毫秒级求解；最坏情况仍是指数级（集合覆盖 NP-hard），
但归约与下界剪枝足以应对该规模。

## 测试

```sh
go test ./...
```

包含单元测试（重复合并并集、失败类别保留、字典序目标、下界有效性）以及
与暴力枚举对拍的随机测试（300 组随机实例，验证精确解与下界）。
