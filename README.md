# regex_engine：显式字母表上的教学级正则引擎

Python 3.11，仅标准库 + unittest，不使用任何现成正则/自动机库。
字母表与转移结构全部显式构造。

## 功能

- 语法：连接、并 `|`、星号 `*`（外加语法糖 `+` `?`）、字符类
  `[abc]`/`[^a]`/`[a-z]`/`.`、括号捕获、`()` 空串、`[]` 空语言。
- 解析：递归下降，AST 节点与语法错误均保留源码位置（`Span` / `ParseError.pos`）。
- 编译：Thompson 构造 epsilon-NFA，捕获以标签边（TAG）挂在 NFA 上。
- 确定化：按需（懒惰）子集构造；`max_states` 限制状态膨胀，
  `cache_size` 限制转移缓存（LRU 驱逐）。
- 匹配：一次性 `search`/`findall`，以及分块流式 `feed`/`finish`，
  实现最长匹配等待。
- 参考实现：`regex_engine/reference.py` 为独立的 AST 回溯匹配器，
  测试用它在小字母表上穷举短字符串交叉验证。

## 匹配语义（确定的优先规则）

1. 最左：从最小起始位置匹配；
2. 最长：该起始位置取最长终点（流式模式因此等待更多输入再提交）；
3. 优先级：达到最长终点的路径中，交替分支按书写顺序、星号贪婪，
   取第一条路径的捕获；循环捕获组取最后一次迭代。

空串循环规则：星号首次迭代允许为空（之后循环必须结束）；非首次的
空迭代在 NFA 上必然重复经过同一 `(状态, 位置)`，被简单路径约束排除。
因此 `(a*)*`、`(()*)*` 等嵌套星号不死循环，主引擎与参考实现语义一致。

## 标签为何不会在状态合并时丢失

DFA 状态是 NFA 状态的集合并集，不携带标签；标签只存在于 NFA 边上。
DFA 仅用于判定接受与定位最长终点，随后在原 NFA 上按优先级顺序做
带备忘的深度优先搜索，重走消费该区间的路径并收集标签事件
（`Regex._recover`）。因此确定化合并多少状态都不影响捕获。

## 资源额度

- `max_states`：限制整个运行期出现过的不同 NFA 状态集合数。超限抛
  `BudgetExceeded`；`findall`/流式接口将其标记为 `incomplete=True`
  并保留已确认的正确前缀结果，绝不返回错误自动机。
- `cache_size`：转移缓存 `(dfa状态, 字符) -> dfa状态` 的 LRU 上限。
  缓存是纯函数记忆化，驱逐后按需重算，语义不变
  （`tests/test_budget.py` 用 `cache_size=1` 对比验证）。

## 运行

```bash
python3.11 demo.py                 # 运行样例
python3.11 -m unittest discover -s tests -t . -v   # 测试
python3.11 repro.py '(a|ab)(b?)' 'ab' 'ab'         # 独立复现反例
```

## 测试结果

43 个测试全部通过（约 4 秒），包括：

- 解析器：源码位置、字符类、转义、错误位置、空串/空语言区分；
- 基本匹配：优先级、捕获边界、嵌套星号终止、标签在 DFA 合并后保留；
- 流式：最长匹配等待、任意分块不变性、匹配间状态恢复、绝对偏移；
- 预算：超限标未完成且部分结果正确、预算跨调用累计、LRU 驱逐语义不变；
- 穷举对拍：39 个精选模式 × 短字符串全集、150 个随机生成模式 ×
  短字符串全集、随机分块下流式与一次性结果一致。

样例输出见 `demo.py` 的运行结果（嵌套星号终止、分块等待、
预算超限标记、驱逐一致性等均有演示）。
