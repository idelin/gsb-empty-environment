# 积分兑换规划器

给定有限时段、分批到期的积分和每个时段库存有限的兑换项，求总兑换价值最高的兑换方案。

## 规则模型

- **批次（Batch）**：积分按批次管理，每批有来源（source）、数量和到期时段，时段结束时未用完的积分计入到期损失。
- **兑换项（Offer）**：挂在某个时段上，有单份积分成本、单份价值、库存上限，以及可选的返还积分。
- **返还积分**：兑换后按份返还，**下一时段才到账**，因此同一时段内不存在"兑换 → 返还 → 再兑换"的循环套利；最后一个时段产生的返还直接作废并单独上报。
- **来源限制**：兑换项可通过 `allowed_sources` 限定允许支付的积分来源（空 = 不限）；返还积分自带来源（默认 `rebate`），同样受限。

## 算法

1. **时段间**：带记忆化的深度优先搜索。状态 = (当前时段, 各批次剩余量)，每个时段枚举所有兑换项的份数组合（受库存与可用积分上界剪枝），取后续总价值最大者。
2. **时段内支付**：对每个兑换组合，用最小费用最大流把所需积分分配到批次上——批次边费用取到期时段，保证在所有可行支付方案中优先消耗最早到期的积分（FEFO），最小化到期损失；来源限制即批次→兑换项的边是否存在。
3. **返还**：时段末按兑换份数生成返还批次（id 形如 `rebate#<到账时段>:<兑换项>`），加入下一时段状态。

状态数超过 `maxStates`（默认 50 万）时搜索截断并在结果中置 `truncated: true`。

## 使用

```sh
go run . examples/input.json          # 文本报告
go run . -json examples/input.json    # JSON 输出
cat input.json | go run .             # 从标准输入读取
go test ./...                         # 运行测试
```

## 输入格式

```json
{
  "periods": 3,
  "batches": [
    {"id": "b1", "source": "creditcard", "amount": 600, "expire_period": 1}
  ],
  "offers": [
    {"id": "coffee", "period": 1, "cost": 100, "value": 130,
     "rebate": 20, "rebate_source": "rebate", "rebate_expire_period": 3,
     "inventory": 5, "allowed_sources": ["creditcard", "rebate"]}
  ]
}
```

`rebate_source` 默认为 `"rebate"`，`rebate_expire_period` 默认为最后一个时段，`allowed_sources` 缺省表示不限来源。

## 输出

- 总兑换价值、总消耗积分、到期损失、返还作废；
- 每个时段：返还到账、兑换明细（份数/消耗/价值/返还）、**批次扣减**（哪个批次为哪个兑换项支付了多少积分）、**到期损失**（哪个批次损失了多少积分）。
