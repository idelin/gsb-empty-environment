现代 SQL 优化器必须把任意嵌套的相关子查询（Correlated Subquery）重写为可被哈希/归并连接高效执行的非相关计划，但朴素重写极易踩中三类经典语义炸弹（**`COUNT` 空组 Bug、`NOT IN` 三值 `NULL` 陷阱、以及复杂嵌套条件下的关联依赖下推**）；请按 Neumann & Kemper 通用去相关化（General Unnesting）框架实现关系代数重写与执行验证核：1）**Dependent Join（`⋈_dep`）识别与去重域提取（Domain `D`）**：将外层查询与含自由关联变量的任意子查询统一建模为 `T1 ⋈_dep T2`，先提取外层被引用关联列的去重集合 `D = distinct(π_corr(T1))`，把 `D` 沿子查询算子树逐层下推穿过 `Filter`、`Project`、`Join`、`GroupBy/Aggregate`、`Union` 与 `Limit`，直至彻底消除内部对外部变量的自由引用，将 `⋈_dep` 转化为普通 `Left/Inner/Mark/Single Join`；2）**`COUNT` 空组 Bug 精准修正**：对标量聚合相关子查询（如 `SELECT a, (SELECT COUNT(*) FROM S WHERE S.x = R.x) FROM R`），当某外层行在 `S` 中无匹配行时，外连接填充的 `NULL` 绝不可让 `COUNT(*)` 错算为 `1`（必须通过 `LeftOuterJoin` + `COUNT(non_null_probe_col)` 保证返回 `0`！），而 `SUM`/`AVG`/`MAX`/`MIN` 在无匹配行时仍须返回 `NULL`；3）**`MarkJoin` 与 `IN`/`NOT IN` 三值 `NULL` 语义**：将 `EXISTS`/`NOT EXISTS`、`x IN (subq)`、`x NOT IN (subq)` 及任意比较量词 `= ANY` / `<> ALL` 统一编译为输出三值布尔标记列 `{TRUE, FALSE, UNKNOWN}` 的 `MarkJoin`——当 `x NOT IN (SELECT y FROM S WHERE ...)` 中外层 `x` 为 `NULL`（且子查询非空！）或子查询结果包含任一 `NULL` 时，标记必须为 `UNKNOWN`（在 `WHERE` 中被过滤掉，绝不可误判为 `TRUE`！），而子查询为空集时即便 `x` 为 `NULL` 也必须返回 `TRUE`！4）**`SingleJoin` 标量子查询基数检查**：标量相关子查询在运行时若对任一外层行产出超过 1 行，必须抛出明确的运行时基数违例错误（产出 0 行则补 `NULL`！）。为查询优化器交付可导入的 TypeScript 通用去相关化重写器与参考嵌套执行对照引擎。验收覆盖任意深度嵌套相关子查询去相关化后与逐行嵌套参考求值逐行等价、空组 `COUNT(*)=0` vs `SUM=NULL`、`NOT IN` 含 `NULL`（含空子查询豁免！）三值逻辑对照、带 `OR` 析取条件的 `MarkJoin` 以及 `SingleJoin` 多行运行时报错。
