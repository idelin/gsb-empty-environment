在多路 NUMA 宿主机上，Kubelet 的 `CPU Manager (static)` 策略必须与 `Topology Manager`（`none`/`best-effort`/`restricted`/`single-numa-node` 四策略）协同工作，才能在保证延迟敏感容器独占物理核的同时避免跨 NUMA 访存抖动，四处规范细节极易写错：1）**`reservedSystemCPUs` 保留隔离与共享池维护**：宿主机按 `(Socket -> NUMA Node -> Physical Core -> Logical Sibling CPUs)` 建模；初始化时从全局可分配集扣除 `reservedSystemCPUs`（至少保留 1 核），剩余全部进入默认共享池 `defaultCPUSet`；仅 **Guaranteed QoS 且 CPU request 为正整数** 的容器（不含一次性 Init 容器在主容器启动后仍占核——Init 容器释放的独占核必须归还池中，但可重用型 Init 容器需先被计入独占！）才从 `defaultCPUSet` 划出独占核；Burstable 与 BestEffort 容器统一留在 `defaultCPUSet`；2）**物理核与超线程（SMT Sibling）整体优先分配**：为独占容器分配 `N` 个逻辑核时，当 `N >= 2` 且宿主机开启超线程，必须优先分配完整空闲物理核（成对分配同核 Sibling），避免把不同容器的独占线程塞到同一物理核争抢执行单元；仅在无完整空核时按 NUMA 局部性回落至散落逻辑核；3）**Topology Manager 跨资源 Hint 笛卡尔积与四策略准入**：联合 CPU 与外设设备（如 SR-IOV 网卡 / GPU）两类 Hint Provider 上报的 `TopologyHint{NUMANodeAffinity, Preferred}`，对所有容器（含 Pod 级 Scope `pod` vs 容器级 Scope `container`！）计算跨资源亲和位掩码按位与，选出最窄（包含 NUMA 节点数最少）且优先满足 `Preferred=true` 的交集掩码：在 `single-numa-node` 下若无单 NUMA `Preferred` 交集立刻拒绝准入，在 `restricted` 下若无任何 `Preferred` 交集立刻拒绝准入，在 `best-effort` 下允许降级接受最窄非 Preferred 交集；4）容器删除或驱逐时准确回收独占核回到 `defaultCPUSet` 并保证不变量（任何时刻 `reserved ∩ exclusive = ∅`、`default ∩ exclusive = ∅`、三者并集等于全部在线 CPU）。为节点容器运行时交付可导入的 Go CPU Manager 与 Topology Manager 协同分配包。验收覆盖 SMT 完整物理核优先分配、Init 容器回收与重启复用、Pod 级 vs Container 级 NUMA Hint 交集、`single-numa-node`/`restricted`/`best-effort` 准入分叉以及全生命周期核集不变量校验。
