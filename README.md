# MVCC 事务状态库

零依赖的 TypeScript MVCC（多版本并发控制）键值状态库，不依赖任何响应式框架。

## 特性

- **读事务固定状态版本**：事务/快照在开启时固定全局版本，之后只读该版本下的状态（快照隔离）。
- **写前校验读集**：写事务提交时校验读过的键的版本，过期即冲突失败。
- **冲突原子回滚**：冲突时缓冲写入整体丢弃，存储状态不受任何影响。
- **读者隔离中间态**：写入先存于事务私有缓冲，提交前对其他读者不可见。
- **只读快照与 GC**：快照钉住版本防止误回收；`gc()` 回收所有活跃读者都看不到的旧版本。
- **操作可回放**：每次提交追加日志（journal），`Store.replay()` 可完整重建状态。

## 环境要求

Node.js >= 22.18（原生 TypeScript 类型擦除 + 内置 `node:test`，无需编译、无需安装依赖）。

## 运行

```sh
npm test    # 运行 node:test 测试
npm run demo # 运行演示样例
```

## API 概览

```ts
import { Store } from "./src/mvcc.ts";

const store = new Store();

// 写事务
const txn = store.begin();
txn.get("key");        // 读固定版本下的值（并记录读集）
txn.set("key", value); // 缓冲写入，提交前他人不可见
txn.commit();          // 校验读集 → 原子应用；冲突抛 TransactionConflictError 并回滚
txn.rollback();        // 或主动回滚

// 只读快照
const snap = store.snapshot();
snap.get("key");       // 永远看不到快照版本之后的提交
snap.release();        // 释放后其旧版本可被 GC 回收

// 垃圾回收与回放
store.gc();                       // 回收无读者可见的旧版本
const replica = Store.replay(store.getJournal()); // 日志回放重建
```

## 设计要点

- 每个键维护一条按提交版本升序的版本链；读取即"找最后一个 `version <= 读版本` 的条目"。
- 乐观并发控制：读集记录 `{key -> 读到的版本}`，提交时与当前最新版本逐一比对。
- 冲突即失败而非合并，因此两个事务读同一值后各自写回时，后提交者必然失败，
  不会静默丢失更新；失败方重读新值后可重试。
- 写集在提交前仅存于事务私有 `Map`，提交时一次性追加到版本链与日志，天然原子。
