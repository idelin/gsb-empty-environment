插件装入后可能抢占主程序调用的鉴权符号，签名正确的主程序因此调用到不可信实现。实现供Go加载审查宿主调用的符号绑定包，采用本题自定义规则，不声称实现某平台链接器：总计最多16个模块；模块有唯一ID、信任位、有序依赖及按(名称,版本)唯一的导出表，导出分强弱两类；全局模块列表由宿主给顺序。重定位点包含发起模块、名称、精确版本、是否允许外部抢占及是否要求可信目标。允许抢占时先查全局列表再查发起模块依赖的广度优先序列，不允许时先查发起模块；其余仍按上述顺序，去重保留首次，缺失依赖或重名同版本导出是输入错误。搜索完整序列后选第一个强定义，没有强定义才选首个弱定义，版本必须精确一致，且同一不可信插件通过别名重导出或经由可信中继模块间接暴露不可信定义时仍按实际定义方信任位判定。攻击者只可把至多3个给定插件插入全局列表的任意位置，原模块相对次序不变；搜索使某要求可信的鉴权重定位最终绑定不可信导出的最少插件方案，并输出完整查找与胜出理由。输出所有等长方案前最多20个，按插件ID及位置排序，注明截断。覆盖弱定义被后方强定义抢占、依赖环、版本不同不命中和禁止抢占时本地强定义，预算耗尽返回未知。

## 用法

核心类型位于 `symbolbind` 包：

- `Bind`：按宿主提供的全局模块列表解析单个重定位点，返回完整搜索序列、逐模块检查、候选定义、胜出者和理由。
- `BindWithGlobal`：在某个插件插入后的全局列表上执行同样解析。
- `FindMinimalAttacks`：枚举至多三个插件的插入方案，返回最少插件数、前 20 个等长方案、截断标记，或预算耗尽时的 `unknown`。

`Trace.String` 和 `AttackResult.String` 会格式化完整查找过程与胜出理由，便于审计。
