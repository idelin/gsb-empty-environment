# 派生配方发布前审查包

`recipereview` 是 Go 密钥服务在发布前调用的 KDF info 编码审查器。模块路径为
`prescreen.local/ddd-2009-20261122-v2`，无第三方依赖，仅使用标准库。

## 领域模型

- `Alphabet` / `Field`：调用方给定字节字母表上的有界串，`MinLen == MaxLen`
  表示定长字段；字段可在表达式中被引用多次，解码时强制取值一致。
- 编码表达式 `Expr`：
  - `ConstExpr` 常量；
  - `RawExpr` 定长字段原样输出（变长字段在校验期拒绝）；
  - `PrefixExpr` 单字节长度前缀 + 原样字节；
  - `EscapeExpr` 对转义字节和终止字节做转义，再以裸终止字节收尾；
  - `BranchExpr` 按字段是否为空选择两个分支臂；
  - `SeqExpr` 顺序拼接。
- `Recipe`：独立用途 (`Purpose`)、版本 (`Version`)、只读标记、有限字段模式与
  根表达式；`ValidateRecipe` 在入口拒绝未知字段、长度越界、不可达分支臂等。
- `CompatTable`：同一用途下允许同时生成密钥的版本对；不同用途默认视为共存，
  同用途同版本恒共存。

## 三类发布门禁属性

1. 单配方可注入性：同一用途同版本必须可唯一解码，`Recipe.Decode` 用回溯解析，
   对多解或残字节显式报错。
2. 共存配方互不碰撞：不同用途，以及兼容表连接的同用途版本，不允许把不同参数
   编码成同一 info。
3. 只读旧配方隔离：恰好一方标记 `ReadOnly` 且用途不同时，旧配方的任何合法
   info 都不得被新用途配方完整解码为其字段赋值。

## 审查机制

- 符号检查 (`symbolic.go`)：用首字节集合的过近似证明分支臂不相交，并对无分支
  配方给出结构性可注入/互不碰撞证明；无法证明的属性保守地转入枚举。
- 全枚举 (`enumerate.go`, `properties.go`)：对小模式枚举字母表上全部有界串，
  按总参数长度分层生成候选，冲突见证按以下顺序决胜：
  1. 一对输入的字段总长度最短；
  2. 配方编号升序；
  3. 按字段名排序后的原始字节字典序。
- 状态预算 (`Budget`)：枚举域大小和候选检查都计入预算；预算耗尽时未决属性
  只能得到 `VerdictUnknown`，绝不静默放行。

## 独立编码器与见证核验

- `Recipe.Encode` 递归求值表达式；`Recipe.CompileProgram` 把表达式线性化为
  操作码程序，`Program.Encode` 用独立的字节码解释器再次编码，二者在见证核验
  和测试中交叉比对。
- `VerifyWitness` 不信任见证携带的 info 字节：重新校验赋值、用两套编码器
  重算、碰撞类还要过兼容表，只读类还要让新配方重新解码并比对字段。

## 测试

`go test ./...` 以小模式全枚举交叉核验：重复字段一致性、零长分支碰撞、
二进制转义跨边界、只读版本重叠、兼容表门控、预算未知、最短见证决胜和见证
篡改拒绝。
