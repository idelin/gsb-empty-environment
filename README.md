# antientropy — 分片成员表反熵同步

两个分片集群恢复连接后，成员视图不一致。本实现用**摘要交换 + 差异分片区间拉取**
做反熵同步，避免全量广播挤满链路。仅依赖 Go 标准库。

## 记录模型与合并格

- 记录为 `(nodeID, incarnation, state)`,state 排序 `alive < suspect < dead`(`member`)。
- 合并是 `(incarnation, state)` 字典序的格上 join：高 incarnation 胜；同 incarnation
  状态大者胜。结合律、交换律、幂等 ⇒ 过期、重复、乱序的响应**不可能**让表回退，
  同步中本地继续更新也不会被旧响应覆盖（`member.Table.Apply`)。
- nodeID 的分片归属由固定哈希（FNV-1a mod numShards）确定，各节点独立算得一致边界
  (`syncx.ShardOf`)。

## 协议（每轮）

1. **摘要交换**：客户端分页拉取对端分片摘要（响应有字节上限，`NextShard` 翻页）。
   摘要绑定**分片边界**(shardID + numShards)、**记录数**与**内容哈希**
   (`syncx.ComputeDigest`)。首个响应的快照版本钉住整轮；版本变化则整轮重启。
2. **差异拉取**：只拉摘要不一致的分片。本地按**对端的 numShards** 现算摘要比较，
   因此滚动分片配置变更期间双方边界不同也能同步。
3. **游标续传**：`PullRequest{shard, snapshotVersion, cursor, maxBytes}`，服务端从
   版本化不可变快照中有序取页，游标=最后一条 nodeID（开区间下界）。每页至少一条
   记录保证推进；请求/响应都计字节并受上限约束（仿真校验 `LimitViolations`)。
4. **快照失效 ⇒ 重启而非跳过**：快照被驱逐或分片配置变更后，旧版本游标的拉取返回
   `StatusRestart`，客户端重新交换摘要，绝不跳过记录区间。
5. **页校验与全量验证**：每页带 FNV 校验和，截断/篡改（不完整响应）即失败重试；
   分片拉完后，收到的记录全集重算摘要与广播摘要比对，**伪造摘要**（包括"伪装成
   一致"）会被发现并对端信任降级。`ForceFullEvery` 周期性强制全量拉取，使伪造
   摘要掩盖分歧的时间有界。
6. **重复区间**：重复/重放的页幂等吸收；`NextCursor <= cursor` 的页不得回退游标，
   停滞超过上限则判协议错误。

## 信任分数

`syncx.Scheduler` 中信任分只在每个周期内**重排**探测顺序；每个节点每周期恰好被
探测一次。信任是调度提示而非准入控制——0 信任节点发布的合法新 incarnation 依然
在有界轮数内传播（`TestTrustScoreCannotStarveRecovery`)。

## 终止性论证（有限稳定数据 + 公平轮询）

**前提**：某时刻后不再有新更新（数据有限且稳定），numShards 固定；调度器公平——
每个有序对在长度为 N-1 的周期内至少同步一次。

1. **单调性**:`Table.Apply` 是格 join，各节点的表在格上单调不减，且以全量合并
   结果 M（有限）为上界 ⇒ 每个节点的表只变化有限次。
2. **进展性**：若一对节点的某分片摘要不一致，则一次拉取使请求方的表严格增长
   （至少合入一条非极大记录）；摘要伪造要么被页校验/拉后验证发现，要么被周期性
   强制全量同步绕过，分歧被隐藏的时间有界。
3. **无活锁**：表不变则快照稳定，不会无限 `Restart`；每轮重启次数有上界，失败轮
   由公平调度在后续周期重试。
4. **结论**：静止后每个周期所有有序对完成一次交换；由 (1)(2)，有限轮内所有表
   达到 M，摘要全部一致，拉取停止——协议终止于"仅摘要"稳态（每轮字节数降为
   摘要大小）。`TestTerminationUnderFairPolling` 实测：6 节点 30 条记录在界
   `3·N·(N-1)` 内收敛（实测第 5 轮），收敛后两轮 `pulled=0`。

## 测试与回放

```sh
go test ./...                 # 单元 + 仿真：不完整响应/伪造摘要/重复区间/
                              # 跨分片配置变更/传输取消/旧响应竞态/信任公平性/终止性
go run ./cmd/replay           # 内置演示：故障 + 配置变更，逐轮打印字节与游标进度
go run ./cmd/replay -scenario scenario.json -rounds 120
```

仿真用独立**全量合并模型**(`model.FullMerge`，与协议无关）校验每个节点的最终表。
