复制状态机在日志压缩生成快照并向落后副本流式发送分块快照（InstallSnapshot）时，经常在乱序分块、中途出现更新快照或本地日志已领先快照的场景下发生状态机回退或日志断层。为共识存储适配层交付可导入的 Go 快照交接状态机包。管理副本的当前任期、已提交/已应用索引、带起始基址 `(baseIndex, baseTerm)` 的截断日志切片、状态机字节镜像，以及正在接收中的分块快照缓冲。输入事件包括：本地创建快照压缩日志、收到 `InstallSnapshotChunk(term, leaderId, lastIdx, lastTerm, offset, data, done)`、以及收到 `AppendEntries(term, prevIdx, prevTerm, entries, leaderCommit)`。核心契约：任期小于当前任期一律拒绝；分块快照允许按任意偏移乱序/重复到达，且若中途收到更大 `lastIdx` 的新快照须丢弃旧未完缓冲；当分块完整覆盖并收到 `done` 标记时，若 `lastIdx <= commitIndex` 或 `lastIdx <= appliedIndex` 必须拒绝安装防止状态机倒退；合法安装时，若本地日志在 `lastIdx` 处条目存在且任期恰等于 `lastTerm`，必须保留 `lastIdx` 之后的日志后缀而非误删，否则清空日志并以 `(lastIdx, lastTerm)` 作为新基址；随后的 `AppendEntries` 若 `prevIdx < baseIndex` 须精确裁掉已被快照覆盖的旧前缀再续接新条目。验收用乱序网络事件重放对照状态机全历史单调不回退与日志连续性不变量，覆盖乱序分块组装、中途高索引新快照覆盖、拒绝落后快照防回退、匹配后缀保留，以及 `AppendEntries` 跨快照基址裁剪续接。
