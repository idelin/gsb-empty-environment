备份集群希望跨租户复用物理密文块，但未上传数据的租户不能用接口判断别人是否已有它。给 Go 备份宿主写可导入的提交组件。提交清单以序号列出块摘要与长度，含租户签名、会话随机数和父快照摘要。每个租户上传必须独立消费同量输入、执行本租户可观察到的相同阶段，再决定是否复用物理对象；仅知道摘要不能建立本租户引用。失败、取消、重传与并发提交都要满足同一隔离要求。恢复快照只按已提交的租户引用授权；删除及后台回收不得在仍有读租约时移除物理块。宿主提供带版本号的对象存储、事务式租户索引及可注入故障的回调，调用方能看到响应码、返回长度、阶段通知和可取消点，物理存储内部读写耗时不在观察模型内。写一个双运行验证入口：向两个只在其他租户数据上不同的存储喂同一公开操作序列，比较所有可观察事件、提交的租户快照和实际可恢复字节。小规模枚举重复块、共享块丢失、块确认前后掉线、相同清单换租户及回收与重传交错；不要使用真实客户数据。
