# buildproxy — 可解释的构建文件访问代理

Linux / Python 3.11（仅标准库）。所有文件操作都通过 `FileProxy` 完成；
代理在启动时把根目录固定为一个**目录文件描述符（dirfd）**，之后的每一次
解析与操作都基于 dirfd 逐组件进行，绝不"先 realpath 检查、再按字符串打开"。
本代理不声称、也无法拦截绕过代理直接访问文件系统的任意进程——它保护的是
"经由代理"的每一次访问。

## 公开操作

`read` / `create` / `replace` / `rename` / `unlink` / `list`

- 根内**相对符号链接**可用；**绝对链接**与会越过根的 `..` 一律拒绝
  （`EscapeAttempt`）；符号链接跳数有上限（默认 40，`SymlinkLoop`）。
- `replace`：在同目录（同一个被钉住的 dirfd）写唯一临时文件 → `fsync` →
  `renameat` 原子替换 → `fsync` 目录。可用 `write_hook(offset, chunk)` 注入
  写入失败；失败时临时文件被清理，半成品永远不会以正式名字出现。
- `rename`：双路径操作，需同时满足**源删除权限**与**目标创建权限**（两者都
  必须落在可写子树内）。使用 `renameat2(RENAME_NOREPLACE)` 原子提交：目标在
  检查后被并发占用时得到 `FileExistsError`，而不是静默覆盖；被拒绝的 rename
  不改变任一路径。
- `unlink` / `create` / `replace` 作用于最终名字本身：符号链接被替换/删除的
  是链接自身，绝不跟随。`create` 写入失败（含注入失败）时会清理自己创建的
  半成品文件（清理前校验身份，不会误删并发替换进来的同名对象）。

## 解析与竞态防护（不依赖字符串路径）

`buildproxy/resolver.py` 的解析器：

1. 从根 dirfd 出发，逐组件 `openat`（`O_NOFOLLOW`，Linux 上用 `O_PATH`），
   绝不把解析结果重新按字符串打开；
2. 符号链接由代理解析（`readlink` + dirfd），目标切回组件继续走，跳数受限；
3. `..` 通过弹出自己持有的目录 fd 栈实现，从不让内核按名字解析 `..`，
   因此并发改名目录不会把解析带偏；
4. **组件身份验证**：每个目录打开后 `fstat`，与打开前的 `lstat` 比较
   `(dev, ino)`，不一致说明"检查后、打开前"被替换，丢弃结果并有界重试；
   最终组件的打开同样校验身份（`O_NOFOLLOW` 下被换成符号链接会触发
   `ELOOP` → 重新解析）。

## 威胁模型与边界

**在威胁模型内**（代理防御的）：另一个线程在可写根内替换符号链接、改名
普通目录、创建同名路径。这些情况下代理保证：根外对象不可达、策略按解析后
的逻辑路径执行、审计记录的是真实访问对象的身份。

**明确不在威胁模型内**（本代理无法防御，也不声称防御）：

- 修改挂载点（如在根内挂载新文件系统、移动挂载点）；
- 把**已打开的目录**移动到根外（dirfd 锚定无法察觉这种移动）；
- 绕过代理直接访问文件系统的进程、以及在代理进程内执行任意代码的攻击者。

如需更强的内核级保证，可在此架构上换用 `openat2(RESOLVE_BENEATH |
RESOLVE_NO_MAGICLINKS)`；本项目按要求显式实现逐组件解析，便于解释与审计。

## 策略

`Policy(readable=(...), writable=(...))` 由可读的输入子树与可写的输出子树
组成，子树为根内相对路径（`""` 表示整个根）。成员判定作用于**解析后的逻辑
路径**（符号链接与 `..` 已归一化），按组件前缀匹配——因此同前缀兄弟目录
（`in` vs `input`）不会混淆，符号链接也无法把访问偷渡到未授权子树。

## 审计

每次操作（含被拒绝与出错）产生一条 `AuditEvent`：调用路径、解析后的逻辑
路径、实际访问对象的 `(dev, ino)`（取自**已打开 fd 的 `fstat`**，而非检查
时刻的旧路径）、结果（`ok`/`denied`/`error`）与拒绝原因，以及从根到父目录
的目录身份链。`unlink`/`rename` 无法在系统调用期间钉住被删对象，故其
`dev`/`ino` 为 `None`，以目录身份链为证据。

## 测试与样例

```sh
python3.11 -m unittest discover -s tests -v   # 全部测试（stdlib unittest）
python3.11 examples/demo.py                   # 使用样例，打印审计 JSON
```

- `tests/test_proxy.py`：功能、策略矩阵、`a/../b` 归一化、同前缀兄弟目录、
  链接环、权限交叉、根外诱饵文件从未被读写、replace 失败注入、审计字段、
  fd 释放。**只测静态路径不构成竞态安全的证明。**
- `tests/test_races.py`：用 `threading.Barrier` 配合代理的 trace 钩子
  （`component_checked` / `final_open` / `replace_commit` / `rename_commit`）
  **精确调度**交错：检查后打开前的链接替换（绝对与 `..` 逃逸两种）、最终
  组件被换成链接后的重校验、解析后 dirfd 钉住不受后续替换影响、rename 目标
  被并发占用、replace 提交瞬间目标被换成指向根外的符号链接。每个用例断言
  安全性质（诱饵从未被读/写、不覆盖、审计身份即实际对象），而非特定时序。

注：仓库在 macOS 上也能跑测试（`renameatx_np/RENAME_EXCL` 仅作为开发期
fallback）；正式支持目标是 Linux。
