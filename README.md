自治系统边界路由器在验证 BGPsec（RFC 8205）更新报文与 RPKI 路由源授权（ROA / ASPA）时，若仅校验最后一跳签名而未按倒序重建每一跳的签名输入（含 `Target AS`、`Secure_Path` 前缀与 `pCount` 计数），或忽略 `pCount=0` 路径预置滥用、ROA `maxLength` 越界与 ASPA 谷底无环（Valley-Free）约束，恶意中转 AS 可发动路径缩短、路由泄漏或子前缀劫持。为 Go 路由安全宿主实现可导入的 BGPsec 二进制路径验证与 RPKI ROA/ASPA 联合决策包，严禁联网（使用标准库 `crypto/ecdsa` P-256 与 SHA-256）。组件解析二进制 `BGPsec_Path`（`Secure_Path` 段列表与 `Signature_Blocks`）及 NLRI 前缀：按 RFC 8205 Section 4.2 精确逐跳重构各 AS 的签名摘要并验签，校验 `Flags` 保留位、SKI 公钥映射与 `pCount` 合法性（允许合规的 `pCount=0` 透明路由服务器段但拒绝起源 AS 或非法位置置零）；联合 RPKI ROA 表执行精确最长前缀匹配与 `maxLength` 核验（区分 Valid/Invalid/NotFound）；并基于 ASPA 客户-提供商集合按上下行方向执行完整 Valley-Free 路径检查，阻断从对等方/提供商向另一提供商的路由泄漏。附路径截断、篡改中间跳 `pCount`、ROA 超长子前缀劫持与 ASPA 路由泄漏对抗测试。
