Kubernetes 批处理控制器在支持 `completionMode: Indexed`、`backoffLimitPerIndex`、`maxFailedIndexes` 与 `podFailurePolicy` 后，每个索引子任务的成败与全局作业终态之间形成了复杂的多层状态机：1）Pod 失败时必须按序求值 `podFailurePolicy.rules` 取**首条命中规则**（支持匹配指定业务容器的 `onExitCodes`：`In`/`NotIn` 精确退出码集合，以及 `onPodConditions` 如 `DisruptionTarget` 驱逐标记！）——`Ignore` 动作下的失败绝不计入该索引的失败次数或全局 `backoffLimit`（立即可重试！）；`FailIndex` 无论该索引是否还有剩余重试次数都立刻将该索引判为永久失败；`FailJob` 立刻将整个 Job 置为 `Failed` 并终止全部在跑 Pod；`Count` 或未命中任何规则则按默认递增失败计数！2）对每个索引 `i in [0, completions - 1]` 独立维护重试次数与指数退避截止时刻，当某索引失败计数超过 `backoffLimitPerIndex` 时仅该索引标为永久失败（其他索引继续推进！），而一旦永久失败索引总数严格超过 `maxFailedIndexes`（或全局总计失败超 `backoffLimit`），则整个 Job 立刻终止为 `Failed`！3）调度新 Pod 时在 `parallelism` 并发上限内优先选择编号最小、未完成、未永久失败、当前无活跃 Pod 且退避计时已到期的索引；4）将所有已完成索引集合实时压缩为规范连续区间字符串（如 `'0-3,5,8-10'`），并在全索引均完成（或全部到达终态且永久失败索引数 `<= maxFailedIndexes` 与全完成条件满足）时精确判定 `Complete` vs `Failed`。为云原生批处理控制面交付可导入的 TypeScript Indexed Job 调度与失败策略引擎。验收覆盖 `podFailurePolicy` 首条命中与 `Ignore` 不计退避、`FailIndex` 提前判死单索引、`maxFailedIndexes` 阈值触发全局终止、分索引指数退避并发补位以及规范区间压缩串生成。
