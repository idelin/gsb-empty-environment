分布式流作业从多个分片源并发拉取事件时，单个分片长时间无流量会把全局 Watermark 彻底卡死，而个别快分片遥遥领先又会把下游连接状态撑爆；启用空闲检测（Idle Detection）与水位对齐（Watermark Alignment）后，快源暂停、慢源转空闲再恢复的边界极易引发水位倒退或永久死锁。为流协调器交付可导入的 Go 水位控制包。输入分片源集合、最大允许漂移 `maxDrift`、空闲判定时长 `idleTimeout` 及按处理时间毫秒递增的事件流（分片上报新局部水位、分片切换/扩缩容增删、时钟推进）。规则：全局对齐基准 `minActiveWM` 为所有当前非 Idle 分片的最小局部水位；任何局部水位超过 `minActiveWM + maxDrift` 的分片进入 `Paused` 态停止继续拉取，直至基准追上使其落回允许范围才恢复 `Active`；任何持续 `idleTimeout` 毫秒未收到新事件且当前非 `Paused` 的分片转入 `Idle` 态（**注意：被协调器主动 Paused 暂停拉取的快分片绝不可被误判为 Idle！**）；分片转 Idle 后移出 `minActiveWM` 计算，全部分片皆 Idle 时全局水位冻结在最后发射值；任意时刻对外发射的全局 Watermark 必须严格单调不降（即使刚从 Idle 恢复的落后分片上报更低局部水位，全局输出也不回退，但该落后分片可立即拉低 `minActiveWM` 触发快源限流暂停）。验收用交错事件流对照全部安全与活性不变量，覆盖快分片被 Paused 超过 `idleTimeout` 不得误判 Idle、慢分片转 Idle 解冻快分片、Idle 恢复上报低水位保全局单调且暂停快源，以及全源 Idle 冻结。
