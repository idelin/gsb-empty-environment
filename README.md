ZeRO-3 把每层模型参数按数据并行分片存储，执行每层前向或反向前都要先通过 AllGather 聚合完整参数；提前预取下一层能把通信藏进计算时间里，用完保留到反向还能省一次 AllGather，但都会立刻吃掉宝贵显存导致 OOM。为训练运行时交付可导入的 Go 排期优化包。输入顺序网络层数 L（1≤L≤10）、每层前向/反向计算耗时、完整参数字节数、AllGather 通信耗时、前向结束需留存到对应反向释放的激活字节数（反向算完该层立即释放激活）以及单卡硬显存上限 M（常驻分片与基础开销已扣除）。按严格层序 `F_0..F_{L-1}, B_{L-1}..B_0` 在计算流上串行执行，通信流上串行执行各层 AllGather（不得并发两笔 AllGather）：在每层计算开始前该层完整参数须已在显存就绪（可前向保留不释放直接复用到反向，或前向完释放而在反向前再次预取），每次预取发起即占满该层参数显存，释放立即归还，任意时刻显存占用（已存激活 + 所有已就绪或正在预取的完整参数）不得超过 M。组件求总端到端完成时间（makespan）最短的精确（预取启动时机，前向后是否保留）排期，并列按总通信耗时最小，再按保留层掩码字典序最小；无法满足 M 返回 OOM 错误。验收在小层数网络上用事件驱动调度穷举对照最优 makespan 与峰值显存，覆盖保留尾层参数直接供反向免重传、显存吃紧迫使推迟预取暴露通信等待、预取与前向激活叠加撞顶 M，以及单层激活加参数即超 M 报 OOM。
