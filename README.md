Kubernetes Deployment 控制器在连续多次变更 PodTemplate 导致同时存在 3 个及以上未清空旧 ReplicaSet（RS）时，滚动升级、比例扩缩与回滚逻辑隐藏着四条极易写错的规范细则：1）`maxSurge` 若为百分比必须**向上取整（ceil）**，而 `maxUnavailable` 若为百分比必须**向下取整（floor）**（当 `desired > 0` 且两者同时为 `0` 时必须判定配置非法报错！）；全过程始终维护双硬边界：`totalPods <= desired + maxSurge` 与 `availablePods >= desired - maxUnavailable`；2）当同时存在多个旧 RS 且需要为新 RS 腾出配额（缩容旧 RS）时，不能只从最老 RS 一口气减完，必须先优先清理所有旧 RS 中的**不可用副本**，剩余待缩减额再按各旧 RS 当前副本数做**比例缩容（Proportional Scaling）**并按最大余数/创建时间确定性分配余数！3）`paused: true` 仅暂停新建 RS 与新旧滚动交接，但若用户在暂停期间修改 `spec.replicas`，控制器仍必须按当前各活跃 RS 副本占比执行比例扩缩！4）回滚到历史 `revision` 时，绝不可新建重复 RS——必须按 PodTemplate 规范哈希找到历史匹配的既有 RS，将其他 RS 标为旧 RS 并把目标 RS 的 `deployment.kubernetes.io/revision` 提升为 `maxRevision + 1`；5）精确维护 `progressDeadlineSeconds` 推进超时计时（仅当新 RS 实际创建/可用副本数递增或旧 RS 清理取得实质进展时刷新 `lastUpdateTime`，无进展超期置 `ProgressDeadlineExceeded`）并按 `revisionHistoryLimit` 清理最老的 0 副本历史 RS。为声明式集群控制面交付可导入的 Go Deployment 多代 RS 滚动与回滚控制器包。验收覆盖 `maxSurge` ceil vs `maxUnavailable` floor 差异、3 代以上 RS 优先清不可用+比例缩容、暂停态修改 `replicas` 比例扩缩、回滚复用旧 RS 提版本号以及无进展超时状态迁移。
