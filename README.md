# 被污染的秘密分片恢复

密钥恢复服务收到参与方提交的错误分片，不能选前k份插值后把错误秘密交给下游。给Go恢复宿主实现可导入的纠错包：分片为互异非零横坐标x及y，均在调用方给定素数p的有限域内，p≤65521；真实分片来自次数小于k的多项式，1≤k≤16，k≤n≤40。调用方声明最多t份错误且n≥k+2t，采用代数纠错恢复多项式和f(0)，随后逐份重算并返回不一致分片ID；找不到与至少n-t份相符的次数受限多项式时拒绝，不能挑一组恰好能插值的分片凑成功。未知错误少于t时也必须成功，处理线性系统多解和误差定位多项式含多余因子的情形；拒绝重复x、非素数域与不满足距离约束的请求。用独立全子集参考在小域核对唯一性，注入0至t个恶意分片，另造超限但仍碰巧落在另一合法码字附近的输入，报告只能说明与收到分片的一致性，不能声称识别了真实攻击者。

## 使用

```go
shares := []netsec.Share{
    {ID: "alice", X: 1, Y: 3},
    {ID: "bob", X: 2, Y: 5},
    {ID: "carol", X: 3, Y: 7},
}

result, err := netsec.Recover(shares, 17, 2, 0)
if err != nil {
    // 参数错误，或不存在与至少 n-t 份分片相符的次数受限多项式
}

secret := result.Secret                // f(0)
coefficients := result.Polynomial      // 恰好 k 个，按幂次升序
inconsistentIDs := result.InconsistentIDs
```

`Recover` 先在 F_p 上求 Welch–Berlekamp 线性系统，再对误差定位多项式做精确多项式除法，最后逐份重算。它不会用任意 k 份分片直接插值。线性系统欠定时任取一组解均可得到同一个次数受限多项式；定位多项式的多余因子会在精确除法中被消去。

返回的 `Inconsistent*` 字段只表示这些分片与恢复出的多项式不一致，即与本次收到数据的相对关系。它不声称识别了最初注入错误的参与方，也不能用于证明某份提交就是真实攻击来源。若收到数据超出 t 份错误预算、但恰好落在另一合法码字 n-t 范围内，解码器会恢复该合法码字并报告相对一致性；这同样不是攻击者归因。

拒绝条件包括：`p` 非素数或大于 65521、`k`/`n`/`t` 越界、`n < k+2t`、重复 `x`、`x = 0` 或坐标不在 F_p 内。无法通过 `n-t` 份一致性检查时返回 `ErrNoConsistentPolynomial`。
