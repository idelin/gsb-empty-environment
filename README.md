# 分布式滑动窗口限流：心跳租约配额预分配（Go 标准库实现）

中心协调器（Master）持有全局限流池，按滑动窗口向各工作节点（Worker）下发
租约配额。Worker 在本地直接消耗预分配的 Token，**无需每次请求都走 RPC**；
仅当本地余额低于阈值（20%）时，才异步触发一次**批量心跳**向 Master 续订。
Master 在心跳中回收空闲节点的空余额度，再均衡地调拨给繁忙节点。

## 结构

- `master.go` — 协调器：租约登记、心跳处理、空闲额度回收与再均衡、窗口滑动
- `worker.go` — 工作节点：本地 Token 消耗、低水位异步批量续订、窗口重置
- `quota_test.go` — 验收测试（`go test`）
- `cmd/demo/main.go` — 运行样例

## 关键设计

- **租约预分配**：Worker 拿到的是整个窗口的配额，本地扣减，零 RPC。
- **批量异步续订**：余额低于 20% 时触发；`inflight` CAS 保证同一时刻只有
  一个心跳在途，多次触发自动合并，RPC 频率与流量解耦（测试中 1500 次
  请求仅 1 次心跳）。
- **再均衡不变式**：心跳处理时按"空闲度"（grant - used）降序回收，配额只在
  节点间转移，全池总量恒定（3000）。
- **滑动窗口**：窗口到期后用量计数归零，被调走的额度随窗口滑动自然恢复。

## 运行

```sh
go test -v ./...    # 验收测试
go run ./cmd/demo   # 运行样例
```

## 验收场景

3 个 Worker 平分 3000 QPS（各 1000）。Worker A 突发流量耗尽自身 1000
配额，低水位触发批量心跳；Master 发现 Worker C 完全空闲，将其 1000 空
余额度调拨给 A（A=2000, C=0），A 继续承接突发流量，全池总量恒为 3000。
