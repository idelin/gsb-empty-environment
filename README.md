# rename — 文件重命名规划器

给定一组 `Src -> Dst` 重命名请求（全部按初始目录解释），生成临时路径
最少的执行计划，并提供独立模拟核对与可恢复的带日志执行。

## 设计

- **图分解**：把映射看成函数图（每个源出度为 1）。重复源、重复目标
  直接报错，因此每个连通分量只能是纯链或纯环。
- **链**：目标槽位空闲（或会被先执行的分量腾空），逆序执行即可，
  零临时路径。
- **环**（如 `a->b->c->a`）：恰好用一个临时路径破环——先把环上
  一个节点停放到临时名，逆序展开其余节点，最后把临时名落位。
  每个环一个临时名是最优下界，计划达到该下界。
- **占用检查**：任何不会被参与者腾空的目标若已存在于磁盘，报错。
- **临时名**：`.rename-tmp-N`，跳过所有源、目标、自改名路径、
  磁盘已有文件及已用临时名，保证不冲突。
- **自改名**（`Src == Dst`）：空操作，不产生任何步骤。

## 独立核对

`Simulate` 在「路径 -> 文件身份」的虚拟文件系统上逐步执行计划，
任何一步源缺失或目标被占都会失败；`Verify` 再比对最终映射是否与
请求完全一致、其余文件分毫未动。

## 执行与恢复

`Execute` 对每步先写 `BEGIN i src dst`、成功后写 `DONE i`。
崩溃后用 `Recover` 读日志：最后一条没有 `DONE` 的 `BEGIN` 结合磁盘
状态判定——源还在则重做该步，只有目标在则说明重命名已完成、跳过；
其余组合视为损坏并报错。恢复后从断点继续执行剩余步骤。

## 测试

```sh
go test ./...
```

覆盖：`a->b->c->a` 循环、自改名、多循环加链混合、目标被未参与文件
占用报错、临时名冲突规避、重复源/目标报错、越界路径拒绝、真实磁盘
端到端执行，以及在每个步骤、两种崩溃时机（重命名前/后）下注入
失败后的日志恢复。
