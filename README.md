# dyngraph — 动态图连通性查询工具（离线批次算法）

无向图上持续加边 / 删边 / 查询。连通时输出一条最短路径，不连通时输出
分割证据（u 所在连通块、补集、以及跨越割的边数为 0）。所有答案都对应
查询发生的时刻，而不是最终图。

## 输入格式

每行一个事件（空行与 `#` 注释忽略），从文件或标准输入读取：

```
<tick> add   <u> <v>
<tick> del   <u> <v>
<tick> query <u> <v>
```

- 事件严格按输入顺序生效；同一 tick 的多个事件按出现先后排序，
  查询恰好看到它之前所有事件造成的状态。
- 重复 `add` 同一条边按引用计数处理：计数归零的那次 `del` 才真正删边。
- `del` 一条计数为 0 的边是错误，工具报错并以非零码退出。

## 算法

离线批次（`solver.go`）：

1. 扫描事件流，用引用计数把每条边的每次存活期算成开区间
   `(add_event, del_event)`（`buildIntervals`）。
2. 以事件下标为时间轴建线段树，把每条边插入覆盖其存活区间的
   O(log n) 个节点。
3. DFS 线段树，携带可回滚并查集（按大小合并 + 操作栈回滚）与当前
   根到叶子路径上的激活边集；到达叶子时，该边集就是这一时刻的图，
   连通性由并查集回答，路径 / 割集证据由该时刻边集上的 BFS 产生。

## 核对

`verify.go` 提供逐时重建核对：按顺序重放事件流，在每个查询事件处
用当时的边多重集重建图，验证——

- 连通答案：报告路径的端点与逐点邻接在重建图中真实存在；
- 不连通答案：报告的连通块与重建结果完全一致、补集匹配、且没有任何
  激活边跨越该割。

CLI 默认开启核对（`-verify=false` 可关闭），失败即报错退出。
