# 主从写入模拟器（基于任期的写入日志）

模拟客户端缓存旧主地址、切换后旧主仍收到写入的场景，验证三条核心不变量：

1. **提交仅接受当前任期的授权者**：controller 单调递增任期并指定唯一主；
   提交要求多数派 ack **且**能向 controller 确认当前任期授权。
   分区中的旧主（controller 不可达）只能把写追加为未提交条目，永远无法提交。
2. **延迟复制不能替换已提交前缀**：过期任期的复制消息直接拒绝；
   日志冲突时只截断**未提交**后缀，触及已提交前缀的写入被拒绝。
3. **重复请求幂等**：按 `(clientID, requestID)` 去重，重试返回缓存响应，
   日志不增长；去重状态随已提交日志在 apply 时重建（相当于随复制传播）。

## 运行

```sh
go run .                      # 依次运行全部三个场景
go run . -scenario partition  # 场景1：分区后旧主仍收到写入
go run . -scenario recovery   # 场景2：主崩溃恢复 + 延迟复制到达
go run . -scenario duplicate  # 场景3：重复请求与重复复制
```

## 输出说明

每步打印：controller 视图（当前任期/授权主）、每个节点的角色、任期、
提交水位、日志（`V`=已提交，`x`=未提交）、本地 KV 存储，
以及客户端可见值（当前授权主的已提交存储）。

## 场景概览

- **分区**：N0 被隔离后仍自认 T1 主，收到缓存旧地址的客户端写入
  → 无法提交；客户端改投新主 N1(T2) 后提交；分区恢复时 N0 截断未提交
  后缀；滞留的 T1 复制消息到达 N2 被拒绝，已提交前缀不变。
- **主恢复**：N0 带未提交写崩溃，恢复后被新主全量同步（截断未提交条目）；
  网络中滞留的 T1 消息全部因任期过期被拒绝；客户端重试未完成的请求，
  经重定向后在新主提交。
- **重复请求**：响应丢失后的客户端重试被去重表拦截；同一条复制消息
  重复投递幂等；故障切换后旧主重定向，客户端以同一 requestID 重试，
  新主去重，日志不增长。

## 代码结构

- `sim.go` — Entry/ReplMsg/Node/Network/Controller/Client 及核心协议逻辑
- `scenarios.go` — 三个场景脚本（每步打印可见值）
- `main.go` — 入口与 `-scenario` 参数
