# 数据同步校验和（Checksum）实时比对器

源库与目标库一致性在线巡检器。采用 **Merkle 树风格分层结构 + 滚动 XOR 校验和**：
在变更持续流动的同时，两端各自基于本库数据按分区/分桶增量维护数据摘要，
巡检器周期性比对摘要，发现失配后沿树下钻，**毫秒级定位到具体主键 ID**。

纯 TypeScript 实现，零第三方依赖（Node.js ≥ 22.6 原生类型擦除直接运行）。

## 原理

```
分区 partition (默认 4096 行)  ──XOR──▶  分桶 bucket (默认 256 行)  ──XOR──▶  行 row
```

- **行校验和**：`SHA-256(规范化行)` 截断 128 bit（`src/rowHash.ts`）。
- **滚动 XOR**：每个父节点是子节点校验和的异或值。XOR 自逆（`x^x=0`），
  行变更只需「异或掉旧值、异或入新值」，**O(1) 增量维护**，变更流再快也跟得上（`src/checksumIndex.ts`）。
- **巡检比对**：每周期只交换顶层摘要表（partitionId → checksum），O(分区数)；
  失配分区沿 分区→分桶→行 下钻，**只逐行扫描失配分桶**（≤256 行），而非全表（`src/inspector.ts`）。
- 可检测三类异常：`tampered`（篡改）、`missing_in_target`（丢数）、`extra_in_target`（多数）。

## 运行

```bash
npm run demo    # 运行样例：20 万行初始同步 + 10 万条持续变更 + 人为篡改
npm test        # Node.js 内置测试运行器，13 个用例
```

```
[1] 初始全量同步 200,000 行 ...
    巡检 #1: ✅ 两端一致（比对 49 个分区，耗时 0.44 ms）

    巡检 #2 (批次 1): ✅ 一致（49 分区，0.13 ms）
    ...
    😈 [第 12 批] 已悄悄篡改目标库 id=137777 的 balance 字段（+0.01）
    巡检 #13 (批次 12): 🚨 发现不一致！耗时 10.33 ms
      失配分区: [33]（下钻仅逐行比对 255 行 / 全量 198,933 行）
      定位主键 id=137777  类型=数据被篡改
        source 行校验和: 5d38bc67b5f22bebff6d40bb15548178

        源库 balance=9734.8  目标库 balance=9734.81

[3] 将源库正确数据重新同步到目标库，复巡验证
    巡检 #22: ✅ 两端恢复一致（耗时 0.04 ms）
```

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `src/rowHash.ts` | 行规范化序列化、SHA-256 行校验和、XOR 原语 |
| `src/store.ts` | 模拟源/目标库表，写入即广播变更事件 |
| `src/checksumIndex.ts` | 三层 Merkle 风格滚动 XOR 索引，O(1) 增量维护 + 下钻比对 |
| `src/inspector.ts` | 巡检器：周期比对顶层摘要，失配下钻定位主键 |
| `src/demo.ts` | 端到端样例：20 万行同步、10 万条变更流、人为篡改、复巡修复 |
| `test/` | Node.js 内置 `node:test` 测试（13 个用例） |
