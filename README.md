企业域控 KDC 与服务端在实现 Kerberos 5（RFC 4120）及约束委派扩展（S4U2Self / S4U2Proxy）时，若仅校验服务票据外层解密而漏验 PAC 的双签名（Server Signature 与 KDC Signature）、未检查 `additional-tickets` 的 `FORWARDABLE` 标志与服务白名单，或忽略跨领域 `transited` 路径与加密套件降级，攻击者可利用白银/黄金票据伪造特权组或通过非约束委派横向冒充域管理员。为 Go 身份认证宿主实现可导入的 Kerberos 5 票据与约束委派安全验证包，严禁联网（仅用标准库 `crypto/*` 与 `encoding/asn1`）。组件严格验证 `TGS-REQ`/服务票据结构与委派状态机：（1）解密并校验票据有效期、`caddr`/时钟偏移与 `kvno`/最小允许加密算法（硬拒绝 RC4/DES 降级），同时独立验证 PAC 内的 Server Checksum 与 KDC Checksum（采用 HMAC-SHA256 测试向量）并核对 PAC 内 `ClientInfo` 与票据 `cname`/`authtime` 完全一致；（2）执行 S4U2Self 与 S4U2Proxy 规则：仅当服务在白名单内且目标 SPN 显式列于其 `AllowedToDelegateTo` 列表时放行委派；若请求带协议转换（`S4U2Self`）且源主体被标为敏感不可委派（`NOT_DELEGATED`）或缺失 `FORWARDABLE` 标志则强制拒签；（3）对跨领域票据校验 `transited` 域列表与信任图路径一致性，阻断域间 SID 过滤绕过（`SIDHistory` 含外域特权 RID）。附白银票据篡改 PAC、敏感账号 S4U2Proxy 绕过、加密降级与跨林 SID 注入测试。
