# 共享单车调度器（Bike Rebalancing Scheduler）

根据各站点容量与次日需求，安排搬运车的取送路线，使 **缺车罚金 + 里程成本** 最小。

- 站点最多 8 个，车辆从仓库出发、**必须回到仓库**
- 车辆有载重上限，仓库可配置备货量
- **允许多次访问**同一站点（载重不够时会自动跑多趟）
- 严格按时间顺序模拟：**不能通过负库存提前取走尚未送达的车**
- 输出每一步之后各站点库存与车载库存的完整时间线

## 运行

需要 Node.js ≥ 22.6（利用原生 TypeScript 类型擦除运行 `.ts`，无需编译）：

```bash
node src/cli.ts scenarios/example.json        # 6 站示例
node src/cli.ts scenarios/example-large.json  # 8 站示例
npm test                                      # 运行测试
```

也可以用 `tsc` 编译后运行（`tsconfig.json` 已配置），或任何支持 TypeScript 的运行时。

## 模型

- 状态 = `(车辆位置, 车载库存, 仓库余量, 各站库存)`，在状态图上做 A\* 搜索，
  目标函数为 `总里程 × 每公里成本 + 期末缺车数 × 单车罚金`（可选超量罚金）。
- 加速手段（均不损失精确性）：
  1. **最短路化简**：站点间恒走 Floyd-Warshall 最短路，去掉“只路过不装卸”的移动；
  2. **贪心可行解**作为上界；
  3. **可采纳启发**：剩余成本 ≥ 回仓最短里程 + 不可修复缺车罚金下界。
- 转移量枚举两种模式（`transferMode`，默认 `auto` 按状态空间规模自动选择）：
  - `exact`：枚举所有可行转移量，结果精确最优；
  - `candidates`：只枚举断点值（取空/放满车辆、站点达到目标/空/满），
    状态空间大幅缩小，6–8 站秒出解，实践中与精确解一致或极接近。
- 每搬运一辆车附加 `1e-6` 的微小成本，仅为打破平局、避免退化方案，不影响真实成本口径。
- 求解得到的方案会用 `simulate` 完整重放校验：车载非负且不超载、站点库存
  非负且不超容量、仓库备货不超取、最终必须回仓。

## 场景格式（JSON）

```jsonc
{
  "stations": [
    { "name": "S1", "capacity": 12, "initial": 2, "target": 8 }  // 容量/当前库存/次日需求
  ],
  "vehicle": { "capacity": 10, "initialLoad": 0 },   // 载重上限、出仓载量
  "depot": { "supply": 20, "canUnload": true },       // 仓库备货（默认无限）、可否卸车
  "costs": { "perKm": 2, "shortagePerBike": 50, "overagePerBike": 0 },
  "distanceMatrix": [[0, 4.0], [4.0, 0]],  // (n+1)²，第 0 行/列为仓库
  "transferMode": "auto",                   // exact | candidates | auto
  "maxIterations": 2000000
}
```

## 输出

- 最优方案汇总：总里程、里程成本、缺车数、罚金、总成本；
- 时间线表格：每一步的位置、动作（装车/卸车/取走/放下）、操作后的
  车载库存与各站库存、累计里程；
- 期末各站库存 vs 次日需求对照。
