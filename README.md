硬件安全模块（HSM）与密钥管理服务在实现 PKCS#11 密钥属性策略时，即使把主密钥标记为不可导出（`CKA_SENSITIVE=true`、`CKA_EXTRACTABLE=false`），若同时允许某把包装密钥（Wrapping Key）兼任 `CKA_WRAP=true` 与 `CKA_DECRYPT=true`，或允许通过 `C_SetAttributeValue`/`C_CopyObject` 把非信任包装密钥升级为可解密/可包装，攻击者仅凭合法 API 组合（经典 PKCS#11 Wrap-and-Decrypt / Key-Template 攻击）即可在几步内以明文套出受保护密钥。为 Go HSM 安全控制面宿主实现可导入的 PKCS#11 密钥策略状态机与 API 级明文窃取攻击图搜索包。系统建模 HSM 内部密钥库（对称 AES 密钥与非对称密钥对，每把密钥携带完整属性向量 `CKA_SENSITIVE`/`CKA_EXTRACTABLE`/`CKA_ENCRYPT`/`CKA_DECRYPT`/`CKA_WRAP`/`CKA_UNWRAP`/`CKA_DERIVE`/`CKA_TRUSTED`/`CKA_WRAP_WITH_TRUSTED`/`CKA_ALWAYS_SENSITIVE`/`CKA_NEVER_EXTRACTABLE`）与真实对称加密/包装机制（AES-KW/AES-CBC/AES-GCM），严格执行 PKCS#11 属性单调性约束（禁止将 `CKA_SENSITIVE` 从 true 改为 false、禁止将 `CKA_EXTRACTABLE` 从 false 改为 true、强制包装/解包与加密/解密角色互斥，以及 `CKA_WRAP_WITH_TRUSTED=true` 的密钥只能被 `CKA_TRUSTED=true` 的密钥包装）。除在线 HSM 操作裁决器外，实现深度至多 6 步的有界符号攻击搜索器：给定初始密钥集合、允许调用的 PKCS#11 API 子集（`WrapKey`/`UnwrapKey`/`Encrypt`/`Decrypt`/`DeriveKey`/`SetAttributeValue`/`CopyObject`）与调用方权限，自动搜索能令任意受保护目标密钥明文泄露至攻击者知识集合的最短 API 调用序列（涵盖经典 Wrap+Decrypt、Unwrap 改写模板与跨机制混淆），并用小规模状态空间全枚举验证策略加固后零泄露路径。
