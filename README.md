# 无锁 MVCC 只读事务读取器

针对高频读业务的无锁 MVCC 读路径（TypeScript / Node.js）。只读事务不获取任何锁，
无锁遍历不可变版本节点；写线程高并发追加版本链时，读操作完全免阻塞且绝不读到半脏数据。

## 设计

```
SharedArrayBuffer（写/读线程共享同一块内存）
┌────────────────────────────────────────────────┐
│ Header                                         │
│   COMMIT_SEQ   全局提交序号 = 快照令牌          │
│   POOL_NEXT    版本节点池追加式分配指针         │
│   WRITER_DONE / SCAN_COUNT / TORN_COUNT        │
├────────────────────────────────────────────────┤
│ Key Directory   每键一个原子头指针 → 版本链头   │
├────────────────────────────────────────────────┤
│ Version Node Pool   定长 24B 节点，发布后不可变 │
│   { value:f64, txId:i32, prev:i32, key:i32 }   │
└────────────────────────────────────────────────┘
```

**无锁保证**

- **不可变版本节点 + 只追加版本链**：节点字段先写完，再用一次
  `Atomics.store` 发布头指针（release）；读者一次 `Atomics.load`（acquire）
  即可用普通读遍历整条链，JS 内存模型保证节点字段可见。
- **只读事务 = O(1) 快照**：`snapshot()` 只是 `Atomics.load(COMMIT_SEQ)`，
  无锁、无等待、无重试（wait-free）。
- **单点提交**：写事务先把全部版本节点挂链（txId = 下一序号），最后单点推进
  `COMMIT_SEQ`。读者凭快照序号过滤 `txId > snap` 的节点，因此多键写入
  对任何快照要么整体可见、要么整体不可见 —— 不存在"半个事务"。
- **读写互不阻塞**：写路径只有追加与原子发布，读路径只有原子加载与遍历，
  全代码零 `Atomics.wait`、零锁、零 CAS 重试循环。

## 目录结构

- `src/layout.ts` — 共享内存布局（Header / 键目录 / 版本节点池）
- `src/store.ts` — 无锁 MVCC 核心存储（`snapshot` / `read` / `sum` / `commit`）
- `src/workers/writer.worker.ts` — 写线程：密集转账写事务（总和守恒）
- `src/workers/reader.worker.ts` — 读线程：只读事务全表扫描校验和
- `src/demo.ts` — 实时吞吐压测样例
- `test/mvcc.test.ts` — 单元测试（快照隔离 / 链遍历 / 提交原子性 / 不可变性）
- `test/stress.test.ts` — 验收边界测试（1 写 × 5 读 × 1000 键，零撕裂）

## 运行

要求 Node.js ≥ 22.6（利用内置 TypeScript 类型剥离，无需构建；推荐 ≥ 23.6）。

```bash
npm test        # Node 内置测试运行器：8 个单元测试 + 1 个验收压力测试
npm run demo    # 运行样例：1 写线程 + 5 读线程实时压测
STRESS_COMMITS=1000000 npm test   # 调整验收测试写事务规模
```

## 说明与边界

- 节点池为预分配固定容量（避免在读者遍历期间回收节点，天然免疫 ABA/悬挂指针）；
  容量耗尽时写线程报错退出而非复用节点。生产化可换用 epoch 回收或分段扩容。
- 当前为单写者模型（SWMR），写路径无需 CAS；多写者可在 `commit` 的提交点
  外加 CAS 或写锁扩展，读路径保持无锁不变。
