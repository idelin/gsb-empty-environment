批处理工作负载同时提交一组高价值 Pod 时，逐个贪心调度常因先占独占端口或触发互反亲和而卡死后续高优 Pod。为调度器扩展交付可导入的 Go 批量放置求解包。输入节点列表（含可用 CPU/内存/GPU、标签、污点、已占 hostPort 集合及已有 Pod 标签）、待调度 Pod 列表（含优先级、资源需求、容忍列表、硬节点亲和、可选 hostPort 需求以及基于拓扑键的硬 Pod 亲和与硬 Pod 反亲和——既约束与已有 Pod，也约束与本批同被放下的其他 Pod）。要求在节点数不超过七、待调度 Pod 数不超过八时，求出一个可行子集及其节点放置，使放置 Pod 的优先级总和最大，并列取成功数最多，再按各 Pod 所选节点编号向量字典序最小（未放置记为 -1）。验收用全枚举搜索对照最优优先级和与放置向量，覆盖两待调度 Pod 互为硬亲和须同域成对放下、互为硬反亲和跨拓扑键隔离、独占 hostPort 让位高优 Pod、以及污点未被容忍排除节点。
