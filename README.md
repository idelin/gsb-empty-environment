两个组织合并邮件列表，下次发送前既要兑现旧邮件中的退订请求，又不能把旧列表的一次点击当作另一个列表的全局禁发指令。给 TypeScript 邮件发送服务写可导入的订阅授权组件。每份出站邮件记录不可变的投递 ID、当时的组织及列表身份、收件人订阅代次和已签名的退订范围。合并有方向，可在指定时刻生效；拆分后旧订阅最多映射到明确继承它的子列表。请求的授权范围要先按投递时的快照核对，再沿有签名的迁移记录投影到当前列表，不能只按地址或列表显示名查找。用户后来明确重新订阅会开启新代次，旧邮件不能取消新代次。退订与一批待发送邮件并发：发件许可和退订生效必须有可解释的先后，已排队但尚未领取许可的邮件不能越过撤销。用可控存储回调交错合并、拆分、重订、重复点击及两个发送者领取，检查哪些实际投递许可被撤回。无法证明旧列表与当前订阅关系时标出未决范围，不能误伤同邮箱在另一组织的订阅。
