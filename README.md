写时复制（CoW）文件系统（ZFS 风格）最核心的两大基础设施难题是**多快照共享块的精确空间归属/延迟释放（Birth-Time + Deadlist）**与**抗扫描自适应替换缓存（ARC）**，四处机制必须严密联动：1）**CoW 块出生事务组（`birth_txg`）与多快照空间归属**：每次写入均分配新物理块并打上当前递增 `txg`；创建快照 `S_i` 记录快照时间点 `snap_txg_i` 并继承当前根指针；当后续覆盖或删除旧块 `B` 时，若 `B.birth_txg` 早于最新快照，绝不可立刻释放，而是把 `B` 记入当前活跃集的 `deadlist`！精确实测并维护每快照的 `unique_used`（仅被该快照引用的块字节数）与 `referenced`（该快照可见的总字节数），满足不变量：删除快照 `S_i` 实际释放的物理空间**必须严格等于**删前报告的 `S_i.unique_used`；2）**任意顺序删除中间快照的 Deadlist 合并**：当用户删除中间快照 `S_k`（夹在 `S_{k-1}` 与 `S_{k+1}` 之间！）时，检查 `S_{k+1}.deadlist` 中的每个块 `B`：若 `B.birth_txg > S_{k-1}.txg`（说明 `B` 在 `S_{k-1}` 之后出生、且在 `S_{k+1}` 之前已被删，如今 `S_k` 也删了，再无任何快照引用它！），立刻物理释放 `B`；否则将 `B` 合并迁入 `S_{k+1}` 对应的新历史死列表继续保留给 `S_{k-1}`！3）**四链表 ARC（`T1`/`T2`/`B1`/`B2`）自适应目标 `p` 调节**：缓存容量为 `c` 块，`T1`（近期单次访问）+ `T2`（高频多次访问）存真实块，`B1`/`B2` 存淘汰幽灵元数据（`len(T1)+len(B1) <= c` 且 `len(T1)+len(T2)+len(B1)+len(B2) <= 2c`！）；命中 `B1` 时按 `delta1 = max(1, len(B2)/len(B1))` 增大 `p = min(c, p + delta1)`，命中 `B2` 时按 `delta2 = max(1, len(B1)/len(B2))` 减小 `p = max(0, p - delta2)`，并严格执行 `Replace(x, p)` 淘汰规则，在大规模顺序扫描负载下保护 `T2` 热集不被冲刷；4）快照释放物理块时同步使 ARC 中对应块失效，杜绝已释放块号重用读出陈旧缓存。为文件系统存储层交付可导入的 Go CoW 快照 Deadlist 空间计费与 ARC 缓存协同引擎。验收覆盖多快照交叉覆写下 `unique_used` 与实际删除释放字节精确相等、任意顺序删除中间/首/尾快照的 Deadlist 合并与零物理块泄漏、ARC 顺序扫描抗污染对比 LRU 以及删块同步失效缓存防脏读。
