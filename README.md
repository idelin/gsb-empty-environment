设备群里一部分安装包曾从应急签名分支升级，不能仅按厂商宣称的最新证书认定所有设备都可迁移。请实现 Go 安装宿主可导入的升级计划包。输入为有限安装状态（包名、签名者集合、设备 SDK 区间、已有数据标记）与已验签的升级记录。记录的旧签名者门槛按不同公钥材料计数，新集合中同公钥的两个 ID 只算一票；沿升级链沿用已有数据须每一步都有相应授权。一条广播指令只指定发布包，匹配其 SDK 区间且满足旧签名门槛的设备升级，其余设备原地等待。某些升级允许多个新签名集合，由设备择一，服务器只见本轮成功数量，看不到是哪几台。至多 8 台、12 个发布包和 8 轮；同一包可重发。判断是否存在依赖这些可见计数的发布方案，使所有初始情况与所有设备选择都保住已有数据，最终都进入指定受信签名集合。给出最短最坏轮数、各计数分支下一条广播及验收函数；不可行须覆盖所有候选广播的失败依据。计数相同的真实状态不能因顺序不同而当成发布器可区分。用小设备群的完整决策树对照，覆盖门槛别名、中途丢数据后再升级、同计数不同签名设备和无需广播的初态。
