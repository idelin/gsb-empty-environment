# 有限状态模型死锁核查器

在给定的有限状态、多参与者模型上，区分：

- **声明终态**（declared terminal）：状态被声明为终态且没有任何可执行动作；
- **异常死锁**（deadlock）：状态未声明为终态，却没有任何可执行动作；
- **活锁候选**（livelock candidate）：状态未声明为终态，唯一可执行的动作是自环——自环不是死锁；
- **声明终态违例**（terminal not stable）：声明终态上仍存在可执行动作。

仅使用 Python 3.11 标准库（`dataclasses`、`enum`、`collections`）与 `unittest`。

## 模型与动作语义

- 全局状态是按 `participants` 顺序排列的局部状态元组，例如 `("H_A", "H_B")`。
- 动作是**多参与者同步动作**。动作只有在其声明的**每个**参与者的前置条件同时满足时才全局可执行（`is_enabled`）。
- 某参与者自身前置满足只表示它**局部提供/可邀约**该动作（`offered_by`），**局部可用不等于全局可执行**。
- 每个动作的 `pre` 必须覆盖其全部参与者；`eff` 是效果子集，未出现的参与者保持原状态。
- 验证对象仅限传入的有限状态模型；构造时校验参与者、局部状态、初态（不可重复）、终态、动作前置/效果的合法性。

## 死锁诊断（阻塞动作与证据）

`diagnose_deadlock(model, state)` 输出：

1. **阻塞动作**：至少被一个参与者局部提供、但全局不可执行的动作，以及
   - 提供方 `offered_by`；
   - 每个未满足参与者被要求的局部状态（前置条件）。
2. **等待图**：若 p 提供的阻塞动作 a 还要求 q 的前置满足，则有边 p → q，边标签为动作名。
3. **最小阻塞依赖环**：等待图中最短（长度相同取字典序最小）的环。
4. **无提供者证据**：若无环，输出最短的等待链，链尾参与者不提供任何阻塞动作。

若死锁状态上连一个可邀约动作都没有（如长链末端，模型中再无任何局部可用动作），则显式报告“无阻塞动作”。

## 搜索、预算与未决

- `analyze(model, state_budget=...)` 按初态**分别**做 BFS，因此：
  - 每个初态都有自己的最短反例（`InitialResult`）；
  - 多初态全部覆盖（全部 BFS 正常结束才算覆盖）；
  - 汇总给出跨初态的全局最短反例。
- 预算按“展开的状态数”计算，且在多初态间共享。预算耗尽而尚未发现违例时：
  - **结论保持未决（UNDECIDED）**；
  - 尚未展开的状态绝不被当作终止，也不被当作死锁；
  - 已发现的反例不会因后续预算耗尽而失效。

## 独立完整转移图核验

`verify_full_graph` 独立地从全部初态重新构造可达转移图（默认状态上限 `state_cap=100000`），不复用预算搜索的父指针：

- 独立重算最短死锁 / 最短声明终态违例；
- 对预算搜索给出的**每条**反例调用 `replay_trace` 逐步重放，核验可执行性、终点与状态分类；
- 预算搜索完整结束时，比对双方最短反例是否一致；预算未搜完时一致性标记为“不适用”；
- 完整图若在容量内穷尽，综合结论以完整图为准（可把预算阶段的 UNDECIDED 提升为确定结论）；
- 连完整图也超出容量无法穷尽时，维持 UNDECIDED。

## 明确的状态判定规则

| 非终态？ | 可执行动作 | 分类 |
| --- | --- | --- |
| 否 | 无 | `DECLARED_TERMINAL`（正常终态，不报死锁） |
| 否 | 有 | `TERMINAL_NOT_STABLE`（声明违例） |
| 是 | 无 | `DEADLOCK`（异常死锁） |
| 是 | 仅自环 | `LIVELOCK_CANDIDATE`（活锁候选，不是死锁） |
| 是 | 有非自环 | `ACTIVE` |

反例一律附带可重放的动作名序列；初态即违例时最短证据为空序列。

```bash
python3.11 src/demo.py                                  # 六个运行样例

```

## 运行样例覆盖

1. 双方资源死锁（多初态）：阻塞动作 `finishA`/`finishB`，最小环 P1 → P2 → P1；跨初态最短深度 1。
2. 无提供者死锁：证据链 P1 → P2，链尾 P2 不提供任何阻塞动作。
3. 自环活锁 + 正常终态（多初态）：结论 PASS，活锁仅作候选提示；终态无边不报死锁。
4. 声明终态仍有动作：FAIL_TERMINAL_VIOLATION。
5. 长链隐藏死锁，预算 5：预算阶段 UNDECIDED；独立完整图穷尽后给出深度 30 的死锁。
6. 同一长链、预算无限：直接 FAIL_DEADLOCK，最短证据为 30 步。

完整输出见 `sample_output.txt`，测试结果见 `test_results.txt`。

## 代码结构

- `src/deadlock_checker.py`：模型定义与校验、同步语义、状态分类、阻塞诊断、BFS 搜索、完整图核验、重放与报告。
- `src/demo.py`：六个可运行样例。
- `tests/test_deadlock_checker.py`：语义、诊断、多初态/最短证据、预算未决、独立核验与重放、输入校验共 27 个测试。
