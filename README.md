开放银行与高敏 API 授权服务器同时支持 OAuth 2.0 Pushed Authorization Requests（PAR，RFC 9126）与 Rich Authorization Requests（RAR，RFC 9396）时，若允许客户端在重定向端点混传额外 `authorization_details` 覆盖已推送的 `request_uri` 参数、允许跨客户端盗用一次性 `request_uri`，或在刷新令牌（Refresh Token）阶段未校验新请求的 `authorization_details` 为原授权对象语义子集（例如将限额 100 元扩展为 10000 元或新增收款账户），攻击者可篡改前端重定向参数或利用刷新流程静默扩张金融交易权限。为 TypeScript 授权服务宿主实现可导入的零外部依赖 PAR 与 RAR 策略校验及语义子集收窄组件。组件严格实现：（1）PAR 状态机：在推送端点校验客户端身份、PKCE（强制 `S256`，拒绝 `plain`）、`redirect_uri` 与结构化 `authorization_details` 数组，签发高熵一次性 `request_uri`（带严格 TTL，如 60 秒）并绑定 `client_id`；在授权端点消费 `request_uri` 时硬拒绝超时、重复消费、跨 `client_id` 使用，以及查询串中同时携带任何试图覆盖 PAR 参数（`scope`/`redirect_uri`/`authorization_details`/`code_challenge`）的走私字段；（2）RAR 语义校验与降权子集引擎：支持多类型授权对象（如 `payment_initiation` 含 `locations`/`actions`/`datatypes`/`instructedAmount` 精确十进制金额与币种、`creditorAccount`），在授权确认与 Refresh Token 换新时严格判定请求的每条 `authorization_details` 均存在原授权中同 `type` 对象完整覆盖其 `locations`/`actions`/`datatypes` 子集、金额 ≤ 原限额且币种/目标账户精确一致，任一越权扩张一律拒签。附 PAR 重复消费、前端参数覆盖走私、Refresh Token 金额/账户扩张与合法降权子集测试。
