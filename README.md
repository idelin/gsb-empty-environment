递归解析器在校验 DNSSEC NSEC3 否定存在响应（NXDOMAIN 与 NODATA）及通配符展开答案时，若未严格执行 RFC 5155 规范迭代哈希、跳过最近祖先（Closest Encloser）与通配覆盖验证，或错把 Opt-Out 标志用于非委派节点，攻击者可重放合法签名的 NSEC3 记录伪造域名不存在或劫持子域解析。为 Go DNS 安全解析宿主实现可导入的 DNSSEC RRSIG 与 NSEC3 证明验证包，严禁联网。组件完整实现 RFC 4034 规范线格式域名排序（大小写归一化与从右向左逐标签比较）、RRset 规范排序与真实 ECDSA-P256 `RRSIG` 签名核验（检查 `inception`/`expiration` 时间窗、签名者名称归属当前区、`labels` 标签计数以识别通配符展开并拒绝越权跨区签名），以及 RFC 5155 NSEC3 参数校验（SHA-1、迭代次数上限、盐值编码、Base32hex 无填充扩展十六进制编码与环形区间覆盖判定 `owner < hash < next`，含绕回尾节点）。核心否定与通配判定逻辑须精确覆盖：（1）NXDOMAIN 必须同时验证三条链环——存在精确匹配最近祖先哈希的 NSEC3、存在覆盖次近名称（Next Closer）哈希的 NSEC3、以及存在覆盖 `*.closest_encloser` 哈希的 NSEC3；（2）NODATA 必须区分精确匹配节点位图不含目标类型（含不伪造 `CNAME` 缺失）与隐式空非终端（ENT）或 Opt-Out 未签名委派边界（严禁在非委派查询上接受 Opt-Out 覆盖）；（3）通配符正答必须额外验证次近名称被 NSEC3 否定覆盖，防止用通配记录遮蔽真实存在的精确域名。用真实签名构造的正常、通配、ENT、Opt-Out 及伪造 NXDOMAIN/遮蔽攻击报文全覆盖验证。
