流式消息队列在支持精确一次语义（EOS）时，消费者以 `read_committed` 隔离级别消费分区，既不能提前暴露尚未结束事务写入的消息，也不能在多个并发事务交错提交/中止时把非事务消息或已提交消息永久卡死；同时僵尸生产者重连后若未按 `producerEpoch` 严格隔离并中止其遗留未决事务，就会污染分区日志。为消息代理交付可导入的 Go 事务协调器与分区 LSO（Last Stable Offset）消费过滤引擎。组件维护事务状态机（`Empty`、`Ongoing`、`PrepareCommit`、`PrepareAbort`、`CompleteCommit`、`CompleteAbort`）与各分区追加日志（含普通消息、事务批次及 `COMMIT`/`ABORT` 控制标记）。规则：`InitProducerId(transactionalId)` 递增 `epoch` 隔离所有旧纪元写入（旧纪元写请求立即返回 `PRODUCER_FENCED`），若原纪元有未决事务则自动驱动中止并向所有涉及分区写入 `ABORT` 控制标记；分区级维护全部未决事务的起始偏移（`firstOffset`）最小堆以精确计算 `LSO`（无未决事务时 `LSO == HighWatermark`，否则等于所有未决事务 `firstOffset` 的最小值）；`read_committed` 扫描器只返回偏移严格小于 `LSO` 的数据记录（自动跳过控制标记与属于已中止事务的批次，同时立即放行位于 `LSO` 之前的非事务消息与已提交事务消息！）；支持超时事务自动清理并推进被阻塞的 `LSO`。验收覆盖三个并发事务交错写入同分区（最老事务中止、中间提交、最新仍活跃）时 `LSO` 精确跳变、僵尸生产者 `PRODUCER_FENCED` 拦截与残留事务回滚、非事务消息穿插在未决事务前后以及 `read_uncommitted` 与 `read_committed` 输出逐条对照。
