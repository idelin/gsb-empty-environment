单点登录认证中心与前端桥接 SDK 在校验 OIDC `redirect_uri` 与 `window.postMessage` 目标源时，若使用前缀匹配、简单正则或未统一规范化路径与主机名，攻击者可利用反斜杠权威段混淆（`https://evil.com\@trusted.example`）、userinfo 欺骗、点段路径穿越（`/cb/../../open-redirect`）、八进制/十六进制/IPv4-mapped IPv6 地址变形、混合脚本 IDNA 同形异义域名或 `postMessage` 的 `*`/`null` 源，将授权码或访问令牌窃取至恶意站点。为 TypeScript 认证宿主实现可导入的零外部依赖重定向 URI 与跨源消息目标严格校验组件。组件同时实现两套零宽松策略引擎：（1）`redirect_uri` 严格匹配：拒绝任何包含反斜杠、控制字符、userinfo（`user:pass@`）、fragment（`#`）、相对点段（`.`/`..` 或其百分号编码变体 `%2e`/`%2f`）的输入；规范化方案/端口/主机名后要求协议、主机、端口与路径精确等于预注册条目（禁止子域通配与前缀放行），并对非常规 IP 字面量（八进制/十六进制/整数 IP、回环与内网保留段）及含非 ASCII 混合脚本的欺骗主机名强制拦截；（2）`postMessage` 发送与接收端源校验：硬拒绝 `*`、`null`、`file:`、`javascript:` 与 `data:` 源，要求精确源三元组匹配并验证消息信封绑定一次性 `state`/`nonce` 防重放与跨窗口串话。附涵盖反斜杠混淆、双重编码点段、IP 变形、同形域名与 `null` 源绕过的对抗测试集。
