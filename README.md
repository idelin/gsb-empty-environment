QUIC（RFC 9000）服务端在处理未验证源地址的 UDP 首包、Retry 令牌与连接迁移时，若未严格强制 3 倍防反射放大上限、允许跨源 IP 复用 Retry 令牌或暴露可被探测的无状态重置（Stateless Reset）字节特征，攻击者可利用服务端发动大规模反射放大攻击或主动撕毁他人连接。为 Go 传输层安全宿主构建可导入的 QUIC 握手防放大、连接 ID 与无状态重置安全状态机包，严禁联网。组件解析原始 QUIC 长包头（Initial/0-RTT/Handshake/Retry）与短包头（1-RTT），强制校验客户端首个 Initial 数据报长度不少于 1200 字节；在源地址尚未通过有效 Retry 令牌或 Handshake 确认前，对每个未验证源地址精确累计已收字节 `rxBytes` 与已发字节 `txBytes`，严格保证任何时刻 `txBytes <= 3 * rxBytes`（含重传、ACK 与 coalesced 包合并计费），超出预算必须挂起发送而非截断放行。Retry 令牌必须使用真实 AEAD（AES-256-GCM）加密绑定 `(clientIP, origDCID, retrySCID, issuedAt)` 并按 RFC 9001 规则计算 Retry Integrity Tag，严禁跨 IP、超期或重复使用同一令牌（防重放表）。对连接迁移与无状态重置：新路径启用前须完成 8 字节随机 `PATH_CHALLENGE`/`PATH_RESPONSE` 校验并重置新路径 3 倍限额；发送无状态重置包时须严格满足长度小于触发包且不少于 21 字节（防无限重置循环），重置令牌采用 HMAC-SHA256 绑定 CID 且绝不泄露给未授权对端。附确定性对抗测试覆盖 1199 字节短包、3x 边界越限、跨 IP Retry 令牌重放与无状态重置循环拦截。
