# 恶意模块把间接调用目标藏在一条已解码指令的中间

恶意模块把间接调用目标藏在一条已解码指令的中间。为Go二进制审查宿主编写控制流核验包，调用方给可信入口、固定版本字节和确定性解码器，解码结果含指令区间、直接后继及间接调用许可目标。遍历全部可达后继，任何许可目标必须同时是唯一指令起点；区间冲突不得覆盖消失，返回从入口到冲突目标的最短见证。预算耗尽返回未知而不签发可加载结论，用合成变长指令集穷举小镜像核对合法共享尾部与跳入指令中段。

## 包结构

- `cfverify`：控制流核验核心。调用方通过 `cfverify.Config` 提供镜像、可信入口、
  固定版本字节（偏移+期望值）和确定性 `cfverify.Decoder`，由 `cfverify.Verify`
  返回 `cfverify.Result`。
- `cfverify/synthisa`：合成变长指令集（1/2/3 字节：`HALT`/`NOP`/`JMP rel8`/
  `CALLI abs16`/`BAD`），含零基址与带基址两个确定性解码器及镜像构造助手。

## 判定语义

- `safe`：所有可达指令解码完成、区间两两不相交，且每个间接调用许可目标都是
  唯一指令起点。
- `conflict`：区间重叠、后继/许可目标跳入指令中段，或许可目标不是指令起点。
  字节归属表只登记首个属主、绝不覆盖，并给出从可信入口到冲突地址的 BFS 最短见证。
- `reject`：版本字节不符、解码器违约（PC/区间非法）或后继越界。
- `unknown`：指令或边预算在遍历完成前耗尽，不签发任何可加载结论。

间接许可目标按边类型单独入队：仅校验其是否为唯一指令起点，不会触发新解码而
掩盖既有属主；当目标地址暂未被解码时延迟复核，待直接后继路径排空后再裁决。

## 验证

`go test ./...` 运行：

- 独立预言机对全部 3906 个小镜像（操作数长度 0..5 的全枚举）做交叉核验，
  覆盖合法共享尾部、跳入指令中段与所有判定类别，并校验见证可走通且为最短；
- 预算耗尽返回 `unknown`、版本字节守卫、解码器违约、带基址寻址、确定性重复运行；
- 2000 个随机镜像的无 panic 模糊测试。
