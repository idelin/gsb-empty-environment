处理器在同时存在部分地址匹配 Store-to-Load 推测转发（STLF）与最多2层嵌套分支误预测的乱序执行窗口下，攻击者可利用推测窗口中未撤回的高速缓存观察将私密载荷经由公开地址探测渗出，即便架构回滚后最终寄存器与内存完全复原且单测看似无害，侧信道观察序列早已泄露秘密。为Go安全微架构验证宿主实现可导入的嵌套推测转发泄漏检测与最小屏障修补组件：建模12位物理地址、8位字节值、最多4项未提交Store缓冲、最多20条自定义指令（支持 `store`、`load`、`xor`、`cmp_branch`、`probe(reg)` 与 `barrier`）以及以 `reg & 0x0f` 划分的16路只读微架构观测序列。架构 load 精确命中最近同12位完整地址 store 或内存；推测执行器则在允许最多深度 2 的分支误测展开下，对 load 采用低6位地址冲突转发（若高6位不等则在至多4拍窗口内发现并回滚推测寄存器与未命中分支，但 `probe` 产生的微架构轨迹永不回滚），`barrier` 阻断后续推测并排空全部未决读与未解分支。给定宿主固定的高6位地址、秘密输入槽及公开可控低6位与公开内存空间，搜索公开输入完全一致而敏感秘密相异、架构 `probe` 轨迹字字相同但推测微架构轨迹相异的最短攻击双输入见证（若架构执行已泄密须单列原生漏洞，超时返 `Unknown`）；同时核验待审最小 `barrier` 插入方案在全状态参考模型下消除所有泄漏且不误改架构语义。
