容器与沙箱安全审计器在评估进程执行 `execve`、`setuid`/`setresuid` 及 `prctl(PR_SET_NO_NEW_PRIVS)` 后的权限演化时，若仅检查 `Effective` 能力位而忽略内核精确的五集合能力转移方程（`pP` Permitted、`pI` Inheritable、`pE` Effective、`pB` Bounding、`pA` Ambient 与文件能力 `fP`/`fI`/`fE`、`securebits`），往往漏报借 `Ambient` 继承或 `Inheritable + fI` 在非 root 执行普通二进制时意外获得 `CAP_SYS_ADMIN` 等隐蔽提权漏洞。为 Go 系统安全宿主实现可导入的 Linux `capabilities(7)` 精确状态转移模型与有界提权搜索包。组件逐位完整实现 Linux 内核 `execve` 能力计算公式：`pA' = (file privileged ? 0 : pA)`、`pP' = (X & fP) | (pI & fI) | pA'`（其中 `X = pB`）、`pE' = (fE ? pP' : pA')`、`pI' = pI`，并精确处理 `UID=0`/`EUID=0` 与 `SECBIT_NOROOT`、`PR_SET_NO_NEW_PRIVS`（阻断 `SUID` 与文件能力提权，强制新 `pP'` 为旧 `pP` 子集）以及 `setresuid` 从 0 切换到非 0 时的 `SECBIT_KEEP_CAPS` 与 `pA` 清零规则；严格维护系统不变量 `pE <= pP` 且 `pA <= (pP & pI)`。除单步精确状态转移裁决外，实现深度至多 6 步的有界符号/状态搜索器：给定初始进程凭据与镜像中可执行文件能力表，自动搜索能令非特权进程获得目标危险能力（如 `CAP_SYS_PTRACE`/`CAP_DAC_OVERRIDE`）的最短系统调用序列（`prctl`/`capset`/`setresuid`/`execve`），并附小配置全状态枚举交叉核验零漏报。
