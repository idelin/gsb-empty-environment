SQL 相关标量子查询（如 `SELECT a.id, (SELECT COUNT(*) FROM b WHERE b.k = a.k) FROM a` 或无聚合的 `(SELECT b.v FROM b WHERE b.k = a.k)`）在去关联改写为左外连接加分组聚合时，极易踩中经典 Kim COUNT 陷阱（空内表分组经左连接产生一行 `NULL` 时，误用 `COUNT(*)` 会算出 `1` 而非 `0`，必须改写为对非空列计数加 `COALESCE(..., 0)`，且 `SUM`/`MIN`/`MAX` 空组须保持 `NULL`！）以及基数约束丢失（非聚合标量子查询对某外表行命中 2 条及以上内表行时，SQL 标准要求必须抛出单行基数错误而非静默取任意一行！）。为查询优化器交付可导入的 Go 相关标量子查询去关联重写与执行验证包。输入为外表/内表模式（含列是否可空）、相关谓词集合（支持等值关联与范围关联）、内表自身过滤条件及标量投影（支持无聚合单列、单个聚合 `COUNT(*)`/`COUNT(col)`/`SUM`/`AVG`/`MIN`/`MAX` 及外层包裹任意标量表达式如 `COALESCE(agg, 0) + 1`、`agg IS NULL`）。规则：1）生成单趟去关联物理计划（左连接/外半连接 + 分组聚合 + `AssertMaxOneRow` 算子），精确处理 `COUNT(*)` 空组返回 `0`（注意：仅当外层无 `WHERE` 过滤且内表无 `HAVING` 时直接保留空组；若内表含 `HAVING` 导致聚合行被滤除，标量子查询对应该外表行仍须返回 `NULL` 而非 `0`！）；2）外表关联键为 `NULL` 时按 SQL 三值等值语义匹配零行内表（绝不可与内表 `NULL` 键错配！）；3）外表存在完全重复行时，去关联聚合分组不得把两条外表重复行合并成一行（须引入唯一外表行标识 `outerRowID` 分组！）；4）非聚合子查询对任意外表行匹配超过 1 行时，求值器必须精确报错并指出冲突外表行。验收在含重复外表行、`NULL` 关联键、空组 `COUNT(*)` vs `SUM`、`HAVING` 滤空与多行冲突的数据集上对照逐行嵌套循环参考求值器，验证输出行集合与异常行为逐行一致。
