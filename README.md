企业级 SRE 值班响应平台（PagerDuty 风格）在计算任意时刻“谁在值班”以及驱动多级告警升级时间线时，面对三类极易出错的时区与状态边界：1）**多图层值班表优先级与跨 IANA DST 本地墙上时间对齐**：值班表由多个 Base Rotation 图层（按日/周/自定义时长轮换，按图层所在 IANA 时区本地墙上时间交接——例如美东 `America/New_York` 每日 09:00 交接在春令时跳空日仅持续 23 小时、秋令时重叠日持续 25 小时，绝不可简单加减 `86400s`！）、周期限制窗（Restrictions：如仅限当地周一至周五 09:00–18:00，跨午夜拆段！）与临时替班覆写层（Overrides）叠加而成；规则严格遵循 **Override > 高序图层 > 低序图层**，一条仅覆盖 `14:00-16:00` 的 Override 必须把原本 `09:00-18:00` 的值班区间精准劈为三段并合并相邻同人区段，同时支持输出最终无重叠覆盖的精确 UTC 时间线！2）**多级告警升级与空班即时跳级**：升级策略由 `L_1, L_2, ..., L_k` 组成，每级配置延时 `delayMinutes` 与目标（具体用户或多个值班表）；告警触发立即通知 `L_1` 全部当前值班人，若在 `delayMinutes` 内未被 `Ack` 或 `Resolve` 则升级到 `L_2`；最关键的边界在于：**若某升级层级解析出的目标值班表在当前时刻因 Restriction 无人值班（有效目标集为空！）**，引擎绝不能原地傻等 `delayMinutes`——必须记录空班跳级事件并立刻顺延到下一个非空层级（若全部层级均为空班则立刻上报 `UNASSIGNABLE_ALERT` 而绝不死循环！）；3）**循环升级、静默延后（Snooze）与状态撤销**：支持 `numLoops` 到达末级后回卷 `L_1` 重呼指定轮次；一旦告警被 `Ack` 立即取消待发升级计时器，若响应人执行 `Snooze(duration)` 则在静默到期后自动恢复为未确认状态并按配置重新计时，一旦 `Resolve` 永久终结全部调度事件。为 SRE 响应控制面交付可导入的 TypeScript 跨 DST 值班表求解与多级升级时间线引擎。验收覆盖美东/欧洲春令时 23h 与秋令时 25h 交接对齐、局部 Override 1 裂 3 与相邻同人合并、Restriction 空班即时跳级与全空班防死循环、`numLoops` 轮次上限及 `Ack`/`Snooze`/`Resolve` 计时器精确撤销与重激活。
