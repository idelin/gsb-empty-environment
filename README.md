# blockgc — 共享内容块存储的标记-清扫回收器

针对"根清单可更新、读者仍可能持有旧根"的共享块存储，实现崩溃可续的
标记-清扫垃圾回收。

## 结构

- `store.go` — 块存储。三个区域：`blocks/`（存活）、`quarantine/`（隔离区）、
  `journal/`（每 epoch 一份追加式确认记录，JSONL，写后 fsync）。
  所有写入均为 tmp+rename 原子替换。
- `manifest.go` — 版本化根清单。`Publish` 发布新版本（撤销根 = 发布不含它的
  列表）；读者用 `Pin/Unpin` 钉住其观察到的版本。`ActiveRoots` = 当前版本与
  所有被钉住版本的根之并集。版本持久化在磁盘，重启后仍保护旧根。
- `gc.go` — 回收器：`Collect`（标记-清扫）与 `Recover`（崩溃恢复）。

## 安全性设计

**回收期间发布新根不会误删**：标记是循环进行的——每轮结束后重新读取活动根
集合，出现新根就再标一轮，直到根集合稳定才进入清扫。

**删除 = 隔离区 + 确认记录**：清扫只做原子 rename 进隔离区并写日志，不删除。
随后从**当前**全部活动根独立重遍历核对：隔离块若重新可达（例如扫描后才
新增的引用）则恢复；否则先写 `confirm` 记录（fsync）再物理删除。核对遍历
会穿透隔离区读取引用，保证被恢复块的整条引用链都被保住。

**崩溃可续**：每个破坏性步骤之前都有落盘的日志记录。`Recover` 重放所有
日志，按每块最后一条记录处理隔离区残留：

- `confirm`（已确认未删完）→ 直接删除；
- `quarantine` 或无记录（rename 与写日志之间崩溃）→ 重新核对，
  可达则恢复，不可达则确认后删除。

`Recover` 幂等，可反复执行。

**坏引用容忍**：悬空引用（指向不存在的块）跳过；环状引用由 visited 集合
处理——可达的环保留，不可达的环回收；损坏的块文件保守保留。

## 测试

`gc_test.go` 覆盖：共享块（菱形引用部分撤销）、环状/悬空坏引用、根撤销、
读者持有旧根（Pin）、标记期间发布新根、扫描后新增引用（隔离后恢复）、
崩溃恢复（三种日志状态 + rename/日志撕裂）、清单跨重启持久化。
