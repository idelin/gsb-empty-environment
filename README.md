# expsim — 顺序实验模拟器

Go 实现的顺序实验模拟器：显式整数观测、预先给定上下边界、逐步累计统计量、首次触边即停。

## 核心语义（`expsim/` 包）

- **首次触边即停**：累计和首次触及上/下边界时停止，结论冻结；后续数据只进审计日志，不得改变结论（`engine.go`）。
- **同时刻按序号**：同一 `Time` 的多个观测按 `Seq` 顺序处理；重复事件按 `ID` 幂等去重，同 ID 不同内容视为冲突（须走修订流程）。
- **检查点恢复**：检查点保存停止证据（步号、累计值、边界快照、触发观测），恢复后结论保持冻结（`checkpoint.go`）。
- **前缀穷举核对**：`VerifyStop` / `VerifyCheckpoint` 对原始日志（含重复事件）逐前缀重算，验证停止点恰好是首次触边、重复事件未被重复计数（`verify.go`）。
- **迟到修订**：修订产生新事实版本，原事实永不改写；`Recompute` 在新版本下重算首次停止点（前移/后移/出现/消失）（`revision.go`）。
- **不可撤动作**：动作账 append-only，已执行动作只产生补偿建议（`Compensate`），绝不篡改原账。
- **事件重放**：`Replay` 从事件日志重建系统；`VerifyRecovery` 对每个检查点做"重放到检查点 → 恢复 → 续放"核对（`replay.go`）。

三个版本化存储：事实版本（`FactStore`）、重算结论（`System.Conclusions`）、动作版本（`Ledger`，每条动作记录所依据的事实版本）。

## 运行

```sh
go test ./...   # 全部测试
go run .        # 演示：触边停止 → 检查点 → 修订 → 补偿建议
```
