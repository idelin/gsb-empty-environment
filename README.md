# testselector

基于符号调用图的测试影响选择器：对比改动前后的调用图，找出可能受影响的测试，并为每个被选中的测试输出最短影响路径。

## 模型

- **符号（Symbol）**：调用图节点，`test: true` 标记为测试。
- **静态调用**：`{"from": "a", "to": "b"}`。
- **动态调用**：用候选集表示，`{"from": "a", "dynamic": true, "candidates": ["b", "c"]}`，候选集中任一符号变更都会沿反向边影响调用方。
- **未解析调用**：`{"from": "a", "unresolved": true, "nameHint": "Run"}`，按显式保守规则扩大：
  - **R1**：有名字提示时，扩大为所有短名（最后一个 `.` 之后）匹配的符号；
  - **R2**：无提示（或提示无匹配）时，扩大为调用方所在包的全部符号。

## 变更集

`Diff(old, new, modified)` 计算三类变更根节点：

- **Removed**：旧图有、新图没有的符号；
- **Added**：新图新增的符号；
- **Modified**：两图都在但出边集合变化（边增删/重解析），或经 `modified` 显式标记（函数体改动但调用边不可见）。

## 选择算法

1. 将旧图与新图的边取**并集**构建反向图（被删符号的旧调用方仍会被波及）；
2. 未解析调用按 R1/R2 展开为有效 callee 集合；
3. 从全部变更根节点做 BFS（callee → caller），记录父指针；
4. 新图中所有被访问到的测试即被选中，沿父指针还原的路径即**最短影响路径**（测试 → … → 变更符号）。环与递归由 visited 集合保证终止。

## 用法

```sh
go run . -input example.json     # 或从 stdin 读入
go test ./...
```

输入 JSON 格式见 `example.json`；输出包含变更集与每个选中测试的最短影响路径。
