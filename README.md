TCP 在高丢包乱序链路上依赖 SACK 记分板精确估算在途字节（pipe）和判定丢失段，但尾包丢失无法凑齐三个重复 SACK 时须靠救援重传（Rescue Retransmission）避免 RTO，收到 DSACK 证实伪重传时还须撤销拥塞窗口减半。为协议栈交付可导入的 Go 恢复引擎包，按 RFC 6675 与 RFC 2883 精确实现。输入固定 SMSS、初始窗口、发送序列段及按序到达的 ACK 事件（含累进确认号、SACK 块数组、是否含 DSACK 块）与 RTO 超时事件。规则：维护 HighData、HighACK、HighRxt、RescueRxt、RecoveryPoint 及每段被 SACK 次数与高字节序；按 RFC 6675 计算 IsLost(SeqNum)（至少 3 个高序号段被 SACK 或 SACK 跨越字节达 3*SMSS）与精确 pipe；NextSeg() 按规则 1（首个未重传且 IsLost）、规则 2（未发送新数据）、规则 3（未确认未重传数据）及规则 4（仅当 RecoveryPoint 前存在未确认且未发过救援重传时选最高未确认段设 RescueRxt）严格分优先级决策；DSACK 匹配最近一次重传范围且尚未退出撤销窗口时恢复保存的 cwnd 与 ssthresh。验收用 RFC 场景序列对照逐包状态，覆盖 3*SMSS 跨字节判丢、规则 4 触发单次 RescueRxt 防 RTO、部分 ACK 推进不提前退出恢复，以及 DSACK 撤销伪减窗。
