# artifactflow

面向发布门禁的可导入 Go 包：在**不重跑构建**的前提下，核验一组已验签构建收据能否形成同一个全局一致的构建，并判断最终敏感产物是否存在两种不同的根来源归属。

```go
import artifactflow "prescreen.local/ddd-10563-v3"

result, err := artifactflow.Verify(receipts)
if err != nil {
    // 收据集合本身不合法（路径逃逸、超过 16 步、单步超过 3 个候选等）
}
switch result.Status {
case artifactflow.StatusVerified:
    // result.Certificate 可交给 artifactflow.VerifyCertificate 独立复核
case artifactflow.StatusAmbiguous:
    // result.Ambiguity.First / Second 给出两组冲突的根来源
case artifactflow.StatusRejected:
    // 不存在全局一致的收据选择与制品对应关系
}
```

## 模型

- `Receipt` 是一份已验签的步骤候选实现，`Step` 相同的收据互为替代实现。
- 每个步骤**恰好选择一个**候选；同一步不同候选的输出不能拼接。
- 每个端口同时声明逻辑路径与内容摘要。制品实例由租户、路径、摘要和生产者共同确定，仅同名不构成同一制品。
- `Consume` 输入在同一构建实例中只能使用一个具体实例一次；`Share` 输入可以分叉。
- 每个步骤最多 3 个候选，整组最多 16 个步骤。
- 输出默认继承其输入的全部根来源；若步骤的重命名规则（或完全相同的路径）把某个输出绑定到某个输入，则该输出只继承绑定输入的来源，并额外并入未被任何输出绑定的输入，从而阻止捕获路径在多个输出之间交叉且不丢弃签名来源。

## 重命名与路径

`RenameRule` 支持两种形式：

```text
stage/app -> release/app              // 完整路径精确匹配
stage/{name}/app -> release/{name}/app // 恰好一个捕获分量
```

- 捕获分量只占一个路径分量，输入输出两侧必须使用同一捕获名。
- 完整路径规则、捕获规则和恒等路径都可用于建立制品边。
- 规则由声明它的步骤同时用于两类约束：把上游输出路径映射到本步骤输入路径（`From` 为上游路径，`To` 为输入路径），以及把本步骤的某个输入绑定到某个输出（`From` 为输入路径，`To` 为输出路径）。没有被任何输出绑定的输入仍会保守地并入所有输出。
- 名字规范化只删除显式的 `.` 分量。
- 绝对路径、空分量和任何 `..` 都会被拒绝；规则不能改变租户，租户边界不可跨越。

## 根来源与歧义

构建实例中的每个产物都携带：

- `roots`：根来源标识集合（外部根制品 ID，或无输入的源步骤 `receipt:<receipt-id>`）；
- `receipts`：推导链上参与签名的收据 ID；
- `signers`：链上出现过的签署者角色。

`Verify` 会穷举所有可行选择与制品对应关系。若所有可行构建都给每个敏感最终产物相同的 `roots`，返回 `StatusVerified` 及一份成功证书。若同一敏感产物至少存在两组不同 `roots`，返回 `StatusAmbiguous`，并在 `Ambiguity` 中同时给出两组 `roots`、`receipts`、`signers` 和各自可独立验真的证书。若没有任何最终产物显式标记 `Sensitive`，全部最终产物都按敏感处理。

## 证书

`Certificate` 记录：

- 每步选中的收据及签署者；
- 每条输入边对应的具体制品实例；
- 每个使用到的制品实例的根来源、收据链和签署者；
- 每个最终清单项的来源实例与来源集合；
- 覆盖整体内容的 SHA-256 body hash。

`VerifyCertificate(set, cert)` 不运行求解器、不执行构建，只重放证书并重新计算：

- 每步选择、签署者白名单与最终角色要求；
- 摘要、路径、租户、重命名规则；
- 一次性输入消费计数；
- 构建图环路；
- 每条派生链的根来源。

证书本身证明“存在一次全局一致构建”；`Verify` 的穷举结果额外证明所有可行构建对敏感最终产物的根来源集合一致。两者都不需要重新执行构建步骤。

## 测试覆盖

`go test ./...` 中的小收据集穷举用例包括：

- 同摘要双来源导致两种根归属；
- 一次性输入被两个步骤同时消费；
- 捕获路径同名约束及多输出交叉；
- 替代实现的部分输出不可拼接；
- 每个单步局部可满足、整图因环路无对应；
- 乱序收据、等价替代实现、成功证书往返与篡改检测、16×3 上限。
