# 共享单车调度器

根据各站点容量与次日需求安排搬运路线：车辆从仓库出发、多次访问站点装卸车辆，
最终必须回仓。目标是最小化 **缺车罚金 + 里程成本**。

## 约束

- 站点最多 8 个，允许多次访问同一站点；
- 车辆载重有上限，且必须回仓结束；
- 站点库存任意时刻 ∈ [0, 容量]——**不允许负库存**，即不能提前取走尚未送达的车；
- 车载库存任意时刻 ∈ [0, 载重上限]；
- 需求超过容量时，需求目标按容量钳制。

## 算法

束搜索（beam search）：状态为 `(当前位置, 车载库存, 各站库存向量)`，
每一步枚举“开往任一其他位置 × 该站点的候选装卸量”（只生成有意义的候选：
卸到满足需求 / 卸满 / 卸空车载 / 装走超出需求部分 / 装满 / 路过不装卸）。
同层状态按 `(位置, 车载, 库存向量)` 去重保留最短里程，按
`里程成本 + 当前缺车罚金` 排序后保留前 `beamWidth` 个；位于仓库的状态即为一个
完整方案（保证回仓），并用已知最优方案剪枝。

## 使用

```bash
npm install        # 安装 typescript（仅构建需要）
npm run build      # 编译到 dist/
npm start -- examples/sample.json          # 文本时间线
node dist/cli.js examples/sample.json --json   # JSON 输出
cat examples/sample.json | node dist/cli.js    # 标准输入
npm test           # 编译并运行不变量/边界测试
```

可选参数：`--beam-width N`（束宽，默认 4000）、`--max-stops N`（最多停靠次数，
默认 `2 × 站点数 + 4`）。

## 输入格式

```json
{
  "depot": { "x": 0, "y": 0 },
  "vehicleCapacity": 10,
  "costPerKm": 1,
  "penaltyPerBike": 50,
  "stations": [
    { "id": "A", "x": 3, "y": 0, "capacity": 20, "initial": 18, "demand": 6 }
  ]
}
```

距离按欧氏距离计算。输出包含每步的行驶里程、装卸量、车载库存与各站库存时间线，
以及最终各站缺车数、罚金和总成本。
