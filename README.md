# 流量检测证据有界保留

探针发现攻击模式后需要返回前后文，但不能为了每个候选无限保存整条流。实现供Go检测宿主调用的证据缓冲包，候选通知包含原始区间及前后文长度，重叠窗口共享存储，流缺口在证据中显式保留；全局预算不足时按候选优先级再按事件ID淘汰并报告缺失。用随机通知顺序和逐字节参考验证已承诺窗口不被静默截短，取消释放引用。

## `evidence` 包

入口类型为 `evidence.Buffer`，用 `NewBuffer(budgetBytes)` 设置全局字节预算
（`<=0` 表示不限制）。检测宿主按绝对流偏移写入字节、登记候选、收取证据：

- `Write(off, p)`：按绝对偏移写入，支持乱序与重叠；重叠内容必须逐字节一致，
  否则返回 `ErrInvalidRange` 且不改动缓冲。流缺口不会被合成填充。
- `Notify(Candidate)`：登记候选，`Candidate` 携带 `Match` 原始区间与
  `BeforeContext`/`AfterContext`，窗口起点自动钳制到 0。
- `Collect(eventID)`：返回平铺整个窗口的 `Segment` 列表，数据段带逐字节内容，
  缺失段用 `ReasonGap`（流内真实缺口）、`ReasonPending`（流尚未到达）或
  `ReasonEvicted`（预算淘汰丢失）显式标注。
- `Cancel(eventID)`：释放候选持有的块引用，相关字节变为可回收缓存，不产生
  淘汰记录。
- `Evictions()`：按淘汰顺序返回记录，包含丢失的保留区间，宿主可据此上报缺失。

### 存储与预算

- 字节保存在互不重叠、按偏移排序的块中；多个候选窗口覆盖同一块时通过引用计数
  共享，只存一份。
- 独立维护的 `coverage` 区间集合记录“曾经收到过”的偏移，块被回收后仍能在证据
  中把对应范围显式标为缺失，而不是让窗口静默变短。
- 超预算时先回收无引用缓存，再按 `Priority` 降序（值越大越先淘汰）、同优先级按
  `EventID` 升序淘汰候选，并在 `Evictions` 中报告丢失区间。

### 验证

- 单元测试覆盖上下文钳制、乱序补洞、共享存储、淘汰顺序、取消回收、缺口保留与
  并发访问。
- `TestPropertyRandomOrderByteForByte` 使用随机通知顺序与随机写入，对照独立的
  无界参考流逐字节校验：数据段始终与参考流一致、窗口始终被完整平铺、缺失均显式
  标注、活动窗口引用的块不会被回收。

运行：`go test ./...`，竞态检测：`go test -race ./...`。
