# 安全日志确定性抽样

入侵检测接收器内存有限，丢弃记录又不能掩盖稀有告警。实现供Go探针调用的分层蓄水池包：每类告警保留最少配额，其余按事件ID的带密钥哈希优先级竞争，重复ID仅计一次；合并不同分片应与合并原始去重事件后抽样一致。配置总容量不足时拒绝，换钥开启新窗口。用穷举小流验证合并结合律、同ID不同内容冲突和高频类别不能挤掉保底样本。

## 实现：`reservoir` 子包

代码位于 `reservoir/`，仅依赖 Go 标准库（`crypto/hmac`、`crypto/sha256`）。

### 设计要点

- **带密钥优先级**：优先级为 `HMAC-SHA256(key, eventID)`，与载荷无关；HMAC 越
  大越优先，ID 字典序作为确定性同票裁决。换密钥即得到不可与旧窗口关联的新优先级。
- **去重计数一次**：同 ID 只缓存首见内容；重复出现计入 `Stats.Duplicates`，若类别
  或载荷不同再计 `Stats.ContentConflicts`，首见内容不被覆盖。
- **分层保底**：选择规则为全局确定性规则——先取每个类别的前 `MinQuota` 名候选，
  剩余槽位再按全局优先级填充。选择从有界候选集重算，而不是流式贪心淘汰，因此高频
  类别无法挤占稀有类别的保底位。
- **有界内存**：每类只缓存 `MinQuota(该类) + (Capacity - 配额总和)` 个最高优先级
  候选项；总缓冲量与流长度无关、随容量线性增长，`Snapshot` 输出不超过 `Capacity`。
- **分片精确合并**：`Merge` 要求相同密钥、窗口号与配置，把对端候选按 ID 升序回放，
  再走同一套 `Add/selectWinners` 路径。由于每类缓存的是该类全局前若干名，任何全局
  胜出事件都不会在任一分片中被提前丢弃，合并结果等于对原始去重事件并集直接抽样。
- **配置校验**：配额之和超过 `Capacity`（或出现负值）时 `New` 返回
  `ErrInsufficientCapacity`。
- **换钥开窗**：`RotateKey` 清空候选与计数，窗口号加一；跨窗口/跨配置合并返回
  `ErrWindowMismatch`。

### 验证

`go test ./...` 覆盖：

- 穷举 5 事件宇宙上所有长度 1–6 的序列，单流结果与独立参考实现逐字节一致；
- 穷举所有三段划分，验证 `(s1+s2)+s3 == s1+(s2+s3)`、双向两段合并与轮转分片；
- 300 组随机分片（随机分片数、随机归属、随机合并顺序）等价于并集直接抽样；
- 同 ID 不同类别/载荷冲突（单流与跨分片、正反合并顺序）；
- 40 个高频噪声事件下稀有类别保底位不被挤占（含合并路径）；
- 容量不足拒绝、零容量、换钥开窗、堆外候选缓冲有序性与 1 万事件大流有界性。
