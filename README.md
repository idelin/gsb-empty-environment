# 进程内存页别名保护

安全调试器需要防止通过另一个虚拟地址改写已标记只读的代码页。给Go调试宿主实现可导入的页映射策略包，输入页映射、解除映射和权限变更事务；按物理页汇总所有别名，任何可执行别名存在时不得有可写别名，切换采用先降权后增权的步骤。驱动可在任一步失败，失败后保持不违反约束的状态并给出恢复计划。用小页空间穷举共享映射与部分失败。

## 包 `netsec`

模块路径 `example.org/netsec/uid1256`，无第三方依赖，仅用 Go 1.24 标准库。

### 核心模型

- `Perm`：`PermRead` / `PermWrite` / `PermExec` 位掩码；单个 RWX 映射自身即违反 W^X。
- `State`：虚拟页 `VirtPage` 到 `Mapping{Virt, Phys, Perm}` 的快照，`Summarize()` 按物理页汇总全部别名，`CheckInvariant()` 校验“同一物理页存在可执行别名时不得存在可写别名”。
- `Txn` / `Op`：`OpMap`、`OpUnmap`、`OpReprotect` 事务；同一虚拟页仅允许“先 Unmap 后 Map”的重映射组合。

### 规划与执行

- `PlanTxn(from, txn)` 校验前置条件与目标状态不变量，输出 `Plan`：所有降权步骤（unmap、权限子集）排在所有增权步骤（map、权限超集）之前，混合权限变更拆成“降到公共掩码 → 升到目标掩码”，因此每个中间状态都满足约束。
- `PlanStateDiff(from, to)` 在两个已合法的快照间差分，用于生成恢复计划。
- `Engine` 驱动实现 `Driver` 接口（`Map` / `Unmap` / `Reprotect`）；仅在驱动调用成功后更新内部状态，并在每步后复检不变量。

### 失败与恢复

驱动在任一步返回错误时，`Engine` 停在最后已知良好状态，`Apply` 返回的 `Result.Failure` 携带失败步骤与原因，`Job` 给出两份计划：

- `ResumePlan`：从当前状态重试失败步骤并继续到达原目标（前向恢复）。
- `RollbackPlan`：同样按先降权后增权，退回事务开始前的状态（回滚恢复）。

恢复期间再次失败会按最新已知良好状态重新差分；未决任务存在时拒绝新事务，调用 `Resume()` 或 `Rollback()` 收敛后才能继续。

### 测试

- `TestExhaustivePlans`：3 虚拟页 × 2 物理页 × {R, RW, RX} 共 343 个状态，穷举 73,441 个安全状态对，校验降权前缀、逐前缀不变量及反向计划。
- `TestExhaustivePartialFailure`：对每个状态对在每个步骤（含全部成功路径）注入驱动故障，共 352,153 个用例，验证引擎与驱动状态始终一致、不变量始终成立，且前向/回滚两条恢复路径都收敛。
- `TestInvariantClassification` 用独立参考实现交叉校验包含 RWX 的 4 种权限全集。
- 其余定向测试覆盖持续故障重试、非法事务拒绝、跨物理页重映射、别名汇总与未决任务阻塞。
