# 分布式密钥生成的分发者双重承诺

多个参与者轮流担任分发者运行分布式密钥生成，恶意分发者可向不同接收方发不同多项式的份额，或在投诉阶段谎报。为Go门限签名库写供DKG轮次调用的Feldman承诺核验包：承诺为P-256上t个点，常数项承诺不得为单位元，也不得与其他分发者的常数项承诺相同；接收方份额不满足g^s等于承诺按x幂连乘即可投诉，投诉须附该份额及收到的承诺哈希；被投诉者在窗口内公开的份额若通过校验，投诉者记为诬告，否则分发者出局；同一分发者向两名接收方广播的承诺哈希不一致也直接出局。出局者的份额不计入聚合公钥与聚合份额，结果在窗口关闭时一次确定，晚到的投诉与公开不得改变；窗口按调用方推进的逻辑轮次计，x为零、重复及标量越界一律拒绝。用被篡改份额、诬告、双重广播、窗口边界和并发投诉验证。

## 包结构

- `feldman.go` — P-256 Feldman 承诺类型、承诺哈希（SHA-256 over
  压缩点序列）、份额关系 `g^s == Π C_i^(x^i)` 核验（Horner 求值），
  单位元/非曲线点/重复点、零 x 与越界标量拒绝。
- `engine.go` — 单轮 DKG 的投诉窗口状态机，`RWMutex` 保护并发：
  接收方与承诺登记、收据哈希比对（双重广播即出局）、份额登记、
  投诉/公开、按逻辑轮次推进窗口、关窗时一次性裁决并产出
  聚合公钥与聚合份额。
- `errors.go` — 全部哨兵错误，调用方用 `errors.Is` 判定。
- `random.go` — 安全随机标量。

## 窗口与裁决语义

- `NewEngine(w)` 的窗口覆盖逻辑轮次 `1..w`，`Advance()` 由调用方
  推进；轮次 `w+1` 起 `WindowOpen()` 为假，投诉与公开返回
  `ErrWindowClosed`。窗口未关时 `Finalize` 返回
  `ErrWindowStillOpen`。
- 投诉必须引用该接收方登记过的承诺哈希，哈希对不上返回
  `ErrCommitmentHashMismatch`；投诉证据自身能通过核验的，按
  `ErrShareMismatch` 当场拒收（不进入诬告计数）。
- 关窗裁决：无有效公开 → `unresolved_complaint` 出局；公开份额
  通过核验 → 投诉者进 `Result.FalseAccusers`；公开失败 →
  `invalid_disclosure` 出局。
- 常数项承诺两两相同的所有分发者在关窗时以
  `constant_commitment_clash` 出局。
- `Result` 只在 `Finalize` 成功时确定一次；之后任何变更返回
  `ErrFinalized`，晚到的投诉/公开无法改变结果。聚合只纳入合格
  分发者；合格者份额缺失返回 `ErrMissingShare`，全部出局返回
  `ErrNoQualifiedDealers`。

## 测试

`go test -race ./...` 覆盖被篡改份额、诬告、无效公开、双重广播、
常数项碰撞、单位元承诺、窗口边界（末轮受理/次轮拒绝/关窗后
冻结）、重复 x 与并发投诉/公开/登记。
