机密工作负载从旧芯片迁到新芯片时，两个宿主的证明都可能有效，但不能让两个实例同时持有新一代解封能力。实现供 TypeScript 密钥代理导入的迁移验收包。每份证明绑定芯片身份、工作负载持久 ID、实例启动计数、调试位、运行时公钥、nonce、TCB 版本向量和策略摘要；不是所有 TCB 分量都可互相替代。旧实例停用、旧公钥撤销、新芯片接收移交和设备所有者确认可以乱序到达，签名只认可其各自声明的动作。宿主给更新事件的因果前缀和已闭合的设备清单；单一合法新证明不足以推定旧实例已停止。判定某个密钥代次当前可释放给哪个公钥、拒绝还是等待，以及每个决定最少依赖哪些签名记录。恢复策略允许门限设备确认，但同一物理芯片的多个证书或同一实际管理域只能计一次。合并部分证据时不得误把同工作负载的另一迁移事务当成缺失步骤。用事件集合重算的参考做对照，按持久化边界模拟崩溃，验证旧实例复活、轮换临时公钥、并发两次迁移和向量版本互不可比。
