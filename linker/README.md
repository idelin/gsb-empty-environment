# 简化链接器（C++17）

实现符号裁决与归档按需加载的简化链接器，见 `linker.cpp`（单文件，无依赖）。

## 构建与运行

```sh
c++ -std=c++17 -Wall -Wextra -o linker linker.cpp
./linker demo1.txt        # 或从 stdin 读入： ./linker < demo1.txt
```

退出码：0 链接成功；1 存在强定义冲突或未解析引用；2 输入解析错误。

## 输入格式

行式文本，`#` 为注释：

```
object <name>     普通目标模块（总是加载）
archive <name>    归档开始
member <name>     归档成员（按需加载）
end               归档结束
strong <sym>      强定义
weak <sym>        弱定义
undef <sym>       强未定义引用（须解析，触发归档加载）
weakundef <sym>   弱未定义引用（悬空记 0，不触发归档加载）
```

## 裁决规则

1. **强定义唯一**：同一符号的多个强定义构成冲突。链接器收集*全部*强定义
   来源，在不动点达成后统一排序报告，因此冲突不会被输入顺序掩盖
   （`demo2.txt` 与其顺序颠倒版 `demo2_rev.txt` 报出同一冲突）。
2. **强优先于弱**：符号同时有强、弱定义时取强定义；多个弱定义取先加载者。
3. **归档按需加载**：对每个未解析的强未定义引用，按归档出现顺序扫描成员，
   加载第一个定义该符号的成员。新成员可能引入新的未定义引用，外层循环
   迭代至不动点（一趟内无任何新加载）。
4. **已有定义（含弱定义）的符号不再从归档提取成员**（见 `demo3.txt`：
   `main.o` 的弱 `malloc` 使 `libm.a(malloc.o)` 不被加载）。
5. **弱未定义引用**不触发归档加载，解析不到时记为 0。

## 输出

- **Load trace**：每个模块的加载原因（命令行输入 / 第几趟、为解析哪个
  符号、被谁引用）。
- **Symbol table**：每个符号的最终状态——定义（强/弱）及来源模块、
  未定义（含引用者）、弱未定义（归 0）。
- **Errors**：强定义冲突（列出全部来源）与未解析引用，按符号名排序，
  输出确定。

## 示例

- `demo1.txt`：链式依赖 `printf → memcpy → cache_flush`，三趟迭代到稳定；
  未被引用的 `unused.o` 不加载。
- `demo2.txt` / `demo2_rev.txt`：强定义冲突的顺序无关报告。
- `demo3.txt`：弱定义压制归档提取。
