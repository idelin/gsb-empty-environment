# MPU 配置安装包

`mpu` 包为固件管理层提供 ARMv7-M 风格 MPU（PMSA-v7，Cortex-M3/M4 同类）
的配置编译与安全安装能力，全部逻辑在纯 Go 模拟设备上运行，可在主机侧
穷举验证后再把寄存器序列下发到真实硬件。

## 硬件模型

- 区域尺寸为 2 的幂，范围 32B–4GiB，基址按区域尺寸对齐。
- 每个区域固定 8 个等长子区，`SRD` 中置位的子区被屏蔽；最小保护
  粒度为 4 字节（32B 区域 / 8）。
- 槽位号即硬件优先级：编号越大优先级越高，有效权限由编号最大的
  使能且覆盖该地址的区域决定；无命中时为 `PermNone`。
- 使能且权限为 `PermNone` 的区域表示显式拒绝，会压制所有低优先级区域。

## 编译：区间 → 对齐区域 + 子区屏蔽

`Compile(ivs, spaceSize, defaultPerm, dregion)` 把受限内存区间编译成
不超过 `dregion` 个区域：

1. 逐地址按 `Priority` 解释最终权限，同优先级重叠且权限不一致即
   `MapAmbiguous` 失败。
2. 非默认权限游程必须按 4 字节子区边界起止，否则 `MapAlignment`
   （包裹 `ErrNotRepresentable`）失败。
3. 迭代加深 + 回溯穷举最少区域组合：候选区域的每个使能子区权限必须
   统一，不满足的子区一律进入 `SRD`；区域使能足迹不得相交。
4. 所需区域超过 `dregion` 时返回 `MapCapacity`（包裹
   `ErrNotRepresentable`）。

所有失败都通过带类别、地址与原因的 `MapError` 明确上报，可用
`errors.Is` 匹配 `ErrNotRepresentable` / `ErrInvalidRegion`。

## 安全更新时序

`Device.PlanUpdate(target)` 生成寄存器写序列（`Plan.Steps`），分三阶段，
每一步都在微型地址空间上逐地址穷举：

1. **收紧 tighten**：需要变更的槽位禁用，或把 RASR 权限改写为
   `PermNone`。已经是使能 `PermNone` 的槽位跳过（禁用反而会暴露
   低优先级区域）。回溯搜索写入顺序，保证每一步的 W/X 集合都是
   **初始 W/X 集合的子集**——只减不增。
2. **几何 geometry**：槽位在禁用（或保持 `PermNone`）状态下写 RBAR，
   再以 `PermNone` 使能并写入目标 SRD。新覆盖地址先全部拒绝。
3. **提升 raise**：逐槽位把 RASR 权限提升到目标值，回溯搜索顺序，
   保证每一步的 W/X 集合始终是**最终目标 W/X 集合的子集**。

关键判据是与初始/最终基准比较，而非与上一步比较：收紧阶段允许
先前被高优先级槽位压制的地址在中间态“恢复”，只要它从未超出初始
授权范围。

若槽位/几何约束导致不存在满足上述不变量的写入顺序，规划器返回
包裹 `ErrUnsafeTransition` 的 `TransitionError`，其中给出阶段、槽位
与见证地址，固件层应放弃切换而不是冒险安装。

## 独立验证

`VerifyPlan(plan)` 不信任规划器，从初始快照重放整个序列：

- 第一次权限提升之前，每步 W/X 必须包含于初始集合；
- 提升阶段及之后，每步 W/X 必须包含于目标集合；
- 结束时逐地址比对有效权限，并逐槽位比对使能位与区域寄存器。

## 测试

`mpu_test.go` 在 128 字节微型地址空间上：

- 校验 SRD 编码、优先级覆盖、对齐/容量/歧义等明确失败；
- 用朴素的“使能态直接改几何”坏序列验证 `VerifyPlan` 必须拒绝，
  并检查见证地址落在越权窗口内；
- 随机生成 2000 组两端映射，编译、规划并逐步穷举 W/X 不变量；
- 包含确定性的不可安全切换用例，断言 `ErrUnsafeTransition`。

```sh
go test -race ./mpu
```
