# 会话协调包设计说明

面向 TypeScript 中继宿主的会话协调库。核心目标：参与方断线换节点后，
旧节点上未消费的应答只能被同一签名身份在新连接上代次接管，绝不会流向
复用了显示名称或传输地址的另一个人。

## 身份与同意模型

- 身份是签名公钥的 SHA-256 指纹（`IdentityId`），与外部显示名称、传输地址完全分开。
- 显示名称、地址、会谈号被重用都不继承任何同意；路由只看签名身份、代次和会谈事实。
- 邀请经过规范化 JSON + SHA-256 得到摘要（`invitationDigest`）。每个应答都必须
  携带该摘要，摘要不符直接拒绝，无法跨邀请重放。
- 同意范围（`ConsentScope`）由各方自签，绑定会谈号、双方身份、内容组、邀请摘要、
  签发时代次、动作集合（`relay-answer`、`migrate-connection`）与有效时间窗。

## 迁移事务

一次连接迁移由三个各自签名的事实组成，且允许乱序到达：

1. `migration-release`：旧连接释放，由迁移方自签，携带旧/新代次与旧节点。
2. `migration-takeover`：新连接承接，由迁移方自签，携带新代次与目标节点。
3. `migration-approval`：对端认可，由对端（counterparty）签名。

三个事实只有在同一个 `migrationId` 下、且会话号/迁移方/新代次全部一致时才会
合并到同一跟踪器；不同事务的事实永远无法凑齐三要素。同一参与方同时只允许一个
未完成迁移。跟踪器未完成时，发往该参与方的应答返回 `waiting` 并列出具体缺失的
事实；完成后代次推进到新连接，旧连接随即释放。

## 事件溯源与双节点回放

- 每个会谈一个仅追加事件日志（`session:<sessionId>`），事实接受前先做签名校验，
  再做纯函数领域校验，最后通过单键 CAS 追加。
- `replay(events)` 是纯函数，两个节点回放同一事件流得到逻辑相同的状态，
  这是接管正确性的参考基准。
- 持久化原语只有按键比较交换（`CasStore`），没有多键事务；索引、日志、回执
  各自占用独立的键，争用时重试。

## 投递判定与回调

`evaluateAnswer` 在任意部分日志上给出四类判定：

- `deliverable`：当前可投递对象（身份、代次、节点）。
- `waiting`：尚缺哪些事实（邀请、某方同意、连接注册、迁移三要素）。
- `blocked`：不可投递及原因（撤销、摘要/组不符、无活连接、签名错误等）。
- `in-flight` / `delivered`：投递生命周期状态。

协调器的判定回调按答案做指纹去重，只有判定内容变化才回调一次，重复查询不多发。

## 幂等收件回执与恢复

- 投递端先在回执目录按 `answerId` 原子申领回执，回执绑定接收身份、邀请摘要、
  代次与节点；同一答案重复申领返回同一回执，冲突接收方直接报错，绝不静默改投。
- 中继在申领之后、确认之前崩溃时，恢复逻辑区分：
  - `delivered`：本地已确认；
  - `delivered-reconciled`：中继丢失响应，但接收方目录可查到回执；
  - `indeterminate`：在途且无任何回执，只能向原目标重试，不能改投；
  - `not-attempted`：尚未尝试。

## 双节点完整事件回放参考

`src/replay/run.ts`（`npm run replay:reference`）内置五个场景，每个场景都在
节点 A 产生完整事件流并在节点 B 回放比对：

1. 异步接管：迁移事实乱序、部分缺失时等待，完成后路由到新节点同身份；
   陌生人复用显示名称/地址拿不到应答。
2. 交叉邀请：双向邀请各自独立日志与摘要，跨邀请/跨方向应答被拒。
3. 撤销后迟到确认：撤销后迟到的同意与应答均被拒，会话不会复活。
4. 接收方已收到而中继丢失响应：回执对账、幂等重试与三种恢复分类。
5. 同一参与者使用两个内容组：组作用域隔离，跨组应答与会谈号重用均被拒。
