# walstore — 带日志的固定长页存储原型

每笔事务修改多个固定长页;写入可能只完成前缀(短写/撕裂写);
提交确认严格晚于恢复所需信息落盘;崩溃恢复保证每笔事务全有或全无,且重复恢复结果不变。

## 结构

- `file.go` — 最小文件接口 `File`(ReadAt/WriteAt/Sync/Size)。
  - `OSFile`:真实文件。
  - `MemFile`:可注入故障的内存文件,区分易失态/持久态:
    - `ShortWriteMax`:每次 WriteAt 最多写 N 字节(注入短写);
    - `SyncLoss`:Sync 假成功、不持久化(注入持久化丢失);
    - `Crash()`:丢弃未持久化数据,模拟断电。
- `log.go` — WAL 记录编码 `[type:1][len:4][payload][crc32:4]`、
  追加器(循环重试短写)与扫描器(遇撕裂/CRC 错误即截断尾部)。
- `store.go` — 提交协议、页缓存、崩溃恢复。

## 提交协议(关键不变式)

1. 事务全部页的物理后像(update 记录)+ commit 记录追加到日志;
2. `Sync` 日志 —— 持久化屏障,此后 `Commit` 才返回成功;
3. 确认之后才应用页缓存;数据页由 `FlushData` 惰性落盘。

因此 commit 确认 ⇒ 恢复所需信息已持久化。日志不截断,恢复始终全量重放。

## 恢复与幂等

- 物理日志:整页后像,天然可重放;
- 每页头部存 `pageLSN = 已应用记录 LSN + 1`,仅当记录 LSN ≥ pageLSN 才重做,
  重复恢复(含恢复过程中再次崩溃)结果不变;
- 无 commit 记录的事务一律忽略(全有或全无);撕裂尾部按 CRC/长度截断。

## 切点核对

`TestCutPoints` 跑三笔有交叠页的事务,得到 561 字节日志,
枚举全部 562 个持久化切点(含记录中间),对每个切点:
按"持久化日志前缀 + 初始数据页"重放恢复,断言状态恰好等于
串行前缀 S0..S3 中对应的一个,并验证二次恢复与恢复中再崩溃均不变。
